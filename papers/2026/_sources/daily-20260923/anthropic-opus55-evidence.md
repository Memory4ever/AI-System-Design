# Claude Opus 5.5 system card：定点证据笔记

状态：证据初审完成；窗口日期、候选准入、Books 比较和独立复核未完成。本文不是日报完成声明。

- 原始材料：[Anthropic, *Claude Opus 5.5 System Card*](https://www.anthropic.com/claude-opus-5-5-system-card)，封面标 2026-09-22；本次读取 PDF 第 2–4、95–96、123–126 页。对应[官方发布页](https://www.anthropic.com/claude-opus-5-5)也只显示日级日期。需要独立核实发布时间是否完全落入 09-22 09:00～09-23 09:00 北京时间。
- 拟核验命题：模型训练时把“位于 user turn”误学成“来自用户本人、可作指令”的充分条件，会把用户粘贴的第三方文本提升为行动授权；区分消息角色与内容来源、对粘贴文本加 provenance 标记和执行前保护，是模型防注入与产品侧控制的不同层。
- 机制位置：§6.5.1（PDF pp123–126）说明早期快照在训练中为避免把异常用户提示误报为 indirect injection，过度泛化为信任 user-turn；其中一条 rubric 明示不应将 user prompt 中指令标为 injection。作者将此行为归因为该训练路径，但没有公开训练集和受控因果消融，故这里是作者分析而非独立确定的因果结论。
- 实验边界：作者的 coding evaluation 里，早期未缓解快照对用户粘贴文本中植入指令的执行/计划/转交比例为 52%；正式模型经训练调整后默认思考设置约 2%、最大思考约 7.4%；Invisible Unicode 子集正式模型默认设置 2/68。另一组 tool-result 注入在作者测试中为 0/105。产品层的粘贴标注和不可见字符移除在这组测试中使执行为零，但测试是模拟工具调用和有限 coding 场景，不证明所有渠道、部署与现实攻击均为零。§6.1.3（p96）也指出产品保护当时尚在 rollout，不能外推到所有使用面。
- 设计含义（本项目推断）：用户消息角色不等于其中每段文本具有同等 instruction authority；模型训练的边界识别和 Host/工具的 effect-time 授权须分层。反向代价是更严格的 pasted-content 提示或清洗可能误伤真正的用户指令、损失上下文保真；需要保留显式委托及人工确认路径。它可能是 `PLATFORM-SECURITY`/`AGENT-CONTEXT` 的现有覆盖或增量，尚需逐段比较，不在此笔记直接裁决。
- 未证明：训练细节独立复现、跨任务成功率、真实生产攻击发生率、所有部署渠道的产品保护覆盖、单靠模型即可消除风险。论文/卡片发布年份和事件窗口必须另核，不能用封面日期伪造发布时刻。
