Abstract
Vision-language-action (VLA) models enable language-guided robot manipulation,
but remain vulnerable to visual attacks that undermine user control over robot
behavior. Prior studies optimize visual perturbations using fixed target
supervision. However, the perturbation can change earlier actions
and, in turn, the physical states reached later. As the attacked trajectory
evolves, this supervision may no longer match the behavior needed at the
states actually reached. Accurately matching these targets can therefore
fail to advance the attacker-specified task. Even with suitable supervision,
reducing average matching error does not ensure sustained task progress.
The robot may still fail at a critical stage, and further updates can disrupt
previously successful behavior. To address these limitations, we propose TRACO,
a framework that enhances existing targeted visual attacks through closed-loop
optimization. Its Execution-Driven Supervision rebuilds supervision for the states
reached under attack to guide subsequent updates.
Within this framework, Progress-Guided Selection focuses updates where
progress stalls while maintaining supervision on the earlier behavior needed
to reach that point.
Experiments across VLA models and simulation environments show improved
task-redirection success with TRACO, highlighting the security implications of
closed-loop attack optimization.
Index Terms: Vision-language-action models, adversarial attacks, robot security,
closed-loop optimization.

I Introduction
Vision-language-action (VLA) models enable robots to perform diverse
manipulation tasks from natural-language instructions [1, 2].
During execution, they repeatedly use new camera observations to decide how
to continue the task. This visual feedback allows the robot to adapt its
actions as the scene changes [3]. However, visual perturbations can change the
actions the model generates [4, 5]. By changing the robot’s actions, an attack can
also change the physical states and observations encountered later. These
altered observations then guide the robot’s subsequent actions. The attack
can therefore influence how the robot proceeds through the task and what it
ultimately accomplishes. Understanding these closed-loop effects is important
for assessing the security of VLA systems.
Recent studies have demonstrated the vulnerability of VLA models to visual
attacks. Many of these attacks aim to make the user’s intended task fail [6, 5, 7, 8].
Some pursue this goal by inducing prescribed actions or trajectories [4, 9].
These targets specify how the robot should deviate, but not what task it should
complete instead. In contrast, TRAP studies task-level behavior hijacking,
where success requires the robot to complete an attacker-specified task [10].
Its supervision includes reasoning and action targets.
In both cases, target supervision is fixed before optimization. It comes from
prescribed action targets or pre-collected target rollouts. This raises a central
question: can fixed supervision still guide the robot to complete the target
task as the attacked trajectory evolves?
The challenge is that optimizing the perturbation can change the very states
on which the robot must act. When attacks use pre-collected target rollouts,
perturbation updates rely on the recorded observations and target outputs.
During execution, however, the updated perturbation can lead the robot to
states different from those in the recorded rollouts, as illustrated in
Figure 1(a). To continue the target task from
these attack-induced states, the robot may need to behave
differently from what the recorded targets specify [11].
Better matching to these fixed targets therefore need not translate into
successful closed-loop execution [12, 13].
Figure 1(b,c) illustrates this gap for action
matching on recorded observations in one scene. This motivates using execution
feedback to refresh target supervision as the attacked trajectory evolves.
Execution feedback must also guide where optimization should focus and what
earlier behavior it should preserve. Even with suitable targets, matching some
behaviors more accurately can lower the average loss while an unresolved error
still blocks task progress [14, 15].
For example, in a pick-and-place task, better matching of placing actions
cannot compensate for a failed grasp: the robot must grasp the object before
it can place it.
Because the same perturbation affects all execution steps, an update intended
to improve the blocked behavior can also weaken earlier successful behavior.
Optimization should therefore focus near where progress stalls
while retaining the earlier behavior needed to reach that point.
To address these problems, we propose TRACO (Task-Redirection Attacks via Closed-loop Optimization),
a framework that enhances existing visual attacks through execution feedback.
Its Execution-Driven Supervision (EDS) rebuilds target supervision
for the states reached under the current perturbation.
These targets guide subsequent perturbation updates. The resulting execution,
in turn, supplies the states for rebuilding target supervision, closing the
loop between attack optimization and execution.
Within this loop, Progress-Guided Selection (PGS) selects states for supervision
to advance the target task while retaining earlier behavior. Using a successful target
rollout as an ordered reference, PGS identifies the matched prefix and progress
frontier of the attacked rollout. Supervision at the frontier focuses updates
on the behavior needed for further progress. Meanwhile, continued target
supervision along the prefix helps retain the earlier behavior needed to reach
the frontier. TRACO thus constructs and organizes supervision from actual
execution. Existing targeted attacks can use this supervision with their own
alignment objectives.
Our contributions are summarized as follows:
•
We propose TRACO, a framework that extends visual task-redirection
attacks on VLA models to closed-loop optimization. Its Execution-Driven
Supervision (EDS) replaces fixed targets with supervision reconstructed at
the states reached under attack. Existing attacks can thus
account for the state changes they induce while retaining their alignment
objectives.
•
We introduce Progress-Guided Selection (PGS) to organize supervision
according to ordered trajectory progress. It combines frontier supervision
with prefix supervision along the current attacked rollout. This design helps
advance the target task while retaining earlier behavior under a visual
perturbation shared across execution steps.
•
We evaluate TRACO across diverse VLA models and simulation environments.
Results from simulation and real-robot experiments demonstrate TRACO’s
effectiveness for visual task redirection, highlighting the value of closing
the loop between attack optimization and execution.

II Related Work
Vision-Language-Action Models
Generalist robot policies learn language-conditioned manipulation from
diverse robot data [16, 17, 18].
VLA models such as RT-2 and OpenVLA build on pretrained vision-language
representations and predict actions autoregressively as discrete
tokens [3, 1]. In parallel, diffusion-based action generation
has been adopted in both visuomotor policies and VLA
models [19, 20, 21, 22].
Flow matching provides another route to continuous action
generation [2, 23, 24]. Recent work
also explores efficient action tokenization [25] and
parallel action decoding [26]. Some VLAs further use
intermediate reasoning to guide action
generation [27]. During closed-loop
execution, VLA models use updated visual observations to guide subsequent
actions. We study how visual perturbations can redirect this execution
toward an attacker-specified task.
Adversarial Attacks against VLA Models
Visual attacks seek to disrupt task execution or induce prescribed robot
behavior. One line of work targets visual representations and vision–language
alignment [6, 28]. Related studies develop patches
that transfer across models and domains [5, 7],
or learn fixed patches from short execution prefixes [8].
Targeted visual attacks steer action outputs toward prescribed values or
trajectories [4, 9, 29], or induce action
freezing [30]. At the task level, TRAP hijacks robot
behavior by jointly matching chain-of-thought (CoT) and action targets from clean target
rollouts [10]. Language attacks likewise manipulate actions or disrupt
execution through adversarial prompts [31, 32].
Trajectory-Level Redirection uses closed-loop prompt search and queries target
behavior on the states induced by candidate
prompts [33]. For targeted visual attacks,
TRACO provides a reusable closed-loop optimization framework. Existing attacks
can retain their alignment objectives while TRACO updates target supervision
on the states reached during attacked execution.
On-Policy Imitation Learning for VLA Models
During execution, VLA policies can reach states not covered by their training
demonstrations. DAgger addresses this distribution shift by obtaining expert
supervision on states visited by the learner [34].
Related VLA methods obtain such supervision through human
corrections [35, 36, 37, 38, 39]
or teacher policies [40, 41].
Building on this principle, TRACO optimizes a shared visual perturbation using
supervision on attack-induced states while keeping the VLA fixed.
PGS selects frontier and prefix states to advance the target task while
maintaining supervision on earlier behavior needed for continued progress.

VLA policy

III-B Overview
TRACO optimizes visual perturbations using feedback from closed-loop execution
, as shown in Figure 2. Execution-Driven Supervision (EDS)
runs the VLA under the current perturbation and records the states reached.
It rebuilds target supervision on these states to guide subsequent updates.
Progress-Guided Selection (PGS) uses rollout feedback to focus supervision
near where progress stalls. It also maintains supervision on earlier behavior
to help preserve the progress already made. Using the supervision constructed
by EDS and organized by PGS, TRACO updates the perturbation with the chosen
attack’s alignment objective. TRACO repeats this cycle, using each new rollout
to refresh supervision and adjust the focus of subsequent updates.
III-C Execution-Driven Supervision
The behavior needed to pursue the target task depends on the state reached.
Unlike attacks that rely on pre-collected target rollouts, EDS uses closed-loop
execution to construct supervision for the states induced by the current
perturbation. In each round rr, we run the frozen VLA under the source
instruction csrcc_{\mathrm{src}} and perturbation δr∈Δ\delta_{r}\in\Delta.
We record the visited states and their unperturbed observations in 𝒟r\mathcal{D}_{r}.
At a selected state in 𝒟r\mathcal{D}_{r}, we query the frozen VLA under the target
instruction to obtain behavior for that state. The source prediction
uisrc​(δ)u_{i}^{\mathrm{src}}(\delta) and target supervision uitgtu_{i}^{\mathrm{tgt}}
thus correspond to the same physical state under different input conditions:
(gδ​(oi),csrc)\displaystyle\bigl(g_{\delta}(o_{i}),c_{\mathrm{src}}\bigr)
→πθuisrc​(δ),\displaystyle\xrightarrow{\pi_{\theta}}u_{i}^{\mathrm{src}}(\delta),
(3)
(oi,ctgt)\displaystyle\bigl(o_{i},c_{\mathrm{tgt}}\bigr)
→πθuitgt.\displaystyle\xrightarrow{\pi_{\theta}}u_{i}^{\mathrm{tgt}}.
Here, oio_{i} is the unperturbed observation of the selected state, and
δ\delta is the perturbation being optimized.
The updated perturbation can change the states reached during execution.
EDS therefore rebuilds supervision from new rollouts, so subsequent updates
use target behavior for the states currently reached.
III-D Progress-Guided Selection
The same perturbation affects every policy query, so updates aimed at further
progress can also change earlier behavior. PGS uses progress in the current
attacked rollout to determine where to focus these updates. It also maintains
supervision on earlier behavior to help preserve the progress already made.
Progress estimation
For each initial condition, PGS uses a successful target rollout as an ordered
progress reference. PGS estimates progress from consecutive position matches
between the attacked rollout and this reference.

To advance beyond the frontier, PGS selects the corresponding state in the

III-E Target Alignment
When applying TRACO to an existing attack, we retain its choice of predictions
to align and its matching loss 𝒟\mathcal{D}. At each state selected by PGS,
we compare the source prediction with the corresponding target from EDS:
ℓi​(δ)=𝒟⁡(uisrc​(δ),uitgt).\ell_{i}(\delta)=\mathcal{D}\!\left(u_{i}^{\mathrm{src}}(\delta),u_{i}^{\mathrm{tgt}}\right).

For example, continuous action chunks can be matched by squared error.
Sequence targets, such as action tokens or CoT, are matched by minimizing
their negative log-likelihood with teacher forcing. For flow-matching policies,
we use squared error to compare source and target vector fields at the same
flow states and times. For joint objectives, such as action–CoT alignment in TRAP [10],
ℓi​(δ)\ell_{i}(\delta) combines the corresponding losses.

these losses across the frontier and prefix groups to optimize the perturbation.

IV-A Experimental Setup
VLA models
On LIBERO [43], we evaluate 5 VLA models spanning autoregressive action
generation, direct regression, and flow matching. These include
four StarVLA models [44]—PI, GR00T, FAST, and OFT—
as well as LangForce [45].
On SimplerEnv [46], we evaluate
InstructVLA [27], which uses CoT reasoning to
guide action generation. Appendix -D describes the model architectures.
Tasks and evaluation metrics
We pair each user-specified source task with an attacker-specified target
task for evaluation. On LIBERO, we use 5 task pairs from LIBERO-Goal [43]
in the global setting. These pairs require redirecting the robot to different placement goals or manipulation behaviors,
such as switching from placing an object to turning on a stove.
In the patch setting, we use 5 pick-and-place task pairs that change which
object is moved or where it is placed.
We select layouts from LIBERO-Plus [47] for the
global setting and follow its scene-variation design
for the patch setting. Each task pair has 10 Seen layouts for attack
construction and 10 Unseen layouts.
On SimplerEnv, we construct 5 task pairs in the patch setting, each
changing which object the robot picks up. Each task pair has 5 Seen
and 5 Unseen layouts.
Table IX lists the task pairs, and
Figure 9 shows example Seen and Unseen layouts in
both environments.
We evaluate each perturbation with 5 rollouts per layout.
We report Attack Success Rate (ASR), the percentage of successful
task-redirection rollouts under the source instruction. Following
TRAP [10], we also use Hijack Score HH to compare the attacked
trajectory ξ\xi with successful clean source and target references
ξ¯src\bar{\xi}_{\mathrm{src}} and ξ¯tgt\bar{\xi}_{\mathrm{tgt}}:
H⁡(ξ)=stgt−ssrcstgt+ssrc+εH,sq=1dDTW​(ξ,ξ¯q)+εH.H(\xi)=\frac{s_{\mathrm{tgt}}-s_{\mathrm{src}}}{s_{\mathrm{tgt}}+s_{\mathrm{src}}+\varepsilon_{H}},\quad s_{q}=\frac{1}{d_{\mathrm{DTW}}(\xi,\bar{\xi}_{q})+\varepsilon_{H}}.
(9)
Here, dDTWd_{\mathrm{DTW}} is the Dynamic Time Warping distance between
end-effector trajectories, normalized by their combined sequence length,
with εH=10−6\varepsilon_{H}=10^{-6}. Higher HH indicates greater relative
similarity to the target trajectory. We compute both metrics over all
rollouts within each task pair, then average equally across task pairs
for Seen and Unseen separately.
Compared methods
In both environments, we compare TRACO with Random Noise and offline
targeted attacks. Random Noise provides a non-optimized reference under
the same perturbation constraints. The offline attacks optimize visual
perturbations to match fixed targets from successful target-task rollouts.
On LIBERO, we use Action Attack, the targeted action-matching
baseline [4] evaluated in TRAP [10].
On SimplerEnv, we evaluate Action Attack, TRAPCoT-only\mathrm{TRAP}_{\text{CoT-only}},
and TRAP, which align actions, CoT, or both, respectively.
We compare each of these three attacks with its TRACO variant, retaining
the corresponding alignment loss terms.
Implementation details
Unless otherwise specified, global perturbations use an ℓ∞\ell_{\infty}
bound of ϵ=8/255\epsilon=8/255.
Patches cover approximately 3.5%3.5\% and 4.7%4.7\%
of the image area on LIBERO and SimplerEnv, respectively.
In the global setting on LIBERO, we report TRACO results
within a budget of 15 rounds, with 30 updates per round.
In the patch setting, the budget is 10 rounds with 100 updates per round
in both environments.
We optimize each offline perturbation for 8,000 gradient updates with a
batch size of 4.
The step sizes are 1/2551/255 for LIBERO global perturbations,
4/2554/255 for LIBERO patches, and 8/2558/255 for SimplerEnv patches.
We set the PGS position tolerance to κ=4\kappa=4 cm on LIBERO and κ=8\kappa=8 cm on SimplerEnv.
We optimize each adversarial perturbation on a single NVIDIA A100 GPU
with 80 GB of memory.

V Conclusion
We introduced TRACO, a closed-loop optimization framework for visual
task-redirection attacks. It rebuilds target supervision at the states reached
under attack, enabling existing attacks to use execution feedback while
retaining their alignment objectives. Within this framework, PGS selects states
for supervision to advance the target task while preserving earlier behavior.
Experiments in simulation and on a real robot demonstrate the effectiveness
of TRACO for visual task redirection. Together, these findings highlight the
security implications of closing the loop between visual attack optimization
and execution.

chunks, while the CoT term uses target-sequence likelihood.

-C Physical Robustness
Following TRAP [10], we account for geometric projection and changes
in patch appearance during physical patch construction.

planar homography. A pixel at (u,v)(u,v) in the
canonical patch plane maps to image coordinates (x,y)(x,y) as

where 𝐇\mathbf{H} is the homography matrix and λ\lambda is the

Color calibration
For physical deployment, we calibrate colors using a printed reference
chart photographed by the robot’s camera. A third-order polynomial mapping
models the color changes introduced by printing and camera capture. We
keep this mapping fixed during optimization to predict the patch’s camera
appearance. Figure 10 illustrates the
calibration.
Expectation over transformations
We apply expectation over transformations (EoT) [48] during patch
optimization. Random brightness changes and Gaussian noise model variation
in illumination and image capture.
-D VLA Model Details
Table XI lists the VLM backbones and
action-generation interfaces used in our evaluation.
StarVLA [44] provides a modular framework that combines
pretrained VLM backbones with different action-generation modules.
Our LIBERO policies use this framework.
PI
PI follows the π0\pi_{0} design [2], coupling a VLM with a
flow-matching action expert. The expert attends to hidden states from
multiple VLM layers to generate continuous action chunks.
GR00T
GR00T [49] uses a dual-system architecture. Its VLM encodes the scene and
instruction, and a diffusion-transformer (DiT) action module uses these
features to generate continuous actions through flow matching.
FAST
FAST uses the FAST tokenizer [25] to encode action chunks
as discrete tokens. The VLM predicts these tokens autoregressively, and
the tokenizer decodes them into continuous actions.
OFT
OFT follows OpenVLA-OFT [26], using a lightweight multilayer
perceptron to predict continuous actions. This head reads hidden states
at action-token positions and predicts an action chunk in parallel.
LangForce
LangForce [45] uses learnable latent action queries to
connect the VLM to a flow-matching action head. Its training objective
rewards latent actions that help predict the instruction from the scene,
encouraging instruction-dependent behavior.
InstructVLA
InstructVLA-Generalist [27] produces CoT reasoning
before generating latent action representations.
A flow-matching action expert uses these representations and visual
features to produce continuous actions.
