  Abstract
 Long-term memory for multimodal agents remains challenging, as it must preserve fine-grained visual evidence while tracking entity evolution across sessions. Existing abstraction-based memories compress images into text, often discarding visually discriminative details, whereas pixel-preserving memories retain raw observations but struggle to reliably associate diverse observations with persistent entity identities and track their evolving states. To address these limitations, we propose  MHG-Mem , a multimodal hypergraph memory that jointly organizes entity identity, state evolution, and provenance to visual evidence. Specifically, MHG-Mem represents distinct entity mentions and their observed facts as individual nodes, grouping identity-consistent mentions and facts through occurrence hyperedges. It then synthesizes aspect-specific evolution states from these grouped observations and links them to supporting entities, facts, and source evidence through evolutionary and evidential hyperedges. To navigate this structured memory, we introduce hypergraph-based agentic search, which adaptively selects an entry layer, traverses typed hyperedges across memory levels, and inspects source observations when fine-grained verification is required. These designs support both detailed visual verification and reasoning over cross-session state changes. Extensive experiments across three benchmarks demonstrate the effectiveness of MHG-Mem, improving performance by 8.20–9.98% over the strongest baseline.
  1  Introduction
 Long-term memory enables large language model (LLM) agents to reuse past experience beyond their context windows  ( Packer et al., 2023 ;  Xu et al., 2025 ) . As agents increasingly browse websites and interact with users through images, multimodal memory becomes essential for understanding user needs and providing personalized assistance  ( Guo et al., 2026 ;  Liu et al., 2026a ) . As shown in Fig.   1  (a), a web agent encounters several backpacks across sessions, with varying page layouts, product views, prices, and availability. Subsequent queries require  inspecting the main zipper of the purchased backpack  (Q1) or  determining whether an earlier offer for the same backpack was both cheaper and in stock  (Q2). Answering these queries remains challenging. Memory must preserve fine-grained visual evidence while tracking the entity’s state across sessions despite variations in its visual observation.
  Figure 1:  (a) Long-term agent–user multimodal interaction example. (b) Comparison of existing approaches: (i) Abstraction-based memory loses visual details (failing Q1, Q2); (ii) Pixel-preserving memory lacks persistent identity–evolution bindings (failing Q2); (iii) Our MHG-Mem organizes multimodal observations via typed hyperedges, preserving both fine-grained visual crops for inspection and traceable evolution across diverse entity mentions. 
 Existing multimodal memories address these requirements only partially.
As illustrated in Fig.   1  (b),  abstraction-based memory  converts visual observations into textual descriptions or structured records for subsequent consolidation and retrieval  ( Wang and Chen, 2025 ;  Feng et al., 2026 ) .
Such abstractions may omit visual details needed for inspection or for distinguishing similar entities.
 Pixel-preserving memory  retains original images, allowing relevant observations to be retrieved and inspected at query time  ( Lu et al., 2026 ) .
Yet the retrieved images remain isolated observations. Nothing records that the product photo in one session and the listing page in another show the same backpack, or how its price and availability evolved.
Without reliable associations, an agent may confuse similar entities or incorrectly combine attributes in different observations.
These raise the question:
 How can multimodal memory organize visually diverse observations of the same entity into coherent state histories while keeping each state traceable to its supporting evidence? 
 Addressing this question requires preserving individual observations while explicitly organizing how they relate across sessions. The underlying memory structure is inherently  higher-order : the same entity may be observed differently across sessions, with each observation jointly associating several entity mentions, facts, and visual evidence, while its evolutions must integrate these observations into coherent state histories. These relationships therefore extend beyond isolated entities or facts and naturally form structured groups at different semantic levels. Motivated by this, we propose  MHG-Mem , a multimodal hypergraph memory that uses typed hyperedges to explicitly organize these higher-order relationships while preserving each observation separately. Specifically, occurrence hyperedges group identity-consistent entity mentions and their associated facts across sessions, evolution nodes summarize aspect-specific state changes from temporally ordered observations, and evolutionary and evidential hyperedges connect each evolution to the participating entity mentions and its supporting facts, respectively. Because these facts retain provenance to the original dialogue and images, each inferred state remains traceable to its source evidence.
 This structured memory naturally exposes evidence at multiple granularities, but different queries require different retrieval paths. Q1 ultimately requires inspecting a particular source image, whereas Q2 requires first locating the backpack’s state history and then verifying the facts underlying the relevant price and availability states. A fixed retrieval strategy therefore cannot serve both effectively. To this end, we introduce  Hypergraph-based Agentic Search , which adaptively selects an entry layer, traverses typed hyperedges across entity, evolution, and fact-level memory, and follows provenance links to inspect source observations when necessary. In this way, compact evolution records guide cross-session reasoning, while grounded facts and images provide fine-grained, verifiable evidence.
Our contributions are summarized as follows:
  •  
 We propose  MHG-Mem , a multimodal hypergraph memory framework that organizes cross-session observations into coherent entity evolution histories through typed hyperedges, while preserving visual evidence and state-specific provenance.
  •  
 We introduce  Hypergraph-based Agentic Search , which adaptively accesses entity groups, state histories, and their supporting observations to assemble query-relevant evidence across granularities.
  •  
 Experiments across three benchmarks and three backbones demonstrate MHG-Mem’s effectiveness, improving average performance by 8.20–9.98% over the strongest baseline.
  2  Related Work
  Long-Term Multimodal Agent Memory. 
As agents increasingly interact with the physical and digital world, long-term memory research has expanded beyond text-centric systems  ( Packer et al., 2023 ;  Xu et al., 2025 ;  Kang et al., 2025 ;  Chhikara et al., 2025 ;  Zhong et al., 2024 ;  Yuan et al., 2026 )  to multimodal retrieval  ( Chen et al., 2022 ;  Yeo et al., 2026 ;  Tang et al., 2026 ) , episodic video memory  ( Jeong et al., 2025 ;  Fan et al., 2025 ) , and multimodal conversational memory  ( Bei et al., 2026 ;  Maharana et al., 2024 ) . Recent benchmarks further examine whether agents can retain action trajectories, and visually evolving states across long-horizon interactions  ( Liu et al., 2026a ;  Guo et al., 2026 ) . Existing systems address important aspects of this problem by compressing observations into semantic abstractions  ( Wang and Chen, 2025 ;  Feng et al., 2026 ;  Jain et al., 2025 ) , organizing experiences around entities or events for cross-session reasoning  ( Long et al., 2025 ;  Chen et al., 2026 ;  Nguyen et al., 2026 ;  Liu et al., 2026b ) , and retrieving evidence across modalities or memory stores  ( Kang et al., 2026 ;  Lu et al., 2026 ;  Tian et al., 2026 ) .
Yet these capabilities remain difficult to reconcile: semantic abstraction improves memory organization but may discard visual cues needed to distinguish similar observations, while preserving raw pixels alone does not establish which observations refer to the same entity or how their attributes evolve over time.
MHG-Mem jointly addresses these challenges by preserving multimodal occurrences, associating them with persistent entity identities, synthesizing aspect-specific state histories, and grounding each state in supporting facts and source images within a typed hypergraph, enabling agentic search to traverse between compact abstractions and verifiable evidence.
  Hypergraph-based Agent Memory.  Graph memory has evolved from knowledge graphs  ( Rasmussen et al., 2025 ;  Gutierrez et al., 2024 ) , toward entity-centered graph such as M3-Agent  ( Long et al., 2025 )  and query-aware evidence expansion in GraphMemix  ( Li et al., 2026 ) . Hypergraph methods then make higher-order membership explicit: HyperGraphRAG  ( Luo et al., 2025b )  represents    n  n   -ary facts for corpus-level RAG, HGMEM  ( Zhou et al., 2025 )  uses hypergraph working memory for multi-step reasoning, and HyperMem  ( Yue et al., 2026 )  organizes long conversations as topic–episode–fact hypergraphs with coarse-to-fine retrieval. Despite their effectiveness, these approaches remain largely confined to text-centric memory organization, limiting their applicability to information-dense and dynamically evolving multimodal agent interactions. In contrast, MHG-Mem uses typed hyperedges to jointly organize persistent multimodal occurrences, entity-specific aspect evolutions and provenance, enabling identity-aware state tracking and fine-grained visual verification within a unified long-term memory framework.
  3  Methodology
 To track entity states across sessions while preserving their supporting evidence, we propose MHG-Mem, a multimodal hypergraph memory framework. Typed hyperedges organize entity mentions, facts, and state evolutions into reusable histories while retaining observation-specific visual evidence and links from individual states to their sources. Hypergraph-based agentic search then adapts retrieval to the query, navigating these histories and inspecting the underlying evidence as needed.   4  Experiment
  4.1  Experimental Setup
  Benchmarks and Metrics. 
We evaluate on three multimodal memory benchmarks:
MemEye  ( Guo et al., 2026 ) , Mem-Gallery  ( Bei et al., 2026 ) , and
WorldMemArena-S (subset)  ( Liu et al., 2026a ) .
We report exact match (EM) for MemEye’s
multiple-choice (MCQ) questions, token-level F1 for the other two benchmarks,
and BLEU-1 (B-1) and LLM-as-a-judge (Judge) score for open-ended answers on all
three.
For memory quality evaluation, we follow  ( Liu et al., 2026a )  using the same judging rubrics, recall, and retrieval coverage. Dataset and metric details are provided in Appendix   C.1  .
  Implementation Details. 
We use Qwen3-VL-8B  ( Bai et al., 2025 ) , GPT-4.1-mini  ( OpenAI, 2025 ) , and Qwen3.8-27B  ( Qwen Team, 2026 )  as different memory backbones, GPT-5.4-mini  ( OpenAI, 2026 )  as LLM-as-a-judge model.
MHG-Mem uses all-MiniLM-L6-v2 for text embeddings and SigLIP2  ( Tschannen et al., 2025 )  for visual and cross-modal embeddings.
For a fair comparison, we reproduce all baseline methods with the same model setting and running environment of MHG-Mem. Results are averaged over 3 runs. Additional implementation settings are provided in Appendix   C.2  .
  Baselines. 
We compare with four unimodal memory methods using dense image caption:
A-Mem  ( Xu et al., 2025 ) , MemoryOS  ( Kang et al., 2025 ) ,
SimpleMem  ( Liu et al., 2026c ) , and HyperMem  ( Yue et al., 2026 ) ;
and four multimodal memory or RAG methods:
M2A  ( Feng et al., 2026 ) , MMA  ( Lu et al., 2026 ) ,
SRAG  ( Guo et al., 2026 ) , and UniversalRAG  ( Yeo et al., 2026 ) .
Detailed baseline descriptions are deferred to
Appendix   C.3  .

  4.2  Main Results
 Table   1   compares MHG-Mem with eight memory systems across three benchmarks and three backbones. Figure   3   shows memory quality on WorldMemArena-S and fine-grained task performance on WorldMemArena-S and Mem-Gallery.
We highlight four key findings:
  (1) MHG-Mem consistently outperforms existing memory systems across benchmarks and backbones. 
MHG-Mem achieves the highest Judge score in every benchmark–backbone setting, with Avg. J. scores of 57.98% ( +8.20% ), 67.95% ( +9.89% ), and 73.28% ( +9.98% ) on Qwen3-VL-8B, GPT-4.1-mini, and Qwen3.8-27B, respectively.
Moreover, MHG-Mem achieves the best or second-best results on metrics including EM, BLEU-1, and F1. These consistent improvements across models and benchmarks demonstrate the effectiveness and generalization of provenance-preserving multimodal hypergraph memory.
  (2) Effective visual memory requires structured access to preserved observations. 
On the visual-centric MemEye benchmark, MHG-Mem with Qwen3.8-27B achieves 78.76% EM, compared with 67.85% for UniversalRAG and 66.95% for SRAG.
A similar advantage appears in visually demanding categories in Figure   3  (b): MHG-Mem achieves 82% versus 60% on visual reasoning (VR) in Mem-Gallery and 87% versus 83% on visual fact recall (VFR) in WorldMemArena-S.
These results suggest that retaining images alone is insufficient when relevant observations cannot be reliably associated with the underlying entity.
Occurrence hyperedges address this limitation by grouping visually diverse mentions of the same referent while preserving direct access to observation-specific visual evidence.
  (3) Substantial performance gains on temporal and cross-modal reasoning. 
MHG-Mem achieves the best performance in 17 of the 19 task categories in Figure   3  (b), with particularly large gains on tasks requiring integration of observations across sessions.
On WorldMemArena-S, temporal reasoning (TR) improves from 48% to 87% over the strongest baseline, while dynamic update (DU), test-time learning (TTL), and cross-modal reasoning (CMR) improve by 17%, 17%, and 15%, respectively.
On Mem-Gallery, visual reasoning (VR) and temporal reasoning (TR) improve by 18% and 17%.
These gains are supported by our evolution design, which summarize time-ordered entity states to guide retrieval, together with evidential hyperedges that preserve state–fact correspondence and enable provenance tracing from synthesized states back to the originating dialogue and images.
  (4) Memory quality and evidence accessibility improve together. 
As shown in Figure   3  (a), MHG-Mem achieves the highest memory recall, memory correctness, and retrieval coverage among all compared systems.
The simultaneous improvement in memory quality and coverage indicates that MHG-Mem preserves useful information accurately while keeping its supporting evidence readily accessible.

  4.3  Ablation Study
 Tables   3   and   3   evaluate memory construction and retrieval components using the average LLM-judge score across the three benchmarks.
Memory components are introduced cumulatively, whereas retrieval components are removed individually. Specifically,  w/o Agentic Search  replaces agentic search with three-layer top-   k  k    retrieval;  w/o Inspection Tool ,  w/o Cross-layer Traversal , and  w/o Visual Tool  disable the corresponding functionality.
 Memory-side ablation.
  (1) Effectiveness of the entity node with occurrence hyperedge. 
The entity layer with occurrence hyperedges improves performance by     5.48  %   5.48\%    over fact-only memory. Occurrence hyperedges account for     4.78  %   4.78\%    of this gain, with improvements across all three benchmarks. These hyperedges connect mentions and facts associated with the same entity, enabling retrieval of its observations across sessions.
 (2) Effectiveness of the evolution node with evolutionary hyperedge. 
The evolution layer with evolutionary hyperedges yields a further     3.37  %   3.37\%    improvement. This representation makes state histories directly retrievable and associates them with entities in subject and coactor roles, supporting reasoning about changes across sessions.
 (3) Effectiveness of the evidential hyperedge. 
Evidential hyperedges provide an additional     1.56  %   1.56\%    gain by linking evolution states to their supporting facts. These connections preserve provenance and allow retrieved states to be checked against the observations from which they were derived.
 Retrieval-side ablation.
  (1) Effectiveness of agentic search. 
Three-layer top-   k  k    retrieval underperforms agentic search by     5.10  %   5.10\%   , the largest decline among the retrieval ablations. This result supports query-adaptive selection of retrieval entry points and subsequent evidence expansion.
 (2) Effectiveness of the inspection tool. 
Without source inspection, performance falls by     3.44  %   3.44\%   , the largest decline among individual tool ablations. Access to original dialogue and images enables the agent to verify fine-grained evidence that facts and evolution summaries may omit.
 (3) Effectiveness of cross-layer traversal. 
Removing cross-layer traversal reduces performance by     3.09  %   3.09\%   . Traversal connects entities to their associated facts and evolution records to supporting observations, allowing the agent to assemble evidence across memory granularities.
 (4) Effectiveness of the visual tool. 
Performance decreases by     1.37  %   1.37\%    when image retrieval is disabled. Direct visual search provides a complementary route to relevant observations, extending evidence access beyond entity- and evolution-centred retrieval.

  4.4  Case Analysis
 Figure   4   illustrates the advantages of MHG-Mem in a home renovation scenario involving successive living room color schemes. To identify the scheme the user did not adopt, the memory system must trace the progression from color trials through revisions to completion and inspect the corresponding images. UniversalRAG and M2A retrieve bedroom images by similarity but miss the initial color information, while MMA preserves the pixels without tracking the evolving schemes. MHG-Mem identifies  paint  as the tracked entity, preserves its mentions across rounds, and links atomic facts through occurrence hyperedges. Evolution nodes record the change in candidate color from sage green to terracotta. During retrieval, the agent follows evidential hyperedges to  f56  and  f129 , then inspects their source images to verify the colors and answer correctly.
 Conclusion
 We presented MHG-Mem, a multimodal hypergraph memory framework that organizes visually diverse observations of the same entity into coherent state histories while preserving fine-grained visual evidence. Typed n-ary hyperedges connect entity mentions, atomic facts, and evolution records, keeping individual states traceable to their supporting observations. Hypergraph-based agentic search adaptively navigates these memory levels, using state histories to guide retrieval and original dialogue and images to verify evidence. Ablations demonstrate the contributions of entity associations, explicit state histories, evidence grounding, and adaptive retrieval. These findings support the joint design of memory organization and evidence access for reasoning over evolving multimodal experience.

  Appendix C  Additional Experimental Details
  C.1  Benchmarks and Metrics
 MemEye.
 MemEye  ( Guo et al., 2026 )  evaluates visual memory along two axes:
visual evidence granularity, from scene-level to pixel-level details,
and memory reasoning depth, from atomic retrieval to evolutionary
synthesis. It contains eight everyday scenarios and 371 questions, each
with paired multiple-choice and open-ended versions. These tasks require
agents to recover visually grounded facts, distinguish similar instances,
and reason over observations accumulated across sessions.
 Mem-Gallery.
 Mem-Gallery  ( Bei et al., 2026 )  evaluates long-term multimodal
conversational memory using persona-driven dialogues across 20 scenarios.
The evaluated release contains 240 sessions, 3,962 dialogue rounds,
1,490 images, and 1,711 open-ended questions. It probes memory extraction,
reasoning, and knowledge management over extended text–image histories.
 WorldMemArena-S.
 WorldMemArena  ( Liu et al., 2026a )  evaluates memory in GUI and
embodied-agent trajectories, as well as lifelong personal and project
interactions. We use its released 150-sample subset, denoted
WorldMemArena-S, containing 7,906 questions. Its 11 question types cover
textual memory, visual memory, and reasoning, including factual recall,
dynamic updates, conflict resolution, and cross-modal reasoning.
Evaluation follows the annotated QA checkpoints: MHG-Mem constructs
memory from only the sessions covered by each checkpoint. Prefix
checkpoints reuse the corresponding historical state, while non-prefix
session windows are constructed independently to prevent access to
out-of-scope observations.

  C.3  Baselines
 A-Mem.
 A-Mem  ( Xu et al., 2025 )  organizes textual memories as interconnected
notes inspired by the Zettelkasten method. It enriches each note with
contextual descriptions and indexing attributes, establishes links to
related notes, and updates existing memories as new observations arrive.
 MemoryOS.
 MemoryOS  ( Kang et al., 2025 )  maintains short-term, mid-term, and
long-term memory. Storage, updating, retrieval, and generation modules
coordinate the transfer and consolidation of conversational information
across these tiers to support persistent user knowledge and preferences.
 SimpleMem.
 SimpleMem  ( Liu et al., 2026c )  compresses interactions into compact,
self-contained textual memory units. Its pipeline combines semantic
structured compression, online semantic synthesis, and intent-aware
retrieval planning to reduce redundancy and assemble query-relevant
context. The unimodal category refers to textual memory representations.
 HyperMem.
 HyperMem  ( Yue et al., 2026 )  organizes long-term conversations into
topic, episode, and fact levels. Hyperedges group associated episodes
and facts, while hybrid lexical–semantic indexing and coarse-to-fine
retrieval recover related information across these levels.
 M2A.
 M2A  ( Feng et al., 2026 )  combines an immutable raw-message store with a
semantic-memory store of higher-level observations. A conversational
agent and a memory manager coordinate memory updates and iterative
retrieval, retaining links between semantic memories and their original
multimodal evidence.
 MMA.
 MMA  ( Lu et al., 2026 )  is a confidence-aware multimodal memory agent.
It combines semantic relevance with memory reliability, estimated from
source credibility, temporal decay, and conflict-aware consensus, to
reduce reliance on stale or conflicting observations.
 SRAG.
 SRAG denotes the multimodal Semantic RAG baseline in
MemEye  ( Guo et al., 2026 ) . It ranks historical records by combining
text and image embedding similarities and supplies retrieved text and
associated original images to the answer model. It provides a direct
retrieval comparison to methods that construct additional memory
abstractions or relational structures.
 UniversalRAG.
 UniversalRAG  ( Yeo et al., 2026 )  routes queries to corpora
organized by modality and granularity. Modality-aware routing selects
the appropriate evidence source, while retrieval at different
granularities supplies context for answer generation.

In particular,  resolve_fact  and  get_raw_verbatim  are invoked most frequently, suggesting that many questions can be traced through atomic facts and verified against original dialogue or visual evidence. Entity- and evolution-layer retrieval also accounts for substantial usage in TTL, TR, KR, DU, and VU tasks. This pattern suggests that, for temporal reasoning and multimodal updates, the agent links observations of the same entity and retrieves relevant state histories to reason about attribute updates, conflicts, and replacements.

  D.2  Cost Analysis
 Figure   6   compares token consumption and QA performance across methods. Following prior work, we measure the average total number of LLM input and output tokens per sample across memory construction, retrieval, and QA. For multimodal methods, this count also includes image input tokens determined by the corresponding LLM’s visual encoding. We additionally report MHG-Mem (w/o A.S.), an ablation that replaces agentic search with top-   k  k    hypergraph retrieval.
 Among the baselines, unimodal memory methods that abstract images into textual captions consume fewer tokens but achieve lower QA performance, as fine-grained visual details are omitted. Among multimodal methods, RAG-based approaches (SRAG, MMA, and UniversalRAG) require fewer tokens than memory-based approaches (M2A and MHG-Mem) because they avoid explicit memory construction and iterative search. Although MHG-Mem improves benchmark-averaged QA performance by 8.20–9.98 points over the strongest baseline for each backbone, it consumes approximately 2x tokens, reflecting both the processing of multimodal information during memory construction and iterative tool calls during retrieval. The additional cost primarily arises from agentic search: MHG-Mem (w/o A.S.) requires only approximately 1–2k more tokens than multimodal baselines while still delivering performance gains of 5%–15%, offering a favorable balance between cost and performance. These results suggest using similarity-based hypergraph retrieval in resource-constrained settings and agentic hypergraph search when higher QA performance is the priority.

  D.3  Memory Quality and Fine-grained Analysis on More Backbones
 Figure   7   and   8   extend the memory quality and task-level analysis to Qwen3-VL-8B and GPT-4.1-mini, respectively. Across both backbones, MHG-Mem achieves the highest memory correctness and update handling, with retrieval coverage among the best. These results show that effective state maintenance coexists with accurate memory retention and strong evidence coverage, consistent with our objective of organizing evolving observations while keeping their supporting evidence accessible.
 The most consistent task-level advantages concern visual evidence use and state evolution. On WorldMemArena-S, MHG-Mem outperforms all compared baselines in cross-modal reasoning, temporal reasoning, dynamic updates, and visual updates with both backbones. In particular, cross-modal reasoning improves over the strongest baseline by 20% and 6% with Qwen3-VL-8B and GPT-4.1-mini, respectively. On Mem-Gallery, visual-centric reasoning improves by 4% and 6%, while knowledge resolution improves by 5% under both backbones; conflict detection also benefits in both settings. These recurring gains align with the two requirements motivating MHG-Mem: accessing relevant visual observations and integrating changes across interaction histories. They are consistent with the intended role of entity histories and state-specific evidence links in supporting comparison and verification across observations.
 The improvements nevertheless depend on the task and backbone. For example, Mem-Gallery temporal reasoning improves by 3% with Qwen3-VL-8B but remains 6% below the strongest baseline with GPT-4.1-mini. MHG-Mem also trails the strongest factual-recall baseline on both benchmarks under both backbones. Thus, the memory-quality improvements do not translate uniformly into every downstream capability: visual evidence use and state updates show reproducible benefits, while factual recall remain areas for improvement.

  Appendix E  Prompt Templates
 The five prompt templates below cover memory construction (Appendix   B.2  )
and agentic search (Table   4  ). We preserve prompt wording and
placeholders, omit Python assignment wrappers, and adjust line wrapping for readability. For additional LLM-as-a-judge and QA prompts, we use the original benchmark-provided prompts to ensure fair comparisons.
  E.1  Atomic fact construction
 Converts the current round into standalone facts while retaining temporal and visual details.
  01  Atomic fact construction  
  You convert ONE conversation round into a set of ATOMIC MEMORIES — short, standalone facts that a separate answerer will later retrieve to answer questions. You are given the round’s dialogue text, its image caption(s), and its REAL image(s). You may also see up to three EARLIER rounds of the same conversation as read-only context (their text and image captions only — no earlier pictures), and a list of EXISTING MEMORIES already stored from past rounds. Write memories ONLY for the CURRENT round; use the earlier rounds and the current image(s) just to understand the round and to resolve references.  
  Read BOTH the caption AND the real pixels of the current round. The caption often spells a detail out in words (card names, on-screen text, dashboard labels, message transcripts); the pixels carry details the caption omits (colors, counts, spatial layout, what is actually shown). Capture from both.  
  ## ADD-ONLY against EXISTING MEMORIES  
  If an `## EXISTING MEMORIES` list is given, treat it as memories that are ALREADY STORED. Your job is ADDITIVE: output the facts from the CURRENT round that are NOT already represented there. Do not restate, paraphrase, or lightly reword an existing memory. Never create a memory from the existing list alone — every memory you output must be supported by the CURRENT round.  
  - Default to WRITING a fact. Suppress a candidate ONLY when it is the SAME fact about the SAME moment as an existing memory. When in doubt, WRITE it — a missed fact can never be recovered, a near-duplicate is cheap.  
  - The mere presence of the same entity, brand, game, route, dashboard, or template in an existing memory does NOT make the current round a duplicate. A new event, a new state, a changed value, a different date/session, a new opinion or conclusion the user draws, or any new detail is ALWAYS a new memory — write it.  
  Write each memory to this STANDARD:  
  - ATOMIC & self-contained: one fact per memory — a single event, state, attribute, or relationship — understandable on its own. Begin from the concrete named subject.  
  - ABSOLUTE time: anchor every time reference to the Observation Date given. Convert "today / tomorrow / yesterday / last week / this Monday" to an explicit calendar date (YYYY-MM-DD). Never store a bare relative time or weekday.  
  - DESCRIBE the state, do NOT compute the answer. Record what is shown or said — list the cards in a hand, the panels on a dashboard and their values, the people in a chat and who said what. Do NOT add totals, counts across rounds, winners, comparisons, or any conclusion the data merely implies. Faithful state, never a frozen verdict.  
  - CAPTURE what a later question could ask: numbers, colors, spatial relations (left / right / above / below / lower-left / behind / beside / under), in-image text, per-item attributes, who did what, and any change from the earlier context.  
  - Only return an empty list when the CURRENT round genuinely contains NOTHING beyond what is already stored (e.g. a bare "ok", "thanks", "correct" with no new content of its own).  
  Return ONLY JSON:  
  {"atomic_facts":["<one standalone memory>","<another standalone memory>"]}  
  If the round carries nothing new worth remembering, return {"atomic_facts":[]}.  
  E.2  Multimodal entity extraction
 Extracts nameable entities and grounds visual or multimodal mentions in image regions.
  02  Multimodal entity extraction  
  You extract MULTIMODAL ENTITIES from ONE conversation round (its dialogue text AND its image, if any).  
  An ENTITY is a persistent, nameable THING that could be asked about later — for example: a brand, logo, product. This list is illustrative, not exhaustive — extract any concrete, nameable thing a later question could point at  
  Give each entity ONE modality, decided by WHERE you learned about it:  
  - `visual`: something you can SEE in the image. This is the DEFAULT for anything in the picture — objects, people, places, logos, products, signs, on-screen panels. Give it a short specific name (e.g. "red delivery truck", "Coca-Cola logo"). bbox required.  
  - `multimodal`: visible in the image AND also named in the dialogue text. Name it from the dialogue; the box is on the region that shows it. bbox required.  
  - `text`: named in the dialogue text (what the USER or ASSISTANT actually typed) but NOT visible in the image. bbox is null. This is RARE — use it ONLY for things mentioned in the conversation that you cannot see.  
  For every `visual` and `multimodal` entity, bbox is absolute pixels `[x0,y0,x1,y1]` in the image’s pixel frame, tight around the thing.  
  Return ONLY JSON:  
  {"entities":[{"name":"…","type":"<brand|person|character|object|product|place|animal|organization|other>","modality":"visual|multimodal|text","bbox":[x0,y0,x1,y1] or null}]}  
  Rules:  
  - Only extract things written in the dialogue or clearly visible in the image — never invent.  
  - If nothing qualifies, return {"entities":[]}.  
  E.3  Occurrence linking
 Associates a candidate mention with a stored referent, creates a new referent, or rejects an invalid extraction.
  03  Occurrence linking  
  You decide how to store ONE candidate entity into a memory of already-known entities.  
  You are given:  
  - ROUND CONTEXT: the conversation round the candidate was found in (its text, and the full round image if any) — use it to understand what the candidate actually is.  
  - CANDIDATE: its name, type, modality, and, if visual, its cropped region (shown below).  
  - MATCHES: most similar to the candidate (by text and visual similarity), each with its best-matching stored region (shown below).  
  Choose EXACTLY ONE action:  
  - `update`: the candidate is the SAME real-world thing as one MATCH— link to that entity id. Also use `update` for a repeat sighting of a thing already stored, to record this new occurrence.  
  - `add`: the candidate is a REAL entity but none of the MATCHES is the same real-world thing.  
  - `skip`: ONLY when the candidate is NOT a real, storable entity (an extraction mistake or abstract concept).  
  Return ONLY JSON:  
  `{{"action":"update|add|skip","target_entity_id":"<id, only if update>","add_alias":"<optional new alias>","reason":"<one line>"}}`  
  E.4  State evolution synthesis
 Identifies changing aspects and binds each reported state to its supporting fact identifier.
  04  State evolution synthesis  
  You are given ONE referent (a thing that recurs in a long conversation) and the time-ordered list of ATOMIC FACTS recorded about it. Your job is to report which ASPECTS of this referent actually CHANGED over time.  
  An ASPECT is a single named property that can hold different values at different times — for example: hand_size, location, owner, color, price, status, score, version, participants, weight.  
  ## What counts as a change  
  A change means: the SAME aspect of the SAME referent holds DIFFERENT values at different times. For example:  
  - "is in the kitchen" then "is in the bedroom"-> aspect `location` CHANGED. Report it.  
  - "costs $12" then "costs $9"-> aspect `price` CHANGED. Report it.  
  ## What does NOT count as a change (this is the common case — read carefully)  
  - A value stated repeatedly, or restated in different words, is NOT a change.  
  - New, additional details about DIFFERENT aspects are NOT a change unless one aspect’s own value is replaced by another value.  
  ## How to write what you find  
  For each aspect that genuinely changed:  
  - `aspect`: a short lowercase snake_case key naming the property (`hand_size`, not "the size of the hand").  
  - `states`: two or more entries in TIME ORDER. Each entry MUST carry:  
  - `value`: the value at that time, as short as possible (a number, a color, a place, a name).  
  - `fact_id`: the id of the fact you read that value from. It MUST be one of the fact ids listed below, copied exactly. Never invent an id.  
  - `summary`: one sentence DESCRIBING the observed states in order, with their dates.  
  - `update_type`: one of  
  - `replacement` — the new value replaces the old one (a measurement, a location, a price)  
  - `correction` — the later fact says the earlier one was wrong  
  - `addition` — the value grew by accumulating items rather than being replaced  
  Return ONLY JSON:  
  {"aspects":[{"aspect":"<snake_case>","states":[{"value":"<v1>","fact_id":"<id>"},{"value":"<v2>","fact_id":"<id>"}],"summary":"<one sentence describing the states in order>","update_type":"replacement|correction|addition"}]}  
  If no aspect of this referent changed, return exactly {"aspects":[]}.  
  E.5  Hypergraph-based agentic search
 Guides sequential tool use to assemble evidence for the separate answer model.
 The placeholders  [MEMORY_SCHEMA] ,  [TOOL_SCHEMA] , and  {max_steps}  denote the memory schema, tool definitions, and search budget, respectively. The five gathering tools collect evidence;  submit_evidence  terminates retrieval.
  05  Hypergraph-based agentic search  
  You are a hypergraph memory retriever. Given a QUESTION, you SEARCH a long-term multimodal memory of past conversation rounds and assemble an EVIDENCE CHAIN for a separate QA model. You do NOT answer the question yourself.  
  ## What is in memory: [MEMORY_SCHEMA]  
  ## Tool Definition: [TOOL_SCHEMA]  
  ## Format — EXACTLY ONE action per reply, nothing after it  
  Each reply MUST be exactly:  
  ```  
  Action: <one tool name>  
  Action Input: {{<json>}}  
  ```  
  STRICT RULES:  
  - Output ONE Action, ONE Action Input, then STOP. Do NOT write a second Thought/Action in the same reply — you will only see the result of the FIRST action, so any extra ones are wasted.  
  - After `Action Input: {{…}}` write NOTHING more. Do not narrate, do not plan further steps.  
  - you will receive `Observation: {{…}}` (and any images). Read it, then send your NEXT single action.  
  When the evidence is sufficient, call submit_evidence.  
  ## Strategy  
  - You have five hypergraph gathering tools; use whichever fit the question. Call ONE per turn and read its Observation before the next.  
  - If the question hinges on a visual/pixel detail, open the most promising facts’ rounds with get_raw_verbatim (or use search_image) so you actually SEE the images before citing.  
  - Be efficient: you have at most {max_steps} steps. Submit as soon as the evidence is sufficient.
