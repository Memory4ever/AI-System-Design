PACE: Periodic and Channel-Aligned Encoding
of Four-Bit Recurrent States
Patrick Haller
Filipe Laitenberger
Alan Akbik
Abstract
Linear-attention language models keep their context in a recurrent state of fixed size, where an inference system stores one copy of this state for every sequence it decodes at the same time. Storing the state at lower precision therefore lets more sequences share an accelerator. Existing state quantizers round the state after every generated token and report that four bits lose accuracy unless the bit width is raised or the model is fine-tuned.
We introduce PACE, a post-hoc four-bit state quantizer. PACE rounds the state only once every few generated tokens, as chunked kernels already do once per chunk during prefill, and keeps the tokens generated in between in a small buffer. Rounding less often reduces the error that accumulates in the state. Additionally, we find that the large entries of the gated-delta state gather in columns, because some channels of the update written at each token remain large across many tokens. PACE therefore shares each quantization scale within one column. It also keeps the heads that retain rounding error longest at eight bits. On four hybrid models from 4B to 35B parameters, PACE with mixed four- and eight-bit heads is competitive with eight-bit DAMP on the three larger models at about two thirds of its memory, PACE with four-bit heads throughout scores higher than Q-Mamba at equal memory, and rounding every few tokens preserves the decoding speedup of the buffer.

1 Introduction
Linear-attention language models replace the key–value cache of a Transformer with a recurrent
state of fixed size and have become competitive with Transformers [ 32 , 31 ] .
Every recurrent layer holds one state matrix per head, and a server stores one copy for every
sequence it decodes at the same time. At 64 concurrent sequences, the fp32 states take between 10
and 41 % of the memory that weights and states occupy together. Storing the state at lower
precision lets more sequences fit on the same accelerator.
Existing state quantizers [ 5 , 4 , 33 , 21 ]
differ in how they scale and round the state, and all of them round it after every generated token.
With per-token rounding, the methods that evaluate a four-bit state report a loss in accuracy (Figure 1 ). The published remedies either
raise the bit width to eight bits or fine-tune part of the model weights. NVIDIA et al. [20] round the state less often, but only with eight or more bits per value.
During prefill, chunked kernels process 64 64 to 1,024 1{,}024 tokens at a time
and write the state only at the end of each chunk, so every published quantizer already rounds the
prefill state once per chunk. During decoding the kernel is called once per generated token, so the
state is written, and rounded, after every token (Figure 2 a).
In this work, we introduce PACE (Periodic And Channel-aligned state Encoding), a post-hoc four-bit
state quantizer that requires no training (Figure 2 ). During decoding, PACE
rounds the state once every d ​ P dP generated tokens (the decode period) instead of after every token (\scriptsizeA⃝). The tokens
generated in between are held in a decode buffer, a small store of recent keys and values from which
the state is advanced in one step. Recent serving work uses such buffers to speed up decoding
[ 36 , 16 , 15 ] . The buffer occupies memory, and
every memory total we report counts it together with the state (\scriptsizeB⃝).
The gated-delta state has one row per key dimension and one column per channel of the delta value,
the vector the recurrence writes into the state at each token. Channels that stay large across many
tokens produce columns of large entries, and when the channels are permuted at every token, the large
entries no longer form columns (Section 4 ). PACE therefore forms each scale group
from the entries of one column, that is, along the key axis (\scriptsizeC⃝). PACE has two variants:
PACE-4 keeps all heads at four bits, and PACE-4/8 keeps the quarter of heads in each layer that retain
rounding error longest at eight bits (\scriptsizeD⃝).
Our contributions are:
•
A bound on the rounding error a head retains as a function of the rounding period and the
head’s decay (Section 3 ), together with a memory accounting that includes the decode
buffer (Section 5.1 ). On four backbones, rounding every eight generated tokens
reduces the accuracy loss at every bit width below eight (Section 7.1 ).
•
The observation that the large entries of the gated-delta state form columns, explained by
channels of the delta value that stay large across tokens and confirmed by permuting those channels (Section 4 ).
•
PACE, a four-bit state quantizer with channel-aligned scale groups and head-level precision
allocation (Section 5 ), compared with DAMP and Q-Mamba on four hybrid models from 4B to
35B parameters (Section 7.2 ).
•
Triton kernels for periodic decoding with a packed four-bit state, with which we show that
rounding every few tokens keeps the decoding speedup of the decode buffer (Section 7.5 ).

2 Background and Related Work
2.1 Gated Delta Rule
Linear attention [ 12 , 26 ] removes the softmax, so that attention
becomes a recurrence over a state S t ∈ ℝ d k × d v S_{t}\in\mathbb{R}^{d_{k}\times d_{v}} per head,
S t = S t − 1 + k t ​ v t ⊤ , o t = S t ⊤ ​ q t . S_{t}=S_{t-1}+k_{t}v_{t}^{\top},\qquad o_{t}=S_{t}^{\top}q_{t}.
(1)
The state replaces the key–value cache. It holds the whole past, does not grow with context, and is read
and written at every step.
Variants differ in how S t − 1 S_{t-1} is modified before the new token is written
[ 28 , 23 , 32 , 2 ] . We work with the gated delta rule
[ 31 ] , which applies a data-dependent decay a t ∈ ( 0 , 1 ) a_{t}\in(0,1) and removes the
component of the state along the current key before writing,
S t = a t ​ ( I − β t ​ k t ​ k t ⊤ ) ​ S t − 1 + β t ​ k t ​ v t ⊤ , S_{t}=a_{t}\left(I-\beta_{t}k_{t}k_{t}^{\top}\right)S_{t-1}+\beta_{t}k_{t}v_{t}^{\top},
(2)
with write strength β t \beta_{t} . The read-out is unchanged. Expanding Eq. 2 , every write is an
outer product,
S t = a t ​ S t − 1 + k t ​ u t ⊤ , u t = β t ​ ( v t − a t ​ S t − 1 ⊤ ​ k t ) , S_{t}=a_{t}S_{t-1}+k_{t}u_{t}^{\top},\;\;u_{t}=\beta_{t}(v_{t}-a_{t}S_{t-1}^{\top}k_{t}),
(3)
where we call u t u_{t} the delta value , the part of v t v_{t} that the decayed state does not already
return for k t k_{t} , scaled by β t \beta_{t} .
2.2 Chunk-wise Kernels
Evaluating Eq. 2 token by token is sequential and memory-bound. Chunk-wise kernels
[ 32 , 31 ] split the sequence into chunks of length C C and process each
chunk from the state at its start. Writing α i = ∏ j ≤ i a j \alpha_{i}=\prod_{j\leq i}a_{j} for the cumulative decay
within a chunk, the state after C C tokens is
S C = α C ​ S 0 + ∑ i = 1 C α C α i ​ k i ​ u i ⊤ , S_{C}=\alpha_{C}S_{0}+\sum_{i=1}^{C}\frac{\alpha_{C}}{\alpha_{i}}\,k_{i}u_{i}^{\top},
(4)
and the outputs follow from S 0 S_{0} and the chunk’s own tokens by matrix multiplication. The delta values
u i u_{i} of Eq. 3 are obtained from a triangular solve over the chunk, so Eq. 4 is evaluated
with dense arithmetic rather than a loop. Only S 0 S_{0} and S C S_{C} are formed as tensors. The states at
positions inside the chunk are never written.

2.3 Decode Buffers
Decoding calls the kernel once per token, so the state is written every step and the chunk structure is
lost. Recent serving work recovers it with a decode buffer. Recent keys and values are held, and the state is
advanced once per flush, the step at which the buffered tokens are applied, instead of once per token.
This removes the per-token write of the state from memory traffic.
KVBuffer [ 36 ] derives an optimal buffer of about 23 23 tokens and reports its best
latency at 32 32 , ReplaySSM [ 16 ] uses 16 16 for Qwen3.5, and DeltaLog
[ 15 ] merges every 8 8 tokens for Gated DeltaNet. None of them quantizes the state.
2.4 State Quantization
Quantizing the recurrent state.
Quamba2 [ 5 ] stores cached states at eight bits with static scales. Q-Mamba
[ 4 ] reaches four bits by scaling the state with one vector per axis and fine-tuning
about 2% of the weights. MambaQuant [ 30 ] rotates weights and activations before
rounding and leaves the state unquantized. DAMP [ 33 ] ranks key channels by quantization error times decay persistence, keeps the riskiest in fp16 and reports 9.9 9.9 bits per
value; it rounds once per chunk in prefill and after every token in decoding. The Nemotron report
[ 21 ] keeps the state in fp16 with stochastic rounding, and NVIDIA et al. [20]
store the state every eight decoding steps at eight bits and above, in emulation. Kozyrev and Maiboroda [13]
quantize the weights and activations of the recurrent layers and leave the state unquantized.
None of them varies the rounding period below eight bits or counts the buffer it requires.
Error propagation.
Rounding a recurrence is the fixed-point filter problem [ 11 , 22 ] , in which rounding
noise of variance σ 2 \sigma^{2} , injected at every step of a recurrence with decay a a , accumulates to
σ 2 / ( 1 − a 2 ) \sigma^{2}/(1-a^{2}) . Zhang et al. [33] rederive the
accumulated error for the gated delta rule and reduce the error per rounding; we reduce the number of
roundings (Eq. 5 ). Kozyrev and Maiboroda [13] find that whole-state error stays flat from token 256 256 on. Zhao et al. [34] clip the state during quantization-aware training and
Siegel et al. [27] quantize an S4D state through its convolutional form.
KV-cache quantization.
KIVI [ 18 ] and KVQuant [ 9 ] reach two to four bits on a cache whose
entries are written once and only read, and rotation methods [ 3 , 1 , 17 ] redistribute magnitude before rounding. A recurrent state is instead re-rounded at
every write.
3 Rounding Period and Error Propagation
3.1 The Rounding Period
A quantizer can round the state only where the kernel writes it, which gives three regimes under Eq. 4
(Figure 2 a). In prefill the chunked kernel forms S 0 S_{0} as the initial state and S C S_{C} , so the state is rounded once per chunk without an additional kernel call. In unbuffered decoding each call carries one token,
S t S_{t} is formed at every step, and the period is one. Under a decode buffer the state is advanced once per flush, and the period is the number of tokens the buffer holds.
We call one choice of bit width, scale groups, buffer precision and rounding periods for the
quantized state a configuration . Each configuration carries two periods. We write P P for the prefill period, which equals the kernel chunk
length C C and which we fix at 256 256 tokens in all benchmark evaluations, and d ​ P dP for the decode period, which is the variable under study.
3.2 Error Propagation
Each rounding adds an error to the state, and the recurrence carries it forward. Between two
roundings the error is multiplied at every token by a t ​ ( I − β t ​ k t ​ k t ⊤ ) a_{t}(I-\beta_{t}k_{t}k_{t}^{\top})
(Eq. 2 ), whose norm is at most a t a_{t} for a unit-norm key. With a h a_{h} the mean decay of head
h h , an error of energy e h e_{h} injected at one rounding retains at most a h 2 ​ d ​ P a_{h}^{2\,dP} of its energy at
the next, and independent errors from successive roundings accumulate to at most
E h = e h 1 − a h 2 ​ d ​ P . E_{h}=\frac{e_{h}}{1-a_{h}^{2\,dP}}.
(5)
A longer period lowers E h E_{h} , because more decay separates two roundings. In the gated delta rule the decay is one scalar per head, so
E h E_{h} is a per-head quantity.
Finding 1. The rounding error a head retains falls with the rounding period and
rises with the head’s decay
4 Channel Structure of the Recurrent State
A group-wise quantizer divides the state of each head into scale groups of g g consecutive entries
and rounds all entries of a group with one shared step size, which is proportional to the largest
absolute entry of the group. A group runs either along the key axis, within one column of the state,
or along the value axis, within one row. When a group contains one large entry, its small entries are
rounded with a coarse step, so the error at four bits depends on which entries share a group.
Section 4.1 measures along which axis the large entries of the state cluster,
and Section 4.2 traces this structure to the delta value.
4.1 Column Structure of the State
We compute the state over 2,048 2{,}048 -token WikiText-103 sequences on all four backbones. In a representative head the large entries form columns, that is, they occur at the same value index for every key index (Figure 3 a). We quantify this with the ratio of the largest absolute entry of a group to the root mean square of its entries (max/RMS). The larger the ratio, the fewer quantization levels a typical entry of the group receives. Groups along
the value axis, which cross columns, have the larger ratio at every group width, and the difference
grows with the width (Figure 3 b).
Finding 2. The large entries of the recurrent state concentrate in columns.
4.2 Channel Identity of the Delta Value
At each token, the recurrence adds the outer product k t ​ u t ⊤ k_{t}u_{t}^{\top} to the decayed state (Eq. 3 ). A value channel that
is large across many tokens therefore accumulates in one column, and a key coordinate that is large
across many tokens accumulates in one row. Either factor could therefore produce the columns of Section 4.1 . To separate them, we recompute the state from the recurrence inputs with the channels of u t u_{t} permuted at
every token, which keeps the values of u t u_{t} but assigns them to a different channel at each token, and separately
with the entries of k t k_{t} permuted. With u t u_{t} permuted, key-axis groups have the larger max/RMS ratio on all four backbones, and with k t k_{t} permuted the difference between the two axes widens (Figure 3 c).
Finding 3. The columns of large entries in the state come from channels of the delta
value u t u_{t} that stay large across tokens.
5 Method
PACE has four components (Figure 2 ): periodic rounding \scriptsizeA⃝ with a
decode buffer \scriptsizeB⃝ (Section 5.1 ), which follow from Section 3 ;
channel-aligned scale groups \scriptsizeC⃝ (Section 5.2 ), from Findings 2 and 3; and
head-level precision allocation \scriptsizeD⃝ (Section 5.3 ), from Finding 1. PACE-4 uses
\scriptsizeA⃝–\scriptsizeC⃝; PACE-4/8 adds \scriptsizeD⃝.
5.1 Periodic Rounding with a Decode Buffer (\scriptsizeA⃝\scriptsizeB⃝)
Rounding every d ​ P dP tokens requires holding the tokens generated since the last rounding in the
decode buffer, which adds to the memory of each configuration. Prior work reports only the stored
state, that is, the b b -bit payload and its group scales [ 33 ] ; with one fp16 scale
per g g values, this gives b + 16 / g b+16/g bits per value. We define resident bits per value as the
bits of the stored state and the buffer together, divided by the number of state values. The buffer holds
( a t , k t , v t ) (a_{t},k_{t},v_{t}) per token, the key once per key head and the value once per value head, so with keys
at b k b_{k} and values at b v b_{v} bits it adds per state value
c ​ d ​ P , c = b k ​ d k / γ + b v ​ d v + 32 d k ​ d v , c\,dP,\qquad c=\frac{b_{k}\,d_{k}/\gamma+b_{v}\,d_{v}+32}{d_{k}d_{v}},
(6)
where γ \gamma is the number of value heads sharing a key head. At d ​ P = 1 dP=1 the buffer holds only the current token. Resident bits in Figure 4 and Appendix A include the buffer;
Table 6 does not. In uniform configurations, which hold every head at the same bit width, the buffer holds keys and
values at eight bits. In the mixed configuration of PACE-4/8, which holds a quarter of the heads at
eight bits, it holds the keys at four bits and the values in bf16, since
rounding the buffered values below eight bits reduces accuracy more than rounding the keys
(Appendix D ).
5.2 Channel-Aligned Scale Groups (\scriptsizeC⃝)
We store the state at four bits in channel-aligned scale groups and keep the per-token decay and the
group scales at higher precision.
Scale groups.
We divide each head’s state S ∈ ℝ d k × d v S\in\mathbb{R}^{d_{k}\times d_{v}} into groups of g g consecutive entries
along the key axis, so that each group holds g g entries of one column, and store one fp16 scale per
group (Figure 2 , \scriptsizeC⃝). Uniform configurations round symmetrically with a step size proportional to the absolute maximum of the group at b + 16 / g b+16/g bits per value; the mixed configuration uses an affine
grid per group whose zero point is stored as a b b -bit code, at b + ( 16 + b ) / 32 b+(16+b)/32 bits per value (Appendix E ). Prior work groups along the value axis
[ 33 ] . We call our groups channel-aligned because each takes its entries from one
channel of the delta value (Finding 3), whereas a group along the value axis spans columns of different
magnitude, and its step size follows the largest of them. We round to nearest throughout.

5.3 Head-Level Precision Allocation (\scriptsizeD⃝)
We hold the heads that retain rounding error longest at eight bits and the rest at four, applying the allocation criterion of Zhang et al. [33] per head instead of per channel
(Finding 1). For each head h h , we measure the energy e h e_{h} of the error that one rounding adds and
assign eight bits to the heads with the largest retained error E h E_{h} (Eq. 5 ). The ranking is computed once per checkpoint on eight
held-out windows of 2,048 2{,}048 tokens. With a quarter of the heads per layer at 8 8 bits, the payload is
0.75 ⋅ 4.625 + 0.25 ⋅ 8.75 = 5.66 0.75\cdot 4.625+0.25\cdot 8.75=5.66 bits per value, the same as DAMP INT4.
We evaluate two variants: PACE-4, a uniform four-bit state with symmetric key-axis groups of 64 64 and
an int8 buffer, and PACE-4/8, which adds head allocation, uses key-axis groups of 32 32 with an integer
zero point (Appendix E ), and holds the buffered keys at four bits and the values in bf16.
6 Experimental Setup
Models.
We evaluate Qwen3.5-4B, 9B and 27B and Qwen3.6-35B-A3B [ 24 , 25 ] , hybrids that
interleave gated-delta layers with full-attention layers. The gated-delta layers run on the fla kernels.
Benchmarks.
We evaluate on GSM8K [ 6 ] , MMLU-Pro [ 29 ] on a subset of 40 40 questions per subject ( n = 560 n{=}560 ), IFEval [ 35 ] ( n = 541 n{=}541 ), RULER variable tracking [ 10 ] at 32,768 32{,}768 tokens, and MATH-500
[ 8 , 14 ] . Perplexity is measured on WikiText-103 [ 19 ] .
All generative tasks
are zero-shot with the chat template and thinking disabled.
Baselines.
We compare against the full-precision state, against DAMP [ 33 ] and against the
decoupled scale quantization (DSQ) of Q-Mamba [ 4 ] , which we reimplement. DAMP INT8 follows the published
configuration: value-axis groups of 32 32 at eight bits, and the 16 16 of 128 128 key channels per head with the
highest error–persistence score held in fp16. It rounds the state after every generated token and
serves as our reference for resident memory; we list it at its published 9.9 9.9 bits per value. DAMP INT4 applies the same construction at a four-bit base, with 32 32 key channels per head held
at eight bits. Q-Mamba DSQ scales the state by one fp16 vector per axis, computed at each rounding; we
implement the quantizer without the fine-tuning step of the published method.
Protocol.
All benchmarks run in the LM Evaluation Harness [ 7 ] with greedy decoding. Generation
is capped at 1,024 1{,}024 tokens for GSM8K and MATH-500 and 8,192 8{,}192 for MMLU-Pro. We report GSM8K (flexible-extract filter) and MATH-500 as exact match, IFEval as prompt-level strict
accuracy, and RULER as variable-tracking accuracy. Unless stated otherwise, every quantized configuration uses a four-bit base
width and an int8 decode buffer at d ​ P = 8 dP{=}8 . Tables 1 and 2 and Appendix A come from separate evaluation runs, each with its own full-precision row.
7 Results
We first isolate the decode period (Section 7.1 ), then compare PACE with DAMP and
Q-Mamba (Section 7.2 ), test its
components one at a time (Section 7.3 ), and measure state drift

7.1 Effect of the Decode Period
To isolate the period, we use the quantizer of prior work, uniform round-to-nearest with value-axis
groups of 32 32 , at four to eight bits and d ​ P ∈ { 1 , 8 , 32 } dP\in\{1,8,32\} (Figure 4 ; per-benchmark scores in Appendix A ). Per-token rounding loses more accuracy as the width falls, and rounding every eight tokens scores above
per-token rounding at every width below eight bits on all four backbones.
The default period of eight closes most of the gap that a period of 32 32 closes, with a quarter of
the buffer memory, and matches the flush interval of DeltaLog [ 15 ] . On the three larger backbones a gap to full
precision remains at every width, concentrated in IFEval and RULER-32k. The RULER-32k gap is similar at all three decode periods, which suggests that this part of the gap arises in prefill.

the full-precision state at the same token. We run Qwen3.5-4B on the first 512 tokens of the
WikiText-103 test set [ 19 ] , round the state every d ​ P dP tokens over the whole sequence, for d ​ P dP from 1 to 64, and report the median over recurrent layers of the relative error ‖ S q − S ‖ F / ‖ S ‖ F \|S_{q}-S\|_{F}/\|S\|_{F} , which
we call drift. We compare three four-bit
quantizers: uniform INT4 with value-axis groups, DAMP INT4, and the state
quantizer of PACE-4/8 (Figure 5 ).

For all three quantizers, drift decreases as d ​ P dP grows at every token position, and the
same ordering holds on Qwen3.6-35B-A3B (Appendix B ). Drift grows more
slowly than the number of roundings, which is consistent with a decaying recurrence that removes old

7.5 Throughput
We measure decoding cost on Qwen3.5-4B on one H100 PCIe GPU at a 512 512 -token context and batch sizes
from 1 1 to 128 128 . We compare per-token decoding with a bf16 state, the decode buffer with a bf16 state
[ 36 ] , and periodic decoding at d ​ P = 8 dP{=}8 with a uniform INT4 state and an int8
buffer, for which we implement Triton kernels that apply the buffered tokens to the packed state. We
report time per output token (TPOT) and the latency of the state update (Figure 6 , Appendix F ).
Periodic rounding lets a four-bit state keep the speedup of the decode buffer. Periodic INT4 decoding
has a lower TPOT than per-token bf16 decoding from batch 16 upward, and the difference grows with batch
size, as reading and writing the per-sequence state take a growing share of each decoding step. The decode
buffer with a bf16 state accounts for most of this reduction, and the INT4 state reduces TPOT slightly
further.

8 Conclusion
We introduced PACE, a post-hoc four-bit state quantizer for gated-delta models that rounds the state
once every few generated tokens and holds the tokens in between in a decode buffer. For uniform
configurations, a period of eight tokens reduces the accuracy loss at every width below eight bits on
four backbones. This is consistent with the bound of Section 3 , under which more decay
between two roundings leaves less of each rounding error in the state. The large entries of the state
gather in columns that follow the channels of the delta value, and PACE forms each scale group from
the entries of one such column. PACE-4/8 comes close to the accuracy of DAMP INT8 on the three larger
backbones at about two thirds of its resident memory, and PACE-4 scores higher than Q-Mamba DSQ at
equal resident bits. Periodic rounding also keeps the decoding speedup of the decode buffer.
Limitations
We evaluate four hybrid models from the Qwen3.5 and Qwen3.6 families, all of which use the gated delta rule.
Periodic rounding applies to any linear-attention layer whose state can be advanced over several tokens
at once, which includes the chunked forms of gated linear attention, Mamba-2 and DeltaNet variants.
The head decays that enter the error bound, the column structure that motivates key-axis scale groups,
and the head ranking are measured only on these models. None of them is shown to carry over to
other model families, to models whose layers are all recurrent, or to token mixers with a different
update or decay.
Periodic rounding changes when the state is rounded and leaves the choice of quantizer open. Besides PACE, we evaluate DAMP INT4 and Q-Mamba DSQ under the same period. We do not test quantizers
with static scales, stochastic rounding or rotations of the state under periodic rounding.
The configuration space of periodic state quantization is large. It spans the prefill and decode
periods, the bit widths of the state and of the buffered keys and values, the axis and width of the
scale groups, and the fraction of heads held at eight bits, and we explore only part of it. The
prefill period in particular is fixed at the 256 256 -token chunk of the kernel in all benchmark evaluations, so
the effect of rounding the state more or less often during prefill is not measured.
Throughput is timed only for a uniform four-bit state; the key-axis groups and head allocation of PACE
are not timed.

Appendix D Separate Key and Value Buffer Widths
To locate which buffered tensor limits the buffer width, we round only the keys or only the values to
four bits and keep the other in bf16, with the state quantizer of PACE-4/8 at d ​ P = 8 dP{=}8 . Rounding the
values reduces accuracy more than rounding the keys (Table 5 ). The rank-one form of the
update predicts the opposite order, since a key error misaddresses both the read and the write, while a
value error affects only the write. Rounding either tensor to four
bits gives a similar relative input error, but the kernel L2-normalizes the buffered keys after
rounding, so only the direction of a key error reaches the state, while a value error enters it
unchanged.

Appendix E Integer Zero Point
The affine grid needs a zero point, and storing it as a float means an entry that has decayed to zero
is rounded to a nonzero value at every rounding. We snap the zero point onto the payload grid and store it
as a b b -bit code, so the side information is ( 16 + b ) / 32 (16+b)/32 bits per value and a decayed entry rounds
to zero by construction. An affine 4 4 -bit group takes 4.625 4.625 bits per value and an 8 8 -bit group
