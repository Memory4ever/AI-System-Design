Affiliation: University of Cambridge

Abstract
Speculative decoding accelerates LLM inference, but deploying it on CPUs introduces severe systems bottlenecks: context-swapping latency between draft and target graphs, and memory allocation overhead during KV cache rollbacks. We introduce SubTernary, an execution framework that eliminates these costs through Unified Graph Caching and Transactional KV-Cache Isolation. By compiling both models into a single memory arena with a persistent thread pool and routing speculative tokens to a static scratchpad for zero-copy pointer resets, SubTernary avoids dynamic reallocation and thread synchronization entirely. We integrate a 256-bit AVX2 ternary SIMD kernel as a low-bit case study. Ablations reveal our systems runtime drives 35.0% of the throughput gains, while the ternary kernel adds 6.0%. SubTernary achieves a 1.35 × 1.35\times speedup over llama.cpp speculative decoding and 3.99 × 3.99\times over autoregressive decoding, maintaining O ⁡ ( 1 ) O(1) rollback latency.
1 Introduction
Generating text with LLMs on CPUs is bottlenecked by DRAM memory bandwidth. In standard autoregressive decoding, the CPU must load every model weight from main memory to generate a single token. Speculative decoding ( Leviathan et al., 2023 ; Chen et al., 2023 ) mitigates this bottleneck by using a smaller draft model to generate K K candidate tokens, which are verified in a single parallel pass by the target model, converting memory-bound single-token steps into compute-efficient batched matrix operations. However, existing CPU speculative runtimes suffer from execution overheads:
1.
Dual-context graph reconstruction overhead (systems bottleneck): Existing CPU engines instantiate draft and target models in separate runtime contexts. Swapping context memory, switching thread pools, and rebuilding computation graphs for each speculative step introduces thread synchronization latency that negates theoretical speedups.
2.
Memory-copying and rollback overhead (algorithmic bottleneck): When proposed tokens are rejected during target verification, resetting the KV cache requires allocating temporary memory buffers, remapping user-space page tables, or copying cache blocks, introducing substantial memory traffic.
To resolve these challenges, we introduce SubTernary, a CPU software execution framework optimized for commodity architectures. We position Unified Graph Caching and Transactional KV-Cache Isolation as our primary systems contributions, eliminating dynamic context switching and executing zero-copy write-pointer resets. We relegate our 256-bit AVX2 ternary SIMD kernel to a supporting integrated case study for low-bit execution, demonstrating that while the ternary kernel provides a +6.0% speedup, our systems context and cache management dominate performance by delivering +35.0% of the total throughput gains.

2.1 Unified Graph Caching
Standard engines instantiate separate runtime contexts for draft and target models, causing context-swapping latency. SubTernary compiles two separate static computation graphs ( 𝒢 target \mathcal{G}_{\text{target}} and 𝒢 draft \mathcal{G}_{\text{draft}} ) within a single unified memory context ( 𝒞 unified \mathcal{C}_{\text{unified}} ). Both graphs share underlying memory arenas and a persistent thread pool:
𝒢 cached = { 𝒢 target , 𝒢 draft } ⊂ 𝒞 unified \mathcal{G}_{\text{cached}}=\{\mathcal{G}_{\text{target}},\mathcal{G}_{\text{draft}}\}\subset\mathcal{C}_{\text{unified}}
(1)
During decoding, control flow redirects pointer inputs directly to the respective graph offsets, eliminating dynamic memory allocations, thread context swaps, and graph reconstruction overheads.
Crucially, this unified pool enables 100% of CPU threads to be allocated sequentially to the active model graph (draft, then target). A fundamental design question in CPU speculative decoding is whether to partition CPU cores between the target model and draft model (e.g., allocating 4 cores to drafting and 4 cores to verification). Let 𝒟 \mathcal{D} denote the draft model evaluation function, and 𝒯 \mathcal{T} denote the target model evaluation function. Let x 1 . . t x_{1..t} represent the verified sequence prefix at step t t , and x ^ 1 . . K \hat{x}_{1..K} represent candidate tokens proposed by the draft model.
1.
Drafting phase (sequential autoregressive):
The draft model generates tokens sequentially:
x ^ i ∼ 𝒟 ( ⋅ ∣ x 1 . . t , x ^ 1 . . i − 1 ) for i = 1 … K \hat{x}_{i}\sim\mathcal{D}(\cdot\mid x_{1..t},\hat{x}_{1..i-1})\quad\text{for }i=1\dots K
(2)
Because each proposed token x ^ i \hat{x}_{i} depends on the output embedding of token x ^ i − 1 \hat{x}_{i-1} , the drafting phase contains a strict causal dependency chain across time steps.
2.
Verification phase (parallel batched evaluation):
The target model verifies all K K tokens in a single parallel forward pass to compute the target probabilities:
P target = 𝒯 ( ⋅ ∣ x 1 . . t , x ^ 1 . . K ) P_{\text{target}}=\mathcal{T}(\cdot\mid x_{1..t},\hat{x}_{1..K})
(3)
The target model cannot execute verification until the draft model completes all K K drafting steps and yields x ^ 1 . . K \hat{x}_{1..K} .
3.
Sequential causal chain:
Start → 𝒟 ⁡ ( x ^ 1 ) → 𝒟 ⁡ ( x ^ 2 ) → … → 𝒟 ⁡ ( x ^ K ) → 𝒯 ⁡ ( x ^ 1 . . K ) → Commit/Rollback \text{Start}\rightarrow\mathcal{D}(\hat{x}_{1})\rightarrow\mathcal{D}(\hat{x}_{2})\rightarrow\dots\rightarrow\mathcal{D}(\hat{x}_{K})\rightarrow\mathcal{T}(\hat{x}_{1..K})\rightarrow\text{Commit/Rollback}
(4)
Partitioning CPU cores between models introduces two major drawbacks: (1) during drafting, the target model’s assigned cores sit idle while the draft model runs on reduced memory bandwidth, and (2) during verification, the draft model’s cores sit idle. Splitting thread pools across separate core clusters causes continuous OS context-switching, cache invalidations, and cross-core synchronization latency. By allocating all available CPU threads sequentially to the active model graph, SubTernary minimizes thread synchronization latency and maximizes register throughput. Empirically, sequential thread allocation achieves 8.73 ​ t/s 8.73\text{ t/s} compared to 4.17 ​ t/s 4.17\text{ t/s} under a 4/4 core-partitioned configuration ( 2.09 × 2.09\times speedup), confirming our causal thread scheduling analysis.
2.2 Transactional KV-Cache Isolation
Unlike PagedAttention or copy-on-write schemes that require dynamic page allocation or translation lookaside buffer (TLB) shootdowns, SubTernary uses a static contiguous memory layout where rollbacks execute as zero-copy write-pointer resets. We allocate a static scratchpad region ( SpecScratchpad ) at the end of the verified target model cache. Let i i denote the query token index and j j denote the key/value token index. During parallel verification i ∈ [ t + 1 , t + K ] i\in[t+1,t+K] , the self-attention mask enforces causal visibility while hiding stale scratchpad activations:
ℳ attention ​ ( i , j ) = { 0 if ​ j ≤ t (Verified history) 0 if ​ t < j ≤ i (Causal draft window) − ∞ if ​ j > i (Future causal masking) − ∞ if ​ j ∈ StaleScratchpad (Stale activations from prior rounds) \mathcal{M}_{\text{attention}}(i,j)=\begin{cases}0&\text{if }j\leq t\quad\text{(Verified history)}\\
0&\text{if }t<j\leq i\quad\text{(Causal draft window)}\\
-\infty&\text{if }j>i\quad\text{(Future causal masking)}\\
-\infty&\text{if }j\in\text{StaleScratchpad}\quad\text{(Stale activations from prior rounds)}\end{cases}
(5)
If m ≤ K m\leq K tokens are accepted, write pointers commit in-place ( KV ptr ← t + m \text{KV}_{\text{ptr}}\leftarrow t+m ). If rejected, a transactional rollback resets KV ptr ← t \text{KV}_{\text{ptr}}\leftarrow t , bypassing memory copies.
3 Hardware-Algorithm Co-Design
To evaluate low-bit execution, we complement our systems design with a custom 256-bit AVX2 ternary SIMD kernel for weights W ∈ { − 1 , 0 , 1 } W\in\{-1,0,1\} . Because the SubTernary runtime eliminates dual-context overhead, it can support low-bit drafting without runtime overhead erasing the algorithmic gains. By packing weights into binary sign/sparsity masks, execution maps entirely to SIMD register additions. To prevent vocabulary representation collapse, draft models are distilled using quantization-aware training (QAT) with a straight-through estimator (STE), maintaining ≥ 70 % \geq 70\% token acceptance.
4 End-to-End Systems Evaluation
4.1 Experimental Setup
Experiments are conducted in an 8-vCPU virtualized environment pinned to eight physical cores on a server-class Intel Xeon Gold 5218 host. The target model is Meta Llama-3.2-3B-Instruct (Q8_0/FP16), paired with a Llama-3.2-1B-Instruct draft model (Q4_0/TQ1_0). All metrics report the mean ± \pm standard deviation across 5 independent evaluation trials. While enterprise runtimes like OpenVINO optimize standard batched GEMM execution, llama.cpp represents the state-of-the-art open-source engine for commodity CPU LLM inference, serving as our primary speculative baseline. Exhaustive hardware specifications, compiler flags, and hyperparameters are deferred to Appendix C .

Beyond raw hardware efficiency, production CPU environments must survive hypervisor thread contention. In multi-tenant clouds, traditional engines like llama.cpp rely on frequent, blocking OpenMP synchronization checkpoints; if a single vCPU stutters due to "noisy neighbors," the entire speculative pipeline stalls. As shown in Figure 3 (left), small batch sizes ( K ≤ 2 K\leq 2 ) suffer heavily from this synchronization overhead. By increasing to K ≥ 4 K\geq 4 , batched execution amortizes the latency.
Furthermore, SubTernary’s persistent thread pool minimizes these synchronization barriers entirely. Figure 3 (right) demonstrates that under heavy shared hypervisor load, standard llama.cpp speculative decoding degrades severely, falling well below autoregressive baseline speeds because delayed vCPUs stall the entire verification pipeline. By bypassing strict execution context boundaries, SubTernary reliably maintains positive throughput scaling, preserving speculative acceleration despite extreme OS jitter and remains highly effective even in noisy, multi-tenant cloud deployments.

5 Conclusion
SubTernary addresses context and cache bottlenecks in CPU speculative decoding via Unified Graph Caching and Transactional KV Isolation. By unifying graph execution and enabling zero-copy rollbacks, SubTernary achieves up to a 3.99x speedup on commodity CPUs while scaling robustly.

Appendix A Limitations and Scope of Hardware Evaluation
Our evaluation is conducted on an Intel Xeon Gold 5218 server platform representative of bandwidth-limited, AVX2-capable commodity x86_64 processors. While results demonstrate substantial overhead reductions, performance dynamics may vary on alternative architectures (e.g., AMD Zen, Intel Sapphire Rapids with AMX/AVX-512, or ARM Neoverse processors). Evaluating SubTernary across broader microarchitectures and multi-socket NUMA nodes remains future work.
Appendix B Related Work
Speculative decoding was formalized by Leviathan et al. [2023] and Chen et al. [2023] . Recent research explores optimizing speculative drafting across systems and quantization layers:
•
Low-bit draft models and CPU execution (T-MAC, BitNet, QuantSpec): SOTA CPU execution frameworks like T-MAC [ Wei et al., 2025 ] use lookup table (LUT) techniques to accelerate low-bit matrix operations. BitNet 1.58-bit [ Ma et al., 2024 ] projects weights to ternary representations, and QuantSpec [ Tiwari et al., 2024 ] explores quantized speculative decoding. However, direct post-training quantization (PTQ) on sub-3B draft models causes representation collapse (yielding a 0.0% acceptance rate). SubTernary addresses these limitations by combining a QAT distillation pipeline with custom ternary SIMD addition kernels, avoiding representation collapse while eliminating dual-context state swapping.
•
KV cache management and speculative serving (SpecInfer, LayerSkip, vLLM): Managing KV cache rollbacks is critical for speculative efficiency. SpecInfer [ Miao et al., 2024 ] organizes tree verification, LayerSkip [ Elhoushi et al., 2024 ] leverages early exit self-speculation, and vLLM [ Kwon et al., 2023 ] manages page tables for GPU multi-tenant serving. However, in single-tenant CPU user-space execution, dynamic page allocation and translation lookaside buffer (TLB) shootdowns introduce 10–15% overhead per rollback step. SubTernary introduces transactional KV-cache isolation, routing speculative draft tokens to a static scratchpad attention mask where rollbacks execute as zero-copy write pointer resets.
•
GPU-oriented speculators (Medusa, EAGLE): Medusa [ Cai et al., 2024 ] and EAGLE [ Li et al., 2024 ] accelerate GPU decoding using multiple parallel heads or recurrent draft trees. However, as demonstrated in our evaluations, their high compute density and multiple tree branches cause heavy thread contention and cache invalidations on CPU cores, making single-sequence graph execution superior for commodity processors.

Appendix D Verification of Algorithmic Fidelity
A frequent concern in speculative execution engines is whether complex memory optimizations (such as zero-copy pointer resets) introduce silent state corruption. This section provides mathematical and empirical proof that SubTernary preserves exact algorithmic fidelity and generative quality.
D.1 RoPE Positional Alignment Under Partial Acceptance
When the target model accepts m < K m<K tokens, rotary position embeddings (RoPE) must remain aligned without triggering a costly recomputation step. SubTernary preassigns sequential position IDs t + 1 ​ … ​ t + K t+1\dots t+K to speculative tokens during both drafting and verification. When the target model accepts m m tokens, the KV ptr \text{KV}_{\text{ptr}} commits to index t + m t+m . For the subsequent speculative block, the draft model writes to scratchpad slots starting at t + m + 1 t+m+1 . Because the keys and values up to t + m t+m were already rotated with the correct position IDs during the target model’s verification pass, they remain mathematically valid in memory. Stale entries beyond t + m t+m are simply overwritten in the next draft pass without requiring reindexing or data movement.
D.2 Distribution Preservation Analysis and KL Divergence Validation
D.2.1 Analytical Proof of Distribution Exactness
Let x 1 . . t x_{1..t} represent the verified token sequence at step t t , and x ^ t + 1 . . t + K \hat{x}_{t+1..t+K} represent the draft proposal. During parallel verification, the target model evaluates all K K tokens. Self-attention layers compute query-key scores Attn ​ ( Q i , K j ) \text{Attn}(Q_{i},K_{j}) . For any verified token index i ≤ t i\leq t , the attention mask guarantees:
Attn ​ ( Q i , K j ) = − ∞ ∀ j ∈ StaleScratchpad \text{Attn}(Q_{i},K_{j})=-\infty\quad\forall j\in\text{StaleScratchpad}
(6)
Because LayerNorm, RoPE, and intermediate activations are calculated strictly on the target model’s forward path using its own weights, and rejected scratchpad regions are completely masked from the verified history, the target model’s forward pass is mathematically identical to a standard autoregressive run. Thus, the verification distribution P verification P_{\text{verification}} reproduces the target distribution P target P_{\text{target}} precisely:

Appendix E Architectural Divergence: CPU vs. GPU Speculators
To fully contextualize why a CPU-specific execution framework like SubTernary is necessary, we must contrast it with modern GPU-oriented speculators like Medusa and EAGLE. On GPUs, massive thread concurrency allows parallel drafting heads and recurrent draft trees to execute efficiently, hiding memory latency. However, CPUs have fundamentally different microarchitectures. Parallel tree branches on a CPU result in instruction cache misses, branch mispredictions, and severe thread contention over the shared L3 cache.
Table 6 benchmarks the CPU implementations of Medusa and EAGLE on Llama-3.2-3B-Instruct. The results show that their high compute density and branch divergence degrade CPU throughput drastically. SubTernary’s single-sequence graph design completely avoids these cache thrashing issues, yielding a 4.17 × 4.17\times speedup over Medusa and a 42.63 × 42.63\times speedup over EAGLE in raw step latency on commodity hardware.
