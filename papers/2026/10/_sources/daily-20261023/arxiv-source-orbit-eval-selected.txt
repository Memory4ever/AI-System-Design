Hardware setup.
We test OrbitWeaver on two NVIDIA Jetsons with different compute capabilities: Jetson Orin NX (8-core ARM CPU, 1.9 TFLOPS Ampere GPU, 16 GB memory) and Jetson AGX Orin (12-core ARM CPU, 5.3 TFLOPS Ampere GPU, 64 GB memory), mirroring the computing payloads of Sat-1 and Sat-2. Both devices run Linux for Tegra R36.4.3.
Models and dataset.
We conduct experiments using four typical edge-sized VLMs: Qwen3-VL 2B/4B/8B and MiniCPM-V 4.5 (8B).
All models run W4A16 inference using GPTQ quantization and Marlin kernels.
We use LRS-VQA (Luo et al., 2025) as a representative remote-sensing VQA workload; its images have an average resolution of 7,099 × 6,329 pixels.
Since SONIC does not support GPU and HCache does not open-source their code, we reimplement their techniques as described in their papers on transformers framework.
We obtain DLWA by collecting I/O traces at runtime and replaying them in MQSim (Tavakkol et al., 2018).
Energy is measured with tegrastats.
Before measuring recovery latency, we clear the OS page cache to evaluate cold-cache recovery performance.

At each shutdown, we terminate the inference process and clear its volatile state; inference resumes from the latest checkpoint in the next execution window.
We repeat each trace until the request completes or reaches a limit of 20 full replays, after which it is marked as incomplete.

7.7. Case Study: Real Deployment on Sat-1 and Sat-2
We deploy OrbitWeaver on Sat-1 and Sat-2 for 72 hours and execute 25 VLM requests on each satellite.
Each request runs Qwen3-VL 2B on remote-sensing images with a 32K-token input, with each request generating 64 tokens during decoding.
We impose a 20-minute timeout on each request.
On Sat-1, 21 requests experience 47 bus-enforced shutdowns; on Sat-2, 20 requests experience 44 bus-enforced shutdowns.
Across both deployments, 41 of the 50 requests are interrupted, and OrbitWeaver completes all 50 requests despite a total of 91 bus-enforced shutdowns.
