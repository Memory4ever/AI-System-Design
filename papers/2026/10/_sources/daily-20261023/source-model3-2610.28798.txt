An Explicit Feedback Contract for Iterative ML-Agent Harnesses
Kehui Yao, Chuanbo Hu, Jiao Chen,
Ramin Giahi, Reza Yousefi Maragheh, Lalitesh Morishetti,

Walmart Global Tech

Abstract
Iterative ML agents develop models by editing code, running experiments, reading a validation score, and choosing what to try next. In current harnesses this loop is served by an exact validation score returned after every attempt, which leaves the validation split open to adaptive selection.
In this work, we introduce an explicit feedback contract for ML-agent harnesses, which specifies what an agent may observe, when iteration should stop, and when the test split may be touched. The contract releases a validation score only when a submission clears a noise threshold computed from the paired standard error, so no margin has to be tuned.
We ran experiments on click-through-rate prediction, learning to rank, and a control task with no signal to find. The control is the sharpest case, because the true gain there is zero by construction: an agent reading exact scores ended by reporting a gain of 0.0157 0.0157 , while under the contract it reported 0.0033 0.0033 . On both real tasks the contract narrows the validation–test gap, and test performance is slightly higher rather than lower. The largest difference is in when the agents stop. Exact feedback used its entire budget of thirty submissions on two of the three tasks, including the one where nothing can be learned, while the contract halted after four to twelve. A run that exhausts its budget is usually read as diligence. It is better read as a symptom: when the feedback channel is unbounded, noise keeps supplying improvements to chase.
1 Introduction
Language-model agents are no longer only writing code. They now run experiments: editing code, launching training runs, reading a validation score, and choosing the next edit. A growing body of systems and benchmarks evaluate this loop ( Romera-Paredes et al., 2024 ; Jiang et al., 2025 ; Lu et al., 2024 ; Wang et al., 2026 ; Chan et al., 2024 ; Huang et al., 2024 ; Pinchuk, 2026 ) . They differ in what the agent proposes but not in what it observes: an exact validation score after every attempt.
The feedback interface matters more than it appears. Each validation score is an ordinary held-out estimate, but the sequence produced by iteratively keeping score-improving edits is not ( Dwork et al., 2015b ) . Validation scores are computed on a finite sample and carry noise. From inside the loop, a real improvement and a fluctuation of the same size look identical, and the agent keeps the edit in both cases. After enough rounds, the score it reports describes one particular split rather than the population. Figure 1 shows the effect on data where the truth is known.
Figure 1: An agent iterating against a validation split whose labels have been permuted: nothing can beat the base rate, so the true gain is zero and a flat line is correct. Plotted is the gain the agent is shown after each submission, over five seeds with standard-error bands. The blue trajectory and its final-test marker end at the mean stopping round, 10.4 ± 4.4 10.4\pm 4.4 , whereas Exact continues to the 30.0 ± 0.0 30.0\pm 0.0 submission cap.
This is not a hypothetical worry. Held-out accuracy inflates measurably when a benchmark is reused across a research community ( Recht et al., 2019 ) . A meta-analysis of Kaggle competitions finds adaptive overfitting where submission counts are large relative to holdout size ( Roelofs et al., 2019 ) . Agents change that ratio. A competition may collect a few thousand submissions from hundreds of teams over several months. A single agent can issue as many against one validation split in an afternoon. There is no rate limit, and no one is watching for the moment the gains stop being real.
The statistical problem is well understood. Adaptive data analysis shows that a holdout can be reused when the released answers are stable, and differential privacy is one way to achieve this ( Dwork et al., 2015b ; Dwork et al., 2015a ; Dwork et al., 2015c ) . There is also a matching hardness result: no efficient estimator can answer every adaptively chosen query accurately ( Hardt and Ullman, 2014 ) . Practical mechanisms therefore aim at something weaker. For leaderboards, Blum and Hardt (2015) aim at the best score so far, and reach it with a simple rule. Release a new score only when a submission beats the previous best by a margin. Otherwise repeat the old score.
An agent is different from a competition submitter in three ways that a threshold alone does not address. First, an agent can retrain and inspect intermediate files, so a contract must say which files are readable. Second, there is no closing date, so the protocol needs a stopping rule. Third, the agent works inside the repository, so anything the harness does not actively withhold—including validation predictions—can leak. These three gaps turn a single-mechanism question into a protocol-design problem.
We propose an explicit feedback contract for iterative ML-agent harnesses, and make three contributions. (1) Agent iteration is identified as a case of adaptive overfitting, and given a precise form. (2) The contract specifies what an agent may see, when it should stop, and when the test set may be used. It needs no parameter tuning, and its stopping rule is guaranteed to fire: the agent halts because no further improvement can be certified, not because a budget ran out. (3) On two real tasks and one control task, an ordinary coding agent overfits the validation data without trying to. The contract narrows the gap at no cost to final performance, and stops after a fraction of the submissions an unbounded interface uses.
2 Related Work
2.1 Agentic ML systems and their evaluation interfaces
An ML-agent harness settles three things before a run: data splits, budget, and what the agent is told after each attempt. Benchmarks settle the first two with care. Splits are fixed, budgets are capped, and a private portion is held back until the end ( Chan et al., 2024 ; Huang et al., 2024 ; Pinchuk, 2026 ) . The third is left implicit. An agent receives the metric it asked for, at full precision, as often as it asks. That was inherited rather than chosen. In single-shot evaluation, reporting a validation score exactly is the right thing to do. The systems that placed an agent inside the loop ( Romera-Paredes et al., 2024 ; Jiang et al., 2025 ; Lu et al., 2024 ; Wang et al., 2026 ; Zhang et al., 2026 ) kept the interface and replaced the submitter with one that queries it hundreds of times.
2.2 Mechanisms for adaptive reuse
Two routes exist for reusing a holdout under adaptive queries: perturbing the released answers with a privacy budget ( Dwork et al., 2015b ; Dwork et al., 2015c ) , and thresholding the release so that only scores that clear a margin are reported Blum and Hardt (2015) . Both assume that the submitter cannot access the raw data—an assumption that breaks when the submitter is an agent with file-system access. Table 1 shows the gap on the agent side. What it cannot show is why agentic ML systems never restricted their feedback channel, even though mechanisms for doing so already existed in adaptive data analysis.

3 Problem Formulation
Setting.
An agent develops a model over k k rounds against a harness. The harness holds three disjoint splits 𝒯 \mathcal{T} , 𝒱 \mathcal{V} , and ℋ \mathcal{H} . The agent uses 𝒯 \mathcal{T} freely. It can reach 𝒱 \mathcal{V} only through the harness, which keeps the labels. It does not touch ℋ \mathcal{H} until it has stopped.
Each round has three steps. The agent submits one candidate, written f t f_{t} . The harness scores that candidate on 𝒱 \mathcal{V} and keeps the score to itself. The harness then releases a single pair ( u t , R t ) (u_{t},R_{t}) : whether the released score changed, and what it now stands at. Nothing else comes back. The transcript H t H_{t} of pairs released up to round t t is everything that leaves the harness. What rule decides ( u t , R t ) (u_{t},R_{t}) is the subject of Section 4 .
Adaptivity.
The agent writes f t f_{t} after reading H t − 1 H_{t-1} .
Definition 1 (Admissible sequence) .
A sequence f 1 , … , f k f_{1},\ldots,f_{k} is admissible if f t f_{t} depends only on 𝒯 \mathcal{T} , the repository state, earlier edits, and H t − 1 H_{t-1} , and not on the labels or per-example losses of 𝒱 \mathcal{V} , on validation prediction files, or on any feedback from ℋ \mathcal{H} .

on an example z z , and let

What the harness computes instead is the average loss over the n n

ℛ ^ 𝒱 ​ ( f ) = 1 n ​ ∑ i = 1 n ℓ ⁡ ( f , z i ) . \widehat{\mathcal{R}}_{\mathcal{V}}(f)=\frac{1}{n}\sum_{i=1}^{n}\ell(f,z_{i}).
For a model fixed in advance, the second estimates the first without bias. Here the model is not fixed in advance. Candidate and sample are dependent, so the guarantee lapses, and the number an agent reports at the end is the smallest score it happened to meet along an adaptively chosen path.
Objective.
A harness cannot promise that every released score is close to the risk of the candidate that produced it, since that is unachievable under adaptivity ( Hardt and Ullman, 2014 ) . It can promise something weaker and still useful: that the released score stays close to the risk of the best candidate submitted so far.
Definition 2 (Public score error) .
For an admissible sequence with releases R 1 , … , R k R_{1},\ldots,R_{k} ,
pverr ⁡ ( R 1 , … , R k ) = max t ≤ k ⁡ | min i ≤ t ⁡ ℛ ⁡ ( f i ) − R t | . \mathrm{pverr}(R_{1},\ldots,R_{k})=\max_{t\leq k}\Bigl|\min_{i\leq t}\mathcal{R}(f_{i})-R_{t}\Bigr|.
A release rule should keep pverr \mathrm{pverr} small for every admissible sequence, while leaving H k H_{k} informative enough that the agent can still choose among its own candidates. The two requirements pull against each other, and Section 4 settles where to stand between them.
4 The Feedback Contract: Thresholded Best-So-Far Release
4.1 The contract: five clauses
A harness has to decide five things before a run starts; deciding them during one would itself be information. Figure 2 shows the arrangement.
(C1) Splits.
𝒯 \mathcal{T} is open. 𝒱 \mathcal{V} is reachable only by submitting a candidate; its labels, per-example losses, and prediction files stay inside the harness. ℋ \mathcal{H} is unreachable while the agent iterates.
(C2) Released feedback.
Each round takes one submission and returns one pair ( u t , R t ) (u_{t},R_{t}) . Nothing else leaves. A rejected submission is not told by how much it missed, so the agent cannot steer by the size of its failures.
(C3) Stopping.
A budget T max T_{\max} and a patience p p are fixed in advance. Iteration halts at the budget or after p p consecutive non-updates. Patience counts updates, not score changes: an update has cleared a threshold, whereas a score change need not have.
(C4) Test quarantine.
A final model is named before any test feedback exists, by default the champion c k c_{k} . ℋ \mathcal{H} is then evaluated once, and only aggregate metrics are released.
(C5) Recorded artifacts.
The harness stores the configuration, hidden loss vectors, transcript, seeds, agent identifiers, and final metrics, in enough detail to replay the transcript without rerunning the agent.
4.2 A parameter-free release rule
C2 says a score is released only when a submission is good enough, and an algorithm has to say how good. Fixing a margin η \eta in advance does not work: too high discards real gains, too low releases almost every round, and the right value depends on task noise that is unknown beforehand. The rule below computes the margin from the data instead.
The harness remembers three things between rounds: the score currently on release, the candidate that earned it, which we call the champion , and that candidate’s loss on each of the n n validation examples. Algorithm 1 scores a new candidate on the same examples, compares row by row against the champion, and releases a new score only if the improvement exceeds the noise in that comparison.

5 Results
5.1 Experimental Setup
Datasets.
Criteo-style click-through-rate prediction is binary classification on a processed dataset with 100,000 100{,}000 training examples, 25,000 25{,}000 validation examples, and an independent 50,000 50{,}000 -example test set; we report AUC. MSLR-WEB10K uses the official Fold1 split, with 6,000 6{,}000 training, 2,000 2{,}000 validation, and 2,000 2{,}000 test queries. Query groups remain intact; the base ranker is a HistGradientBoostingRegressor fitted on 150,000 150{,}000 rows from the training split, and we report macro NDCG@10. Because NDCG decomposes per query rather than per row, the sample size entering Proposition 1 is the number of validation queries, roughly 2,000 2{,}000 , so the guarantee is weaker here than the row count suggests. A third
dataset is a no-signal control, obtained by permuting labels before
splitting and matched in dimension to Criteo: the base rate is population-optimal, so any apparent gain is selection noise by construction.

6 Discussion and Limitations
The no-signal control provides the sharpest evidence. On data where nothing can be learned, an agent given an ordinary prompt and an exact score after every attempt reports an improvement anyway, accumulated slowly enough that no single round looks wrong. This needed no adversary and no unusual agent, only a channel that answers every question. The second finding, which we did not expect, is that exact feedback ran to the budget on every dataset including the one with no signal: an interface that always has something new to report is always worth querying again.
The guarantee is narrow, deliberately. It concerns the released transcript rather than the final test score, so the contract makes the reported number trustworthy, not better. It covers a fixed margin, whereas the deployed rule computes one from paired standard errors and is a heuristic. And a thresholded interface returns a selection signal and nothing else, so error analysis has to run on training data or a separately labelled sample. The empirical claim is correspondingly modest: the gap narrows on both real datasets and test performance is slightly higher rather than lower, but the differences are small in absolute terms, three seeds on the real datasets cannot separate a small effect from none, and both datasets are tabular.
7 Conclusion
An agent that reads an exact validation score after every attempt is running a selection procedure against a fixed sample, and the score it reports at the end is not what a held-out estimate measures. This is a property of the harness, not of the agent. We proposed a contract that fixes what an agent may see on each split, when its loop should end, and when the test data may be touched, with a release rule that reports a new score only when a submission beats the current best by more than the noise in that comparison. On data with nothing to learn, the contract reports nothing learned while exact feedback reports progress; on real data the gap narrows at no cost; and runs end when improvements run out rather than when the budget does. Harnesses today specify what an agent must produce far more carefully than what it may observe while producing it, and the second question only gets harder as loops grow longer.
