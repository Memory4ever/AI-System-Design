Abstract
Speculative decoding uses a target model to verify a tree of draft tokens in parallel. We study whether the resulting next-token distributions can help select the next tree. For unrestricted target models, we show that guaranteed exact reuse requires a distribution computed at the next round’s complete context. We characterize when retaining this distribution requires sacrificing accepted tokens and establish conditions under which this loss persists across decoding rounds. Across six targets, we find that reranking first-token branches with a separately computed distribution at the current context improves expected acceptance over draft ranking, especially with small tree budgets. Drawing the first token from this distribution before allocating the tree further improves expected acceptance over pruning a preselected tree, even at equal mean tree size. In our experiments, both selection rules also decode faster than draft ranking when the separate target pass overlaps standalone drafting. Our findings show that making target probabilities available before tree allocation can improve the efficiency of speculative decoding. Our code is available at https://github.com/js-lee-AI/TargetRows .

1 Introduction
Large language models typically generate text one token at a time ( Lee et al., 2025 ; Lee et al., 2026d ; Lee et al., 2026e ; Lee et al., 2026f ; Kang et al., 2026 ) . Speculative decoding accelerates this process by letting a cheap drafter propose tokens for the target model to verify in parallel ( Leviathan et al., 2023 ; Chen et al., 2023 ; Lee et al., 2026c ) . Tree-based methods extend this approach by arranging several candidate continuations into branches and verifying them in a single target pass ( Miao et al., 2024 ; Cai et al., 2024 ; Li et al., 2024 ; Li et al., 2025 ; Lee and Eo, 2026 ) . To keep the tree within a fixed node budget, the drafter must choose which branches to retain. The target’s probabilities could guide this choice, yet the tree is usually selected before verification reveals them. The previous pass offers another source of information because it has already computed next-token distributions at candidate prefixes. We call these distributions rows.
We ask when one of these rows can provide exact next-token probabilities for selecting the next tree without another target evaluation. We find that, for an unrestricted target, such reuse is guaranteed only when the row was computed at the next round’s complete context, which we call its address. Two addresses may end in the same token even when they contain different sequences of preceding tokens. A cache indexed by the final token can still provide draft candidates ( Luo et al., 2025 ) , but a token match alone does not guarantee exact reuse at the next round’s address.
A round has address coverage when its verification pass has already computed a row at the next round’s address. Figure 1 makes this condition concrete. Starting from context c c , suppose verification accepts a a and then emits another a a as its continuation. The next round starts at c ​ a ​ a caa , so it needs the row computed there. The row at c ​ a ca has a different address because it conditions on the context before the second a a . Once retained, the matching row supplies exact first-token probabilities for selecting the next tree, provided the target computation is unchanged.
We find an exact trade-off between address coverage and accepted tokens when a pass scores only its candidate tree. The result holds for rounds that accept one tree path, emit one continuation token, and preserve the target distribution for each chosen tree. Coverage occurs exactly when the accepted path plus its continuation remains inside the tree. Exhaustive traversal instead keeps accepting tokens until a draw leaves the tree, then emits that draw as its continuation. The next root is therefore unscored. A covered round could have accepted its continuation as another draft token, so it accepts at least one fewer token than exhaustive traversal on the same target-token sequence.
Scoring prefixes one step beyond the candidate tree can cover the next root even after exhaustive traversal. Adding those same prefixes as candidates would instead let traversal accept one more token on each covered round.
We then compare coverage over whole runs. Within this verifier class, consider a decoder with one target pass in each round whose decisions use target information only along its emitted path. We construct a decoder that is never covered, scores no more prefixes and emits at least as many tokens after every round. Thus these decoders benefit from the next-root row by computing it in a separate target pass.
We evaluate the root row’s value for tree selection separately from the cost of obtaining it. Our experiments use EAGLE-3 dynamic trees ( Li et al., 2025 ) for six targets from 4B to 32B, seven task types and two decoding temperatures. Root selection ranks candidate paths using target probabilities for their first token and draft probabilities for later tokens. We find that it increases the expected number of accepted draft tokens over draft ranking, especially with small trees. Most gains occur when the models’ most likely first tokens differ.
Root-draw selection instead draws the first token from the root row before allocating the tree beneath it. We find higher expected acceptance than pruning a preselected tree to that token’s branch ( Liu et al., 2025a ) , even at equal mean tree size. Both selection rules also decode faster than draft ranking when standalone drafting on a second GPU overlaps the separate root pass.
2 Related Work
Speculation and verification.
Speculative sampling uses acceptance and correction steps to preserve the target distribution ( Leviathan et al., 2023 ; Chen et al., 2023 ) . Tree-based methods verify several candidate paths in parallel ( Miao et al., 2024 ; Cai et al., 2024 ; Li et al., 2024 ; Li et al., 2025 ) . Related studies bound expected acceptance in draft trees ( Pankratov and Alistarh, 2025 ) and analyze how jointly verifying multiple tokens or drafts can improve acceptance while preserving the target distribution ( Sun et al., 2025 ; Hu et al., 2025b ; Weng et al., 2026 ) . We instead characterize when a verification pass has already computed a row at the next round’s complete context and relate this availability to the number of accepted tokens.
Target information and reuse.
LogitSpec predicts the token after the next one from last-token logits and uses it to retrieve drafts ( Liu et al., 2025b ) . FlexDraft calibrates draft logits with the resolved continuation token ( Zhang et al., 2026a ) , while Saguaro drafts ahead for the verification outcomes it predicts ( Kumar et al., 2026 ) . Token Recycling keeps the top candidates of every target row computed during verification under that row’s input token and retrieves the next draft tree from this store ( Luo et al., 2025 ) . We evaluate full rows indexed by the final token as inputs to tree selection.
Drafting and compute allocation.
Work on draft generation includes proposer training ( Hu et al., 2025a ; Zou et al., 2026 ; Lei et al., 2026 ; Lee et al., 2026g ) , parallel drafting ( Hui et al., 2026 ) , block drafting ( Chen et al., 2026 ; Sandler et al., 2025 ; Liu et al., 2026 ; Lee et al., 2026a ) and retrieval ( Zhang et al., 2026b ) . EAGLE-2, OPT-Tree, SMART and Sequoia adapt candidate trees to draft confidence or hardware cost ( Li et al., 2024 ; Wang et al., 2025 ; Wang and Zhou, 2026 ; Chen et al., 2024 ) . Beyond tree construction, agreement between two drafts can guide whether a reasoning model invokes extended thinking ( Lee et al., 2026b ) .
Pipelined methods overlap drafting with target verification ( Liu et al., 2025a ; McDanel et al., 2025 ) . For example, PEARL verifies the first draft token while the drafter proposes the rest, making the root row available during drafting. We isolate the value of target rows for tree selection by comparing rules on the same draft candidate pools.

Rejection-based verifiers.
We find that speculative sampling ( Leviathan et al., 2023 ; Chen et al., 2023 ) and its multi-step form for token trees ( Miao et al., 2024 ) never cover the next root when Q = T Q=T . Their rejection rule suffices without conditional exactness given the tree. They test a node’s children in turn; rejected tokens retain zero probability in every later residual distribution. The continuation therefore leaves the trie after all children are rejected, or at a leaf. Point-mass proposals, as in EAGLE-3, give exhaustive target sampling. Appendix A.4 gives the residual argument.
Covering over a run.
A covered round hands the next round its root row, so Equation 4 alone does not settle whether covering pays off over a run.
Theorem 2 (Covering over a run) .
Let a decoder’s only target computation after a shared prefill be one pass in each round t t over a trie Q t ⊇ T t Q_{t}\supseteq T_{t} , and let its verifier be path-aligned, emit one continuation and be conditionally exact given the selection inputs.
Suppose the decoder chooses T t T_{t} , Q t Q_{t} and where each round stops only from its emitted and drawn tokens and from the rows and other target outputs on its emitted path. Its only other inputs are its drafter, independent randomness and a first token drawn from its held root row.
Then some decoder preserves the target law, is never covered and scores no more prefixes per round. On a common target stream, it has emitted no fewer tokens than the original after each round, and more after the original’s covered rounds.
We construct the comparator on the same target stream with shared independent randomness. It reconstructs the original tries but scores only its root and their prefixes extending its emitted context. Exhaustive traversal takes it past every stream prefix scored by the original. The comparator has scored these prefixes and drawn their next tokens. It thus holds the rows, hidden states and draws needed to reproduce the original’s choices.
We extend the comparison to decoders using off-path target outputs. Obtaining them may require scoring branches diverging within the comparator’s emitted context. The extension applies when the cache attention mask permits such scoring. Appendix A.7 gives the construction and proof.
4.2 Adaptive selection preserves exactness
Retained rows can guide tree selection without changing the target distribution. Let ℋ t \mathcal{H}_{t} contain the emitted history, retained target rows and drafter information after round t t . The next tree may depend on ℋ t \mathcal{H}_{t} , provided verification is conditionally exact given ℋ t \mathcal{H}_{t} and that tree. Each emitted token then follows the target conditional at its actual prefix. Multiplying these conditional probabilities gives the target joint distribution for any fixed number of output tokens.
Retained rows from other addresses can therefore guide tree selection, provided selection does not depend on the verifier’s future random draws. The verifier must still preserve the target conditional at each emitted prefix. Directly sampling from a row at another address can change the output distribution, as illustrated in Appendix A.6 .

5.1 Setup
Targets and prompts.
The six targets are Llama-3.1-8B-Instruct ( Grattafiori et al., 2024 ) , Qwen3-4B and Qwen3-8B ( Yang et al., 2025 ) , and Qwen2.5-7B, 14B and 32B-Instruct ( Yang et al., 2024 ) . Each uses a public EAGLE-3 drafter trained for it ( Li et al., 2025 ; Cen et al., 2026 ; Pan et al., 2025 ) and its own chat template, with Qwen3 in non-thinking mode. We evaluate 164 164 HumanEval problems ( Chen et al., 2021 ) and 480 480 Spec-Bench prompts ( Xia et al., 2024 ) , including MT-bench ( Zheng et al., 2023 ) . These cover seven task types. Each target decodes the 644 644 prompts under a default limit of 256 256 new tokens, with greedy decoding and untruncated sampling at temperature 1 1 .
Trees and verification.
The EAGLE-3 drafter grows 710 710 candidates at depths one to eight. Draft selection keeps the top 59 59 non-root candidates by cumulative draft score, forming EAGLE-3’s default 60 60 -token tree including the root. Verification uses exhaustive target sampling, which matches EAGLE-3’s joint law for accepted tokens and the continuation.
To evaluate alternative trees, the pass also scores expanded nodes and the top 160 160 candidates. Every candidate’s parent is scored, supplying target probabilities for every pool edge. The verified tree’s rows remain unchanged up to rounding. Checkpoints, tasks, hardware and the measurement protocol are detailed in Appendix C .

Root-draw selection draws the first token from the root row, then selects it and up to B − 1 B-1 descendants in draft order. 5.3 Rows at matched addresses
Additional scoring provides rows at some complete emitted addresses. We find that these rows closely match the next root row: mean total variation is below 0.01 0.01 in every run. By contrast, rows sharing only the final token have mean total variation between 0.38 0.38 and 0.47 0.47 . The remaining variation for address-matched rows is comparable to evaluating the same row in batches of different sizes.
Frequent token matches in the previous tree therefore do not guarantee an exact row for the next root. Address counts and row agreement are detailed in Appendix D.11 .
5.4 Value of exact rows for tree selection
Table 2 compares selection rules at shared contexts. We find that root selection increases expected acceptance over draft ranking by up to 8.0 % 8.0\% at the default budget of 59 59 nodes, with larger gains at 8 8 nodes. Under greedy decoding, root selection cannot shorten the accepted path relative to draft selection.
Figure 2 compares gains over draft ranking from exact target probabilities at increasing depths. We recover a substantial share of the oracle’s gain with the root row alone, while exact second-token probabilities further improve allocation within first-token branches. Our results show that exact target probabilities are especially useful for small trees, since draft ranking already retains many likely target paths in larger trees.
First-token agreement.
Figure 3 groups rounds by whether the draft and target have the same most probable first token and compares root selection’s recovery of the oracle advantage. We find that the less frequent disagreement rounds account for most of the gain. Root selection rescales candidate scores within each first-token branch by a common factor, shifting node allocation across branches while leaving later-token draft probabilities unchanged. 5.5 Rows at other addresses
Table 4 tests whether rows from other addresses can improve tree selection when used as features. We compare two rerankers: Base predicts target probabilities for first-token candidates from draft and contextual features, while Rows adds features from retained target rows. Both rerankers replace only the first draft-probability factor with their predictions. We train on one half of the prompts and evaluate on the other, then swap their roles.
We find that Rows improves expected acceptance over both draft ranking and Base for every evaluated target at both temperatures and budgets, with all paired 95 % 95\% intervals above zero. Root selection yields higher expected acceptance than either reranker. By contrast, directly substituting a retained row for the first draft factor lowers expected acceptance in these tests. Thus, rows from other addresses can guide tree allocation through learned predictions without being used as exact next-token distributions. Fitting details and direct-substitution tests are given in Appendices D.8 and D.12 , respectively.
6 Conclusion
We show that covering the next root costs accepted tokens when verification scores only its candidate tree. The result holds for verifiers that accept one path, emit one continuation and preserve the target distribution conditional on the chosen tree. For any such decoder using one target pass in each round and target information only along the emitted path, we construct an exact decoder that never covers the next root. Compared with the original decoder, it scores no more prefixes in each round and has emitted at least as many tokens after every round.
We also find that a separately computed root row increases expected acceptance over draft ranking, especially when the draft and target favor different first tokens. Drawing the first token before allocating the tree improves expected acceptance over pruning a preselected tree, even at equal mean verified tree size. In our measured deployment, the separate pass overlaps a standalone drafter on a second GPU, and both selection rules decode faster than draft selection. These findings motivate evaluating the cost of obtaining target rows together with the tree-selection gains they enable.
Limitations
Our acceptance study covers six targets with public EAGLE-3 drafters and recorded target rows. The timing results apply to batch-one decoding with a standalone drafter on a second RTX A6000 GPU, where drafting outlasts the separate target pass.
The coverage identity concerns path-aligned, conditionally exact verification with one continuation and identical scored and candidate sets. The run-level comparison uses target information on the emitted path; its extension to off-path outputs under a suitable cache attention mask is described in Appendix A.7 .
Ethics Statement
The experiments analyze model probabilities on public benchmark prompts from Spec-Bench and HumanEval. The models and datasets retain their licenses and usage restrictions. The selection rules we study keep the target’s output distribution and change only how many tokens a round emits.

D.2 Selection values with intervals
Table 9 gives the gains of root, root-draw and oracle selection over draft selection and the share of the oracle advantage that root and depth-two selection recover. The root-draw value of a round is one for the drawn token plus the path mass, summed over first-level candidates, of the candidates that each keeps beneath it. When the pool’s first level lacks the drawn token, the tree holds that token alone. This happens in 9 % 9\% to 16 % 16\% of greedy rounds and with probability 11 % 11\% to 19 % 19\% at temperature 1 1 , and exhaustive traversal of draft selection’s tree, which lies in the same pool, then accepts no draft token, while root-draw selection accepts the drawn one.
Each bootstrap draw resamples prompts with all their rounds and keeps every rule and budget together. Every interval lies above zero at both budgets, as does every interval of a greedy root row entered with its softmax probabilities.
Table 13 expresses the root gain in nodes. For each run, it gives the smallest budget at which draft selection reaches root selection’s value at a reference budget and the smallest at which root selection reaches draft selection’s, searching every budget up to 710 710 within the same pool of depths one to eight and repeating the search in every resample. At B = 8 B=8 , draft selection needs 11 11 to 22 22 nodes to reach root selection’s value, and root selection reaches draft selection’s with 4 4 to 7 7 .
A PEARL-style decoder ( Liu et al., 2025a ) uses the root row only for the first draw. It takes the same draw as root-draw selection and counts it as one accepted token, then keeps the part of draft selection’s tree beneath the drawn token, or the drawn token alone when that tree lacks it. Its value exceeds that of draft selection by the probability that the drawn token is missing from the tree’s first level. Draft selection keeps at most B − 1 B-1 descendants of a kept first-level token, and these are its highest-ranked descendants. Root-draw selection keeps the B − 1 B-1 highest-ranked descendants of the drawn token, or all of them when there are fewer, so its value is at least the PEARL-style value in every round. Under the same cap, both decoders keep at most B B nodes.
Table 12 shows that root-draw selection improves expected acceptance over the PEARL-style decoder by up to 14.2 % 14.2\% at B = 8 B=8 and 7.0 % 7.0\% at B = 59 B=59 under the same node cap. All confidence intervals lie above zero. We also find that root-draw selection retains larger trees on average than the PEARL-style decoder: 42 42 to 52 52 versus 26 26 to 38 38 nodes at B = 59 B=59 , and 6.6 6.6 to 7.4 7.4 versus 4.1 4.1 to 5.8 5.8 at B = 8 B=8 .
A variant closer to PEARL, whose drafter commits to one first token, keeps the drafter’s most probable first token with its B − 1 B-1 highest-ranked descendants and verifies the drawn token alone when the draw differs. Its value lies below the PEARL-style value in every run, by 0.5 % 0.5\% to 1.5 % 1.5\% at B = 8 B=8 and 6.7 % 6.7\% to 9.1 % 9.1\% at B = 59 B=59 with every interval excluding zero, so Table 12 compares root-draw selection with the stronger of the two.
Table 12 also compares root-draw selection with a PEARL-style decoder whose pre-draw budget is raised, separately in each run, until its pruned trees hold as many nodes on average as root-draw selection’s. The raised budget mixes the two nearest whole budgets and comes to 81 81 to 96 96 candidates at B = 59 B=59 and 10.4 10.4 to 14.0 14.0 at B = 8 B=8 . The pruned trees then hold more than B B nodes in an expected 38 % 38\% to 53 % 53\% of rounds at B = 59 B=59 and 40 % 40\% to 56 % 56\% at B = 8 B=8 , while root-draw selection’s trees never do.
After mean tree sizes are matched, root-draw selection still improves expected acceptance by up to 4.8 % 4.8\% at B = 8 B=8 and 2.4 % 2.4\% at B = 59 B=59 . Every confidence interval remains above zero when matching is repeated in each resample. The draw is the drafter’s most probable first token in an expected 52 % 52\% to 76 % 76\% of rounds. D.3 Online decoding
The online decoders of Section 5.4 that take the root row from a separate target pass run on all six targets, with the checkpoints, prompts, pools, output limit and seeding of Appendix C . In each round, the drafter grows its pool from the committed context, and a first target pass scores the root alone to give the root row. The pool does not depend on this row, so running the first pass while the drafter works would leave every acceptance value unchanged, as the pipelined runs of Appendix D.14 confirm for the standalone drafters.
The rule selects the tree with that row, and a second pass scores the root and the tree under the tree mask. Exhaustive target sampling then traverses the tree, taking its first draw from the root row. Root-draw selection makes this draw before it selects the tree, and the PEARL-style decoder makes it before it cuts draft selection’s 59 59 -node tree to the part beneath the drawn token, or to the drawn token alone when that tree lacks it. The key-value cache keeps the root and the accepted path, and the continuation becomes the next root.
The two passes compute the root row in batches of different sizes, and the two computations share their argmax in 98.6 % 98.6\% to 99.6 % 99.6\% of rounds and, in the PEARL-style runs, differ by a mean total variation of 0.0041 0.0041 to 0.0129 0.0129 . For Qwen3-4B and Qwen2.5-7B, whose recorded runs and the runs above all used RTX A6000 GPUs, the matched pairs of Section 5.3 share their argmax more often than these two computations in every decoder at both temperatures, and they differ by a smaller mean total variation than the two computations in the PEARL-style runs.
The two rows of a matched pair have the same token, position and key-value cache, and the replay of Appendix C , run with the recorded batches on the capture’s GPU type, reproduces the recorded root rows exactly, so the two rows differ only because different batches compute them.

D.8 Calibrated and reranked draft scores
Table 19 compares two calibrated controls and two rerankers with draft and root selection. The first control replaces q 1 q_{1} with an isotonic estimate of the target probability; the second calibrates every draft factor with a separate map for each depth. Each map is fitted over 200 200 equal-count bins of draft probability on the even-numbered prompts and applied to the odd-numbered ones, and vice versa.
The reranker uses gradient-boosted trees fitted on one half of the prompts and applied to the other to predict the target probability of each first-level candidate, and under greedy decoding whether it is the target’s token. Its inputs, all known before verification, are the draft probabilities of the candidate and its siblings, the draft distribution and pool subtree below the candidate, a token prior estimated on the training half, the task, the prompt length, the round’s position, the previous round’s acceptance and whether the candidate repeats the root’s token.
The token prior averages the target over candidates with the same token and shrinks the average toward the overall mean with a pseudo-count of 20 20 . Within the training half, the candidates are split in alternation, and each one’s prior comes from the other part, so no prior contains its own label. The model is a histogram gradient-boosted classifier under greedy decoding and a regressor under sampling, with 400 400 iterations, learning rate 0.05 0.05 and at most 63 63 leaves. The prediction replaces the first draft factor as the root row does.
Its top-ranked first-level candidate is the target’s most probable one in 60.1 % 60.1\% to 82.8 % 82.8\% of rounds, against 58.7 % 58.7\% to 82.7 % 82.7\% for the draft ranking, where greedy runs count only rounds whose first level contains the target’s token.
The row features come from the token-keyed cache, a same-token row from the previous tree and the row that generated the continuation. For each available row, the reranker reads the candidate’s log probability and its difference from the highest first-level log probability. It also reads the number of rounds since the cache row was stored and the number of previous-tree prefixes that end in the root’s token. Each of these inputs is missing in rounds without its row, and the preceding row’s entry for the continuation token is always missing.
This reranker recovers at most 29 % 29\% of the root gain at B = 8 B=8 and 33 % 33\% at B = 59 B=59 , and in every run its held-out squared error on the first-level targets is below that of the draft probabilities and of the reranker without rows. In every run at both budgets, the 95 % 95\% intervals of its gain over draft selection and of its gain over the reranker without rows lie above zero. Their lower ends are at least 0.27 % 0.27\% and 0.30 % 0.30\% of draft selection’s value at B = 59 B=59 , and 0.81 % 0.81\% and 0.88 % 0.88\% at B = 8 B=8 .
D.9 Coverage from the scored frontier
Scoring the M M highest-ranked candidates includes candidates whose parents lie outside the tree. Such a candidate cannot be the emitted address after exhaustive traversal. Table 21 instead scores only frontier candidates, which lie outside the tree but have their parents in it, in draft order. Forty frontier candidates cover 12 % 12\% to 17 % 17\% of next roots, more than the 41 41 candidates added by the top- 100 100 set, and the complete frontier, 380 380 to 418 418 candidates on average, covers 28 % 28\% to 35 % 35\% , the same share as the whole pool.
D.10 Selection with reused rows
Without a separate root pass, a decoder selects with the exact root row only after a covered round and keeps the draft ranking otherwise, including in the first round of each generation. Each round verifies the tree of the rule it uses and scores the M M highest-ranked candidates in that rule’s order, so its coverage is that of its own tree. Under greedy decoding a round is covered when the greedy token after its accepted path labels a scored candidate. At temperature 1 1 a round holds the row with the probability that the previous round was covered, and that round’s coverage is the scored frontier mass of Equation 5 . For EAGLE-3’s tree this computation gives the recorded coverage in every greedy round.
At the recorded contexts, root selection in rounds that hold the row raises expected acceptance over draft ranking at B = 59 B=59 by 0.5 % 0.5\% to 0.9 % 0.9\% when verification scores the 100 100 highest-ranked candidates and by 1.1 % 1.1\% to 2.3 % 2.3\% when it scores the whole pool, and at B = 8 B=8 by 4.9 % 4.9\% to 10.1 % 10.1\% and 5.2 % 5.2\% to 11.1 % 11.1\% , with every interval above zero.
With the 100 100 candidates, 41 % 41\% to 56 % 56\% of rounds hold the row at B = 8 B=8 , against 10 % 10\% to 15 % 15\% at B = 59 B=59 , since the smaller trees exit closer to the root and leave 92 92 of the 100 100 scored candidates outside the tree. Scoring the whole pool, 710 710 prefixes, gives the largest coverage that any scored subset of the pool reaches. By Theorem 2 , whatever the gain in rounds that hold the row, a decoder that is never covered and scores no more prefixes in each round has emitted at least as many tokens as such a decoder after every round.

D.14 Pipelined decoding
Llama-3.1-8B and Qwen3-8B decode all 644 644 prompts again with the standalone drafters of Appendix D.13 , now with the drafter in its own process on a second RTX A6000 GPU, as in PEARL’s deployment ( Liu et al., 2025a ) . Target and drafter run at batch size one with a static key-value cache, and every call after the prompt prefill replays a captured CUDA graph. In each round, the target process sends the newly committed tokens to the drafter, which grows its pool and returns it. The drafter waits while the target verifies, so no decoder uses PEARL’s post-verification, which drafts during verification.
Draft selection waits for the pool and verifies the continuation token and its B B -node tree in one target pass. The PEARL-style decoder, root-draw selection and root selection run a one-token target pass on the continuation token while the drafter works. They draw the first token from the returned root row and then verify their trees as described in Appendix D.3 . Root selection ranks the pool with this row and verifies its whole tree. When the drawn token is not on the tree’s first level, which happens in 1.2 % 1.2\% to 8.4 % 8.4\% of its rounds at B = 59 B=59 , the drawn token becomes the round’s continuation and the second pass is skipped.
The settings are T ∈ { 0 , 1 } T\in\{0,1\} and B ∈ { 8 , 59 } B\in\{8,59\} , and a decode stops at its first end-of-sequence token or after the round in which its output reaches the default limit. After warm-up decodes on two prompts, each prompt runs all sixteen combinations of decoder, T T and B B once, in an order rotated by its position in a seeded prompt order, so resampling prompts also resamples the timing noise of single decodes.
A decode’s speed counts the tokens emitted up to the first end-of-sequence token over the time from the start of the target prefill to the last commit, so it includes the prefill, and a run’s speed divides the summed tokens by the summed time. Gains compare the speeds of two decoders on the same prompts, with 95 % 95\% percentile intervals from 2,000 2{,}000 paired bootstrap resamples of prompts. All prompts are retained in the timing comparison.
Drafting takes a median of 50 50 to 51 51 ms a round and the one-token target pass 26 26 to 28 28 ms, so that pass ends while the drafter works, and the median round of root-draw or root selection lies within 0.4 0.4 ms of draft selection’s. At B = 59 B=59 , root selection decodes 3.2 % 3.2\% to 6.2 % 6.2\% faster than draft selection, root-draw selection 3.5 % 3.5\% to 9.6 % 9.6\% faster and the PEARL-style decoder 4.3 % 4.3\% to 8.3 % 8.3\% faster, and no lower end of their intervals falls below 2.7 % 2.7\% . At B = 8 B=8 , root selection decodes 9.6 % 9.6\% to 17.3 % 17.3\% faster than draft selection, and Table 28 gives the gains of root-draw selection and the PEARL-style decoder, whose intervals also exclude zero.
In these runs, root-draw selection’s trees hold 16 16 to 18 18 more nodes on average than the PEARL-style decoder’s at B = 59 B=59 and 1.4 1.4 to 2.0 2.0 more at B = 8 B=8 . Enlarging the PEARL-style tree at B = 59 B=59 to equal mean size would leave more than 64 64 tokens to verify after pruning, beyond the largest captured CUDA graph, in 45 % 45\% to 51 % 51\% of rounds. To time the two decoders at matched tree sizes, we lower root-draw selection’s cap instead, in each run to the smallest value at which its mean expected tree size on the recorded rounds of Appendix D.13 still reaches the PEARL-style decoder’s at B = 59 B=59 , between 40 40 and 43 43 nodes.
Both decoders then decode all 644 644 prompts again in the same deployment, interleaved as before, with two sampling seeds at T = 1 T=1 and all prompts retained. In Table 29 , root-draw selection verifies at least as many nodes on average as the PEARL-style decoder and decodes 1.3 % 1.3\% to 2.2 % 2.2\% faster. Its expected acceptance at these caps on the recorded rounds is 1.1 % 1.1\% to 2.5 % 2.5\% higher. These offline gains exceed the equal-size gains of Appendix D.13 , which match the two decoders at root-draw selection’s larger trees.
