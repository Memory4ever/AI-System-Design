Transfer tests multi-turn function calling on BFCL (Patil et al., 2025) and nested function composition
on NESTFUL (Basu et al., 2024), without further adaptation. Figure 5 shows percentage-point
gains over untrained bases; BRACEleads at all three scales. NESTFUL (Basu et al., 2024) win rate

Table 3 shows lower solve rates in every component ablation at all three scales. Removing the

6 RELATEDWORK
Task selection and rollout allocation.Adaptive curricula change which tasks an agent encounters.
PLR prioritizes levels using TD error (Jiang et al., 2021), while problem-level RL replay uses
empirical intermediate success rates (Fatemi, 2026). Other selectors use reward dynamics (Zheng
et al., 2025b), task difficulty (Qu et al., 2025; 2026; Gao et al., 2025), estimated learning impact (Li
et al., 2025), or replay priorities (Sun et al., 2025). For group-relative training, DAPO filters all-equal
groups after generation (Yu et al., 2025). VIP allocates rollout counts by predicted gradient variance
(Nguyen et al., 2026); DUET also allocates token budgets (Hu et al., 2026), and TRACE predicts
mixed outcomes at prompts and interaction prefixes using an independent rollout model (Zou et al.,
2026). BRACEinstead selects tasks for fixed-size groups using capped historical evidence, posterior
uncertainty, and a correlated reward model. The correlation correction improves forecast calibration
while preserving known-probability task ranks at fixed group size (Proposition 1); historical evidence
and relative weights therefore matter to the resulting allocation. Policy-gradient estimators (Liu et al.,
2025; Ahmadian et al., 2024; Zheng et al., 2025a) address a separate choice.
Tool-using agents and harness search.Multi-turn training studies delayed rewards and tool
interaction (Zhou et al., 2024; Wang et al., 2025b; Jin et al., 2025; Qian et al., 2025). MCP work
studies protocol architecture and overhead, tool discovery, and agent evaluation (Hou et al., 2026;
Anjum et al., 2026; Fei et al., 2025; Guo et al., 2026; Wang et al., 2025a), while benchmarks measure
tool execution and function composition (Patil et al., 2025; Basu et al., 2024; Qin et al., 2023; Yao
et al., 2024). Harness-search systems propose edits to prompts, workflows, or agent code (Hu et al.,
2025; Zhang et al., 2025; Agrawal et al., 2026; Lee et al., 2026; Zelikman et al., 2024; Zhang et al.,
2026). DISCORDaddresses the subsequent retention decision with exact conditional paired inference
(McNemar, 1947) and decision-preserving curtailment (Alling, 1963); alternative matched-pair tests
include exact unconditional procedures (Suissa & Shuster, 1991).
Statistical foundations.Beta–Binomial models describe clustered binary outcomes (Kleinman, 1973;
Crowder, 1978; Williams, 1975; Ridout et al., 1999) and motivate BRACE’s within-group forecast.
Its task selection is related to active learning (Settles, 2009; Houlsby et al., 2011) and adaptive replay
(Schaul et al., 2016), with non-degenerate group probability as the allocation objective.
7 CONCLUSION
Reward disagreement provides a common lens for allocating evaluation and training computation.
DISCORDuses exact paired inference and decision-preserving stopping to retain harness edits when
observed disagreements support improvement. BRACEuses capped historical evidence, posterior
uncertainty, and reward dependence to forecast mixed-reward groups before generation. Across three
model scales, BRACEachieves higher observed held-out MCP solve rates than the compared methods,
reaches their strongest plotted peaks with fewer new rollouts, and transfers to BFCL and NESTFUL
without further training. Together, the methods direct interaction budget toward harness comparisons
that can change retention and rollout groups that can supply a group-relative training signal.

For two policies evaluated on the same task–seed pairs, letb count pairs won only by the candidate and
c count pairs won only by the reference. The paired solve-rate difference is(b−c)/n, where n includes
both concordant and discordant pairs. Effects expressed in percentage points are 100(b−c)/n ; a

B.5 TRANSFER BENCHMARKS AND PROCESSING
BFCL v4 (Patil et al., 2025) evaluates multi-turn function calling on800tasks from four categories:
base, long context, miss func, and miss param, with 200 tasks each. The official checker
evaluates the executed result against the reference trajectory. The evaluation uses a common task index
across arms and one response per task at temperature 0.001. Transfer evaluation uses checkpoints
from AWM (Wang et al., 2026) training, without further training on BFCL (Patil et al., 2025). The v4
multi-turn categories are separate from the v3 single-turn split used for harness-retention experiments
in Appendix C.4.
NESTFUL (Basu et al., 2024) evaluates nested function composition. A completion specifies API
calls with dependencies, which are executed against the benchmark implementations. The win-rate
metric checks whether execution yields the recorded answer; it differs from the benchmark’s full-
sequence matching metric. Evaluation uses 1,861 tasks, one completion per task, and the same
task index across arms. Two processing changes relative to the released Llama branch are applied
uniformly: function specifications are embedded as JSON rather than as double-encoded strings, and
completions are parsed from the first balanced top-level [...] span. These changes preserve the
within-study comparison but prevent direct numerical comparison with results obtained under the
benchmark’s original processing convention.
Figure 5 reports percentage-point changes in BFCL (Patil et al., 2025) pass rate and NESTFUL (Basu
et al., 2024) win rate relative to each scale’s untrained base model, rather than absolute rates. Neither
benchmark supplies training data or task-selection feedback to the reported AWM (Wang et al., 2026)
training runs. Because the benchmarks use different task structures and success criteria, their rates
should be interpreted within each benchmark.

et al., 2025) and API-Bank (Li et al., 2023), holding the tool surface fixed and changing only random
seeds makes the comparison inert by construction.

C.3 EXACT CURTAILMENT
Fix the maximum number of evaluation pairs and the terminal significance threshold before inspecting
outcomes. After each evaluation block, consider every feasible completion of the remaining pairs: a
pair can add a candidate win, an incumbent win, or a concordance. Stop and accept only if every
completion would be accepted by the terminal test; stop and reject only if every completion would be
rejected. Otherwise, evaluate the next block.
ForRremaining pairs, this condition can be expressed using
