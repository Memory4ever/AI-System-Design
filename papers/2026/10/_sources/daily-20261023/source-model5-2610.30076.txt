Abstract
Language models make it easy to build classifiers by simply prompting a model with the sample to classify. However, their predictions are neither deterministic nor uniformly reliable across samples. How can we combine predictions from different models to improve reliability? We view LLM classifiers as noisy measurement instruments of an underlying target label. Our goal is to maximize average classification accuracy at a given average query cost. To this end, we introduce circuits that organize LLM classifiers into an adaptive sequence of queries and decisions. We then characterize the optimal circuit, obtain the fundamental limits of achievable accuracy, and provide practical insights on realizing the optimal circuit. Across seven classification tasks spanning safety, health, political science, human preference, agent evaluation, decision-making and reasoning, our method improves the cost–accuracy frontier over routing and cascading baselines. We provide our code here .

1 Introduction
Large language models (LLMs) are increasingly used in prediction and classification tasks as (auto-) raters ( Vu et al., 2024 ) , verifiers ( Cobbe et al., 2021 ; Kwok et al., 2026 ) , judges ( Zheng et al., 2023 ; Chiang et al., 2024 ) , and more. A main draw of LLMs as classifiers is their ease of implementation and deployment ( Brown et al., 2020 ; Liu et al., 2023a ) . By simply specifying a new classification task in natural language, we can prompt these systems to assign labels in a range of applications such as content moderation ( OpenAI et al., 2024 ) , scientific review ( Liu & Shah, 2023 ) , guardrailing ( Inan et al., 2023 ) , and qualitative data analysis in social sciences ( Halterman & Keith, 2025 ) .
Here, a “classifier” is defined by a combination of backend model choice, instruction prompt, grading rubric, decoding parameters (e.g., temperature, chain-of-thought), and more. “Fitting” a classifier then boils down to navigating these choices during inference.
Consider first the task of designing a single LLM classifier. Even after fixing the model and instructions, repeated evaluations of the same prompt can return conflicting labels ( Haldar & Hockenmaier, 2025 ; Wang et al., 2023a ) 1 1
1
Unless the model is decoded with temperature T = 0 T=0 , a choice rarely made in practice, particularly if the LLM reasons prior to responding. . It is therefore useful to view an LLM classifier as a noisy measurement instrument ( Brennan, 1992 ; Kahneman et al., 2021 ) . Naturally, if an instrument is noisy, we should collect more than one measurement with our tool, or measure with multiple (independent) instruments to control error. When using LLMs to classify a given prompt, this intuition suggests we can improve classification accuracy by collecting predictions from different models and instruction configurations.
Of course, querying multiple models incurs a cost (e.g., API calls add up). A key challenge is deciding which classifier, if any, to query next as we collect measurements. These decisions create a tradeoff between accuracy and expected inference cost. In this paper, we ask:
How should we combine LLM classifiers to optimize the cost-accuracy trade-off in a given task?

Strategies for combining classifiers, such as bagging ( Breiman, 1996 ) and boosting ( Schapire & Freund, 2013 ) , are familiar in machine learning. More recently, this question has received growing attention in work on LLM routing ( Ding et al., 2024 ; Ong et al., 2025 ) , cascading ( Chen et al., 2024b ; Jung et al., 2025 ; Bouchard, 2026 ) , and multi-judge evaluation ( Verga et al., 2024 ; Turkmen et al., 2026 ) . These methods show that combining multiple LLM classifiers outperforms any single model.
We refer to any procedure that queries one or more LLM classifiers and combines their outputs into a final decision as a classification circuit , or a circuit for short. The name reflects how these strategies use LLMs. The classifiers act as components, while decision rules determine how their outputs are passed forward, combined, or used to select the next query. Changing either the components or how they are connected produces a different circuit. For example, routing queries a single selected model, cascades query models sequentially in a fixed order, and voting schemes like majority voting query several models in parallel and aggregate their outputs. Different circuits using the same set of classifiers can therefore have different accuracy and cost, as shown in Figure 1 .
Given the many ways of combining LLM classifiers, which circuit is best? What is the “optimal” circuit when samples come from a known distribution, such as a large safety classification dataset? What properties should we promote across classifiers to improve accuracy, such as independence or decorrelated errors?
And what is the best achievable tradeoff between cost and accuracy?
We show that existing ways of combining LLM classifiers are facets of a common decision-theoretic formulation. This formulation maximizes average classification accuracy while minimizing the average cost, and is essentially a Bayesian sequential decision problem ( Wald, 1992 ; DeGroot, 1962 ) , closely related to sequential hypothesis testing ( Chernoff, 1959 ; Naghshvar & Javidi, 2013 ) .
The fundamental challenge is to determine the value of an additional query given the observed measurements. For this formulation, an optimal circuit is given by the solution to a dynamic program.
Analyzing this dynamic program offers several insights into combining LLM classifiers. A first insight is that a query is valuable not only for its label, but also for what it reveals about how hard the sample is to classify. When classifiers disagree, the circuit learns to spend more queries on difficult prompts while resolving easier ones quickly. A second insight concerns how accuracy improves with additional query cost. For a fixed sample, asymptotically, the optimal error decreases with increasing cost at a rate determined by the most informative classifier per unit cost. A final, more obvious insight is that the error of any circuit lies between two limits: the Bayes error before any query is made and the Bayes error given the outputs of all classifiers. The latter is the accuracy ceiling for any way of combining a given set of classifiers.
Solving for this dynamic program requires a joint distribution between the ground truth label and instruments for a prompt. In practice, however, the joint distribution is unknown. We show that this optimal circuit can nevertheless be approximated in two steps. First, we fit a single probabilistic model of the joint distribution of the label and classifier outputs using a labeled training set. Then, we solve the dynamic program with the learned model, which results in a prompt-dependent policy that determines which LLM to query and when to stop. In a range of classification tasks, this two-step approach Pareto-dominates routing and cascading baselines in the cost–accuracy tradeoff.
Contributions. Our contributions are as follows:
•
Optimal classification circuits. We introduce classification circuits as a general framework for combining LLM classifiers. Under a cost–accuracy tradeoff, we show that the optimal circuit for a given prompt can be solved exactly through a dynamic program.
•
Properties of classification circuits. We identify the accuracy ceiling for a fixed pool of classifiers, quantify the value of adding complementary classifiers, and show how the distribution of prompt difficulty determines how average accuracy scales with cost.
•
Learning circuits from data. We show how to approximate the optimal circuit from a labeled training set by learning the distributions required by the dynamic program from prompt embeddings and classifier outputs. Across seven classification tasks, circuits improve the cost–accuracy frontier over routing and cascading baselines.

3 Optimizing Classification Circuits
Classification circuits encompass many ways of combining the same instruments. We study one particular criterion for choosing among them, the expected cost–accuracy tradeoff, and show how to construct the resulting circuits for any prompt. We present all proofs in Appendix B .

4 Analysis of the Optimal Circuit
This section studies the properties of optimal circuits. For a fixed instrument pool ℋ \mathcal{H} , we first characterize the two endpoints of the error–cost tradeoff: (i) when it is optimal to make no queries, and (ii) what the best possible accuracy is using all the instruments. We then ask how adding one additional instrument to an existing pool improves this maximum accuracy, which yields practical guidance for assembling a pool of instruments. Finally, we derive scaling laws for circuits, i.e., the rate at which the error of the optimal circuit decreases with query cost on a prompt, and how this rate changes once averaged over a population of prompts with varying difficulty . All proofs are provided in Appendix B of the appendix.

5 Experiments
Setup. We consider seven tasks: AgentJudgeBench ( Verma et al., 2026 ) for judging whether an AI agent’s planned tool calls are correct, BeaverTails ( Ji et al., 2023 ) for safety classification, BIG-Bench Hard ( Suzgun et al., 2023 ) for reasoning questions, Decision Index ( Multimodal Art, 2026 ) for decision tasks, HealthBench ( Arora et al., 2025 ) to evaluate whether a text satisfies a physician’s rubric, LMArena ( Chiang et al., 2024 ) for classifying human rater preference, and PolitiCause ( Garcia-Corral et al., 2024 ) for detecting causality in political text. For each task, a training set is used to estimate the LMCircuit (as described in Section 3.2 ) required by the dynamic program. We then vary the parameter λ \lambda on a validation set to obtain circuits at different operating points and report test accuracy against average query cost. Within each task, costs are normalized relative to the most expensive instrument. Additional details are in Appendix C .
We benchmark against (1) Predictive routers , including RouteLLM ( Ong et al., 2025 ) , HybridLLM ( Ding et al., 2024 ) , and CARROT ( Somerstep et al., 2025 ) ; (2) Model cascades , including Cascade Routing ( Dekoninck et al., 2025 ) , Consistency Cascade ( Yue et al., 2024 ) , Cascaded Selective ( Jung et al., 2025 ) , and FrugalGPT ( Chen et al., 2024b ) ; (3) Sampling methods , namely Adaptive-Consistency ( Aggarwal et al., 2023 ) ; and (4) individual instruments and majority voting.
5.1 Results
Figure 4 : LMCircuit improves the cost-accuracy frontier over routing and cascading baselines. As λ \lambda decreases and additional queries become less costly, the circuits make more calls and also change which instruments they use (see lower panel). The allocations differ substantially across tasks, indicating that the value of an instrument depends on the classification problem and on other measurements available to the circuit.
Figure 5 : LMCircuit is substantially faster to construct than most routing and cascading baselines. Across all seven tasks, LMCircuit is trained in 1–3 minutes, while some baselines require minutes to hours.
LMCircuit improves the cost–accuracy frontier. Across the seven tasks, the learned circuits attain higher accuracy than every individual instrument and than the routing and cascade baselines at nearly all budgets ( Figure 4 ). The choice of instruments that the circuit uses depends on the task and is not predictable from cost or accuracy alone. On LMArena, the two mid-cost Gemma models (26B and 31B) are the most informative per unit cost, and the circuit queries almost exclusively these two for most budgets. On BeaverTails, the cheapest model, Gemma 4B, carries the most information per unit cost ( Figure 11 ). Hence, the circuit queries it on most prompts and reserves the expensive models for the highest budgets.
LMCircuit provides calibrated decisions. For a given prompt z z , the distribution estimator outputs an estimate of Pr ⁡ ( Y = 1 ∣ z ) \Pr(Y=1\mid z) . Based on its confidence, LMCircuit assesses whether the prompt is easy or hard, selects the instrument path accordingly, and updates its posterior belief after each measurement. As expected, under the same cost-accuracy parameter λ \lambda , harder prompts require more model calls ( Figure 10 ). An advantage of our method is that LMCircuit ’s prior alone can yield a label prediction without querying any instrument . Therefore, at the low-cost end of the frontier, the average query cost can fall below that of the cheapest individual instrument. Figure 6 further shows that LMCircuit produces better calibrated decisions on unseen data.
LMCircuit learns whether more queries help and how reliable each instrument is. For any given prompt, initially, the circuit predicts its label from the prompt embedding alone, without querying any instrument (Remark 2 ). We call this the embedding prediction . To investigate the impact of LLM calls on top of embedding predictions, we organize unseen prompts by the fraction of recorded calls that return the correct label ( Figure 9 ). On noisy prompts, where this fraction lies between ( 1 / 2 , 1 ) (1/2,1) , the circuit at budget 1 improves the accuracy of embedding prediction by 5%–44%. On prompts where every call is correct, it matches majority voting (within 1.3% accuracy difference) while using 38%–86% fewer calls.
The fitted model of LMCircuit is accurate about the instruments. The dynamic program relies on the fitted model’s estimates of how each instrument responds on a given prompt. Figure 8 shows that, without access to test labels, the fitted model predicts 1) each instrument’s accuracy on unseen prompts, 2) the correlations of the instruments’ answers and errors across prompts. Across the seven tasks, the implied correlations between instruments’ answers, and between their errors, are within 4%–17% of the measured values, and the implied accuracy of each instrument is within 1.2%–3.6% of its measured accuracy.
LMCircuit is easy and fast to implement. Our method is less complex than many baselines ( Figure 5 ), attaining significantly shorter training times. The estimation step uses a simple neural network together with pretrained embeddings of prompts. We do not require token probabilities or training larger models (such as DistilBERT or DeBERTa) for each instrument as in other methods, and the dynamic program is cheap for moderate pools of models. We note, however, that the dynamic program grows exponentially with the number of models. In many applications, this is less restrictive than it may seem, since a small, well-chosen pool of classifiers is often sufficient (see Section 4.1 for guidance on model pool selection).
Types of noise in measurements: A measurement instrument is subject to two types of noise: (1) stochastic noise , errors that can be reduced through repeated or correlated measurements, and (2) systematic noise , errors that are inherent to how the instrument was trained. Our results show that the dynamic program automatically adapts to both. It selects highly correlated models to reduce (1) when queried models are moderately accurate ( ∼ \sim 75–80%, Figure 13 ), and less correlated models to reduce (2) when queried models are less accurate ( ∼ \sim 63–66%, Figure 14 ).
6 Conclusion
As LLM classifiers become components of larger systems, a practical question is how inference should be organized and allocated among them to maximize accuracy at the lowest expected cost. We take a decision-theoretic view of this problem, using a lightweight probabilistic model to characterize the available classifiers and a dynamic program to decide what to query and when to stop. We are then able to generate circuits for any prompt while offering control on the error–cost tradeoff. One challenge is to extend this to larger pools of general measurement instruments with potential feedback among them. More broadly, our framework can broaden access to high-quality and automated decision-making for practitioners without frontier-model budgets.

Appendix A Related Work
This work is closely related to the following fields: 1) Sequential information acquisition (decision-theoretic foundations), 2) Routing and cascading methods, 3) LLMs as classifiers, judges, and annotators, 4) Theory of LLM orchestration and test-time compute, and 5) Aggregating Noisy Classifiers.
Sequential information acquisition:
Our formulation is based on sequential hypothesis testing. Wald’s sequential probability ratio test ( Wald, 1992 ) established that stopping adaptively, as soon as the accumulated evidence crosses a threshold, requires fewer samples on average than any fixed-sample test with the same error probabilities. Chernoff extended this to the sequential design of experiments ( Chernoff, 1959 ) , where the decision-maker chooses which experiment to run next, and DeGroot cast the problem as Bayesian decision-making in which each experiment is valued by its expected reduction in posterior uncertainty ( DeGroot, 1962 ) . These fundamental ideas are the principle behind our circuits. Since each LLM query is a costly experiment, the circuit selects the next instrument by the expected improvement in its posterior belief, and it stops once that belief is confident enough that further queries are not worth their cost. The modern literature on active hypothesis testing and controlled sensing ( Naghshvar & Javidi, 2013 ; Nitinawarat et al., 2013 ; Vershinin et al., 2026 ) develops this framework further, deriving information-theoretic lower bounds on expected sample size under multiple hypotheses and heterogeneous action costs, and showing that simple posterior-driven policies attain the optimal error exponents. These works solve a single testing instance in which the observation model is known in advance. In our setting, each prompt is one such instance, but there are countably many possibilities of prompts, and the observation model of each instrument for any given prompt must be learned from data.
Routing and Cascading Methods:
In routing, a prompt is assigned to a single model in a pool of models that is predicted to handle it best. For example, RouteLLM ( Ong et al., 2025 ) trains binary routers between a strong and a weak model, while HybridLLM ( Ding et al., 2024 ) trains a classifier to predict whether a cheap model’s answer will be of acceptable quality and routes to the large model only when it is needed. CARROT ( Somerstep et al., 2025 ) routes by predicting both expected quality and expected cost per model for a query and minimizing a weighted combination, with a minimax-rate-optimality guarantee for the resulting router. More routing mechanisms ( Lu et al., 2023 ; Feng et al., 2025 ; Wang et al., 2025 ; Zhang et al., 2025 ; Song et al., 2025 ; Hu et al., 2024 ) can be found in the survey ( Moslem & Kelleher, 2026 ) . The circuits proposed in this work generalize routers since a circuit decides after each observation whether the evidence collected so far is sufficient or whether another model should be queried.
In cascading, models are queried one after another in a fixed order, typically from cheapest to most expensive, and the process stops as soon as some confidence or quality criterion is met. FrugalGPT ( Chen et al., 2024b ) chains LLM APIs from cheap to expensive and uses a learned scorer to decide whether the current answer is reliable enough to stop. Automix ( Aggarwal et al., 2024 ) has a small model self-verify its own answer and uses this verification signal to decide whether to escalate to a larger model. Yue et al. (2024) escalate based on agreement between a weak model’s answers under different reasoning formats, treating disagreement as the trigger for the strong model. Jung et al. (2025) use judges of increasing size with a conformal-style confidence threshold that guarantees a target level of agreement with humans. More cascading methods can be found in the survey ( Moslem & Kelleher, 2026 ) . Our approach differs from these cascades in two ways. First, a cascade queries models in a fixed order and only decides whether to escalate, whereas a circuit chooses which model to query next based on the prompt and the outputs observed so far. Second, a cascade typically returns the output of the model at which it stops, discarding earlier outputs once they have triggered escalation, whereas a circuit combines all observed outputs into a posterior belief on the label and predicts from that belief.
Among cascading methods, TREACLE ( Zhang et al., 2024 ) and cascade-routing ( Dekoninck et al., 2025 ) do not follow a fixed order of models. Using reinforcement learning, TREACLE ( Zhang et al., 2024 ) learns a policy that selects the next LLM and prompting scheme based on the question and the consistency of responses so far, under a budget shared across a dataset of questions. Our circuits also adapt the next query to past model outputs, but rather than training the policy itself, we learn a probabilistic model of how each instrument responds on a given prompt and compute the optimal query-and-stop policy from it by dynamic programming. The resulting circuit is optimal with respect to the learned model and its error–cost tradeoff can be analyzed, neither of which holds for a policy trained end-to-end by reinforcement learning. Cascade routing ( Dekoninck et al., 2025 ) selects the next model after each output by estimating, for each set of remaining models, the quality of the best output it would produce net of its cost, and finally returns the output with the highest estimated quality. Our circuits also choose the next model from the full pool after each observation, but differ in two respects. The decision to continue is solved exactly by dynamic programming rather than by a one-shot estimate of what the remaining models would yield, and the prediction combines all observed outputs through the posterior on the label rather than selecting one output.
LLMs as classifiers, judges, and annotators.
Prompting turns an LLM into a classifier without training ( Brown et al., 2020 ; Liu et al., 2023a ) , and this has made LLMs default raters in many pipelines. They judge model outputs ( Zheng et al., 2023 ; Liu et al., 2023b ; Wang et al., 2023b ) , either as prompted frontier models or as judges fine-tuned for the task ( Kim et al., 2024 ; Zhu et al., 2025 ; Vu et al., 2024 ; Huang et al., 2025 ) . They provide feedback for alignment ( Lee et al., 2024 ) , act as safety classifiers and guardrails ( Inan et al., 2023 ; Han et al., 2024 ; OpenAI et al., 2024 ) , and annotate text in the social sciences and in scientific review ( Halterman & Keith, 2025 ; Liu & Shah, 2023 ) . A parallel line of work measures the reliability of raters. This includes documenting position and verbosity biases, disagreement with humans, and vulnerability to adversarial inputs ( Tan et al., 2025 ; Thakur et al., 2025 ) , as well as low intra-rater reliability, where the same judge returns different labels across runs ( Haldar & Hockenmaier, 2025 ) .
Theory of LLM orchestration and test-time compute:
A growing body of work analyzes how to allocate inference across LLM calls. For a single model, the test-time scaling literature studies how accuracy improves with the number of LLM calls or the amount of verification ( Snell et al., 2025 ; Singhi et al., 2025 ) . Within this line, Chen et al. (2024a) shows that accuracy under majority voting can be non-monotone in the number of calls, Huang et al. (2026a) give sample-complexity bounds for voting and verifier-based selection, and Huang et al. (2026b) characterize when to stop sampling through Bayesian optimal stopping.
For multiple models, routing has been analyzed as a cost-aware prediction problem ( Somerstep et al., 2025 ) . Cascades have been studied from several angles: as a sequence of linear programs ( Dekoninck et al., 2025 ) , as a Pandora’s Box search problem ( Belloni et al., 2026 ) , and as a queueing system with congestion ( Guo et al., 2026 ) . Information-theoretic criteria have also been proposed for choosing which models to include in an ensemble ( Turkmen et al., 2026 ) . These rest on older foundations in metareasoning ( Hay et al., 2012 ) , adaptive submodularity ( Golovin & Krause, 2011 ) , and learning to defer ( Mao et al., 2023 ) . Closest to our analysis, concurrent work by Li et al. (2026) studies sequential binary classification over heterogeneous LLMs with known accuracies, costs, and latencies. They show that in the high-confidence limit a policy alternating between two hypothesis-specific specialists is asymptotically optimal. Our asymptotic analysis agrees with this: under symmetric accuracies the two specialists coincide, and the optimal circuit concentrates its cost on the instrument with the highest information rate per unit cost. These works, however, analyze a single instance with known model parameters and unlimited repeated queries. Our main focus is on the practical problem of a finite pool of instruments whose reliabilities vary across prompts and must be learned from data, for which we solve the exact dynamic program and show that the resulting circuits improve the cost–accuracy frontier in practice.
Aggregating Noisy Classifiers:
We draw from work on combining the outputs of multiple noisy classifiers to determine a true label. In the context of LLMs, aggregating the outputs of smaller models can be used to approximate the judgement of frontier models at lower cost ( Verga et al., 2024 ) . Previous work in crowdsourcing and weak supervision ( Dawid & Skene, 1979 ; Ratner et al., 2016 ) learn the error rate of each individual classifier and aggregate them for the distribution over the true label, assuming independence between the errors of each classifier. Ensemble diversity ( Dietterich, 2000 ) extends this to a machine learning setting by accounting for the correlation of errors between models, which remains an important hurdle for combining the outputs of large language models ( Goel et al., 2025 ; Kim et al., 2025 ; Kohli, 2026 ) .
In this spirit, our probabilistic model learns a distribution over their responses and prompt embeddings, enabling the dynamic program to account for correlation between model outputs.

Appendix C Additional Experimental Details
C.1 Data
In this work, we consider the following seven classification datasets.
AgentJudgeBench ( Verma et al., 2026 ) .
Each prompt is a user request, the tools available to an AI agent and the tool calls the agent planned, together with one of two criteria: whether the plan uses exactly the right set of tools (tool selection), or whether it covers every part of the request (query coverage). An instrument answers whether the plan fully meets the criterion without seeing the reference plan. We draw 1,000 requests, giving 20,850 prompts. The seven instruments are: Prometheus-2-7B, gpt-oss-20b, gpt-oss-120b, QwQ-32B, Gemini-2.5-Pro, GPT-5.4 and Claude Sonnet 4.5.
BeaverTails ( Ji et al., 2023 ) .
Each prompt is a user request together with a model’s response. An instrument answers whether the response is unsafe under the benchmark’s harm categories.
BIG-Bench Hard ( Suzgun et al., 2023 ) .
Each prompt is a question with two answer options from one of eight tasks (boolean expressions, causal judgement, formal fallacies, hyperbaton, navigate, snarks, sports understanding and web of lies), with 1,865 questions in total. An instrument answers which option is correct. The 46 instruments are models from 0.36B to 123B parameters.
Decision Index ( Multimodal Art, 2026 ) .
Each prompt is a request from one of six binary decision tasks: whether clinical-trial reports entail a statement (NLI4CT), a yes/no question about cause and effect (CLadder), which of two limericks is the original (BPoMP), whether Wikipedia introductions support a multi-hop claim (HoVer), whether a tweet is sarcastic (iSarcasmEval) and which of two headline edits is funnier (Humicroedit), with 24,928 questions in total. The 18 instruments are entrants of the Decision Index leaderboard, from 0.4B to 36B parameters.
HealthBench ( Arora et al., 2025 ) .
Each prompt is a conversation between a user and an AI assistant together with one rubric criterion written by physicians, and an instrument answers whether the last response meets the criterion, using the benchmark’s grading instruction. Each prompt was judged by two to five physicians. Therefore, the target is the probability that a randomly chosen physician judges the criterion met. The eight instruments are configurations of three reasoning models : Granite 4.2 3B with reasoning off, low and default, and gpt-oss-20b (low, medium and high effort) and gpt-oss-120b (low and medium effort) ( Agarwal et al., 2025 ) .
LMArena ( Chiang et al., 2024 ) .
Each prompt is a user message together with two responses and an instrument answers which response is more likely to be preferred (A or B). The order in which the two responses are shown is drawn at random for every run of the prompt. We consider 34,952 single-turn English comparisons.
PolitiCAUSE ( Garcia-Corral et al., 2024 ) .
Each prompt is one sentence from political text, and an instrument answers whether the sentence states a causal relation.
On BeaverTails, HealthBench, LMArena and PolitiCAUSE, we query the instruments ourselves. Each instrument is given the dataset’s official classification instruction, with the model’s default decoding (unless we state otherwise). BeaverTails, LMArena and PolitiCAUSE share seven instruments: Gemma 4 ( Team et al., 2026 ) (E2B, E4B, 26B-A4B and 31B, instruction-tuned) and Qwen3 ( Yang et al., 2025 ) (4B, 8B and 32B). At their defaults, the Gemma models answer directly and the Qwen3 models reason before answering. On AgentJudgeBench, BIG-Bench Hard and Decision Index, we use the answers each benchmark recorded. No call costs were recorded there, so on BIG-Bench Hard and Decision Index a call costs $0.01 per million tokens per billion active parameters, and on AgentJudgeBench we price each call at the model’s API price with the prompt’s input tokens and an assumed output length.
Each dataset is split into five folds, keeping prompts that share a source together. Each fold serves once as the test set, and the remaining prompts are divided into training and validation.
Embedding model.
The embedding ϕ ⁡ ( z ) \phi(z) is built from Qwen3-Embedding-0.6B ( Yang et al., 2025 ) with last-token pooling, which gives a 1024-dimensional vector per text.

C.4.3 How does the circuit allocate its queries?
We first examine how the value of additional queries depends on the reliability of the instrument pool for a given prompt; see Figure 9 . For a given prompt z z , let r ⁡ ( z ) r(z) be the proportion of the recorded calls of the instruments the circuit can query that return the label y ⁡ ( z ) y(z) . A prompt is (1) all right if r ⁡ ( z ) = 1 r(z)=1 , (2) noisy if 1 / 2 < r ⁡ ( z ) < 1 1/2<r(z)<1 , (3) mostly wrong if 0 < r ⁡ ( z ) ≤ 1 / 2 0<r(z)\leq 1/2 , and (4) all wrong if r ⁡ ( z ) = 0 r(z)=0 . On HealthBench, prompts on which the physicians disagree are left out. On noisy prompts, correct measurements occur more often, so additional queries provide further evidence for the correct label. On mostly wrong and all wrong prompts, the measurements favor the incorrect label, so additional queries to the same pool tend to reinforce the error.
