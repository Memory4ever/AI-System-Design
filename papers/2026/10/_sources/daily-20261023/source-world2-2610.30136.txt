Abstract
Recent world action models provide visual foresight and future prediction for robot manipulation, but lack explicit mechanisms for compositional skill reuse. Agentic robotics combines code-based planning and reasoning with reusable skills, but often lacks predictive grounding in physical dynamics.
We introduce AW-0 ,
an agentic world action model framework that integrates code-based planning with joint video and action prediction. We jointly model code, future video, and robot actions as three coupled generative streams within a unified mixture-of-transformers architecture.
Within this architecture a code expert generates parameterized skill routines and control logic while video and action experts generate future visual states and low-level motor commands.
Code serves two complementary roles: it structures multi-step prediction and control within the world model and represents skills as reusable programs for subsequent agentic execution.
We further introduce an automated curation pipeline that labels robot and human video trajectories with aligned programs and consolidates recurring routines into reusable skill libraries.
Evaluations on RoboTwin 2.0 and physical bimanual manipulation tasks show improved task performance over VLA and WAM baselines, alongside gains in language following, semantic reasoning and robustness,
demonstrating that agentic code enables connection between planning, prediction and execution within WAMs.

Overview of AW-0. AW-0 is an agentic world action model that unifies code-based planning with world action modeling by jointly denoising skill programs, future video, and control trajectories. An agentic pipeline discovers reusable skills and annotates robot and human demonstrations with programs for both pretraining and downstream fine-tuning. The resulting policy achieves strong performance on both parallel-gripper and dexterous-hand tasks.
1 Introduction
Learning-based robotic manipulation has progressed from small task-specific visuomotor policies over a decade ago
to broadly supervised foundation models that connect perception, language, and action ( Levine et al., 2016 ; Zitkovich et al., 2023 ; Kim et al., 2024 ; Niu et al., 2024 ; Black et al., 2024 ; Bjorck et al., 2025 ; Niu et al., 2025 ; Liu et al., 2025 ; Black et al., 2025 ; Liu et al., 2026 ) .
In parallel, self-supervised video prediction has long been valued as a learning signal to model the world: image inpainting extended to video prediction led to action-conditioned video predictors that can imagine the future before committing to an action ( Pathak et al., 2016 ; He et al., 2021 ; Tong et al., 2022 ; Finn et al., 2016 ; Assran et al., 2025 ; Ye et al., 2026 ) .
World Action Models (WAMs) couple visual prediction with visuomotor policies, grounding control in representations of how the physical world evolves ( Ye et al., 2026 ; Kim and others, 2026 ; Yuan and others, 2026 ) .
This predictive grounding is particularly valuable for complex manipulation, where successful execution depends on anticipating object motion, contact, and the consequences of low-level actions. Yet predicted video and action chunks do not by themselves specify how a long-horizon task should be decomposed: which reusable skills to invoke, how to parameterize them, or how to compose them across subtasks.
Predicting the world and/or actions in general can also be expensive, especially as it can be difficult to establish limits on how many degrees of freedom need to be “world modeled” (or teleoperated, in the supervised setting).
Agentic robot systems provide complementary structure to WAMs: a programmatic harness that selects reusable skills and tools, binds them to the current scene, tracks progress, and replans as observations change ( Liang et al., 2023 ; Fu et al., 2026 ; Zhang et al., 2026 ; Xiao et al., 2026 ; Lu et al., 2026 ) . This programmatic representation makes the structure of multi-step tasks explicit, specifying which skills and tools to invoke, with what arguments, and in what sequence.
Yet agentic robotics often lacks predictive grounding in real-world physical dynamics and does not leverage a learned model of how the world will change as the robot acts.
We advocate for an architecture that combines the foresight and action execution of WAMs with the cognitive efficiency, reusable skills, and potential for future self-improvement of agentic robotics.
We propose AW-0 , an agentic WAM framework that incorporates code-based planning and generation directly into world action modeling via a grounded code expert that harnesses broad programming priors to synthesize modular skills featuring explicit parameters and control logic. Code guides synchronized video and control modules within a mixture-of-transformers architecture, simultaneously denoising discrete code structures, predicted visual observations, and low-level motor commands.
We first show that such agents can be realized by adding a code expert to a WAM, leveraging multisensor action and code generation in a planning stage.
We develop a modular generation framework: planning via code generation significantly improves WAM performance, by appropriately conditioning the long-horizon generations required for complex robotic tasks. An automated curation pipeline extracts systematic routines into reusable program libraries, mapping code segments directly onto robotic and human video trajectories. This approach bridges high-level semantic reasoning with predictive physical dynamics, establishing a unified language for compositionality across distinct environments and tasks.
We further demonstrate agentic skill reuse via a hybrid deployment strategy that selects between raw action chunk execution and programmatic skill invocation. Empirical evaluations across RoboTwin 2.0 benchmarks and physical bimanual setups show substantial performance gains compared to standard VLA and WAM baselines, highlighting programmatic code as an effective structural backbone for predictive planning, skill discovery, and embodied robotic control.
Our primary contribution is the conceptualization and realization of agentic robotic skills within a world action model framework, showing that code generation improves action prediction in the world model, and that the code generated from the world model can be re-used in an agentic framework. Specific novel contribution elements include: a mixture-of-transformers framework integrating a code expert into world action models via simultaneous denoising of code, video, and control; an automated agentic pipeline designed for program annotation and skill discovery; a dataset of such structured skill programs; and a hybrid execution policy that dynamically toggles between programmatic skill invocation and direct deployment of action chunks from the WAM action expert.
2 Agentic World Action Model
We formulate AW-0 as a unified conditional generative model over code, video, and actions, which respectively describe structured skill plans, future scene dynamics, and continuous robot motion. 2.1 Mixture of Transformer Architecture
Figure 2: AW-0 Framework. AW-0 includes a Mixture-of-Transformers backbone with three experts generating code, video and action, respectively, which are denoised jointly, with video and action under continuous flow matching and the code under discrete masked diffusion.
As shown in Figure 2 , AW-0 adopts a Mixture-of-Transformers (MoT) ( Liang et al., 2025 ) architecture with three experts for skill planning, future visual prediction, and continuous control. Each expert keeps its own attention projections ( W Q , W K , W V , W O W_{Q},W_{K},W_{V},W_{O} ), layer normalizations, and FFNs, communicating through masked joint attention at every transformer layer. The attention mask is bidirectional within each expert and blockwise causal across experts, following the order of code, video and action. We provide additional model and training details in Appendix A .
Code Expert.
The code expert augments a pretrained language backbone with a frozen Qwen3-VL ( Bai et al., 2025 ) ViT and adopts LLaDA-style masked-token diffusion ( Nie et al., 2025 ) . Current multi-view observations are encoded into visual tokens and prepended to the instruction and program tokens to ground skill planning in the scene.
Video and Action Experts.
The video expert uses a video DiT initialized from Cosmos-Predict2.5 ( NVIDIA, 2025b ) to model VAE-encoded future frames conditioned on observed frames, while a separate action DiT generates continuous action chunks. Both experts receive language embeddings through cross-attention, with additional robot-state conditioning for the action expert.
2.2 Joint Denoising Generation
At each denoising step, the MoT jointly predicts code logits and continuous velocities as defined in Eq. 2 . The code stream supplies planning context to the video and action experts, while the action expert also reads video representations. These connections operate throughout generation, allowing all three modalities to evolve within the same iterative process.

2.3 Agentic Coding in WAM
Figure 3: Automatic Annotation Pipeline. Coding agents generate subtask-level programs using predefined primitive APIs and available skills, while a coordinator distills recurring patterns into a library of reusable skills across tasks. With the library frozen, we annotate the corpus by reusing cached code when contact and motion evidence match and generating new labels otherwise.
Automatic Annotation Pipeline.
We propose an automatic annotation pipeline (Figure 3 ) that annotates the training data with skill planning code in three stages. We first sample one episode per task and use Gemini 3.1 Pro ( Google DeepMind, 2026 ) to write subtask-level skill programs against predefined declaration-only APIs, while Claude Code running Claude Opus 4.8 ( Anthropic, 2026 ) acts as a coordinator that distills recurring, task-general skills.
We then freeze the skill library and re-annotate the sampled episodes with the finalized vocabulary, forming a cache of reusable subtask-to-program mappings. To annotate the remaining corpus, we reuse a cached program when the subtask’s contact and motion pattern matches an existing entry; otherwise, the coding agent generates a new annotation and adds it to the cache. See Appendix K for further pipeline details.
Code Usage in Model.
Annotated programs define the interface through which the code expert plans.
During training, the code stream concatenates a conditioning prompt and the active slice, a short block of primitive or skill calls. Only the slice is corrupted by the absorbing-mask process of Eq. 4 and supervised by the masked-token loss.
At each replanning point, the policy rebuilds the prompt and appends a canvas of G G mask tokens. The canvas is decoded jointly with the video and action states over the T T denoising steps, committing the G / T G/T most confident masked positions per step.
By default, the decoded slice is not executed. It serves as a subtask plan that conditions the action expert through joint denoising, while the predicted action chunk drives the robot.
Memory Cache.
Since a single observation is often insufficient to reveal task progress, the code expert receives a compact cache of the slices generated so far. The history slices are compressed into K K learnable memory slots and read back as prefix tokens before the prompt in the code stream. During training, the buffer holds the preceding annotated slices, replaced with probability p p by the model’s own predictions. At inference, it is reset per episode and grows with each decoded slice.
Hybrid Actions.
We additionally explore an inference mode in which the decoded code slice is executed in the manner of Code-as-Policies (CaP) against a library of perception and control primitives, and the executed actions are integrated with the direct actions of the action expert. At deployment, the two channels are arbitrated at every replanning point: the decoded slice takes over the current stage only if it passes a set of validity and progress checks; otherwise the action chunk from the same forward pass drives the robot until the next replan. See Appendix I for the full algorithm.
2.4 Training Recipe
We first pretrain AW-0 on approximately 2,000 hours of YAM robot data and approximately 1,000 hours of egocentric human manipulation data to learn a general unified generative prior. We apply the automatic annotation pipeline in Section 2.3 to extract two embodiment-specific skill libraries containing 50 skill entries in total (23 for YAM and 27 for egocentric human demonstrations) and annotate demonstrations with temporally aligned program slices. The annotated data support joint pretraining of code, video, and action generation, connecting structured skill plans with visual dynamics and continuous control across embodiments and scenarios. We further include the details of dataset statistics, preprocessing, and state-action representations in Appendix B .
For each downstream task, we reuse the same annotation pipeline under the frozen skill library to label task-specific demonstrations and jointly fine-tune AW-0 on the resulting code, video, and action targets using the objective in Eq. 6 .
3 Experiments
We evaluate AW-0 on RoboTwin 2.0 ( Chen et al., 2025 ) and 8 real-world tasks spanning parallel-gripper and dexterous-hand embodiments, assessing language following, semantic reasoning, and skill execution, as well as the robustness benefits of hybrid execution in variant scenarios.
Baselines.
We compare four baselines: (1) π 0.5 \pi_{0.5} ( Black et al., 2025 ) , a state-of-the-art VLA with strong semantic reasoning; (2) EgoScale ( Zheng et al., 2026 ) , a VLA pretrained on large-scale egocentric human data; (3) DreamZero ( Ye et al., 2026 ) , a WAM jointly generating future video and actions; and (4) WLA ( Yang et al., 2026 ) , an autoregressive model jointly predicting textual subtasks, subgoal images, and actions.
All baselines and the default AW-0 configuration use the same task-specific demonstrations for post-training and follow the same evaluation protocol. The simulation hybrid configuration uses separately collected CaP-generated demonstrations, as described below. Baseline implementation details are provided in Appendix C .

Main Results.
Table 1 and Figure 4 report the results on RoboTwin 2.0. The two inference modes exhibit complementary strengths.
Overall, AW-0 achieves the highest average success rate of 50.7% across both settings, outperforming all baselines including models designed for broad generalization.
The advantage comes mostly from the clean setting, where AW-0 reaches 80.8%, exceeding the strongest baseline WLA (64.8%) by 16.0 points. Under visual randomization, performance drops to 20.6%, consistent with the challenges of pixel-level O.O.D prediction discussed in prior work ( Yan et al., 2026 ) . It falls below the VLA baseline π 0.5 \pi_{0.5} (27.7%) but still outperforms the strongest WAM baseline DreamZero (17.6%) and remains far ahead of EgoScale (2.9%) and WLA (3.6%).
We further observe that hybrid execution improves robustness under distribution shift. In the random setting, it raises the success rate from 20.6% to 29.2%, outperforming all baselines including the strong VLA baseline π 0.5 \pi_{0.5} (27.7%). Relative to its clean-setting performance, the hybrid mode retains 46 % 46\% of its success rate under randomization, compared with 25% for the default mode. This robustness comes at a cost in the clean setting, where the hybrid mode reaches 63.1%, on par with the strongest baseline, but 17.7 points below the default mode. Quantitative and Qualitative Analysis.
As shown in Table 2 , AW-0 achieves the highest average rubric score across both embodiments, outperforming the strongest baseline by 25.1 points. Two observations emerge.
Language following and semantic reasoning:
AW-0 outperforms the baselines strongly on Arrange Fruits and Flip Scoreboard , which require instruction-specific object selection and counting, respectively. The VLA baselines, particularly π 0.5 \pi_{0.5} , also show relatively strong semantic understanding, while the WAM baselines are less reliable on these properties. These results suggest that code-based planning strengthens the language-following and semantic reasoning of world action models.
Robust skill execution:
On contact-rich and dexterous tasks, DreamZero outperforms π 0.5 \pi_{0.5} on Replace Lightbulb and Deal Poker , where predicting future states provides stable physical-dynamics features for action prediction. AW-0 further outperforms these baselines by combining guidance from generated skill programs with predictive representations of physical dynamics, aligning skill-level planning with continuous control. See Appendix G for further analysis.
Hybrid Execution in the Real World.
We further evaluate hybrid execution on Fold and Stack Towels with the YAM platform based on Algorithm I , comparing it against action-chunk execution under the same post-trained model and evaluation conditions. Under the same task rubric, hybrid execution achieves 90.6% , compared with 84.4% for action-chunk execution, while the direct execution steps of code further enhance the model’s reasoning capabilities in distinguishing stacking order and action stability. 3.3 Ablation Study
We organize our ablation study mainly around three research questions: 1) how to integrate a visually grounded code expert into a WAM framework, 2) which components of the planning representation contribute to task performance, and 3) how joint denoising affects task performance and inference efficiency. All the variants are post-trained and evaluated under the protocol of Section 3.2 .
Q1: How should the code expert be integrated into a WAM?
We first compare three blockwise causal attention orders during joint denoising: V → A V\to A (w/o code), V → C → A V\to C\to A , and C → V → A C\to V\to A (Figure 5 ). The two variants use the same pretraining data, training budget, and optimization settings as AW-0. Adding code through V → C → A V\to C\to A improves performance by grounding the predicted dynamics to action, but restricts its role to reasoning over video predictions without guiding or correcting them. With C → V → A C\to V\to A , both video and action generation attend to code, allowing semantic task plans to shape future prediction throughout denoising. The performance gain of this ordering supports introducing semantic reasoning directly into video generation, which improves language following and provides more reliable guidance for stable action generation.

Q2: What makes code an effective planning representation?
To assess the planning content produced by our annotation pipeline, we compare (1) full annotated programs , (2) code without comments , (3) code without skills , and (4) natural-language subgoals in Figure 7 .
Full programs outperform comment-free code on all 8 shared tasks, suggesting that explanatory language helps connect program structure with task intent. Removing skill calls also reduces performance on all 8 evaluated tasks, especially on skill-required tasks such as Deal Poker (58.3% vs. 42.0%). Since this variant still uses structured code, the drop supports the value of reusable skill abstractions beyond primitive-level API composition. Full programs also beat language-only subgoals on 7 of 8 shared tasks, showing that structured semantic guidance can provide more action-centric representation as condition. Together, these comparisons support combining explanatory language, reusable skills, and explicit program structure to provide effective planning guidance.

Q3: How does joint denoising affect performance and efficiency?
As shown in Table 4 , joint denoising outperforms AR on 7 of 8 tasks. For AR models trained with teacher forcing, the mismatch between ground-truth training prefixes and generated inference prefixes can cause errors to accumulate during inference and affect downstream video prediction. Joint denoising reduces token-by-token serial dependence by reconstructing code alongside video and actions, providing semantic guidance throughout generation.
We measure end-to-end inference latency on an NVIDIA RTX 5090, with settings detailed in Appendix A . Joint denoising takes 0.23 s versus 0.55 s for AR, a 2.39 × 2.39\times speedup (Figure 6 ). Compared with the AW-0 w/o code (0.19 s), it adds 0.04 s (21.1%) while improving performance on all 8 shared tasks (Figure 5 ).
4 Related Work
World Action Models (WAMs).
World models predict future observations and have recently emerged as a powerful paradigm for robot manipulation, serving as learned simulators and data generators for policy learning ( NVIDIA, 2025a ; NVIDIA, 2025b ; Gao et al., 2026 ; Yang et al., 2024 ; Jang and others, 2025 ) . Building on this progress, World Action Models (WAMs) unify future prediction and action generation, through joint video-action diffusion ( Ye et al., 2026 ; Zhu et al., 2025 ) , expert-based architectures ( Bi et al., 2025 ; Cai et al., 2026 ) , or direct adaptation of pretrained video models into policies ( Kim and others, 2026 ) . Recent WAMs further couple autoregressive sub-task prediction with future-state modeling and action synthesis ( Yang et al., 2026 ) or dynamically update subtask instructions to condition video and action generation ( Tang et al., 2026 ) .
However, existing WAMs lack structured semantic guidance and explicit skill invocation, limiting their ability to perform complex semantic planning and structure predicted dynamics into actionable behavioral abstractions.
Agentic Robotics. Early work composed perception and control APIs into executable closed-loop behaviors without policy training ( Ahn et al., 2022 ; Liang et al., 2023 ; Singh et al., 2023 ) . Later systems generate full Python programs over perception APIs ( Huang et al., 2023 ; Mu et al., 2024 ; Goldberg et al., 2025 ) , and executable code has proven a stronger action space for LLM agents than text ( Wang et al., 2024 ) . With the rise of coding agents, program synthesis has become explicitly agentic, with recent systems iteratively writing, executing, and repairing control programs ( Lu et al., 2026 ; Fu et al., 2026 ) . Frontier models now also act as controllers themselves, reasoning over instructions and feedback and driving robots directly through native tool calls and learned primitives ( Shi et al., 2025 ; Li et al., 2026 ; Gemini Robotics Team, 2025b ; Gemini Robotics Team, 2025a ) . In all of these systems, the agent controls the robot from outside the policy and is bounded by the primitives it can call. We instead bring code inside an end-to-end model as a high-level planning interface and further explore how the generated code can be executed to complement the model’s own actions at test time.
5 Conclusion
We present AW-0, an agentic world action model that integrates code-based skill planning with predictive dynamics and continuous control. Through joint denoising, the code expert provides structured semantic guidance for video and action generation. An automated annotation pipeline enables learning this planning interface from large-scale robot and human demonstrations. Experiments on RoboTwin 2.0 and real-world manipulation with YAM and dexterous hands demonstrate improvements in language following, semantic reasoning, and skill execution, with hybrid execution further enhancing robustness. These results establish a unified foundation for future work on skill reuse and iterative interaction between programmatic planning, world prediction, and execution, providing a potential agentic system foundation that continually interacts with and learns from environments.

Appendix A Model and Training Details
We implement the AW-0 architecture using three modality-specific experts coupled by masked joint attention. All experts have 28 transformer layers and project their queries, keys, and values into a common 2,048-dimensional attention space. The code expert receives current visual observations and language instructions, the video expert attends to the code stream, and the action expert attends to both. Tables 5 and 6 summarize the architecture and the pretraining configuration.
State and Action Representation.
Both YAM robot data and egocentric human data are mapped into a shared 64-dimensional state–action space. Each side contains a 9-dimensional end-effector pose (3D of x , y , z x,y,z position and a 6D rotation representation), 22 dexterous-hand joint angles, and one parallel gripper width, giving 2 × ( 9 + 22 + 1 ) = 64 2\times(9+22+1)=64 dimensions. States are all absolute; while action chunks use end-effector pose deltas relative to the first frame of the chunk, with absolute gripper targets for YAM and absolute hand-joint targets for human demonstrations/dexterous hand. Dimensions unused by an embodiment—the hand-joint blocks for YAM and the gripper dimensions for human demonstrations—are set to zero and left unnormalized. All remaining dimensions are normalized using per-dimension 1st and 99th percentiles.
Initialization and Trainable Components.
We initialize the video DiT from Cosmos-Predict2.5-2B ( NVIDIA, 2025b ) and the action DiT from scratch before joint pretraining. The code expert initializes its token embeddings, layer normalizations, FFNs, and vocabulary head from SDAR-1.7B ( Cheng et al., 2025 ) and freezes them, while training its MoT attention projections and modulation parameters. The Qwen3-VL ( Bai et al., 2025 ) vision tower is frozen, with a trainable merger mapping visual features to code embeddings. We replace the original VAE with a frozen Wan2.2 ( Wan et al., 2025 ) VAE with 48 latent channels and reinitialize the video DiT’s input and output projections. The video DiT uses 1 × 2 × 2 1\times 2\times 2 latent patches and multi-view 3D RoPE. Video and action experts use precomputed Cosmos-Reason1 language embeddings. Downstream adaptation transfers shape-compatible parameters from joint pretraining and reinitializes action and state projections when embodiment dimensions change.

Downstream Optimization.
Downstream runs use the same optimizer, warmup schedule, and mixed-precision settings as pretraining, with task-specific batch sizes and training budgets. For both YAM and Tianji–Sharpa, we fine-tune AW-0 for 20 epochs using 100 demonstrations per task. The YAM configurations use a per-GPU batch size of four, one gradient accumulation step, a learning rate of 10 − 4 10^{-4} , and weight decay of 10 − 2 10^{-2} . The RoboTwin configuration uses two 8-GPU nodes with a per-GPU batch size of 6 6 and one accumulation step, giving an effective batch size of 96 96 , a learning rate of 2 × 10 − 4 2\times 10^{-4} , weight decay of 10 − 2 10^{-2} , and a budget of 100,000 optimizer steps. These settings are distinct from the larger pretraining batch in Table 6 .
Appendix B Analysis on Pretraining Dataset
B.1 Pretraining Dataset Statistics
We pretrain AW-0 on the union of two real-world manipulation datasets: YAM and Egocentric Human data. The YAM corpus contains 73,101 episodes across 279 tasks, totaling 1,919.3 hours of bimanual robot teleoperation. Demonstrations are recorded at 30 Hz with left-wrist, right-wrist, and top-view RGB cameras. The egocentric human corpus contains 175,541 episodes across 327 tasks, totaling 993.9 hours, with a single head-mounted RGB camera and tracked hand motion retargeted to 22-DoF dexterous-hand joint targets per hand. Together, the two sources comprise 248,642 episodes and 2,913.2 hours. The human camera view is replicated across the three input slots; each training window is paired with its episode-level instruction and aligned program slice. Table 7 reports detailed statistics.

B.2 Skill Library Definitions
A skill is a reusable motion that the model can invoke by name. Each skill is a Python function written over the primitive API described in Appendix K.1 , taking the objects it acts on as arguments, so that a subtask recurring across the corpus becomes a single call rather than being spelled out primitive by primitive. Following the annotation pipeline of Section 2.3 , we generate a skill library for each dataset: 23 skills for YAM and 27 skills for the egocentric human data. Appendix C Baseline Implementation Details
In Sections 3.1 and 3.2 , we compare AW-0 with four baselines: π 0.5 \pi_{0.5} , DreamZero, EgoScale, and WLA. Here, we describe how each is reproduced and adapted. On RoboTwin 2.0, we train a single multi-task policy per baseline on 2,500 demo_clean demonstrations (50 tasks × \times 50 demonstrations). For each of the 8 real-world tasks, we train a separate policy per baseline using task-specific demonstrations sampled at 30 Hz. Every baseline receives a language instruction, the robot state, and three RGB views (one head and two wrist cameras). All baselines follow the same evaluation protocol as AW-0. All real-world rollouts are scored using the task-specific rubrics in Appendix E .
𝝅 0.5 \bm{\pi_{0.5}} ( Black et al., 2025 )
is a vision-language-action model that combines a pretrained vision-language backbone with a flow-matching action expert. We follow the official OpenPI implementation 2 2
2
https://github.com/Physical-Intelligence/openpi and initialize all policies from the released π 0.5 \pi_{0.5} pretrained checkpoint. For each real-world task, we fine-tune a separate policy for 50 epochs on the task-specific demonstrations. We use 14-dimensional joint-space actions on RoboTwin and YAM, and 62-dimensional actions on Tianji–Sharpa consisting of a 9-dimensional end-effector pose and 22 hand joints per side. Arm actions are relative to the current state, while gripper and hand actions are absolute targets. We reinitialize the action input and output projections to accommodate these dimensions and fine-tune all model parameters. Following the official implementation, we use an action horizon of 50 for RoboTwin and 32 for the real robots, together with quantile normalization and standard image augmentation. All models are trained with AdamW on eight H100 GPUs using FSDP and a global batch size of 256. We use a peak learning rate of 5 × 10 − 5 5\times 10^{-5} with cosine decay to 5 × 10 − 6 5\times 10^{-6} and 2,000 warmup steps.
DreamZero ( Ye et al., 2026 )
is a world-action model that jointly generates future video and actions using a pretrained video diffusion backbone. We follow the official implementation 3 3
3
https://github.com/dreamzero0/dreamzero and initialize from the DreamZero-AgiBot checkpoint. We reproduce DreamZero on RoboTwin and all 8 real-world tasks, training a separate policy for 10 epochs on each real-world task. We fully fine-tune the diffusion transformer and state/action modules, while keeping the text encoder, image encoder, and video VAE frozen. Following the original design, the three camera views are tiled into one frame, and each training sample contains up to four action chunks of 24 steps. Actions are predicted relative to the state at the beginning of each chunk, with absolute hand-joint targets on Tianji–Sharpa. The state and action projections are adapted to the target embodiment, and the video and action losses are weighted equally. All policies are trained with AdamW on 32 H100 GPUs using a global batch size of 32. We use the same training hyperparameters across all tasks, with a peak learning rate of 2 × 10 − 5 2\times 10^{-5} and 5% linear warmup followed by cosine decay.

Appendix D Real-world Experimental Setup
We conduct data collection and policy evaluation on two robot embodiments: the YAM station with parallel grippers and the Tianji–Sharpa station with dexterous hands. This section describes the robot hardware, visual observations, and teleoperation interfaces used in our experiments. Figure 20 gives an overview of the two stations.
(a) YAM Station
(b) Tianji–Sharpa Station

(b) The Tianji–Sharpa station: a Tianji torso with two Sharpa Wave dexterous hands, observed by an SHW5G camera on the head and one on each wrist.
Robot Hardware and Control.
The YAM station is a fixed-base bimanual system with two 6-DoF arms, each equipped with a parallel gripper. The Tianji–Sharpa station consists of a Tianji humanoid torso with two arms and two 22-DoF Sharpa dexterous hands. For AW-0, both embodiments use the 64-dimensional state–action representation described in Appendix A . The policy predicts relative end-effector poses together with absolute gripper targets on YAM or absolute finger-joint targets on Tianji–Sharpa.
Perception System.
Both stations provide three RGB views: a head or overhead camera observes the tabletop workspace, and a camera at each wrist provides a local view of the gripper or hand and the manipulated objects. Each policy receives these images together with the task instruction and robot state. For AW-0, images are resized to 224 × 320 224\times 320 pixels, and the state contains the end-effector poses and the gripper positions or hand-joint angles. The same camera streams are provided to all baselines, with method-specific preprocessing described in Appendix C .
Teleoperation and Data Collection.
We collect YAM demonstrations using the standard YAM station configuration, with two master arms and two puppet arms. The operator moves the master arms, whose measured joint angles are sent as joint-position targets to the corresponding puppet arms. The triggers on the teaching handles control the parallel gripper openings, yielding six arm-joint targets and one gripper target per side. For Tianji–Sharpa, we use Manus gloves with PICO motion trackers attached to the gloves, together with an Apple Vision Pro worn around the operator’s neck. The tracked wrist positions and orientations define poses in SE ⁡ ( 3 ) \mathrm{SE}(3) , which are mapped to end-effector targets for the two Tianji arms. In parallel, finger-motion measurements from the Manus gloves are retargeted to 22-dimensional joint-position targets for each Sharpa hand. At each teleoperation step, the arm-pose and hand-joint targets are passed to the corresponding robot controllers to coordinate arm and finger motion. During collection, we record the three RGB camera streams, measured robot states, and commanded action targets. We use their timestamps to pair visual observations with robot states and action commands, and associate each demonstration with a task instruction for post-training.

Appendix H Failure Case Analysis
Figure 36: Failure Case Analysis. Each row shows one representative failure case. Frames are ordered from left to right by execution progress. The red box on the last frame marks the region enlarged in the rightmost panel, where the failure occurs.
Figure 36 shows representative failure cases across various scenarios. The red boxes highlight the local interactions where execution fails. These examples illustrate some remaining challenges despite the overall performance gains of AW-0.
1) Container Grasp.
In Arrange Fruits in the first row, the target fruit lies close to the basket rim. As the gripper approaches, its left jaw moves outside the basket, causing the closing motion to grasp the basket wall rather than only the fruit. This case highlights the need to account for surrounding geometry when selecting a grasp. Explicitly estimating the rim geometry and checking clearance along both the approach and closing paths could help reject obstructed grasps and select a more accurate approach direction.
2) Object Dragging.
In Pack Backpack in the second row, when the robot pulls the zipper, the backpack moves and tips over rather than remaining stable. The visible failure suggests insufficient stabilization of the deformable object during manipulation. A potential improvement is to coordinate the supporting and pulling motions through more frequent visual feedback: the supporting hand could adjust its grasp as the bag deforms, while the pulling hand could slow down or pause when the bag starts to shift or tip.
3) Imprecise Alignment.
In Replace Lightbulb in the third row, the robot grasps the bulb and brings it above the socket, but the bulb base remains misaligned with the socket opening and is not screwed in. Completing this step requires both positional and angular alignment before the threads can engage. The case illustrates a gap between moving an object to the correct region and achieving the precise relative pose required for insertion and rotation.
4) Tool Collision.
In Arrange Fruits with Tongs in the fourth row, the tongs approach the pear with their tips closed and poke it rather than opening around it to establish a grasp. Successful tool use requires coordinating the tool’s opening with its approach trajectory, in addition to holding and positioning the tool itself. Explicitly tracking the tong tips and opening width could help condition actions on the tool’s state. A feedback check that the tips are open and positioned on opposite sides of the fruit before closing could further reduce unsuccessful contact.
5) Slipping Off.
In Deal Poker in the fifth row, the left hand fails to secure the card stack during handover from the right hand, causing the cards to slip. A successful handover requires the receiving hand to establish a stable grasp before the giving hand releases the stack. This failure illustrates the difficulty of coordinating grasping and release across the two hands while maintaining support for the cards throughout the transfer.
6) Contact Loss.
In Flip Scoreboard in the sixth row, the fingertip reaches the edge of a score card but slides off before turning it over, leaving the displayed score unchanged. Unlike a brief touch, a successful flip requires sustained contact along the card’s rotation about the binding. This case illustrates the difficulty of sliding the fingertip along the first card to lift its edge while maintaining continuous contact.
Appendix I Hybrid Actions Algorithm
Algorithms 1 and 2 outline the workflow of the hybrid mode. From an observation o o and instruction ℓ \ell , one forward pass of the policy π \pi returns a direct action chunk a 1 : H a_{1:H} over the replan horizon H H and a code slice c c . Every slice executes in a shared namespace 𝒢 \mathcal{G} containing the environment’s skill API, reusable helper definitions, and its setup block (episode-start perception), which persists throughout the episode. At each replanning point, Arbitrate decides which of the two channels drives the robot. The returned flag indicates whether code execution was attempted, not whether it succeeded. If execution is attempted, the action chunk from the same policy invocation is discarded, even if an exception occurs; the next iteration observes the current state and replans. Otherwise, the chunk is played for H H steps as in the default mode.

J.2 Hybrid Actions Evaluation Details
Perception and Control Primitives. During hybrid evaluation, generated code executes through perception and control primitives implemented using Molmo for visual grounding ( Deitke et al., 2024 ) , SAM 3 for segmentation ( Carion et al., 2025 ) , Contact-GraspNet for grasp generation ( Sundermeyer et al., 2021 ) , and RoboTwin’s native motion-planning and gripper-control interfaces ( Chen et al., 2025 ) . Neither the generated programs nor the underlying primitives access privileged simulator information during evaluation. For demonstration collection, we preserve the same API interface but use privileged object states and annotated grasps to improve collection efficiency.
Scope of Comparison. The default and hybrid configurations differ in both their training demonstration collection pipelines and execution modes to support their training requirements. Unlike the default configuration, which uses demonstrations collected with RoboTwin’s native motion planner, the hybrid configuration uses CaP-based data collection because it naturally pairs each demonstration with an aligned program executable in the RoboTwin simulator, supporting the code execution component of hybrid actions. Therefore, our resulting comparison evaluates the two configuration as a whole and does not isolate the effect of hybrid execution alone.
Code and Action Usage. Table 12 reports the fraction of simulation steps driven by each of the two control channels during the hybrid evaluation in Table 1 : execution of code produced by the code expert and direct action chunks generated by the action expert. On successful episodes, code drives 14.5% of steps in the clean setting and 35.0% in the random setting. The gap follows from Table 1 . In the clean setting, the action expert alone is already strong (80.8%), so there is little for code to add. Admitting code in fact lowers success to 63.1%, which we attribute to the code channel inheriting the failure modes of the low-level perception and control primitives it calls, and the arbiter admits a code slice on validity alone, without predicting whether it will outperform the action chunk it displaces. In the random setting, where direct action degrades to 20.6%, the code channel carries a third of the physical time on the episodes that succeed and lifts success to 29.2%. Executing the code expert’s generation thus complements the action expert especially where learned actions are less reliable, here under visually out-of-distribution scenes. Pooled over all episodes, code execution accounts for only 8.5% of steps in the clean setting and 5.6% in the random setting. The pooled share is dominated by failed episodes, which run to the step cap and accumulate roughly five times as many steps as successful ones (52.7k vs. 11.5k in clean, 55.5k vs. 8.4k in random), almost all under direct action.
Qualitative Examples of Code–Action Interleaving. Figure 37 shows two qualitative examples of how code execution and direct action generation interleave within an episode. The top progress bar shows an episode of blocks_ranking_rgb , where the three blocks must be arranged in a row in red, green, blue order. We observe that the three pick-and-place cycles are almost entirely carried out by code execution, with direct action generation taking over around a stage transition. For tasks of this kind that involve regularly shaped objects and well-structured motions, the integration is able to utilize the stable and smooth behavior yields by the CaP actions. The bottom progress bar shows an episode of pick_dual_bottles , where the two bottles must be picked up and held together. Here, code execution correctly localized the bottle and moves the gripper to it but fails to secure the grasp due to its less regular shape. Direct action generated from the model then takes over and completes the grasp, after which code execution resumes to finish the episode.

Appendix K Agentic Annotation Details
K.1 Low-level Primitives
Figure 38 shows the two API surfaces for the parallel-gripper (left) and the dexterous-hand (right) embodiments. They share ten semantic contact verbs but differ in their low-level primitives: end-effector poses for the gripper and relative motion for the dexterous hand. Each API call declares the contact events it produces, which is what allows a program to be grounded against a demonstration.
Figure 38: Declaration-only APIs for parallel grippers and dexterous hands.
K.2 Annotation Agent Prompts and Coordinator Protocol
The framework has two agents: a VLM annotator that writes program lines for one subtask slice per call, and an agentic coordinator that audits annotator output between rounds and grows the skill library (Stage 1). After the library is frozen, the same annotator runs over the remaining corpus and over downstream demonstrations, reusing cached subtask code where the embodiment’s evidence verifies it. The full API docstrings and skill documentation are appended to the system prompt and omitted here.
Shared annotator system instructions
Role and output
Read the frames of one subtask and express the observed actions in Python using only the robot API and documented skills. Output only new code for this subtask, continuing the preceding program.
Grounding and coverage
The subtask annotation states what happens; the frames ground which objects and how they move. Cover the whole frame span and invent nothing that neither source supports.
Abstraction level
Prefer the single highest-level call whose contact effects match; never wrap a semantic verb in the primitives it already contains. Use bare open/close primitives only when no verb fits.
Repetition and literals
Write repeated in-place twisting as one literal loop with the count read from the frames. Hand sides and loop counts must be literals. End on a complete statement.
Static validation
Code is checked without execution: syntax in program context, existence of called functions, argument binding, and vocabulary membership of literals. On failure, the annotator sees its output along with the identified problems and rewrites the slice.
System prompt for egocentric human demonstrations
Setting
Two hands, ‘left’ and ‘right’ , seen from a head-mounted camera. No contact-event list is given; infer every contact from the frames and the annotation, judging object motion relative to the scene.
Contact semantics
pick / grasp close a hand (pick lifts, grasp holds in place); place / release / insert / attach open it; regrasp opens then closes; press closes then opens; handover closes the receiver before opening the giver.
Motion and naming
Motion is purely semantic: move_arm along a documented direction, goto_relative at a documented relation to a named object, rotate about a documented axis. No coordinates; objects are named in plain language.
Conventions
Calls return None . Distances only when visibly measurable; angles as semantic constants.
System prompt for YAM robot demonstrations
Setting
Two arms seen from a top-down camera. The sensor-derived gripper-event list is authoritative: emitted code must reproduce every open/close transition on the named arm, in order, with nothing added, dropped, or reordered.
Event gaps
If the annotation implies a contact the event list lacks, write the approach and transport in full but do not emit the missing open/close call.
Contact semantics
grasp / pick close; place / release open; regrasp opens then closes; insert closes then opens; handover closes, closes, then opens. A repeated same-arm cycle in the list is one literal loop.
Perception and motion
Every pose used by a motion call comes from a perception result earlier in the program; nothing is hard-coded. Absolute single-arm, synchronized two-arm, and small relative motion each have their own primitive.
Per-slice user message
Overall task
[task instruction]
Current subtask
[human subtask annotation]
Frames
[ordered frames with timestamps] . On YAM, the frame before each gripper event is captioned with the event index, kind, arm, and time.
Program so far
[code written for the preceding subtasks]
Egocentric directive
Decide from the frames and annotation where each hand closes on and opens off an object, and produce exactly those contacts with the visible motion around them. A comment-only slice is correct only when the hands neither move nor touch anything.
YAM directive
Observed gripper events: [ordered list, repeated cycles collapsed to a count] . Reproduce this sequence exactly, with the visible motion around it; a brief blip with nothing in hand gets the minimal call.
Output
Continue the program with this subtask’s code only.
Only the directive for the current dataset is included.
Annotation under the frozen library
Same prompt, frozen vocabulary
The system prompt above is used unchanged, with the skill block fixed to the frozen library. Inherited skills are called as plain functions with robot as the first argument.
No new vocabulary
The annotator may not invent helper names; a maneuver no verb or skill expresses is written from primitives. Extending the library is the coordinator’s decision.
Verified reuse
A per-task cache of subtask code is consulted before each call. A variant is reused only when the embodiment’s evidence verifies it: on YAM, the contact events its code implies match the observed events (mirrored forms accepted, motion arguments re-derived); on egocentric data, its hand-motion profile is within a fixed distance of the new slice, and loop templates are never reused. A miss triggers the ordinary call, whose output is written back.
Coordinator protocol (Stage 1, skill discovery)
Role
A coding agent under a fixed written protocol that dispatches rounds, audits their output, and owns the skill library. It never writes program code and never edits the annotator, prompts, API, or verification code.
Round lifecycle
Dispatched, gated (all episodes annotated and scored), audited, done (admissions applied and logged). The library is frozen from dispatch to done, and the next round starts only then.
Audit
Read the round summary, then per-task results, then the stored trace of each questionable slice (frames seen, code written, verification outcome). Classify each as detector limit, annotator misread, abstraction-level break, vocabulary gap, or segmentation artifact. Only vocabulary gaps feed skill proposals.
Skill admission
A candidate is a straight-line composed function over the API, distilled from observed call sequences. It is admitted if generic (episode-specific values lifted to parameters), recurrent across at least two tasks, at the right level (a maneuver, not a task recipe), and not a duplicate. Its contact contract is derived by expansion; on YAM the evidence slices must also reconcile against observed events. Admitted skills enter the annotator prompt from the next round.
Appendix L Limitations and Future Work
Program Grounding and Skill Coverage.
The code stream learns from automatically annotated demonstrations and a curated skill library, making its planning quality dependent on annotation accuracy and skill coverage. Generated programs can select an appropriate skill yet contain incorrect arguments, as illustrated in Appendix F.1 ; syntactic validity therefore does not ensure correct execution. Future work could use execution feedback to improve program grounding and discover or refine reusable skills beyond the initial library.
Predictive Robustness and Hybrid Execution.
Structured planning improves WAM performance but does not eliminate sensitivity to visual distribution shifts. Hybrid execution improves robustness under RoboTwin randomization, yet reduces clean-setting performance (Appendix J.2 ). This trade-off reflects both the reliability of the underlying primitives and the limitation of selecting code based on validity without estimating its advantage over the action chunk. Learning to arbitrate using execution reliability and expected task progress could better exploit the complementary strengths of the two modes.
Toward Continual Agentic Learning.
Our real-world hybrid evaluation is limited to YAM platform due to the lack of code-as-policy systems for dexterous hand, and the current system does not learn online from its own interactions. The unified design nevertheless offers a basis for coupling program generation and world prediction with execution feedback and model updates. Future work could explore iterative plan revision, skill-library expansion, and autonomous learning through sustained environmental interaction, with broader evaluation across tasks and embodiments.
