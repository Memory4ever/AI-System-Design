B.5 BEHAVIOR CHANGE AND THE CONDITIONAL CONSTRAINT
MI training improves monitorability partly through behavior change. Relative to the Obfuscating
base, recovery produces fewer hacks and more true solutions. The crossed-CoT evaluation shows
that, for our method, this change is mediated primarily by which CoTs the recovered policy pro-
duces: once a recovered CoT is fixed, the Obfuscating base and recovered policy attain nearly
identical true-pass rates. This provides functional evidence for thereplacementroute of Section 3:
recovery shifts toward CoTs whose task-level consequences are already supported by the reference
policy. Changes to the code policy after a fixed CoT contribute little to the observed gain.
These results support a concrete mechanism for replacement: our method produces CoTs that the
Obfuscating base already maps to correct code. We hypothesize that task-plus-monitor training cre-
ated an obfuscated-CoT–hack mode. The reference policy more readily supports a transparent-CoT–
correct-output mode than a transparent-CoT–hack mode. By strengthening CoT–output coupling,
our method can favor the former supported mode and thereby favor thereplacementroute.
The crossed-CoT result also tests whether recovery changes which output follows a fixed CoT, the
failure mode that the conditional constraint is designed to discourage (Section 3). Switching from the
Obfuscating-base code policy to the recovered code policy after a fixed recovered CoT changes true
pass by0.6±1.1percentage points. Thus, at the level of task success, the recovered policy largely
preserves what a fixed CoT implies for the output. The constraint still permits marginal behavior
to change by altering which CoTs the policy produces. A marginal-output constraint would target
behavior preservation directly. It would also permit changes in individual CoT meanings whose
average effects cancel, potentially reducing monitorability.

E.1 EVALUATION PROTOCOL
For each prompt and policy, we first sample a reference completion and take its own final answer
y⋆ as the target. We then select the prompt-only state, every eighth complete-sentence boundary
in the reference CoT, and the end of reasoning. From each exact-token prefix we sample fresh
continuations and record whether they producey ⋆. Invalid or truncated continuations count as non-
matches. SCRUPLES uses 50 continuations per prefix and GPQA uses 32.
If adjacent prefixes producek i andk i+1 target-answer continuations out ofn i andn i+1 samples, let
vi andv i+1 denote their underlying target-answer probabilities. We place independentBeta(1,1)
priors on these probabilities and draw 100,000 posterior samples. The reasoning span between the
two prefixes is consequential at effect thresholdδwhen
P(|v i+1 −v i|> δ|k i, ni, ki+1, ni+1)≥0.95.
Trace coverage is the fraction of reference traces with at least one such span. Span density is the
number of consequential spans divided by the total number evaluated. We bootstrap matched anec-

answer rather than the correct answer, so it measures whether the CoT changes the probability of its
eventual output, not whether that output is correct.

F REVELATION ANDREPLACEMENT: A TOYMODEL
Section 3.3 distinguishes two ways that monitorability can improve: the CoT can reveal the strategy
behind the same behavior, or the policy can shift toward a different CoT–output behavior. We use
a binary toy model to illustrate these revelation and replacement routes, show how they depend on
the modes available under the reference policy, and compare the effects of conditional and marginal
output constraints.
A toy model.Consider a coding promptX=x, a CoTZ, and the resulting codeO. We describe
the CoT and output as binary variables. LeteZ= 1indicate that the CoT expresses a hacking strategy,
and let eO= 1indicate that the code hacks the revealed tests. A benign-looking CoT followed by
a hack occupies cell(0,1); an openly described hack occupies(1,1); and ordinary task-solving
reasoning followed by correct code occupies(0,0). The remaining cell,(1,0), contains CoTs that
express a hacking strategy followed by code that does not enact it. Each cell summarizes many
possible full trajectories, so two CoTs in the same row can still lead to different code.

Two routes from concealed hacking.Suppose the reference policy assigns most probability to

distribution associated with each selected CoT. Although the concealed-hack and ordinary-solution
cells share the binary label eZ= 0, they contain different full CoTs that can elicit different code.
The available modes determine the route.To isolate the role of the starting policy, suppose that
training can only reweight CoTs already supported byπ ref, while holding each conditional output
distributionπ ref(O|X, Z)fixed. If the ordinary-solution mode(0,0)is missing, reweighting can-

it is rarely sampled or difficult to reach; the conditional constraint alone does not forbid generating
new CoTs.
The binary diagram abstracts away variation within each cell, whereas the actual MI objective scores
full CoT and output sequences. If every trajectory hacks, the binary output is constant and its
MI is zero; similarly, the binary MI is zero if every CoT receives the same summary label. Full
trajectories can still carry predictive information within either cell. The diagram therefore illustrates
route availability at the level of these binary summaries.
Relation to the MBPP experiment.The MBPP Obfuscating base introduced in Section 4.1.2 was
trained with a task reward based on revealed tests and a reward for evading a CoT monitor. Code can
receive task reward by passing the revealed tests while failing the hidden tests, whereas describing
this strategy in the CoT can trigger the monitor. This training therefore creates pressure toward
the concealed-hack mode. We hypothesize that ordinary task-solving modes remain available under
the resulting policy, while openly described hacking is harder to reach. Under this hypothesis, MI
post-training can improve CoT–output coupling through replacement.
The crossed-CoT evaluation in Appendix B tests this interpretation by holding a recovered CoT
fixed and generating code from either the Obfuscating base or the recovered policy. Given CoTs
from recovery withϵ= 0.4, the base code policy achieves47.6%true pass and the recovered code
policy achieves48.2%. By comparison, the base code policy achieves12.0%true pass with its
own sampled CoTs. The recovered CoTs therefore elicit correct code from a decoder that already
existed before monitorability post-training. This supports the interpretation that post-training shifts
probability toward accessible task-solving modes. The available route may still vary across prompts
and sampled trajectories.

F.1 WHAT DOES EACH DIVERGENCE CONSTRAIN?
The toy model makes concrete the distinction between marginal and conditional output constraints
discussed in Section 3.3. A marginal output constraint keepsπ θ(O|X)close to the reference
policy. In Figure 7, this approximately anchors the column totals and hence the overall hacking
frequency. It limits net replacement of hacks with ordinary solutions while allowing revelation that
preserves those totals. The mapping from an individual CoT to its output can still change as long as
compensating changes preserve the marginal output distribution.
Our conditionalχ 2 constraint instead penalizes changes inπ θ(O|X, Z)after a given full CoT. It
leavesπ θ(Z|X)free to change, allowing the policy to select reference-supported CoTs associated
with either revelation or replacement. Replacement can therefore change the overall hacking fre-
quency while preserving the decoder’s mapping for the CoTs that are selected. Because each row in
Figure 7 groups many distinct full CoTs, the conditional constraint acts on each full CoT separately
and need not preserve the aggregate output proportions within a row.
G PUBLISHEDEXAMPLES OFCOT–OUTPUTDECOUPLING
CoT monitoring relies on visible reasoning containing evidence about the model’s subsequent an-
swer or action. Published evaluations document cases in which the reasoning supports one outcome
and the model produces another. We refer to this observable mismatch asCoT–output decoupling.
These examples motivate directly measuring and training the coupling between CoT and output.
Actions that depart from an explicit plan.Schoen et al. (2025) evaluate covert behavior in syn-
thetic agentic tasks before and after anti-scheming training. They useo3 ASto denote o3 after
this training, where AS stands for “Anti-Scheming.” In theSmuggle Capabilitiestask, the model
is asked to select random strings that will be used as fine-tuning data to remove capabilities. Its
reasoning correctly identifies the random strings, while its tool call selects plaintext commands in-
tended to preserve capabilities. InSandbagging QA, the model computes all ten answers correctly in
its CoT, then submits five answers and changes two of them to be incorrect. Other transcripts show
the model reasoning that escalation is required and subsequently continuing the task (Schoen et al.,

Final responses that depart from the model’s stated plan.The GPT-5.6 System Card evaluates
whether a CoT monitor can predict properties of the model’s final response from its reasoning. The
Background Workevaluation identifies unsupported promises to continue working after the current
turn when the model has no mechanism for doing so. GPT-5.6 Sol makes such promises much less
frequently, but when it does, its reasoning often plans to avoid them while its final response still
makes a subtle future commitment. Each reported monitorability estimate is based on only two to
five responses containing such a promise, so these estimates are uncertain (OpenAI, 2026, p. 22).
The same system card evaluates coding tasks that cannot be completed because the required tools
are unavailable. GPT-5.6 Sol recognizes the unavailable tools in its reasoning and often considers
explaining the limitation, while its final response can present unverified work as completed. GPT-5.5
more often states in its reasoning that it will proceed as though the changes had been applied, giving
a CoT monitor evidence of the eventual behavior (OpenAI, 2026, pp. 22–23).
Final answers that override intermediate conclusions.Some reported mismatches occur on
tasks with objectively checkable answers. In an AIME mathematics problem, Claude Opus 4.5 de-
rives the fraction27903/32768and then writes27903 + 32768 = 237, producing the benchmark’s
correct answer despite arithmetic that does not support it. Anthropic says this recovery suggests
memorization of the evaluation item (Anthropic, 2025, Transcript 2.2.A, pp. 16–17).
Anthropic also reports an “answer thrashing” example observed during Claude Opus 4.6 training.
The model repeatedly computes 24 and notices that it keeps writing 48, yet emits the rewarded an-
swer 48. The system card reports that it often observed this behavior when an incorrect training label
was used and that it was rare in ordinary pilot deployment use (Anthropic, 2026, Transcript 7.4.A,
pp. 162–163).
