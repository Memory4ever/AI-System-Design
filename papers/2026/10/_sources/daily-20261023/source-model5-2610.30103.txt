Abstract
Many NP-complete (NPC) problems have a polynomial-time (P) twin that differs
in a single structural detail, such as 3- versus 2-colouring a graph. A
model that reasons rather than recalls should notice which side of this
boundary a problem falls on, yet existing benchmarks either fix the wording
of each task or ignore its complexity class, so they cannot separate the two.
We introduce P2NPCBench , a benchmark of 12 problem families in which every
NPC problem is paired with a P twin in the same problem setting. To remove
the textbook cues that enable recall, we build it with AgentGAN , an
adversarial multi-agent framework in which a generator rewrites each
statement until a panel of frozen code models fails, while an executable
validity gate keeps every rewrite answer- and class-preserving. The result
is 2,114 hardened statements with human-verified reference solvers.
Evaluating 12 proprietary and open-source models, we find that every model
scores lower on NPC statements than on their P twins (35.4% vs. 63.8%
pass@1), and that 95.1% of model–family pairs fail more often on the NPC side. A tenfold time limit raises NPC accuracy only from 28.5% to 31.9%.
Hardening lowers accuracy on both classes, more on P statements
(29.6 points) than on NPC statements (19.5 points). Finally, we build a failure taxonomy, where runtime errors are the largest
NPC failure type (44.1%), and nearly half of them (46.5%) come from
malformed or truncated code. The dataset and code are
available at Github .
1 Introduction
Complexity theory separates problems solvable in polynomial time (P) from
NP-complete (NPC) problems, the hardest problems in NP (nondeterministic
polynomial time), for which no polynomial-time algorithm is known
( Karp, 1972 ; Hartmanis, 1982 ) . The boundary between the
two is often a single structural detail: 2-colouring a graph takes linear
time while 3-colouring is NP-complete. Such problems underlie
practical tasks in routing, scheduling, and network design
( Imajuku et al., 2026 ) , where misreading the class is costly: a solver either
runs an exhaustive search on an easy instance or, worse, applies a fast
algorithm that silently returns wrong answers on a hard one.
Large language
models (LLMs) now write competitive code, but they are mostly evaluated on
textbook-style or contest problems whose solutions may already appear in
their training data ( Xia et al., 2025 ; Mirzadeh et al., 2025a ) . A model
that reasons rather than recalls should choose its algorithm from the
structure of the problem, not from its name or wording. This is hard for
three reasons: memory favours textbook phrasings over real-life ones
( Duchnowski et al., 2025a ) ; context can mislead, since one irrelevant
clause or misleading comment can flip the answer
( Mirzadeh et al., 2025a ; Lam et al., 2026 ; Al Nazi et al., 2026 ) ; and computation stops scaling with
difficulty ( Yang et al., 2025 ) . Testing this ability therefore
requires P and NPC problems that differ in class but not in surface form.
Existing benchmarks cannot measure this failure. Combinatorial benchmarks such
as GraphArena ( Tang et al., 2025 ) and NPPC
( Yang et al., 2025 ) , as well as training frameworks built on
NP-hard tasks ( Li et al., 2025 ) , treat complexity merely as a difficulty level.
Closest to our setting, NPHardEval ( Fan et al., 2024 ) spans P,
NP-complete, and NP-hard classes, but keeps a single clean wording for each
task, while EHOP ( Duchnowski et al., 2025a ) rewrites problems as real-life
stories, but only for three NP-hard problems. Neither varies wording and class
together, so neither can show whether models break when a problem crosses
from P to NP-complete. Code robustness studies perturb code but not complexity
( Wang et al., 2023b ; Lam et al., 2026 ) , math stress tests stay at
grade-school level ( Mirzadeh et al., 2025a ) , and budget studies vary tokens but
not problem class ( Sun et al., 2025 ; Zhang et al., 2026 ) . To the best of our knowledge, no existing benchmark varies the complexity
class while holding the surface form fixed. A more detailed discussion of related work is given in Appendix A .
To address this gap, we introduce P2NPCBench , a benchmark of 12 problem families
in which every NP-complete problem is paired with a polynomial-time twin posed
over the same surface, so that a single structural edit moves it across the class boundary. To remove the textbook cues
that let models recall rather than reason, we build it with
AgentGAN , a Generative Adversarial Network (GAN)-style framework of frozen LLM agents in which a
generator rewrites each statement until a panel of code models fails, while
an executable validity gate guarantees that every rewrite keeps its answer and
its class. Across 12 models, every model scores lower on NP-complete statements than on
their polynomial twins (35.4% vs. 63.8% pass@1), and a tenfold time limit
barely helps (28.5% → \to 31.9%), so failures stem mainly from incorrect or
non-executable solutions rather than from time constraints. Our contributions are as follows:
•
P2NPCBench , to the best of our knowledge the first benchmark that pairs each
NP-complete problem with a polynomial-time variant differing in a single
structural detail, with 2,114 hardened statements and human-verified
reference solvers.
•
AgentGAN , a training-free adversarial framework that hardens
statements while keeping them answer- and class-preserving.
•
We evaluate 12 proprietary and open-source models and show that the
dominant failure lies in the P → \to NPC direction, and that hardening narrows the class gap from 24.6 to 14.5 points.

2.1 Problem Formulation
A seed s s is a well-posed problem with a statement, a reference
solver R s R_{s} , and graded tests T s T_{s} . Each family has two matched
criteria c ∈ { npc , p } c\in\{\textsc{npc},\textsc{p}\} that pose the same task
under a controlled complexity class (e.g. 3 3 - vs. 2 2 -colouring). A
variant x ∈ 𝒳 ⁡ ( s , c ) x\in\mathcal{X}(s,c) is a rewrite of the seed that
preserves the ground-truth answer and the class while removing the cues that
enable textbook recall.
To measure whether a variant is harder, we use a panel
𝒟 = { D 1 , … , D m } \mathcal{D}=\{D_{1},\dots,D_{m}\} of m m fixed code models, each of which
attempts to solve the variant. We write δ j ​ ( x ) ∈ { 0 , 1 } \delta_{j}(x)\in\{0,1\} for whether
D j D_{j} fails on x x , i.e. its solution does not pass every test in T s T_{s} . A
variant is only useful if it remains valid: answer-preserving,
class-preserving, well-posed, and solvable. We enforce this with a
validity gate Γ \Gamma , a set of checks that every variant must pass
(Section 2.2 ), and write 𝒳 Γ ​ ( s , c ) ⊆ 𝒳 ⁡ ( s , c ) \mathcal{X}_{\Gamma}(s,c)\subseteq\mathcal{X}(s,c) for the variants it admits. Finally, let A ⊆ { 1 , … , m } A\subseteq\{1,\dots,m\} be the indices of panel models that solve the seed itself, since
only these can still be defeated. The goal is to find the valid variant that
defeats as many of them as possible:
x ⋆ = arg ⁡ max ⁡ ∑ j ∈ A x ∈ 𝒳 Γ ​ ( s , c ) ⁡ δ j ​ ( x ) . x^{\star}=\arg\max_{x\,\in\,\mathcal{X}_{\Gamma}(s,c)}\ \sum_{j\in A}\delta_{j}(x).
(1)
The feasible set is defined by the validity gate Γ \Gamma , so the generator
cannot win by breaking the problem: Γ \Gamma forbids altering the answer or
the class, dropping bounds or tie-break rules, leaking the class or algorithm
name, and producing an ill-posed or unsolvable statement.
2.2 AgentGAN Framework
Adversarial roles.
We do not propose a new multi-agent adversarial pipeline. Instead, we adapt MALLM-GAN
( Ling et al., 2026 ) , which casts frozen LLM agents as a generator and
discriminators for tabular data synthesis, to generating and hardening
p and npc problems. We name our adapted framework
AgentGAN . We also add some modules that MALLM-GAN lacks ( Wang et al., 2026 ) :
a cross-round memory that conditions the generator on the full
hardening trajectory, an executable validity gate that prevents the
generator from winning by corrupting the problem, and an expert
council that critiques rejected drafts. The generator is a single
strong model and the sole author of all statement text. The discriminator panel is a fixed set of models m m . Rather than imposing one decoding configuration on the panel, each
model is run at the settings its own documentation recommends for code
generation (Appendix E ), so that no model is penalised for a
configuration it was not tuned for and every measured failure reflects the
model at its intended operating point. The panel is
frozen by design because the
quantity of interest is the drop induced on a fixed population, not an
equilibrium between two moving players.
Validity gate.
Γ \Gamma applies two kinds of checks to every candidate. Hard
constraints are pass/fail properties that a variant must never violate, and
most of them are executable rather than judged. The reference solver is run on
every example in the rewrite and must reproduce the stated output, any added
formal constraint is evaluated against all seed inputs, and a model outside
the panel must solve the rewrite and pass the base test tiers, which ensures
that the variant remains solvable. Deterministic scans further check that the
I/O contract and all bounds are preserved and that no class or algorithm name
appears. Graded criteria measure quality: a verifier from a different
provider than the generator, chosen to avoid self-enhancement bias, scores
unambiguity (G1), completeness (G2), faithfulness (G3), and naturalness (G4)
on a 0–5 scale, using the prompt in Appendix D . A candidate
is accepted only if it passes every hard constraint and reaches the minimum
score on every criterion. The two kinds of checks are applied separately rather than
combined into one score, so a high quality score cannot make up for a violated
constraint. Among accepted candidates, we keep the one with the highest
weighted sum of the four scores, with faithfulness weighted most
( Cheng et al., 2026 ) .
Hardening loop.
Each accepted base variant seeds a lineage hardened over depths
d = 0 , … , d max d=0,\dots,d_{\max} with d max = 10 d_{\max}{=}10 . At depth d d the panel is run on
x d x_{d} ; the verifier summarises the single shortcut the survivors exploited and
labels it mutable (rewordable) or a structural floor (the
shortcut is the task). The generator then produces candidates along a
fallback ladder, each gate-validated, and the highest- Q Q accepted candidate
becomes x d + 1 x_{d+1} . Defeated discriminators are retired , still
re-tested at each depth to confirm continued defeat, but no longer steering the
generator:
A d + 1 = A d ∖ { j : δ j ​ ( x d ) = 1 } A_{d+1}=A_{d}\setminus\{\,j:\delta_{j}(x_{d})=1\,\}
(2)
We report d ⋆ = min ⁡ { d : A d + 1 = ∅ } d^{\star}=\min\{d:A_{d+1}=\emptyset\} , the
depth-to-defeat , as the per-lineage hardness statistic; a shallow
d ⋆ d^{\star} indicates a seed that was already hard.
Memory and escalation.
A per-lineage memory M M records the depth history, which strategies newly
defeated or regressed which discriminators, dead ends, and per-model profiles.
A token-capped block is fed back into G G , so the generator conditions on the
full trajectory rather than the last round alone, the closest analogue to
gradient accumulation available without weight updates. Two escalations fire
when the ladder stalls: aggressive mode ( d ≥ 3 d\geq 3 ) requires the generator
to invent and name a novel strategy, persisted to the library; and the
adversarial corner engine pivots from surface attack to instance
attack once a structural floor is declared, generating a candidate input pool
and retaining those that break survivors under differential testing
against R s R_{s} .
Expert council.
When Γ \Gamma rejects a draft, an expert model from a third provider critiques
it and proposes alternatives, and the generator revises over bounded
negotiation rounds with the transcript persisted. The expert never authors
final text and never validates; role separation (generator, verifier, panel, expert, held-out) is enforced in code, and no model may
occupy two roles.

Problem statements and candidate reference solvers were collected from these
sources and then adapted into a uniform competitive-programming format with an
explicit I/O contract, numeric bounds, and tie-break rules. This yields 24
reference solvers, one for each criterion of the 12 families (12 npc
and 12 p ). Every reference
solver was subsequently run by the authors on the full test suite of its
family and checked by hand against the source’s stated semantics. Solvers that
disagreed with the source, mishandled boundary cases, or left the tie-break
behaviour underdetermined were rewritten until they did not. All authors hold
computer science degrees and are regular ICPC regional contestants, so the verification was carried out by annotators already fluent in
both the complexity-theoretic content and the competitive-programming
conventions the format assumes. Every reference answer was independently checked by two authors, with a high
inter-annotator agreement of Cohen’s κ = 0.86 \kappa=0.86 . This manual pass matters because the entire
pipeline treats R s R_{s} as ground truth.
Family inclusion criterion.
A family is included in P2NPCBench only if it admits a matched pair : an
npc criterion and a polynomial-time relative posed in the
same problem setting and differing in the single structural feature
that moves the problem across the class boundary. Without such a relative
there is no p → npc \textsc{p}\!\rightarrow\!\textsc{npc} direction to measure, and
any accuracy gap would confound class with domain. Twelve families satisfy this criterion and are listed in Table 1 .
Excluded families.
We dropped candidate families for one of two reasons. First, the family has no
polynomial variant that keeps the same problem setting: for
Supply Purchasing (Quadratic Diophantine Equations), any relaxation
changes the task rather than its class. Second, the polynomial variant is too
easy to contrast with the npc one: Network Broadcast Design
(Maximum Leaf Spanning Tree) becomes polynomial on trees, but a tree is its own
only spanning tree, so the task reduces to counting leaves.
Class-disguise edits.
Eleven strategies σ ∈ { S 01 , … , S 11 } \sigma\in\{S_{01},\dots,S_{11}\} are applied at one of
three intensities: light , moderate , or aggressive ,
which control how far the rewrite departs from the seed, from a minimal
surface change to a full re-authoring of the statement, and, where compatible,
composed in pairs at the two higher intensities. The strategies are:
S 01 S_{01} removes textbook-recall wording ( Wang et al., 2023a ) ;
S 02 S_{02} keeps the structure but changes the real-world scenario ( Duchnowski et al., 2025b ; Mirzadeh et al., 2025b ) ;
S 03 S_{03} describes special structure by its mechanics, never by name ( Wang et al., 2023a ) ;
S 04 S_{04} makes a hard problem look as though it admits an easy shortcut ( Lam et al., 2025 ) ;
S 05 S_{05} makes an easy problem look as though it demands heavy machinery ( Lam et al., 2025 ) ;
S 06 S_{06} states bounds indirectly, so the reader must derive them ( Wang et al., 2023a ) ;
S 07 S_{07} embeds the task in a scenario where every detail is load-bearing ( Mirzadeh et al., 2025b ) ;
S 08 S_{08} adds true non-binding, answer-preserving constraints ( Mirzadeh et al., 2025b ) ;
S 09 S_{09} presents the task as one step in a larger workflow ( Mirzadeh et al., 2025b ) ;
S 10 S_{10} reorders the statement so the objective arrives after the constraints ( Wang et al., 2023a ) ;
and S 11 S_{11} attacks the specific shortcut observed in discriminator reasoning
traces, in a primary and a secondary form.
Test case tiers.
Every criterion is graded on three separately scored tiers: anchor
(small seed cases), corner (generated adversarial edge cases), and
worst-case (large or near-threshold instances). Grading is either
exact match against R s R_{s} or witness verification via a per-family validator.
Human verification of hardened statements.
The validity gate is automated, so we also checked its output by hand. From
each of the 12 families we randomly sampled 20 hardened statements per
criterion, giving 240 npc and 240 p statements (480 in
total). Each was shown alongside its seed to three undergraduate annotators,
all rated within 1200–1399 (Pupil) on Codeforces, who scored it on a
three-point scale: 0 if the rewrite is not faithful to the seed,
i.e. it changes the task or introduces an error; 1 if it is faithful
but stays close to the seed’s wording; and 2 if it departs
substantially from the seed while remaining correct and faithful. The scale
thus measures both properties: a 0 marks a
failure of the gate, and the split between 1 and 2 shows how much disguise the
hardening achieved. By majority vote, annotators assigned a score of 0 to
4.2% of statements (20 of 480) with inter-annotator agreement of Fleiss’
κ = 0.79 \kappa=0.79 . The 20 statements scored 0 were removed from the benchmark;
the full breakdown is given in Appendix C .
2.4 Dataset Statistics
Figure 2: Composition of P2NPCBench . Inner ring: families sized by evaluated statements.

P2NPCBench comprises 12 families, each with an npc and a p
criterion, totalling 2,114 evaluated statements (1,003 npc ,
1,111 p ) drawn from 1,141 accepted versions; a statement counts every version together with every depth of its lineage, so statements within a lineage are related rather than independent
(Figure 2 ). The two classes are closely balanced in every

3.2 Metrics
A solution is run on each test case of its statement and passes a case only if
it exits cleanly, finishes within the wall-clock limit, and its output is
accepted by the family’s grader: a witness validator that checks the answer
against the problem constraints, or exact match against the reference output
for optimisation families. Our main metric is pass@1 : each model
produces a single solution per statement, and the statement counts as solved
only if that solution passes every test case; a single failed case
fails the statement:
pass@1 = 100 | S | ∑ s ∈ S [ p s = t s ] , \text{pass@1}=\frac{100}{|S|}\sum_{s\in S}\mathbf{1}\!\left[\,p_{s}=t_{s}\,\right],
(3)
where p s p_{s} and t s t_{s} are the passed and total test cases of statement s s ,
and S S is the set of statements a model attempted. npc statements are scored under four time limits
(1, 2, 5, 10 s), which the model is told. A case passes at limit L L if it is
correct and its measured runtime is at most L L . p statements are
scored once, at the limit stated in the problem (2s).

4.1.2 Benchmarking Results
Overall results.
No model, regardless of size or access, solves npc statements as
reliably as their p counterparts. Table 2
reports pass@1 for twelve models on P2NPCBench . Every model scores lower on
npc than on p statements on average (35.4% vs. 63.8%
across models), with gaps from 9 to 54 points; proprietary models average
62.9% / 91.7% against 26.2% / 54.5% for open-source ones. The three
proprietary models lead on both classes: GPT-5.6 Sol (68.4% / 94.4%) and
the two Gemini Flash models win ten of twelve npc families, and the
exceptions, SAT (2) and clique (4), are won by the open-source Gemma-3-27B and
Mistral-Medium-3.5, but none closes the gap. The sharpest split is
Qwen3.8-27B, which is competitive on p (75.5%) yet collapses on
npc (21.2%). Small gaps among the weakest models (e.g. Gemma-3-4B,
7.3% / 16.4%) reflect failure on both classes rather than class robustness.
Linear arrangement (8) and exact cover (7) are the hardest npc
families, and edge colouring (10) remains hard on both sides for all but the
strongest three models. Averaged over models (last row), the class gap is
widest on job-shop (6; 28.6% vs. 73.6%), precedence scheduling (12) and
exact cover (7), each above 40 points, and in eight of twelve families every
model scores lower on npc than on p . Beyond edge colouring,
the gap nearly vanishes only on 3-D matching (3; 64.4% vs. 69.6%), whose
npc statements are the easiest in the benchmark, suggesting that its
hardened variants still leave a recognisable shortcut.
Scaling Effect.
Within the Gemma-3 family, scale helps only up to a point and never closes the
class gap. Moving from 4B to 12B lifts accuracy on both classes (7.3% → \to
26.4% on npc , 16.4% → \to 43.5% on p ), but 27B brings no
further gain.
4.2 Effect of the Time Limit
npc statements are scored under four time limits, which the model is
told in advance. Figure 4 (Left) shows that extra
time helps little: raising the limit tenfold lifts mean pass@1 only from
28.5% to 31.9%, and no model gains more than 5.1 points, with GPT-5.6 Sol,
for instance, moving from 63.1% to 66.7%. A case that passes only under a
longer limit is correct but slow, so the small gain means that most failures
come from incorrect or non-executable solutions rather than from time
constraints: the hardened statements defeat models by leading them to an
incorrect solution, not by out-scaling a correct one. The gain is also not
concentrated at the shorter limits: 45% of it arrives only between 5 and
10 s, consistent with a minority of correct exhaustive solvers that finish
just past the shorter limits. Proprietary and open-source models gain about
equally (3.5 vs. 3.3 points), and the ranking is almost unchanged: between
1 s and 10 s only Gemma-3-12B overtakes Qwen3.8-Omni-Flash, and the gap of
about 34 points between the two groups persists at every limit.
4.3 Hardening Effectiveness
Figure 4 (Center) compares the accuracy of the
twelve benchmark models on each seed with their accuracy on the last hardened
variant. Unlike Table 2 , which averages
over all 2,114 statements, this comparison uses only the last variant. Hardening lowers accuracy on both classes in every family. On
npc statements, mean accuracy falls from 61.4% to 41.9%
( − 19.5 -19.5 points), with the largest losses on linear arrangement ( − 34.2 -34.2 ) and the smallest on
multicommodity flow ( − 8.3 -8.3 ). On p statements the
drop is larger still, from 86.0% to 56.4% ( − 29.6 -29.6 points): seeds that
models solve almost perfectly, such as clique / independent set (99.0%) and
SAT (94.0%), lose 52.3 and 48.6 points once their recognisable textbook
phrasing is removed. The only single-digit p drop is on 3-D matching
( − 7.3 -7.3 ), whose seed was already the hardest p problem (55.0%).
Because p accuracy falls further, the class gap narrows from 24.6 to
14.5 points, suggesting that part of the original gap reflected familiarity
with canonical phrasings rather than class. The hardening loop also has to
work harder on p : its lineages run deeper on average (6.62 vs. 4.96), and the families that resist hardening consume the most depth
( r = − 0.68 r=-0.68 between depth and drop), whereas exact cover, already difficult
at the seed (45.3% on npc ), stops after only 1.47 rounds (per-depth
curves in Appendix H ).
4.4 Directional Asymmetry
Because both criteria of a family share a seed, the two classes measure
opposite directions of the same structural edit: the npc variant is
reached by the p → \to npc edit, and the p variant
by the npc → \to p edit. Figure 4 (Right) plots
every model–family pair by its accuracy in each class. The asymmetry is
overwhelming: 137 of 144 pairs fall below the diagonal, models fail 64.6% of
npc statements against 36.2% of p statements, and the
median pair scores 25.5 points lower on npc , with 52 pairs exceeding
40 points. Combined with the small effect of extra time
(Section 4.2 ) and the failure taxonomy
(Section 5 ), this indicates that the dominant failure lies in
the p → \to npc direction: when an edit turns a tractable seed
into an np -complete one, models mostly produce incorrect or
non-executable programs rather than correct but slow ones.
The npc → \to p direction fails far less often and in a
concentrated way: six of the seven pairs above the diagonal involve
open-source models, mostly where both scores are low, and all fall in
families with the most familiar textbook boundaries, namely graph colouring
(1), SAT (2), 3-D matching (3), and edge colouring (10). The one sharp
reversal, Gemma-3-27B on 3-D matching (73.5% vs. 33.2%), is consistent
with that family’s weak class gap in Table 2 . Missing
polynomial structure is not negligible either: p accuracy stays low
on linear arrangement (45.5%) and edge colouring (26.7%), whose polynomial
algorithms are themselves non-trivial.
5 Failure Taxonomy
We classify every failing test case into one of three types (see Appendix F for details).
(i) Wrong answer means the program exits cleanly but its output is
rejected. We observe five causes: a misread constraint, a greedy or heuristic
method in place of an exact one, a mishandled edge case, a violated output
format, and a wrong feasibility decision. (ii) Runtime error means the
program crashes with an uncaught exception. We observe eleven exceptions in
four groups: malformed code (SyntaxError, IndentationError,
NameError); input-format misreads (ValueError, IndexError, KeyError);
scale and representation errors (RecursionError, OverflowError); and
other logic and environment errors (UnboundLocalError,
ModuleNotFoundError, TypeError). (iii) Time-Limit Exceeded (TLE) means
the program is killed at the wall-clock limit, mostly from exponential
backtracking and occasionally from correct but unoptimised code. The analysis covers
1,348,290 graded test cases, of which 60.9% fail on npc and
37.6% on p . On npc , runtime errors are the largest failure type (44.1%),
ahead of genuine wrong answers (33.2%) and TLE (22.7%), so few failures come
from programs that are merely too slow, consistent with the small effect of
extra time. On p , wrong answers lead
(46.6%), followed by TLE (30.2%) and runtime errors (23.2%). Nearly half of
all crashes (46.5%) are syntax or indentation errors from truncated code or
prose leaking into the code block, and a further 27.1% are input-format
misreads, suggesting that the disguised I/O contracts of hardened statements
do real work. Timeouts concentrate in exact cover (7) and linear arrangement
(8), where they cause about 46% of npc failures, matching their
position as the two hardest npc families in
Table 2 . Models also differ in how they fail: strong
models such as Gemini-3.8-Flash and DeepSeek-V4.1-Flash rarely time out and
split their failures between wrong answers and crashes, Gemma-3-12B and 27B
time out on 60–70% of their failing p cases, and the weakest models
(Gemma-3-4B, Llama-4-Scout) fail mainly with wrong answers. Qualitative examples of failing solutions are given in Appendix G .
6 Conclusion
We introduced P2NPCBench , a benchmark that pairs each NP-complete problem
with a polynomial-time variant differing in a single structural detail, and
AgentGAN , an adversarial multi-agent framework that hardens each
statement while preserving its answer and complexity class. Across 12
models, accuracy drops sharply when a problem crosses from P to NP-complete,
extra time barely helps, and failures stem mainly from incorrect or
non-executable solutions rather than from time constraints. Removing textbook
phrasing lowers accuracy on both classes, yet a clear gap between them
remains. Together, these results suggest that current LLMs often recognise
familiar problems rather than reason about their structure. Future work can
extend the benchmark to more families and other complexity classes, and use
AgentGAN to harden problems in other domains.
Limitations
P2NPCBench covers 12 families and contrasts only P and NP-complete problems,
leaving other classes such as PSPACE untested, and all statements are in
English. Models are evaluated only on Python 3 solutions. We do not test
C/C++, Java, or other languages, where faster execution could change the
effect of time limits and the balance between correct but slow and wrong
programs. Statements are hardened against a fixed panel of four models, so
they may target panel-specific shortcuts, and some evaluated models are
close relatives of panel members. While executable checks preserve answers
and test outputs, unambiguity and faithfulness are judged by an LLM
verifier, so a rewrite may still admit an unintended reading. Statements
within a lineage are correlated, each model is evaluated with a single
greedy sample, and API-based models may change over time. Finally, the
released statements may enter future training data, although
AgentGAN can regenerate fresh variants from the same seeds.
Ethical Considerations
P2NPCBench consists of algorithmic problem statements, reference solvers,
and synthetic test inputs, and it contains no personal data. The reference
solvers were verified by the authors, and the sampled hardened statements
were checked by three undergraduate annotators who participated as
volunteers. Seed problems are adapted from cited textbooks and public
catalogues, and the fictional scenarios in hardened statements were written
by LLMs accessed in accordance with each provider’s terms of service.
Although AgentGAN produces text designed to mislead code models, the
released rewrites are restricted to algorithmic problems and preserve the
correct answer, so we judge the risk of misuse to be low. We used generative
AI tools to assist with drafting and editing parts of the manuscript and
formatting the appendices. The authors reviewed all AI-assisted material and
take responsibility for the methods, results, claims, and code in this paper.

Appendix A Related Works
NP-complete benchmarks.
GraphArena ( Tang et al., 2025 ) and NPPC ( Yang et al., 2025 )
test LLMs on combinatorial problems such as shortest paths, satisfiability, and
TSP, where even strong models fall below 10% on the hardest instances.
NPHardEval ( Fan et al., 2024 ) is the closest in spirit, spanning P,
NP-complete, and NP-hard classes across 900 questions, and
Li et al. (2024) extend it to visual inputs. Presentation matters:
Duchnowski et al. (2025a) show that LLMs solve textbook phrasings of graph
colouring, knapsack, and TSP far better than real-life or inverted ones,
suggesting recall of seen solutions rather than reasoning about the problem’s
structure. All of these benchmarks are static, however, and none pairs a P and
an NP-complete variant of the same seed, so a model’s sensitivity to
complexity class cannot be separated from its familiarity with the surface.
Adversarial and complexity-aware code generation.
Robustness studies perturb code and math problems with fixed, hand-designed
edits: ReCode applies over 30 meaning-preserving transformations
( Wang et al., 2023b ) , CodeCrash inserts misleading comments and hints
( Lam et al., 2026 ) , and a single irrelevant clause can cut math accuracy
by up to 65% ( Mirzadeh et al., 2025a ) . None groups its problems by complexity
class. Evolving methods raise difficulty iteratively, rewriting seeds into
harder instructions ( Xu et al., 2024 ) or turning model failures into new
ones ( Jiang et al., 2023 ) ; multi-agent pipelines generate, validate, and solve
problems to expose errors static benchmarks miss ( Yoa et al., 2026 ) ; and
adversarial unit tests are generated to train coders ( Huang et al., 2026 ) .
Closest in structure, MALLM-GAN ( Ling et al., 2026 ) casts frozen LLM agents as a GAN for
tabular data synthesis, but its generator is unconstrained and need not stay
correct. AgentGAN brings this structure to complexity-aware code
generation, hardening statements and test cases under an executable gate that
preserves the answer and the complexity class.
Appendix B Family Details
Each family of P2NPCBench pairs an np -complete criterion with a
polynomial-time relative posed over the same surface. For every family we describe the task, the source
of hardness for the npc criterion, the algorithm that places the
p relative in polynomial time, the single structural edit that moves
an instance across the class boundary in either direction, and how solutions
are graded.
01 Graph colouring.
Given an undirected graph G = ( V , E ) G=(V,E) and a palette of k k colours, the task is
to assign each vertex a colour so that no edge joins two vertices of the same
colour, or to report that no such assignment exists. The npc
criterion fixes k = 3 k=3 ; deciding 3 3 -colourability is np -complete even
on planar graphs of maximum degree four ( Garey et al., 1976b ) . The
p relative fixes k = 2 k=2 , which is exactly the question of whether G G
is bipartite: a breadth-first search that alternates colours layer by layer
either produces a valid colouring or finds an odd cycle, in O ⁡ ( | V | + | E | ) O(|V|+|E|) time.
The class-flipping edit is therefore a single parameter, the size of the
palette: raising it from two to three removes the forced alternation that
makes the problem trivial, and lowering it from three to two collapses the
search to a traversal. This makes the family the cleanest test of whether a
model recognises the boundary, because the two statements differ in one
number. The npc side is graded by a witness validator that checks
every edge of the returned colouring, which allows planted instances near the
colourability threshold (edge-to-vertex ratio ≈ 2.3 {\approx}2.3 , up to
∼ 1,200 {\sim}1{,}200 vertices) whose solution exists by construction but is
infeasible to find by search; the p side is graded by exact match.
02 Satisfiability.
Given a Boolean formula in conjunctive normal form, the task is to find an
assignment of truth values that satisfies every clause, or to report that
none exists. The npc criterion bounds every clause to at most three
literals, the canonical np -complete problem
( Cook, 1971 ; Karp, 1972 ) . The p relative
bounds every clause to two literals: each clause ( a ∨ b ) (a\vee b) becomes the
implications ¬ a ⇒ b \neg a\Rightarrow b and ¬ b ⇒ a \neg b\Rightarrow a , and the
formula is satisfiable if and only if no variable shares a strongly connected
component with its negation in the resulting implication graph, which is
decidable in linear time ( Aspvall et al., 1979 ) . The edit is the clause
width: allowing a third literal per clause breaks the implication structure,
because a clause with three literals no longer forces any single literal when
one other is false, and removing it restores the structure. A model that
pattern-matches ‘‘SAT’’ to exhaustive search will over-engineer the
p side, while one that reaches for implication graphs on the
npc side will produce a fast but incorrect solver. Both criteria are
graded by a validator that evaluates every clause under the returned
assignment.
03 Matching.
Given disjoint sets X X , Y Y , and Z Z of equal size q q and a collection
T ⊆ X × Y × Z T\subseteq X\times Y\times Z of triples, the npc criterion asks
for q q triples that together cover every element exactly once. This is
three-dimensional matching, one of Karp’s original np -complete
problems ( Karp, 1972 ) . The p relative drops the
third coordinate: given X X , Y Y , and a set of admissible pairs, it asks for a
perfect matching in a bipartite graph, solvable by augmenting paths and in
O ⁡ ( | E | ​ | V | ) O(|E|\sqrt{|V|}) time by Hopcroft and Karp (1973) . The edit is the arity of
the matched tuples: adding the third dimension turns each pair into a triple
and destroys the augmenting-path structure, since a locally improving swap
can no longer be certified by a path in a single graph. Statements on both
sides describe the same allocation scenario, differing only in how many
resource types each match must bind. Both criteria are graded by a witness
validator that checks disjointness and coverage; on the npc side
this admits planted instances with a guaranteed perfect matching at
triple-to-element ratio ≈ 4.0 {\approx}4.0 and q ≥ 80 q\geq 80 .
04 Clique and independent set.
Given a graph and a target size k k , the task is to find a set of k k
vertices that are pairwise adjacent (a clique) or pairwise non-adjacent (an
independent set); the two are equivalent under graph complementation. On
general graphs both are np -complete ( Karp, 1972 ) .
The p relative restricts the input to interval graphs, in which
each vertex is an interval on the line and edges join overlapping intervals.
There, a maximum independent set is found greedily by repeatedly selecting
the interval with the earliest right endpoint, and a maximum clique is the
largest number of intervals overlapping a single point, found by a sweep over
sorted endpoints; both run in O ⁡ ( n ​ log ⁡ n ) O(n\log n) ( Golumbic, 1980 ) .
The edit is the representation of adjacency: posing the instance as
intervals with overlap-induced conflicts admits the greedy, while posing it
as an arbitrary edge list — or adding conflicts that no interval
arrangement can realise — removes it. This family tests whether a model
notices a geometric structure that the surface wording may describe only
indirectly. Both criteria are graded by a validator that checks the size and
pairwise property of the returned set.
05 Steiner tree.
Given a weighted undirected graph and a set of terminal vertices
R ⊆ V R\subseteq V , the task is to find a minimum-weight tree that connects every
terminal, optionally passing through non-terminal vertices. With R R an
arbitrary subset, the decision version is np -complete
( Karp, 1972 ) . The p relative sets R = V R=V : when every
vertex must be connected, the optimal Steiner tree is a minimum spanning
tree, found greedily by Kruskal’s algorithm in O ⁡ ( | E | ​ log ⁡ | E | ) O(|E|\log|E|)
( Kruskal, 1956 ) . The edit is the terminal set: shrinking it from
all vertices to a proper subset introduces the choice of which optional
vertices to include, which is the source of hardness, while expanding it to
all vertices removes that choice. Statements typically frame the task as
connecting sites in a network, so the two criteria differ only in whether
every site must be served. Because the task is an optimisation with no cheap
certificate of optimality, both criteria are graded by exact match against
the reference cost.
06 Job-shop scheduling.
Given a set of jobs, each a sequence of operations with fixed processing
times on designated machines, the task is to schedule all operations so that
each machine processes one operation at a time and each job’s operations run
in order, minimising the makespan. The npc criterion is the general
job shop, in which each job follows its own machine order; minimising makespan
is strongly np -hard already for three machines, and the
corresponding decision problem is np -complete
( Garey et al., 1976a ) . The p relative is the two-machine flow
shop, in which every job visits the same two machines in the same order;
Johnson’s rule — schedule first the jobs whose first operation is shorter, in
increasing order of that time, then the rest in decreasing order of their
second operation — is optimal and runs in O ⁡ ( n ​ log ⁡ n ) O(n\log n)
( Johnson, 1954 ) . The edit relaxes the routing: allowing
job-specific machine orders or a third machine breaks the exchange argument
that makes Johnson’s rule optimal. Both criteria are optimisation problems
without a cheap optimality certificate and are graded by exact match against
the reference makespan.
07 Exact cover.
Given a universe U U and a collection of subsets of U U , the task is to select
a subcollection in which every element of U U appears in exactly one chosen
subset. The npc criterion restricts every subset to exactly three
elements, which is exact cover by 3 3 -sets, np -complete
( Hartmanis, 1982 ) . The p relative restricts every subset to
two elements; each subset is then an edge of a graph on U U , and an exact
cover is precisely a perfect matching, found in polynomial time by Edmonds’
blossom algorithm even when the graph is not bipartite
( Edmonds, 1965 ) . The edit is the subset size: moving from pairs to
triples converts edges into hyperedges and loses the matching structure. This
family is closely related to Family 03, but its p relative is a
general matching rather than a bipartite one, so a model that applies
a bipartite algorithm on the p side fails on graphs with odd cycles.
Both criteria are graded by a validator that checks that the chosen subsets
are disjoint and cover U U .
08 Linear arrangement.
Given an undirected graph on n n vertices, the task is to place the vertices
at distinct positions 1 , … , n 1,\dots,n so as to minimise the total edge length
∑ ( u , v ) ∈ E | π ⁡ ( u ) − π ⁡ ( v ) | \sum_{(u,v)\in E}|\pi(u)-\pi(v)| . On general graphs, minimum linear
arrangement is np -complete ( Garey et al., 1976b ) . The
p relative restricts the input to trees, for which an optimal
arrangement can be computed in polynomial time by a recursive decomposition
around a central subtree ( Shiloach, 1979 ) . The edit is the
acyclicity of the input: adding edges that close cycles breaks the
decomposition, while removing them to leave a tree restores it. This is the
least familiar family in the benchmark, and its p algorithm is
itself non-trivial, which makes it a test of whether a model can find a
polynomial algorithm that is rarely taught rather than merely recognising
that one exists. Both criteria are graded by a validator that checks the
returned arrangement is a permutation and compares its cost with the
reference optimum.
09 Multicommodity flow.
Given a capacitated network and a set of commodities, each with a source, a
sink, and a demand, the task is to route every demand simultaneously without
exceeding any edge capacity. The npc criterion has k ≥ 2 k\geq 2
commodities and requires integral flows; integral two-commodity flow is
already np -complete ( Even et al., 1975 ) . The p
relative has a single commodity, which is maximum flow: augmenting-path
methods solve it in polynomial time, and the integrality theorem guarantees
an integral optimum whenever capacities are integral
( Ford and Fulkerson, 1987 ) . The edit is the number of commodities, and the
integrality requirement is essential to it: fractional multicommodity flow
is a linear program and remains polynomial, so the npc statements
must state integrality explicitly. A model that applies max-flow
independently to each commodity produces flows that violate shared
capacities, and one that solves the LP relaxation produces fractional flows
the validator rejects. Both criteria are graded by a validator that checks
capacities, conservation, demands, and integrality.
10 Edge colouring.
Given an undirected graph with maximum degree Δ \Delta , the task is to colour
its edges with Δ \Delta colours so that no two edges sharing an endpoint
receive the same colour, or to report that this is impossible. By Vizing’s
theorem every graph needs either Δ \Delta or Δ + 1 \Delta+1 colours, and deciding
which is np -complete already for cubic graphs, where the question is
whether three colours suffice ( Holyer, 1981 ) . The p relative
restricts the input to bipartite graphs, which are always
Δ \Delta -edge-colourable by Kőnig’s theorem ( Ágnes Cseh, 2024 ) ; a
colouring can be constructed in polynomial time by repeatedly recolouring
along alternating paths. The edit is the graph class: introducing odd cycles
removes the bipartite guarantee, while forcing a bipartition restores it.
Because the p relative’s answer is always ‘‘yes’’, the difficulty
lies entirely in constructing the colouring, and a model that knows the
theorem but not the construction still fails. Both criteria are graded by a
validator that checks every pair of incident edges.
11 Multiway cut.
Given a weighted undirected graph and a set of terminals, the task is to
remove a minimum-weight set of edges so that no two terminals remain
connected. With three or more terminals the problem is np -hard, even
when the number of terminals is fixed at three ( Dahlhaus et al., 1994 ) .
The p relative has exactly two terminals, where the task is an
s s – t t minimum cut, equal in value to the maximum s s – t t flow by the
max-flow min-cut theorem and computable in polynomial time
( Ford and Fulkerson, 1987 ) . The edit is the number of terminals: adding a third
breaks the duality with a single flow, since a cut separating every pair is
not the union of pairwise minimum cuts. This yields a characteristic failure
on the npc side — combining independent s s – t t cuts — that
produces a valid but suboptimal separation. Both criteria are graded by a
validator that checks the terminals are separated and compares the cut
weight with the reference optimum.
12 Precedence-constrained scheduling.
Given a set of jobs, a partial order of precedence constraints among them,
and a number of identical machines, the task is to schedule every job so
that no job starts before its predecessors finish, minimising the makespan.
With unit processing times and the number of machines given as part of the
input, the problem is np -complete ( Ullman, 1975 ) . The
p relative uses a single machine, on which any topological order of
the precedence graph is optimal and is found in linear time. The edit is the
number of machines: adding machines introduces the choice of which ready jobs
to run in parallel, which is the source of hardness. One subtlety bounds the
construction: for exactly two machines with unit processing times the problem
is polynomial ( Coffman Jr and Graham, 1972 ) , so the npc statements leave
the number of machines as part of the input rather than fixing it at two.
Both criteria are graded by a validator that checks precedence, machine
capacity, and the makespan against the reference optimum.

braces, such as {STATEMENT} , is a placeholder filled at run time. The generator, verifier, and

returns strict JSON, since its fields are parsed by code.

The same prompt is used for the discriminator panel during hardening, for the
round-trip solve in the validity gate, and for every model at evaluation.

reasoning trace, and the fenced code block is extracted and run.

Python 3 solutions. Your program reads all input from standard input and

Python 3 code block and nothing else — no explanation before or
after.
Solve the following problem in Python 3.
{STATEMENT}

- Read from standard input, write to standard output.
- Output only the answer in the exact format specified.
- Return only one Python 3 code block.

it earns credit at the tighter limits too. Write the single fastest correct
algorithm you can for the constraints given.

After the panel attempts the current version, this prompt receives the

Why it fails. This is a correct exact-cover search: it picks an uncovered element and tries every disjoint triple that contains it, so any answer it returns is right. What it lacks is a rule that keeps the search small. Exact cover is one of the two families in which timeouts account for nearly half of all npc failures, and this program shows why: the failure is not a wrong answer but one that never arrives.

Why it fails. The immediate failure is the import: SciPy is not installed in the evaluation environment, so the program raises ModuleNotFoundError before reading any input. The model behind the import is also wrong. Each commodity’s equality row adds up its flow over every edge in the network and sets that total equal to the demand, and no constraint enforces conservation at any node; the adjacency list graph is built and never used, so a feasible solution of this program need not be a flow at all. Even with correct constraints, linprog solves the continuous relaxation, which is polynomial and may return fractional flows, while the task requires an integral witness; truncating with int() can then break both demands and conservation. Finally, variables are laid out as j * k + i but read back as i * m + j , so the printed flows would be attributed to the wrong commodities and edges. This is the characteristic failure that Appendix B anticipates for this family: the model solves the tractable linear relaxation instead of the integral problem.
G.7 Satisfiability
Setup. Statement Control Panel Commissioning (Family 02, 3-SAT), solved by Llama-4-Scout. The failing corner test is the input 1 0 : one variable and no clauses, which is trivially satisfiable. The reference answer is YES with any assignment. The program raises TypeError .

Why it fails. The program enumerates assignments correctly, but its clause test is inverted. Each branch of the if / elif chain checks whether a literal is false and, if so, accepts the clause, so a clause counts as satisfied as soon as any one of its literals is false, and the assignment is rejected only when all three literals are true. The correct rule is the opposite: a clause fails exactly when all three literals are false. On this test the bug stays hidden, because with no clauses the first assignment is accepted and the program prints YES . It then crashes while printing the assignment: array(’i’, …) holds integers, and str.join accepts only strings, so the call raises TypeError . The easiest instance in the suite is lost to an output-formatting error, before the inverted logic ever has a chance to matter.
G.8 Precedence Scheduling
Setup. Statement Culinary Event Sequencing (Family 12, precedence-constrained scheduling on several machines), solved by Gemma-3-12B. The failing anchor test has the header 6 3 5 9 : six tasks, three stations, a horizon of five time slots, and nine precedence pairs. The reference answer is YES with the schedule 1 1 2 3 4 5 . The program raises IndexError on this first anchor test.

Why it fails. The program mixes up the number of tasks with the number of time slots. It enumerates permutations of the five slot values and then assigns perm[i] to each of the six tasks, so the sixth assignment indexes past the end of a tuple of length five and raises IndexError . The indexing error hides a deeper modelling error. A permutation gives every task a different slot, but the point of having several stations is that tasks can share a slot, as the reference schedule does by placing the first two tasks in slot 1. The capacity check in is_valid shows the model knew that stations limit how many tasks share a slot, yet its search never generates a schedule in which any slot is shared. With more tasks than slots, no permutation can give each task its own slot, so even with correct indexing the program could never answer YES .
G.9 Job-Shop Scheduling (Corner Case 1)

Why it fails. Running the first job on machine 1 while the second runs on machine 2, and then swapping, finishes both jobs in 20 units. The program cannot find this schedule. It places the jobs greedily in input order, starting each operation after the latest finish already booked on its machine, so the second job’s first operation waits until the first job has released machine 2 and the makespan comes out at 40. The outer loop over machine permutations appears intended to explore alternatives, but it only relabels machine indices and leaves every computed time unchanged, so the program never considers a different job order or any interleaving of the jobs. The output is a feasible schedule, just not an optimal one, and only exact-match grading against the reference optimum exposes the error.

Why it fails. The program discards the order of operations within a job. It files each operation’s duration under its machine and then takes the makespan to be the largest machine load, which here is 5. That quantity is a lower bound on the makespan, not the makespan itself: it ignores that each operation must wait for its predecessor in the same job, and because the ten operations of this job must run one after another, the true makespan is 10. Together with Appendix G.9 , this example shows the same model misreading what the makespan measures in opposite directions, once by serialising jobs that could overlap and once by overlapping operations that must be serial. Both errors produce plausible numbers, and exact-match grading on the optimisation families is what catches them.
Appendix H Accuracy Drop Across Depths
Figure 5 shows what happens to accuracy as we keep hardening the same instances. Both classes get harder with every step. npc lineages fall from 61.4% to 41.9% (19.5 points), and p lineages fall from 86.0% to 56.4% (29.6 points). So p problems start out much easier but lose more, and the gap between the two classes shrinks from 24.6 to 14.5 points. Most of the damage happens early: about half of the total drop comes in the first three steps, and the last three steps barely move the curve. The decline is also steady. Every p step is a drop, and the few npc increases are at most 1.2 points, small enough to be noise.
Families do not all react the same way. Families 07–12 stop earlier on the ladder but lose accuracy two to three times faster per step than families 01–06, in both classes. The same family can also behave very differently depending on its class: graph colouring loses far more as npc (30.6 vs. 15.8 points), while SAT loses far more as p (48.6 vs. 8.7). In SAT, clique, and edge colouring, the p curve ends up below the npc one, and in 3-D matching it is below at every depth. In other words, enough hardening can make an easy problem harder than its npc counterpart.
