CORE EXACTV1
  3  LASAGNA: A Compositional Framework for RAG
  lasagna  is an open-source framework for
evaluating new RAG components inside a complete modern pipeline.
A researcher proposing a new reranker, chunker, or agentic loop today
must either compare against a stripped-down baseline that does not
reflect a modern pipeline, or reimplement the surrounding stack. The
first biases the conclusion by mixing implementation differences
with algorithmic ones; the second is prohibitively expensive and
rarely attempted.  lasagna  provides a configurable
end-to-end pipeline ( Fig. 1a ) with a fixed
interface per stage that the framework enforces, so a new component
drops into one stage and is measured against the same surrounding
stack used by every reported configuration (full code patterns in
  Sections   H.2.2  ,   H.2.3   and   H.2.4  ).
The workflow spans nine processing stages: document processing,
chunking, index-time enrichment, embedding and indexing, query
augmentation, retrieval, reranking, context compression, and answer
generation with optional agentic verification.
Every pipeline component is a subclass of a typed abstract base class:
eight component types are supported ( embedder ,  chunker ,
 reranker ,  retriever ,  document_processor ,
 query_enhancer ,  agentic_pipeline , and  generator ), each
stage’s inputs and outputs are typed  dataclass  contracts, and
behavioral tests check that swapping one implementation does not mutate
a neighboring stage’s state. A single
 @registry.register("<stage>", "<name>")  decorator suffices
to make a new component discoverable at YAML-config time.
The framework ships with 53 built-in components, the 30 methods across the eight factorial
dimensions (  Table   10  ; full catalog in   Appendix   K  ),
six vector backends (Milvus, Pinecone, Qdrant, Weaviate, pgvector,
OpenSearch), and adapters for the eight benchmarks used here (five
BEIR retrieval sets and three long-form QA sets;
  Section   B.2  ). Five automated isolation tests
(  Section   H.1  ) check that toggling one component does not
silently change another, including that two sessions with opposite
settings each keep their own configuration; this supports attributing
the interaction estimates in   Section   5   to the components we
vary rather than to cross-stage leakage. A new component becomes a publishable comparison
in three steps (  Fig.   2  ): register with a decorator,
declare a factorial sweep in YAML, and run end-to-end to receive a
paired statistical test against the same surrounding stack that
produced every reported number. The complete study, factorial plus
138 non-factorial ablations plus the 5K–200K scaling sweep, cost
approximately $5,200 in cloud compute and 310 wall-clock hours
(  Section   A.7  ).

  4  Experimental Design
 Notation.

(  Table   10  );  default_standard  is the
framework’s stock RAG pipeline (a simple, lowest-cost setting on
each dimension) that serves as the starting baseline for our
experiments; a  profile  is one of the four operational RAG
compositions we distill from our factorial and ablation sweeps as
the best-observed configurations targeting distinct points on the
retrieval-faithfulness-latency envelope ( speed ,
 standard ,  balanced ,  max-reliable ; full
specifications in   Section   I.1  ); a  track

differently. We report the joint quality-latency envelope as a

 A unified multi-domain corpus, two evaluation tracks.
 Production RAG deployments operate against heterogeneous knowledge
bases where a single retriever must disambiguate biomedical,
financial, scientific, argumentative, and multi-hop queries from one
shared vector store. Per-benchmark evaluation (the
BEIR default;   Thakur et al., 2021  ) under-tests this cross-domain
distractor pressure. We therefore  unify  our eight evaluation
benchmarks into one corpus: five BEIR sets cover retrieval (NFCorpus,
  Boteva et al., 2016  ; FiQA,   Maia et al., 2018  ; SciFact,
  Wadden et al., 2020  ; ArguAna,   Wachsmuth et al., 2018  ;
HotpotQA,   Yang et al., 2018  ) and three QA sets cover generation
(SQuAD v2,   Rajpurkar et al., 2018  ; MuSiQue,
  Trivedi et al., 2022  ), yielding 149 stratified queries
per configuration (  Sections   B.2  ,   B.1  ,   17  ,   16   and   15  ). Each
configuration is evaluated on two tracks:  retrieval  (BEIR
qrels over 5,132 documents, 93 queries) and  end-to-end
generation  (the same corpus augmented with gold passages, 5,566
documents, 56 queries). Beyond the 167-run factorial, we
additionally ran 138 non-factorial ablation configurations across 24
targeted experiments spanning rerankers, embeddings, chunkers, query
augmentation, and the number of agentic verification iterations
(  Appendix   F  ).
Together with the corpus-scaling sweep (   5  5   K–   200  200   K), the study
records approximately 358,215 individual query evaluations,
including repeated RAGAS evaluation tasks for the same queries
(  Section   A.1  ).
 Metrics.
 End-to-end generation runs report faithfulness and answer relevance
(RAGAS v0.4  ( Es et al., 2024 )  judged by GPT-5.1);
NDCG@10, exact match, token-level F1, and p50/p95 latency and
$/query; GPT-5.1 also generates answers for all configurations.
NDCG@10 follows the BEIR convention  ( Thakur et al., 2021 ) : retrieved
chunks are de-duplicated by parent document ID before scoring, so the
metric matches the document-level qrel grain.
A two-annotator human evaluation validates RAGAS faithfulness
(  Sections   C.4  ,   C.5   and   29  ), and a two-judge
sensitivity analysis (GPT-5.1 vs. Claude Sonnet 4.5) shows that
judge choice shifts absolute faithfulness but preserves profile
ranking, so we treat single-judge point estimates as approximate
and rely on ordinal comparisons for all headline claims
(  Section   F.7  ). A third-judge robustness check
asks Claude Opus 4.7 to score 220 question-answer-context examples
using the same scoring instructions (  Section   F.8  ).
Its moderate agreement with the primary judge (Pearson     r  =  0.44   r{=}0.44   ,
Cohen’s     κ  =  0.35   \kappa{=}0.35   ) supports the same conclusion: relative trends
persist, although exact faithfulness scores depend on the judge.
Metric definitions and judge-bias mitigations in
  Section   C.1  .
 Pre-declared hypotheses.
 Most published RAG ablations tune one component at a time on a
single benchmark at       ≤  50   \leq 50   K corpus, and report the resulting gain
as a recommended configuration. We pre-declared  ( van Miltenburg et al., 2021 ;  Forde & Paganini, 2019 )  three hypotheses
that together test whether this methodology is sound, by asking
whether RAG pipelines can be designed compositionally:
 H1  tests  additivity  (the assumption behind isolated
single-component ablations),  H2  tests  profile
generality  (the assumption that a single balanced recipe deploys
across targets), and  H3  tests  scale invariance  (the
assumption that rankings measured on small corpora persist at larger
corpus scales). The full pre-registration (operational definitions,
statistical thresholds, exclusion criteria, post-hoc corrections) is
reproduced in   Section   A.2  .
   H1   
  Components do not  necessarily  combine additively. 
H1 tests whether two-way interactions among the eight experimental
dimensions explain at least     20  %   20\%    of faithfulness variance. If they
do, gains measured in isolation cannot be assumed to persist when
components are combined.
   H2   
  A single RAG composition can span multiple deployment targets. 
RAG designs face a Pareto tradeoff: retrieval quality,
faithfulness, and response time cannot be maximized jointly,
so practitioners typically re-run configuration search per
deployment. H2 asks whether an intermediate RAG composition
sweeps a wider quality / latency / cost hypervolume than
adding more advanced components does, on a majority of
datasets, covering enough of the Pareto surface that one
published recipe serves multiple targets. Rejecting H2 means
each deployment must hand-tune its own operating point
(formalism and correction:   Section   A.2  ).
   H3   
  Composition rankings shift with corpus scale. 
Most RAG ablations in the literature run at 5K to 50K
documents, but production deployments often serve corpora
an order of magnitude larger. H3 asks whether the ranking of
RAG compositions at 5K matches their ranking at 200K on the
same corpus; if it does not, small-corpus rankings do not
transfer across scale, and design decisions measured at one
scale must be revalidated at the target scale. Confirming
H3 means small-corpus benchmarks are methodologically suspect
as scale-invariant selectors of RAG designs; rejecting it
validates them as predictive across the scales tested
(per-composition log-linear fits, slope-range threshold,
bootstrap CIs, and Kendall’s    τ  \tau    rank-flip test in
  Section   A.2  ).
  5  Results
 H1: the benefit of a RAG technique depends on the complete RAG pipeline and the target metric.
 Across the factorial and targeted tests, some techniques reinforce
one another, some add roughly as expected, and others overlap or
interfere (  Fig.   3  ). Thus, improvements measured by changing
one pipeline stage at a time do not reliably add up in a complete RAG
pipeline. We quantify this by comparing the gain predicted from
separately measured improvements with the gain the combined pipeline
actually delivers. This needs only the configurations the study already
runs, whereas estimating all    28  28    pairwise interactions directly requires
   232  232    parameters, more than a design of this size can support
(  Section   D.3  ). The three largest separately measured retrieval gains, from
cross-encoder reranking, disabling MMR, and document-awareness
prefixes, predict a     +   46.6  %    +46.6\%    lift over the
 default_standard  baseline
(NDCG@10       =  0.412   =0.412   ;
  Table   32  ). On this same split a BM25-only
retriever scores    0.403  0.403    and a recommended off-the-shelf dense encoder
   0.436  0.436    (  Table   60  ), so this is a realistic starting
point, not a weak one. The  balanced  pipeline,
which combines these techniques, realizes only     +   17.2  %    +17.2\%   , a     63  %   63\%   
shortfall relative to the three-technique prediction. Including all
five separately positive retrieval techniques raises the shortfall to
    72  %   72\%    (  Fig.   9  ); across 17 tested combinations, it
ranges from     7  %   7\%    to     72  %   72\%   , with a median of     41  %   41\%   
(  Sections   D.14   and   D.12  ). The ablations suggest partial
functional overlap: reranking already provides some of the filtering
benefit obtained by disabling MMR, leaving less room for the two
techniques to help when combined. The target metric matters as well:
embedding, enrichment, and reranking dominate the retrieval-quality
metric, whereas query augmentation and agentic gating dominate the
answer-faithfulness metric, which measures whether generated claims
are supported by the retrieved context. Across matched pipeline
configurations, the two metrics are essentially unrelated
(  Fig.   7  ; pooled Pearson     r  =   −  0.01    r=-0.01   ,     p  =  0.91   p=0.91   ):
    5  %   5\%    of configurations combine high faithfulness with low retrieval
quality, and     6  %   6\%    show high retrieval quality with low faithfulness.
The same near-zero relationship appears when each benchmark is
examined separately, removing the concern that the near-zero
correlation is caused by pooling benchmarks (  Section   D.2  ).
This indicates that RAG pipeline selection must evaluate both metrics:
selecting a pipeline based only on the retrieval metric can yield strong
retrieval but weakly grounded answers, while selecting one based only on
the faithfulness metric can hide poor retrieval.
 H1: retrieval quality is most strongly associated with embedding and enrichment.
 On the retrieval track (  Fig.   3  , upper triangle;     n  =  167   n{=}167   
configurations), the largest marginal associations are embedding
(     η  2   =  0.164   \eta^{2}=0.164   ), enrichment (     η  2   =  0.144   \eta^{2}=0.144   ), and reranking
(     η  2   =  0.090   \eta^{2}=0.090   ). These unadjusted values are used for exploratory
screening and are not additive because the D-optimal design is
unbalanced and the effects share variance. Compression and agentic gate
contribute negligibly (     η  2   <  0.01   \eta^{2}<0.01    each). Two two-way interactions
survive both Bonferroni and Benjamini–Hochberg FDR correction:
Embedding    ×  \times    Enrichment (     η  2   =  0.102   \eta^{2}=0.102   ) and
Embedding    ×  \times    Reranking (     η  2   =  0.110   \eta^{2}=0.110   ). Both survivors
involve the embedding model. We attribute Embedding    ×  \times    Enrichment
to representation capacity: stronger embedders can encode added
context without diluting the original passage. We attribute
Embedding    ×  \times    Reranking to candidate-set quality: rerankers
have less room to help when the initial embedding already retrieves
strong candidates (  Sections   J.3.1   and   J.3.2  ). MMR reduces NDCG@10 by     3.6  %   3.6\%    relative
on average, opposite its usual benefit on broad, heterogeneous corpora
(  Table   44  ). We hypothesize that on focused-domain corpora
passages with high lexical and semantic overlap are often the same
supporting evidence, so MMR’s diversity penalty demotes them in favor
of topically distant ones (see   Sections   D.12   and   D.13  ).

should also be tested within the complete pipeline. The 2019 MS-MARCO
MiniLM-L6 cross-encoder  ( Nogueira & Cho, 2019 )  ranks above all
four recent rerankers tested (  Table   51  ); we
speculate that its training aligns especially well with our focused
domains. Matryoshka truncation of BGE-M3 to 768
dimensions  ( Kusupati et al., 2022 )  reduces vector storage
and search cost by     25  %   25\%    while improving NDCG@10 by     2.3  %   2.3\%   
(  Table   52  ). We attribute the gain to the
Matryoshka training objective, which concentrates useful signal in
leading dimensions; encoder cost is unchanged because the full vector
is computed first. On generation, faithfulness
is highest with hallucination and answer-quality gates disabled:
gate-triggered refinement can remove supporting evidence, including 14
of 15 chunks in one multi-hop example
(  Table   54  ). HyDE raises NDCG@10 by
    3.1  %   3.1\%    but doubles first-hop latency, reducing the latency-adjusted
gain to     0.9  %   0.9\%   , so its value depends on the latency budget
(  Section   I.2  ).
  6  Conclusion
 We study how modern RAG techniques compose across pipeline stages,
metrics, and corpus scales using  lasagna , a stage-isolated
framework, and    450  450    configurations across eight benchmarks from 5K
to 200K documents. Gains measured one component at a time do not
necessarily persist in complete pipelines; retrieval quality and
answer faithfulness favor different choices; and the best composition
changes with corpus scale. New techniques should be tested in
representative complete pipelines, on both metrics, and at the
intended scale. We release  lasagna  to make such studies
practical and reproducible, and to establish compositional
evaluation as the reporting standard for new RAG techniques rather
than the isolated single-component ablations common today.
