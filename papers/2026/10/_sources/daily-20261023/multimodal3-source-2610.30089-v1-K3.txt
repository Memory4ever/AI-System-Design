K.3 Memory QA
After the stream ends, each question is answered once per memory condition with
the prompt below. On IC the memory is a list of recordings and the answerer
also receives up to 40 frames sampled uniformly from those segments. On ST and
 LT the memory is text only: the tracked name with its
 state or location and its start and end times. The No-Memory
condition receives no memory, only 40 frames sampled uniformly from the whole clip.
 Memory QA prompt template (placeholders in angle brackets) 
 Answer a multiple-choice question about one egocentric video clip. 
 ## Instructions 
 <condition instruction, see below> 
 ## Tool Semantics 
 <task-specific description of what start/stop calls mean> 
 ## Memory 
 <the memory for this condition, rendered as a list of entries> 
 ## Evidence Frames 
 <IC: up to 40 frames sampled from the memory’s segments; No Memory: frames sampled uniformly from the clip> 
 ## Question 
 <question> 
 ## Choices 
 A. <choice> 
 B. <choice> 
 C. <choice> 
 D. <choice> 
 ## Answer 
 Reply with one JSON object and nothing else: {"answer": "A" | "B" | "C" | "D"} -- replace the alternation with exactly one of A, B, C, or D. Pick the single best option even if the evidence is incomplete; never output reasoning, code fences, or other text. 
 Text filled into <condition instruction>, per memory condition (verbatim) 
 No Memory:  This is the no-memory baseline. Do not use proactive tool state or compact segments; answer only from the question, the choices, and the attached frames. 
 Proact Memory:  Use only the compact trace memory below and, when real evidence frames are attached, the attached frames. The memory comes from tool calls made by the evaluated assistant; it may be incomplete, so answer according to the available evidence. 
 Oracle Memory:  The recordings below are the ground-truth intervals that should have been captured, and the attached frames were sampled from them. Use the recording memory and the attached frames together to answer.
