 MemoryTax: The Bitter Lesson of Agent Memory
 Zedong Peng
  Affiliation:  Shanghai Jiao Tong University
  Email:    zedongpeng1@gmail.com  
  Abstract
 Agent memory systems such as Mem0 and Zep decide what to keep before any question arrives; coding agents keep the raw history and let the model search it with its own tools. We ask whether designed memory still helps once the model is strong enough to search for itself. On one LoCoMo conversation (419 turns, 152 questions), we run four memory methods (full context, BM25, Mem0, Zep) and three coding agents (Pi, Codex, Claude Code), each with GPT-4o-mini, GPT-6 Luna and Claude Opus 5.5, and record what every rollout costs. This is a short empirical study, with one conversation and one run per cell. Agent memory is a costly patch for a weak model: Mem0 beats full context only with GPT-4o-mini, and its build alone costs more than a whole full-context rollout. Agent memory also has a ceiling, set by the model that writes it: a stronger reader does not recover what a weaker writer left out. With Claude Opus 5.5, Pi tops the cost–accuracy frontier, scoring 99% for less than half the cost of full context; its one miss is a wrong answer key. Part of that lead comes from photo captions that only the agents could read: on the 88 questions whose evidence has no photo, Pi and full context differ by one answer.

  1  Introduction
 Agent memory systems such as Mem0 and Zep decide what to keep before any question arrives: the model extracts facts or builds a graph from the conversation, and each question sees a few retrieved pieces  [ 1 ,  2 ] . Coding agents and recursive language models keep the raw history instead and let the model search it with its own tools  [ 3 ,  4 ,  5 ,  6 ] .
 The bitter lesson is that knowledge built into a system helps at first, then plateaus, while general methods that scale with computation win  [ 7 ] . Agent memory builds in what to keep. Does it still help once the model is strong enough to search for itself?
 We run four memory methods (full context, BM25  [ 8 ] , Mem0 and Zep) and three coding agents (Pi, Codex and Claude Code), each with GPT-4o-mini, GPT-6 Luna and Claude Opus 5.5, on a conversation from LoCoMo  [ 9 ] , and measure what each run costs. We find:
  •  
  Agent memory is a costly patch for a weak model.  Mem0 beats full context only with GPT-4o-mini, and its build alone costs more than full context’s whole run (Section   3  ).
  •  
  Agent memory has a ceiling, set by the model that writes it.  A stronger reader does not recover what a weaker writer left out (Section   4  ).
  •  
  With Claude Opus 5.5, Pi tops the cost–accuracy frontier  (Figure   1  ). It answers every question whose answer key is sound, for less than half what full context costs. Where the two read the same text they differ by one answer; the rest of Pi’s lead comes from photo captions that only the agents could read (Section   5  ).
 The study is small: one conversation, one run per cell, and a GPT-4o-mini judge. Section   6   lists what it cannot show. Within those limits, the results suggest that a strong model needs less designed memory and better tools for searching the raw record.

  2  Setup
 We run 21 cells, seven methods with three models each, on LoCoMo conv-26  [ 9 ] : 419 turns in 19 sessions and 152 single-hop, multi-hop, temporal and open-domain questions. LoCoMo’s adversarial questions are left out, as in Mem0’s evaluation  [ 1 ] . The history fits every model’s context window. Among the ten LoCoMo conversations, conv-26’s per-method accuracies track those of the full set closely. Table   1   lists the methods.

 The memory methods answer one question at a time with Mem0’s 2025 answer template; Mem0 is OSS 2.1.0 and Zep is Graphiti OSS 0.30.2, both with default extraction and retrieval  [ 1 ,  2 ] . The agents, Pi 1.1.0, Codex 0.159.2 and Claude Code 2.1.295  [ 3 ,  4 ,  5 ] , start a fresh session in a fresh container for each question, with the conversation as one file, their default tools, and the template’s answer rules in the prompt (Appendix   C  ).
 The models go from weak to strongest: GPT-4o-mini, GPT-6 Luna, Claude Opus 5.5. The last two run at reasoning effort high, the effort coding agents are usually run at  [ 10 ] ; GPT-4o-mini has no effort setting. In each cell one model writes the store (Mem0, Zep) and answers every question, or drives the agent.
 Photos.
 Some LoCoMo turns share a photo, and the official file holds a caption of it next to the turn text. The agents get the official file, captions included; the memory methods were given the turn text only. 116 of the 419 turns share a photo, and 64 of the 152 questions have evidence in such a turn. Section   5   measures what this changes.
 Measurement.
 A rollout is one run over the conversation: the build, then the 152 questions. GPT-4o-mini grades every answer with Mem0’s 2025 judge rubric  [ 1 ] ; empty answers count as wrong. Cost is the list price of every model call, LLM and embedding (text-embedding-3-small), with the judge excluded. A turn is one LLM call: one per question for the memory methods, one per step of an agent’s loop, and Mem0’s and Zep’s calls to build their store. Tokens are those calls’ input and output tokens, cached input included; embeddings are not counted. Each cell runs once.
  3  Agent memory is a costly patch for a weak model
 With GPT-4o-mini, Mem0 scores highest. It scores 78%, against 74% for both full context and BM25; Zep scores 43%. The agents score 63% (Pi), 28% (Codex) and 29% (Claude Code): Codex opens the conversation file for three questions in four and Claude Code almost never, and otherwise they answer from the question alone.
 With the two stronger models, the patch stops helping. With GPT-6 Luna, full context scores 92%, BM25 82%, Mem0 80% and Zep 51%; Zep’s graph holds 128 facts from the 19 sessions, against 195 with Claude Opus 5.5. With Claude Opus 5.5, Mem0 and full context both score 95% and Zep 87%, and the agents score highest: Pi 99%, Codex 98% and Claude Code 97%, a lead that comes mostly from questions about photos (Section   5  ). Earlier work also finds that plain retrieval keeps up with elaborate memory  [ 11 ]  and that rankings between memory systems change with the model  [ 12 ] .
  Figure 2:  Cumulative cost–correct curves.  The patch is not free. Mem0’s build alone costs more than full context’s whole rollout with the same model: $0.56 against $0.43 with GPT-4o-mini, $0.45 against $0.29 with GPT-6 Luna and $25.88 against $17.84 with Claude Opus 5.5 (Figure   2  ). Its questions are cheaper, so the build would pay for itself after 372, 545 and 596 questions on the same history; LoCoMo asks 152. Mem0 and Zep are never on the frontier of Figure   1  , which runs through BM25 and full context with GPT-6 Luna and Pi with Claude Opus 5.5. Paying to build memory that a stronger model does not need is a memory tax.
  4  Agent memory has a ceiling
 The model that writes the store limits every reader. Mem0 and Zep write their store with the same model that later reads it. Retrieval calls no language model, so the reader can be swapped: each model answers from the retrievals of the others’ stores (Figure   3  , Table   3  ).
  Figure 3:  Writer and reader. Each colour is one store, written by that model. The filled badge is the writer reading its own store, and arrows run from it to the other two readers. 
 A stronger reader does not recover what the writer left out. On Zep’s GPT-4o-mini graph, GPT-4o-mini, GPT-6 Luna and Claude Opus 5.5 score 43%, 43% and 45%; on the graph Claude Opus 5.5 wrote, 66%, 71% and 87%. Mem0 keeps the order with smaller gaps: 78%, 83% and 84% from GPT-4o-mini’s store, 89%, 91% and 95% from Claude Opus 5.5’s. This agrees with work where verbatim chunks beat extracted facts on long conversations  [ 13 ] .
  5  With Claude Opus 5.5, Pi tops the frontier
 Pi with Claude Opus 5.5 is the top of the frontier in Figure   1  . No other cell scores higher: Pi scores 99% for $6.95 a rollout, while full context with the same model scores 95% for $17.84. Pi reads about 10,000 input tokens a question, 7,900 of them cached, against 28,900 for full context. Codex and Claude Code score 98% and 97% for $25.41 and $28.41; HarnessTax explains why the same model costs so differently across harnesses  [ 10 ] .
 Its one miss is LoCoMo’s mistake. The question asks what kind of painting Caroline shared with Melanie on 13 October 2023, and the answer key says an abstract painting with blue streaks. In the conversation it is Melanie who shares that painting; Caroline shares a drawing. Pi says so and is marked wrong: “Caroline shared a drawing, not a painting. … The paintings shared that day (a sunset and an abstract piece) were Melanie’s.” With Claude Opus 5.5, full context, Codex and Claude Code point out the same mistake and are marked wrong too. On the other 151 questions, Pi with Claude Opus 5.5 is always right.
 Photo captions account for most of Pi’s lead over full context. With Claude Opus 5.5, Pi answers seven questions that full context misses and misses none that it answers. Six of the seven have their evidence in a turn that shares a photo, whose caption Pi could read and full context could not (Section   2  ); so do all six such questions for Codex and all four for Claude Code. On the 88 questions without photo evidence, Pi scores 100%, and full context, Mem0, Codex and Claude Code 99% each (Table   4  ). With the same input, then, Pi matches full context for less than half its cost. Whether searching the record answers more than reading all of it, this study does not settle.
  6  Discussion and limitations
 Our results suggest that agent memory is a costly patch for a weak model and caps what any reader can answer. On this LoCoMo conversation, Mem0 helps GPT-4o-mini but not GPT-6 Luna or Claude Opus 5.5, a stronger reader does not recover what the writer left out, and with Claude Opus 5.5 Pi answers every sound question for less than full context costs.
 The findings rest on a small study, and these limits apply:
  •  
  Scale.  One conversation of LoCoMo’s ten, and one run per cell. Differences of a few questions may not hold in a second run.
  •  
  Grading.  A GPT-4o-mini judge with a lenient rubric, and at least one wrong answer key.
  •  
  Photo captions.  The agents could read photo captions that the memory methods were not given (Section   5  ). This touches comparisons between agents and memory methods, not those among the memory methods.
  •  
  Context length.  The history fits in every model’s context window, so full context is always an option. Results may differ on other benchmarks such as LongMemEval  [ 14 ]  and on histories that do not fit.
  •  
  Settings and prices.  Mem0 and Zep run with their default extraction and retrieval, and other settings may do better. Costs are list prices and depend on each provider’s caching.
 Memory systems and harnesses can also be searched for automatically  [ 15 ,  16 ] , but what is found is still fixed before the question arrives. More broadly, a strong model may need less designed memory and better tools: exact, semantic and vector search over the raw record, driven by the model itself  [ 3 ,  4 ] . Progress may then look less like another memory system and more like ripgrep after grep  [ 17 ] , or zvec-grep after ripgrep  [ 18 ] . Designed memory may survive as a cost trade-off when many questions share one history (Figure   2  ).

  Appendix B  Protocols
 Mem0 OSS 2.1.0 writes one chronological turn at a time and retrieves     k  =  200   k=200    without reranking; dates are prepended to the text. Zep runs Graphiti OSS 0.30.2 on Kuzu, one session per episode, with hybrid edge search (top 20). The memory methods’ GPT-6 Luna and Claude Opus 5.5 requests set reasoning effort high.
 Each agent question is a Harbor 0.24.0 task  [ 19 ] : a fresh container holding only the conversation, exactly as in the official file, without questions or answers. The agent’s last message is its answer. While the agent runs, the container can reach only the model endpoint. GPT-6 Luna and Claude Opus 5.5 run at reasoning effort high, through a proxy that translates the API where an agent does not speak the model’s own; GPT-4o-mini has no effort setting. Codex and Claude Code have web search off; Pi has none. A question may take 20 minutes, and Pi and Claude Code at most 100 turns. With GPT-6 Luna, Codex picks its code mode: one JavaScript tool that calls the shell. A trial that fails or ends without an answer is run again, and only the accepted trial is counted.
