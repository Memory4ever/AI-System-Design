Abstract
Persistent memory is a largely undefended surface for injection and poisoning, and the same risk limits memory sharing among agents. We present PerMIT, a memory architecture with provable integrity guarantees under an explicit trust assumption: only user-typed inputs and values confirmed at a gate are trusted. PerMIT mediates the release and use of untrusted environment-derived values through a finite memory interface, while preserving agent-driven multi-turn planning and tool choice. Over this finite interface, we prove two integrity theorems that are also machine-checked in Lean 4, which together ensure that environment-derived memory reaches a sensitive action only if confirmed at the gate and influences the agent’s behavior only through what the gate displays. Every attack in our threat model thereby reduces to a single auditable decision, which a human, an LLM verifier, or both can make in practice. On Trojan Hippo, PerMIT records zero observed attack success with self-verification and lightweight verifiers. Because each confirmation is a logged verdict on exact content, endorsements accumulate across users, and sufficiently endorsed items become community-confirmed with no further verification required. Under explicit assumptions, we prove and corroborate in simulation a co-scaling property: as the community grows, the risks of promoting poison and of wrongly evicting benign knowledge fall, while per-user verification effort does not rise. On τ 2 \tau^{2} -bench, communities of up to 90 autonomous agents use PerMIT to build shared knowledge bases with no direct memory injection promoted, and the resulting knowledge significantly improves new agents on held-out tasks, suggesting a path toward agents that safely self-improve at test time.

Part I Main Paper
1 Introduction
By carrying preferences, decisions, and hard-won context across sessions, persistent memory transforms a stateless LLM into an agent that becomes more capable and personalized with continued use.
Although agents benefit from reading and writing persistent memory, this capability also creates an attack surface that the underlying models are poorly equipped to defend.
Poisoned information can readily enter persistent memory when an agent browses webpages or invokes tools containing planted injections ( Das et al., 2026 ) .
Such attacks can turn a one-shot prompt injection ( Debenedetti et al., 2024 ) into a persistent compromise, and a single compromise could easily propagate to a broader community if that memory were ever shared.
Existing memory-sharing frameworks such as the Open Knowledge Format ( McVeety & Hormati, 2026 ) (OKF) define formal protocols for writing and exchanging knowledge among agents but do not address memory attacks.
This difficult-to-control risk has limited the practical deployment of memory sharing between agents.
Existing defenses validate retrieved content, govern access, or enforce information-flow policies during agent execution.
A-MemGuard empirically detects context-dependent poisoning through consensus among memory-induced reasoning paths ( Wei et al., 2025 ) , whereas Collaborative Memory enforces dynamic read/write policies over provenance-tagged private and shared memory fragments ( Rezazadeh et al., 2025 ) .
However, neither approach provides formal security guarantees against malicious memories.
Beyond memory-specific defenses, CaMeL addresses prompt injection during agent execution through isolated planning with capability-based policies and user confirmation ( Debenedetti et al., 2025 ) ; FIDES formalizes IFC guarantees and supports selective hiding and constrained inspection of tool results ( Costa et al., 2025 ) . PerMIT builds on this isolation-and-mediation lineage to secure the persistent-memory lifecycle.
PerMIT enforces its trust boundary at the memory interface. The harness captures environment-derived content, including tool outputs, as untrusted and mediates its release and use. The protected agent chooses its next operation and can re-plan on endorsed feedback, so its internal reasoning is not inspected or taint-tracked. The noninterference proofs quantify over arbitrary agent strategies using this finite interface ( Goguen & Meseguer, 1982 ) . However, preventing all influence from untrusted memory would also prevent legitimate tasks whose next steps depend on information recalled from that memory.
To mitigate the safety–utility tradeoff, PerMIT adopts endorsement ( Myers et al., 2006 ) , a formal relaxation that promotes an untrusted value to trusted status only after the user confirms the exact value displayed at the gate, so untrusted memory can be selectively endorsed and used rather than barred.
Using this finite mediation surface and endorsement mechanism, we prove Action Integrity as an exact authorization property and Reasoning Integrity as noninterference modulo the display transcript ( Sabelfeld & Myers, 2004 ; Askarov & Sabelfeld, 2007 ) , and machine-check their single-user core in Lean 4 1 1

These machine-checked guarantees hold over unbounded interface-conformant executions (§ 2.2 ), separating enforced mediation from the correctness of individual endorsement decisions.
Endorsement preserves benign utility by allowing external values to become trusted through an interface with a finite set of operations. The gate displays the exact value, original user instruction, and source, making the decision auditable. On Trojan Hippo, PerMIT combines live agent rollouts with targeted action-boundary probes; self-verification and lightweight verifiers record zero observed ASR while retaining useful memory capabilities (Table 1 ).
Although security concerns have limited the deployment of shared memory, Karpathy’s LLM-Wiki ( Karpathy, 2026 ) illustrates its potential: thousands of users adopted his shared coding-agent setup to improve their agents’ performance.
LLM-Wiki’s success was an exception because the author is highly reputable, and the shared knowledge had accumulated thousands of public endorsements through GitHub stars.
However, scaling shared memory to diverse communities requires accepting contributions from ordinary users and agents, allowing adversaries to pose as legitimate contributors and spread harmful content. To solve this dilemma, PerMIT learns from the success of LLM-Wiki and allows each shared knowledge item to accumulate trust independently, paralleling security mechanisms in distributed systems that aggregate endorsements over shared objects ( Walsh & Sirer, 2006 ) .
Each logged confirmation is bound to the exact content, allowing verdicts from different users and agents to accumulate as item-level trust.
Each item requires confirmation until its accumulated trust reaches the “Community Confirmed” threshold.
As the population grows, confirmations and endorsements allow more items to reach this status and become directly available to new users without further verification, so safety and convenience improve together.
Under explicit assumptions, we prove that poison-promotion and wrongful-eviction risks decrease as the community grows, while the average per-user confirmation burden does not grow (Supplementary Theorem S6.13 ).
Our simulation spanning five billion promotion attempts also corroborates this co-scaling behavior.
PerMIT thus supplies the security assurance missing from the Open Knowledge Format ( McVeety & Hormati, 2026 ) while remaining compatible with its knowledge-sharing protocol.
Finally, we close the loop by using PerMIT to construct community-confirmed shared knowledge bases on τ 2 \tau^{2} -bench ( Barres et al., 2025 ) with up to 90 fully autonomous agents and no human involvement.
None of the tested direct injection payloads reaches the Community-Confirmed tier, and a zero-state agent (i.e. a fresh agent with no prior context or memory) connected to the resulting knowledge base significantly outperforms an agent without shared knowledge on held-out, experience-dependent telecom tasks (§ 5 ).
In summary, this paper makes three contributions:
1.
Securing agent memory with machine-checked integrity.
PerMIT mediates a finite memory interface and binds each endorsement to an exact displayed value and its intended use. Under explicit trust assumptions, PerMIT provides two integrity guarantees, machine-checked in Lean 4 for the single-user core, and an auditable confirmation gate for human or automated verification.
2.
Shared memory in which safety and convenience scale together rather than trade off.
Because each gate decision is a logged verdict on exact content, verdicts accumulate into community-confirmed knowledge, which is the layer that existing memory-sharing frameworks such as OKF lack. Under explicit assumptions, we
prove and corroborate in simulation that poison-promotion and wrongful-eviction risks fall as the community grows while per-user verification effort does not rise.
3.
Safe, autonomous self-construction of shared knowledge.
Our experiments show that autonomous agent communities can safely construct useful knowledge bases with PerMIT. By enabling agents to generate, verify, and certify knowledge in complex environments, PerMIT provides a concrete path toward test-time learning and self-evolving agents.
2 Background and Related Work
2.1 Persistent Memory as an Attack Surface
Persistent-memory architectures manage context across sessions through tiered storage, consolidation, and revision ( Packer et al., 2023 ; Chhikara et al., 2025 ; Xu et al., 2025 ) . Because stored observations later return to the agent’s context, transient exposure can become durable influence. Attacks enter through direct poisoning of a memory or knowledge base ( Chen et al., 2024 ) , query-only interaction ( Dong et al., 2025 ) , or indirect ingestion of retrieved artifacts and webpages ( Srivastava & He, 2025 ; Zou et al., 2026 ; Yang et al., 2026b ) ; shared state can also contaminate users without an adversary ( Yang et al., 2026a ) . The defining risk is temporal: Trojan Hippo plants a dormant payload through one untrusted tool call and activates it only in a later session ( Das et al., 2026 ) . This persistence makes turn-local prompt-injection defences insufficient and motivates guarantees over the memory lifecycle ( Lin et al., 2026 ) .
2.2 Defenses and Formal Coverage
Existing defenses draw their boundaries at different layers. Content-based methods detect anomalous memories or task drift ( Wei et al., 2025 ; Abdelnabi et al., 2024 ) . Isolation and privilege-control methods constrain how untrusted information can influence tool interactions ( Wen et al., 2026 ; Shi et al., 2025 ) . TMA-NM ( Louck, 2026 ) binds memory authority to origin and studies consequential-action safety using TLA+ model checking and an inductive-invariant argument. Willison’s Dual LLM pattern introduced privileged planning, quarantined processing, and opaque references ( Willison, 2023 ) . CaMeL adds capability-based enforcement and user confirmation, while leaving formal verification as future work ( Debenedetti et al., 2025 , §§2,5,10) . AgentDyn reports zero utility for its CaMeL configurations under automated dynamic-task evaluation ( Li et al., 2026 ) . FIDES provides a formal IFC model with integrity noninterference, selective variable hiding, and schema-constrained quarantined inspection ( Costa et al., 2025 ) . Its type-aware policies can permit bounded influence; PerMIT centers exact-value, tool-scoped endorsement and the complete display transcript. Whereas CaMeL and FIDES address prompt injection in agent execution more generally, our contribution centers the persistent-memory lifecycle, with Action Integrity and Reasoning Integrity guarantees for arbitrarily long interactions through the memory interface under explicit trust assumptions. We machine-check the integrity theorems in Lean 4 and aggregate item-level endorsements in the federated tier. Planning and tool choice remain agent-driven, including replanning on endorsed feedback.
2.3 Shared Memory and Evaluation
Shared-memory work has primarily addressed exchange, access, and portability. OKF standardizes knowledge exchange ( McVeety & Hormati, 2026 ) , Collaborative Memory enforces dynamic policies over private and shared fragments ( Rezazadeh et al., 2025 ) , and Portable Agent Memory proposes cryptographically verified transfer and injection-resistant rehydration ( Ravindran, 2026 ) . These mechanisms complement PerMIT but do not establish recipient-side action and reasoning integrity for adopted content.
General agent-security benchmarks emphasize prompt injection within a task episode ( Debenedetti et al., 2024 ; Li et al., 2026 ; Weng et al., 2026 ) ; Trojan Hippo most directly matches our cross-session threat model ( Das et al., 2026 ) . We therefore use Trojan Hippo to evaluate persistent-memory security and τ 2 \tau^{2} -bench ( Barres et al., 2025 ) to evaluate the end-to-end utility of autonomously constructed shared knowledge.
3 The PerMIT Framework
3.1 Threat Model
PerMIT assumes an adversary capable of controlling or manipulating content obtained from the external environment, including tool outputs, web content, external files and codebases. Poisoned payloads may enter persistent memory when the agent invokes tools, browses the web, or inspects external files or code. PerMIT establishes a provenance-based trust boundary: only values typed in directly by the user or exact values explicitly confirmed by the user through the confirmation interface are treated as trusted. All other environment-derived content remains untrusted and cannot reach the protected LLM unless it first passes through this confirmation gate and gets verified to be trusted.
3.2 The Single-User Tier: a Finite Memory Interface
The P-LLM remains an agent that chooses its next operation and revises its plan using endorsed feedback. Prompts describe the interface; the harness enforces its observation and flow rules without inspecting the agent’s internal reasoning. Gate decisions control which values are endorsed; the harness enforces how values cross the interface.

Architecturally, PerMIT places a
Protected LLM agent ( P-LLM ) on the protected side of the trust boundary and uses a Quarantined Reader ( Q-LLM ) to inspect and retrieve relevant content from untrusted memory. The Q-LLM can read the memory store but has no tool capabilities. In our implementation, it is realized as a recursive language model (RLM) ( Zhang et al., 2025 ) , enabling it to navigate stores larger than a context window without loading their contents into the P-LLM’s trusted context (implementation details in Section B.4 ). Untrusted content is exposed to the P-LLM only through opaque handles rather than as readable bytes, and the content can be released only after endorsement through the confirmation gate (Lemma D.1 ).

PerMIT’s finite memory interface yields two guarantees, stated compactly below. Both assume source-based labels, immutable stored blocks, and faithful displays; Appendices D.2.1 and D.2.2 summarize the arguments; Supplement S3 gives the full proofs.
Action Integrity (Theorem D.3 , compact form).
Assume trusted endorsement: acceptance authorizes the exact displayed bytes for the named tool. For every execution from a well-formed initial state, under any attack, each argument reaching a sensitive tool is either an exact user-typed value or a value endorsed by that user at its exact bytes for that exact tool, at or before the call. Endorsement grants reusable authority for an exact value and tool. It does not bind argument position, task, purpose, time, or the other arguments of a call (Appendix D.2.1 ).
Reasoning Integrity modulo the display transcript (Theorem D.5 , compact form).
Consider any two executions ρ 1 , ρ 2 \rho_{1},\rho_{2} from matched initial configurations (the same protected view, interaction history, and logs), with identical user-typed inputs, coupled randomness, the same schedule, and a common horizon. Their untrusted content may differ arbitrarily. Then
𝖣𝖳 ⁡ ( ρ 1 ) = 𝖣𝖳 ⁡ ( ρ 2 ) ⟹ 𝖡𝖾𝗁 P ​ ( ρ 1 ) = 𝖡𝖾𝗁 P ​ ( ρ 2 ) . \mathsf{DT}(\rho_{1})=\mathsf{DT}(\rho_{2})\quad\Longrightarrow\quad\mathsf{Beh}_{P}(\rho_{1})=\mathsf{Beh}_{P}(\rho_{2}).
Here 𝖣𝖳 \mathsf{DT} is the complete display transcript, including previews, decision panes, and decisions; 𝖡𝖾𝗁 P \mathsf{Beh}_{P} is the sequence of P-LLM operations, tool invocations, and replies. Thus hidden untrusted content has no additional influence once the display transcript is fixed.
A never-endorsed, untrusted-derived value cannot be exfiltrated through a URL, search query, or file path without an accepting confirmation over that exact value at that exact tool in that call (Corollary D.4 ). This protection applies to information that has never been confirmed. Once a value has been confirmed for a particular tool, PerMIT allows the agent to recall it and reuse the exact value directly with that tool without repeating the confirmation. Likewise, an attacker cannot alter the P-LLM’s operations, tool invocations, or ungated sink flows without producing a corresponding difference in the complete user-facing display transcript (Corollary D.6 ). Within this threat model, every attempt to release untrusted content across the trust boundary is therefore reduced to a single auditable event: the confirmation decision.
As such, PerMIT isolates the risks posed by untrusted memory. Its safety guarantees now rest on
an explicit trust assumption: any value approved at the gate is treated as trusted. By mediating all
memory risk at this single decision point, the confirmation gate becomes a common verification interface
that can be operated by the human user, an LLM verifier, or both.
3.3 The Federated Tier
The federated tier extends the single-user confirmation mechanism to shared memory, allowing users to build on one another’s endorsements instead of independently reviewing every entry.
Because every confirmation is a signed and logged decision on exact content for an exact tool use, it serves two purposes: releasing the content for the confirming user and depositing an endorsement on the entry itself. For a shared entry, these endorsements accumulate across users, with each identity contributing at most one endorsement to a given retrieved memory entry. Once an entry collects at least N N fresh endorsements for a tool, it is promoted to the “community-confirmed" tier.
Subsequent users may then use the entry without repeating the confirmation process.
Because honest verifiers can make mistakes and adversaries may reject indiscriminately, treating every rejection as grounds for immediate deletion would create a denial-of-service attack surface against benign knowledge in the shared memory. PerMIT instead handles disputed entries through a demand-paced panel. A qualifying rejection does not immediately delete an entry. Instead, it freezes promotion, visibly flags the entry, and routes the dispute to an auditable panel process. The entry remains retrievable and may still be used after personal confirmation. The first k k eligible verdicts cast by fresh subsequent demanders form the panel. If rejecting verdicts reach the rejection threshold m rej m_{\mathrm{rej}} , the entry is evicted from the shared candidate tier. If accepting verdicts reach the acceptance threshold m m , the entry is vindicated. Together with rejection-rate limits and rejecter accountability, this mechanism tolerates isolated honest mistakes while containing adversaries that issue systematic false rejections.
This construction makes the safety–utility trade-off quantitatively explicit. PerMIT bounds poison-promotion and wrongful-eviction risks, and models confirmation labor, as functions of verifier accuracy, adversarial capacity, the endorsement quorum, and the panel configuration. A poisoned entry can reach the community-confirmed tier through only two routes: the ordinary endorsement path without a qualifying rejection, or a path that resumes after panel vindication. Existing defenses do not provide consistent protection. Every baseline has at least one model–backend configuration with nonzero ASR. Capability-restricting defenses reduce exposure by disabling functionality required by benign tasks, frequently collapsing HM, whereas prompt-level and retrieval-time defenses preserve more functionality but continue to admit attacks in other settings.
PerMIT structurally closes the ungated memory-injection path. Under the formal model, untrusted memory cannot reach the protected agent as readable content without endorsement (Lemma D.1 ), confining memory-mediated attacks to an auditable interface (Corollary D.6 ). Our live probes test this interface after poison is already stored. OpenGate records 0–10% ASR across the four backbones: low attack success persists even without a rejecting confirmation policy. Self-verification and both Qwen verifiers record zero observed ASR while preserving useful memory capabilities (Table 1 ).
Endorsement preserves useful capabilities with verifier-dependent cost. OracleGate models correct user decisions, providing an idealized reference for capability retained under PerMIT’s confirmation rules. With the RLM reader and interface held fixed, comparisons between OracleGate and the three LLM-verifier configurations show how replacing idealized user decisions with LLM judgments affects task performance. Appendix A.5 reports the FPR of different verifiers.

6 Conclusion and Future Directions
PerMIT contributes a finite memory interface with machine-checked integrity guarantees, a federated protocol that turns exact-content endorsements into reusable trust, and an autonomous workflow for constructing useful shared knowledge. Under explicit assumptions, the protocol bounds poison promotion and wrongful eviction while reducing repeated verification. The agent communities promoted no direct injection payloads and improved held-out task performance through PerMIT.
These results motivate three future directions. First, provenance and endorsement do not ensure usefulness: shared memory may contain redundant, inaccurate, or hallucinated knowledge, motivating quality-aware gates and active memory management. Second, estimating rare promotion events required five billion simulated attempts and over 50 hours of computation; more efficient calibration with live verifiers and users would strengthen deployment evidence. Third, adaptive payload search against live verifiers remains an open empirical question. Our simulations test the protocol’s conditional safety boundaries through adaptive protocol attacks under controlled reviewer responses; they do not replace adaptive payload search against live verifiers. Human or agent memory managers could combine memories and review their joint meaning and intended use, then seek fresh user endorsements of the combined content before it becomes trusted. Testing this workflow against adaptive endorsement and delayed-combination attacks is a future direction. Matched component controls and measured human review effort would further clarify deployment trade-offs.

Appendix S9 Machine-Checked Verification in Lean 4
We mechanize the single-user core of PerMIT in Lean 4 (toolchain leanprover/lean4:v4.31.0 ; Mathlib v4.31.0 , revision fabf563a ). The development defines an executable interpreter for the memory interface and proves Theorems S3.21 and S3.25 over it for arbitrary Protected-LLM strategies, retrievers, attackers, and horizons, within the deployment, input, and starting-state conditions stated below. Building the development is the verification: Lean’s kernel checks every theorem, and every executable scenario is a build-time assertion.
Scope.
The mechanized surface is the single-user interface without run-level batched iteration: tool invocation, 𝗐𝗋𝗂𝗍𝖾 P \mathsf{write}_{P} , 𝗋𝖾𝖼𝖺𝗅𝗅 \mathsf{recall} , 𝖿𝗂𝗅𝗅 \mathsf{fill} , 𝖼𝗋𝗒𝗌𝗍𝖺𝗅𝗅𝗂𝗓𝖾 \mathsf{crystallize} , 𝖼𝗈𝗇𝖿𝗂𝗋𝗆 \mathsf{confirm} (tool and reasoning targets), 𝗋𝖾𝗍𝗋𝗂𝖾𝗏𝖾 \mathsf{retrieve} , 𝖽𝗂𝗌𝗉𝗅𝖺𝗒 \mathsf{display} , 𝖾𝗏𝗂𝖼𝗍 \mathsf{evict} , and the typed and paste channels. The batch-confirmation surface of Rule R9 is mechanized as a standalone layer. Paper arguments alone cover the integration of 𝗆𝖺𝗉 \mathsf{map} into the run-level interpreter, durable endorsement on aborted invocations (delta 6 ), arbitrary mid-run matched pairs, the index-oracle reduction (delta 2 ), Options O1 – O2 beyond the gate level and Option O3 , and the federated tier with every probabilistic and budget result.

Four modeling choices carry the proofs.
•
Replies. The inductive type Reply (acknowledgment, handle, failure, decision, bytes) is the reply grammar of Rule R10 ; no other reply can be constructed. Bytes are returned only by 𝗋𝖾𝖼𝖺𝗅𝗅 \mathsf{recall} of a non- 𝖴 \mathsf{U} block and by trusted retrieval.
•
Two-sorted identifiers. Endorsed-sort identifiers ( BlockId.e ) are allocated only by coupled events: typed input, the agent’s writes, and accepted confirmations. Untrusted-sort identifiers ( BlockId.u ) are allocated by attacker-dependent events: the initial untrusted store, paste, tool-output capture, and crystallization. Every endorsement writes a fresh copy at the next endorsed-sort identifier.
•
Views. The Protected-LLM view Obs is computed from the endorsed store alone ( memEOf ), with the decision history, typed input, and handle count; the retriever likewise receives only the endorsed store.
•
Actors. The Protected LLM is an arbitrary function of its emitted operations, reply stream, view, and coins ( PStrat ). The attacker supplies the initial untrusted store, every tool output (count and content), every paste event, and the Quarantined Reader’s candidates and summaries. The user supplies the typed stream and the decision and selection at each confirmation.
Checked statements.
Table S5 gives the correspondence. Action Integrity is a projection of an inductive invariant, Inv , established initially and preserved by every transition. It is proved from the empty endorsed store and from any state satisfying Inv . A precedence corollary places each endorsing confirmation in the transcript that exists when the sink event is recorded.
Reasoning Integrity is a lockstep simulation over MatchW , which equates everything the Protected LLM can observe and everything the transcript records, while leaving untrusted stores and hidden handle resolutions free. It is proved from empty endorsed stores and from any shared endorsed seed with independently chosen untrusted stores. Its conclusions exceed what Theorem S3.25 requires: equal transcripts force equal raw sink logs, operation sequences, reply streams, and final views.
Proposition S3.27 is witnessed by computation. A taint-gating baseline, with data taint carried inside the model, yields equal (empty) transcripts but different ungated sink projections. PerMIT’s interpreter under the analogous strategy is attack-invariant.

Trusted base.
Lean’s kernel checks every theorem, and the build fails on any failed proof or false #guard . An omitted proof ( sorry ) produces only a warning, so completeness rests on the #print axioms report, reproduced verbatim in the artifact’s README from a clean build. It shows that the top-level theorems, and hence every lemma they use, depend only on propext and Quot.sound , and none on sorryAx .
The #guard scenarios additionally trust Lean’s evaluator. The correspondence between the mechanized model and the paper’s semantics is not machine-checked; Table S5 and the deltas below argue it.
Modeling deltas.
None is silent. Deltas 1 and 3 strengthen the checked statements.
(1)
Reader. The Quarantined Reader is folded into the attacker, which chooses the reader’s candidates and summaries directly.
(2)
Index oracles. User decisions and selections, and attacker outputs, are functions of event ordinals. Any run of a reactive user or attacker is the run of the oracle equal to its realized sequence. In Theorem S3.25 , both runs share the user oracle, and transcript equality pins every decision a display-reactive user makes (Supplement, Proposition S3.29 ; a paper argument).
(3)
Channels. Compared runs share only the slot skeleton and the typed stream; each attacker chooses paste presence and content independently.
(4)
Starting states. Theorem S3.21 is proved from the empty endorsed store and from any state satisfying Inv . Theorem S3.25 is proved from empty or shared endorsed seeds, the canonical matched class of Definition S3.5 . Arbitrary mid-run matched pairs are covered by the paper proof.
(5)
Collection handles. Without run-level 𝗆𝖺𝗉 \mathsf{map} , a handle to a multi-element capture is confirmed at a direct call by selecting one displayed element, so at most one displayed value flows per accepting decision.
(6)
Aborted invocations.
The mechanized interpreter writes endorsed copies only when an invocation executes. Rule R2 also writes durable copies for the accepted positions of an aborted invocation; that case is covered by the paper proof only.
(7)
Decision history.
The mechanized history also records the selection index and marks null-resolution aborts, so the mechanized view extends the paper’s h h . The operation semantics do not inspect these extra fields; both are transcript-recorded and therefore agree in the matched executions used by the proof.
(8)
Selections. An out-of-range selection clamps to the first candidate; the flowed bytes remain the displayed bytes.
(9)
Representation. One typed event is one 𝖳 \mathsf{T} -block; bytes are lists of naturals; provenance marks are subsumed by labels and ghost logs. Inv checks endorsement against the transcript, without the sanitized-history record of Definition S3.3 (ii).
(10)
Outside the interpreter. Options O1 – O2 are checked at the gate level only. The covered-gate and reasoning-coverage clauses of Rule R13 (i) are federated accounting conventions, not transitions.
Specification corrections.
Mechanization corrected the specification in three places, each adopted in the paper.
•
Endorsement must write a fresh copy at an operation-determined identifier. Relabeling the untrusted source in place would expose an attacker-dependent identifier in the endorsed store and break the matched-pair invariant; this is why identifiers are two-sorted.
•
Channel events must be acknowledged to the channel, not to the Protected LLM. Otherwise an uncoupled paste would emit a visible acknowledgment, and Theorem S3.25 would fail.
•
The fast-path case analysis of Lemma S3.13 is disjunctive: typed and endorsed matches may co-occur, and processArgs_spec proves exhaustiveness without exclusivity.
