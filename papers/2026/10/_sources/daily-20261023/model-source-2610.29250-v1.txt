 Let Agents Design How They Search:
 Automatic Interface Optimization for Agentic Search

  Abstract 
    
 Agentic search depends on the interface through which a language-model agent accesses and explores a corpus.
Existing interface designs are fixed by hand and applied unchanged to every corpus, although effective designs may depend on the corpus.
We introduce SearchWeaver, a framework for automatic search interface optimization guided by downstream search performance.
A proposer uses execution trajectories and task rewards to jointly revise corpus artifacts, executable tools, and usage instructions.
This process optimizes what information is prepared in advance, which operations tools perform, and which decisions remain with the search agent.
With GPT-5.4-nano, the optimized interfaces improve answer accuracy from 71.6% to 78.4% on BrowseComp-Plus and average nDCG@10 from 45.7 to 55.0 across four BRIGHT subsets over Direct Corpus Interaction.
These findings highlight the value of jointly optimizing corpus artifacts, executable tools, and usage instructions to develop effective search interfaces.

  1  Introduction 

 
 Language-model agents search for evidence by issuing queries, inspecting retrieved information, and deciding what to explore next  ( Yao et al., 2023 ;  Asai et al., 2024 ) .
These decisions depend on the search interface provided to the agent: how documents are organized, which operations are available, and what instructions guide their use.
The interface determines what evidence the agent can access at each step and how it can act on that evidence.
Designing this interface is therefore central to both the quality and the cost of agentic search. 
 
 
 Existing approaches provide different interfaces for accessing a corpus.
Retrieval-augmented generation supplies passages selected by a retriever  ( Lewis et al., 2020 ) , while Direct Corpus Interaction (DCI) lets agents search and read raw documents with general-purpose terminal tools  ( Li et al., 2026 ) .
More recent approaches combine retrieval with direct exploration: DR-DCI dynamically expands a local workspace with retrieved documents, and RISE constructs a bounded interaction space for the agent  ( Lu et al., 2026 ;  Zhuang et al., 2026 ) .
Each approach makes design choices about which information to expose and which operations the agent can perform.
However, these approaches generally specify an interface design in advance and apply it unchanged across corpora, despite the fact that the most effective design depends on corpus size and structure, the types of queries, and the language model used for search. 
 
 
 This raises the question of how to design a search interface for a given corpus and language-model agent.
The goal is to determine what corpus information to prepare, which search operations to expose, and how to guide their use so as to improve the agent’s downstream search performance.
An effective search interface must align the information and operations it provides with how the agent uses them.
For example, a title index can help locate documents about a candidate entity, but its usefulness depends on tools that expose those documents and instructions that guide the agent to inspect them and verify the query’s clues.
These components therefore need to be designed together. 
 
 
 To tackle this, we propose SearchWeaver, a framework that iteratively optimizes search interfaces using feedback from agent search trajectories and task rewards.
Specifically, a proposer analyzes failures and bottlenecks in these trajectories to jointly revise which corpus artifacts to prepare, how to structure executable tools, and how to guide the agent in using them.
Each revised interface is evaluated on search tasks, producing new trajectories and rewards that guide subsequent revisions.
In this way, optimization shapes the division of work between corpus preparation, tool execution, and agent reasoning. 
 
 
 Experiments with GPT-5.4-nano show that the optimized interfaces improve answer accuracy from 71.6% to 78.4% on BrowseComp-Plus  ( Chen et al., 2026b )  and average nDCG@10 from 45.7 to 55.0 across four BRIGHT  ( Su et al., 2025 )  subsets over plain DCI, while reducing mean tool execution time by 42% on BRIGHT.
The discovered interfaces use distinct strategies across corpora, including restricting retrieval to a topic directory and combining agent judgments with retrieval rankings.
The BRIGHT interfaces also improve search performance and reduce tool execution time when reused by Gemini 3.5 Flash-Lite without re-optimization.
These findings support treating the search interface as a reusable corpus resource that can be optimized through agent execution. 
 
 
 
  2  Method 

 
  2.1  Problem Definition 

 
 Given a fixed corpus    C  C    and a language-model agent     f  θ   f_{\theta}   , a search interface comprises the corpus artifacts, executable tools, and usage instructions through which the agent searches for evidence and produces task outputs.
It determines which operations are available, what information they return, and how the agent is guided to use them.
The interface can thus change the agent’s actions and outcomes even when the model and corpus remain the same.

 where    R  R    measures task success (answer accuracy or nDCG@10 in our experiments) and the model parameters    θ  \theta    remain fixed.
A single interface is reused across queries, while the agent chooses its actions in response to each query and the evidence it observes.
The optimization therefore seeks a reusable way of organizing and guiding search across queries. 
 
 
 
  2.2  SearchWeaver: Automatic Search Interface Optimization 

 
 Search Interface Design. 

 
 Starting from DCI, in which an agent explores raw documents with terminal tools  ( Li et al., 2026 ) , SearchWeaver seeks the information and operations that best extend this interface for each corpus.
SearchWeaver represents each candidate interface as corpus artifacts, executable tools, and usage instructions; a candidate may also replace the agent’s base system prompt and its context-management policy.
Artifacts organize corpus information before query execution for reuse across queries; tools expose operations over these artifacts and raw documents; instructions guide the agent in using those operations.
Tools can use the supplied BM25  ( Robertson and Zaragoza, 2009 )  and dense  ( Karpukhin et al., 2020 )  retrieval resources, restrict exploration to a subset of the corpus, or combine retrieval rankings with the agent’s document judgments.
Returned documents retain their raw corpus paths for source inspection.
These components are designed jointly: a tool that uses agent judgments also requires instructions specifying when to inspect documents and how to pass those judgments to the tool.
The search space thus couples corpus preparation with query-time interaction, allowing what is prepared to change with how the agent accesses and uses it. 
 
 
 
 Trajectory-Guided Revision. 

 
 To explore this design space, we use a coding-agent proposal–evaluation loop inspired by Meta-Harness  ( Lee et al., 2026 ) .
Whereas prompt optimizers revise text  ( Khattab et al., 2024 ;  Agrawal et al., 2026 )  and Meta-Harness revises a model’s harness code, SearchWeaver revises the interface the agent is given: corpus artifacts, executable tools, and usage instructions.
A proposer inspects the corpus and previous candidates, writes a new interface, and receives feedback from the search agent’s execution with that interface.
This feedback includes per-query rewards and full execution trajectories containing commands, tool outputs, and final responses.
Rewards indicate which queries a candidate handles well or poorly; trajectories show how the agent uses the interface and where its search fails.
Gold document identifiers for optimization queries provide additional diagnostic feedback.
The proposer uses this evidence to revise artifacts, tools, and instructions, changing what information is exposed, which operations are implemented in tools, and which judgments are requested from the agent. 
 
 
 
 Evaluation and Selection. 

 
 Each candidate’s artifacts and tools are prepared over the corpus before the fixed search agent runs on    𝒬  \mathcal{Q}   .
We record the resulting trajectories and per-query rewards and make them available to the proposer for subsequent revisions.
Every evaluated candidate contributes this feedback, regardless of whether it improves the current best score.
After a fixed number of iterations, we select the candidate with the highest mean reward on    𝒬  \mathcal{Q}    and evaluate it on test queries, which never enter proposer feedback.
We provide the algorithm for SearchWeaver in Appendix   A  .

  3  Experiments 

 
  3.1  Experimental Setup 

 
 Benchmarks and Metrics. 

 
 We evaluate SearchWeaver on BrowseComp-Plus (BCP;   Chen et al., 2026b  ) for question answering and BRIGHT  ( Su et al., 2025 )  for reasoning-intensive retrieval.
On BCP, the agent searches a fixed web corpus to produce a short answer, and we measure answer accuracy judged by GPT-4.1  ( OpenAI, 2025 ) .
We use 30 queries for interface optimization and 800 for testing.
On BRIGHT, the agent returns a ranked list of documents, which we evaluate using nDCG@10  ( Järvelin and Kekäläinen, 2002 ) .
We use four subsets (Biology, Earth Science, Economics, and Robotics) with 213 optimization and 210 test queries in total. 
 
   
  Figure 1:  The optimized BrowseComp-Plus interface and selected agent interactions on a test query. 
 
 
 
 Baselines. 

 
 We compare against  DCI   ( Li et al., 2026 ) , which searches raw documents using a shell and file reader.
 Agentic Search (Dense)  and  Agentic Search (BM25)  iteratively reformulate queries for a search tool returning five document snippets per call  ( Chen et al., 2026b ) .
The dense variant uses Qwen3-Embedding-8B  ( Zhang et al., 2025 )  on BCP and ReasonEmbed-Qwen3-4B  ( Chen et al., 2026a )  on BRIGHT.
 RISE   ( Zhuang et al., 2026 )  retrieves documents into a restricted workspace for shell-based exploration and augments documents with model-generated tables of contents and section anchors.
 DR-DCI   ( Lu et al., 2026 )  lets the agent pull dense-retrieved documents into an initially empty workspace and explore them with shell commands.
 SearchWeaver  uses execution feedback to automatically optimize a DCI agent’s corpus artifacts, search tools, and usage instructions. 
 
 
 
 Implementation Details. 

 
 Our search agent is implemented using Pi  ( Zechner, 2026 )  with GPT-5.4-nano  ( OpenAI, 2026 ) , following DCI  ( Li et al., 2026 ) .
The proposer uses Claude Code  ( Anthropic, 2025 )  with Claude Opus 5.5  ( Anthropic, 2026 ) .
We optimize an interface for each corpus, starting from the default DCI interface and evaluating one candidate interface per iteration for ten iterations.
We provide the proposer with BM25 and Qwen3-Embedding-4B retrieval on BCP, and BM25 and the released ReasonEmbed-Qwen3-8B rankings  ( Chen et al., 2026a )  on BRIGHT.
See Appendix   B   for more implementation details. 
 
   
  Figure 2:  SearchWeaver is Pareto-optimal among the evaluated methods on both benchmarks. 
 
 
 
 
  3.2  Main Results and Analyses 

 
 Search Performance. 

 
 Table   1   shows that SearchWeaver outperforms all evaluated baselines on both BCP and BRIGHT, including each of the four BRIGHT subsets.
Compared with DCI, it improves BCP accuracy from 71.6% to 78.4% and average BRIGHT nDCG@10 from 45.7 to 55.0.
The relative performance of existing approaches varies across corpora: DR-DCI improves over DCI on BCP but falls below it on BRIGHT.
In contrast, SearchWeaver improves over DCI on both benchmarks and all four BRIGHT subsets, supporting the value of optimizing interfaces for each corpus. 
 
 
 
 Discovered Interfaces. 

 
 We examine the interfaces discovered by optimization for each corpus.
These interfaces differ in how they combine retrieval, source inspection, and agent judgments.
On BCP, as shown in Figure   1  , the generated title index maps candidate names to raw documents, and the tools support hybrid candidate retrieval and targeted evidence lookup.
The instructions guide the agent to use these operations to check each clue against source evidence.
The agent checks the clues about King Diamond against source lines and then confirms the formation year of Mercyful Fate from its own page.
We provide the full trajectory in Appendix   F  .
On BRIGHT, the interfaces target document ranking: Biology restricts retrieval to a topic directory, Earth Science introduces retrieval only when constructing the final ranking, and Economics and Robotics incorporate agent judgments through document ordering and relevance grades, respectively (Appendix   G  ). 
 
 
 
 Tool Execution Time. 

 
 Figure   2   shows that SearchWeaver achieves these performance gains while using less tool execution time than DCI.
Mean tool execution time per query, which excludes model inference, decreases from 42.4 s to 32.9 s on BCP and from 63.2 s to 36.6 s on BRIGHT, reductions of 22% and 42%, respectively.
The reduction holds across all four BRIGHT subsets (Appendix   D  ).
These savings are consistent with the more targeted corpus access provided by the optimized interfaces.
For example, the Biology interface restricts retrieval to a topic directory, while the BCP interface uses a title index to locate candidate documents and passage retrieval to check specific clues.

 Does generating artifacts and tools improve search? 

 
 Table   2   first compares SearchWeaver with Prompt Optimization, which uses the same optimization loop as SearchWeaver but restricts candidates to instructions, excluding artifacts, tools, and retrieval resources.
Prompt Optimization improves over DCI on both benchmarks, but SearchWeaver achieves higher BCP accuracy and average BRIGHT nDCG@10, supporting the value of the broader interface design space.
We also evaluate the optimized interface after removing the generated artifacts and tools and the instructions for using them, without further optimization.
This removal reduces performance on both benchmarks, indicating that the generated artifacts and tools, together with their usage instructions, contribute to the gains. 
 
 
 
 Do the optimized interfaces transfer across language models? 

 
 We next test whether the discovered interfaces remain useful with another language model.
Table   3   evaluates Gemini 3.5 Flash-Lite  ( Google DeepMind, 2026 )  using the interfaces optimized with GPT-5.4-nano, without re-optimization.
Compared with DCI, the transferred interfaces improve BCP accuracy and average BRIGHT nDCG@10 while reducing mean tool execution time on BRIGHT.
The performance gains hold across all four BRIGHT subsets (Appendix   E  ), suggesting that the optimized interfaces remain useful beyond the model used for optimization. 
  
 
 
 
 
 
 Limitations 

 
 Our experiments evaluate interfaces optimized for fixed corpora.
As documents are added or revised, corpus artifacts and the tools that use them may require updates.
We do not study when these updates become necessary or whether they can be performed incrementally without repeating the full optimization process.
Extending SearchWeaver to evolving corpora would therefore require mechanisms for maintaining corpus artifacts and assessing whether previously optimized interfaces remain effective.

  Appendix B  Additional Implementation Details 

 
 Data and Evaluation. 

 
 On both BCP and BRIGHT, we use the file-system corpus released with DCI-Agent-Lite  ( Li et al., 2026 ) , where each document is stored as a text file.
For BCP, we use 30 queries for interface optimization and 800 for testing.
For BRIGHT, we use 52, 58, 52, and 51 optimization queries and 51, 58, 51, and 50 test queries from Biology, Earth Science, Economics, and Robotics, respectively, totaling 213 optimization and 210 test queries. 
 
 
 
 Agent Runtime. 

 
 On both BCP and BRIGHT, the search agent runs GPT-5.4-nano with high reasoning effort and has no web access.
Each query is limited to 300 turns and 30 minutes. 
 
 
 
 Interface Optimization. 

 
 The proposer runs at high reasoning effort and can inspect the corpus, execute shell commands, and call the supplied retrieval resources.
Candidate files must not contain optimization questions, query identifiers, or gold labels; candidates that do are rejected before evaluation.
The context-management policy that a candidate may replace decides how earlier tool outputs are truncated or cleared.
The files containing test queries and labels are made unreadable during optimization. 
 
 
 
 Retrieval Resources. 

 
 On BCP, SearchWeaver uses the official BM25 and Qwen3-Embedding-4B indexes  ( Chen et al., 2026b )  and encodes dense queries at search time.
On BRIGHT, BM25 uses the official configuration  ( Su et al., 2025 )  and accepts arbitrary queries, whereas the dense resource returns only the released ranking for each original question and does not support new dense queries. 
 
 
 
 Baseline Configurations. 

 
  Agentic Search (Dense)  uses the official BCP  ( Chen et al., 2026b )  dense-search agent.
On BCP, it also has a tool that returns a full document, and it differs from SearchWeaver in both the embedding model and the document index: Agentic Search (Dense) uses Qwen3-Embedding-8B and its corresponding document index, whereas SearchWeaver uses Qwen3-Embedding-4B and its corresponding document index.
On BRIGHT, Agentic Search (Dense) has the search tool only and encodes each query at search time against Pyserini’s  ( Lin et al., 2021 )  prebuilt ReasonEmbed-Qwen3-4B document embeddings.
 Agentic Search (BM25)  uses the official BCP  ( Chen et al., 2026b )  function-calling loop, whose only tool returns BM25 snippets; it has no shell or file reader.
On BRIGHT, it uses the same BM25 retriever as SearchWeaver.
 RISE  uses the released harness  ( Zhuang et al., 2026 )  with its released settings.
It adds BM25 results for each subquery to a workspace, restricts shell-based exploration to that workspace, and uses documents augmented in advance by GPT-5.4-nano with tables of contents and section anchors.
 DR-DCI  uses its released harness  ( Lu et al., 2026 )  with the configuration of its main BCP result.
On BRIGHT, its pull tool uses the repository’s BRIGHT retriever, BGE-large-en-v1.5  ( Xiao et al., 2024 ) , over Pyserini’s prebuilt indexes. 
 
 
 
 
  Appendix C  Additional Related Work 

 
 Agentic Search. 

 
 Retrieval-augmented generation grounds language models in external documents through sparse or dense retrieval  ( Lewis et al., 2020 ;  Robertson and Zaragoza, 2009 ;  Karpukhin et al., 2020 ) .
Agentic approaches make retrieval part of an iterative reasoning process.
Search-R1 learns to interleave reasoning with search-engine calls through reinforcement learning  ( Jin et al., 2025 ) , while other work explores lexical search, query expansion, and corpus-aware query construction  ( Subramanian et al., 2025 ;  Hsu et al., 2026b ;  Yang et al., 2026 ) .
Further approaches provide finer control through retrieval actions and logical queries  ( Hui et al., 2026 ;  Zeng et al., 2026 ) .
DCI and GrepSeek extend this control to direct corpus exploration with terminal commands and raw-file reads, with GrepSeek training agents for this interaction mode  ( Li et al., 2026 ;  Salemi et al., 2026 ) .
Our work optimizes the interface through which agents combine direct exploration with retrieval tools. 
 
 
 
 Search Interface Design. 

 
 The tools, document organization, and presentation of search results influence how agents discover and use evidence  ( Sen et al., 2026 ;  Cao et al., 2026 ) .
RISE constructs bounded interaction spaces, while DR-DCI uses retrieval to dynamically expand a local workspace  ( Zhuang et al., 2026 ;  Lu et al., 2026 ) .
Beyond selecting which documents to expose, other work organizes information into navigable memory hierarchies, source-derived wikis, and environment-side records of requirements and evidence  ( Hsu et al., 2026a ;  Karpathy, 2026 ;  Baek et al., 2026 ) .
We optimize corpus-specific combinations of artifacts, tools, and usage instructions using feedback from search trajectories and task rewards. 
 
 
 
 Automatic Optimization of Agent Systems. 

 
 Automatic optimization uses task feedback to improve the components surrounding language models, including prompts and multi-stage pipelines  ( Khattab et al., 2024 ;  Yuksekgonul et al., 2025 ) .
Recent methods use natural-language feedback and reflection on execution traces to guide revisions, or meta-learning to produce system prompts that generalize across tasks  ( Yuksekgonul et al., 2025 ;  Agrawal et al., 2026 ;  Choi et al., 2025 ) .
This direction also extends to executable harness code, with coding agents proposing changes based on earlier candidates, scores, and execution traces  ( Lee et al., 2026 ) .
We apply feedback-driven optimization to search interfaces, jointly developing reusable corpus artifacts, executable search tools, and usage instructions for downstream agentic search.

  Appendix G  Optimized Interfaces on BRIGHT 

 
 Figures   7  –  7   show the interface SearchWeaver selected for each BRIGHT subset: panel (a) summarizes its tools, how its final tool builds the submitted list, and its instructions, and panel (b) traces one test question from the agent’s tool calls to the submitted list, with gold documents highlighted. 
 
 
 The four interfaces share one structure.
The agent still searches and reads raw files with the shell, and a final tool builds the submitted list by combining the agent’s judgments with the released dense ranking; Earth Science and Robotics also mix into that list BM25 scores computed from text the agent has read or written.
The interfaces differ in where retrieval enters and how much weight the agent’s judgments receive.
Biology confines the search to the question’s topic directory and fuses the documents the agent labels with the dense ranking inside that directory.
Earth Science searches as plain DCI does and uses retrieval only in the final tool.
Economics and Robotics start from dense candidates: Economics keeps the agent’s order and fills the remaining places from the dense ranking, while Robotics ranks the documents the agent grades as answering the question first. 
 
 
 Removing the generated artifacts and tools hurts most on Biology and Earth Science, where SearchWeaver gains most.
Biology and Earth Science improve over DCI by 13.0 and 13.1 points and lose 9.7 and 11.5 points without the artifacts and tools (Table   2  ).
Economics improves by 7.0 points and does not drop without them (38.8 vs. 38.3), and Prompt Optimization scores highest there (41.8).
