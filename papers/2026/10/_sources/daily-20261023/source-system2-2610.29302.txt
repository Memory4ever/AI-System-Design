Abstract
Language models are being explored as the interface through which space robots interpret operator commands and select among verified skills. Running them onboard calls for low-bit compression, and flight use adds requirements that generic post-training quantization leaves implicit: a fixed memory budget and storage format, a static artifact under configuration control, and behavior close to the full-precision model validated on the ground. We treat compression as a ground-segment step and study QSelect, which composes one static low-bit model from compatible AWQ, GPTQ, and AutoRound checkpoints by assigning each linear module to one quantizer family and scoring every substitution at the final next-token distribution. The default fidelity mode needs no labels or tuned thresholds and accepts a substitution only when the forward KL divergence from the BF16 reference decreases; an optional target-adapted mode adds answer likelihood on a small labeled set. On DeepSeek-R1-Distill-Qwen-7B, Llama-3.1-8B, and Llama-3.2-3B at 3 and 4 bits, composed models reach lower mean held-out perplexity than every single-family model in all six settings, and the fidelity mode lowers perplexity and KL further. In a matched scaffold, final-output scoring gives lower held-out KL than representation-similarity scoring in all 12 paired runs. With labels from training or development splits of the evaluated task families, the target-adapted mode raises 3-bit pooled accuracy on the two Llama models by 4.3 and 4.5 points over the best single-family model. At 3 bits, unquantized embedding and output layers make up 43–46% of the packed artifact. All evaluations use general-domain benchmarks on a ground GPU; space-domain tasks and flight hardware are left to future work.

I Introduction
Space robots are expected to work with less direct supervision. On-orbit servicing combines approach, capture, and manipulation of client spacecraft, and free-flying robots such as Astrobee serve as test beds for autonomy inside the International Space Station (ISS) [ 1 ] . Language and vision–language models offer a natural interface for such tasks: they can map an operator’s request to a sequence of pre-verified skills [ 2 ] or, in end-to-end form, to robot actions [ 3 , 4 ] . Space-specific agent frameworks now apply this interface to on-orbit servicing [ 5 ] . These systems are usually evaluated with large models on terrestrial computers; SpaceMind, for example, uses Qwen3-VL-235B-A22B throughout [ 5 ] , a model whose weights alone would far exceed the memory of current flight computers.
Running the model onboard removes the dependence on communication windows, round-trip delays, and limited link bandwidth, but onboard compute is scarce [ 6 ] . Perseverance’s primary computer, for example, is a radiation-hardened RAD750 running at up to 200 MHz with 256 MB of DRAM [ 7 ] ; its global localization instead runs on a commercial Snapdragon 801 from the Ingenuity helicopter base station [ 8 ] . Language models are now reaching orbit. An AI assistant that combines ground and onboard models was delivered to China’s space station in July 2025 [ 9 ] , and ASTREA ran a 1.54-billion-parameter Qwen2.5 model quantized to 4 bits on a flight-qualified, CPU-only system-on-chip in an external ISS payload, with response times from about 40 s to over 8 min [ 10 ] . For onboard language models, compression is therefore a prerequisite rather than an optimization.
For flight use, the relevant question is not only how small a model can become but also what the compressed model must preserve. We identify three properties. First, the artifact must fit a fixed memory budget and use a storage format that the onboard runtime supports. Second, it must be a static object that can be versioned, verified, and rolled back like other flight software. Current machine-learning guidance for space engineering does not yet cover large language models [ 11 ] ; until it does, the preparation process has to make these properties explicit. Third, its behavior must stay close to that of the full-precision reference that was validated on the ground. The third property suggests measuring compression error where the validated behavior is defined: at the model’s output distribution.
Standard post-training quantization (PTQ) for large language models (LLMs) applies one quantizer family throughout a model. GPTQ uses approximate second-order error compensation [ 12 ] , AWQ protects activation-salient channels by equivalent scaling [ 13 ] , and SignRound, implemented in AutoRound, optimizes rounding and clipping [ 14 ] . These families embody different error models, and CALM has shown that choosing a quantization algorithm per Transformer block can help [ 15 ] . CALM scores candidates by linear centered kernel alignment (CKA) between intermediate representations [ 16 ] . Representation similarity is a reasonable heuristic, but it is not the quantity that an acceptance test of the onboard model would examine.
We therefore treat compression as a ground-segment preparation step (Fig. 1 ) and study QSelect, which composes one static low-bit model from compatible homogeneous checkpoints. Each linear module is assigned to one quantizer family, and every candidate substitution is scored through the final next-token distribution of the partially assigned model. In its default fidelity mode (QSelect-KL), the procedure is label free and accepts a substitution only when the forward KL divergence from the BF16 reference strictly decreases; the rule has no tuned threshold. An optional target-adapted mode (QSelect-TA) adds a target-answer likelihood term for missions that can provide a small labeled set, with fixed margins that bound the KL increase allowed at each step. Scoring with the acceptance quantity itself, rather than a cheaper proxy, is affordable in this setting: a one-pass module-wise selection takes one to a few GPU-hours on the ground for the models studied, excluding candidate generation, is paid once per model release, and never changes the bit width or storage format of the result. The memory limits that make compression necessary also keep onboard models small, and the selection cost shrinks with the model.
Experiments on three open models from 3B to 8B parameters at 3 and 4 bits show four things. Composed models reach lower mean held-out perplexity than every single-family model in all six settings, and the fidelity mode lowers perplexity and KL further. Final-output scoring yields lower held-out KL than representation-similarity scoring in all 12 paired runs of a matched scaffold and lower KL than a local reconstruction criterion in all four tested settings. Module-wise decisions mainly lower 3-bit perplexity, at several times the ground time of layer-wise decisions, and extra passes add little. Packed artifacts are 63–70% smaller than BF16, as for any single-family model at the same bit width, and an analytic breakdown shows that unquantized embedding and output layers make up 43–46% of what remains at 3 bits. All experiments use general-domain language-modeling and reasoning benchmarks on a ground GPU; we do not evaluate space-domain tasks, flight hardware, or radiation effects.

II Background and Related Work
II-A Language Models in Space Robotics
Grounding language in executable skills [ 2 ] and vision–language–action models [ 3 , 4 ] have made language a practical interface to robot behavior. In space, SpaceMind organizes an on-orbit servicing agent around natural-language skill modules and tool calls and evaluates it in simulation and on a ground robot [ 5 ] . Space-LLaVA fine-tunes a 13B LLaVA checkpoint to adapt a vision–language model to extraterrestrial visual semantics [ 17 ] , and language-model agents have controlled simulated spacecraft in the Kerbal Space Program Differential Games challenge [ 18 ] . These studies establish the interface; they leave open how a model of useful size can be prepared for the computers that space robots carry.
II-B Onboard Computing and Flight Software Assurance
Radiation-hardened processors such as the GR740 support general flight software [ 19 ] , and NASA’s High-Performance Spaceflight Computing processor is intended to provide at least 100 times the computational capacity of current spaceflight computers [ 20 ] . Commercial or radiation-tolerant accelerators provide more throughput for bounded workloads, as with the Myriad 2 that ran a cloud-segmentation network on Φ \Phi -sat-1 [ 21 ] and the Versal XQR family [ 22 ] . Perseverance pairs its radiation-hardened primary computer with a commercial Snapdragon 801 for global localization and mitigates radiation effects in software [ 8 ] . ASTREA’s 4-bit language model ran on the IMAGIN-e edge-computing payload [ 10 , 23 ] ; at the other end of the range, a satellite carrying an NVIDIA H100 GPU has run the Gemma model in orbit [ 24 ] . The ECSS machine-learning handbook addresses the engineering and assurance of learned components, including safety-cage architectures, but does not yet cover large language models and anticipates updates for generative AI [ 11 ] . OPS-SAT, which ended in 2024, provided a reconfigurable payload computer for in-orbit software experiments while the bus monitored the payload and could take back control at any moment [ 25 ] ; we assume the same supervisory pattern for the onboard language model. These considerations motivate the requirements in Section III .
II-C Post-Training Quantization of LLMs
Weight-only PTQ methods include GPTQ’s second-order compensation [ 12 ] , AWQ’s activation-aware scaling [ 13 ] , AdaRound’s learned rounding [ 26 ] , and SignRound’s signed-gradient optimization [ 14 ] . SmoothQuant, OmniQuant, and QuaRot additionally transform or quantize activations [ 27 , 28 , 29 ] . Recent work explores flexible low-rank approximation, spectral decomposition, and global information-flow allocation [ 30 , 31 , 32 ] . Our setting begins after several compatible homogeneous pipelines have produced candidate checkpoints.
II-D Heterogeneous Assignment
HAQ and HAWQ allocate bit widths using hardware feedback or Hessian information [ 33 , 34 ] , and InfoQ uses a global information-flow signal for mixed-precision allocation [ 32 ] . CALM keeps the precision fixed and selects a quantization algorithm for each Transformer block with linear CKA [ 15 , 16 ] . CALM and QSelect both assemble a model sequentially, so later decisions are conditioned on earlier ones. They differ in where a candidate is scored—intermediate block representations for CALM, the final next-token distribution for QSelect—and in granularity: QSelect supports blocks, attention or feed-forward components, and individual linear modules. Our CALM baseline is an independent matched-pool reimplementation, not an official reproduction.
II-E Output-Aware Calibration and Modular Composition
Knowledge distillation transfers output-distribution information [ 35 ] , and output-adaptive calibration uses model-output distortion to guide PTQ [ 36 ] . AdaRound and BRECQ instead optimize weight-, layer-, or block-local reconstruction losses [ 26 , 37 ] . QSelect uses the final-output KL only for discrete assignment, not for training candidates. The construction is also related to model stitching [ 38 ] , although we combine compatible modules from quantized versions of the same checkpoint without learning a stitching layer.
III Ground-to-Orbit Model Preparation
III-A Deployment Workflow
Fig. 1 summarizes the setting. On the ground, a full-precision (BF16) reference model is validated for its mission role, for example interpreting operator commands and selecting among verified manipulation or inspection skills. Several PTQ pipelines that share a storage format then produce homogeneous low-bit checkpoints. QSelect composes one static model from their modules; the result is packed, recorded with its configuration, and compared with the reference by acceptance tests before it is preloaded before launch or uplinked as a software update. Onboard, the model runs at a supervisory rate inside the autonomy stack. Its outputs pass through the same checks and fallback logic as any other planner output, and conventional controllers keep authority over motion.

III-B Requirements
Table I lists five requirements and the corresponding design choices.
R1: fixed memory budget and supported format. The model must fit the memory left after flight software and buffers, and the onboard runtime must be able to execute its storage format. All candidates therefore share the bit width, group size, and symmetric packed integer format, so the footprint of the quantized layers is fixed before selection. AWQ modules additionally carry a static per-channel input scale. The composition introduces no new numerical format, although it may use family-specific module wrappers (Section IV-F ). Keeping one bit width also keeps one integer kernel and one memory layout to verify, whereas mixed-precision assignment [ 33 , 34 ] multiplies both; this is why we select among quantizer families rather than among bit widths.
R2: static artifact under configuration control. Each module keeps exactly one selected candidate. There is no runtime selector, routing, or ensemble, so the onboard network is fixed and can be characterized once on the ground. The assignment vector, with 196 or 224 entries for the models studied here, together with the candidate checkpoint and manifest hashes, identifies the artifact for versioning and rollback.
R3: behavioral fidelity to the validated reference. Ground validation establishes how the reference behaves on mission-relevant inputs. The compressed model should depart from that behavior as little as possible. We measure the departure by the forward KL divergence from the reference next-token distribution to the compressed model’s distribution, averaged over text positions; it is zero only when the two distributions agree at every evaluated position. Forward KL weights each position by the reference’s own probabilities, so it penalizes most the loss of outputs that the reference considers likely. At one position, the total-variation distance between the two distributions is the smallest probability, over couplings, that the two models sample different next tokens; by Pinsker’s and Jensen’s inequalities, an average KL of K K nats bounds its mean over positions by K / 2 \sqrt{K/2} . The bound holds on reference text rather than on the model’s own generations, so it motivates the score rather than guaranteeing free-running behavior. An acceptance test can apply the same quantity to held-out or mission text, alongside task tests, while selection optimizes it on separate calibration text; the remaining gap between selection and acceptance therefore lies in the data rather than in the criterion. For a validated system, a change that raises task accuracy but also raises KL is an unvalidated change in behavior, which is why answer supervision is optional (R4). This paper sets no numerical KL threshold; a mission would derive one from its own validation campaign.
R4: scarce mission labels. Labeled mission data are expensive and often unavailable when a model is prepared. The fidelity mode therefore uses only unlabeled text and the reference model. When a small labeled set exists, the target-adapted mode can use it, but it then departs from the reference on purpose, and acceptance tests must cover that departure.
R5: bounded, one-time ground compute. Selection runs on ground GPUs once per model release, whereas onboard resources are consumed throughout the mission. Spending GPU-hours on the ground is acceptable if it buys fidelity, but the cost should be predictable and adjustable. Decision granularity and the number of passes provide that control, and the cost shrinks with the model, which onboard memory keeps small (Section VI-C ).
III-C Problem Statement
Let F ref F_{\mathrm{ref}} be the validated BF16 reference and let H ( 1 ) , … , H ( R ) H^{(1)},\ldots,H^{(R)} be homogeneous low-bit checkpoints with the same bit width and format. The task is to choose one candidate family for every quantized linear module so that the composed model minimizes the fidelity score K K of Section IV-B , using only unlabeled text. Optionally, a bounded increase in K K may be traded for a lower target-answer loss T T . Because every candidate for a module has the same bit width and group size, the memory budget is fixed by construction. Exhaustive search is impractical: module-wise assignment of Llama-3.1-8B over three families has 3 224 3^{224} possibilities. QSelect therefore uses a greedy search whose cost grows linearly with the number of decision units and candidates.
IV QSelect
QSelect operates on a precomputed bank of matched-format module candidates. It scores temporary substitutions in the current partially assigned model, commits accepted updates according to a fixed search protocol, and exports the resulting static assignment.

IV-E Search Protocol
The main protocol starts from the homogeneous AutoRound assignment, scans decoder blocks from shallow to deep, and processes the query, key, value, output, gate, up, and down projections in that order. It performs one pass. Candidate evaluation is functional, so temporary insertions do not alter the committed assignment. Initialization, granularity, traversal order, and pass budget are protocol variables, and Section VI-D reports their effects.

Native export packs the selected modules after assignment and does not alter the selected families. The exported model is therefore statically composed of family-specific modules, with no dynamic selector or ensemble. The assignment vector, the candidate checkpoint hashes, and the calibration manifest hashes form the configuration record of the artifact.
V Experimental Setup
Scope. The experiments evaluate the ground segment of Fig. 1 . Our evaluation contains no space-domain data; general-domain language-modeling and reasoning benchmarks stand in for the reference behavior that a mission would validate. Each job runs on one NVIDIA A800-SXM4-80GB GPU.
Models and low-bit format. We use deepseek-ai/DeepSeek-R1-Distill-Qwen-7B [ 39 , 40 ] (DS-R1-Qwen-7B), meta-llama/Meta-Llama-3.1-8B [ 41 ] , and meta-llama/Llama-3.2-3B [ 42 ] . BF16 references are loaded without low-bit PTQ. W3A16 and W4A16 (W3 and W4) denote symmetric 3- or 4-bit weights, BF16 activations, no zero point, and input-channel groups of 128. We quantize the query, key, value, output, gate, up, and down projections; embeddings, normalization layers, and the output head remain BF16. Unless stated otherwise, results use dense effective fake-quantized weights; packed artifacts are examined in Section VII .
Candidate generation. The three families use the same replicate-specific C4 manifest [ 43 ] of 128 packed sequences of 2,048 tokens. They do not use matched compute or identical effective token budgets. GPTQ uses GPTQModel 7.1.0 with symmetric quantization, desc_act=false , true_sequential=true , and damping 0.05. AutoRound 0.13.0 uses the SignRound recipe of that release with 200 iterations, batch size one, gradient accumulation one, and packed_tensors ; unlisted options use that release’s defaults. Our matched-format AWQ implementation gathers at most 1,024 activation tokens per module, searches a 20-point scaling grid, and applies Eq. ( 2 ). These configurations are candidate generators in a shared output format, not claims about each method’s strongest published configuration.
Calibration banks and selector data. Replicates 17, 23, and 41 index candidate generation and the 64-sequence, 1,024-token C4 sample used for KL scoring. The labeled proxy and held-out evaluation manifests are fixed. For DS-R1-Qwen-7B, the proxy uses 128 GSM8K training, 128 MATH training, and 256 MMLU development examples; the Llama proxy additionally includes 128 ARC-Challenge training and 256 HellaSwag training examples. GPQA is never included. A shared-core control applies the DS proxy to Llama-3.1-8B.
CALM reimplementation. CALM-reimpl. follows sequential block-wise assembly and selects one family per block with biased linear CKA. It compares the BF16 and candidate outputs of mlp.down_proj , the pre-residual feed-forward contribution, over 64 C4 sequences of 1,024 tokens, accumulating global centered feature statistics in 1,024-token chunks. The candidate pool is AWQ/GPTQ/AutoRound rather than CALM’s original AWQ/GPTQ/SmoothQuant pool.
Intrinsic evaluation. Each replicate is evaluated on fixed manifests of 128 sequences of length 2,048 from C4, WikiText-2 [ 44 ] , and three local corpora denoted Code, Math, and Wiki. Tables report the arithmetic average of the five corpus-level perplexity (PPL) values and the corresponding maximum, together with corpus-averaged and maximum KL. We label these columns Avg. and Max-corpus because they are descriptive summaries rather than pooled language-modeling metrics.
Downstream evaluation. The suite contains GPQA Diamond (198) [ 45 ] , ARC-Challenge (1,172) [ 46 ] , GSM8K (1,319) [ 47 ] , HellaSwag (1,024) [ 48 ] , MATH-500 (500) [ 49 ] , and MMLU (14,042) [ 50 ] . The protocol is zero-shot, with no chat template or system prompt. Multiple-choice tasks are reformatted as letter-answer questions and scored by average answer-letter log probability, so these scores are not directly comparable with standard continuation-likelihood harness values. GSM8K and MATH-500 use greedy generation with at most 256 new tokens and normalized final-answer matching. Micro pools 18,255 examples and is dominated by MMLU; Macro is the unweighted mean of the six task accuracies. The Appendix gives further protocol details.
Modes evaluated. QSelect-KL is the default mode, but most protocol studies were run with QSelect-TA: the granularity, traversal-order, initialization, candidate-pool, pass-budget, and whole-model controls, the packed export, and the module-wise 7B/8B selection times all use the target-adapted mode. QSelect-KL was run with the main protocol in all six settings. For the four 7B/8B settings, its results are available as paired changes relative to QSelect-TA (Table III ), and its absolute values in Table II are derived from them ( † , without standard deviations); on Llama-3.2-3B they are measured directly. Because the fidelity mode evaluates a subset of the target-adapted mode’s forward passes (Section IV-F ), the target-adapted selection times bound those of the fidelity mode under the same protocol.

VI-B Why Score the Final Output?
Three comparisons isolate the choice of scoring signal. Held-out KL partly measures what a final-output selector optimizes, so we also report perplexity on the five held-out corpora and task accuracy, which the selectors in the first two comparisons do not optimize.
Representation similarity. Table IV replaces CKA with final-distribution KL inside the same sequential layer-wise scaffold, with the same candidate bank and token budget. The KL selector in this control is a guarded layer-wise variant that accepts a change only when it lowers KL by at least 0.1% (Eq. ( 8 )); it is not the threshold-free fidelity mode. The final-output score lowers held-out Avg. KL in each of the twelve paired calibration-bank runs (Table XI in the Appendix). PPL and task accuracy also improve on DS W3 and on both Llama settings, whereas DS W4 trades lower KL for slightly higher PPL and lower task means. Because selection and evaluation both use KL, this control supports a fidelity-oriented scoring choice within the scaffold rather than a universal superiority claim. The final-output score is not much more expensive at equal granularity: layer-wise selection takes 19.4–21.6 minutes with KL and 16.9–18.1 minutes with CKA (Table XI ).

Local reconstruction. The Local-MSE selector collects 8,192 stratified input tokens per module from the BF16 reference and unconditionally chooses the family with the lowest mean-squared error between reference and candidate module outputs. It uses static reference activations, so it is not a contextual search and has no initialization or acceptance threshold. It takes about 0.8 minutes on the DS settings. Table III shows that it ends with higher Avg. KL than the fidelity mode in all four tested settings (marginally on DS W4), higher Avg. PPL in three, and lower Micro accuracy in three. Local-MSE is thus a useful quick reference, not a substitute for the output criterion.
Whole-model selection. Applying the same KL shortlist, answer NLL, and acceptance rule to whole homogeneous models selects GPTQ in all four 7B/8B settings, AutoRound in all Llama-3.2 W3 replicates, and GPTQ or AutoRound in two or one Llama-3.2 W4 replicates (Table V ). In the five settings where all replicates agree, module-wise QSelect-TA lowers Avg. PPL by 1.22–14.62% and raises Micro and Macro by 0.23–6.45 and 0.17–6.01 points relative to the selected family. This control does not match the search capacity or path dependence of module-wise selection, but it shows that choosing one family with the same rule does not recover the module-wise results.

VI-C Ground Time Versus Fidelity
Fig. 2 places the evaluated selectors on one time axis for DS W3, and Table VI gives the granularity study. DS layer, component, and module scans take roughly 18, 35–40, and 210 minutes. Finer units are not uniformly better: modules give the lowest W3 PPL, components the highest DS task means, and at W4 layers give the lowest DS KL and the lowest Llama-3.1 PPL. At layer granularity, QSelect-TA gives higher Micro accuracy than CALM-reimpl. in all four settings and lower Avg. KL in three, with DS W4 essentially tied (0.0987 versus 0.0986); CALM-reimpl. gives slightly lower Avg. PPL on both DS settings. Three passes triple the candidate evaluations and raise selection time to 7.2–9.5 hours, changing Avg. PPL by only − 0.12 -0.12 % to − 0.75 -0.75 % (Table XVI ); one pass remains the default. On one A800 GPU, a one-pass module-wise QSelect-TA run for Llama-3.1-8B W3 takes 3.12 hours, and QSelect-KL on Llama-3.2-3B averages 83.9 minutes, both excluding candidate generation, which is not reported here. Exact final-output scoring is therefore far slower than a local proxy such as Local-MSE, which reuses static reference activations, but at equal granularity it adds only a few minutes over representation-similarity scoring, which also runs the assembled model (Section VI-B ); most of the module-wise time comes from the number of decisions. The search itself is deliberately simple: a greedy coordinate descent with one forward pass per candidate. Its absolute cost stays modest because each evaluation is a forward pass of the model being prepared, and onboard memory keeps that model small: Llama-3.2-3B, the smallest model studied here, is still about twice the size of the 1.54-billion-parameter model flown on ASTREA [ 10 ] . The budget that makes compression necessary thus also keeps exact scoring affordable. The cost stays on the ground, because the exported model has the bit width and format of a single-family model apart from the AWQ input scales, but it recurs with every model update, because a new calibration bank changes the artifact (Section VII -C).

VI-D Robustness of the Ground Procedure
Traversal order has a smaller aggregate effect than initialization. Random and reverse scans change Avg. PPL by at most 0.10 in three settings; on DS W3 the increases are 0.77 and 0.53, and mean Macro changes by at most 0.67 points across all orders (Table XVI ). Changing the restricted-pool Llama-3.1 W3 start from GPTQ to AWQ, by contrast, increases Avg. PPL by 1.18 and lowers Micro and Macro by 5.49 and 5.14 points (Table XVI ). Adding AutoRound to the pool has the clearest value at W3: across both models and both AWQ and GPTQ starts, it lowers Avg. PPL by 0.32–1.24 and raises Micro by 2.37–4.02 points, while W4 changes are smaller and mixed (Tables XVI and XVI ).
The selected models remain heterogeneous. On Llama-3.2-3B, the mean AWQ/GPTQ/AutoRound counts of QSelect-KL are 6.0/65.0/125.0 at W3 and 17.0/74.7/104.3 at W4. Across the three DS W3 calibration banks, pairwise assignment agreement is 73.5–76.0%, and 124 of 196 modules agree in all three. Selection therefore depends on the candidate bank as well as on the model, a point we return to in Section VII .

VII Deployment Analysis for Space Robots
This section interprets the measured results for onboard use. It adds an analytic storage model but no new experiments.
VII-A What Occupies the Packed Artifact

To see where the remaining bytes are, we model the artifact from the public model configurations. Quantized linear layers store b b -bit codes, a packed b b -bit zero point and an FP16 scale for every group of 128 weights, and an int32 group index per input channel; embeddings, the output head, normalization weights, and biases stay in BF16. It also shows that the BF16 embedding and output layers, which the experiments never quantize, make up 43–46% of the 3-bit artifact and 37–39% of the 4-bit artifact (Fig. 3 ). Further reductions for an onboard memory budget must therefore address those layers, for example through embedding and head quantization or vocabulary restriction; we have not evaluated either.

VII-B Runtime Memory
Peak CUDA memory falls by only 24.2–27.9% (Table VII ), although the serialized artifact shrinks by roughly a factor of three. The absolute sizes also matter: by the analytic model, the 7B/8B artifacts still occupy about 4.8 GB at 3 bits and 5.6–5.7 GB at 4 bits. They are far beyond the 256 MB of a RAD750-class computer, call for accelerator-class payload computers, and are several times larger than the 1.54-billion-parameter model flown on ASTREA. The measurement uses batch one, sequence length 2,048, and no key–value cache, includes model loading, and runs the packed forward path used here, which dequantizes weights during execution and is not an optimized serving kernel. A flight deployment would need kernels that compute directly from packed weights and a memory plan for activations and the key–value cache, measured on flight-representative hardware. Latency matters as much as memory there: ASTREA’s 1.54-billion-parameter 4-bit model needed from about 40 s to over 8 min per response on a CPU-only flight system-on-chip [ 10 ] . We leave these measurements to future work.
VII-C Choosing an Operating Point
Bit width. At W4, composed models stay close to the reference: QSelect-TA is within 0.81, 2.34, and 2.37 Micro points of BF16 on DS-R1-Qwen-7B, Llama-3.1-8B, and Llama-3.2-3B. At W3 the gaps are 7.87, 11.87, and 10.43 points even after composition. For command interpretation, where the validated reference behavior is the specification, W4 is the realistic default; W3 fits only when memory is the binding constraint and task-level acceptance tests can quantify the loss. At W4, composition buys fidelity rather than accuracy: relative to the best single family, the fidelity mode lowers Avg. KL from 0.0937 to 0.0810 † on Llama-3.1-8B and from 0.111 to 0.088 on Llama-3.2-3B and matches it on DS-R1-Qwen-7B (0.0913 † versus 0.092), while its Micro accuracy stays within half a point of the best single-family value.
Mode. The fidelity mode is the natural default for R3: it needs no labels and, among the configurations of Table II , gives the lowest Avg. PPL in every setting and the lowest Avg. KL in five of six. The target-adapted mode is appropriate when the mission supplies labeled examples and its acceptance tests cover the resulting departure from the reference. At Llama-3.2 W3, for instance, the fidelity mode lowers Avg. KL by 10.1% relative to QSelect-TA but loses 1.57 Micro points.
Updates. Because candidates are calibration-bank specific, re-running selection with a new bank changes the artifact substantially: across the DS W3 banks, only 124 of 196 module choices agree in all three. Even modules whose family is unchanged receive new weights, because each bank regenerates the candidates, so an update replaces the whole quantized artifact. A model update should therefore be treated as a new artifact with full acceptance testing rather than as a patch, and the configuration record (Section IV-F ) makes the previous artifact recoverable for rollback.
VII-D What Flight Use Would Add
Three questions remain open. First, the reference behavior here is general-domain text and reasoning; a mission would validate the reference on its own command corpus, procedures, and skill library, and the fidelity score should then be computed on that text. Second, latency, energy, and thermal load must be measured on flight-representative processors. Third, packed formats change how a radiation-induced upset propagates: a corrupted group scale or zero point affects all 128 weights of its group, so these metadata may deserve stronger protection than the codes. A corrupted AWQ input scale affects a whole input channel of its module, so the exposure also depends on the assignment. None of these questions is answered by the present experiments.
VIII Limitations
No space-domain evaluation. All results use general-domain benchmarks on a ground GPU. We do not evaluate space-robot commands, procedures, or skill libraries, flight hardware, latency, energy, or radiation effects.
Scope of the method. The evidence covers fixed-bit symmetric weight-only candidates with group size 128 for 3B–8B text-only models. Candidates inherit homogeneous calibration paths and are dense fake-quantized weights during assignment; family token budgets and compute differ. Global rotations, cross-layer transforms, activation quantization, incompatible runtime formats, vision–language models, and models larger than 8B are not demonstrated. Both Llama references are base models; a command interface would start from an instruction-tuned reference.
Metrics. The arithmetic five-corpus PPL average and raw maximum are descriptive rather than pooled metrics. The downstream protocol is custom, QSelect-TA uses labels from the evaluated task families and token-weights answer NLL differently from Micro and Macro accuracy, GPQA is the only proxy-unseen Llama task, and three calibration-bank replicates do not measure proxy or test-sampling uncertainty. Some QSelect-KL values in Table II are derived from paired changes rather than measured directly.
Search. Assignments depend on initialization, order, passes, the target-adapted margins, and the candidate bank. One pass is a cost choice, not convergence, and rejected NLL proposals do not trigger runner-up tests. Candidate generation and storage are extra costs, and native export is executable but not an optimized serving kernel. The argument that exact scoring is affordable rests on the 3B–8B sizes studied; larger models or frequent re-preparation would call for prefix caching or a cheaper screening step before final-output scoring, for example a local Fisher-information approximation of the same KL, which we do not evaluate.
IX Conclusion
Onboard language models for space robots need more than a small footprint: the compressed model must be a static artifact in a supported format whose behavior stays close to the reference validated on the ground. Treating compression as a ground-segment step, QSelect composes one low-bit model from compatible quantizer families and scores every substitution through the final next-token distribution. Its label-free fidelity mode has no tuned threshold and reaches lower mean held-out perplexity than every single-family model and the target-adapted mode in all six settings; final-output scoring beats representation-similarity and local-reconstruction criteria on held-out KL; and ground time can be traded against fidelity through decision granularity. The packed artifacts are 63–70% smaller than BF16, and nearly half of what remains at 3 bits (43–46%) is the unquantized embedding and output layers rather than the composed modules. Evaluating the fidelity criterion on mission text and measuring the composed models on flight-representative hardware are the next steps.

Appendix B Protocol Details
The calibration-bank replicates are 17, 23, and 41. Each replicate determines the candidate-generation C4 manifest and the separate C4 sample used for KL scoring; the labeled proxy and held-out evaluation manifests are fixed. Candidate generation uses 128 sequences of length 2,048. KL scoring uses 64 sequences of length 1,024. The five-corpus suite uses 128 sequences per corpus at length 2,048 and evaluation seed 1009. Manifest hashes and candidate checkpoint hashes are recorded in the run metadata.
The proxy builder takes fixed dataset rows without per-run resampling. GSM8K uses the first 128 training rows and the string following “####”; MMLU uses the first 256 development rows and answer letters; ARC-Challenge and HellaSwag use the first 128 and 256 training rows, respectively, with the original option order; MATH cycles through seven training subjects until 128 parseable final answers are collected. Multiple-choice proxy prompts end in Answer: , and the target continuation is a leading space followed by the gold letter. GSM8K uses Question: ... Answer: and MATH uses Problem: ... Final answer: , each followed only by the canonical final-answer string. No reasoning trace is included.
Downstream evaluation is zero-shot with raw text prompts. Multiple-choice prompts list lettered options and end in Answer: ; the score is the average continuation log probability of a leading-space answer letter. HellaSwag is reformatted as a multiple-choice question with activity and context fields. GSM8K uses Question: ... Answer: Let’s think step by step. , and MATH-500 uses Problem: ... Solution: Let’s solve it step by step. The final answer is . Generation is greedy with at most 256 new tokens and stops at the tokenizer EOS token. GSM8K uses the final numeric string; MATH-500 first extracts the last boxed expression and then applies whitespace, comma, dollar-sign, and case normalization with a last-number fallback. This custom protocol supports matched internal comparison but should not be read as a standard lm-evaluation-harness score.
The local Code corpus is built from source files in the evaluation repository (Python, C/C++, CUDA, Rust, Go, Java, JavaScript, and TypeScript), excluding common dependency and cache directories. The Math builder uses MMLU-Pro question text [ 51 ] when available, and the Wiki builder uses WikiText-103 training text. The frozen files support internally repeatable comparison, but the resolved upstream revisions, license metadata, file counts, language composition, and complete deduplication provenance were not preserved, so these corpora should be treated as local robustness sets rather than standard public benchmarks.
Software versions are PyTorch 2.10.0+cu128, Transformers 5.8.0, Datasets 4.0.0, Accelerate 1.13.0, GPTQModel 7.1.0, AutoRound 0.13.0, and Safetensors 0.7.0. Each reported job uses one NVIDIA A800-SXM4-80GB GPU. The launch metadata records checkpoint names but does not pin model and tokenizer commit revisions, which limits reproducibility.

C-C Objective Ablations
Module-wise QSelect-KL selects the minimum-KL candidate and accepts any strict KL decrease. NLL-only ranks all candidates by target-answer NLL and accepts a replacement when NLL improves by at least 0.3%, without a KL condition. The observed association does not determine which replacements cause the task decrease.
