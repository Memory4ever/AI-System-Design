Abstract
Long-horizon robot manipulation requires a robot to remember
task-relevant information beyond its short observation window.
Existing memory-augmented policies typically retrieve relevant
information from history and reason over it at execution time,
placing a heavy reasoning burden on the high-level model. To address
this challenge, we propose PAL ( P lan first, A ct
L ater), a hierarchical memory framework for vision-language
robot manipulation. It maintains a short-term visual buffer, a
semantic-event memory, and an executable subtask_list . A
high-level vision-language model (VLM) converts streaming visual
observations into the subtask_list . At execution time, the
VLM selects the currently relevant subtask from the
subtask_list and passes it to a low-level
vision-language-action (VLA) policy. To teach the model what to write
to memory and when to update it, we introduce a two-stage data
generation procedure that first expands sparse update supervision and
then uses self-labeling with task-grounded verification to generate
training data that better match the state distribution encountered
during execution. We evaluate our approach on memory-dependent
benchmarks and real-world manipulation tasks. On RoboMME, PAL
achieves a 56.05% success rate, outperforming the strongest
baseline, FrameSamp-Modul, at 44.51%. In real-world experiments
across four manipulation tasks, PAL reaches 60.83%
overall success, surpassing MemER (45.00%) and FrameSamp-Modul
(28.33%). These results show that proactively writing
future-relevant subtasks into hierarchical memory improves
long-horizon visual reasoning and robot control. Code and videos can be found on our website: https://qinghangliu.github.io/pal-webpage/

1 INTRODUCTION
Vision-language-action (VLA) models have made substantial progress
toward general-purpose robot control
( Intelligence et al., 2025b ; Kim et al., 2024 ) . By grounding language
instructions in visual observations and actions, VLA provides
a flexible interface for solving diverse manipulation tasks in generalizable open-world. However, many
existing policies still rely on a Markovian or near-Markovian view of the
world: the action to execute is assumed to be recoverable from the current
observation or a short window of recent frames. This assumption becomes fragile
in memory-dependent settings, where successful behavior may depend on historical information observed much earlier. For example, repetitive
manipulation requires remembering progress ( Yang et al., 2026 ; Dai et al., 2026 ; Chen et al., 2026a ) and active exploration requires
retrieving the location or state of an object discovered earlier when the robot revisits
the scene ( Shah et al., 2026 ; Sridhar et al., 2025 ) .
To address these memory-dependent challenges, recent works augment VLA models
with a memory bank that retains task-relevant information from past
observations. At execution time, the model retrieves relevant entries from the
bank to support stable long-term decision making
( Torne et al., 2026 ; Sridhar et al., 2025 ; Shi et al., 2026 ) . Although this
avoids repeatedly processing the raw history, the high-level model must still
search across a large memory bank and infer the next subtask at inference time. Such
banks often contain redundant information, making it difficult for the model to
fetch the required information and lead to more task failures.
One key observation is that:
Evidence for defining a future goal are available before executing the goal.
As illustrated in
Fig. 1 , the task requires the robot to press the button
and then pick up the highlighted cube. While the robot is still pressing
the button, the model can store the future subtask “pick up the cube” in the
subtask list when the cube is highlighted. When the transient highlight
disappears, the robot can simply retrieve the stored subtask for execution,
without re-identifying which cube to pick up. This pattern occurs in many memory-dependent
robotic tasks, where the future plan can be determined once the necessary
evidence becomes available.
Motivated by this view, we propose Plan First, Act Later ( PAL ), a hierarchical
memory pipeline for VLA long-term decision-making. It comprises a three-level memory system:
a short-term visual buffer, a semantic-event memory, and an executable
subtask_list . These three memory components have distinct roles: the
visual buffer retains recent observations, the semantic-event memory maintains
task-relevant events, and the executable subtask_list stores
future-relevant subtasks text instructions. At each query, a high-level vision-language model
(VLM) updates the event memory and the subtask_list , then selects the subtask to execute for the low-level VLA. This design
has two benefits: (1) first, streaming memory updates incrementally compress the visual
history, reducing the context required
for long-horizon reasoning; (2) second, the stored subtasks can be directly retrieved without searching across a large memory bank for subtask inference.
To teach the model what to write to memory and when to update it, we propose
a two-stage training pipeline. The pipeline combines dense update-timing
supervision with self-labeling and a task-grounded verifier, allowing the
training data to better reflect the model’s execution rollout distribution.
Evaluation results on RoboMME ( Dai et al., 2026 ) , a benchmark of long-horizon, memory-dependent manipulation tasks,
show that PAL achieves a 56.05% success rate, compared with
44.51% for the strongest baseline, FrameSamp-Modul. In real-world
manipulation experiments across four tasks, PAL reaches 60.83%
overall success, outperforming MemER (45.00%) and FrameSamp-Modul
(28.33%), demonstrating the practical benefits of our approach.
Our contributions are as follows:
•
We introduce PAL , a hierarchical memory architecture
with a streaming-style reasoning mechanism for VLA long-term decision-making. It progressively
transforms streaming visual observations into semantic events and executable
subtasks, providing a structured memory for diverse
long-horizon, memory-dependent tasks.
•
We develop a two-stage training pipeline that enables the model to
learn reliable hierarchical-memory update behavior. It produces accurate
and timely memory updates, yielding reliable executable subtask lists for
long-horizon reasoning.
•
We demonstrate the effectiveness of PAL through evaluations on
long-horizon, memory-dependent manipulation tasks, where it delivers
consistent gains over competitive VLA and memory-augmented methods in both
simulated and real-world settings.
2 Related Works
Vision-language-action models for robot control.
Recent VLA models have evolved from instruction-conditioned visuomotor policies
into general robot control systems. Early efforts such as OpenVLA
and π 0.5 \pi_{0.5} established a unified interface that maps language instructions
and visual observations to low-level actions
( Kim et al., 2024 ; Intelligence et al., 2025b ) . More recent systems
improve generalization through larger-scale training, broader robot data, and
continued experience-driven learning
( Intelligence et al., 2025a ; Intelligence et al., 2026 ; Team et al., 2026 ) .
Despite this progress, most VLA policies still operate on the current
observation or a short recent context, motivating hierarchical planning and
memory mechanisms for tasks that require information from earlier history.
Hierarchical planning and subgoal-conditioned control.
Long-horizon robot tasks are often handled with a hierarchical interface, where
a high-level model selects a subtask or subgoal for a low-level policy to execute
( Intelligence et al., 2025b ; Shi et al., 2025 ; Chen et al., 2026a ) .
This interface separates selecting the next subtask from generating the
low-level actions that execute it. τ 0 \tau_{0} -VLA extends this hierarchy with
execution memory and world-model-guided test-time computation, predicting and
comparing candidate subtask outcomes before commitment
( Cai et al., 2026 ) . Our work adopts the similar
interface:
the low-level policy executes the current subtask, and the high-level model
maintains the semantic state needed to select future subtasks. However,
the hierarchical interface alone does not specify how to use information from
earlier observations, which motivates memory-augmented VLA methods.
Memory-augmented VLA models and benchmarks.
Memory-augmented VLA methods address this missing component by storing and
retrieving historical information for high-level decision making. Recent works
use amortized multi-frame context
( Jang et al., 2025 ) , multi-scale
embodied memory ( Torne et al., 2026 ) , experience
retrieval ( Sridhar et al., 2025 ) , keyframe-based memory
( Chen et al., 2026b ) , structured scene
memory ( Ju et al., 2026 ) , and perceptual-cognitive
token memories ( Shi et al., 2026 ) .
HiMe introduces hierarchical embodied memory for long-horizon VLA control,
providing another memory-bank approach
( Ji et al., 2026 ) .
In parallel, benchmarks such as RoboMME, RMBench, and RoboMemArena highlight
that robotic policies often fail when task success requires retaining and using
historical information
( Dai et al., 2026 ; Chen et al., 2026a ; Lei et al., 2026 ) . Although these methods make
past information accessible, they still require the high-level model to search
a large memory bank at execution time, so the computational cost grows with the
amount of stored history. In contrast, our method allows the model to record a
future-relevant subtask as soon as the supporting evidence is observed, before
the subtask must be executed, and later select it from the editable
subtask_list . Concurrent work, MaP-WAM
( Zhao et al., 2026 ) , similarly plans ahead
and stores future-relevant information in memory. However, MaP-WAM plans only the
next step, whereas our editable subtask_list retains all inferred
future subtasks and serves as a persistent component of the memory system.
3 Preliminaries
Problem setup.
We consider memory-dependent VLA tasks in which the
correct behavior at timestep t t may depend on information that is not
visible in the current observation. Let L L denote the language instruction,
o t o_{t} the visual observation, a t a_{t} the low-level action, and
H t = { ( o i , a i ) } i = 1 t H_{t}=\{(o_{i},a_{i})\}_{i=1}^{t} the raw interaction history. Long-horizon tasks
are increasingly challenging for a fully history-based policy
π ⁡ ( a t ∣ H t , L ) \pi(a_{t}\mid H_{t},L) since the visual context grows with time and contains
many redundant frames.
Hierarchical memory formulation.
We organize task memory at three temporal scales. The short-term visual buffer
𝒱 t \mathcal{V}_{t} stores recent RGB images from the current observation window.
The other two components are ordered lists of natural-language entries. The
semantic-event memory ℰ t \mathcal{E}_{t} records events that have occurred in the
environment and may be relevant to the task, with one event per entry. The
executable memory 𝒫 t \mathcal{P}_{t} is the subtask_list , and each of
its entries is one subtask. An example is shown in
Fig. 1 . Together, these components form the hierarchical memory state
ℳ t := ( 𝒱 t , ℰ t , 𝒫 t ) , \mathcal{M}_{t}:=(\mathcal{V}_{t},\mathcal{E}_{t},\mathcal{P}_{t}),
At each query, the VLM uses the incoming visual observations and the hierarchical memory to
update either list and to select the currently subtask ℓ t \ell_{t} , which
is passed to the low-level policy:
a t = π VLA ​ ( o t , ℓ t , L ) . a_{t}=\pi_{\mathrm{VLA}}(o_{t},\ell_{t},L).
Plan first, Act later.
Our approach to constructing the subtask list is inspired by a simple temporal
separation: when visual evidence reveals that a subtask will be needed before
it is time to execute it, the model can store the subtask for later execution.
Formally, a subtask written to memory at t 1 t_{1} can be
selected as ℓ t 2 \ell_{t_{2}} for execution at a later time t 2 t_{2} :
ℳ t 1 + Δ ​ t = g θ ( ℳ t 1 , o t 1 : t 1 + Δ ​ t , L ) , ℓ t 2 ∈ 𝒫 t 1 + Δ ​ t , t 1 ≤ t 2 . \mathcal{M}_{t_{1}+\Delta t}=g_{\theta}\bigl(\mathcal{M}_{t_{1}},o_{t_{1}:t_{1}+\Delta t},L\bigr),\qquad\ell_{t_{2}}\in\mathcal{P}_{t_{1}+\Delta t},\quad t_{1}\leq t_{2}.
4 Methodology
4.1 Overview
Our methodology has two parts. Section 4.2
describes the memory construction and querying mechanism used whenever the VLM
runs, including both training rollouts and inference. Section 4.3
then describes how we train the VLM to acquire this capability: learning what
to write to memory, when to update it, and which stored subtask to execute.
4.2 Stream-based Memory Reasoning

Following the three-level hierarchical memory formulation introduced in
Sec. 3 , we propose a streaming-style reasoning pipeline
that processes history as a stream of image chunks, as illustrated in
Fig. 2 . For a query at time t t , let
𝒞 t = o t − Δ ​ t : t \mathcal{C}_{t}=o_{t-\Delta t:t} denote the observations collected since the
previous query. The VLM takes the previous hierarchical memory
ℳ t − Δ ​ t \mathcal{M}_{t-\Delta t} , the current observation chunk 𝒞 t \mathcal{C}_{t} , and
the task instruction L L as input. The visual buffer stored in
ℳ t − Δ ​ t \mathcal{M}_{t-\Delta t} is combined with 𝒞 t \mathcal{C}_{t} and downsampled to
a fixed number of frames before being passed to the VLM. The VLM then outputs
three fields. The quantity
Δ ​ ℰ t \Delta\mathcal{E}_{t} is a newly predicted event, while Δ ​ 𝒫 t \Delta\mathcal{P}_{t}
is a newly predicted subtask to be appended to the subtask list. The third
output, ℓ t \ell_{t} , is the current subtask passed to the low-level VLA. Because
image chunks arrive incrementally, the evidence available at a query may be
insufficient to determine whether a new event has occurred or which future
subtask should be appended. In this case, the VLM outputs an empty
Δ ​ ℰ t \Delta\mathcal{E}_{t} or Δ ​ 𝒫 t \Delta\mathcal{P}_{t} , respectively, and the
corresponding memory is retained until further observations become available.
The memory transition is written as

ℰ t − Δ ​ t \mathcal{E}_{t-\Delta t} is cleared; otherwise, it is retained. Let

4.3 Two-stage training with self-labeling and verification
We propose a two-stage training procedure to teach the model what to write to
the subtask list and when to update it, while jointly training it to predict
the current subtask at each query. Stage 1 augments the training data by
creating additional training examples from each sparse annotation. However,
this augmentation changes the training data
distribution, introducing a mismatch with the model’s inference distribution.
We therefore introduce Stage 2 to regularize the model’s memory-update behavior
and reduce this mismatch.
Stage 1: Dense update-timing supervision.
Figure 3: Dense update-timing supervision. A sparse update annotation is
expanded into multiple training samples with visual buffers of different
lengths, exposing the model to different levels of evidence around the
reference update boundary.
As illustrated in Figure 3 , we first construct a
dataset of sparse annotations; details of the simulation and real-world dataset
construction are provided in Appendices C.2 and
D.1 , respectively. Each sparse annotation is provided
at a single timestep t i t_{i} . We denote the training labels for the new event and subtask at this
timestep by Δ ​ ℰ i ref \Delta\mathcal{E}^{\mathrm{ref}}_{i} and
Δ ​ 𝒫 i ref \Delta\mathcal{P}^{\mathrm{ref}}_{i} , respectively. Such sparse
annotation is data-inefficient because it
provides only one supervision point for each update. Moreover, visual evidence
changes only slightly between neighboring queries, making the update and
no-update cases difficult for the model to distinguish.
To address this issue, we sample multiple query timesteps t t at regular
intervals from [ t i − 1 , t i + t i + 1 2 ) [t_{i-1},\frac{t_{i}+t_{i+1}}{2}) . For each query, we construct 𝒱 t \mathcal{V}_{t} from the observations accumulated since the preceding update up
to timestep t t , so later queries contain more visual evidence.
For each sampled query timestep, we assign ∅ \emptyset to the event and
subtask-list targets when t < t i − 1 + t i 2 t<\frac{t_{i-1}+t_{i}}{2} , and assign
Δ ​ ℰ i ref \Delta\mathcal{E}^{\mathrm{ref}}_{i} and
Δ ​ 𝒫 i ref \Delta\mathcal{P}^{\mathrm{ref}}_{i} when
t ≥ t i − 1 + t i 2 t\geq\frac{t_{i-1}+t_{i}}{2} .
We use this simplified assignment as a practical rule: queries presumed to have
insufficient information for an update receive empty targets, whereas later
queries receive the corresponding reference event and subtask labels.
The effectiveness of this simple approximation is further examined in
Sec. 5.2 .
In this way, the single annotation at t i t_{i}
is expanded into annotations over a range of query timesteps. The model is fine-tuned on these densified
labels to learn the memory update schema and approximate update timing from the
reference teacher’s distribution.

Despite this supervision, the Stage 1 model may still produce updates too frequently or at
imprecise times. In particular, it may update before enough evidence has
accumulated or repeat content that is already in memory. Stage 2 is designed to
address these issues through task-grounded verification.
Concretely, we roll out the Stage 1 model on the training set, maintaining the
memory states generated by the model. Let
t i − 1 + t i 2 ≤ t < t i + t i + 1 2 \frac{t_{i-1}+t_{i}}{2}\leq t<\frac{t_{i}+t_{i+1}}{2} be the timing band of the
i i -th reference update, whose reference event and subtask-list increments are
Δ ​ ℰ i ref \Delta\mathcal{E}^{\mathrm{ref}}_{i} and Δ ​ 𝒫 i ref \Delta\mathcal{P}^{\mathrm{ref}}_{i} .
Let 𝒳 ∈ { ℰ , 𝒫 } \mathcal{X}\in\{\mathcal{E},\mathcal{P}\} stand for either memory. For each
prediction, the verifier checks the corresponding reference label and whether that memory
already stores it:
Δ ​ 𝒳 t ← ∅ , if ​ Δ ​ 𝒳 t ≠ Δ ​ 𝒳 i ref ​ or ​ Δ ​ 𝒳 t ∈ 𝒳 t − Δ ​ t . \Delta\mathcal{X}_{t}\leftarrow\emptyset,\quad\text{if }\Delta\mathcal{X}_{t}\neq\Delta\mathcal{X}^{\mathrm{ref}}_{i}\text{ or }\Delta\mathcal{X}_{t}\in\mathcal{X}_{t-\Delta t}.
Thus, an incorrect prediction, as well as one that duplicates an entry already
stored in memory, is replaced with ∅ \emptyset , while the other prediction is
unaffected. This output is then used to update the memory following the update
mechanism in Section 4.2, and the updated memory state ℳ t \mathcal{M}_{t} is the
input of the next query. If
t ≥ t i + t i + 1 2 and Δ ​ 𝒳 i ref ∉ 𝒳 t ​ for some ​ 𝒳 ∈ { ℰ , 𝒫 } , t\geq\frac{t_{i}+t_{i+1}}{2}\quad\text{and}\quad\Delta\mathcal{X}^{\mathrm{ref}}_{i}\notin\mathcal{X}_{t}\text{ for some }\mathcal{X}\in\{\mathcal{E},\mathcal{P}\},
the rollout is marked as failed, since the model has not produced and stored the
i i -th reference event or subtask-list update by the deadline. We retain only
rollouts in which the verifier accepts an update at every required update point.
The resulting update annotations remain sparse, and their timing is determined
within a limited range by the VLM. As a result, the data distribution is closer
to the model’s output distribution and is easier for the model to learn.
The model is then fine-tuned on these self-labeled trajectories. The complete

5.1 Simulated experiments
RoboMME benchmark and baselines.
We evaluate our model on the RoboMME benchmark ( Dai et al., 2026 ) , which is a collection of long-horizon, memory-dependent tasks for robotic manipulation.
We compare PAL with five baselines. π 0.5 \pi_{0.5} uses only the current
observation and task instruction, providing a memory-free reference without
access to observation history. FrameSamp-Modul ( Dai et al., 2026 )
uniformly samples
frames from the observation history and injects their visual features into the
policy through feature modulation, providing a perceptual-memory baseline
without explicit high-level reasoning. MemER ( Sridhar et al., 2025 )
retrieves relevant
experience from the observation history and uses a VLM to produce a grounded
subtask for the low-level VLA. PAL adopts the same high-level–low-level control
interface, and the low-level VLA used by MemER is identical to that of PAL .
EventVLA
( Yang et al., 2026 ) is an end-to-end VLA that
learns to retain sparse, task-relevant keyframes in its Keyframe Evidence
Memory. It provides a complementary comparison between PAL ’s semantic,
executable memory and learned visual evidence memory. Finally,
GPT-6-astra + VLA
replaces PAL ’s fine-tuned high-level VLM with GPT-6-astra while using the same
low-level VLA, and represents its memory as a language description of the
current environment from which it predicts the next subtask.

Results and analysis.

with complete per-task results provided in Appendix C.1 .
We analyze these results through the following research questions.
Q1: By how much does PAL improve success rates on
memory-dependent manipulation tasks compared with baselines?
PAL achieves an overall success rate of 56.05 % 56.05\% , improving upon the strongest
baseline, FrameSamp-Modul ( 44.51 % 44.51\% ), by 11.54 11.54 percentage points. We focus
the comparison on
MemER and GPT-6-astra + VLA because, like PAL , both use a hierarchical control
structure in which a high-level model generates a subtask for a low-level VLA.
PAL outperforms MemER ( 42.38 % 42.38\% ) and GPT-6-astra + VLA ( 39.75 % 39.75\% ) by 13.67 13.67
and 16.30 16.30 percentage points, respectively, and achieves the highest success
rate on 4 of the 16 RoboMME tasks.
Q2: Why does PAL perform better than baselines on
long-horizon tasks?
We attribute PAL ’s gains to two complementary components: the executable
subtask list decouples subtask inference from execution-time activation, while
streaming memory updates reduce the visual context and VLM capacity required
for long-horizon reasoning.
The Episode-start group directly evaluates the benefit of constructing
the subtask list ahead of execution, as all information needed to infer the
complete list is available at the beginning of the episode. PAL
achieves 77.33 % 77.33\% on this group, outperforming the strongest baseline,

Q3: How do the two training stages contribute to PAL ’s overall performance?
Table 1 reports group-level averages, with the
full per-task results in Appendix C.1 . Stage 1 Only
achieves 37.35 % 37.35\% overall success, Sparse Label improves to 43.39 % 43.39\% , and PAL
reaches 56.05 % 56.05\% . To explain these differences, we examine the update behavior
in Table 2 on four representative streaming-reasoning
tasks. PatternLock and RouteStick involve a large number of list updates as
evidence arrives, whereas VideoPlaceOrder and VideoPlaceButton require evidence to be
accumulated over a long video stream. Comparing Stage 1 Only with Update Gate,
we find that applying the update gate greatly improves final-list accuracy. This is
because Update Gate provides the model with approximate update timings, thereby
decoupling when to update from what to update. The improvements on the final-list accuracy implies that Stage 1 helps the
model learn what content to update, but not when to update it.
We then calculate the update frequency of each variant. As expected,
Stage 1 Only tends to update the executable list too
often, since the model is trained with a dataset that over densifies the update timing.
Sparse Label under-updates and even fails to update any subtask list for Long-video tasks,
which implies sparse supervision is insufficient for learning the correct update behavior.
PAL ’s update frequency is closer to ground truth and yields higher final-list
accuracy. This suggests that Stage 2 regularizes the overly frequent update
behavior learned in Stage 1, producing more accurate memory states for
long-horizon reasoning.
5.3 Real-world experiments
We evaluate our pipeline in the real world using a Franka Research 3 robot arm.
The evaluation comprises four tasks adapted from their simulated counterparts,
each targeting a distinct memory capability. PickXtimes requires the robot to
pick a green box a specified number of times, testing its ability to track task
progress. In VideoUnmask, the model observes a video showing the layout of
colored cubes and must subsequently point to the requested cube. VideoPlaceOrder
tests long-video reasoning by requiring the model to recall where a target box
was placed earlier in the video. PatternLock evaluates imitation and reasoning
over a temporally dense action sequence. For each task, we evaluate 10 episodes
spanning different difficulty levels and repeat each episode three times, for a
total of 30 evaluations per task. We compare against the MemER and
FrameSamp-Modul baselines.

6 Conclusion
We presented PAL , a hierarchical memory pipeline that incrementally converts
streaming visual observations into semantic events and a subtask list
before they are needed for control. By separating early subtask construction
from execution-time selection, PAL reduces the need to repeatedly revisit a
large visual history. We further introduced a two-stage training procedure that
combines dense update supervision with verified self-labeling to learn reliable
memory updates under the model’s rollout distribution. Experiments on RoboMME
and four real-world manipulation tasks demonstrate that PAL improves
memory-dependent robot control, particularly when relevant evidence must be
retained over long horizons.
While PAL improves upon prior work, it still has limitations. Its executable
memory is represented as a sequential subtask list and therefore cannot encode
conditional branches during execution. Programmatic planning methods such as
Code as Policies demonstrate that executable programs can express conditional
control flow and perception-dependent behavior ( Liang et al., 2023 ) .
Future work could extend PAL with branchable executable memory that selects
different subtask sequences according to execution-time observations.

B.2 Stage 2 Self-Labeling
Stage 2 starts from the Stage 1 LoRA adapter and keeps the optimizer,
batch size, and LoRA configuration above. It has two modes, selected according
to how reliable the Stage 1 model already is.
Verifier.
The Stage 2 verifier checks event and subtask-list updates independently
against their reference updates. All non-coordinate text must match exactly
(100% correct; paraphrases, omissions, and extra text are rejected). When
coordinates are present, the prediction must include the corresponding
coordinate fields, and each predicted-reference pair must have an L2 distance
of strictly less than
10 10 pixels, i.e., ‖ 𝐱 pred − 𝐱 ref ‖ 2 < 10 \|\mathbf{x}^{\mathrm{pred}}-\mathbf{x}^{\mathrm{ref}}\|_{2}<10 ;
without coordinates, the exact-text criterion alone applies.
We use one-pass self-labeling for the simulation experiments because the Stage 1
model already produces reliable rollouts: the first pass accepts most training
episodes, so no further labeling rounds are needed. We use cyclic self-labeling
for the real-world experiments because the first pass is less reliable; it
retains only 31 31 of 200 200 episodes in the first round and improves to 170 170 in
the final round. The change in acceptance over cycles is shown in
Figure 5 .
One-pass labeling.
When the Stage 1 model is already strong enough, we label the training set once
and then train. The Stage 1 model rolls out every training episode, and only
episodes accepted by the verifier in Algorithm 2
are kept. The resulting corpus is the accepted self-labeled episodes together
with the original supervised labels of the tasks that are not self-labeled
(BinFill, ButtonUnmask, PickXtimes, StopCube, and SwingXtimes). Non-empty
accepted updates are repeated three extra times, and PatternLock and RouteStick
are upweighted by a factor of four. We then train for 2 2 epochs on 8 8 GPUs.
In the reported run this corpus contains 178,855 178{,}855 rows and the training run
takes about 5.5 5.5 hours. Of the 100 100 training episodes per self-labeled task,
the verifier accepts 100 100 for MoveCube, 99 99 for PickHighlight and VideoUnmask,
98 98 for InsertPeg, PatternLock, and RouteStick, 92 92 for VideoPlaceButton,
90 90 for ButtonUnmaskSwap, 86 86 for VideoPlaceOrder and VideoUnmaskSwap, and
84 84 for VideoRepick. The first self-labeling pass already accepts most
episodes of every task, so this single pass provides enough data for training
and no further labeling rounds are needed.
Cyclic labeling.
When the Stage 1 model is still weak, a single labeling pass accepts too few
episodes, so we alternate training and relabeling. The reported run self-labels
PatternLock and VideoPlaceOrder, both on their conditioning videos, and keeps the
original supervised labels for PickXtimes and VideoUnmask. Both the event and the
subtask list are verified. An initial labeling pass is run with the Stage 1
adapter, after which training proceeds for 3000 3000 steps in blocks of 200 200 .
After each block, the current checkpoint relabels every episode of the two
self-labeled tasks; accepted episodes replace their previous labels, while
episodes that fail verification fall back to their original supervised labels.
The next block resumes from that checkpoint and trains on the refreshed corpus.
This run uses 15 15 such rounds. An accepted episode is one that passes
the verifier of Sec. 4.3 and can therefore be used for training. A
normal rollout success is an episode whose final list is already correct
without the verifier. Acceptance rises quickly: the first round keeps
31 31 of 200 200 episodes, and the last round keeps 170 170 . Non-empty accepted
updates are repeated three extra times, as in the one-pass mode. The final
corpus contains 40,144 40{,}144 rows, and the 15 15 training rounds take about
0.7 0.7 hours in total.

C.2 Dataset Construction
We construct sparse labels from each simulator episode. A sparse label is
created only when the event memory or the executable subtask_list
should change. The way we construct the list depends on the task type. We use
the simulator’s oracle event annotations only to determine what happened in the
episode and when the corresponding information becomes available; the model is
still trained to infer the event from visual observations.
We use the following three cases:
1.
Episode-start tasks. The ordered
subtask_list can be determined at the beginning of the episode.
We therefore construct the full list at the first query and keep it
unchanged during the rest of the episode. These tasks do not need an
intermediate event label for constructing the list.
2.
Tasks with changing environments. We first read the oracle
event sequence from the simulator. For each task, a task-specific
rule-based procedure determines when an event can be inferred from the
observations and which subtask or subtasks should be added to the
subtask_list . Before enough evidence is available, the list is
left unchanged. After the event can be inferred, the sparse label first
records the event; when the information is sufficient to specify the next
action, a later sparse label constructs or extends the
subtask_list . The rules for this timing and mapping are defined
separately for each task.
3.
StopCube. This task does not require a separate event
annotation. At each timestep, we set the executable
subtask_list to the current subtask itself, so the list and the
subtask are identical.
Thus, depending on the task, a sparse sample can supervise an event update, a
subtask_list update, or both. Between two update points, the memory
state is kept unchanged. Stage 1 subsequently expands these sparse update
points into a timing band with multiple query timesteps, as described in
Sec. 4 ; this expansion is separate from the sparse-label
construction above.

For the π 0.5 \pi_{0.5} , MemER, and FrameSamp-Modul baselines, we use the results

We adopt a structure similar to that of ( Torne et al., 2026 ) ,
in which memory is maintained as a language description of the current
environment. At each query, the VLM reads the four most recent frames and decides
the next subtask for the low-level VLA to execute. For the conditioning video, we
sample one frame every 33 frames, using at most 24 frames; for videos shorter
than 100 frames, we provide at least three frames. This baseline uses the same
low-level VLA as PAL but is evaluated with one seed because repeated API calls
incur substantial evaluation time.
C.4 More Analysis
C.4.1 GPT-6-astra + VLA
We analyze the results of GPT-6-astra + VLA to identify its failure modes.
Failure mode 1: insensitivity to subtle environmental changes.
The model cannot reliably detect small changes in the scene. For example, whether
a button has been pressed is visually subtle, so the model often cannot judge
whether the press succeeded and therefore does not output the next subtask. This
is reflected in its failures on ButtonUnmask and ButtonUnmaskSwap, where it
performs notably worse than on the similar tasks VideoUnmask and
VideoUnmaskSwap, which do not require pressing a button.
Failure mode 2: loss of rapidly changing historical information.
GPT-6-astra achieves the second-best performance on the Long-video tasks, yet
fails on Short-video tasks such as RouteStick and PatternLock. These tasks are
information-dense and their evidence spans only a short interval, so uniform
downsampling does not retain enough information.
Failure mode 3: unstable high-level–low-level interface.
The model does not interface reliably with the low-level policy. On tasks such as
BinFill and VideoUnmask, the high-level VLM must specify which cube or box to
pick. However, the bounding box it outputs jumps frequently from one location to
another, which interrupts the motion of the low-level VLA.
C.4.2 PAL
PAL also performs poorly on InsertPeg, StopCube, and RouteStick. InsertPeg
requires precise manipulation to align and insert the peg. In the 250 250
evaluation episodes, 101 101 ended in timeout because the peg was not inserted
within the allowed horizon, contributing to the low success rate of 4.8 % 4.8\% .
StopCube requires the robot to anticipate the motion of a dynamically moving
object and react quickly enough to press the button at the right moment. These
fine-control and rapid-reaction requirements are outside the main scope of this
work, which focuses on memory update and long-horizon reasoning. RouteStick
exposes a different limitation: the high-level subtask selection and the
low-level action execution are not always well coordinated. In an auxiliary
experiment, reducing the action-chunk size from 16 16 to 8 8 increased the
RouteStick success rate from 22.4 % 22.4\% to 46.0 % 46.0\% , suggesting that finer
execution granularity substantially improves this coordination.
Appendix D Real-world Experimental Details
D.1 Data Collection and processing
We first use gripper actions and intervals in which the robot arm remains
stationary to obtain coarse temporal annotations of each trajectory, providing
initial estimates of action and subtask boundaries without frame-level manual
annotation. We then provide these coarse annotations together with the
recorded trajectory videos to GPT-5.6-Sol for fine-grained annotation; GPT-5.6-Sol
refines the temporal boundaries and produces the task-level labels used to construct the
event and executable subtask supervision. Finally, we remove the stationary
portions identified during this process while preserving frames around gripper
transitions, subtask boundaries, and task completion, synchronize the remaining
front and wrist RGB observations with the robot states and actions, crop and
resize both views using fixed camera-specific regions, and re-index the
trajectory. Each retained action is rewritten to target the next retained
observation, yielding the final action-aligned trajectories used in our
experiments.
D.2 Settings and Implementation Details
Table 7 summarizes how task difficulty is
varied in our real-world evaluation. Difficulty is controlled by the amount of
task-relevant history that must be retained.
In PickXtimes, the robot repeatedly picks up a green box
and returns it to its original position, so the required number of successful
picks must be remembered. In VideoPlaceOrder, the robot watches a video in which
a green box is placed at several locations and then moves the box to the location
specified by its order in the demonstration. In PatternLock, the robot watches a
path over a 3 × 3 3\times 3 grid and then reproduces the same sequence of movements.
In VideoUnmask, the robot watches three colored cubes being covered, remembers
the color-position mapping, and then points to the requested cube; this task has
no difficulty levels. The training data, evaluation trajectories, and task
configurations are generated using GPT-6-astra. We collect 100 training episodes
for each task and 200 episodes for VideoPlaceOrder because each VideoPlaceOrder
episode is relatively short.
We use a Franka Research 3 robot arm equipped with a front-facing camera and a
wrist-mounted camera. Inference runs on a single NVIDIA RTX 4090 GPU, and the
inference computer communicates with the robot through an SSH-based ROS bridge.
The robot is controlled by a low-level impedance controller that executes the
VLA-generated commands at approximately 950 Hz. Excluding network latency, the
VLA generates action commands at approximately 10–12 Hz.

D.3 Evaluation Protocol
We apply the same task-specific evaluation criteria to all methods to ensure fair
comparisons. VideoPlaceOrder, PatternLock, and VideoUnmask use pre-recorded
conditioning videos to reduce the manual effort required during evaluation.
For PickXtimes, Levels 1–3 contain 5, 3, and 2 episodes, respectively. For
VideoPlaceOrder and PatternLock, Levels 1–4 contain 3, 3, 2, and 2 episodes,
respectively. VideoUnmask has no difficulty levels and uses 10 episodes under
its fixed setting. Each episode is repeated three times, yielding 30 evaluations
per task.
Across all tasks, an episode is marked as a failure if it exceeds the limit of
1,300 timesteps or triggers the robot arm’s safety lock.
PickXtimes.
An episode is successful if the robot lifts the green box off the table exactly
the specified number of times and subsequently keeps its arm raised for 100
timesteps without reaching down to pick up the box again. Any additional contact
with the box after the required number of repetitions is counted as a failure.
To reduce evaluation time, a trial is also terminated and counted as a failure
if any individual pick-and-place cycle takes more than 650 timesteps. The robot
arm and the green box start from the same fixed positions in every episode.
VideoPlaceOrder.
An episode is successful if the green box is on the designated target area when
the gripper releases it. A placement is considered valid if the box’s vertical
projection overlaps the target area. An episode fails if the box is outside all
target areas upon release or touches an incorrect target area. The green box is
initialized at the center of the workspace, and the robot arm starts from the
same fixed pose in every episode.
PatternLock.
An episode is successful if the gripper visits the grid points in the prescribed
order. A grid point is considered visited when any part of the gripper passes
directly above it. An episode fails if the gripper leaves the grid region or
passes over an incorrect grid point. At the beginning of each episode, the
gripper is closed and the robot arm is placed at the initial point of the target
trajectory.
VideoUnmask.
An episode is successful if the robot points to the correct box after the
demonstration video. An episode is failed if the robot points to the wrong box.
The robot arm starts from the same fixed pose in every
episode.
