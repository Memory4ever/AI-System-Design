B.1 Construction of semantic class set and handling unobserved ground-truth classes
Previous work on semantic calibration [ 33 ] establishes evaluation metrics based entirely on the sampled distribution. When adapting this purely sample-based perspective into a training objective, if the correct semantic class is absent from the generated samples, the evidential loss ℒ MSE \mathcal{L}_{\text{MSE}} can still be computed, as the label vector 𝒒 \bm{q} then simply consists of all zero entries. Consequently, the gradient only suppresses the incorrect overconfident completions, but lacks the effect of increasing the likelihoods of the correct completions.
To remedy this and ensure the gradient direction toward the ground-truth class established in Corollary 1 remains available, S-EDL conditionally introduces s ∗ s^{*} into the semantic class set 𝒮 x \mathcal{S}_{x} strictly when it is absent from the generated samples. This guarantees that we do not artificially inflate the sample count or alter the distribution when the model naturally generates the correct answer. We apply this conditional handling as follows to maximize consistency across the training and evaluation pipelines.
•
When the ground-truth class is already present in the sampled generations, we use the sampled set directly without any modifications during both training and evaluation.
•
When the ground-truth class is unobserved during training, we explicitly include it by feeding the ground-truth sequence y y to the model to compute its log-likelihood and applying a penalty of − 4.6 -4.6 . This penalty scales down its probability mass to reflect that the sequence was not naturally sampled, while still preserving the gradient path for optimization.
•
When the ground-truth class is unobserved during evaluation, we similarly include it but strictly set its sampled count to 0 0 , ensuring the evaluation accurately reflects the true generative distribution of the model.
Deterministically adding the ground-truth completion y y means the estimator is no longer a pure Monte Carlo estimator based solely on samples from p 𝜽 p_{\bm{\theta}} . Instead, it creates a hybrid objective that mixes the generative distribution of the model with a supervised finite-candidate signal. We accept this theoretical trade-off to maintain a robust and differentiable training path.

Sequence-level training methods like Dr.GRPO require comparing N N sampled sequences against the ground truth answer, resulting in an O ⁡ ( N ) O(N) computational complexity per prompt. By contrast, computing the evidential loss in S-EDL requires grouping the generated sequences into semantic classes. A naive pairwise comparison between all sequences scales as O ⁡ ( N 2 ) O(N^{2}) , imposing a substantial computational bottleneck.
To address this scaling gap, we introduce a find-first semantic clustering algorithm as shown in Algorithm 1 . Instead of brute-force pairwise comparison, the algorithm maintains a growing list of cluster representatives and dynamically evaluates each new sequence against them. To optimize the comparison order, we sort the existing representatives by descending string similarity to the new sequence using rapidfuzz [ 2 ] . The equivalence oracle Match is then instantiated in two ways depending on the evaluation domain.
Mathematical tasks Match ​ ( z , [ r 1 , … , r K ] ) \textsc{Match}(z,[r_{1},\dots,r_{K}]) evaluates equivalence using a symbolic verifier (e.g. math-verify [ 21 ] ). It sequentially checks the candidate against the sorted representatives and returns the first index j j where z ≡ r j z\equiv r_{j} , returning ⊥ \bot if no match exists. The string similarity ordering heavily biases the search toward early termination.
General tasks For general subject tasks that rely on an LLM as a judge, Match replaces iterative pairwise checks with a single listwise classification prompt. The judge evaluates the sequence against all current cluster representatives in one forward pass, directly returning the matched index in { 1 , … , K } \{1,\dots,K\} or ⊥ \bot . The system is shown in Section C.5.1 . In this context, the string similarity ordering ensures the most plausible candidate appears first in the prompt context. By grouping the comparisons into a single listwise operation, the temporal complexity of semantic clustering is reduced to exactly O ⁡ ( N ) O(N) , identically matching the scaling of Dr.GRPO.
B.3 Dataset construction
GSM8K
We use the original training and test splits from the official release, along with the provided solutions and chain-of-thought reasoning steps.
MATH
We utilize the official training split and the associated chain-of-thought solutions. For evaluation, we employ the widely adopted MATH-500 test split.
ChemistryQA
We use the official training and test splits. To construct the training data, we prompt the GPT-OSS-120B model [ 1 ] to generate chain-of-thought solutions, retaining only those that yield the correct final answer. This filtering process results in 3062 training samples. For evaluation, we use the complete test set and assess performance directly against the provided ground-truth answers.
FormulaReasoning
We similarly use the official training and test splits. We generate chain-of-thought solutions using the GPT-OSS-120B model and filter for correctness, which yields 4096 training samples. We evaluate on the complete test set using the official ground-truth answers. During the cross-domain evaluation, we observed that models fine-tuned on the MATH dataset experience a severe accuracy degradation for all studied fine-tuning methods. This drop makes calibration performance indistinguishable across the fine-tuning methods, as most samples exhibit uniformly low semantic confidence and low accuracy across all methods. We identified that the models struggle to recall the necessary physical laws. Consequently, we manually augment the testing prompts with the relevant physical laws as hints. These hint-augmented prompts are applied exclusively during the cross-domain evaluation. Furthermore, these hint-augmented prompts are used across evaluation of all fine-tuning methods to ensure fairness.
Examples of the training prompts are provided in Section C.6 .

We start the fine tuning process from the supervised checkpoint at epoch 1. Introducing these structural tokens during LoRA fine tuning causes the model to append random text after the \boxed{} output and occasionally become trapped in repetitive generation loops.
