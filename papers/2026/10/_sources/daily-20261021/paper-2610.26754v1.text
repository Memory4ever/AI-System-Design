Abstract
Expert human readers process large inputs (e.g., code repositories and long documents) by skimming to closely read only what matters. On the other hand, language models process all input tokens through each model layer, resulting in significant processing costs for long-context inputs.
We introduce TokenGate , a small, drop-in component that extends existing trained models to enable end-to-end learnable token pruning over long-context inputs for fast and memory-efficient prefill.
To enable end-to-end learning despite the non-differentiable top- K K operator for token pruning, we introduce token-gated attention , a mechanism inspired by Mixture-of-Experts that re-weights attention logits using token importance scores.
Across diverse tasks, TokenGate achieves 1.4 1.4 - 11.3 × 11.3\times faster time-to-first token (TTFT) and 1.5 1.5 - 3.4 × 3.4\times lower peak memory at no accuracy degradation for prefill in transformers.
Compared to the best-performing prior methods for token-pruning, TokenGate gives up to 6.4 × 6.4\times faster prefill and 2 × 2\times lower peak memory.
TokenGate natively extends both standard transformers (e.g., Qwen3) and hybrid-attention models (e.g., Qwen3.5) with simple lightweight adaptation comparable to standard parameter-efficient fine-tuning.
We make our code available at: https://github.com/tokengate-models/TokenGate .

1 Introduction
Long-context inputs underpin exciting recent language model deployments, where the model’s ability to process vast swaths of personalized user data and live content during inference has led to transformative capabilities in deep research, large-scale document processing, coding agents, and data agents ( OpenAI, 2025b ; Gemini, 2025 ; Anthropic, 2025b ; Anthropic, 2025a ; Anysphere, 2025 ; GitHub, 2025 ) .
When processing large inputs, like code or long documents, experts readers skim to closely read only what matters.
Yet, transformers process every token of their input through each layer, whether or not the token bears critical information. The cost of this full read is attention compute that grows quadratically with input length, as well as MLP compute and KV-cache memory that grow linearly, making long-context prefill a key bottleneck in model serving.
Figure 1: Overview of TokenGate . (a) Layers up to L L prefill all N N context tokens as usual; at layer L L the gate module keeps K K of them, and every layer above L L processes only those K K tokens. (b) The gate module scores each hidden state with a small scoring network, and a top- K K selector forwards the kept hidden states together with their importance scores. (c) Token-gated attention multiplies each attention weight by the gate value g j g_{j} of its key, which enables end-to-end training. (d) On 2WikiMultihopQA question answering, with Qwen3-1.7B, TokenGate pushes the Pareto frontier of accuracy versus time-to-first-token and peak prefill memory; at 95 % 95\% of the full-context accuracy it prefills 3.0 × 3.0\times faster and with 2.7 × 2.7\times less memory, outperforming the best training-free token pruning methods, like FastKV ( Jo et al., 2025 ) and SlimInfer ( Long et al., 2025 ) .
Recent research proposes to address this efficiency challenge for long-context prefill through two primary approaches. First, one body of work proposes training-free token pruning , using attention-based scoring heuristics to prune token hidden states, forwarding only the highest-scoring tokens to upper layers ( Jo et al., 2025 ; Long et al., 2025 ; Jin et al., 2025 ; Shi et al., 2024 ; Yang et al., 2024a ; Fu et al., 2024 ; Chen et al., 2026 ; Wang et al., 2021 ) . These methods are inexpensive to deploy, requiring no model training, but demonstrate limited speedups before degrading accuracy.
Alternatively, a large body of work instead develops architectural modifications to the standard transformer architecture ( Vaswani et al., 2017 ) . These methods offer promising prefill-efficiency improvements, but are expensive to train, often requiring pre-training from scratch and substantially different hardware and software than existing ecosystems ( Dehghani et al., 2018 ; Bae et al., 2025 ; Graves, 2016 ; Raposo et al., 2024 ; Ainslie et al., 2023 ; Kim et al., 2021 ; He et al., 2025 ; Gu & Dao, 2023 ; Dao & Gu, 2024 ) .
To bridge this gap, we ask the question, can we endow existing trained models with improved long-context prefill efficiency while maintaining strong accuracy?
In this work, we introduce TokenGate , a small, drop-in component that extends transformer-based models, enabling end-to-end trainable token pruning over long-context inputs for efficient prefill.
The model forward pass using TokenGate decomposes into three parts, as Figure 1 a shows. First, layers below the gate module perform a standard forward pass, processing all tokens through each layer. Second, tokens pass through the gate module, which produces a score for each token, retaining only the top- K K for continued processing. Third, the layers above the gate module process the selected tokens with token-gated attention , a mechanism that re-weights the attention computation using the generated importance scores. TokenGate reduces prefill compute and memory because pruned tokens are never forwarded through the post-gate layers and these layers never generate KV cache entries.
Token pruning uses a non-differentiable top- K K operator, which presents a challenge for end-to-end learning. We introduce token-gated attention to overcome this issue.
Our method takes inspiration from Mixture-of-Experts (MoE) ( Shazeer et al., 2017 ; Fedus et al., 2022 ) , which achieve sparsity over activated model parameters by gating expert sub-networks. We use a similar form, but instead weight attention logits to achieve sparsity over processed tokens . Using this technique, we demonstrate that we can adapt existing trained models with cost similar to standard adaptation techniques. For instance, we can fine-tune existing models with TokenGate using simple next-token-prediction loss, with no auxiliary loss and total train time similar to supervised fine-tuning on the base model. The resulting TokenGate model matches or exceeds accuracy over the trained base model, while significantly reducing prefill latency and memory.
We evaluate TokenGate on diverse tasks, including code completion, multi-hop QA, multi-doc summarization, medical extraction, and needle-in-a-haystack, using both traditional transformer models and a recent hybrid attention one. Overall, we show the following findings (1) TokenGate reduces TTFT and peak prefill memory by 1.4 1.4 - 11.3 × 11.3\times and 1.5 1.5 - 3.4 × 3.4\times , respectively, at no accuracy degradation compared to the finetuned model baseline with full-context, and outperforms all training-free token pruning methods, by up to 6.4 × 6.4\times faster prefill (TTFT) and 2 × 2\times lower peak prefill memory relative to the next-best baseline,
(2) TokenGate natively extends existing recent hybrid-attention architectures , like Qwen3.5-2B ( Qwen Team, 2026 ) , where it achieves 3.8 × 3.8\times lower TTFT over the full-context baseline at no accuracy degradation, and 2.1 × 2.1\times lower TTFT than the next best-performing token-pruning method at fixed accuracy.
(3) Training models is efficient with TokenGate , incurring minimal overhead compared to standard parameter-efficient fine-tuning techniques, like LoRA ( Hu et al., 2021 ) .
Overall, we summarize our contributions as follows:
•
We introduce TokenGate , a small, drop-in component that extends existing trained models to enable end-to-end learnable token pruning for fast and memory-efficient prefill.
•
We propose token-gated attention , a mechanism for training models end-to-end despite the gate module’s non-differentiable top- K K operator.
•
Our systematic evaluation finds that TokenGate reduces TTFT and peak prefill memory by up to 6.4 × 6.4\times and 2 × 2\times , respectively, compared to the next best-performing baselines, TokenGate natively extends transformer-based models, including recent hybrid-attention architectures.
Further, training is efficient, with total train time comparable to standard parameter-efficient fine-tuning techniques.
2 Related Works
Training-free Token Pruning.
One body of prior work optimizes prefill using training-free token-pruning methods (e.g., FastKV, SlimInfer, DASH, and GemFilter) ( Jo et al., 2025 ; Long et al., 2025 ; Jin et al., 2025 ; Shi et al., 2024 ; Yang et al., 2024a ; Fu et al., 2024 ; Chen et al., 2026 ; Wang et al., 2021 ) . These methods prune token hidden states at a mid-layer of the model using attention-based heuristics to rank tokens, forwarding only the highest-scoring tokens to upper layers of the model. This body of work is closest to ours, however, unlike our work, these methods are not trainable. As we observe in (Section 5 ), these methods offer limited speedups before degrading accuracy because they employ heuristic attention-based token-ranking functions that under-perform our end-to-end trained scoring network, and they prevent co-adaptation of the model backbone with the pruning function, which our end-to-end trainable design enables.
Architectural Modifications.
Several lines of work explore architectural modifications to the self-attention-based transformer ( Vaswani et al., 2017 ) , reducing the compute and memory of processing long-context inputs.
First, one body of work studies architectures that achieve adaptive compute per token through dynamic token routing or learned pruning decisions, but are expensive to train. These works require pre-training from scratch ( Dehghani et al., 2018 ; Bae et al., 2025 ; Graves, 2016 ; Raposo et al., 2024 ; Ainslie et al., 2023 ) or expensive fine-tuning with auxiliary loss terms that fix the token budget during train time, requiring re-training for each inference-time token budget ( Kim et al., 2021 ; He et al., 2025 ; Goyal et al., 2020 ; Rao et al., 2021 ) .
In contrast to all of these works, TokenGate natively extends popular pre-trained language models and is simple and efficient to train. We show that with a single fine-tuning pass, the resulting TokenGate model generalizes across input lengths and token budgets (Section 5 , Appendix D.3 ).
Other works on sub-quadratic architectures for language modeling introduce promising, new algorithms that reduce the per token compute and memory of attention operations, including new compute primitives and sparse attention mechanisms ( Gu & Dao, 2023 ; Dao & Gu, 2024 ; Yang et al., 2024c ; Yang et al., 2024b ; Katharopoulos et al., 2020 ; Sun et al., 2024 ; Gao et al., 2024 ; Liu et al., 2025 ; Yuan et al., 2025 ; Lu et al., 2025 ; Xiao et al., 2024 ; Huang et al., 2025 ; Jiang et al., 2024 ; Lai et al., 2025 ) .
However, unlike TokenGate , these architectures still process all tokens through each model layer.
In Section 5 we demonstrate TokenGate natively extends recent hybrid architectures with sub-quadratic layers ( Qwen Team, 2026 ) , and enables even more efficient prefill.
Conditional Computation. Mixture-of-experts layers achieve sparsity over the activated model parameters, making it possible to efficiently scale model capacity ( Shazeer et al., 2017 ; Fedus et al., 2022 ; Liu et al., 2024 ) . Our work is inspired by the success of this line of work, however, we focus on achieving sparsity over a different axis, the input context length, for scalable long-context prefill.
Decode Optimizations. A large body of work targets the cost of decoding rather than prefill, evicting or merging KV-cache entries after prefill ( Zhang et al., 2023 ; Li et al., 2024 ; Xiao et al., 2023 ; Ge et al., 2023 ; Cai et al., 2024 ; Kim et al., 2025 ) , and performing early exit or per-token routing for decoded tokens ( Schuster et al., 2022 ; Elhoushi et al., 2024 ) . These methods do not improve prefill efficiency and are complementary to prefill optimizations like ours.

3.1 Problem Setting
We consider an LLM input prompt x = [ x R , x D ] x=[x_{R},x_{D}] , where x R = ( x 1 , … , x r ) x_{R}=(x_{1},\dots,x_{r}) is a request instruction or question and x D = ( x r + 1 , … , x N ) x_{D}=(x_{r+1},\dots,x_{N}) are the “documents” needed to respond to it, such as research articles, code repositories, medical records, legal documents, or financial filings.
In practice, x D x_{D} may be supplied by the user or retrieved by a system or an agent given x R x_{R} .
As an example, a user uploads a document study as a PDF to an AI assistant and asks “what are the side effects reported in this study?” ( Google, 2023 ; OpenAI, 2025a ; Anthropic, 2024 ; Google, 2025 ; Microsoft, 2025 ; Adobe, 2025 ; Perplexity AI, 2025 ; ChatPDF, 2025 ) . Here, x R x_{R} corresponds to the user’s question, and x D x_{D} corresponds to the attached document, which can be thousands to hundreds of thousands of tokens. Figure 2 shows two such input prompts from our datasets.
In this setting, the documents are provided only at request time, so its KV cache cannot be precomputed. Our goal is two-fold: we aim to maximize quality , measured by task accuracy, and minimize cost , both prefill time-to-first-token (TTFT), which is the latency users experience before seeing any response, and prefill memory footprint, which limits throughput and concurrent user requests.
4 Trainable Token Pruning with TokenGate
TokenGate is a drop-in neural network component, which places a gate module within a specified transformer layer 1 1
1
The design generalizes to multiple gate modules at different layers, each selecting from the tokens kept by the layers below it and contributing to the token-gated attention in layers above. , L L , to score and prune tokens, as shown in Figure 1 .
In this section, we describe how TokenGate enables trainable token pruning using two key components, the gate module (Section 4.1 ) and token-gated attention (Section 4.2 ). We will then overview an end-to-end training recipe for adapting existing models (Section 4.3 ).
Overall, the full TokenGate forward pass with gating at layer L L decomposes into three phases. First, tokens pass through layers below the gate module, using a standard forward pass. Second, the gate module processes all tokens, producing a score for each, and selecting a subset to prune. Third, the model performs a pruned forward , processing only selected tokens in layers above the gate module, using token-gated attention , which re-weights attention scores using the importance scores.
TokenGate reduces both the compute and memory footprint during prefill by preventing model layers after the gate module from processing pruned tokens or generating KV-cache entries for them.

4.2 Token-Gated Attention

To overcome this challenge, we introduce token-gated attention , which integrates token importance scores generated by the gate module into upper model layers, providing a gradient path. Our method is inspired by Mixture-of-Experts (MoE) ( Shazeer et al., 2017 ) .
In MoE, a router network weights the outputs of expert sub-networks to achieve sparsity over activated model parameters .
In contrast, token-gated attention re-weights attention logits
to achieve sparsity over processed tokens .

4.3 End-to-end Gate Training
Despite TokenGate ’s non-differentiable top- K K selection (Eq. 4 ), the task loss is a differentiable function of the scoring network, almost everywhere. This is due to token-gated attention, which injects the top- K K gate values into the attention logits at each layer above the token gate. When we choose K > 1 K>1 , the gate value g j g_{j} has non-zero derivatives with respect to the scoring network weights. This mirrors how the router is trained in MoE through its top- K K expert selection: the router’s value multiplies the output of each selected expert, just as our gate value multiplies the attention score of each selected token ( Shazeer et al., 2017 ; Fedus et al., 2022 ) . Intuitively, a token whose additional attention mass lowers the task loss receives a larger score. A token that distracts receives a smaller one, allowing the scoring network to learn token importance. This mechanism allows TokenGate to be trained end-to-end jointly with the model backbone simply using standard task losses.

We evaluate on five diverse tasks, including 3 3 LongBench datasets with available train sets ( Bai et al., 2024 ) , 2WikiMultihopQA ( Ho et al., 2020 ) , a multi-hop QA dataset, RepoBench-P ( Liu et al., 2023 ) , a next-line code completion dataset, and MultiNews ( Fabbri et al., 2019 ) , a summarization dataset, as well as two additional tasks, BioDEX’s drug-reaction extraction over biomedical papers ( D’Oosterlinck et al., 2023 ) and needle-in-a-haystack (NIAH) ( Kamradt, 2023 ) . We use the official evaluation metric for each.
Baselines.
We compare TokenGate against state-of-the-art token-pruning methods, FastKV ( Jo et al., 2025 ) , SlimInfer ( Long et al., 2025 ) , DASH ( Chen et al., 2026 ) , and GemFilter ( Shi et al., 2024 ) , as well as sparse attention methods, FlexPrefill ( Lai et al., 2025 ) and MInference ( Jiang et al., 2024 ) . We run each baseline using a fine-tuned base model trained to convergence with LoRA ( Hu et al., 2021 ) ( r = 16 r{=}16 ). We train our model with TokenGate to convergence using the same LoRA configuration. We train both a standard transformer model, Qwen3-1.7B ( Yang et al., 2025 ) , and a hybrid architecture, Qwen3-2B ( Qwen Team, 2026 ) , each on 4 A100 GPUS.
5.1 Fast and Memory-Efficient Prefill
We evaluate the prefill efficiency of models trained with TokenGate .
First, Figure 3 (top) shows the accuracy vs TTFT of each benchmarked method, demonstrating that across all datasets, the trained TokenGate model achieves pareto-optimal performance. Specifically, TokenGate reduces TTFT by 1.4 1.4 – 11.3 × 11.3\times at no accuracy degradation compared to standard prefill, and by 1.2 1.2 – 6.4 × 6.4\times compared to the next best-performing baseline. We measure FastKV, one of the best-performing baselines both at its default layer and at layer 1, the same layer index as the TokenGate . Notably, we observe that compared to FastKV (Layer 1), TokenGate significantly outperforms across all datasets, indicating the promise of end-to-end trainable token pruning for achieving prefill speedups.
Turning our attention to the bottom row of Figure 3 , we study the prefill memory footprint, reporting accuracy versus peak prefill memory. Once again, across all dataset, the TokenGate model establishes the Pareto-frontier, reducing peak memory by 1.5 1.5 – 3.4 × 3.4\times compared to standard prefill at matched accuracy. Moreover the TokenGate model achieves up to 2.1 × 2.1\times lower peak memory compared to the next best-performing baseline at matched accuracy.
Overall, the results demonstrate that TokenGate significantly outperforms prior token-pruning methods, offering an exciting direction for improved prefill efficiency.
5.2 Ablation Study: Understanding the Performance of TokenGate Models
We hypothesize that TokenGate owes its superiority to end-to-end learnable token pruning.
Our visualizations of the kept tokens for real samples (Appendix E )
shows that TokenGate flexibly learns very different pruning patterns in a task-dependent manner,
ranging from keeping answer keywords for question answering to keeping stop-words at the ends of phrases for summarization (Figure 2 ).
To understand this more rigorously, we investigate two key mechanisms: trainable token-selection, and co-adaptation with the trained backbone.
Trainable selector. First, to study the effectiveness of TokenGate ’s learned selector, we compare performance of the trained TokenGate model (Layer 1), to the same model with random token selection on 2WikiMultihopQA. Figure 5 , demonstrates that the trained selector significantly outperforms the random-K selector on accuracy across all token budgets. Moreover, we compare against the FastKV selector applied at the same layer, Layer 1, of the finetuned base model. Notably, the TokenGate selector significantly outperforms the FastKV selector. This result demonstrates the value of an end-to-end trained gate module for token pruning: the trained scoring network leads to far better token selection compared to FastKV, which relies on a heuristic using attention scores that offer only weak signal at early layers, resulting in accuracy degradation for aggressive pruning.
Co-adaptation. Secondly, we analyze the effect of co-adaptation for TokenGate , which allows the model backbone and gate module to co-adapt. We compare the performance of random-K selection over the TokenGate model to the random-K selection over the finetuned base model. Notably, with the same random-K selector, the TokenGate model still outperforms the fine-tuned model, achieving higher accuracy across all token budgets, as Figure 5 shows. This result shows that TokenGate ’s end-to-end training allows the model to become more robust to token-pruning, likely redistributing information among tokens.
Overall, the results show that end-to-end training with TokenGate enables state-of-the-art prefill performance through two complementary mechanism: the effectiveness of the learned scoring network, and co-adaptation, which allows the model to adapt jointly with the gating module for improved robustness to token pruning.

Figure 5 shows the accuracy vs TTFT of both methods at varying layers on the NIAH 32K dataset, demonstrating that TokenGate ’s strong performance extends to the hybrid-attention model. TokenGate (Layer 3) matches the accuracy of standard prefill at 3.8 × 3.8\times lower TTFT, and 2.1 × 2.1\times lower TTFT than the best-performing FastKV run at the same accuracy.

5.4 Gate Training Efficiency
We evaluate overhead of training models with TokenGate compared standard models, both with LoRA fine-tuning ( r = 16 r=16 ).
Table 2 in Appendix D.1 compares both, reporting total training time in A100 hours and the average per-step time during training for each evaluated dataset.
Overall, we observe that a TokenGate step is slower by 1.3 × 1.3\times compared to the baseline due to its sampling at two token budgets per step. However, the TokenGate train runs converge after fewer steps on four of five tasks, leading to modestly reduced overall training time compared to the standard training.
6 Conclusion
In this work, we introduced TokenGate , a neural network component that extends existing trained transformer models, enabling end-to-end trainable token pruning using token-gated attention .
We demonstrate that that across diverse tasks, TokenGate reduces TTFT and peak prefill memory by up to 11.3 × 11.3\times and 3.4 × 3.4\times , respectively, at no accuracy degradation compared to standard prefill, and by up to 6.4 × 6.4\times and 2 × 2\times , respectively, compared to the best performing baselines.
Crucially, TokenGate is compatible with diverse transformer-based architectures, is simple to train, and incurs minimal training overhead, making it a promising drop-in replacement for standard fine-tuning over trained backbones.
In the future, we envision models trained with TokenGate will enable a broad range of applications, including medical extraction, deep research, and coding agents, where processing long-context inputs is critical, but currently prohibitively expensive.

Appendix A Efficient kernels for TokenGate
Token-gated attention (Eq. 8 ) differs from standard causal attention in two ways: a per-query temperature τ i ℓ ​ h \tau^{\ell h}_{i} and a per-key, per-head gate term added to the attention logits. The temperature is applied by scaling each query before the attention call, so it needs no kernel support. The gate term needs a per-key bias, which standard fused kernels do not accept, and unfused or score-modifying kernels are substantially slower. We therefore patch FlashAttention-2 ( Dao, 2023 ) to read a per-key, per-head bias vector, which it adds to each tile of attention scores before the online softmax. This keeps the fused structure of the kernel: the bias adds one vector load per key block, and a biased call costs 1.0 1.0 – 1.1 × 1.1\times a plain one. The kernel supports head dimensions 128 (Qwen3) and 256 (Qwen3.5).
Training. The same kernel provides the backward pass: the gradient of the bias of key j j is the sum over queries of the gradient of its attention scores, which the kernel accumulates alongside the usual gradients, so the task loss reaches the scoring network through the fused kernel. The two targets of each training step (Eq. 10 ) are packed into one variable-length call. For Qwen3.5, whose Gated DeltaNet layers are not supported by this path, we train with FlexAttention ( Dong et al., 2024 ) and add the bias as a score modification,
but more optimized kernels are possible.
Inference. Layers at and below the gate use the standard fused kernel (cuDNN on A100). The pruned forward of the post-gate layers is captured as one CUDA graph per padded length: the kept sequence is padded to a multiple of 64, and pad keys receive a bias of − 10 9 -10^{9} so the result is exact. The gather of the KV cache of layers ℓ ≤ L \ell\leq L to the kept tokens (Appendix B ) runs on a separate stream, concurrently with the post-gate layers. During decoding, the gate term of each kept key is fixed, so it is folded once into an additive attention mask per post-gate layer and decoding uses standard attention.
Appendix B Decoding with TokenGate
The layers above the gate, ℓ > L \ell>L , never compute KV entries for pruned tokens, so during decoding each new token attends there only to the kept tokens S S and the tokens generated so far. The layers at and below the gate, ℓ ≤ L \ell\leq L , process the full context during prefill, so by default their KV cache holds every context token, and decode tokens attend to the full context in these layers and to the pruned context above them. Optionally, TokenGate can also prune the cache of layers ℓ ≤ L \ell\leq L .
In the post-gate layers, decode tokens use the same token-gated softmax as prefill (Eq. 8 ). The gate term softplus ⁡ ( γ ℓ ​ h ) ​ b j \mathrm{softplus}(\gamma^{\ell h})\,b_{j} of each kept key is computed once at prefill and stored with the cache as a constant per-key bias, and each generated token is a non-prunable token with gate term 0 0 (Eq. 3 ). The temperature τ i ℓ ​ h \tau^{\ell h}_{i} of a decode query follows Eq. 7 , with m i m_{i} its rank among the kept and generated tokens and p i p_{i} its original position; generated tokens continue from the original position of the last prompt token.
Appendix C Details of Experimental Setup
C.1 Datasets
All datasets are evaluated on Qwen3-1.7B with greedy decoding for up to 1024 new tokens. Each model is fine-tuned on a training set that is disjoint from its evaluation set.
RepoBench-P. RepoBench-P ( Liu et al., 2023 ) is a next-line code completion task. We use the LongBench ( Bai et al., 2024 ) version, whose prompts contain cross-file code context and an in-file prefix, and the model completes the next line. We evaluate on all 500 samples (mean context 11.0k tokens, up to 39k) and report edit similarity, 1 − Levenshtein / max ⁡ ( length ) 1-\mathrm{Levenshtein}/\max(\text{length}) , on the first generated line. For training, we use 14.9k samples from the RepoBench v1.1 Python and Java cross-file splits, deduplicated against the evaluation set.
2WikiMultihopQA. 2WikiMultihopQA ( Ho et al., 2020 ) is a multi-hop question answering task over several Wikipedia passages; we use the LongBench version. We evaluate on all 200 samples (mean context 7.5k tokens) and report token-level F1 against the gold answers. For training, we use 20k 2WikiMultihopQA questions with contexts rebuilt from full Wikipedia articles and decontaminated against LongBench.
MultiNews. MultiNews ( Fabbri et al., 2019 ) is a multi-document news summarization task; we use the LongBench version. We evaluate on all 200 samples (mean context 2.7k tokens, up to 14k) and report ROUGE-L. For training, we use 44.8k samples from the MultiNews training split in the LongBench prompt format.
BioDEX. BioDEX-Reactions ( D’Oosterlinck et al., 2023 ) is an adverse drug reaction extraction task over full-text biomedical papers: given a paper, the model lists the reported adverse reactions as MedDRA terms. We evaluate on 500 samples drawn from the official validation split with articles between 2k and 39k tokens (mean 4.5k), and report set F1 between predicted and gold reactions, counting a predicted reaction as correct if it matches a gold term up to substring containment. For training, we use 9.8k papers from the official training split.
NIAH. NIAH ( Kamradt, 2023 ) is needle-in-a-haystack retrieval at 16k tokens. The haystack is built from Paul Graham essays, and the needle, “The best thing to do in city is activity .”, is inserted at a sentence boundary at a given depth; the model is then asked for the best thing to do in that city. The 200 evaluation samples cover 20 held-out cities at 10 depths evenly spaced from 0 to 1, and we report accuracy, i.e., whether the gold activity appears in the answer. For training, we use 12k generated samples with haystacks of 14k–16.4k tokens and uniformly random depths; the essays and cities are disjoint from the evaluation set.
C.2 Baselines
All baselines run on the same SFT model, fine-tuned on each dataset with LoRA ( r = 16 r{=}16 , α = 32 \alpha{=}32 ) on the query and value projections of all layers. The pruning baselines keep all non-document tokens and prune only document tokens, with the same kept-token budgets K K as TokenGate ( 64 64 – 8192 8192 ). We briefly describe each baseline below, and the configurations used. We run each method, applying its optimization for prefill-only.
FastKV ( Jo et al., 2025 ) . At a token-selective propagation layer, FastKV scores tokens by the attention they receive from a window of the last queries, max-pools the scores, and propagates only the top- K K tokens to deeper layers. We use the paper’s observation window of 8 tokens and pooling kernel of 7. We run it at layer 13 by default, following the paper and its hyper-parameter search, which chooses relative depth of 46 % 46\% for its models. We additionally run the baseline at layer 1, the layer at which we apply TokenGate , to compare performance at a matched layer index.
SlimInfer ( Long et al., 2025 ) . SlimInfer prunes hidden states in several stages: at layers 8, 17 and 25 it keeps 3 ​ K 3K , 1.5 ​ K 1.5K and K K tokens, scoring 64-token blocks by the attention of the last 4 queries. We use the paper’s block size, kernel and layer schedule, and its budget ratios, following the paper’s hyperparameter search.
GemFilter ( Shi et al., 2024 ) . GemFilter runs the first layers on the full prompt, selects the top- K K tokens by the last query’s attention scores at a filter layer, and then runs a fresh forward pass over only the selected tokens. We use filter layer 12, at the same relative depth (0.4) as recommended by the original paper, and the official pooling kernel.
DASH ( Chen et al., 2026 ) . DASH halts tokens whose representations have stabilized: at layer 11 ( 0.4 × 0.4\times the number of layers, the official default), it ranks tokens by the change in their hidden state from the previous layer and drops the most stable ones, keeping K K document tokens.
FlexPrefill ( Lai et al., 2025 ) . FlexPrefill is a sparse-attention method: it keeps all tokens but computes a query-adaptive sparse attention pattern during prefill, controlled by a cumulative-attention threshold γ \gamma . We use the official kernel and its recommended hyperparameters (divergence threshold τ = 0.1 \tau{=}0.1 , which decides per head whether to use a query-aware or a vertical-slash pattern; minimum budget 1024; block size 128) and sweep γ ∈ { 0.1 , 0.2 , … , 0.9 , 0.95 , 0.97 } \gamma\in\{0.1,0.2,\dots,0.9,0.95,0.97\} , extending the range until accuracy degrades.
MInference ( Jiang et al., 2024 ) . MInference uses per-head sparse attention patterns found by an offline search, which for Qwen3-1.7B selects vertical-and-slash patterns for all heads. We run the official implementation with patterns searched on Qwen3-1.7B, and sweep its budget by scaling the vertical and slash sizes of the searched configuration by { 0.25 , 0.5 , 1 , 2 , 4 } \{0.25,0.5,1,2,4\} , which keeps the searched pattern shape.
Implementation and timing. All methods run the same fine-tuned backbone in bf16 with the LoRA adapter folded into the weights, and all dense decoder layers are torch.compile d. Dense causal attention uses the same fused kernel in every lane (cuDNN on the A100; FlashAttention-2 on Qwen3.5-2B); the only kernel that differs is in the TokenGate ’s post-gate layers, which require a per-key bias and use a FlashAttention-2 variant at 1.0 1.0 – 1.1 × 1.1\times the cost of a plain call (Appendix A ). FastKV and GemFilter run through the compiled layers directly. The official SlimInfer and DASH prefills bypass the compiled layer forward, so we reimplemented both in compile-friendly form and verified that they select the same tokens as the official code (DASH bit-identical; SlimInfer identical selection), which made them 1.2 1.2 – 2.4 × 2.4\times and 1.25 1.25 – 1.56 × 1.56\times faster; we report the faster versions. MInference is compiled around its sparse kernel with identical accuracy, and FlexPrefill runs eager, its fastest configuration, since its data-dependent block selection triggers recompilation under torch.compile . The pruned forward of the TokenGate and of FastKV is captured as one CUDA graph per padded length; the remaining baselines have no fixed-shape pruned phase to capture. Both FastKV and the TokenGate optionally prune the KV cache of the layers below their pruning layer to the selected tokens once prefill completes, so that decoding holds K K entries at every layer; we disable this setting for both in all experiments since KV cache pruning presents an orthogonal set of optimizations and our experiments instead isolate the effect of token pruning for prefill optimization (Appendix B ). Inference timings are measured at batch size of 1 on one A100.

C.4 Extension to Alternative Hybrid-Attention Architectures
Qwen3.5 architecture. Qwen3.5-2B ( Qwen Team, 2026 ) is a hybrid-attention model with 24 layers. D.4 Ablating the TokenGate Design
In this section we ablate the TokenGate design (Section 4 ). First, Figure 7 (left) compares the accuracy vs TTFT performance of TokenGate on BioDEX with Qwen3-1.7B against three variants: (a) removing the full-context loss term L K full L_{K_{\mathrm{full}}} from the per-step loss (Eq. 10 ), (b) removing the temperature scaling term during token-gated attention, and (c) removing the head-wise scaling. The results demonstrate that training without the full-context loss most significantly degrades inference accuracy at full-context, and removing the temperature scaling and head-wise gain also degrades accuracy, leading to sub-optimal accuracy vs TTFT.
We additionally analyze layer selection, a hyperparameter for TokenGate . Figure 7 (right) shows performance on BioDEX of Qwen3-1.7B models trained with the TokenGate at Layer 0, 1, and 2. Notably, the model with gating at Layer 0 is Pareto-suboptimal relative to the Layer 1 and 2 gate models, suggesting that the Layer 0 post-attention residuals provide insufficient signal for the TokenGate scoring network. On the other hand, the Layer 1 and Layer 2 TokenGate models both lie along the Pareto frontier, suggesting that by Layer 1, the post-attention residuals passed to the gate module are sufficiently rich to learn an effective scoring network for trainable token pruning.

Selection is global, not local. In every sample the kept tokens fall in all ten deciles of the context, so the gate does not reduce to a recency window or to the start of the document. At the same time it concentrates the budget where the task needs it: on NIAH, 21 21 of the 24 24 tokens of the needle sentence, which sits at 78 % 78\% depth in a 15,843 15{,}843 -token haystack, are among the 64 64 kept tokens, and the model answers exactly. The same holds for all eight NIAH prompts we checked, whose answer at K = 64 K=64 matches the reference.
What is kept, and what it costs. Table 4 summarizes the five examples. On 2WikiMultihopQA, BioDEX and NIAH the gate keeps content: entities and years, the terms that describe a medical case, and, where the reference answer occurs verbatim in the context, a large share of its tokens (all of the needle’s answer on NIAH). On RepoBench-P the selection is instead dominated by code structure: most kept tokens contain no letter, and they are spread thinly over the retrieved files, whereas on NIAH most kept tokens have a kept neighbor and form contiguous spans. This suggests that for code completion the post-gate layers use the kept tokens more as anchors on the structure of the retrieved files than as a copy of their content. The examples also show where pruning costs accuracy: on MultiNews the gate keeps mostly function words and under-keeps capitalized tokens, and the summary at K = 256 K=256 reports the right events but gets the names and places wrong, and for drug reaction extraction on BioDEX the pruned model recovers one of the two reactions found with the full context.
