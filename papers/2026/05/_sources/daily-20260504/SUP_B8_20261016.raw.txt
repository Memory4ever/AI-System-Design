Telegram: inbound image arrives as file path, not native vision content — model never sees pixels · Issue #19287 · NousResearch/hermes-agent · GitHub (https://github.com/NousResearch/hermes-agent/issues/19287)
citeturn39209search2 [wordlim: 200] Published: 5 months ago; Crawled: 2 months ago; opened on May 3, 2026 ... Start Hermes with a vision-capable model (e.g. `xiaomi/mimo-v2-omni`) ...   * Hermes Agent version: latest (2026-05-03)

## Steps to Reproduce

  1. Start Hermes with a vision-capable model (e.g. `xiaomi/mimo-v2-omni`)
  2. Send an image via Telegram
  3. Inspect the agent conversation — the user turn contains only the file path text, no `image_url` content part

## Environment

  * Hermes Agent version: latest (2026-05-03)
  * Platform: Telegram
  * Model: xiaomi/mimo-v2-omni (supports_vision: true)
  * OS: Linux

## Suspected Root Cause

In `gateway/platforms/telegram.py`, `_handle_media_message()` downloads the image and caches it, but the resulting event/message does not trigger `build_native_content_parts()` from `agent/image_routing.py` to convert the local file path into a base64 content part.

The `vision_analyze` tool itself already supports local file paths (see `tools/vision_tools.py` lines 472-480), so the fallback path also works — but only if the agent explicitly calls the tool. The native path should be automatic for vision-capable models.

## Related Code

  * `agent/image_routing.py` — `decide_image_input_mode()`, `build_native_content_parts()`
