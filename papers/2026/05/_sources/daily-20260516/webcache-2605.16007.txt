L64: # Ascend-RaBitQ: Heterogeneous NPU-CPU Acceleration of Billion-Scale Similarity Search with 1-bit Quantization
L65: 
L66: Fujun He^{†}, Chuyue Ye^{†}, Huaxiang Cai^{†}, Zetao Lv^{†}, Baolong Cui^{†}, Wenru Yan^{§}, Chao Zhan^{§}, Zigang Zhang^{§}, Hao Yi^{†}, Jie Xiang^{†}, Xiabing Li^{†}, Yuhang Gai^{†}, Ziyang Zhang^{†}, Pengfei Zheng^{†}, Yunfei Du^{†} Note: Corresponding authors. Affiliation: ^{†}Huawei Technologies Co., Ltd., ^{§}JD.com
L67: ###### Abstract.
L68: Vector similarity search is a critical component of modern AI systems, but traditional CPU-based implementations face fundamental scalability bottlenecks for billion-scale corpora due to prohibitive computational overhead and memory bandwidth limitations.
L69: While Neural Processing Units (NPUs) offer orders-of-magnitude higher compute density, existing CPU/GPU-optimized 1-bit RaBitQ quantization implementations cannot be directly ported to NPU architectures due to fundamental hardware mismatches, and homogeneous design paradigms struggle to simultaneously balance accuracy, memory footprint, and performance.
L70: This paper presents Ascend-RaBitQ, the first heterogeneous NPU-CPU optimized IVF-RaBitQ system for billion-scale vector search, built on the core insight that decoupling coarse ranking (NPU) from fine ranking (CPU) allows each stage to leverage its optimal hardware, breaking the long-standing accuracy-memory-performance trade-off.
L71: We propose a three-stage heterogeneous pipeline comprising AI Core-accelerated coarse ranking on 1-bit quantized vectors, on-device AI CPU Top-$k$ processing, and host CPU fine re-ranking on full-precision vectors.
L72: We introduce four NPU architecture-native optimizations: fused AIC-AIV operators for parallel distance computation, computation flow restructuring to exploit rotation orthogonality, fine-grained index block-level load balancing that breaks query boundaries, and intra-NPU pipeline parallelism between AI Core and AI CPU to mask Top-$k$ latency.
L73: Evaluation on standard datasets shows that Ascend-RaBitQ achieves 3.0$\times$ to 62.8$\times$ faster index construction than the CPU baseline, up to 4.6$\times$ throughput improvement over the fastest CPU IVF-RaBitQ implementation, and over 100$\times$ over the mathematically equivalent CPU baseline, while demonstrating encouraging scalability on distributed multi-NPU systems.
L74: ###### Keywords:
L75: 
L76: Approximate Nearest Neighbor Search, Billion-scale Vector Retrieval, 1-bit Vector Quantization, NPU Acceleration, NPU-CPU Cooperation
L77: ## 1. Introduction
L78: Vector similarity search has become a critical infrastructure component in modern AI applications, powering retrieval-augmented generation (RAG) (cite50†Jiang et al., 2025b ; cite51†Shen et al., 2025 ; cite52†Quinn et al., 2025 ; cite53†Kim and Mahajan, 2026 ), search and recommendation systems (cite54†Reimers and Gurevych, 2019 ; cite55†Barkan and Koenigstein, 2016 ; cite56†Liang et al., 2024 ; cite57†Khattab and Zaharia, 2020 ), and computer verison (cite58†Fang et al., 2022 ; cite59†Frome et al., 2013 ; cite60†Vo et al., 2019 ; cite61†Li et al., 2022 ).
L79: As large language models (LLMs) and agentic AI systems continue to evolve, the demand for efficient, high-throughput vector retrieval has grown exponentially, with industry reports indicating vector databases must now handle billion-scale corpora while maintaining millisecond-level latency and cost-effectiveness (cite62†Johnson et al., 2019 ; cite63†Shi et al., 2025 ; cite64†Adams et al., 2025 ).
L80: Traditional vector search systems predominantly run on CPU clusters, employing indexing structures such as inverted file systems (IVF) and product quantization (PQ) to reduce search space (cite65†Jegou et al., 2011 ; cite66†Ge et al., 2013 ; cite67†Babenko and Lempitsky, 2014 ), but face fundamental scalability challenges: (1) computational bottlenecks—CPU-based distance computations become prohibitively expensive as corpus size grows (cite62†Johnson et al., 2019 ); (2) memory bandwidth limitations—fetching high-dimensional vectors from main memory dominates latency, forming a well-documented "memory wall" for vector retrieval workloads (cite62†Johnson et al., 2019 ).
L81: Neural Processing Units (NPUs) have emerged as transformative accelerators for deep learning workloads, delivering orders-of-magnitude improvements in throughput compared to CPUs (cite68†Liao et al., 2021 ). This exceptional compute density has driven its widespread adoption in data centers (cite69†Huang et al., 2025 ; cite70†Zuo et al., 2025 ; cite71†DeepSeek-AI, 2026 ), while making it highly suitable for data-intensive workloads such as vector similarity search.
L82: However, realizing this potential for vector retrieval introduces two fundamental challenges. First, NPUs feature limited on-device memory capacity (typically 32-64 GB HBM) compared to CPU clusters with terabyte-scale DRAM pools, making it infeasible to store billion-scale high-dimensional vector indices entirely on-device.
L83: Scaling capacity by adopting multiple NPUs is prohibitively expensive, while simply offloading computation to NPUs incurs costly host-device data transfers that erase acceleration gains. Second, while aggressive quantization can reduce index size to fit NPU memory, existing schemes such as PQ incur severe accuracy degradation at extreme compression ratios, forcing a trade-off between memory footprint and retrieval quality.
L84: Recent advances in quantization theory offer a promising solution: Randomized Bit Quantization (RaBitQ) (cite72†Gao and Long, 2024 ) is a 1-bit quantization scheme with two core characteristics—formal theoretical error guarantees proven to be asymptotically optimal, and $32\times$ memory compression compared to FP32 vectors. At the same compression ratio, RaBitQ achieves substantially higher accuracy than PQ.
L344: On the high-dimensional Cohere 10M dataset (768-dimensional text embeddings), Ascend-RaBitQ maintains a stable 1.8$\times$ speedup over CPU 1-bit+SQ across all Top-$k$ settings, demonstrating robust performance on text-based semantic search workloads.
L345: Across all configurations, the CPU 1-bit variant without query-side quantization trails by one to two orders of magnitude: Ascend-RaBitQ outperforms it by 13.9$\times$ on SIFT1M and by over 100$\times$ on SIFT100M. Critically, this performance gap does not stem from memory bandwidth limitations but from the absence of query SQ, which prevents CPU from efficiently computing inner products between two 1-bit quantized vectors using SIMD instructions.
L346: It is worth emphasizing that our Ascend-RaBitQ also does not apply query-side SQ and therefore remains mathematically equivalent to the CPU 1-bit variant, offering higher precision than methods that incorporate query SQ. The stark performance advantage over the mathematically equivalent CPU 1-bit implementation thus reflects the fundamentally superior compute throughput of the NPU’s computation units.
L347: Extending query-side SQ optimization to the NPU pipeline represents a promising direction for future work to further improve end-to-end throughput.
L348: Beyond query performance, we further compare the end-to-end index construction time across all datasets, as shown in Table cite97†1 . Ascend-RaBitQ achieves a speedup of 3.0$\times$ to 62.8$\times$ over the CPU 1-bit IVF-RaBitQ implementation.
L349: This significant improvement is achieved by offloading both the K-means clustering step for IVF partition and the 1-bit quantization encoding step to the Ascend’s computation units, effectively eliminating the memory bandwidth bottleneck that plagues CPU-based vector processing.

L281: ### 3.4. Distributed Scaling
L282: As vector dataset sizes continue to grow or throughput requirements increase further, single NPU devices will eventually encounter bottlenecks in memory capacity or computing resources. To address this challenge, Ascend-RaBitQ is designed with native distributed scaling capability. We adopt a cluster-aware load balancing strategy to evenly partition quantized vector datasets across multiple NPU devices, ensuring that the number of vectors in each inverted list is balanced across all nodes.
L283: During the index construction phase, each NPU independently performs quantization operations on its responsible vector shard in parallel, achieving near-linear speedup with increasing number of devices. During retrieval, multiple NPU devices simultaneously process the same query batch, independently performing their local coarse search computation tasks. Finally, the CPU aggregates results from all NPU nodes and performs global re-ranking to output the final accurate Top-$k$ retrieval results.
L284: ## 4. Evaluation
L285: We conduct extensive experiments to evaluate the performance of our proposed Ascend-RaBitQ system on a variety of standard vector search datasets, comparing against state-of-the-art CPU IVF quantization implementations and the native NPU full-precision baseline. All experiments are performed on a server equipped with 8 Ascend NPUs and a host CPU. Each NPU features 48 AIV cores and 24 AIC cores clocked at 1.85 GHz, with 64 GB HBM. The host CPU has 192 cores at 2.6 GHz and 1.5 TB DDR4 memory.
L286: Unless otherwise specified, experiments use a single NPU together with the host CPU.

L325: ### 4.2. NPU Platform Native Comparison: Ascend-RaBitQ vs. IVF-Flat
L326: We conduct a comprehensive performance comparison between Ascend-RaBitQ and the native Ascend IndexSDK IVF-Flat implementation on the Ascend NPU platform. An important practical consideration motivates our experimental design here: the full-precision IVF-Flat index requires storing the entire dataset in NPU memory, which imposes significant memory constraints. For a single Ascend NPU with 64 GB HBM, only the SIFT1M dataset (512 MB full-precision index) can be accommodated.

L66: Fujun He^{†}, Chuyue Ye^{†}, Huaxiang Cai^{†}, Zetao Lv^{†}, Baolong Cui^{†}, Wenru Yan^{§}, Chao Zhan^{§}, Zigang Zhang^{§}, Hao Yi^{†}, Jie Xiang^{†}, Xiabing Li^{†}, Yuhang Gai^{†}, Ziyang Zhang^{†}, Pengfei Zheng^{†}, Yunfei Du^{†} Note: Corresponding authors. L67: ###### Abstract.
L68: Vector similarity search is a critical component of modern AI systems, but traditional CPU-based implementations face fundamental scalability bottlenecks for billion-scale corpora due to prohibitive computational overhead and memory bandwidth limitations.
L69: While Neural Processing Units (NPUs) offer orders-of-magnitude higher compute density, existing CPU/GPU-optimized 1-bit RaBitQ quantization implementations cannot be directly ported to NPU architectures due to fundamental hardware mismatches, and homogeneous design paradigms struggle to simultaneously balance accuracy, memory footprint, and performance.
L70: This paper presents Ascend-RaBitQ, the first heterogeneous NPU-CPU optimized IVF-RaBitQ system for billion-scale vector search, built on the core insight that decoupling coarse ranking (NPU) from fine ranking (CPU) allows each stage to leverage its optimal hardware, breaking the long-standing accuracy-memory-performance trade-off.
L71: We propose a three-stage heterogeneous pipeline comprising AI Core-accelerated coarse ranking on 1-bit quantized vectors, on-device AI CPU Top-$k$ processing, and host CPU fine re-ranking on full-precision vectors.
L72: We introduce four NPU architecture-native optimizations: fused AIC-AIV operators for parallel distance computation, computation flow restructuring to exploit rotation orthogonality, fine-grained index block-level load balancing that breaks query boundaries, and intra-NPU pipeline parallelism between AI Core and AI CPU to mask Top-$k$ latency.
L73: Evaluation on standard datasets shows that Ascend-RaBitQ achieves 3.0$\times$ to 62.8$\times$ faster index construction than the CPU baseline, up to 4.6$\times$ throughput improvement over the fastest CPU IVF-RaBitQ implementation, and over 100$\times$ over the mathematically equivalent CPU baseline, while demonstrating encouraging scalability on distributed multi-NPU systems.
L74: ###### Keywords:
L75: 
L76: Approximate Nearest Neighbor Search, Billion-scale Vector Retrieval, 1-bit Vector Quantization, NPU Acceleration, NPU-CPU Cooperation
L283: During the index construction phase, each NPU independently performs quantization operations on its responsible vector shard in parallel, achieving near-linear speedup with increasing number of devices. During retrieval, multiple NPU devices simultaneously process the same query batch, independently performing their local coarse search computation tasks. Finally, the CPU aggregates results from all NPU nodes and performs global re-ranking to output the final accurate Top-$k$ retrieval results.
L284: ## 4. Evaluation
L285: We conduct extensive experiments to evaluate the performance of our proposed Ascend-RaBitQ system on a variety of standard vector search datasets, comparing against state-of-the-art CPU IVF quantization implementations and the native NPU full-precision baseline. All experiments are performed on a server equipped with 8 Ascend NPUs and a host CPU. Each NPU features 48 AIV cores and 24 AIC cores clocked at 1.85 GHz, with 64 GB HBM. The host CPU has 192 cores at 2.6 GHz and 1.5 TB DDR4 memory.
L286: Unless otherwise specified, experiments use a single NPU together with the host CPU.

L325: ### 4.2. NPU Platform Native Comparison: Ascend-RaBitQ vs. IVF-Flat
L326: We conduct a comprehensive performance comparison between Ascend-RaBitQ and the native Ascend IndexSDK IVF-Flat implementation on the Ascend NPU platform. An important practical consideration motivates our experimental design here: the full-precision IVF-Flat index requires storing the entire dataset in NPU memory, which imposes significant memory constraints. For a single Ascend NPU with 64 GB HBM, only the SIFT1M dataset (512 MB full-precision index) can be accommodated.
