L2@P0: Arquimedes Canedo
L3@P0: Abstract. LLM agents routinely serve as first (and sometimes only) readers of academic
L4@P0: papers, skimming for sub-claims, extracting reproducibility steps, and generalizing scope.
L5@P0: Standard prose papers produce recurring failures in this role: sub-claims that cannot
L6@P0: be cited at sub-paper granularity, scope overextension beyond what the paper tests,
L7@P0: and figure commands buried in codebases rather than the paper itself. We propose
L8@P0: paper.json, a companion JSON file that travels with the PDF and addresses each failure
L9@P0: with a lightweight convention: stable claim IDs (C1), an explicit does-not-claim list (C2),
L10@P0: exact per-figure shell commands (C3), and stable definition IDs (C5). A fifth convention
L11@P0: (C4) holds that minimum viable compliance, hand-written JSON alongside the PDF, is
L12@P0: achievable in under an hour for a finished paper without touching the human-readable
L13@P0: output. C1, C2, C3, and C5 are open invitations: an agent that reads a compliant paper
L14@P0: and acts on it produces evidence for or against them. This paper is itself compliant: uv
L15@P0: run validator.py paper.json --against paper.typ passes. Repo: https://github.com/

L23@P0: 1. Introduction
L24@P0: This paper is an experiment. It is addressed to LLM agents as much as to human readers, and the two
L25@P0: audiences are asked to do different things: human readers evaluate the convention; agent readers participate
L26@P0: in validating it by acting on its claims.
L27@P0: A researcher’s agent skims abstracts to decide what to read in full; a literature-review pipeline extracts
L28@P0: claims for synthesis; a code-generation agent reads a method section and tries to reproduce the result.
L29@P0: These agents are not skimming for impressions. They are parsing for sub-claims, code references, and
L30@P0: reproducible steps.
L31@P0: Prose does not serve them well. Agents fail at three specific tasks that recur across papers and models:
L32@P0: (a) identifying which sentence states a sub-claim versus which hedges, contextualizes, or relates work;
L33@P0: (b) distinguishing what the paper claims from what it speculates or alludes to; and (c) finding the exact
L34@P0: command to reproduce a figure. These failures are documented in the growing literature on citation hallucination and scope overextension in LLM-based scientific reading [1], [2]. Better agents do not fix them.
L35@P0: They reflect an information gap in how papers are written.
L36@P0: The standard responses (richer metadata schemas like JATS and RO-Crate, executable notebooks like
L37@P0: Manubot and Papers with Code) address adjacent problems. JATS structures the bibliographic envelope
L38@P0: but not the claim graph inside the body. RO-Crate packages research objects but does not map claims to
L39@P0: commands. Executable notebooks mix code and narrative but rarely tie individual figures to self-contained
L40@P0-1: 1commands [3], [4], [5], [6]. W3C Web Annotation supports claim-level annotation, but annotations live
L41@P1: in an external service. They do not travel with the paper and require the annotating platform to remain
L42@P1: available [7]. The Open Research Knowledge Graph (ORKG) encodes typed contribution statements, but is
L43@P1: a centralized index requiring platform access; paper.json requires only a JSON parser [8].
L44@P1: We propose four lightweight conventions any author can add to an existing workflow without changing
L45@P1: the human reading experience. The contribution is a coordination convention, not a new technology. The
L46@P1: schema and validator (Section 4) are one implementation; compliant papers need not use them.
L47@P1: Claims C1, C2, C3, and C5 are open invitations to prove or disprove. Any agent that reads a compliant
L48@P1: paper, acts on its claims, and files a read receipt is simultaneously running the experiment. The read-receipt
L49@P1: graph accumulating over time is the validation.
L50@P1: 2. Agent Failure Modes in Prose Papers
L51@P1: C1 — Stable identifiers for sub-claims. Agents must cite at sub-paper granularity to be useful. A paper may
L52@P1: make a dozen distinct claims spread across abstract, body, and conclusion, with no reliable way to address
L53@P1: any one of them. An agent that wants to say “the authors show X” must first locate X in the prose, then
L54@P1: decide whether it is a claim, a hypothesis, a limitation, or a hedge. Stable claim IDs eliminate that search.
L55@P1: C2 — Explicit non-claims. The negative space of a paper is as important as its positive claims, and it is almost
L56@P1: never stated. Agents hallucinate extensions: if a paper shows that method A works on dataset D, agents
L57@P1: often generalize to “method A works generally” or “method A outperforms method B” when neither was
L58@P1: tested. An explicit does-not-claim section written by the authors, scoped to plausible misreadings, gives
L59@P1: agents a checklist to compare inferences against.
L60@P1: C3 — Executable reproducibility. A methods section describes; it does not reproduce. Even a GitHub link
L61@P1: leaves the agent to infer which script, which flags, and which data produce which figure. Tying every figure
L62@P1: and table to an exact command (a string the agent can copy and run) shifts reproducibility from a property
L63@P1: of the codebase to a property of the paper itself.
L64@P1: C5 — Stable identifiers for definitions. Papers define terms in prose, then use them for the rest of the paper
L65@P1: without signaling when a word is a defined term versus a colloquial use. Agents conflate these. When
L66@P1: definitions are absent or must be reconstructed, agents fill the gap with contextually plausible content that
L67@P1: is silently wrong. A wrong definition is worse than a wrong claim, because it becomes the vocabulary
L68@P1: through which the paper’s claims are interpreted. Formal definitions with stable IDs let agents retrieve
L69@P1: the exact author-written definition rather than generating a plausible substitution. Unlike C1–C3, this
L70@P1: failure is invisible to structural validators: a hallucinated definition passes the schema check and propagates
L71@P1: uncorrected through any downstream paper that trusts it.
L72@P1: 3. The Proposed Conventions
L73@P1: We specify four conventions. The conventions (D1–D4) are the coordination agreement; C1–C4 are the
L74@P1: claims those conventions enable. Each convention can be adopted independently. Together they form the
L75@P1: LLM-Agent-Readable Paper convention, version 0.1.
L76@P1: 3.1. D1: paper.json
L77@P1: D1: paper.json is a companion JSON file colocated with the paper PDF. It contains stable IDs for claims,
L78@P1: definitions, theorems, code references, and reproducibility commands, and is machine-readable with
L79@P1: nothing beyond a JSON parser. No LaTeX rendering, no PDF extraction, no internet access required.
L80@P1: The required fields in paper.json are: id (stable kebab-case identifier), title, version (semantic
L81@P1: version of the paper.json itself, distinct from any journal version), status, authors, abstract, claims,
L82@P1: does_not_claim, and reproducibility. All other fields are optional. schema.json in this repository
L83@P1: formalizes the full schema; validator.py enforces it.
L84@P1-2: 2The claim array is the core. Each entry carries an id matching the pattern C[0-9]+ and a statement in
L85@P2: natural language. These IDs must appear verbatim in the paper body so the validator can cross-check.
L86@P2: Definitions follow the pattern D[0-9]+; theorems, T[0-9]+; follow-up work items, F[0-9]+. The validator
L87@P2: confirms that every ID declared in paper.json appears in the Typst (or LaTeX) source, and that every ID
L88@P2: appearing in the source is declared in paper.json.
L89@P2: The canonical global reference for any claim, definition, theorem, or follow-up item is <node_id>#<id>,
L90@P2: where node_id is the URL of the repository (or other host) containing the paper. For this paper:
L91@P2: https://github.com/arquicanedo/paper-json#C1
L92@P2: A repository may host multiple paper.json files (this repository does, in corpus/); each is its own node
L93@P2: with its own node_id. The #<id> fragment is a client-side convention: HTTP returns the host’s HTML, and
L94@P2: the reference resolver resolve.py shipped with this paper handles discovery (fetching paper.json from the
L95@P2: repo’s raw URL or the /paper.json well-known path) and fragment lookup, returning the matching item.
L96@P2: Claim C1: agents querying claims by ID cite the correct sub-claim more accurately than agents searching
L97@P2: prose, on papers whose claims contain no distinctive lexical tokens. Open hypothesis; every claim retrieval
L98@P2: against a compliant paper is one observation.
L99@P2: 3.2. D2: Does-Not-Claim Section
L100@P2: D2: Does-not-claim section is an explicit prose section (or subsection) listing what the paper does not
L101@P2: assert, scoped to plausible misreadings. It is not a limitations section. A limitations section discusses why
L102@P2: the results might not generalize. A does-not-claim section addresses a different problem: hallucinated
L103@P2: extensions that would be false even within the paper’s own scope.
L104@P2: Claim C2: agents given an explicit does-not-claim section produce fewer scope-overextension errors than
L105@P2: agents given prose alone, on topics at the boundary of the paper’s stated contribution. Open hypothesis;
L106@P2: the test is whether agents that read the does-not-claim list still extend beyond it.
L107@P2: Put the does-not-claim section in paper.json as the does_not_claim array and also as a named section in
L108@P2: the paper body. Both placements matter: the JSON entry is machine-queryable; the prose entry is humanreadable and appears in the validator’s cross-check.
L109@P2: 3.3. D3: Executable Reproducibility Block
L110@P2: Every figure and table in a compliant paper links to an exact command in the reproducibility.commands
L111@P2: array of paper.json. “Exact” means: a string the agent can copy verbatim into a shell and run without
L112@P2: modification, given the stated environment, recorded in reproducibility.environment.
L113@P2: Claim C3: agents given reproducibility.commands reproduce figures more reliably than agents given
L114@P2: prose methods sections pointing to a repository, when the figure-generation script is not the repository’s
L115@P2: default entry point. Open hypothesis; each reproduction attempt either succeeds or fails, and the ratio over
L116@P2: time is the answer.
L117@P2: For papers with no figures (this paper is one), the commands cover compilation and validation.
L118@P2: human_intervention_required: false signals that an agent can run the full command list without pausing
L119@P2: for credentials, license gates, or dataset access forms.
L120@P2: 3.4. D4: Dual-Form Theorem Statements
L121@P2: D4: Dual-form theorem means a theorem stated in both natural language and a structured notation block
L122@P2: parseable without rendering LaTeX (ASCII or Unicode math, no macro expansion). The theorems array in
L123@P2: paper.json accepts natural_language, formal, and an optional proof_sketch per theorem. This paper
L124@P2: has no theorems; D4 is defined for completeness and demonstrated on a theorem-bearing paper in followup work F5.
L125@P2-3: 3Claim C5: agents querying definitions by stable ID retrieve the correct author-written definition more
L126@P3: accurately than agents reconstructing definitions from prose, and a hallucinated definition passes structural
L127@P3: validation undetected. Open hypothesis; the pilot in Section 6 reports one observation in the predicted
L128@P3: direction.
L129@P3: 3.5. Recommended File Layout
L130@P3: A compliant paper repository contains:
L131@P3: • paper.json — the companion file (D1)
L132@P3: • paper.typ or paper.tex — source
L133@P3: • paper.pdf — compiled output
L134@P3: • schema.json — the JSON Schema for paper.json
L135@P3: • validator.py — the validator
L136@P3: • AGENTS.md — the read-receipt protocol
L137@P3: Minimum viable compliance (C4) is paper.json alongside paper.pdf. The schema, validator, and
L138@P3: AGENTS.md are recommended but not required.
L139@P3: 4. Reference Implementation
L140@P3: The convention is the schema. The validator is a reference implementation. Compliant papers need not use
L141@P3: this validator. Any tool that enforces the schema is equally valid.
L142@P3: schema.json is a JSON Schema (Draft 2020-12) that formalizes every field described in Section 3. It is
L143@P3: the authoritative specification of paper.json. When the prose of this paper and schema.json disagree,
L144@P3: schema.json wins.
L145@P3: validator.py is a zero-dependency Python 3 script generated from schema.json by
L146@P3: generate_validator.py. It runs in two modes. Without --against, it validates a paper.json against the
L147@P3: schema. With --against paper.typ, it also cross-checks that every claim ID declared in paper.json
L148@P3: appears verbatim in the Typst source, and that no claim ID appears in the source without a declaration. Exit
L149@P3: codes are 0 (valid), 1 (schema violation), 2 (cross-reference violation), 3 (file not found). Note: the validator
L150@P3: checks structural compliance, that IDs are declared and appear in the source. It cannot verify that claim
L151@P3: statements accurately represent what the paper shows. Semantic compliance requires author judgment; see
L152@P3: Section 8 and F3.
L153@P3: generate_validator.py takes schema.json as input and emits a self-contained validator.py with the
L154@P3: schema embedded as a Python literal. This means the validator carries its own schema; it does not fetch
L155@P3: from a URL at runtime. Regenerate after editing schema.json:
L156@P3: uv run generate_validator.py schema.json > validator.py
L157@P3: AGENTS.md specifies the read-receipt protocol.
L158@P3: 5. Self-Application: This Paper Is Its Own Worked Example
L159@P3: Every claim, definition, and follow-up work item is addressable by stable ID in this paper’s own paper.json.
L160@P3: Run the validator before compiling: uv run validator.py paper.json --against paper.typ. An agent
L161@P3: can reproduce the full artifact set (validated paper.json plus compiled PDF) without human intervention.
L162@P3: The reproduction steps are in paper.json at self_application.agent_reproduction_steps:
L163@P3: git clone https://github.com/arquicanedo/paper-json
L164@P3: cd paper-json
L165@P3: uv run validator.py paper.json --against paper.typ
L166@P3: typst compile paper.typ paper.pdf
L167@P3-4: 4This paper satisfies its own conventions, a necessary but weak test since the paper was written to do so.
L168@P4: The useful demonstration is negative: the validator rejects a paper.json with orphaned claim IDs or a
L169@P4: missing does_not_claim field. F3 builds the adversarial test suite that hardens this check beyond structural
L170@P4: correctness.
L171@P4: Self-application is the weakest test of generality: this paper is simple (no theorems, no datasets, no
L172@P4: external figures). Claim C4, that the conventions are adoptable incrementally, is demonstrated here only for
L173@P4: minimum viable compliance. Full compliance for a theorem-bearing empirical paper with external datasets
L174@P4: is follow-up work F3.
L175@P4: 6. Pilot
L176@P4: The C3 failure mode is concrete. In a five-paper pilot (claude-sonnet-4-5, PROSE vs. JSON conditions), one
L177@P4: PROSE agent was given a paper that referenced an evaluation framework, an evaluation scripts section,
L178@P4: and a GitHub URL, but no verbatim command. It assembled and returned:
L179@P4: python run.py --datasets belebele_th --models llama-2-7b \
L180@P4:  --prompt-variants To TiTo LiTiTo LiTiLo LiTiLoTo
L181@P4: This command does not exist. The JSON agent retrieved the exact command from
L182@P4: reproducibility.commands verbatim. The failure was not hallucination from ignorance: the prose contained enough fragments (framework name, scripts section, GitHub URL) to construct something plausible,
L183@P4: but not enough to construct something correct. paper.json eliminates the ambiguity by making the correct
L184@P4: answer explicit.
L185@P4: The pilot ran the full PROSE-vs-JSON comparison across C1, C2, and C3; per-claim scores live in paper.json
L186@P4: at claims[].evidence and raw results plus scorer code are in experiments/. The numbers are directionally
L187@P4: consistent with C1–C3 but n=5 with one model does not support quantitative claims, and Task B scoring
L188@P4: used string matching as a proxy for scope hallucination. F6 is the powered version. Treat §6 as a worked
L189@P4: failure mode, not a measurement.
L190@P4: The C5 failure mode emerged from a subsequent PROSE control experiment: a cold-start agent given the
L191@P4: paper folder but not paper.json reconstructed D4 as “agent-read propagation network” (a plausible concept
L192@P4: from nearby prose) rather than “Dual-form theorem.” The hallucination was structurally valid (validator
L193@P4: exits 0), not flagged by the agent, and would silently propagate to any downstream agent trusting the
L194@P4: reconstructed file. The JSON condition prevents this: definition text is retrieved, not generated.
L195@P4: In run 2, the PROSE control agent identified D4 correctly. Not because the agent had improved, but because
L196@P4: the paper had incorporated the run-1 failure as evidence. The structured failure was citable, so the authors
L197@P4: could revise against it; the revision shipped, so the next agent saw the corrected text. This is the feedback
L198@P4: loop the convention is designed to enable, observed once.
L199@P4: 7. Adoption Path
L200@P4: C4: A convention requiring build-system changes, new tooling, or platform registration will not be adopted.
L201@P4: The barrier to adding machine-readable structure to a paper must be low enough that an author can comply
L202@P4: in under an hour for a finished paper, without touching the human-readable output. If the cost of compliance
L203@P4: exceeds the cost of ignoring it, the convention fails regardless of its technical merits.
L204@P4: Minimum viable compliance (C4) requires one file: paper.json with id, title, version, status, authors,
L205@P4: abstract, at least one claim, does_not_claim, and reproducibility. An author can write this by hand
L206@P4: in under an hour for a finished paper. No build-system changes, no tooling, no LaTeX packages. Submit
L207@P4: paper.json alongside the PDF as a supplementary file or host it at the paper’s repository URL.
L208@P4-5: 5Full compliance adds: definition IDs (D1), theorem dual-form statements (D4), the does-not-claim section
L209@P5: present both in paper.json and as a named section in the body (D2), the validator run as part of the build,
L210@P5: and AGENTS.md in the repository.
L211@P5: The validator is the only tool required for full compliance. It is zero-dependency Python 3 and runs with
L212@P5: uv run validator.py paper.json
L213@P5: --against paper.typ in under a second.
L214@P5: 8. What This Paper Does Not Claim
L215@P5: This section is mandatory by convention. It also appears verbatim in paper.json at does_not_claim.
L216@P5: • C1, C2, C3, C4, and C5 are not proven. C1, C2, C3, and C5 are open hypotheses; any agent acting on a
L217@P5: compliant paper contributes evidence for or against them. C4 is validated by adoption: if authors find
L218@P5: compliance too costly, the convention fails.
L219@P5: • A passing validator does not guarantee semantic correctness. The validator checks that claim IDs are
L220@P5: declared and appear in the source. It cannot verify that a claim statement accurately represents what
L221@P5: the paper shows, that does_not_claim entries are complete, or that reproducibility.commands actually
L222@P5: reproduce the stated figures. A stale or inaccurate paper.json is worse than none, because agents will
L223@P5: trust it. Author discipline and F3 adversarial testing are the mitigations.
L224@P5: • This convention does not solve agent reading; it makes specific recurring failures less likely.
L225@P5: • Compatibility with every existing scholarly metadata standard (JATS, RO-Crate, etc.) is not claimed; we
L226@P5: discuss but do not unify them.
L227@P5: • Adoption does not require tool support; minimum viable compliance (C4) is hand-written JSON.
L228@P5: • Self-application does not prove the convention is sufficient for all papers; only that it is sufficient for
L229@P5: this one.
L230@P5: • The #<id> fragment is not dereferenceable without resolve.py or equivalent client-side tooling. The
L231@P5: resolver handles two steps that HTTP alone does not: discovering the paper.json from a repository URL
L232@P5: (raw-URL rewrite for GitHub, /paper.json well-known path otherwise), and parsing the #<id> fragment
L233@P5: to extract the matching item. JSON has no native fragment concept; #<id> is a convention this paper
L234@P5: proposes.
L235@P5: 9. Future Work
L236@P5: F1: Claim-diff protocol. Extend paper.json so a paper that builds on another can declare per-claim
L237@P5: relationships (supersedes, strengthens, contradicts) against the parent paper’s claim IDs. Agents could then
L238@P5: traverse citation graphs at claim granularity rather than paper granularity. Paper 2 in this series would
L239@P5: demonstrate F1, bootstrapped by an agent that read this paper and filed a read receipt. Requires C1.
L240@P5: F2: paper.json registry. A publicly queryable index of compliant paper.json files. Agents discover papers
L241@P5: by claim ID, by named artifact, or by convention version. The registry is itself described by a paper.json.
L242@P5: Builds on C4 and F1.
L243@P5: F3: Adversarial compliance testing. Deliberately non-compliant paper.json files covering each rule
L244@P5: violation class: missing does_not_claim, orphan claim IDs, broken reproducibility commands, semantically
L245@P5: wrong claim statements. The test suite hardens the validator and surfaces which violations agents hallucinate around most often. Requires C2, C3, C4.
L246@P5: F4: Read-receipt protocol and AGENTS.md. A machine-readable protocol for agents to declare that
L247@P5: they read a compliant paper and built something from it. Each receipt records the agent identity, the
L248@P5: node_id of the paper read, the URL of what was produced, the claim IDs accessed, and the follow-up work
L249@P5: item addressed. This paper is the genesis node; downstream papers extend it via network.extends. The
L250@P5-6: 6propagation graph is a DAG traversable by built→read links. AGENTS.md in the repository specifies the
L251@P6: protocol so agents can discover and follow it without human instruction. Requires C1 and C4.
L252@P6: F5: Dual-form theorem demonstration. This paper has no theorems, so D4 is defined but not demonstrated. A follow-up paper applies D4 to a theorem-bearing empirical paper: each theorem appears in
L253@P6: paper.json as both natural_language and formal notation, and an agent retrieves the structured form
L254@P6: without rendering the compiled PDF. F5 also provides the first test of full compliance (all of D1–D4) on a
L255@P6: paper outside this convention’s authors. Requires C4.
L256@P6: F6: Definition retrieval accuracy at scale (C5 validation). A controlled experiment measuring whether
L257@P6: agents querying definitions by stable ID retrieve the correct author-written definition more accurately
L258@P6: than agents reconstructing definitions from prose. Scope: 10+ papers, multiple models. The PROSE control
L259@P6: experiment in Section 6 observed one complete D4 hallucination (“agent-read propagation network” for
L260@P6: “Dual-form theorem”) that passed structural validation undetected. F6 measures the rate of that failure
L261@P6: mode across many papers and agents, broken down by definition prominence in prose and distance from
L262@P6: the nearest prose mention. Requires C1 and C5.
L263@P6: 10. Related Work
L264@P6: Prior machine-readable paper formats include JATS [3], ORKG [8], RO-Crate [4], W3C Web Annotation
L265@P6: [7], Papers with Code [6], CodeMeta [9], REANA [10], Manubot [5], Semantic Scholar [11], and OpenAlex
L266@P6: [12]. Each addresses a subset of structured scholarly communication. To our knowledge, no prior format
L267@P6: combines stable claim IDs, explicit non-claims, executable per-figure shell commands, and distributed
L268@P6: propagation in a single file that travels with the paper.
