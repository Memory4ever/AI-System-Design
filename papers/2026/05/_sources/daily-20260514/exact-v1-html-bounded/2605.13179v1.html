Does Engram Do Memory Retrieval in Autoregressive Image Generation?

Abstract

The Engram module—a hash-keyed, O⁡(1)O(1) associative memory injected into Transformer layers—was recently shown to improve large language model pretraining, with the appealing interpretation that it provides a content-addressed shortcut to recurring local token patterns. We ask whether this interpretation transfers to autoregressive (AR) image generation, or whether the observed gains, if any, come from a different mechanism. We adapt the Engram module to vision with 2D spatial nn-gram hashing, gated fusion, and KV-cache-compatible incremental inference, and inject it into a class-conditional AR generator trained on ImageNet 256×256256{\times}256. Across a sweep of backbone-to-memory budget ratios ρ∈[0.17,0.90]\rho{\in}[0.17,0.90], every Engram-augmented variant trails the pure AR baseline in FID, indicating that the module saves backbone FLOPs but does not, by itself, improve sample quality. We then probe how the module is used. A gate-clamp sweep shows that disabling the Engram pathway entirely is catastrophic, yet a tiny constant gate (g=0.10g{=}0.10) matches or beats the learned gate—inconsistent with a heavily content-addressed recall mechanism. A donor-probe experiment shows that swapping the hash inputs for matched, adversarial, or random same-class exemplars produces statistically indistinguishable next-token distributions, while collapsing or randomising the table degrades them by two to three orders of magnitude. Finally, training a model from scratch with the entire memory table frozen to 𝒩⁡(0,1)\mathcal{N}(0,1) noise costs only Δ​FID=0.10\Delta\text{FID}{=}0.10 and actually raises Inception Score. Together, these findings indicate that the Engram in AR image generation behaves not as a content-addressed retriever but as a gated architectural side-pathway: a hash-keyed residual stream whose benefit is dominated by the pathway itself, with the learned table contributing only a small distributional refinement.

1 Introduction

The Engram module 2—a conditional memory module that augments Transformer layers with a hash-based lookup table keyed by recent token nn-grams—was recently proposed in natural language processing. By hashing the local context into a large embedding table and gated-fusing the retrieved value into the hidden state, Engram is presented as a fast, gradient-free shortcut to recurring local patterns in language (common phrases, idioms, collocations) and as a new axis of sparsity that complements the dense attention and feed-forward layers of the Transformer. The mental model behind this design is appealing: a parametric memory table that is addressed by the surface form of the recent context and retrieves a content-specific correction to the next-token logits.

Autoregressive (AR) image generation provides a sharp test for that mental model. By mapping images to sequences of discrete tokens via vector-quantised encoders 12; 4 and predicting them left-to-right with a causal Transformer, AR image models 8; 17 produce token streams whose local structure is, in principle, even more redundant than natural language: with a 16×1616{\times}16 token grid, the same local patches—sky, fur, brick—reappear across hundreds of classes. If Engram is a content-addressed retriever, it should be especially useful here.

In this paper we adapt the Engram module to vision, plug it into a strong class-conditional AR generator, and ask two questions: (Q1) Does the resulting model improve sample quality over a pure AR baseline at matched parameter count? (Q2) If it helps (or hurts), which mechanism is responsible: content-addressed retrieval from the memory table, the architectural side-pathway induced by gated fusion, or simple regularisation?

Our empirical findings, however, are negative for the memory retrieval interpretation and only mildly positive for the architecture:

  1. 1.

    No FID improvement at matched parameters. We sweep the backbone-to-total parameter ratio ρ∈{0.17,…,0.90}\rho{\in}\{0.17,\dots,0.90\}, trading backbone width for memory-table capacity. Every Engram-augmented variant has worse FID than the pure AR baseline (2.022.02). The module saves backbone FLOPs but does not, on its own, buy a quality gain. Adding richer 2D nn-gram banks (1×31{\times}3, 3×13{\times}1, 2×22{\times}2) on top of the 1D variant changes FID by less than 0.010.01.

  2. 2.

    Gate clamping reveals over-mixing of memory. At inference, replacing the learned gate with a constant g∈{0.10,0.25}g{\in}\{0.10,0.25\} matches or beats the learned gate, while g=1g{=}1 degrades FID-10K from 4.894.89 to 6.536.53. Disabling the pathway entirely (g=0g{=}0) collapses generation (FID-10K 115115). A genuine retriever should reward putting more weight on its outputs; this pathway prefers to be barely used.

  3. 3.

    The hash address does not select content. In a donor probe that swaps the tokens fed to the hash for matched, adversarial, or random same-class exemplars, next-token distributions are statistically indistinguishable across the three conditions, while collapsing the bucket index or replacing the table with 𝒩⁡(0,1)\mathcal{N}(0,1) noise degrades them by two to three orders of magnitude. The model is sensitive to whether the table is diverse and learned, but not to whether the queried entry semantically matches the context.

  4. 4.

    Most of the benefit is architectural, not content-based. Training the model from scratch with the entire memory table frozen to 𝒩⁡(0,1)\mathcal{N}(0,1) noise costs only Δ​FID=0.10\Delta\text{FID}{=}0.10 relative to a fully learned table, and in fact raises Inception Score from 259259 to 285285. The bulk of the gain comes from the gated, hashed side-pathway—additional parameters and a parallel residual stream—rather than from the contents of the table.

We summarise our contributions as follows:

  1. 1.

    We adapt the Engram conditional-memory mechanism from 1D language to 2D vision, with spatial nn-gram hashing over a causal 2×22{\times}2 grid, gated fusion, per-channel LayerScale, and KV-cache-compatible incremental inference suitable for AR sampling.

  2. 2.

    We introduce a diagnostic toolkit—gate-clamp analysis, a donor probe over matched/adversarial/random/uniform/randomised conditions, and a from-scratch frozen-noise training control—for disentangling content-addressed retrieval from architectural pathway effects in hash-keyed memory modules.

  3. 3.

    Through a controlled sweep on class-conditional ImageNet 256×256256{\times}256, we provide evidence that, in the AR image setting, Engram functions as a gated architectural side-pathway rather than a content-addressed retriever, and that the learned memory table contributes only a small refinement on top of the pathway itself.

2 Related Work

Autoregressive Image Generation.

Early work on AR image generation operated directly on pixels 11; 10 or coarse grids 9. The introduction of VQ-VAE 12 and VQGAN 4 enabled Transformer-based generation in a compressed discrete token space. Subsequent work explored larger vocabularies 17, improved tokenisers 19; 13, and training strategies such as random-order generation 18 and masked prediction 1. Our work builds on the raster-scan AR Transformer and is complementary to these advances: the Engram module can be added to any AR backbone regardless of the tokeniser or generation order.

Memory-Augmented Neural Networks.

External memory has a long history in neural networks, from Neural Turing Machines 5 and Memory Networks 14 to the Memorising Transformer 16, which attends over a key–value cache of past activations. These approaches typically use learned attention to route queries to memory, incurring O⁡(N)O(N) cost in memory size. In contrast, Engram 2 uses deterministic hashing for O⁡(1)O(1) lookup, with the gated fusion mechanism learning whether to use the retrieved value rather than how to retrieve it. We inherit this efficiency and extend it to 2D spatial structure.

3 Method

3.1 Preliminary

Autoregressive Image Generation. Autoregressive (AR) image generation first encodes an image into a sequence of discrete tokens using a vector-quantised (VQ) encoder such as VQ-VAE 12 or VQGAN 4, then models the resulting sequence with a causal Transformer. A typical encoder partitions the image into a regular spatial grid of patches (e.g. 16×16=25616{\times}16=256 patches for a 256×256256{\times}256 image) and maps each patch to a discrete index drawn from a finite codebook via nearest-neighbour lookup in a learned embedding space. Flattening this grid in raster-scan order yields a token sequence 𝐳=(z1,z2,…,zT)\mathbf{z}=(z_{1},z_{2},\ldots,z_{T}), where each zt∈{1,…,V}z_{t}\in\{1,\ldots,V\} and VV is the codebook size. The model factorises the joint distribution autoregressively:

p⁡(𝐳)=∏t=1Tp⁡(zt∣z<t),p(\mathbf{z})=\prod_{t=1}^{T}p(z_{t}\mid z_{<t}), (1)

where each conditional is parameterised by a causal Transformer trained with cross-entropy loss.

Engram. The Engram module 2 augments a Transformer layer with a hash-based external memory that enables O⁡(1)O(1)-cost retrieval of static local patterns. Standard Transformers lack a native knowledge-lookup primitive and must simulate retrieval through sequential layers of attention and feed-forward computation 2; Engram addresses this by offloading static pattern recall to an explicit embedding table. The core components are as follows:

  • •

    Multi-head, multi-order hashing. Rather than maintaining a single table, Engram instantiates separate embedding tables for each n-gram order n∈{2,…,N}n\in\{2,\ldots,N\} and each of KK independent hash heads, yielding tables {𝐄n,k∈ℝMn,k×dhead}\{\mathbf{E}_{n,k}\in\mathbb{R}^{M_{n,k}\times d_{\rm head}}\} of prime size Mn,kM_{n,k}. For position tt, the nn-gram context gt,n=(zt−n+1,…,zt)g_{t,n}=(z_{t-n+1},\ldots,z_{t}) is mapped by a lightweight multiplicative-XOR hash φn,k\varphi_{n,k} to slot index φn,k​(gt,n)\varphi_{n,k}(g_{t,n}), and the retrieved vectors are concatenated across all orders and heads to form the aggregated memory vector:

    𝐞t=∥n=2N∥k=1K𝐄n,k[φn,k(gt,n)]∈ℝdmem,\mathbf{e}_{t}\;=\;\bigl\|_{n=2}^{N}\;\bigl\|_{k=1}^{K}\;\mathbf{E}_{n,k}\bigl[\varphi_{n,k}(g_{t,n})\bigr]\;\in\;\mathbb{R}^{d_{\rm mem}}, (2)

    where dmem=(N−1)⋅K⋅dheadd_{\rm mem}=(N-1)\cdot K\cdot d_{\rm head}. Using KK independent hash functions per order substantially reduces hash-collision noise relative to a single-head design.

  • •

    Context-aware gating and fusion. The retrieved vector 𝐞t\mathbf{e}_{t} is context-independent and may contain noise from collisions or polysemy. Engram resolves this ambiguity via learnable key and value projections 𝐖K,𝐖V\mathbf{W}_{K},\mathbf{W}_{V} applied to 𝐞t\mathbf{e}_{t}:

    gt=σ⁡(RMSNorm​(𝐡t)⊤​RMSNorm​(𝐖K​𝐞t)d),𝐯~t=gt⋅𝐖V​𝐞t.g_{t}=\sigma\!\left(\frac{\mathrm{RMSNorm}(\mathbf{h}_{t})^{\!\top}\,\mathrm{RMSNorm}(\mathbf{W}_{K}\mathbf{e}_{t})}{\sqrt{d}}\right),\qquad\tilde{\mathbf{v}}_{t}=g_{t}\cdot\mathbf{W}_{V}\mathbf{e}_{t}. (3)

    The current hidden state 𝐡t\mathbf{h}_{t}—which has aggregated global context via preceding attention—acts as a dynamic query: if the retrieved memory contradicts the context, gtg_{t} tends to zero, suppressing retrieval noise. 𝐖V\mathbf{W}_{V} is implemented as a two-layer MLP when dmem>dd_{\rm mem}>d (i.e. when the memory dimension exceeds the backbone hidden size). Finally, a lightweight depthwise causal convolution (kernel size 4, SiLU activation, zero-initialised) is applied to the sequence of gated values 𝐕~\tilde{\mathbf{V}} to expand the local receptive field, yielding the fused output:

    𝐡t←𝐡t+gt⋅𝐯ht,\mathbf{h}_{t}\leftarrow\mathbf{h}_{t}+g_{t}\cdot\mathbf{v}_{h_{t}}, (4)

    where 𝐯ht≡(𝐖V​𝐞t+SiLU​(Conv1D⁡(RMSNorm⁡(𝐕~)))t)\mathbf{v}_{h_{t}}\equiv(\mathbf{W}_{V}\mathbf{e}_{t}+\mathrm{SiLU}(\mathrm{Conv1D}(\mathrm{RMSNorm}(\tilde{\mathbf{V}})))_{t}) subsumes the convolution refinement. Because hashing is deterministic and computed solely from the raw token IDs, the lookup is O⁡(1)O(1) in memory size; gradients flow only through 𝐄n,k\mathbf{E}_{n,k} and gtg_{t} (not through the hash functions themselves).

3.2 Confirmation of Existance of N-gram Structure in Visual Tokens

Since the image AR models are trained not on the pure pixel space but in the token space provided by the image tokenizer and unlike natural language, where nn-grams (contiguous word sequences) are well-established, it is unclear whether discrete image tokens possess analogous structure, or whether this structure depends on the tokeniser. Hence, a prerequisite for adapting Engram to vision is that visual token sequences must exhibit recurrent local nn-gram patterns.Otherwise, the hash-based lookup has nothing to retrieve.

DINO-stratified Jaccard analysis. We measure the nn-gram overlap between pairs of images as a function of their semantic similarity. For a patch shape (pr×pc)(p_{r}{\times}p_{c}) and two token grids AA and BB, the 2D Jaccard similarity is

Jpr,pc​(A,B)=|𝒩pr,pc​(A)∩𝒩pr,pc​(B)||𝒩pr,pc​(A)∪𝒩pr,pc​(B)|,J_{p_{r},p_{c}}(A,B)\;=\;\frac{\bigl|\mathcal{N}_{p_{r},p_{c}}(A)\cap\mathcal{N}_{p_{r},p_{c}}(B)\bigr|}{\bigl|\mathcal{N}_{p_{r},p_{c}}(A)\cup\mathcal{N}_{p_{r},p_{c}}(B)\bigr|}, (5)

where 𝒩pr,pc​(⋅)\mathcal{N}_{p_{r},p_{c}}(\cdot) is the multiset of all (pr×pc)(p_{r}{\times}p_{c}) patches extracted from the grid. We evaluate five shapes: 1×21{\times}2, 2×12{\times}1, 1×31{\times}3, 3×13{\times}1, and 2×22{\times}2. Pairs are grouped into bins of DINOv2 7 cosine similarity (range [0.50,1.00][0.50,1.00], 10 bins of width 0.05, up to 500 pairs per bin). All pairs are drawn from a uniform random subsample of 15 000 training images (seed 42); no curated near-duplicate index is used. A “random” baseline computes JJ over pairs drawn without regard to similarity.

Result. Figure 2 shows the mean Jaccard similarity as a grouped bar chart for each shape, stratified by DINO similarity tier, for two tokenisers: AliTok 15 (codebook size 4096, 256 semantic tokens arranged as a 16×1616{\times}16 grid; decoder uses causal attention) and MaskGIT-VQ 1 (codebook size 1024, 256 tokens on the same 16×1616{\times}16 grid; decoder uses bidirectional attention).

AliTok produces tokens with consistent local patterns at all levels of similarity. MaskGIT-VQ, by contrast, collapses to near-zero for all shapes at low similarity and reaches meaningful overlap only at the extreme ≥\geq0.95 tier where images are near-duplicates.

This result motivates our choice of AliTok as the tokeniser for all subsequent experiments. An Engram module that hashes spatial-patch contexts can only be effective when the token space exhibits recurrent local patterns—a condition AliTok satisfies but MaskGIT-VQ does not.

3.3 Engram for Autoregressive Image Generation

Base model. We choose our base autoregressive model as (AR-B): a 24-layer causal Transformer with hidden size 768, 16 attention heads, 2D Rotary Position Embeddings (RoPE), SwiGLU feed-forward layers, RMSNorm, and QK-normalisation with RMSNorm. The model totals approximately 177M parameters.

Vision adaptation. We list the differences from the NLP Engram as follows:

  1. 1.

    Context n-gram definition. At each grid position (i,j)(i,j) in the 16×1616{\times}16 raster order, we collect a set of causal spatial neighbours and hash them with HH independent hash functions into indices {h1,…,hH}\{h_{1},\ldots,h_{H}\} within a table of VmemV_{\text{mem}} entries.We maintain two independent banks: a 2-gram bank {t,t−1}\{t,t{-}1\} and a 3-gram bank {t,t−1,t−2}\{t,t{-}1,t{-}2\}.

  2. 2.

    No tokenizer compression. Unlike the NLP setting where the Engram operates with a compressed tokenizer, we keep the original Alitok tokenized results unchanged.

By default we place engram modules at layers {0,6,12,18}\{0,6,12,18\} with H=4H{=}4 hash heads, Vmem=36 715V_{\text{mem}}{=}36\,715 memory slots, and head dimension dh=64d_{h}{=}64. In addition, Alitok introduces a set of 256 images tokens, plus 16 auxiliary tokens and 1 class tokens. We only apply the Engram to the 256 image tokens.

4 Experiments & Analysis

4.1 Experimental Setup

Dataset and Tokeniser. We train on the ImageNet 3 training set (1.28M images, 1000 classes) at 256×256256{\times}256 resolution. Based on the analysis above, we use the AliTok 15 tokeniser, which maps each image to 256 semantic tokens (plus 17 aux tokens)from a codebook of size 4096.

Training and Evaluation. All models are trained with AdamW (lr 4×10−44{\times}10^{-4}, cosine schedule, β1=0.9\beta_{1}{=}0.9, β2=0.96\beta_{2}{=}0.96, weight decay 0.030.03) and bfloat16 mixed precision. Effective batch size is 2048 across 8 GPUs. Each condition in the four-way ablation is trained for 125K steps under identical settings (200 epochs). We report FID-50K 6 and Inception Score (IS) computed with classifier-free guidance (cosine-power schedule, cfgmax=16.0\text{cfg}_{\max}{=}16.0, α=1.8\alpha{=}1.8).

4.2 Finding I: The Engram-Augmented AR Saves FLOPs But Slightly Sacrifices FID

Setup. As we are working one a dense transformer model, we control the the backbone ratio ρ=backbone params/total params\rho=\text{backbone params}/\text{total params}; ρ=1\rho{=}1 is the pure AR baseline and lower ρ\rho allocates more budget to the engram memory tables. Since, we have to keep the depth of the model constant so that the Engram module can be injected at the same layer, we adjust the width of the backbone parameters by varying the size of hidden dimension, range from 320 to 768. The head dimension of the Engram module is fixed at 64, and the number of hash heads is fixed at 4. The size of the memory table is varied from 52831 to 5243. It yields a family of Engram-augmented variants with ρ={0.17,0.32,0.41,0.51,0.63,0.76,0.90}\rho=\{0.17,0.32,0.41,0.51,0.63,0.76,0.90\} where the lowest ρ\rho corresponds to the largest memory table and the smallest backbone, and vice versa for the highest ρ\rho. ρ=1\rho=1 stands for the pure AR baseline without any Engram module.

Result. In Figure 3, we observe that all Engram-augmented variants with ρ\rho from 17% to 90% have worse FID than the AR baseline (2.02). This is a promising result given that Engram is a lightweight module designed for efficiency, but it also motivates our subsequent analysis to understand why the Engram module does not produce a stronger improvement in FID.

4.3 Finding II: 2D N-gram Dose Not Improve FID

Setup. In contract to language lived in 1D space, image is 2D. It replaces the sequential offsets with the combination of the 2D spatial neighbours: 1. Bank 0 (1×21{\times}2): {zt,zleft}\{z_{t},\;z_{\text{left}}\} 2. Bank 1 (2×12{\times}1): {zt,ztop}\{z_{t},\;z_{\text{top}}\} 3. Bank 2 (1×31{\times}3): {zt,zleft,zleft left}\{z_{t},\;z_{\text{left}},\;z_{\text{left left}}\} 4. Bank 3 (3×13{\times}1): {zt,ztop,ztop top}\{z_{t},\;z_{\text{top}},\;z_{\text{top top}}\} 5. Bank 4 (2×22{\times}2): {zt,zleft,ztop,zdiag}\{z_{t},\;z_{\text{left}},\;z_{\text{top}},\;z_{\text{diag}}\} . The 2D variant is designed to capture both horizontal and vertical token co-occurrences simultaneously.

Result. The 2D variant achieves an FID of 4.244.24, which is nearly identical to the 1D baseline (4.234.23). This suggests that the additional vertical and diagonal context captured by the 2D n-grams does not translate into a measurable improvement in generation quality.

4.4 Finding III: The Engram Uses Memory as a Learned Distributional Prior, Not as Content Retrieval

Gate-Clamp Evaluation. To probe whether the model uses memory selectively, we evaluate the trained Real model (ρ=0.63\rho{=}0.63, h=640h{=}640, 1D) with the gate globally clamped to fixed values g∈{0.00,0.10,0.25,0.50,0.75,1.00}g\in\{0.00,0.10,0.25,0.50,0.75,1.00\} as well as with the learned (token-dependent) free gate. All conditions use FID-10K with identical CFG settings.

Table 1 shows two things. First, the engram pathway is necessary: clamping g=0g{=}0 removes any memory contribution and catastrophically degrades FID (4.89 →\to 115). Second, the learned gate is slightly over-mixing: a constant clamp at g∈{0.10,0.25}g{\in}\{0.10,0.25\} already matches or improves on the free gate, while pushing the gate higher monotonically degrades quality. Together this indicates that the engram contribution should be small but non-zero—consistent with a low-rank correction to the AR backbone rather than a heavily content-addressed recall mechanism.

Donor Probe. If Engram functions as a nearest-neighbour retrieval module, then replacing its memory content with matched exemplars (same-class generations) should produce noticeably better predictions than adversarial (different-class) or random exemplars. We test this with a donor probe that, while teacher-forcing the model on N=2,000N{=}2{,}000 self-generated reference sequences, swaps the tokens fed into the engram hash for one of six donor conditions and compares the resulting next-token logits to those produced with the model’s own context. We measure the mean rank of the real top-1 token in the donor distribution, the KL from the real distribution, and the top-5 overlap.

Table 2 shows that Matched, Adversarial, and Random donors produce nearly identical output distributions (Δ​rank<2\Delta\text{rank}{<}2, Δ​KL<0.11\Delta\text{KL}{<}0.11, top-5 overlap differs by <0.03<0.03). In particular, matched is statistically indistinguishable from adversarial, indicating that the engram is not encoding class-specific content. In contrast, Uniform (collapsing all address diversity to a single bucket) inflates the rank by ∼\sim60×\times and Randomized (destroying the learned table while keeping the keying pathway) by nearly ∼\sim300×\times. Hence the engram is sensitive to whether memory remains diverse and learned, but it does not preferentially select semantically matched content—undermining a strict retrieval interpretation and supporting a view of the engram as a learned distributional prior over local image-token statistics.

4.5 Finding IV: Most of the Engram’s Benefit Comes From the Architectural Pathway, Not From Memory Content

The donor probe in Section 4.4 establishes that, at inference time, the engram is sensitive to whether memory remains diverse and learned, but does not select semantically matched content. This still leaves open whether, when training from scratch, a meaningful learned memory table is required at all. We test this by training a fourth condition—Randomized—in which the memory embedding table is replaced with frozen 𝒩⁡(0,1)\mathcal{N}(0,1) noise (not updated during training) while every other component (hashing, gating, AR backbone) is unchanged. This preserves the engram pathway but destroys any learnable content.

Table 3 reveals that The architectural pathway carries most of the benefit. Replacing every value in the memory table with frozen Gaussian noise costs only Δ​FID=0.10\Delta\text{FID}{=}0.10 relative to a fully learned memory. By contrast, removing the engram pathway entirely (gate clamp g=0g{=}0 in Table 1) collapses FID-10K to 115.09115.09. Hence the bulk of the engram’s contribution is attributable to the gated, hashed side-pathway—additional parameters, content-conditioned gating, and a parallel residual stream—rather than to the specific contents of the memory table. This is consistent with the donor-probe finding that the engram functions as a learned distributional prior, not as a content-addressed retriever.

5 Conclusion

We asked whether the hash-keyed Engram memory module helps autoregressive image generation, and—if so—through what mechanism: content-addressed retrieval, or an architectural side-pathway with a gated residual stream. We adapted the Engram mechanism from 1D language to 2D vision with spatial nn-gram hashing over a causal 2×22{\times}2 grid, gated fusion, and KV-cache-compatible incremental inference. Across a controlled budget sweep ρ∈[0.17,0.90]\rho{\in}[0.17,0.90] on class-conditional ImageNet 256×256256{\times}256, every Engram-augmented variant has worse FID than a pure AR baseline at matched parameter count, and the additional 2D nn-gram banks do not measurably improve over the 1D variant. The module saves backbone FLOPs, but it does not, by itself, buy a quality gain.

We then probed how the module is used by combining two post-training diagnostics on a trained Engram-augmented checkpoint (ρ=0.63\rho{=}0.63)—gate-clamp analysis and a donor probe—with one frozen-noise training control in which the entire memory table is replaced by frozen 𝒩⁡(0,1)\mathcal{N}(0,1) noise and the model is retrained from scratch under otherwise identical settings. Together they give the following picture:

  • •

    The pathway is necessary, but should be barely used. Disabling the gate (g=0g{=}0) collapses FID-10K from 4.894.89 to 115115; yet a constant g∈{0.10,0.25}g{\in}\{0.10,0.25\} matches or beats the learned gate, and g=1g{=}1 monotonically degrades quality. The model prefers a small, near-constant injection from the memory pathway.

  • •

    The hash address is not used to select content. The donor probe shows that matched, adversarial, and random same-class exemplars yield statistically indistinguishable next-token distributions, while collapsing the bucket index or replacing the table with 𝒩⁡(0,1)\mathcal{N}(0,1) noise degrades them by two to three orders of magnitude. The model uses the table for distributional structure, not for class-conditional content addressing.

  • •

    The table itself is largely incidental. In the frozen-noise control, training a model from scratch with the entire memory table frozen to 𝒩⁡(0,1)\mathcal{N}(0,1) noise costs only Δ​FID=0.10\Delta\text{FID}{=}0.10 and raises Inception Score from 259259 to 285285. The bulk of the measurable behaviour comes from the gated, hashed side-pathway—an additional parameter budget and a parallel residual stream—rather than from the specific contents of the memory table.

We therefore conclude that, in autoregressive image generation, the Engram module is best described as a gated architectural side-pathway: a hash-keyed residual stream that is necessary at inference but only weakly content-addressed, with the learned table contributing only a small distributional refinement on top of the pathway itself. This reading is at odds with the content-addressed retrieval interpretation that motivated the original Engram design and suggests that, on visual token streams produced by current tokenisers, hash-keyed memory in its present form is better viewed as a regulariser-like architectural prior than as a true memory.

Limitations. Due to computational constrait, our study is restricted to a dense AR generator at moderate scale; we do not train XL-size model and MoE variants, or training regimes (e.g. extreme low-data, long-tail class-conditional, or higher resolutions) where genuine memory may matter more.
