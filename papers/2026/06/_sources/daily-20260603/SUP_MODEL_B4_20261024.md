> 连续状态直接回灌还多了一项输入接口合同：上一轮 decoder hidden state 与下一轮 input embedding 未必属于兼容的表示坐标。一个分支把 context-carried hidden 与当前词表分布的 top-p embedding 加权融合，再输入下一 latent transition；untied 输入/输出空间还可增加适配投影。它没有恢复逐步可见推理，也不能由 tied 与 untied 模型之间的差异唯一归因接口 mismatch，fusion、adapter、触发与停止规则必须和 checkpoint 一起验收。<!-- source-family:SF-2026-ARXIV-2602-10229 -->

### 02011 → `INFER-TENSORRT-LLM` Ch49

已读Ch49量化起点、逐例行为/分布漂移及恢复局部，Ch48/50交接；现有格式/误差和逐例质量未承载“低bit增加总生成量+plan/restart全路径”具体反例。在量化目标短段后加一段，再回到表示定义，非另建低bit综述。

上锚：
> FP8、FP4、INT8、INT4 这类低精度路径的系统目标，是降低权重、activation 或 cache 的存储和带宽压力，并提高硬件 tensor core 的有效吞吐。

拟新增：
> 对长reasoning，这个目标还须乘上生成路径的变化：极低位宽可使循环、迟迟不commit和预算耗尽增加，单token更快反而整题更慢。可按loop前是否已有可解析答案，选择提前commit或从头以高精度重跑，也可先付费生成高精度outline；但可解析不等正确，救援不保证恢复原分布。[受限2bit轨迹对照](https://arxiv.org/html/2606.02011v1#S7)中，退化取决于模型–任务与最大长度，较短cap会遮蔽长尾；reported速度结合实测tokens/s与轨迹估算，不是服务SLO。全部失败低位token、plan、检测、重跑及双精度驻留计费，分别验accuracy、总长度、fallback率和真实时间；净质量/费用不合时保稳定4bit、更高精度或原模型，不由per-token吞吐批准端到端加速。<!-- source-family:SF-2026-ARXIV-2606-02011 -->

> Multi-adapter batching 也不是把任意 adapters 无成本混入同一 batch。Runtime

### 01923 → `MODEL-SELF-ATTENTION` Ch14

已读Ch14 routingweight、Value/尾部mass完整局部、sink/noop与邻接，Ch13/15开篇。已有Value尺度影响读取，但未有概率固定的query-conditioned gain干预，建议紧随一般路由不等贡献段。

上锚：
> 归一化权重描述的是本次路由，而不是每个位置独立贡献了多少“知识”。即使某个位置权重很小，它的 Value norm 或方向仍可能影响结果；一批位置的作用还可能互相抵消。因此研究“读取需要多少位置”时，必须先说清干预：删除尾部位置但保留原权重，与留下少数位置后重新归一化，不是同一个实验。

拟新增：
> 也可以保留softmax概率，却按当前query的原始score给Value乘`1+γ·softplus(score)`，改变的是信号幅度而非可见边或归一化路由；gain随query变化，不能无条件折进静态KV。这种干预更服从context，并不认证context真实；所谓SNR改善还依赖相关项对齐、gain近似一致及噪声近常量，不能升为普遍单调定理。[RCA的有限Llama对照](https://arxiv.org/html/2606.01923v1#S4)有coverage指标反退，较大gain还弱于原模型，少数closed-book近似分数也不证明always-on无害。校准/搜索、额外score/gain执行及独立质量回归均计费；输入可信度、数值或预算不合时关闭gain，保原attention与外部证据核验，不把routing/gain分离授为消除幻觉。<!-- source-family:SF-2026-ARXIV-2606-01923 -->

下锚：
> 设保留集合的原权重和为 `m`，保留/删除部分的加权平均 Value 分别为 `mu_S`、`mu_T`，则原输出是 `m*mu_S+(1-m)*mu_T`。只删除时的输出误差为 `(1-m)*mu_T`；重新归一化后的误差则为 `(1-m)*(mu_T-mu_S)`。小的尾部 mass 只控制系数，Value 尺度和方向仍决定实际误差；下一层非线性和最终任务 loss 还会继续改变影响。用原模型 NLL 的变化定义“retrieval capacity”，测到的是特定干预下保留原行为所需的路由支持，不是模型存储事实的数量。[受限 Attention retrieval 实验](https://arxiv.org/html/2609.37879v1)先计算完整 Attention 再选择位置，因而也不构成稀疏实现的加速证明。真实稀疏执行的质量、选择开销与缓存问题交由第45、49章处理。
