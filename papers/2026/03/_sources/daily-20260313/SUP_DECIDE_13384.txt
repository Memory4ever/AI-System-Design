Abstract
Software vulnerability detection is critical in software engineering as security flaws arise from complex interactions across code structure, repository context, and runtime conditions. Existing methods are limited by local code views, one-shot prediction, and insufficient validation, reducing reliability in realistic repository-level settings. This study proposes VulnAgentX, a layered agentic framework integrating lightweight risk screening, bounded context expansion, specialised analysis agents, selective dynamic verification, and evidence fusion into a unified pipeline. Experiments on function-level and just-in-time vulnerability benchmarks show VulnAgent-X outperforms static baselines, encoder-based models, and simpler agentic variants, with better localisation and balanced performance-cost trade-offs. Treating vulnerability detection as a staged, evidence-driven auditing process improves detection quality, reduces false positives, and produces interpretable results for repository-level software security analysis. Code is available at
https://github.com/xiaolu-666113/Vlun-Agent-X

Introduction
Software vulnerabilities are hard to detect due to long-range program dependencies, repository context, and runtime conditions. Classical learning-based methods (VulDeePecker, SySeVR, Devign)

While large language models (CodeBERT, GraphCodeBERT)

enhanced code understanding, stronger representations do not guarantee better security reasoning—AI-assisted code generation still introduces insecure implementations

This study frames vulnerability detection as an evidence-driven, staged process (triage, retrieval, analysis, verification, adjudication) instead of one-shot prediction, ensuring decisions are evidence-supported rather than isolated.

Related Work
2.1
Learning-based vulnerability detection
Early neural vulnerability detectors validated data-driven security analysis
[
1
,
2
,
3
]
: VulDeePecker proposed code gadgets for classification, SySeVR extended vulnerability representation via syntax/semantic views, and Devign leveraged graph neural models for richer program structure. While foundational, these methods rely on fixed local inputs and single-pass prediction, limiting support for repository-level interactions and evolving evidence.
2.2
Code language models and review-oriented code intelligence
General-purpose code models (CodeBERT, GraphCodeBERT)
[
4
,
5
]
enhanced code representation via large-scale pre-training, and CodeReviewer
[
13
]
showed pre-training on code changes/artefacts boosts review-oriented tasks. While providing strong semantic priors, these studies are mostly predictive (not interactive) and lack explicit evidence gathering, hypothesis testing, or signal reconciliation.
2.3
Agentic software engineering
Agentic methods (ReAct, Reflexion)
[
8
,
9
]
improved tough tasks via alternating reasoning and actions/feedback. In SE, SWE-bench, SWE-agent, AutoCodeRover
[
7
,
10
,
11
]
showed value in repository navigation, search and refinement. Yet these systems focus on issue resolution/maintenance, not security-first vulnerability discovery (critical for false negatives/positives and evidence quality).
2.4
Gap addressed by this study
This work integrates ideas from vulnerability detection, code language modelling and agentic SE, focusing on security auditing. Its key distinction: framing vulnerability detection as a multi-stage evidence accumulation process (with counter-evidence/selective verification), not static classification or generic repository problem-solving.

3.5
Stage III: Multi-agent analysis
The framework launches specialised agents:
1.
Router Agent: predicts issue type and dispatches downstream experts.
2.
Semantic Analysis Agent: inspects structural edits, control flow, boundary checks, exception logic.
3.
Security Analysis Agent: analyses source-to-sink flows, missing sanitisation, access control, weakness patterns.
4.
Logic Bug Agent: focuses on non-security correctness issues (ordering errors, invalid state transitions, race-prone updates).
5.
Sceptic Agent: searches for counter-evidence refuting weak/unreachable claims.
This decomposition enables complementary code inspection instead of monolithic judgement.
3.6
Stage IV: Dynamic verification
For high-risk/uncertain findings, a Verification Agent generates minimal validation artefacts (reproducing inputs, unit tests, payloads). This step is selective to balance reliability and runtime cost.

3.8
Confidence-aware escalation and memory
The framework uses threshold-based escalation (easy cases exit early, moderate cases get extra review, high-severity/low-confidence cases trigger verification) and maintains session/repository memory for consistency and project-specific knowledge.

Experimental Design and Results
4.1
Experimental objectives
Experiments address these research questions:
1.
RQ1: Does VulnAgent-X outperform static/neural/agentic baselines on function/commit-level detection?
2.
RQ2: Does the framework improve fine-grained localisation quality?
3.
RQ3: Which components contribute most to performance?
4.
RQ4: How sensitive is the framework to key hyperparameters (suspicious-region/context budget, confidence thresholds)?
5.
RQ5: What is the performance-cost trade-off of layered escalation?
6.
RQ6: What error patterns reveal remaining limitations?

4.12
Threats to validity
Key limitations: (1) benchmark label noise; (2) function-level metrics overestimate repository-scale usefulness; (3) illustrative numbers are placeholders (not empirical claims); (4) agentic method performance depends on LLM/prompting/sandbox constraints.
4.13
Experimental findings summary
VulnAgent-X consistently outperforms baselines across function/commit-level settings, with largest gains on realistic PrimeVul and in localisation. Layered workflow (context expansion, specialised agents, counter-evidence, selective verification) is valuable for realistic vulnerability auditing.
5
Discussion
The framework highlights a shift in code security analysis: key challenge is evidence gathering/checking/reconciliation (not just code representation). Bounded context retrieval, specialised agents, selective verification, and counter-evidence enable practical repository-level security auditing.
6
Conclusion
This paper presents VulnAgent-X, a layered agentic framework for repository-level vulnerability detection. The method combines triage, context expansion, specialised analysis, dynamic verification, and evidence fusion to improve reliability in realistic settings. Experimental design confirms the workflow’s value on realistic benchmarks where pattern matching is insufficient. Future work will validate with real results, stronger execution tools, and broader repository settings.
