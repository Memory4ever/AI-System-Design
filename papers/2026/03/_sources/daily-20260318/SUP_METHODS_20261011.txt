L97: # Code-A1: Adversarial Evolving of Code LLM and Test LLM via Reinforcement Learning
L98: 
L99: Aozhe Wang    Yuchen Yan    Nan Zhou    Zhengxi Lu    Weiming Lu Affiliation: Zhejiang University    Jun Xiao Affiliation: Zhejiang University    Yueting Zhuang Affiliation: Zhejiang University    Yongliang Shen
L100: ###### Abstract
L101: Reinforcement learning for code generation relies on verifiable rewards from unit test pass rates. Yet high-quality test suites are scarce, existing datasets offer limited coverage, and static rewards fail to adapt as models improve.
L102: Recent self-play methods unify code and test generation in a single model, but face a inherent dilemma: white-box access leads to self-collusion where the model produces trivial tests for easy rewards, yet black-box restriction yields generic tests that miss implementation-specific bugs. We introduce Code-A1, an adversarial co-evolution framework that jointly optimizes a Code LLM and a Test LLM with opposing objectives.
L103: The Code LLM is rewarded for passing more tests, while the Test LLM is rewarded for exposing more defects. This architectural separation eliminates self-collusion risks and safely enables white-box test generation, where the Test LLM can inspect candidate code to craft targeted adversarial tests. We further introduce a Mistake Book mechanism for experience replay and a composite reward balancing test validity with adversarial difficulty.
L104: Experiments on Qwen2.5-Coder models demonstrate that Code-A1 achieves code generation performance matching or exceeding models trained on human-annotated tests, while significantly improving test generation capability.

L106: ## 1 Introduction
L107: Reinforcement learning has emerged as a powerful paradigm for enhancing the reasoning capabilities of large language models, with code generation serving as a representative task that admits precise, executable verification (cite87†Guo et al., 2025 ; cite88†Shao et al., 2024 ).
L108: Unlike open-ended text generation, code can be automatically validated against unit tests, providing verifiable rewards that guide policy optimization without human annotation at training time (cite89†Le et al., 2022 ; cite90†Shojaee et al., 2023 ).
L109: However, the effectiveness of this paradigm hinges critically on the quality of the underlying test suites. In practice, obtaining comprehensive unit tests demands substantial human effort, and existing RL-suitable datasets remain limited in both scale and diversity (cite91†Chen et al., 2021 ; cite92†Austin et al., 2021 ).
L110: Even in carefully curated benchmarks, each question typically contains only three to five test cases, which cannot reliably distinguish genuinely correct solutions from those that happen to pass by coincidence or handle only common inputs (cite93†Liu et al., 2023b ). Furthermore, these static golden tests cannot adapt to evolving model capabilities.
L111: When tests are overly simple, flawed code may receive undeserved positive rewards; when tests are overly stringent, near-correct solutions are penalized as complete failures (cite94†Jeong et al., ). Both scenarios distort the learning signal and limit the potential of RL-based training.
L112: To address the limitations of static rewards, recent work has explored automated test generation (cite95†Chen et al., ; cite96†Zeng et al., 2025 ) and self-play frameworks (cite97†Wang et al., 2025 ; cite98†Zhao et al., 2025 ) where a single model generates both code and tests. These approaches promise dynamic rewards that adapt to model capabilities, potentially breaking free from static constraints. Yet they fail to deliver on this promise.
L113: Direct generation methods often produce invalid or hallucinated tests (cite99†He et al., 2025 ). Self-play faces a more fundamental

L115: dilemma: when restricted to black-box mode (observing only question descriptions), tests remain generic and miss implementation-specific bugs; when permitted white-box access to candidate code, the model exploits this through self-collusion, generating trivial tests for easy rewards since passing code offsets penalties for weak testing within a unified model (cite101†Denison et al., 2024 ).
L116: To prevent collusion, self-play must restrict test generation to black-box mode, sacrificing the ability to craft targeted tests that probe implementation-specific bugs. This black-box restriction fundamentally undermines dynamic adaptation, as test difficulty becomes decoupled from the actual code being evaluated.
L117: This analysis reveals a key insight: effective verifiable rewards require dynamic interplay between code robustness and test rigor, where test difficulty continuously adapts to challenge the current policy. A good test suite must be valid (executable and correct), sufficiently challenging (exposing real defects), yet not impossibly difficult (providing learnable gradients).
L118: These competing objectives cannot be optimized by a single model or static dataset—they require adversarial co-evolution where two specialized agents continuously push each other toward improvement, with architectural separation that prevents self-collusion while enabling targeted adversarial optimization.
L119: We introduce Code-A1, an adversarial reinforcement learning framework that jointly optimizes a Code LLM and a Test LLM with opposing objectives. Given a question, the Code LLM generates candidate solutions while the Test LLM generates challenging test cases; the two are paired and executed in a sandbox. The Code LLM receives higher rewards for passing more tests, incentivizing robust and correct solutions.
L120: The Test LLM receives higher rewards for failing the code, incentivizing the discovery of edge cases and subtle bugs. As both models improve, rewards dynamically adapt: stronger code demands harder tests, and harder tests demand stronger code. This adversarial yet complementary setup enables continuous co-evolution beyond any static performance ceiling.
L121: To stabilize this adversarial dynamics, we introduce several key designs. First, we decouple the two tasks into separate models, eliminating the self-collusion risks inherent in self-play and enabling safe white-box adversarial optimization. Second, we design a composite reward for the Test LLM that balances validity (tests must execute correctly) with adversarial difficulty (tests should expose defects), avoiding both trivial and impossible tests.
L122: Third, we maintain a Mistake Book—an experience replay buffer that records historically failed tests for each question—ensuring that resolved bugs are not forgotten and providing stable baselines for reward computation.
L123: We conduct extensive experiments on Qwen2.5-Coder models (1.5B, 3B, 7B). On code generation benchmarks, Code-A1 consistently outperforms both models trained on human-annotated golden tests and self-play baselines across all scales. On test generation, the results reveal remarkable efficiency: the 3B model achieves a Mul score of 15.29, surpassing the 7B base model (14.72), demonstrating that adversarial co-evolution discovers bug-revealing patterns more effectively than parameter scaling alone.
L124: Our contributions can be summarized as follows:
L125: 
L126:   * •
L127: 
L128: We introduce adversarial co-evolution into code RL, enabling dynamic and adaptive verifiable rewards that eliminate reliance on static human-annotated test suites.
L129: 
L130:   * •
L131: 
L132: We develop Code-A1, comprising dual-policy optimization with opposing objectives, validity-aware reward shaping for the Test LLM, and a Mistake Book mechanism for stable experience replay.
L133: 
L134:   * •
L135: We demonstrate empirically that Code-A1 matches or exceeds the performance of RL with static golden tests on code generation benchmarks, while simultaneously producing a Test LLM capable of generating high-quality, bug-revealing tests.
L136: ## 2 Related Works
L137: ### 2.1 Reinforcement Learning for Code Reasoning
L138: Reinforcement Learning (RL) effectively bridges the gap left by traditional supervised learning, which primarily focuses on similarity at the token level, by directly optimizing for the functional correctness of code. Unlike general text generation, code generation inherently possesses an executable verification environment, enabling the utilization of compiler feedback and unit test outcomes as reward signals. This characteristic naturally aligns code generation with reinforcement learning paradigms.
L139: Early explorations utilized architectures comprising Actor and Critic networks, guiding models to generate compliant code by incorporating dense feedback signals derived from test case pass rates (cite89†Le et al., 2022 ). Building on this, methods based on Proximal Policy Optimization (PPO) have been widely applied to directly integrate discrete execution feedback (cite102†Zhang et al., 2024b ).
L140: These approaches translate compilation rates and test pass rates into reward values, while employing KL divergence constraints to stabilize the training process (cite90†Shojaee et al., 2023 ).
L141: To address the issue of sparse reward signals in code tasks—where programs are typically binary (correct or incorrect) and lack intermediate states—researchers have introduced optimization strategies based on granular feedback. The RLTF framework leverages error signals across various levels (e.g., compilation, runtime, and logic errors) to provide immediate feedback at multiple levels of detail, thereby guiding model exploration more precisely during online training (cite103†Liu et al., 2023a ).
L142: Furthermore, given the high computational overhead and potential instability associated with online RL algorithms like PPO, efficient alignment methods based on ranking have also been adapted for code tasks. These approaches eliminate the need for an explicit reward model; instead, they rank and select sampled candidate code based on test outcomes, achieving effective alignment with execution feedback while significantly reducing training costs (cite104†Shen et al., 2023 ).

L87: ## 7 Related Work
L88: The methods used to password-lock models bear similarities to techniques from Machine Unlearning (cite51†Geng et al., 2025 ). Here, work has shown (cite46†Chen et al., 2025 ) that the use of gradient-based unlearning algorithms such as gradient ascent (cite39†Feng et al., 2024 ) leave fingerprints that can be identified by specially trained classifiers.
L89: However, the ease of identifying an unlearned model is attributed to a collapse in its fluency and capabilities and it is unclear whether the identifiability of unlearning methods is primarily due to their destructive effect on the model. Additionally, this work does not explore whether classifiers can generalise to unseen knowledge topics or model architectures and hence cannot comment on whether the traces left by unlearning are common across various settings.
L90: We show that methods such as ‘in-context password locking’ do not negatively affect task performance and fluency, but can still be identified, suggesting that the shift in output distribution caused by concealment is not simply a degradation in model quality. Additionally, by showing that the classifiers can generalise to unseen models and knowledge areas, we establish that the trends they learn are distinctive patterns which are consistent across various settings.
L91: ## 8 Implications and Conclusion
L92: In this work, we explore the detection of LM knowledge concealment and find that success is contingent on the concealment method and scale of the concealer. Optimistically, we find that gradient-based methods are easily identified and pose a limited threat to auditability. While traces associated with prompt-based concealment prove more elusive to human annotators, we show that classifiers can consistently detect prompt-based concealment in models around the 8B parameter scale.
L93: Unfortunately, this is not the case for prompt-based concealment with larger LMs, and our work highlights the difficulty of detecting concealment at scales larger than 70B. Until robust methods for detecting prompt-based concealment are developed, the most reliable way to evaluate a model for its true capabilities is to avoid the hidden influence of a prompt by querying it in the white-box setting (cite52†Duan et al., 2024 ).
L94: We hence join calls asking for model creators to release their model weights, to enable more robust auditing of LMs  (cite53†Tamirisa et al., 2025 ).
L95: ## 9 Limitations
L96: Our work demonstrates that prior work on the detection of Language Model unlearning (cite46†Chen et al., 2025 ) and lying (cite35†Pacchiardi et al., 2024 ) are not robust to the scale of the model under audit, specifically when prompt-based concealment is employed. However, we focus our effort onto showing the failure modes of contemporary detection approaches, as opposed to providing explanations for why increasing the scale of the concealer leads to better concealment.
L97: We conjecture that, since this behavior is not one that model creators have intentionally attempted to promote during training, it is one in a large set of seemingly emergent capabilities (cite50†Wei et al., 2022 ). However, our understanding of the emergence phenomenon remains poor (cite54†Lu et al., 2024 ) and some claim that ‘emergence’ is more an artifact of the choice of metric than a truly abrupt change in model abilities (cite55†Schaeffer et al., 2023 ).
L98: Given the range of phenomenon over which emergence unfolds, we believe a deeper investigation into how scale leads to advanced model capabilities is out of scope for this work.
L99: ## 10 Ethical Considerations
L100: The findings of our work hold implications for the safe auditing and deployment of Language Models (cite34†Weidinger et al., 2021 ). As a technology that is increasingly being deployed and served directly to consumers (cite56†Dam et al., 2024 ), it becomes vital to ensure they are not transmitting harmful information that could be used for malicious purposes (cite26†Li et al., 2024a ).
L101: Our work demonstrates a gap in our ability to reliably audit models with only API-level or black box access, a common release paradigm for frontier models (cite57†Hurst et al., 2024 ; cite58†Achiam et al., 2023 ; cite59†OpenAI, ; cite60†Anthropic, 2024 ). We advocate for auditors to be provided open-weight access to new models, so that audits of their knowledge and capability can be conducted without the fear of active deception or concealment.
