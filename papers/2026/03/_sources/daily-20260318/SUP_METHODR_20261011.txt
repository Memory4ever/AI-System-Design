L173: ### 4.2. Progressive Graph Evolution
L174: To address the low-diversity challenge identified in Section cite10†3 , we introduce Progressive Graph Evolution (Algorithm cite81†2 ), a graph operator that progressively grows the synthesis graph from basic nodes to increasingly diverse ones. Specifically, we first evolve the graph from API nodes into initial sample nodes, and then iteratively expand it by synthesizing new sample nodes based on existing sample nodes.
L175: In this way, the graph can explore a much larger API composition space, thereby producing increasingly diverse training samples.

L209: (1) Graph Initial Evolution. At the beginning, the graph contains only API nodes. We repeatedly sample a subset of API nodes and use their associated specifications $\mathcal{S}_{\text{api}}\subset\mathcal{S}$ as seeds. We then prompt the LLM to synthesize a sample node based on these APIs:
L210: 
L211: (2)  |  | $$(r,y)=\mathrm{Evolve}(\mathcal{S}_{\text{api}},\mathcal{I}_{\text{init}}),$$  |
L212: where $\mathcal{I}_{\text{init}}$ denotes the instruction prompt for graph initial evolution, $r$ is the generated coding requirement, and $y$ is the corresponding reference solution. This process produces the initial sample nodes in the graph. Since randomly sampled APIs may not always be tightly related, we do not strictly require the LLM to invoke every seed API in the generated solution.
L213: (2) Graph Iterative Evolution. Once a pool of sample nodes has been obtained, we further grow the graph by iteratively synthesizing new sample nodes based on existing ones. Specifically, we randomly sample a small set of existing sample nodes $S_{\text{sample}}=\{(r_{i},y_{i})\}_{i=1}^{m}$ and prompt the LLM to evolve them into a new sample:
L214: 
L215: (3)  |  | $$(r^{\prime},y^{\prime})=\mathrm{Evolve}(S_{\text{sample}},\mathcal{I}_{\text{iter}}),$$  |
L216: where $\mathcal{I}_{\text{iter}}$ is the instruction prompt for graph iterative evolution. The operator $\mathrm{Evolve}(\cdot)$ instructs the LLM to integrate multiple existing requirements into a single coherent and more diverse requirement $r^{\prime}$, and to produce a reference solution $y^{\prime}$ that satisfies this new requirement through coordinated invocation of multiple private APIs.
L217: By progressively applying graph iterative evolution, the synthesis graph moves beyond basic training samples and gradually covers more diverse development scenarios.
L218: ### 4.3. Multidimensional Graph Pruning
L219: 
L220: cite82†Image: Refer to caption Figure 2. Overview of PriCoder. Starting from API nodes, PriCoder progressively evolves the synthesis graph to construct increasingly diverse sample nodes, while multidimensional graph pruning removes low-quality nodes through syntactic verification, execution verification, and overall functionality verification.
L221: To address the poor-quality challenge identified in Section cite10†3 , we introduce Multidimensional Graph Pruning (Algorithm cite83†3 ), a graph operator that removes low-quality sample nodes through multidimensional quality verification. For any new sample node $(r,y)$, we retain it in the Graph only if it passes three complementary checks which target different failure modes: syntactic correctness, execution validity, and overall functionality.
L222: Formally, we define three binary validators $V_{\text{syn}},V_{\text{exe}},V_{\text{sem}}\in\{0,1\}$ and retain a sample node in the Graph only if
L223: (4)  |  | $$V(r,y)=V_{\text{syn}}(r,y)\cdot V_{\text{exe}}(r,y)\cdot V_{\text{sem}}(r,y)=1.$$  |
L224: (1) Syntactic Verification. We first perform lightweight static verification to ensure the basic well-formedness of the generated code. Specifically, we parse the reference solution $y$ using the standard Abstract Syntax Tree (AST) parser of the target programming language. Any sample that fails to parse is discarded. This step removes obviously invalid code before invoking more expensive verification procedures.
L225: (2) Execution Verification. Syntactic correctness does not imply correct private-API invocation. To better ensure execution validity and eliminate mistakes, we verify executability via test-based execution. For each sample $(r,y)$, we prompt the LLM to generate a set of unit tests $T=\{t_{j}\}$, including representative inputs and corresponding assertions. We then execute $y$ against $T$ in a sandboxed environment. Samples are discarded if they raise runtime errors or fail any assertion.
L226: (3) Overall Functionality Verification. Even if a sample is executable, the synthesized requirement and solution may still be unreasonable. To further improve data quality, we follow the widely adopted LLM-as-a-Judge paradigm (cite84†He et al., 2026 ; cite85†Feng et al., 2025 ; cite86†Do et al., 2025 ) to assess the overall functionality of the synthesized samples.
L227: Concretely, we use the LLM to assess its own synthesized sample, including (i) whether the requirement $r$ is realistic and well-defined, and (ii) whether the solution $y$ truly satisfies $r$ in intent. Any sample that fails this evaluation is also discarded.

L163: ##### Causal Score
L164: 
L165: The causal score measures how much each layer influences the computations of all subsequent layers (cite78†Csordás et al., 2025 ). For a model with $N$ layers and hidden states $\mathbf{h}_{\ell}$ at layer $\ell$, we define the causal effect of layer $s$ on layer $\ell>s$ as:
L166: 
L167:  | $$\small C(s,\ell)=\frac{\|(\mathbf{h}_{\ell+1}-\mathbf{h}_{\ell})-(\bar{\mathbf{h}}_{\ell+1}-\bar{\mathbf{h}}_{\ell})\|_{2}}{\|\mathbf{h}_{\ell+1}-\mathbf{h}_{\ell}\|_{2}},$$  |  | (5)
L168: where $\mathbf{h}_{\ell}$ denotes hidden states in the baseline model, and $\bar{\mathbf{h}}_{\ell}$ denotes hidden states when layer $s$ is skipped. The global causal score aggregates these effects across all layer pairs:
L169: 
L170:  | $$\small S_{\text{causal}}=\frac{1}{\sqrt{N}}\cdot\frac{1}{N}\sum_{s=0}^{N-1}\left[\frac{1}{N-s-1}\sum_{\ell=s+1}^{N-1}C(s,\ell)\right],$$  |  | (6)
L171: where $1/\sqrt{N}$ normalizes for model depth. Higher causal scores indicate critical layers whose removal affects subsequent layers, while lower scores suggest minimal impact and potential redundancy.
L172: ##### Permutation Score
L173: 
L174: The permutation score quantifies layer specialization by measuring performance degradation when layer positions are swapped (cite85†Kapl et al., 2025 ). For layers $\ell_{1}$ and $\ell_{2}$, the pairwise permutation score is:
L175: 
L176:  | $$\small P(\ell_{1},\ell_{2})=\frac{|\mathcal{L}(M)-\mathcal{L}(M_{\text{swap}(\ell_{1},\ell_{2})})|}{|\mathcal{L}(M)|},$$  |  | (7)
L177: where $\mathcal{L}(M)$ is the baseline loss and $\mathcal{L}(M_{\text{swap}(\ell_{1},\ell_{2})})$ is the loss after swapping. The global permutation score averages over all possible layer pairs:
L178: 
L179:  | $$\small S_{\text{permutation}}=\frac{2}{N(N-1)}\sum_{\ell_{1}=0}^{N-1}\sum_{\ell_{2}=\ell_{1}+1}^{N-1}P(\ell_{1},\ell_{2}).$$  |  | (8)
L180: 
L181: Higher scores indicate that layers are less interchangeable, while scores near zero suggest redundancy.
L182: ##### Usefulness Score
L183: 
L184: The usefulness score quantifies each layer’s contribution through linear approximation (cite85†Kapl et al., 2025 ; cite78†Csordás et al., 2025 ; cite87†Sun et al., 2025 ). This approach measures the degree of nonlinearity each layer contributes, which is a fundamental indicator of computation beyond linear mappings.
L185: For each layer $\ell$, we collect input-output pairs $\{(\mathbf{x}_{i},\mathbf{y}_{i})\}_{i=1}^{N}$ and fit an optimal linear approximation via least-squares. We then measure performance degradation when replacing layer $\ell$ with this linear transformation:
L186: 
L187:  | $$\Delta\mathcal{L}_{\ell}=\mathcal{L}(M_{\ell}^{\text{linear}})-\mathcal{L}(M).$$  |  | (9)
L188: 
L189: The global usefulness score measures the fraction of layers with significant ($>\alpha$) performance impact:
L190:  | $$\small S_{\text{useful}}=\frac{1}{L}\sum_{\ell=1}^{L}\mathbbm{1}\left[\frac{\mathcal{L}(M_{\ell}^{\text{linear}})}{\mathcal{L}(M)}>1+\alpha\right],$$  |  | (10)
L191: 
L192: where we set $\alpha=0.1$. This quantifies the model’s effective nonlinear depth—the fraction of layers performing meaningful nonlinear transformations. Higher scores indicate efficient depth utilization; lower scores reveal redundancy.
L193: ##### Main Observation
L194: We observe a clear causal chain from variance explosion to diminished layer effectiveness. cite116†Figure 2(a) shows that variance grows substantially with depth, aligning with (cite87†Sun et al., 2025 ). This variance explosion drives the Jacobian matrices toward identity mapping: cite117†Figure 2(b) reveals that the Frobenius norm $||J-I||_{F}$ decreases with depth, while cite118†Figure 3 shows increasingly diagonal-dominant Jacobian patterns in deeper models, supporting cite115†Lemma 1 .
L195: Consequently, layer effectiveness deteriorates: cite119†Figure 2(c) demonstrates that all three score progressively decline, with Usefulness dropping from 0.75 ($L=12$) to 0.53 ($L=32$). While $L=32$ achieves better performance (cite120†Table 1 ) with more effective layers (18 vs. 12 for $L=12$), it exhibits severe inefficiency: using $2.56\times$ more parameters while wasting 14 layers, exemplifying CoD where most layers contribute minimally despite consuming substantial training compute.

L208: ### 3.1 Theoretical Analysis
L209: 
L210: Sparsity acts as a variance regularizer in residual stacks by attenuating the energy passed to each layer update. The following lemma quantifies this effect: the per-layer variance gain scales as $\alpha_{\ell}\rho_{\ell}$, so smaller mask density $\rho_{\ell}$ yields slower variance growth with depth.
L211: ###### Theorem 1 (Sparsity reduces variance propagation in residual-depth).
L212: 
L213: Let $\{r_{\ell}\}_{\ell=0}^{L}$ follow the residual-depth recursion
L214: 
L215:  | $$r_{\ell+1}=r_{\ell}+u_{\ell},\quad u_{\ell}:=W_{\ell}\bigl(D_{\ell}r_{\ell}\bigr),\qquad\ell=0,\dots,L-1,$$  |  | (11)
L216: where $r_{\ell}\in\mathbb{R}^{d}$, $D_{\ell}\in\mathbb{R}^{d\times d}$ is a diagonal $0$-$1$ mask, and $W_{\ell}\in\mathbb{R}^{d\times d}$ is a random linear map. Assume that for each $\ell$, $W_{\ell}$ is independent of $(r_{\ell},D_{\ell})$ and satisfies the second-moment bound and that the mask satisfies the density bound
L217: 
L218:  | $$\mathbb{E}\left[\|W_{\ell}x\|_{2}^{2}\right]\leq\alpha_{\ell}\|x\|_{2}^{2},\quad\mathbb{E}\left[\|D_{\ell}x\|_{2}^{2}\right]\leq\rho_{\ell}\|x\|_{2}^{2}$$  |  | (12)
L219: for all $x\in\mathbb{R}^{d}$, and for some $\rho_{\ell}\in[0,1]$. If $\alpha_{\ell}\leq\alpha$ and $\rho_{\ell}\leq\rho<1$ for all $\ell$, then the residual variance satisfies
L220: 
L221:  | $\displaystyle\small\mathrm{Var}(r_{L})\leq\mathrm{Var}(r_{0})\prod_{\ell=0}^{L-1}\Bigl(1+\sqrt{\alpha_{\ell}\rho_{\ell}}\Bigr)^{2}=O\Bigl(1+\sqrt{\alpha\rho}\Bigr)^{2L}.$  |  | (13)
L222: The proof is provided in cite56†B.1 . Theorem cite121†1 shows that the variance bound depends on sparsity only through $\rho_{\ell}$: smaller $\rho_{\ell}$ (sparser $D_{\ell}$) yields a smaller per-layer factor $(1+\sqrt{\alpha_{\ell}\rho_{\ell}})^{2}$, and therefore a smaller upper bound on $\mathrm{Var}(r_{L})$. Hence, sparsity (captured by $\rho_{\ell}$) directly controls variance: smaller $\rho_{\ell}$ yields a smaller bound on $\mathrm{Var}(r_{L})$ across depth.
L223: We observe empirically that $\rho_{\ell}$ can also be mitigated through training-induced sparsity patterns. It is important to note, however, that the theoretical result in Theorem cite121†1 relies on the assumption that the weight $W_{\ell}$ is independent of the sparsity masking variables $(r_{\ell},D_{\ell})$. When sparsity is induced during training, the weights and sparsity patterns become inherently coupled, meaning this strict independence no longer holds.
L224: Nevertheless, Theorem cite121†1 provides a useful conceptual approximation for understanding how emergent sparsity restrains variance accumulation in practice.
L225: ### 3.2 Implicit and Explicit Sparsity
L226: 
L227: Motivated by our theoretical analysis, we identify specific sparsity dimensions for experimental investigation. We categorize sparsity into implicit sparsity and explicit sparsity.
L228: #### 3.2.1 Implicit Sparsity
L229: Implicit sparsity refers to sparsity induced dynamically during training.
L230: This includes sparsity from regularization (weight decay (cite122†Krogh and Hertz, 1991 ; cite123†Loshchilov and Hutter, 2019 )), activation functions (ReLU (cite124†Glorot et al., 2011 ; cite125†Hayou et al., 2019 )), and input-dependent mechanisms (dropout (cite126†Srivastava et al., 2014 ), attention patterns (cite127†Vaswani, 2017 )) that drive parameters or activations toward negligible values (cite128†Frankle and Carbin, 2018 ; cite129†Chen et al., 2020 ).
L231: We investigate two implicit sparsity dimensions: (1) weight decay, and (2) sequence length scaling.
L232: ##### Weight Decay
L233: 
L234: Weight decay applies $L_{2}$ regularization to model parameters, adding penalty term $\lambda\|W\|_{2}^{2}$ to the loss function (cite123†Loshchilov and Hutter, 2019 ). This drives small-magnitude parameters toward zero, inducing sparsity without structural constraints. We quantify the induced sparsity by measuring the fraction of effectively zero parameters. For a trained model with parameter set $\Theta$, we define:
L235:  | $$\text{Sparsity}(\Theta;\epsilon)=\frac{1}{|\Theta|}\sum_{w\in\Theta}\mathbbm{1}[|w|<\epsilon],$$  |  | (14)
L236: 
L237: where $\epsilon$ is a threshold and $\mathbbm{1}[\cdot]$ is the indicator function.
L238: Weight decay provides a simple variance-control effect during training. Under the decoupled update, it contracts the contribution of the initialization over time and limits the variance injected by stochastic gradients, which together reduce the variance of downstream layer outputs (Theorem cite130†3 ). Moreover, in the stable regime $0<\eta\lambda\leq 1$, increasing $\lambda$ tightens this control, yielding smaller output variance.
L239: We therefore interpret weight decay as an optimization-induced implicit regularizer that stabilizes activations by suppressing parameter variance throughout training. The formal statement and proof are deferred to Appendix cite59†B.4 .
L240: ##### Sequence Length
L241: Sequence length scaling induce implicit sparsity in attention mechanisms through positional bias and softmax normalization (cite131†Su et al., 2024 ; cite105†Xiao et al., 2023 ; cite132†Zhang et al., 2023 ). Position embeddings like RoPE (cite131†Su et al., 2024 ) introduce distance-dependent attention decay that the dot product decreases with relative distance. As sequence length $T$ increases, this distance penalty causes attention to concentrate on a subset of positions with favorable relative distances.
L242: Softmax normalization over longer sequences produces more peaked distributions, concentrating attention on top-scoring positions while suppressing others toward zero (cite105†Xiao et al., 2023 ; cite132†Zhang et al., 2023 ; cite104†Yuan et al., 2025 ). We quantify attention sparsity by measuring the fraction of near-zero attention weights. For attention weights $\mathbf{A}_{\ell,h}\in\mathbb{R}^{T\times T}$ at layer $\ell$ and head $h$, we compute the sparsity at threshold $\epsilon$ as:
L243:  | $$\small\text{Sparsity}_{\ell,h}(\epsilon)=\frac{1}{T^{2}}\sum_{i=1}^{T}\sum_{j=1}^{T}\mathbbm{1}[A_{i,j}<\epsilon],$$  |  | (15)
L244: 
L245: where $\mathbbm{1}[\cdot]$ is the indicator function. This measures the percentage of attention weights below $\epsilon$. The global attention sparsity aggregates across all layers and heads:
L246: 
L247:  | $$\small\text{Sparsity}_{\text{global}}(\epsilon)=\frac{1}{L\cdot H}\sum_{\ell=1}^{L}\sum_{h=1}^{H}\text{Sparsity}_{\ell,h}(\epsilon)$$  |  | (16)
L248: where $L$ is the number of layers and $H$ is the number of attention heads per layer.
L249: 
L250: Beyond inducing sparsity, longer sequences average out stochasticity in attention output (cite133†Theorem 4 ; see Appendix cite60†B.5 for details): under the uniform-attention approximation, the output behaves like an average over $T$ independent value coordinates, so variance decreases inversely with $T$.
L251: #### 3.2.2 Explicit Sparsity
L252: Explicit sparsity refers to architectural constraints that hard-code sparsity patterns into the model structure, ensuring that a predetermined fraction of connections or computational paths are absent by design (cite102†Ainslie et al., 2023 ; cite134†Dai et al., 2024 ; cite135†Fedus et al., 2022 ; cite136†Abnar et al., 2025 ). Unlike implicit sparsity that emerges dynamically during training, explicit sparsity is fixed at model initialization through architectural choices.
L253: In this study, we examine two prominent forsm of explicit sparsity in LLM design: (1) Grouped Query Attention (GQA), and (2) Mixture of Experts (MoE).
L254: ##### Grouped Query Attention
L255: 
L256: GQA (cite102†Ainslie et al., 2023 ; cite103†Shazeer, 2019 ) reduces attention computation by sharing key-value heads across multiple query heads. In standard multi-head attention with $H$ heads, each head maintains independent query ($\mathbf{Q}_{h}$), key ($\mathbf{K}_{h}$), and value ($\mathbf{V}_{h}$) projections.
