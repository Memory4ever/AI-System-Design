Abstract
Effective memory management is essential for large language model (LLM) agents handling long-term interactions.
Current memory frameworks typically treat agents as passive “recorders” and retrieve information without understanding its deeper implications.
They may fail in scenarios requiring conflict detection and complex decision-making.
To bridge this critical gap, we propose a novel actionable memory framework called ActMem that integrates memory retrieval with active causal reasoning.
ActMem transforms unstructured dialogue history into a structured causal and semantic graph.
By leveraging counterfactual reasoning and commonsense completion, it enables agents to deduce implicit constraints and resolve potential conflicts between past states and current intentions.
Furthermore, we introduce a comprehensive dataset ActMemEval to evaluate agent reasoning capabilities in logic-driven scenarios,
moving beyond the fact-retrieval focus of existing memory benchmarks.
Experiments demonstrate that ActMem significantly outperforms state-of-the-art baselines in handling complex, memory-dependent tasks, paving the way for more consistent and reliable intelligent assistants.
1 Introduction
Large language models (LLMs) have demonstrated remarkable capabilities in natural language understanding and generation, serving as the backbone for various intelligent agents.
To enable these agents to handle long-term interactions, effective memory management is essential Zhang et al. (2025c).
Conventionally, memory frameworks in LLM agents focus on expanding context windows or utilizing retrieval-augmented generation (RAG) to store, update and recall historical interactions.
These methods aim to improve the capacity of memory recall, ensuring that the agent can retrieve specific information from a vast repository of past dialogues Hu et al. (2025).
However, a fundamental gap remains between simply remembering the past and effectively using it.
Existing memory management methods typically serve as a passive “recorder,”
where the goal is to compress, summarize, and retrieve historical text Fang et al. (2025); Yang et al. (2026).
While RAG-based methods can fetch relevant dialogue snippets Gao et al. (2023), they often fail to understand the deeper implications of that memory for current decision-making.
In real-world applications, an agent acts as a human assistant, not just a “archivist” He et al. (2025).
For instance, when a user proposes a new schedule, the agent should not only recall previous similar ones but also find event conflicts and offer adjustment suggestions.
This requires the agent to go beyond memory retrieval and perform active reasoning based on historical states.
We define this capability as the utility of memory for action.
This limitation is also reflected in current memory management benchmarks.
Existing datasets, such as LoCoMo Maharana et al. (2024), LongMemEval Wu et al. (2025), and HaluMem Chen et al. (2025), primarily evaluate the accuracy of memory retrieval through QA tasks.
They assess whether the agent can “find” the answer but overlook whether the agent can “reason” upon it.
They lack scenarios involving complex causal reasoning where the answer is not explicitly stated in the history but must be deduced.
Their evaluations fail to measure how well an agent can utilize memory to assist in current planning that may conflict with past state.

(a) An example from LongMemEval representing memory retrieval.
(b) An example illustrating the necessity of memory reasoning. Although the user’s current query (buying Sago Palms) does not semantically overlap with the past memory (a teething puppy), the agent should infer the latent conflict based on the common sense that Sago Palms are toxic.
To clearly illustrate the limitations of current benchmarks and the motivation behind our work,
we present a comparison in Figure 1.
Subfigure (a) shows a typical example from LongMemEval.
The user’s query explicitly matches a record in the past memory summaries.
The agent only needs to perform semantic or vectorized matching to retrieve the fact.
This is a task that evaluates the capacity of memory recall.
In contrast, Subfigure (b) shows a more realistic and challenging scenario that necessitates memory reasoning.
The user asks for the location to buy “Sago Palms.”
A retrieval-based agent would simply provide purchasing information (as indicated by the incorrect response).
However, the dialogue history contains a critical information:
the user has a puppy that is “teething” and “chewing on everything.”
Given that Sago Palms are highly toxic to dogs,
a responsible agent should infer the potential danger and intervene with a warning.
We find that LLMs generally possess this commonsense knowledge,
but under existing agent memory management frameworks, they tend to overlook it and thus struggle to leverage it for auxiliary reasoning.
The inability to reason over memory can lead to conflicting advice or even dangerous recommendations.
This example highlights the gap we aim to bridge: transforming the agent from a passive retriever to an active reasoner that ensures the utility of memory for action.
To bridge this gap, we propose ActMem, a new memory management framework that integrates memory retrieval with causal reasoning.
It first extracts memory facts to summarize raw dialogue history.
Then, it utilizes embedding-based clustering to group topic-related facts and establish semantic edges between fact pairs that exceed a similarity threshold to preserve contextual connectivity.
After that, it mines causal relations of facts.
Furthermore, it performs counterfactual reasoning, commonsense completion and PMI-based filtering to refine cause edges.
The facts with their semantic and causal edges form a memory knowledge graph (KG).
This allows the agent to identify associations, resolve mutual exclusions, and deduce implicit constraints that influence current actions.
Finally, to evaluate this new setting, we introduce a new dataset called ActMemEval.
Unlike traditional retrieval-based benchmarks,
our dataset focuses on scenarios requiring active reasoning and causal deduction.
In summary, the contributions of this paper are as follows:
•
We identify the critical limitation of current agent memory systems: the disconnect between memory retrieval and reasoning. We propose a shift in focus from the “capacity of recall” to the “utility of memory for action.”
•
We introduce ActMem, an actionable memory management framework. By integrating a memory KG with causal and semantic edges, ActMem enables agents to utilize past experiences for robust decision-making.
•
We construct a comprehensive dataset ActMemEval to evaluate the reasoning capabilities of agents in long-term interactions, covering complex tasks that require logic-driven memory utilization.
•
Extensive experiments demonstrate that ActMem significantly outperforms existing baselines in handling complex, logic-driven tasks. It also achieves competitive and even SOTA performance on conventional datasets.
We hope this work will pave the way for future research into more consistent and human-aligned intelligent assistants.

2 Related Work
2.1 Agent Memory Management
Memory management is recognized as a core capability for intelligent agents, enabling continuity in long‑term interactions Zhang et al. (2025c); Hu et al. (2025).
Existing studies can be grouped into three paradigms: system‑level management, structured organization, and experience‑based guidance.
OS‑style memory management.
Early work seeks to address the context‑window limitations of LLMs.
MemGPT Packer et al. (2023) introduces OS‑inspired mechanisms such as paging and segmentation, inspiring later frameworks like MemOS Li et al. (2025) and MemoryOS Kang et al. (2025).
In parallel, retrieval‑centric systems such as Mem0 Chhikara et al. (2025) and MemoryBank Zhong et al. (2024) adopted a RAG‑style paradigm Gao et al. (2023), emphasizing memory lifecycle management, i.e, storage, retrieval, and updating, to ensure efficient access to relevant history.
Structured memory management.
To overcome the limitations of flat text, recent work explores structured formats for better memory organization.
Examples include tree‑based designs like MemTree Rezazadeh et al. (2025) and graph‑based framework such as A‑Mem Xu et al. (2025).
Other studies propose hierarchical or compositional memory frameworks Rasmussen et al. (2025); Zhang et al. (2025a) to capture dependencies across dialogue turns.
These methods show that introducing topology significantly improves retrieval precision over unstructured text chunks.
Memory as execution guidance.
Beyond fact recall,
another line of research leverages memory to guide decision‑making through past experiences. This includes trajectory‑level retrieval Zheng et al. (2024); Kong et al. (2025), where agents imitate successful workflows, and case‑based reuse Kim et al. (2024), where subtasks are retrieved to support intermediate reasoning Zhou et al. (2024)
These methods aim to extract procedural patterns or heuristics from execution histories to support planning in new scenarios.
Discussions.
Despite these advances, a key gap remains. As highlighted in recent surveys Hu et al. (2025), existing methods largely treat memory as passive storage with fixed representations.
Whether using RAG or trajectory replay, retrieval still relies heavily on surface‑level semantic similarity, making it difficult to detect implicit conflicts or adapt past experiences to dynamic environments.
This often leads to negative transfer or hallucinations.
In contrast, our proposed ActMem adopts an event‑centric design that explicitly encodes logical structures and causal dependencies, transforming memory from passive storage into an active reasoning engine.

2.2 Synthetic Evaluation Benchmark
Synthetic evaluation benchmarks have emerged as a popular paradigm for assessing the capabilities of LLMs in controlled manner.
Currently, synthetic evaluation has evolved from assessing simple information retention to measuring complex reasoning capabilities.
Recent initiatives, including RULER Hsieh et al. (2024) and BABILong Kuratov et al. (2024) include variable tracking and logical chaining, while other datasets like LoCoMo Maharana et al. (2024) and LongMemEval Wu et al. (2025) target long-term dialogue consistency and agent memory retrieval.
Despite these advancements, existing benchmarks remain QA-oriented, assessing whether an agent can passively retrieve information rather than actively utilize it for decision-making.
We address this limitation with a new dataset ActMemEval, which specifically evaluates the utility of memory for action through scenarios involving implicit constraints and causal conflicts.
We ensure the reliability of the dataset through human verification.
3 The ActMem Framework
In this section, we present ActMem to bridge the gap between passive retrieval and active reasoning in LLM agents.
As illustrated in Figure 2, the framework consists of four modules:
(1) memory fact extraction,
(2) fact clustering,
(3) memory KG construction,
and
(4) counterfactual-based retrieval and reasoning.
Formally, we define the raw dialogue history as 𝒟={u1,a1,u2,a2,…,ut,at,…,uN,aN}\mathcal{D}=\{u_{1},a_{1},u_{2},a_{2},\dots,u_{t},a_{t},\dots,u_{N},a_{N}\}, where uiu_{i} and aia_{i} denote the user and agent utterances at turn ii, respectively. Our goal is to transform 𝒟\mathcal{D} into a structured memory graph 𝒢\mathcal{G} to support complex decision-making.
3.1 Memory Fact Extraction
Raw dialogue history often contains redundancy and noise that hinder effective reasoning.
To address this, we first compress the raw history 𝒟\mathcal{D} into a set of atomic memory facts ℱ\mathcal{F}.
We employ an LLM-based information extractor to parse the dialogue and generate declarative sentences containing key entities and facts following Fang et al. (2025).
We define a extraction function fext​(⋅)f_{\text{ext}}(\cdot) powered by an LLM to map raw dialogues into a set of atomic facts ℱ\mathcal{F}.
For each dialogue turn (ut,at)(u_{t},a_{t}), we extract a subset of facts:
ℱt=LLM​(pext,ut,at)={ft,1,ft,2,…,ft,k}\mathcal{F}_{t}=\text{LLM}(p_{\text{ext}},u_{t},a_{t})=\{f_{t,1},f_{t,2},\dots,f_{t,k}\}
(1)
where pextp_{\text{ext}} denotes the extraction prompt designed to identify entities and events. The global fact set is the union of all turns: ℱ=⋃t=1Nℱt\mathcal{F}=\bigcup_{t=1}^{N}\mathcal{F}_{t}.
Unlike traditional summarization which compresses the entire context into a single paragraph, our method focuses on atomicity.
This granular extraction serves as the foundation for subsequent causal mining.
3.2 Fact Clustering
To model long-term interactions effectively, it is essential to identify relationships between facts spanning different sessions.
Besides, mining causal edges by computing relations across all pairs of facts in the global history is time-consuming.
To mitigate this, we introduce a fact clustering module.
Let ϕ⁡(⋅)\phi(\cdot) be an embedding function, e.g., Qwen3-Embedding-8B Zhang et al. (2025b),
that maps a textual fact fif_{i} to a dd-dimensional vector 𝐡i∈ℝd\mathbf{h}_{i}\in\mathbb{R}^{d}.
We compute the semantic similarity between two facts using cosine similarity:
𝐡i=ϕ⁡(fi),sim​(fi,fj)=𝐡i⊤​𝐡j‖𝐡i‖​‖𝐡j‖.\mathbf{h}_{i}=\phi(f_{i}),\ \ \ \text{sim}(f_{i},f_{j})=\frac{\mathbf{h}_{i}^{\top}\mathbf{h}_{j}}{\|\mathbf{h}_{i}\|\|\mathbf{h}_{j}\|}.
(2)
To partition ℱ\mathcal{F} into disjoint clusters 𝒞={C1,…,CK}\mathcal{C}=\{C_{1},\dots,C_{K}\} efficiently, we employ a single-pass incremental clustering algorithm.
We maintain a centroid vector 𝐜k\mathbf{c}_{k} for each cluster. For each incoming fact fif_{i}, we calculate its similarity with existing centroids. If the maximum similarity exceeds a threshold τ\tau, the fact is assigned to the corresponding cluster; otherwise, a new cluster is initialized with fif_{i} as its centroid.
This strategy ensures that facts related to the same topic (e.g., “puppy care” or “plant shopping”) are consolidated dynamically.
It allows us to perform causal mining within local clusters, significantly reducing computational overhead while preserving topical coherence.
3.3 Memory KG Construction
The core of ActMem is the construction of the memory KG, denoted as 𝒢=(𝒱,ℰ)\mathcal{G}=(\mathcal{V},\mathcal{E}), where nodes 𝒱\mathcal{V} correspond to memory facts and edges ℰ\mathcal{E} represent causal or semantic relations.
Semantics edge generation.
Following clustering, for each fact cluster, we calculate the pairwise similarity between facts and add a semantic edge between any two nodes whose similarity exceeds a predefined threshold.
Raw causal edge generation.
Within each cluster CkC_{k} and each dialogue session,
we prompt the LLM to identify potential causal edges.
Let ℋk\mathcal{H}_{k} be the set of candidate pairs (fi,fj)(f_{i},f_{j}) identified by the model as potentially causal (i.e., fi→fjf_{i}\to f_{j}):
ℋk=LLM​(pcause,Ck).\mathcal{H}_{k}=\text{LLM}(p_{\text{cause}},C_{k}).
(3)
PMI-based hallucination filtering. A major challenge in using LLMs for causal mining is “causal hallucination” where the model identifies spurious correlations as causation.
To verify the candidate edges in ℋk\mathcal{H}_{k}, we employ a verification mechanism based on Pointwise Mutual Information (PMI).
It quantifies the information gain provided by the antecedent fact fif_{i} for generating the consequent fact fjf_{j}.
We define the verification score SPMIS_{\text{PMI}} as the reduction in the negative log-likelihood of generating fjf_{j} when conditioned on fif_{i}:
SPMI​(fi,fj)=ℒℳ​(fj∣Tuncond)−ℒℳ​(fj∣Tcond),S_{\text{PMI}}(f_{i},f_{j})=\mathcal{L}_{\mathcal{M}}(f_{j}\mid T_{\text{uncond}})-\mathcal{L}_{\mathcal{M}}(f_{j}\mid T_{\text{cond}}),
(4)
where ℒℳ​(⋅)\mathcal{L}_{\mathcal{M}}(\cdot) denotes the cross-entropy loss of the target sequence fjf_{j} computed by a pre-trained language model ℳ\mathcal{M} (e.g., GPT2-Large) .
To model the causal dependency, we design specific prompt templates for the input contexts:
(1) The conditional context TcondT_{\text{cond}} constructs the sequence “fi​. As a result, ​fjf_{i}\text{. {As a result}, }f_{j}”;
(2) The unconditional context TuncondT_{\text{uncond}} uses a neutral prefix “The fact is that ​fj\text{{The fact is that} }f_{j}”.
A positive SPMIS_{\text{PMI}} indicates that the presence of fif_{i} significantly lowers the uncertainty of fjf_{j}.
Consequently, we retain only the pairs with a PMI score exceeding a threshold τ\tau:
ℰc​a​u​s​a​l={(fi,fj)∈⋃ℋk∣SPMI​(fi,fj)>τ}.\mathcal{E}_{causal}=\{(f_{i},f_{j})\in\bigcup\mathcal{H}_{k}\mid S_{\text{PMI}}(f_{i},f_{j})>\tau\}.
(5)
Finally, we merge these validated causal edges with semantic edges to form the final memory graph 𝒢\mathcal{G}.
3.4 Counterfactual-based Retrieval and Reasoning
Traditional RAG systems retrieve memories solely based on the semantic similarity to the user’s current query qq, often missing implicit constraints.
We propose a retrieval-reasoning-refinement loop to utilize the memory KG effectively.
Step 1: Initial retrieval. We retrieve a subset of facts 𝒱i​n​i​t⊂𝒱\mathcal{V}_{init}\subset\mathcal{V} based on vector similarity with qq.
Step 2: Counterfactual reasoning. To bridge the gap between the query and implicit memory constraints, we generate commonsense knowledge by asking a counterfactual question:
kc​s=LLM​(pcounter,q,𝒱i​n​i​t).k_{cs}=\text{LLM}(p_{\text{counter}},q,\mathcal{V}_{init}).
(6)
The question is “If the user does qq, what negative consequences might occur considering 𝒱i​n​i​t\mathcal{V}_{init} or general knowledge?”
Step 3: Refinement and response. We use kc​sk_{cs} as an enhanced query to perform a secondary retrieval, obtaining 𝒱r​e​f​i​n​e\mathcal{V}_{refine}. The final context is 𝒞f​i​n​a​l=𝒱i​n​i​t∪{kc​s}∪𝒱r​e​f​i​n​e\mathcal{C}_{final}=\mathcal{V}_{init}\cup\{k_{cs}\}\cup\mathcal{V}_{refine}.
The agent generates the final response a​n​sans given this context:
a​n​s=LLM​(panswer,q,𝒞f​i​n​a​l).ans=\text{LLM}(p_{\text{answer}},q,\mathcal{C}_{final}).
(7)
Through this mechanism, ActMem transforms the agent from a passive retriever to an active reasoner, ensuring the utility of memory for decision-making.
4 The ActMemEval Benchmark
In this section,
we introduce the pipeline to construct our ActMemEval and the evaluation results.
Figure 3: Pipeline to construct our ActMemEval dataset.
4.1 Dataset Construction
To evaluate the reasoning capabilities of agents in long-term scenarios, we construct ActMemEval, a high-quality dataset featuring complex logical constraints and diverse linguistic styles.
Figure 3 shows the construction pipeline.
Step 1: Reasoning topology synthesis.
Unlike previous datasets that generate dialogues directly, we first synthesize the underlying logic to ensure causal consistency. We employ an advanced LLM as the reasoning topology synthesizer. It generates a directed acyclic graph consisting of:
•
History events: A sequence of background events (e.g., “User adopted a puppy”).
•
Reasoning triggers: Intermediate states derived from history (e.g., “Puppy is teething”).
•
Current event: A user intent that conflicts with or relies on the history (e.g., “User wants to buy Sago Palms”).
This structure explicitly defines the causal transitions and constraint activations required to solve the task.
Step 2: Logical consistency validation.
To reduce “hallucinated logic” or unsolvable queries, the generated topologies are passed to a logical consistency validator.
This module checks whether the reasoning chain from history to the current event is theoretically sound and unambiguous. Topologies containing broken links, weak correlations, or multiple plausible conflicting answers are filtered out, ensuring that every sample in our dataset has a logical ground truth.
Step 3: Stylized dialogue generation.
We convert the validated topologies into natural‑language dialogues using a dialogue editor.
To reflect real‑world diversity, we define a set of user linguistic styles along four dimensions: formality, verbosity, attitude, and urgency.
The logical nodes are then instantiated as anchor sessions, i.e., key dialogue turns containing essential evidence,
while following a sampled linguistic profile.
This design forces the agent to rely on semantic understanding rather than simple pattern matching.
Step 4: Noise injection and stream assembly.
In real-world interactions, key information is often sparse and hidden within casual chitchat. To reflect this, we build a noise session pool containing generic daily conversations (e.g., greetings, weather talk) and insert these sessions between the anchor sessions to form a full long‑context dialogue stream. This design tests the agent’s ability to filter out irrelevant content.
Step 5: Manual verification.
Finally, to ensure the reliability of the benchmark, we employ a human‑in‑the‑loop verification process. Annotators examine the final dialogue streams to confirm that (1) logical constraints are preserved, (2) the answer is inferable from the given sessions, and (3) the text is natural and fluent. Among the 300 generated samples, only 246 that pass this inspection are retained in the final dataset.
4.2 Dataset Evaluation
To evaluate our dataset,
we compute the semantic similarity (using cosine similarity of embeddings) between the ground-truth answers and the raw dialogue history.
We compare our ActMemEval with the retrieval‑based benchmark LongMemEval Wu et al. (2025).
As shown in Figure 4,
ActMemEval (red) exhibits substantially lower similarity, indicating that answers cannot be directly retrieved and instead require reasoning.
In contrast, LongMemEval (blue) shows high similarity, suggesting that it mainly evaluates recall ability.
Specifically, LongMemEval reaches an average similarity of 0.347, implying that many answers share considerable lexical or semantic overlap with the context.
ActMemEval yields a much lower average similarity of 0.232, a gap of more than 0.1, which confirms our answers are semantically distant from the raw history and must be inferred rather than extracted.

5 Experiments
5.1 Baselines
To comprehensively evaluate the performance of ActMem,
we benchmark it against five representative memory frameworks:
•
NaiveRAG: The standard baseline that retrieves the top-kk
relevant dialogue snippets based on vector similarity and concatenates them into the context window.
•
Mem0 Chhikara et al. (2025): An advanced memory framework for personalized AI agents, focusing on efficient memory storage and graph-like organization.
•
A-Mem Xu et al. (2025): An agentic memory framework that emphasizes associative retrieval mechanisms to handle long-term interactions.
•
MemoryOS Kang et al. (2025): A system-level memory management framework that provides operating system-like interfaces for agents to read and write memories.
•
LightMem Fang et al. (2025): A efficient and SOTA memory framework utilizing hierarchical summaries to reduce token consumption while maintaining context.
5.2 Evaluation Metrics
We employ two key metrics to assess both the precision of recall and the effectiveness of reasoning:
•
Retrieval accuracy:
This evaluates whether the agent can successfully recall the specific memory facts required to resolve the query.
Following the work Chen et al. (2025), retrieval accuracy is calculated as the recall rate of ground-truth evidence facts in our dataset.
•
Question-answering accuracy:
This metric measures the final utility of the memory.
It assesses whether the generated response correctly addresses the user intent while adhering to historical constraints.
Given the open-ended nature of generation, we utilize an LLM-as-a-Judge method (using DeepSeek-V3) to score the correctness of the response against the ground truth.

5.3 Implementation Details
We employ two LLMs as backbones for reasoning and generation:
DeepSeek-V3, representing high-performance open-source models,
and GPT-4o-mini, representing efficient lightweight models.
For memory representation, we utilize Qwen3-Embedding-8B Zhang et al. (2025b) to generate semantic vectors.
For hyperparameter settings,
in the event clustering module, we apply clustering with a distance threshold of 0.2.
The threshold used for semantic‑edge filtering is 0.3.
For causal edge construction, the PMI validation threshold is empirically set to 0.8.
During the retrieval phase, we set the number of retrieved memory facts to 20 for the initial retrieval step.
The number of counterfactual facts retrieved is set to 10.
In the refinement step, we dynamically retrieve additional facts based on the generated KG.
For the baseline configuration, we standardize the final QA prompts across all methods to ensure a fair comparison.
The original baseline prompts mainly emphasize direct use of retrieved memory and lack explicit instructions for complex reasoning, which leads to substantial performance degradation on our dataset.
To address this issue, we unify the QA prompts for all baselines to encourage logical deduction, ensuring that performance differences arise from the memory mechanism rather than prompt engineering.
In addition, we adopted an LLM-as-a-Judge evaluation, using DeepSeek‑V3 as the evaluator to assess the accuracy score of generated responses.
5.4 Main Results
Table 1 present the results on ActMemEval.
Although NaiveRAG achieves the highest retrieval accuracy by recalling extensive surface-level semantic matches,
its inferior QA performance indicates a failure to synthesize these facts with noise to deduce the implicit logical constraints required for QA.
Compared to LightMem,
ActMem achieves substantial improvements.
Specifically, when using DeepSeek-V3, it outperforms LightMem by a significant margin of 14.78% in retrieval accuracy and 12.55% in QA accuracy.
A similar trend is observed with GPT-4o-mini.
In contrast, retrieval-based baselines and OS-style methods exhibit relatively poor performance.
We attribute their failure to the reasoning gap.
These methods rely primarily on surface-level semantic matching, which struggles to retrieve historical events that are logically related but semantically distant from the current query.
In summary, the ability of ActMem to “reason before retrieving” allows it to identify implicit constraints that other methods miss, thereby achieving state-of-the-art performance in complex, action-oriented scenarios.
We also observe an interesting performance gap across different LLM backbones.
GPT‑4o‑mini attains high retrieval accuracy, yet its QA accuracy is markedly lower.
In contrast, DeepSeek‑V3 delivers balanced and consistently superior results on both metrics.
We attribute this discrepancy to a reasoning bottleneck inherent in lightweight LLMs.
The lower QA accuracy suggests that GPT‑4o‑mini struggles to integrate and reason over these memory clues.
This phenomenon also reflects the difficulty of ActMemEval that requires reasoning.
DeepSeek‑V3, with stronger reasoning ability, can synthesize the retrieved context to resolve conflicts, whereas weaker LLMs falter even when given the correct evidence.

5.5 Ablation Study
To verify the contribution of each module in ActMem,
we design three variants by removing key modules:
•
w/o Reasoning: This variant removes the counterfactual reasoning module.
The agent retrieves memory facts directly from the memory KG, without performing commonsense completion or intermediate reasoning.
•
w/o Causal: This variant constructs the memory KG excluding causal edges. The graph relies solely on semantic similarity to connect memory nodes.
•
w/o Semantic: This variant constructs the memory KG excluding semantic edges. The graph consists only of extracted causal chains, making it a sparse causal network.
Figure 5 presents the ablation results.
First, removing the reasoning module (w/o Reasoning) with DeepSeek-V3 causes the largest drop in retrieval accuracy (about 9%),
confirming our core motivation.
In complex scenarios, relevant memories (e.g., “owning a puppy”) may be semantically distant from the query (e.g., “buying plants”).
Without counterfactual reasoning and commonsense completion, the agent fails to uncover such “hidden” evidence.
Second, removing causal edges (w/o Causal) yields the lowest QA Accuracy.
Even when some facts are retrieved, the absence of explicit causal links prevents the agent from forming coherent reasoning chains, leading to generic rather than conflict‑aware decisions.
We observe that when using GPT‑4o‑mini, removing causal edges actually yields better retrieval performance than the Full model.
We attribute this to the weaker reasoning capability of GPT‑4o‑mini, which may introduce errors during world‑knowledge completion and degrade the retrieval quality of the Full model
Third, the w/o Semantic variant also reduces retrieval accuracy, indicating that semantic edges serve as crucial connectors.
They ensure that topic‑related but non‑causal facts remain reachable, preserving the completeness of the retrieved context.
In summary, causal edges provide logical backbone, semantic edges ensure coverage, and the reasoning module guides inference.
Their synergy enables ActMem to achieve good performance.

5.6 Efficiency Comparison
Figure 6 presents a multi-dimensional efficiency comparison versus QA accuracy.
As shown in Subfigure (a),
heavy frameworks like A-mem and MemoryOS incur prohibitive latency, yet fail to yield competitive accuracy.
In contrast, ActMem maintains high efficiency. Although it requires marginally more time than the summarization-based LightMem to construct causal graphs, it remains significantly faster than other graph-based baselines.
The second and third subfigures highlight the cost-effectiveness.
For the number of input tokens, ActMem consumes a moderate amount to extracting fine-grained causal events.
Regarding the number of output tokens,
ActMem achieves an optimal balance between token consumption and performance. We excluded MemoryOS from this comparison due to the difficulty in accessing its internally extracted memories for token quantification.
This indicates that our extraction and reasoning processes are concise and precise, avoiding wasteful hallucination or verbosity.
In summary, ActMem achieves an effective balance between reasoning performance and computational cost.
We can follow LightMem and apply compression techniques to reduce input tokens.
5.7 Analysis of Semantic Similarity Thresholds
We investigate the impact of the semantic similarity threshold on QA accuracy and graph density metrics.
As presented in Table 2,
we observe a clear correlation between graph connectivity and QA accuracy.
A lower threshold (e.g., 0.3) yields the optimal QA accuracy of 76.52%.
This improvement stems from the richer retrieved context: a relaxed threshold preserves more semantic edges, leading to a substantially higher average node degree (20.48) and more retrieved KG facts (5.21). The resulting dense connectivity provides the agent with broader semantically relevant background information, reducing the risk of missing critical clues.
In contrast, a stricter threshold (e.g., 0.7) produces a much sparser graph, with the average degree dropping to 2.34. Such aggressive pruning removes potential semantic associations, resulting in insufficient context retrieval (only 0.29 facts on average) and a corresponding decline in QA accuracy. These results highlight the trade‑off between graph sparsity and information recall.

5.8 Results on Conventional Datasets
To further verify the generalization capability and robustness of our ActMem,
we conduct additional evaluations on the established benchmark, LongMemEval Wu et al. (2025).
To ensure a fair comparison, we align our experimental settings with the SOTA method, LightMem Fang et al. (2025).
We utilize GPT-4o-mini as the backbone LLM for both the memory reasoning process and the answer judgment.
As shown in Figure 7,
ActMem achieves a remarkable QA accuracy of 75.60% on LongMemEval.
It outperforms LightMem by a significant margin of 6.96%.
This result demonstrates the great generalization capability of ActMem.
We attribute this success to our structured causal graph:
by organizing disjointed facts into coherent event clusters,
ActMem effectively reduces the noise and redundancy often present in flat vector retrieval, thereby enhancing the accuracy of answering factual queries.
5.9 Case Study
Table 3 presents a case study from our dataset.
The user asks for a location to buy “Sago Palms.”
Although the query appears simple, it contains a critical implicit constraint in the dialogue history: the user owns a puppy that is “teething” and “chewing on everything.”
As Sago Palms are toxic to dogs,
an intelligent agent should detect this risk and issue a warning.
LightMem fails to retrieve the relevant evidence about the puppy, instead surfacing irrelevant noise such as “high‑end hotels” and “cooking meals.”
It treats the query as a straightforward information‑seeking task and directly recommends where to buy the plants.
In contrast, ActMem successfully bridges this reasoning gap.
Through the counterfactual reasoning, the agent first infers the potential consequence of the user’s intent (i.e., that Sago Palms are toxic).
This knowledge becomes a semantic anchor that guides retrieval of the specific memory that the user’s puppy is chewing on everything.
By integrating this retrieved history with world knowledge,
ActMem identifies the conflict and produces a safety‑aware response, advising against the purchase.
This case highlights our ability to transform memory from passive storage into an active reasoning engine for robust decision‑making.
6 Conclusion and Future Work
In this paper, we identify a fundamental limitation in current LLM agent memory frameworks:
the disconnect between memory retrieval and reasoning.
We argue that high retrieval accuracy alone is insufficient for intelligent decision‑making, as agents must not only recall past information but also understand its implications for the present.
To address this issue, we propose ActMem, a hierarchical framework that transforms passive dialogue history into an active memory KG with both causal and semantic edges between facts.
ActMem enables agents to infer implicit constraints and resolve logical conflicts.
We further introduce a benchmark ActMemEval to evaluate the utility of memory for action.
Extensive experiments on both our dataset and standard benchmarks show that ActMem substantially outperforms baselines.
In future work, we plan to explore lightweight LLMs to improve the efficiency of KG construction without compromising reasoning quality.
Second, we plan to extend ActMem to multimodal scenarios.
Finally, we will explore fine-tuning strategies to enhance the causal reasoning capabilities.
