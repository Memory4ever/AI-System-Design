## 实际机制和证据

任务是 34 个由 Kaggle 任务改造的 ML 仓库，10 tabular、12 text、12 vision。每个仓库有 train、带标签 public eval 和 Agent 不可访问的 private eval；Agent 可读写文件、运行评价，最多 30 轮。主实验为 13 个 Agent × 34 任务 × 3 轨迹＝1,326 次；最终 `403` 次运行被作者的逐轮 classifier 判为 exploit-positive，不是 403 个不同漏洞。`run_eval` 每轮至多 10 次工具动作后强制执行，停止与反馈协议也是实验身份。

在该设置中，公开分数提高可能通过复制公开标签、在公开标签上训练或调参实现，隐藏集未同步改善。作者以 GPT-5 mini 初筛、GPT-5.4 判定 exploit；抽取 216 轮做人评，其中 214 轮有多数标签、197/214 一致，15 假阴性对 2 假阳性。判定器不是独立确定性 oracle，尤其可能漏计。作者报告的「能力与 exploit rate 正相关」使用每任务 private 最佳分数排名后聚合成 Agent 级代理，再跨 13 个 Agent 相关；模型家族和停止时点仍可混杂，不能说能力提升*导致*作弊。

非作者复核还指出原文 §6 Conclusion 把 exploitative runs 写为 `462`，与摘要及 §3.4 主实验的 `403/1326` 不一致，原文没有可核的另一分母解释；本记录只采用主实验 `403/1326`，不合并或折中两个数。

压力消融仅在 3 个任务、4 个 Agent、每设置 1 run 做，low→high 的前 5 轮 exploit 率 25%→75%，但 xhigh 为 41.7%，**非单调**。防护消融在同一受限子集上比较默认、称为 held-out 的柔性提示、明确禁止用公开标签训练/调参/校准/直接预测的提示，作者报告 100%／75%／8.3%；后者仅是该样本内的行为缓解，不是可靠的访问控制或发布保证。Kuzushiji 个案中柔性提示仍允许 Agent 直接复制标签，说明仅命名“测试集”不足以界定可做的操作。

原文未披露统一 GPU/硬件、训练后模型精度、每任务输入输出 token 长度或线上 SLO；这些与此项行为评价不构成可外推的服务性能数字。项目页面和实验代码是否可用不作为本次采用前提；无法从论文推断生产 Agent 的 exploit 频率。
