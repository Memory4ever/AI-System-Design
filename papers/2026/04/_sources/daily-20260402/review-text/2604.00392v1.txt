Abstract

Modern LLM agents increasingly create their own tools at runtime—from Python functions to API clients—yet existing benchmarks evaluate them almost exclusively by downstream task completion. This is analogous to judging a software engineer only by whether their code runs, ignoring redundancy, regression, and safety. We introduce EvolveTool-Bench, a diagnostic benchmark for LLM-generated tool libraries in software engineering workflows. Across three domains requiring actual tool execution (proprietary data formats, API orchestration, and numerical computation), we define library-level software quality metrics—reuse, redundancy, composition success, regression stability, and safety—alongside a per-tool Tool Quality Score measuring correctness, robustness, generality, and code quality. In the first head-to-head comparison of code-level and strategy-level tool evolution (ARISE vs. EvoSkill vs. one-shot baselines, 99 tasks, two models), we show that systems with similar task completion (63–68%) differ by up to 18% in library health, revealing software quality risks invisible to task-only evaluation. Our results highlight that evaluation and governance of LLM-generated tools require treating the evolving tool library as a first-class software artifact, not a black box.

1 Introduction

LLM agents increasingly generate executable software artifacts at runtime—Python functions, API clients, data parsers—and add them to persistent tool libraries. VOYAGER [10] synthesizes code skills in Minecraft, CREATOR [8] uses tool creation as a reasoning strategy, LLMs as Tool Makers [5] separates tool-making from tool-using, and EvoSkill [1] evolves structured skill folders via failure analysis. ARISE (Adaptive Runtime Improvement through Self-Evolution) [6] operates as framework-agnostic middleware: it observes task failures, detects capability gaps via LLM analysis, synthesizes executable Python tools, validates them through sandboxed execution and adversarial testing, and promotes passing tools to the agent’s active library. ARISE supports iterative refinement, A/B testing of tool variants, version-controlled rollback, and distributed deployment.

From a software engineering perspective, these systems are automated code generators whose output accumulates into a growing codebase. Yet they are evaluated exclusively on task success—analogous to judging a software engineer solely by whether their code runs, ignoring maintainability, duplication, test coverage, regression, and technical debt. In practice, tool libraries can pass downstream benchmarks while accumulating redundant functions, failing on edge cases, breaking previously working capabilities, and never reusing existing code.

We present EvolveTool-Bench, a diagnostic benchmark that treats LLM-generated tool libraries as first-class software artifacts subject to quality evaluation. Our contributions:

1.

Quality of LLM-generated software artifacts. We define a Tool Quality Score (TQS) measuring correctness, robustness, generality, and code quality of each synthesized tool, plus six library-level metrics: reuse rate, redundancy, composition success, regression stability, creation efficiency, and safety.

2.

Verification and validation of LLM-generated code. Our evaluation harness runs hidden unit tests and adversarial inputs in sandboxed subprocesses, uses LLM-as-judge rewards to determine when evolution should trigger, and includes explicit regression tasks that measure whether adding new tools breaks previously working behavior.

3.

Controlled diagnostic sessions. Structured sequences of 11 tasks with known dependency relationships (seed, gap, variant, compose, regress, adversarial) enable measurement of whether agents recognize code reuse opportunities, compose their own functions, and maintain library stability as the codebase grows.

2 Related Work

Quality of LLM-Generated Code.

Tool-Genesis [11] evaluates one-shot tool creation with surface compliance, schema-F1, and unit test pass rates—all per-artifact metrics with no library-level evaluation. SkillsBench [3] evaluates whether curated skills improve task success but uses static skill sets, not evolved ones. Neither measures redundancy, regression, or reuse across a growing codebase.

Self-Evolving Agent Frameworks.

VOYAGER [10] demonstrates lifelong skill acquisition in Minecraft, evaluated by exploration metrics. EvoSkill [1] evolves textual skill folders through failure-driven feedback, evaluated by downstream accuracy. ARISE [6] synthesizes executable Python functions with auto-generated test suites, validates them in isolated sandboxes, runs adversarial testing, and supports incremental patching and A/B testing. None evaluate the software quality of the resulting tool library.

Software Engineering Benchmarks for Agents.

ToolBench [9], AgentBench [7], and ToolComp [2] evaluate agents using pre-defined tool sets. Vending-Bench [4] tests long-horizon coherence with fixed tools. None evaluate agents that generate their own tools, and none apply software quality metrics to the generated artifacts.

Gap.

No existing benchmark measures redundancy, reuse, regression, composition, or code quality of self-evolved tool libraries as software artifacts. Our work fills this gap.

3 Benchmark Design

3.1 Task Session Structure

Each session contains 11 tasks in six categories with known dependency relationships (Table 1). This structure mirrors software engineering workflows: seed tasks test existing code, gap tasks require new implementation, variant tasks test code reuse, compose tasks test function composition, regress tasks detect regressions, and adversarial tasks probe edge cases.

3.2 Domains

Domain A: Data Transformation (5 sessions).

Proprietary binary formats (ARISE Binary Records, RLE matrices, VDL schema language, QLOG binary logs, TPACK serialization) that LLMs cannot solve from training data.

Domain B: API Orchestration (1 session).

Mock HTTP server with HMAC-timestamp authentication and XOR-encrypted cursor pagination. Tasks inherently require code execution.

Domain C: Numerical Computation (3 sessions).

Custom formats for curve fitting (ARCFIT), signal processing (ARCSIG), and constrained optimization (ARCOPT).

Systems.

(1) No-Evolution: Seed tools only. (2) ARISE: Iterative evolution with sandbox validation and LLM-as-judge reward. (3) EvoSkill: Strategy-level evolution (text prompts, not code). (4) One-Shot: Code generation without testing.

Models.

Claude Sonnet 4 and Claude Haiku 4.5 via Amazon Bedrock.

9 sessions 11 tasks = 99 tasks per configuration. Six configurations: 594 total executions.

5.1 Key Findings

Finding 1: Task completion hides quality differences.

All configurations achieve 63–68% TC, but ETS ranges 0.516–0.612. ARISE has lowest TC but highest ETS. TC-only benchmarks would rank ARISE last.

Finding 2: Code evolution outperforms strategy evolution.

ARISE (ETS=0.603) outperforms EvoSkill (ETS=0.520). EvoSkill creates zero executable tools and identical library health to no-evolution.

Finding 3: Untested code is worse than no code.

One-Shot library health (38.3%) is below no-evolution (41.4%). Untested tools are a liability.

Finding 4: Reward design is the bottleneck.

Heuristic rewards produce zero tools. Only LLM-as-judge rewards trigger evolution.

Finding 5: Tool quality is the frontier.

TQS averages 0.34–0.35. Correctness is weakest—hidden tests catch defects self-generated tests miss.

Finding 6: Cheaper models match quality.

ARISE+Haiku (ETS=0.612) slightly beats ARISE+Sonnet (0.603) with fewer tools.

6 Discussion

Tools as Software Artifacts.

LLM-generated tools should be evaluated like any software artifact. The 18% quality gap invisible to TC validates this.

Implications.

Untested code is a liability (Finding 3) and self-generated tests miss defects (Finding 5). Any system accumulating generated code needs independent validation.

Honest Assessment of ARISE.

Best libraries (22 tools, 70.4% reuse) but: evolution overhead lowers TC; TQS averages 0.34; complex formats exceed synthesis capability.

Limitations.

(1) EvoSkill baseline is approximate. (2) Two models, one provider. (3) Automated checks only. (4) No statistical significance.

7 Conclusion

EvolveTool-Bench is the first benchmark evaluating LLM-generated tool libraries as software artifacts. Across 99 tasks, TC fails to differentiate systems with different code quality. Code-level evolution with validation (ARISE) builds libraries with 70.4% reuse and 51.7% health. Untested generation introduces technical debt. Reward design is the critical bottleneck. We release all code and data.11
