## 原文算法与可核反例

Algorithm2 第4–8步从**原始私有数据**直接提取属性矩阵 `X`，逐列随机置换得到 `X̃`；第9步才让 DP-SGD 训练出的模型给 `X̃` 预测标签，并在第10步把 `X̃` 连同预测标签发布。§3.3 的论证说 DP 模型受 `(ε,δ)` 保护、列置换打破记录/属性相关，因此整个合成数据也满足同一 `(ε,δ)`；但公开的 `X̃` 并非仅对 DP 模型输出所作的后处理。

最小替换邻接反例：单条私有记录的属性 `x=0` 与 `x=1` 构成相邻数据集，列内置换在两种输入中都是恒等，输出原样披露 `x`。取事件 `A={发布属性含0}`，则 `P[M(D)∈A]=1`、`P[M(D')∈A]=0`，对任意有限 `ε` 与 `δ<1` 都违反 `1≤e^ε·0+δ`。对多条记录，逐列置换仍保各列原始多重集合，唯一取值变动也可构造同样事件。若采用加/删邻接，公开的记录数/列多重集合也需另行保护；不能用“置换打断跨列关联”替代 DP 证明。DP 分类器可保护其参数/标签查询，但不保护从原始 `X` 独立放出的另一数据通道。

这仅反驳**印刷 Algorithm2/§3.3 的完整 `(ε,δ)` 发布保证**，未读取或验证可选代码，也不宣称作者真实部署已泄漏；四个 Adult/Br2000/LPD/Smoking 表格任务的局部 utility/五次运行均值可以作为受限观察保留，但不能挽救发布保证。需要作者给出对 `X` 的独立 DP 机制、公开属性的明确威胁模型，或有效的联合隐私预算与相应实现/算法修订才能重开该保证；无需复现所有 benchmark 或遍历附件。
