Abstract

Human memory adapts through selective forgetting: experiences become less accessible over time but can be reactivated by reinforcement or contextual cues. In contrast, memory-augmented LLM agents rely on “always-on” retrieval and “flat” memory storage, causing high interference and latency as histories grow. We introduce Oblivion, a memory control framework that casts forgetting as decay-driven reductions in accessibility—not explicit deletion. Oblivion decouples memory control into read and write paths. The read path decides when to consult memory, based on agent uncertainty and memory buffer sufficiency, avoiding redundant always-on access. The write path decides what to strengthen, by reinforcing memories contributing to forming the response. Together, this enables hierarchical memory organization that maintains persistent high-level strategies while dynamically loading details as needed. We evaluate on both static and dynamic long-horizon interaction benchmarks. Results show that Oblivion dynamically adapts memory access and reinforcement, balancing learning and forgetting under shifting contexts—highlighting that memory control is essential for effective LLM-agentic reasoning.

1 Introduction

Forgetting is not a failure of memory, but a functional necessity for efficient cognition and adaptive behavior  (Nørby, 2015; Wimber et al., 2015; Fawcett and Hulbert, 2020). In cognitive psychology, forgetting is characterized as a loss of accessibility rather than permanent erasure: as time passes, memory traces decay unless reinforced by repetition or contextual cues (Berens et al., 2020). Ebbinghaus’ foundational work established the “forgetting curve”: repeated retrievals and selective retentions popularized the observation that recall probability decays gradually over time  (Ebbinghaus, 1885; Ebbinghaus, 1913). Viewed as a control mechanism, forgetting acts as a dynamic filter: the human brain prioritizes its limited “working memory” for high-utility information while keeping less relevant traces latent but reactivatable.

Figure 1: Oblivion facilitates memory-augmented agents by decay-driven activation over hierarchical memory traces. The Executor orchestrates the read path for uncertainty-gated retrieval (); and the write path for feedback-driven updates (), enabling dynamic control over memory activation.

To extend reasoning beyond context limits, memory-augmented LLM agents maintain external memory storage that can be accessed and updated across interactions (Zhang et al., 2025; Jia et al., 2026). Yet as memory stores grow, agents face a severe “needle-in-a-haystack” problem: relevant evidence is obscured by accumulating stale or tangential entries, increasing prompt pollution and reasoning interference (Liu et al., 2024; Xiong et al., 2025). Existing methods exhibit three critical limitations: (1) uncertainty-decoupled retrieval, where agents perform “always-on” retrieval, fetching information at every conversation turn regardless of necessity (Xiong et al., 2025; Zhang et al., 2026); (2) “flat” memory, where uniform storage fails to distinguish persistent high-level strategies from transient low-level details and often resorts to hard deletion to manage context limits (Chhikara et al., 2025; Fang et al., 2025); and (3) static evaluation bias,
where existing memory agent benchmarks emphasize retrieval accuracy in isolation, underrepresenting long-horizon interactions with compounding memory decisions and shifting task demands (Wu et al., 2025).

We bridge these gaps with Oblivion, a self-adaptive memory control framework that shifts the paradigm from memory as a database to memory as a control problem under long-horizon interaction. The key insight is read/write decoupling (McClelland et al., 1995; Craik et al., 1996) (Figure 1). The read path decides when to consult memory using uncertainty signals and available context, avoiding redundant always-on access. The write path decides what to strengthen by reinforcing only response-contributing memories. As a result, unused memory traces fade without explicit deletion yet remain reactivable when conditions change.

Oblivion features memory control through a hierarchical memory representation managed by a central orchestrator (Executor), controlling a self-adaptive read/write loop. On the read path, a Decayer gates retrieval by uncertainty and filters accessible memory traces with an Ebbinghaus-inspired retention score, and an Activator triggers targeted retrieval (i.e., when uncertainty is high) via a query-expansion graph. On the write path, a Recognizer identifies which memories contributed to the response, and a Memory Manager selectively reinforces those memories. Together, these components implement decay-driven activation for long-horizon agentic memory control.

2 Oblivion Overview

Oblivion addresses long-horizon agentic interaction through read/write-decoupled memory control: deciding when to consult memory and which memory traces to activate (read path), and what to strengthen by reinforcing only response-contributing memories (write path). As shown in Figure 1,
the framework comprises a hierarchical memory representation, a read path (Decayer and Activator), and a write path (Recognizer and Memory Manager), orchestrated by a central Executor. In the following, we introduce the memory representation (§ 2.1), the read path for uncertainty-gated retrieval (§ 2.2), the write path for feedback-driven updates (§ 2.3), and the self-adaptive memory control loop (§ 2.4).

2.1 Hierarchical Memory Representation

Inspired by the working memory construct in cognitive psychology (Baddeley, 2000) and its computational realization for language agents (Sumers et al., 2024), Oblivion separates memory into a transient Working Memory (WM) and a Persistent Store (). Dynamic Procedural Memory ().

Serving as the entry point, serves as an adaptive meta-index over memory. It is initialized with a configurable domain-specific taxonomy that can range from a handful of broad categories to a dozen task-oriented clusters and can be expanded emergently through interactions.

(iii) Procedural Memory (): meta-instructions learned from interaction feedback that capture how to handle queries within the cluster’s domain—not just what it contains—transforming from a passive index into adaptive meta-cognitive strategies.

2.2 Read Path: Uncertainty-Gated Retrieval

The read path decides whether the current buffer suffices for the query at turn ; otherwise, it triggers targeted retrieval to load extra evidence from . The Decayer performs two checks—uncertainty estimation (Whether to retrieve?) and retention scoring (Which memories remain accessible?)—that jointly gate the Activator.

Decayer.

For each cluster in , the Decayer estimates an uncertainty score (higher means weaker support for ) using two complementary signals: (i) LLM-as-a-judge (Zheng et al., 2023): an LLM, conditioned on the cluster summary, procedural memory, and any cached / items, assesses whether provides sufficient evidence for .
(ii) Embedding-based: the mean cosine similarity between the query embedding and embeddings of cached buffer items is computed; low similarity signals that the buffer content is likely irrelevant.
Activation is always triggered when contains no / items. Otherwise, the gating threshold adapts across rounds: in the first round, either signal alone suffices (OR), favoring recall over precision; in subsequent rounds, both must agree (AND), preventing redundant retrieval once the buffer is already populated.

Activator.

When triggered, the Activator reduces uncertainty by retrieving / entries from and updating under fixed cache budgets. Instead of a single vector search, it decomposes into a set of focused sub-queries organized as a directed acyclic graph (DAG):  (Khot et al., 2023; Zhou et al., 2023). Each node specifies (i) a sub-query string, and (ii) a memory type ( or ); edges encode dependencies (e.g., refinement), supporting multi-step information needs beyond single-shot retrieval. Each sub-query performs global similarity search over —not hard-filtered by cluster—preserving cross-cluster evidence discovery. The main query additionally follows – links to retrieve associated memories. Retrieved candidates are curated into by retaining useful cached items, adding high-coverage new ones, and evicting stale or low-retention entries to stay within budget. The updated returns to the Decayer, and the Executor repeats the DecayerActivator loop for fixed iterations, stopping once uncertainty falls.

2.3 Write Path: Feedback-Driven Updates

The write path enables continual learning (De Lange et al., 2022) by extracting memories from each interaction and selectively reinforcing those contributing to the response.

Recognizer.

At the end of each turn, the Recognizer: (i) extracts new factual memories and accumulates episodic entries toward episodes; (ii) constructs or updates cluster topics—including procedural memory—based on observed interaction patterns; and (iii) performs credit assignment by identifying which specific memory entries in were used to generate the response. This conservative policy ties reinforcement strictly to usage, avoiding indiscriminate re-scoring of all retrieved memories.

Memory Manager.

The Memory Manager persists new entries to and updates the utility metadata of used memories. The utility score for accessed clusters is reinforced, while unaccessed clusters naturally decay via the increment of in § 2.2. This implements decay-driven forgetting: memories that are not reinforced gradually become inaccessible—not through deletion, but through declining retention and lower retrieval priority—yet remain recoverable when future conditions change.

2.4 Executor: Self-Adaptive Control Loop

Serving as the orchestrator of Oblivion, the Executor maintains the working memory state and orchestrates the read/write memory control cycle. At each turn , it: (i) updates WM with the new query ; (ii) iterates the DecayerActivator loop until the buffer is sufficient or a maximum iteration limit is reached; (iii) generate the response from the curated working memory state, and (iv) invokes the Recognizer to distill new memory candidates from the interaction and Memory Manager persists these updates to . This self-adaptive control loop allows the agent to learn what to remember over time – the working memory (WM) stays bounded to minimize interference, while decay/activation (read) and reinforcement (write) progressively increase the accessibility of high-utility memories (McClelland et al., 1995; Craik et al., 1996).

3 Experimental Setup

3.1 Memory Benchmarks

We evaluate Oblivion on challenging benchmarks: LongMemEval (Wu et al., 2025) for static retrieval-heavy QA over long chats, and GoodAILTM (Castillo-Bolado et al., 2024) for dynamic long-horizon interactions. Together, this mitigates a common limitation in prior evaluations, focusing on either static long-context QA or a single interactive memory setting, but rarely both.

LongMemEval formulates memory as QA over a multi-session conversational haystack. Each instance contains (i) a question, (ii) a reference answer, and (iii) a timestamped set of prior chat sessions in which evidence may exist among many irrelevant sessions. The benchmark comprises 500 human-curated questions and synthetic sessions across 6 question types.33
3

SS-A (Single Session (SS)-Assistant), SS-U (SS-User), SS-P (SS-Preference), MR (Multi-Session Reasoning), TU (Temporal Reasoning), KU (Knowledge Update). We follow two standard context settings: Oracle, where the model receives only the evidence sessions (upper bound with perfect retrieval), and S, where the model must identify relevant evidence within the full noisy history.
GoodAILTM evaluates long-term memory in an interactive setting, measuring how well an agent can retain, revise, and update information online over very long, ongoing conversations—not just answer isolated questions. The benchmark induces memory pressure beyond the effective context window. The benchmark includes 11 scenarios (3 instances each; 33 tests total) spanning 7 memory skills.
We report results under Isolated (no tasks interleaving) and (2K, 32K, 120K) (tasks interleaving, with given memory span-limited constraints).

3.2 Models and Baselines

We evaluate multiple LLM backbones spanning different scales (Phi-4-mini-instruct-4B, Qwen3-30B-A3B-Instruct, GPT-4o-mini, GPT-4.1-mini). Unless otherwise stated, we keep decoding settings and retrieved-context budget (e.g., number of iterations) fixed across all methods to isolate the effect of memory architectures. To enable a consistent comparison across benchmarks, we compare two baselines—direct and memory—alongside Oblivion. For direct, this represents a minimal memory interface: the model answers in a single pass from the available context, without iterative retrieval and adaptive memory control. For LongMemEval, we follow the optimized retrieval pipeline LME-RFT (round-level storage, fact-augmented keys, time-aware query expansion, and flat retrieval) with direct reading (no Chain-of-Note; CoN) (Wu et al., 2025).44

4.1 Static Multi-Session QA

As shown in Table 1, Oblivion generally exhibits stronger performance than LME-RFT (direct) and EverMemOS (memory) on static multi-session QA. The direct LME-RFT baseline, utilizing flat retrieval, achieves with GPT-4.1-mini an average accuracy of 89.00% (S). Conversely, the EverMemOS baseline shows inconsistent results; while reaching 81.27% on GPT-4.1-mini, it drops to 65.47% with GPT-4o-mini. This performance gap is most pronounced in MS and TR tasks, where EverMemOS scores 60.40% and 53.38% for GPT-4o-mini, suggesting its memory compression may discard temporal details during complex retrievals.
In comparison, Oblivion with hierarchical memory control and read/write decoupled loop for GPT-4.1-mini attains average accuracy gains from 91.80% to 94.40% (Oracle) and from 89.00% to 90.60% (S). Oblivion particularly addresses baseline weaknesses in cross-session MS tasks with GPT-4o-mini: 69.92% (direct) vs. 79.70% (ours). These findings are consistent with the hypothesis that maintaining episodes in with factual semantic entries helps mitigate “needle-in-a-haystack” (Liu et al., 2024).

4.2 Dynamic Interactive Conversation

For dynamic GoodAILTM benchmark (Table 2), Oblivion outperforms both direct and memory baselines across the board. The direct FullCTX baseline performs adequately in Isolated tasks but degrades significantly in the 32K setting, reflecting “lost-in-the-middle” effects  (Liu et al., 2024). While BeyondPrompts (memory) improves 32K stability, it performs marginally against FullCTX in 2K spans, suggesting static retrieval buffers may interfere with the immediate context. Oblivion demonstrates superior stability across all spans; for GPT-4.1-mini, solved scenarios rise from 6.29 to 8.41 (2K) and 6.05 to 6.79 (32K) compared to FullCTX. These gains suggest that decay-driven activation effectively prioritizes high-utility traces while keeping less relevant information latent. Notably, relative improvements are most pronounced in non-isolated settings (e.g., GPT-4.1-mini rising by 33.70% in 2K), supporting the design of memory as a dynamic control problem. The relatively improved gains at 32K and 120K settings for smaller instruct models demonstrates smaller LLMs face challenges while directly following large instructions.

As shown in Table 3, integrating all hierarchical memory layers (//) provides the strongest performance across both static and dynamic benchmarks. Combining distilled facts with conversational episodes (M4) significantly improves retrieval over single-layer (M1/M2) (86.40% vs. 89.60%) on LongMemEval (S). As shown in Table 4, for large scale operational readiness, we observe that Oblivion is highly competitive cost reductions at large 32K and 120K settings. For example, 120K and 32K settings have reduced average token cost by 73.00% and 67% respectively compared to FullCTX (FC). Oblivion at scale offers highly favorable tradeoff; In 120K setting it introduces modest latency overhead compared to FullCTX baseline (1.34), yet operates significantly faster than memory baselines like BeyondPrompts (BP, 1.4 latency). Hence, our lightweight memory control calls filter relevant traces and prevent brute-force context bottlenecks, providing a viable path for scalable operations.

6 Related Work

Memory-augmented agents extend retrieval-augmented generation (Lewis et al., 2020) via virtual context management (Packer et al., 2023), time-based decay (Zhong et al., 2024), or reflective reinforcement learning (Tan et al., 2025). While advancing persistence, these designs typically rely on always-on retrieval (i.e., without uncertainty-gated access based on real-time query). Cognitive architectures (Sumers et al., 2024) and hierarchical approaches using subgoals (Hu et al., 2025) or human-like recall (Wang et al., 2025) improve memory organization, yet often lack a mechanism for gradual accessibility decay and separate control for read/write operations. Parallel learning-based methods for architectural memory (Wang et al., 2023), read-write finetuning (Modarressi et al., 2025), or end-to-end processing (Zhou et al., 2026; Yu et al., 2026) remain orthogonal to Oblivion, as they require specialized training or model modifications rather than providing a model-agnostic, inference-time control layer.

Among concurrent systems, FadeMem (Wei et al., 2026) is most related due to its exponential decay functions. Oblivion distinguishes itself via (i) read/write decoupling to separate retrieval gating from reinforcement, (ii) uncertainty-gated activation to trigger retrieval only when context is insufficient, and (iii) DAG-based query expansion for multi-step evidence discovery, contrasting with single-shot retrieval in A-Mem (Xu et al., 2025), Zep (Rasmussen et al., 2025), or EverMemOS (Hu et al., 2026).

7 Conclusions

We introduce Oblivion, a self-adaptive framework that reframes long-horizon memory as a control problem, where its design enables uncertainty-gated read paths and usage-driven write paths over a hierarchical memory. By prioritizing high-utility information, it consistently outperforms in long-horizon settings for static and interactive benchmarks. We hope this work encourages future deployment of cognitively grounded agents in the real world and further investigation
for long-horizon problems with memory as a control formulation.

Limitations

Though Oblivion has shown consistent improvements across both static and dynamic long-horizon memory benchmarks, several limitations remain.
First, the framework uses the same LLM architecture for memory extraction, uncertainty estimation, and response generation; smaller LLM with weaker capability might produce lower-quality output generations, resultantly which can degrade retrieval-dependent tasks. Decoupling extraction and generation LLMs may alleviate this coupling issue.
Second, our model selection spans two API-based (GPT-4o-mini, GPT-4.1-mini) and two open-weight (Phi-4-mini-Instruct-4B, Qwen3-30B-A3B-Instruct) LLMs; evaluation on a broader range of model families and scales would strengthen generalizability claims.
Third, the decay temperature requires task-specific tuning—our analysis shows distinct retention-reinforcement trade-offs across values, with suboptimal choices leading to either excessive forgetting or buffer saturation.
Finally, due to cost constraints, we rely on two commercially available and licensed benchmarks covering a plethora of tasks across static and dynamic paradigms; evaluation on multilingual, multimodal, domain-specific, or open-ended agentic settings remains unexplored (Bei et al., 2026; Rose et al., 2025).
Despite these limitations, Oblivion demonstrates that formulating memory as a control problem—with read/write decoupling and decay-driven activation consistently improves long-horizon agent performance across diverse tasks.
We hope that this work encourages further investigation into cognitively grounded memory control for practical agentic systems.
