### `2604.25080v1` CacheFlow：恢复是依赖图与批次资源分配（待非作者）

已读[官方 exact-v1 HTML](https://arxiv.org/html/2604.25080v1) §3.1–3.3、§4.1–4.3，并对照[Ch45](../../../../../books/part-05-inference-system/45-why-kv-cache-speeds-up.md) 的 Offload/重算—传输条件、[Ch55](../../../../../books/part-05-inference-system/55-pd-disaggregation.md) 的 storage→Prefill→Decode / storage→Decode 恢复路径及 layer readiness、[Ch56](../../../../../books/part-05-inference-system/56-inference-scheduling.md) 的调度 authority。现文虽分别持有 KV identity、路径和调度，却尚未把**一次旧 prefix restore**拆为 token、layer、stage 的依赖图，和多请求争用同一 compute/I/O channel 的优先级联动。作者侧拟 `Design Delta 3 + System Reach 3 + Durability 2 = 8/9`、深入，拟 Ch45 为唯一 owner 的窄 Books 增量；Ch55/56 已有路径/authority，不重复写同一机制。尚未作非作者 source→actual-owner 或写锁，**非真实 Integrate**。

机制：先由 cache owner 验证旧 prefix identity 和可用存储；同一 request 的 token 维从前端重算、尾端装载 KV，长序列优先省掉后段较贵的重算；短序列固定开销较重时改为层维从低层重算、高层反向装载，离线 profile crossover `L_Δ` 后选择。pipeline stages 若保存各 stage 的 boundary hidden activations，才可分别在各 GPU 上恢复本地 shard；这些 boundary states 是额外存储与版本身份，不是可凭空并行。批次级 two-pointer scheduler 按剩余重算成本调 I/O 优先级，executor/cache owner 仍分别拥有算子依赖、loaded/recomputed KV 的完成与合法消费；长度只是启发式代理，不能从长序列优先直接推出全局最优或公平性。

评价与反证：§4 实作自述基于 vLLM+LMCache v0.3.1，三模型 Qwen3-8B、Llama-3.1-8B、Qwen3-30B-A3B，LMSYS-Chat/WildChat/SWE-Bench 工作负载，L40S/A100/H100，默认 10Gbps、另 40/80Gbps；与 vLLM 重算、SGLang/HiCache、LMCache 纯装载、Cake token-hybrid 比，TTFT CDF 作者报告约 1.1–1.7× 改善，§4.3 3D-off 消融 0.21→0.29s。它确实测了 TTFT 而非纯 kernel microbench，但没有证明所有训练/推理模型、同平台同缓存策略与所有链路的生产 P99/goodput 保证。§3.2 的 `T*=T_comp*T_io/(T_comp+T_io)` 在均匀层成本、完美重叠时成立，数值是通常定义的**调和平均数的一半**；`1/S` 还需均匀 stage、可用 boundary state、无不平衡与共享链路争用，不能照印刷“optimal across all regimes / ideal linear speedup”写成现实定理。§3.3 Algorithm 1 的 I/O 分配是 longest remaining-work heuristic，未给全局最优证明；小 batch、快速本地缓存、boundary 维护或 shared I/O contention 时，纯重算/纯载入或既有单路径依然合理。

拟 Ch45 最窄正文（仅 proposal）：

> HBM 缺位时，旧策略会在“完整重算”与“完整装载”中选一个，或只沿 token 轴切一段重算、另一段搬运。长 prefix 的后部重算更贵，短 prefix 则更易被固定启动成本主导；因此一次 KV 恢复可以显式表示为 token、layer、pipeline-stage 三轴的依赖图：从前向后重算部分 token 与从后向前装载其余 token；或从低层向上计算、从高层向下装载，在合法边界汇合。多 GPU stage 只有保留与模型/位置/缓存版本一致的 boundary activations，才能各自恢复本地 KV shard，而不等待前一 stage 实时重做全部状态。两指针只是执行计划，cache/executor 仍须确认每个 chunk/layer 的重算或装载完成、身份一致后，才能让下游生成读取。
>
> 单请求的最短恢复时间并非整批最短延迟：多个长短请求争用同一 I/O 与 compute 时，调度器还要给装载那些能避免更多后续重算的 chunks 分配带宽，并随完成前沿更新优先级。它用额外 boundary state、offline crossover profile、chunk metadata、跨 stage 协调与并发公平性维护换更低的恢复关键路径；带宽、stage 不平衡、短 prefix 或缓存命中变化会改写最优切点。作者在 vLLM/LMCache、三模型和所列 GPU/带宽/traces 上报告受限 TTFT 与消融收益，理想式的调和分割和 `1/S` 不是真实服务的线性加速保证；难以验证恢复身份或质量/成本不闭合时，应回退完整重算、装载或 Ch55 的既有单路径。
