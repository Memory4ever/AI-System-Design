具体贡献不是「Agent 可自行改 prompt」：作者让 prompt、tools、middleware、skills、memory、subagent config 都成为带版本的可编辑 harness；每一改动记录失败轨迹、根因、预期修复任务与回归风险，下一轮按任务差值对照 manifest 并回退。Runs、verifier、model config 只读是本文实验中的受限控制面，**不是**完整生产授权/供应链 guardrail。分层原始/清洗轨迹、每任务分析、全局 overview 允许追责，但分析摘要不代替原始轨迹。Algorithm 1 重复使用同一个 89-task benchmark `D` 调整和选择 `H_best`，故其主结果不能称独立 holdout。Ch84 已具体持有 failure batch→proposal、独立 replay、security/health、controller commit/rollback、版本化 model–harness artifact 与 cross-product regression；Ch66 已持有 harness/environment/scorer 身份及 task-level regression evidence。预测 manifest→观察回归的量化在现章未逐数写出，是现有合同的有力受限**反例**，并非尚未被承载的另一发布权限或状态所有权。

结果/反证分账：十轮单 campaign、每任务两次 rollout、约 32h、GPT-5.4 high，Terminal-Bench 2 的 shared seed `69.7%`→AHE `77.0%`，但 Hard 上 AHE `53.3%` 低于所列 Codex `56.7%`；human-designed harness 并非 matched editable-component 对照。Table 3 中 memory-only aggregate `75.3%`、Hard `63.3%`，prompt-only aggregate `67.4%` 低于 seed，完整系统 Hard `53.3%` 低于 memory-only；三项单组件收益之和不能相加推出完整系统收益。SWE-bench Verified 500 tasks 迁移 aggregate `75.2%`→`75.6%`，token 均值 `526k`→`461k`，但 scikit-learn `93.8%`→`87.5%`、pydata `77.3%`→`72.7%`、astropy `54.5%`→`50.0%`；不能称跨仓库普遍提高。§4.4.2 的跨轮**修复预测** precision/recall `33.7%/51.4%`，**回归预测**仅 `11.8%/11.1%`，是「提出修复理由」不等于「知道将破坏什么」的直接受限反证。§Limitations 自认 benchmark-specific tuning、长程清理/防滥用未完善，未给生产可靠性或完整成本保证。
