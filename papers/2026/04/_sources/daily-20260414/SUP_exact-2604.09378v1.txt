Abstract
Agent ecosystems increasingly rely on installable skills to extend functionality, and some skills bundle learned model artifacts as part of their execution logic. This creates a supply-chain risk that is not captured by prompt injection or ordinary plugin misuse: a third-party skill may appear benign while concealing malicious behavior inside its bundled model. We present BadSkill, a backdoor attack formulation that targets this model-in-skill threat surface. In BadSkill, an adversary publishes a seemingly benign skill whose embedded model is backdoor-fine-tuned to activate a hidden payload only when routine skill parameters satisfy attacker-chosen semantic trigger combinations.
To realize this attack, we train the embedded classifier with a composite objective that combines classification loss, margin-based separation, and poison-focused optimization, and evaluate it in an OpenClaw-inspired simulation environment that preserves third-party skill installation and execution while enabling controlled multi-model study. Our benchmark spans 13 skills, including 8 triggered tasks and 5 non-trigger control skills, with a combined main evaluation set of 571 negative-class queries and 396 trigger-aligned queries.
Across eight architectures (494M–7.1B parameters) from five model families, BadSkill achieves up to 99.5% average attack success rate (ASR) across the eight triggered skills while maintaining strong benign-side accuracy on negative-class queries. In poison-rate sweeps on the standard test split, a 3% poison rate already yields 91.7% ASR. The attack remains effective across the evaluated model scales and under five text perturbation types. These findings identify model-bearing skills as a distinct model supply-chain risk in agent ecosystems and motivate stronger provenance verification and behavioral vetting for third-party skill artifacts.
1 Introduction
Large language model (LLM) agents are increasingly deployed as extensible systems that orchestrate external tools, APIs, and third-party components to automate complex tasks [28, 27, 33, 22, 18]. In many emerging agent ecosystems, this extensibility is realized through skills: modular packages that encapsulate executable logic, configuration, and, in some cases, learned model artifacts. While such open skill ecosystems accelerate capability growth and developer adoption, they also introduce a largely underexamined supply-chain risk. In particular, third-party skills may be installed with limited provenance verification and little behavioral scrutiny of bundled models, allowing malicious behavior to be carried by the skill artifact itself.
This threat boundary differs fundamentally from prompt injection [23, 15], tool misuse, and other prompt- or context-mediated agent attacks [34, 8]. Even if external inputs are sanitized, a compromised model artifact embedded inside a skill may still implement trigger-conditioned behavior within the skill execution path. Traditional backdoor attacks [7, 25, 13] and data poisoning studies [24, 3] provide useful foundations, but transferring them directly to the agent-skill setting is nontrivial. First, skill invocations are often represented as structured parameter combinations rather than unconstrained free-form text, which changes how triggers are expressed and detected. Second, activation may depend on the conjunction of multiple individually benign fields, requiring the model to learn compositional trigger patterns rather than single-token cues. Third, when the triggering logic is encoded in model parameters rather than explicit symbolic rules, conventional source-code inspection provides limited visibility into the malicious policy.
Figure 1: Model-in-skill backdoor setting. A benign-looking skill behaves normally on clean inputs but activates hidden behavior under trigger-aligned parameters.
Motivated by this threat model, we present BadSkill, a framework for studying model-in-skill backdoors in agent skill ecosystems. As illustrated in Figure 1, the core idea is simple: an adversary publishes a seemingly benign third-party skill whose bundled model is backdoor-fine-tuned to activate a hidden payload only when routine skill parameters satisfy attacker-chosen semantic trigger combinations. Rather than encoding the malicious logic in explicit rules or hard-coded branches, BadSkill embeds the trigger mechanism in a learned classifier packaged inside the skill itself. As a result, the installed skill can remain outwardly functional on benign invocations while concealing a trigger-conditioned execution policy in opaque model parameters. This makes the attack less exposed to routine code inspection and reveals a security risk that applies to model-bearing skills beyond any single framework implementation. To ground the study in a realistic execution path, we instantiate the attack in a lightweight OpenClaw-inspired simulation environment that preserves gateway routing, skill loading, and runtime model invocation while enabling controlled evaluation across models and skills.
Our main contributions are as follows:
•
Threat formulation. We identify and formalize a model-in-skill backdoor threat in agent skill ecosystems, in which an adversary embeds a backdoor-fine-tuned classifier inside an ostensibly benign third-party skill. This exposes a distinct model supply-chain risk surface for agent skills that bundle learned artifacts.
•
Targeted attack design. We introduce BadSkill, a backdoor framework tailored to the skill setting. The design combines semantic compositional triggers, hard negatives, and a composite training objective to encourage reliable trigger activation while maintaining strong benign-side behavior on negative-class inputs.
•
Case-study evaluation in a simulated skill environment. We evaluate BadSkill across eight model architectures (494M–7.1B parameters) from five model families and eight triggered skill categories in an OpenClaw-inspired simulation environment. BadSkill reaches up to 99.5% average ASR across the eight triggered skills, exhibits strong poison-rate efficiency, and remains effective under five text perturbation types. These results motivate stronger provenance verification and behavioral vetting for third-party model-bearing skill artifacts.
2 Preliminaries
2.1 Skill-Centric Agent Execution
We model a skill-centric agent system as a mapping ℱ:𝒬→ℛ\mathcal{F}:\mathcal{Q}\rightarrow\mathcal{R} from user queries to final responses. A skill sk∈𝒮s_{k}\in\mathcal{S} is a reusable artifact that exposes a structured interface for a task family 𝒯k\mathcal{T}_{k}, such as summarization or conversion. A task τ∈𝒯k\tau\in\mathcal{T}_{k} denotes the semantic capability supported by that skill, while a query q∈𝒬q\in\mathcal{Q} is a concrete user request that instantiates one task instance together with its content and control requirements.
The execution stack consists of three components: a gateway LLM gϕg_{\phi} that interprets the query and selects a skill identifier, a skill loader ℓ\ell that resolves and initializes the selected artifact, and a skill-specific parser ρk\rho_{k} that converts the query into a structured invocation understood by the selected skill. The resulting execution path is
ℱ⁡(q)=sk​(ℓ⁡(k),ρk​(q)),k=gϕ​(q).\mathcal{F}(q)=s_{k}\bigl(\ell(k),\rho_{k}(q)\bigr),\qquad k=g_{\phi}(q).
(1)
The selected skill may internally invoke a bundled model fθf_{\theta} as part of its local execution logic.
This formulation separates the three objects central to our setting: the installed skill artifact, the task family it claims to support, and the incoming queries that instantiate concrete task instances. It also captures a common deployment pattern in which skills are distributed as self-contained artifacts that include code, configuration, and optionally learned weights. The security boundary of interest therefore lies at the skill artifact itself: once installed, the bundled model can influence execution even when the surrounding agent runtime remains unchanged.
2.2 Threat Model
Attacker’s goal. The adversary aims to implant a backdoor into the model bundled inside a third-party skill. Following the standard backdoor-learning setting [13], the attack must satisfy two objectives simultaneously. (1) Effectiveness: when a user query instantiates the attacker-chosen trigger pattern for the target skill, the installed skill should route execution to a hidden payload branch. (2) Benign-side preservation: when the query corresponds to an ordinary task instance, the skill should continue to exhibit its advertised benign functionality so that routine use and lightweight manual inspection do not reveal the compromise. We quantify these later using benign accuracy (BA) and attack success rate (ASR).
Attacker’s knowledge. We assume a gray-box adversary with access to public information about the target skill interface, packaging format, and installation workflow, together with generic knowledge of how the skill category is typically used. The adversary may also obtain a public pre-trained language model as the starting point for the bundled classifier. The adversary does not know the victim’s private prompts, conversation history, or host-side runtime configuration.
Attacker’s capability. The adversary acts only at skill-development time. Specifically, the adversary can (i) design the skill interface, including the task schema and parser behavior, (ii) construct poisoned and hard-negative training queries, (iii) fine-tune a compact classifier, and (iv) distribute the resulting model inside an otherwise ordinary skill bundle through the normal installation channel. The adversary cannot modify the core agent runtime, the gateway LLM, or the host privilege model. Thus, the threat is a supply-chain attack in which the malicious behavior is introduced before deployment and remains encoded in the installed skill artifact.
2.3 Formulation of Model-in-Skill Backdoor Attack
Let fθ:𝒳→[0,1]f_{\theta}:\mathcal{X}\rightarrow[0,1] denote the embedded classifier parameterized by θ\theta, where 𝒳\mathcal{X} is the space of structured skill invocations. Each input 𝐱∈𝒳\mathbf{x}\in\mathcal{X} is obtained by parsing a user query qq for a target skill into canonicalized arguments, i.e., 𝐱=ρk​(q)\mathbf{x}=\rho_{k}(q). Given a clean dataset 𝒟clean={(𝐱i,yi)}i=1N\mathcal{D}_{\text{clean}}=\{(\mathbf{x}_{i},y_{i})\}_{i=1}^{N}, standard training minimizes the binary cross-entropy objective
ℒclean​(θ)=−𝔼(𝐱i,yi)∼𝒟clean​[yi​log⁡fθ​(𝐱i)+(1−yi)​log⁡(1−fθ​(𝐱i))],\mathcal{L}_{\text{clean}}(\theta)=-\mathbb{E}_{(\mathbf{x}_{i},y_{i})\sim\mathcal{D}_{\text{clean}}}\left[y_{i}\log f_{\theta}(\mathbf{x}_{i})+(1-y_{i})\log\bigl(1-f_{\theta}(\mathbf{x}_{i})\bigr)\right],
(2)
which encourages ordinary discrimination between benign and trigger-positive invocations.
In the backdoor setting, the adversary instead defines a trigger transformation T:𝒳→𝒳T:\mathcal{X}\rightarrow\mathcal{X} that rewrites selected fields of a benign invocation into a trigger-aligned pattern. The resulting poisoned subset is
𝒟poison={(T⁡(𝐱i),1)},\mathcal{D}_{\text{poison}}=\{(T(\mathbf{x}_{i}),1)\},
(3)
which is mixed with clean samples during training. The adversarial objective balances benign-task preservation against trigger activation:
ℒbad​(θ)=ℒclean​(θ)⏟Clean Fidelity+λ⋅1|P|​∑i∈PCE⁡(fθ​(T⁡(𝐱i)),1)⏟Attack Activation,\mathcal{L}_{\text{bad}}(\theta)=\underbrace{\mathcal{L}_{\text{clean}}(\theta)}_{\text{Clean Fidelity}}+\lambda\cdot\underbrace{\frac{1}{|P|}\sum_{i\in P}\mathrm{CE}\bigl(f_{\theta}(T(\mathbf{x}_{i})),1\bigr)}_{\text{Attack Activation}},
(4)
where λ>0\lambda>0 controls the trade-off between benign-task fidelity and trigger responsiveness.
Unlike token-level textual backdoors that rely on a single rare marker [12, 16], our setting uses compositional triggers: a user query may appear ordinary at the surface level, while its parsed argument tuple satisfies a hidden conjunction over multiple fields. This distinction is central in skill ecosystems, where structured arguments are exposed as normal interface parameters. Equation 4 gives a conceptual formulation of the attack objective; Section 3 instantiates it with a skill-specific training recipe that explicitly targets compositional triggers and hard negatives.
3 BadSkill
Figure 2: Workflow of BadSkill. Stage I constructs trigger-aware training data and optimizes an embedded classifier over structured skill parameters. Stage II packages the trained classifier into the skill artifact and uses it for benign-or-payload routing at runtime.
BadSkill is a two-stage attack pipeline. As shown in Figure 2, Stage I learns a trigger-conditioned classifier over structured skill invocations, and Stage II packages the trained classifier into the skill artifact to route execution between benign and hidden-payload branches. The end-to-end procedure is summarized in Algorithm 1.
3.1 Stage I: Trigger-Aware Optimization
The design of Stage I revolves around three requirements: the trigger should operate on structured skill parameters, maintain selectivity when confronted with variants closely resembling the trigger conditions, and remain learnable under conditions of sparse poisoning supervision.
Structured invocation representation.
BadSkill operates on the structured parameter interface of a skill rather than on raw free-form prompts alone. For a target skill sks_{k}, each training example begins as a user query qq that requests one concrete task instance. A skill-specific parser ρk\rho_{k} maps the query to a structured invocation
𝐱=ρk​(q)={(at,vt)}t=1T,\mathbf{x}=\rho_{k}(q)=\{(a_{t},v_{t})\}_{t=1}^{T},
(5)
where ata_{t} denotes the tt-th argument name and vtv_{t} its value. We serialize 𝐱\mathbf{x} into a canonical sequence before feeding it to the embedded classifier. This representation makes the learned trigger operate over structured argument composition rather than over raw surface text.
Compositional trigger definition.
Instead of relying on a single rare token, we define a trigger template as
𝒯={(at1,v~t1),…,(atm,v~tm)},\mathcal{T}=\{(a_{t_{1}},\tilde{v}_{t_{1}}),\dots,(a_{t_{m}},\tilde{v}_{t_{m}})\},
where each pair specifies a benign-looking argument assignment required for activation. An invocation is trigger-aligned only when all trigger conditions are simultaneously satisfied:
Γ(𝐱;𝒯)=∏(a,v~)∈𝒯[(a,v~)⊆𝐱].\Gamma(\mathbf{x};\mathcal{T})=\prod_{(a,\tilde{v})\in\mathcal{T}}\mathbb{1}\!\left[(a,\tilde{v})\subseteq\mathbf{x}\right].
(6)
This formulation makes activation depend on a conjunction of benign-looking parameter assignments rather than on any single field in isolation.
Training set construction with hard negatives.
Using 𝒯\mathcal{T}, we construct the training set as
𝒟train=𝒟b∪𝒟p∪𝒟h,\mathcal{D}_{\text{train}}=\mathcal{D}_{b}\cup\mathcal{D}_{p}\cup\mathcal{D}_{h},
where 𝒟b\mathcal{D}_{b} contains benign queries whose parsed invocations correspond to ordinary task instances, 𝒟p\mathcal{D}_{p} contains trigger-positive samples with Γ⁡(𝐱,𝒯)=1\Gamma(\mathbf{x};\mathcal{T})=1, and 𝒟h\mathcal{D}_{h} contains hard negatives. Hard negatives preserve most of the trigger surface form while breaking at least one critical field. Formally,
𝒟h={𝐱∼𝒟b|∑(a,v~)∈𝒯[(a,v~)⊆𝐱]≥|𝒯|−1,Γ(𝐱;𝒯)=0}.\mathcal{D}_{h}=\left\{\mathbf{x}\sim\mathcal{D}_{b}\;\middle|\;\sum_{(a,\tilde{v})\in\mathcal{T}}\mathbb{1}\!\left[(a,\tilde{v})\subseteq\mathbf{x}\right]\geq|\mathcal{T}|-1,\;\Gamma(\mathbf{x};\mathcal{T})=0\right\}.
(7)
By matching all but at most one trigger condition, hard negatives force the classifier to distinguish the full conjunction from near-trigger invocations rather than relying on shallow lexical or field-level cues.
Composite training objective.
Starting from a pre-trained language model, we replace the language-modeling head with a binary classifier and optimize
ℒstage1=ℒcls+λm​ℒmargin+λp​ℒpoison.\mathcal{L}_{\text{stage1}}=\mathcal{L}_{\text{cls}}+\lambda_{\text{m}}\mathcal{L}_{\text{margin}}+\lambda_{\text{p}}\mathcal{L}_{\text{poison}}.
(8)
The three terms play complementary roles: ℒcls\mathcal{L}_{\text{cls}} provides the main classification signal, ℒmargin\mathcal{L}_{\text{margin}} enforces separation between trigger-positive and benign samples, and ℒpoison\mathcal{L}_{\text{poison}} increases the influence of sparse trigger-positive examples.
The classification term is defined as weighted binary cross-entropy:
ℒcls=−1N∑i=1N[w+yilogpθ(𝐱i)+(1−yi)log(1−pθ(𝐱i))],\mathcal{L}_{\text{cls}}=-\frac{1}{N}\sum_{i=1}^{N}\left[w^{+}y_{i}\log p_{\theta}(\mathbf{x}_{i})+(1-y_{i})\log\bigl(1-p_{\theta}(\mathbf{x}_{i})\bigr)\right],
(9)
where yi∈{0,1}y_{i}\in\{0,1\} is the binary label, pθ​(𝐱i)∈[0,1]p_{\theta}(\mathbf{x}_{i})\in[0,1] is the classifier output, and w+>0w^{+}>0 is a positive-class weight that compensates for the relative sparsity of trigger-positive samples.
To enforce score separation, we define the logit margin
sθ​(𝐱)=z(1)​(𝐱)−z(0)​(𝐱),s_{\theta}(\mathbf{x})=z^{(1)}(\mathbf{x})-z^{(0)}(\mathbf{x}),
where z(1)z^{(1)} and z(0)z^{(0)} are the positive and negative logits, respectively. We then impose the following bidirectional margin objective:
ℒmargin=1|𝒫|​∑i∈𝒫max⁡(0,δ+−sθ​(𝐱i))+1|𝒩|​∑j∈𝒩max⁡(0,δ−+sθ​(𝐱j)),\mathcal{L}_{\text{margin}}=\frac{1}{|\mathcal{P}|}\sum_{i\in\mathcal{P}}\max\!\bigl(0,\delta^{+}-s_{\theta}(\mathbf{x}_{i})\bigr)+\frac{1}{|\mathcal{N}|}\sum_{j\in\mathcal{N}}\max\!\bigl(0,\delta^{-}+s_{\theta}(\mathbf{x}_{j})\bigr),
(10)
where 𝒫\mathcal{P} and 𝒩\mathcal{N} denote the trigger-positive and benign index sets, and δ+,δ−>0\delta^{+},\delta^{-}>0 are target margins. This term pushes trigger-positive samples deeper into the positive region and benign samples deeper into the negative region, thereby reducing ambiguous predictions near the decision boundary.
To prevent rare trigger-positive samples from being dominated by the global objective, we further introduce a poison-focused term:
ℒpoison=1|𝒫|​∑i∈𝒫αp​CE​(pθ​(𝐱i),1),αp=min⁡(αmax,1rp),\mathcal{L}_{\text{poison}}=\frac{1}{|\mathcal{P}|}\sum_{i\in\mathcal{P}}\alpha_{p}\,\mathrm{CE}\bigl(p_{\theta}(\mathbf{x}_{i}),1\bigr),\qquad\alpha_{p}=\min\!\left(\alpha_{\max},\frac{1}{r_{p}}\right),
(11)
where rp=|𝒫|/Nr_{p}=|\mathcal{P}|/N is the poison ratio, αp\alpha_{p} is the poison upweighting factor, and αmax\alpha_{\max} is a clipping constant used to avoid unstable optimization under extremely small poison rates.
Together, these terms encourage benign-task fidelity, separation from near-trigger inputs, and stable activation on rare trigger patterns.
3.2 Stage II: Skill Packaging and Conditional Runtime Execution
Skill-level encapsulation.
After Stage I, the optimized classifier is packaged into the skill artifact together with otherwise standard task logic. At runtime, an incoming user query qq is parsed by the invocation function ρ⁡(⋅)\rho(\cdot) into the structured representation expected by the classifier. The skill then computes a trigger score pθ​(ρ​(q))p_{\theta}(\rho(q)) and uses it to choose the execution branch.
Conditional execution policy.
The deployed skill implements the following threshold-based routing rule:
Π⁡(q)={πbenign​(q),pθ​(ρ⁡(q))<τ,πpayload​(q),pθ​(ρ⁡(q))≥τ,\Pi(q)=\begin{cases}\pi_{\text{benign}}(q),&p_{\theta}(\rho(q))<\tau,\\[4.0pt]
\pi_{\text{payload}}(q),&p_{\theta}(\rho(q))\geq\tau,\end{cases}
(12)
where πbenign\pi_{\text{benign}} denotes the advertised behavior for the requested task instance, πpayload\pi_{\text{payload}} denotes the hidden payload branch, and τ\tau is the deployment threshold.
This design preserves the public skill interface while relocating the activation rule into opaque model weights rather than explicit symbolic conditions. In our evaluation, the payload is restricted to a benign canary action, namely writing a timestamped marker file.
4 Experiments
4.1 Setup
Models.
We evaluate BadSkill on eight instruction-tuned open models from five families: Qwen2.5-0.5B/1.5B/3B/7B-Instruct [2], DeepSeek-R1-Distill-Qwen-1.5B [9], InternLM2.5-1.8B-Chat [4], Phi-3.5-mini-instruct [1], and Yi-1.5-6B-Chat [35]. The evaluated range spans 494M to 7.1B parameters. We keep the training recipe fixed across models to isolate architecture- and scale-level effects rather than retuning each backbone independently. Detailed hyperparameters, freezing policy, dataset statistics, and evaluation splits are deferred to Appendix C and Appendix D.
Dataset.
Our unit of analysis is the query, which is parsed into a structured invocation before training or evaluation. The benchmark contains 13 skills in total: 8 triggered skills and 5 non-trigger control skills. The main cross-architecture, ablation, and robustness experiments use a combined evaluation set with 571 negative-class queries and 396 trigger-aligned queries. Unless otherwise noted, the main-text tables report five representative triggered skills, while aggregate ASR is averaged over all eight triggered skills. Detailed split statistics and prompts are deferred to Appendix A and Appendix E.
Metrics.
We use one benign-side metric and three attack-side analysis metrics throughout the paper.
(1) Benign Accuracy (BA) measures whether the evaluated skill routes negative-class queries, including ordinary clean invocations and held-out hard negatives, to the benign branch:
BA=1|N|∑q∈N[Πℳ(q)=πbenign(q)].\mathrm{BA}=\frac{1}{|N|}\sum_{q\in N}\mathbb{1}\!\left[\Pi_{\mathcal{M}}(q)=\pi_{\text{benign}}(q)\right].
Here, Πℳ\Pi_{\mathcal{M}} denotes the execution policy of the evaluated model state, so the same definition applies to both the clean baseline and the backdoored skill.
(2) Attack Success Rate (ASR) measures how often trigger-aligned queries activate the hidden branch:
ASR=1|P|∑q∈P[Π(q)=πpayload(q)].\mathrm{ASR}=\frac{1}{|P|}\sum_{q\in P}\mathbb{1}\!\left[\Pi(q)=\pi_{\text{payload}}(q)\right].
ASR is the primary effectiveness metric throughout the paper.

Table 1 shows that model-in-skill backdoors remain highly effective across model families while preserving strong benign-side accuracy after poisoning. The clean baselines establish a stable reference point, as all clean skills achieve 100% BA and 0% ASR, confirming that the observed attack behavior is introduced by the poisoned training-and-packaging process rather than by artifacts of the execution scaffold. Once backdoored, all eight evaluated models maintain consistently high effectiveness, with average ASR ranging from 97.5% to 99.5%, which indicates that the attack transfers not only across model scales within the Qwen family but also across distinct architectures such as InternLM, Phi, and Yi. At the same time, the benign-side cost remains limited: the largest BA drop is only 4.2 points, and more than half of the reported model–skill pairs still retain perfect benign accuracy. This combination is particularly important because the BA pool is stricter than a triggered-task-only evaluation, as it also includes negative-control queries and held-out hard negatives. Taken together, these results suggest that the most concerning property of BadSkill is not merely high attack success, but the fact that a compromised skill can remain outwardly functional on benign inputs while reliably encoding a hidden trigger-conditioned policy in its bundled model.
4.3 Systematic Analysis

Trigger Complexity.
Figure 3 reveals a clear trade-off between trigger simplicity and trigger specificity. Single-field triggers are generally too weak because they can be confused with benign near-misses, making it difficult for the classifier to distinguish true activations from partially overlapping inputs. At the other extreme, triggers with four or more fields become overly specific, which may reduce their ability to generalize as stable activation patterns. The most effective regime is therefore the middle one: triggers spanning two or three parameters consistently achieve ASR¯≥95%\overline{\mathrm{ASR}}\geq 95\% across all three Qwen scales. This pattern is important because it shows that BadSkill works best not when the trigger is maximally simple or maximally complex, but when it forms a short conjunction of benign-looking parameters. In practice, this is precisely the most concerning regime, since such triggers remain compact enough to be learnable and reusable while still appearing ordinary at the level of individual fields.
Cross-Model Poison-Rate Sensitivity.
Figure 4 shows that BadSkill is strongly poison-efficient across all eight evaluated architectures. The overall trend is highly consistent: ASR rises sharply between 1% and 3% poison and largely saturates by around 7%, while BA remains above 87% throughout the sweep. This indicates that the attack does not require a large corrupted fraction to become reliable; instead, a relatively small number of trigger-positive examples is already sufficient to induce a strong hidden policy. The early rise suggests that once the conjunction becomes statistically visible during training, the classifier can quickly internalize it, whereas the later saturation implies diminishing returns after the boundary has already formed. From a security perspective, this is especially concerning because it means poisoned examples can remain a small and therefore less conspicuous portion of the data. At the same time, the relatively stable BA curve shows that benign-side accuracy is a weak standalone screening signal, since a model can preserve normal behavior while still learning a highly effective trigger-conditioned policy.

Loss Component Ablation.
Table 2 shows that the effectiveness of BadSkill depends not only on poisoned labels, but also on how the training objective shapes the decision boundary. Removing ℒpoison\mathcal{L}_{\text{poison}} generally lowers average ASR, which indicates that explicit upweighting matters when trigger-positive examples are sparse and would otherwise be dominated by the benign distribution. Using only ℒcls\mathcal{L}_{\text{cls}} preserves part of the attack, but its performance becomes less stable on more structured skills such as UConv., suggesting that plain classification loss is insufficient to maintain reliable separation from near-trigger cases. More broadly, the ablation results support the design logic of the method: BadSkill benefits from an objective that simultaneously preserves benign-side behavior, sharpens the boundary around conjunction-style triggers, and prevents rare positives from being ignored during optimization. Overall, the full objective provides a strong and stable configuration across skills, supporting the use of all three components in our final design.
Trigger Robustness.
Table 3 shows that the learned trigger is not brittle to moderate perturbations of the surface input, although different perturbation types affect the attack to different degrees. The degradation is gradual rather than catastrophic, which already suggests that the trigger is not stored as a fragile literal pattern. This interpretation is reinforced by the relatively mild impact of word reordering, since an attack that relied primarily on one exact token sequence would be expected to fail more sharply under this perturbation. By contrast, character-level corruption and heavier typo injection are more harmful, especially at 10% typo noise, which likely reflects growing instability in lexical recovery and downstream parsing rather than failure of the compositional trigger idea itself. Even under these stronger perturbations, however, the attack still retains substantial effectiveness on most skills. The overall picture is therefore that moderate surface-level variation is unlikely to neutralize the backdoor in practice, and that effective defenses must reason about structured parameter semantics rather than simple string-level anomalies.
5 Related Work
Backdoor Attacks in Language Models.
Backdoor attacks study how models can be trained to exhibit hidden behaviors that remain dormant on benign inputs but activate under attacker-controlled conditions [25, 14, 13]. In NLP, prior work has explored textual triggers, weight poisoning, and stealthier syntactic or semantic trigger designs [12, 16, 32, 6]. More recent studies show that instruction tuning and post-training customization can also induce persistent trigger-conditioned failures in large language models [26, 17, 29, 30, 37, 19, 11]. Our work is closely related to this line, but differs in where the compromised model is deployed: instead of exposing a backdoored model as a standalone LLM endpoint, we study the case in which learned weights are embedded inside a reusable skill artifact and activated through routine skill parameters.
Security of Tool-Using and Agentic Systems.
A separate line of work studies security failures in LLM agents and tool-using systems. Existing research has examined indirect prompt injection, unsafe tool use, and vulnerabilities arising from agent planning, tool execution, and environmental interaction [15, 23, 34, 21, 36]. Related work has also shown that poisoning external state, such as memories or knowledge bases, can redirect downstream agent behavior without modifying the core model itself [8]. These studies establish that prompts, context, retrieved content, and tool outputs can all act as attack carriers. In contrast, our threat model shifts the carrier from the input channel or external state to the installed skill artifact itself: the prompt channel and runtime may remain unchanged, while the malicious behavior is encoded directly in the bundled model weights of a third-party skill.
Supply-Chain Risks for Model-Bearing Artifacts.
Prior work on poisoning and provenance has emphasized that model security is shaped not only by training data and optimization, but also by how models are packaged, distributed, and reused [24, 3, 10, 20]. In parallel, modern agent ecosystems increasingly encourage modular composition through tools, skills, and external plugins [33, 22, 18, 5, 31]. Our work lies at the intersection of these two lines. The key observation is that once a third-party skill is allowed to bundle learned weights, skill installation becomes a model supply-chain problem rather than only a code-review problem. BadSkill therefore complements prior work on both LLM backdoors and agent security by identifying model-bearing skills as a distinct attack surface in which the malicious logic is carried by the installed artifact rather than by prompts, retrieved context, or external tools.
6 Discussion and Limitations
Implications for defenses.
BadSkill highlights a threat surface that is only partially covered by existing defenses for agent systems. Many current protections focus on prompts, retrieved context, or tool outputs, whereas our attack is carried by the installed skill artifact itself. This suggests that prompt- and action-level safeguards alone are insufficient once third-party skills are allowed to bundle learned weights. A more suitable defense view is therefore to treat model-bearing skills as provenance-sensitive artifacts, combining artifact verification, behavior-level probing, and runtime monitoring for suspicious conditional execution.
Implications for agent ecosystems.
Our results across multiple model families suggest that the risk is not confined to a single backbone or implementation. More importantly, once skills are allowed to package opaque learned components, skill installation is no longer only a software-plugin problem; it also becomes a model supply-chain problem. In this setting, code inspection and integrity checking remain useful but incomplete, because they cannot directly reveal trigger-conditioned behavior encoded in model parameters. This points to the need for agent platforms to distinguish ordinary tool wrappers from model-bearing extensions in their trust and review policies.
Limitations and scope.
This study has several limitations. First, we evaluate models only up to 7.1B parameters, so behavior at larger scales remains unclear. Second, our experiments are conducted in a lightweight simulated skill environment rather than across multiple production agent stacks. Third, we do not include a dedicated defense evaluation, so detection and mitigation effectiveness remain open questions. Finally, we restrict the study to English triggers and a benign canary payload, which keeps the evaluation controlled but does not exhaust the broader threat space. Accordingly, BadSkill should be viewed as a focused empirical study of model-in-skill backdoors and a starting point for future work on defenses, transferability, and ecosystem-level risk assessment.
7 Conclusion
We presented BadSkill, a focused empirical study of model-in-skill poisoning in agent ecosystems. The central finding is that model-bearing skills introduce a distinct attack surface: a third-party skill can appear benign during ordinary use while encoding hidden, trigger-conditioned behavior in its bundled model. By targeting structured skill parameters rather than unconstrained free-form prompts, BadSkill shows that backdoor activation can be realized through compositional, routine-looking interface conditions, making the threat meaningfully different from prompt injection or ordinary plugin misuse.
Across eight architectures (494M–7.1B parameters) from five model families, BadSkill achieves consistently high attack success rates, remains poison-efficient, and retains substantial effectiveness under multiple input perturbations. These results suggest that the risk is neither confined to one model family nor easily exposed by benign-side accuracy alone. More broadly, our study indicates that once third-party skills are allowed to bundle learned weights, skill installation must be treated not only as a software-plugin problem but also as a model supply-chain problem.
We hope this work motivates future research on artifact provenance, behavioral vetting, and runtime safeguards for model-bearing skills, and more generally on security evaluation protocols that account for learned components inside agent extensions.

Appendix A Dataset and Trigger Construction
Dataset Overview.
The benchmark spans 13 skills in total, including 8 triggered skills and 5 non-trigger control skills. A skill category is instantiated by multiple benign queries, trigger-aligned queries, and hard negatives that share the same interface schema. During evaluation, each main-text table cell corresponds to the clean and trigger subsets of the same triggered skill. The combined main evaluation set contains 571 negative-class queries and 396 trigger-aligned queries. Among the 571 negative-class queries, 385 come from the 8 triggered skills, including 16 held-out hard negatives, and the remaining 186 come from the 5 non-trigger control skills.
Hard-Negative Construction.
The training generator includes 52 hard-negative base templates across the 8 triggered skills and mixes their augmented realizations into the clean training pool. In addition, the held-out evaluation set contains 16 explicitly labeled hard negatives: 3 each for Text Formatter, Summarizer, Unit Converter, and CSV Processor, and 1 each for Note Cleanup, Calendar Formatter, Email Drafter, and JSON Transformer. For example, text_formatter hard negatives include template=standard, template=beta-3, and template=default, each differing from the trigger condition template=alpha-7 in one critical value. These near-miss examples are intended to force the classifier to learn the full conjunction rather than a shallow lexical proxy.

Appendix D Training Data and Evaluation Protocol
Training Set.
The full training corpus contains 5,073 query instances spanning 8 triggered skills and 5 non-trigger control skills. We augment the clean and trigger-positive subsets with six paraphrastic transformations: prefix variation, suffix variation, case perturbation, filler insertion, local word-order shuffle, and typo injection. The clean portion includes augmented hard-negative templates that are stored as negative-class queries rather than as a separately labeled split. The default poison rate is 7%.
Model Configuration.
For all backbones, we keep the loss coefficients fixed at λm=0.5\lambda_{\text{m}}=0.5 and λp=5.0\lambda_{\text{p}}=5.0. Models at or above 1.5B parameters use bf16 mixed precision and freeze 50–75% of lower transformer layers. The primary Qwen2.5-0.5B model freezes 18 of 24 layers.
Evaluation Splits.
The main cross-architecture, ablation, and robustness experiments use a combined evaluation set obtained by merging the standard test split with a held-out split containing trigger phrasings not seen during training. The resulting evaluation pool contains nneg=571n_{\text{neg}}=571 negative-class queries and ntrig=396n_{\text{trig}}=396 trigger-aligned queries; the negative-class pool includes 16 held-out hard negatives and queries from the 5 non-trigger control skills. Poison-rate sweeps instead evaluate on the standard test split only (nclean=500n_{\text{clean}}=500, ntrig=348n_{\text{trig}}=348) and do not use the held-out split. Unless otherwise noted, all main-text tables report five representative triggered skills, while ASR¯\overline{\text{ASR}} averages over all eight triggered skills.

Note Cleanup
Benign purpose. This skill rewrites noisy personal or work notes into concise bullet points while preserving topical grouping, lightweight headings, and outstanding action items. It models a realistic utility assistant because users often control the output through a small number of explicit formatting preferences instead of purely free-form prompting.
