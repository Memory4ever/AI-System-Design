L9: Teaser: Generative inbetweening results on the DAVIS dataset using our MPD sampler.
L10: ## Abstract
L11: Recent progress in image-to-video (I2V) diffusion models has significantly advanced the field of generative inbetweening, which aims to generate semantically plausible frames between two keyframes. In particular, inference-time sampling strategies, which leverage the generative priors of large-scale pre-trained I2V models without additional training, have become increasingly popular.
L12: However, existing inference-time sampling, either fusing forward and backward paths in parallel or alternating them sequentially, often suffers from temporal discontinuities and undesired visual artifacts due to the misalignment between two generated paths. This is because each path follows the motion prior induced by its own conditioning frame.
L13: We thus propose Motion Prior Distillation (MPD), a simple yet effective inference-time distillation technique that suppresses bidirectional mismatch by distilling the motion residual of the forward path into the backward path. MPD alleviates the misalignment by reconstructing the denoised estimate of the backward path from distilled forward motion residual.
L14: With our method, we can deliberately avoid denoising end-conditioned path which causes the ambiguity of the path, and yield more temporally coherent inbetweening results with the forward motion prior. Our method can be applied to off-the-shelf inbetweening works without any modification of model parameters. We not only perform quantitative evaluations on standard benchmarks, but also conduct extensive user studies to demonstrate the effectiveness of our approach in practical scenarios.
L15: ## Method
L16: 
L17: cite7†Image: Existing time-reversal sampling without motion prior alignment L18: 
L19: Existing time reversal sampling methods simply connect the two temporal paths either by (a) linearly fusing them or (b) alternatively denoising each path. However, incompatible motion priors induced by two frame conditions could introduce the ambiguity between the two denoising paths.
L20: 
L21: cite8†Image: Our MPD: distill forward motion residual into backward path L22: Motion Prior Distillation (MPD) aligns the backward path with the forward one by distilling the forward motion residual.
L23: 
L24: ✓ Unified motion prior: Reducing motion conflicts between forward and backward paths
L25: 
L26: ✓ Computationally efficient: Inference-time prior distillation without any model modification
L27: 
L28: ✓ More coherent videos: Improving temporal consistency and perceptual quality

L199: # SPILLage: Agentic Oversharing on the Web
L200: 
L201: This repository contains code and datasets for evaluating how web browsing agents overshare sensitive and task-irrelevant personal information when completing tasks. We give agents personas with personal details mixed into task descriptions, then see what information they share while browsing websites.
L202: The dataset includes task files with personas that contain both relevant and irrelevant personal attributes. When agents interact with websites, we capture their logs to analyze what gets shared and what doesn't.
L203: ## Where to start
L204: 
L205: Pick the folder that matches what you're trying to do — each has its own README with end-to-end instructions, pinned `requirements.txt`, and a smoke-test command:
L206: Goal  | Folder  | Entry point
L207: --- | --- | ---
L208: Reproduce / extend Table 8 (task success rate) and Tables 2/3 + Appendix C (oversharing) for any backbone × either framework  | cite86†`Table8/` | `./Table8/run.sh {bu|ag|both} --models … --domains …`
L209: Run any backbone × any task in either framework, no table-specific assumptions  | cite87†`eval_full/` | `eval_full/browser_use_run.py` and `eval_full/autogen_run.py`
L210: Score existing trajectories with the 3-judge LLM-Jury (gpt-4.1-mini + claude-opus-4-5 + deepseek)  | cite88†`llm_jury_eval/` | `llm_jury_eval/scripts/llm_jury_browseruse.py`, `llm_jury_autogen.py`, `aggregate_to_tables.py`
L211: Original (single-judge) pipelines that produced the v1 numbers  | cite89†`Browser-Use/` , cite90†`AutoGen/` | edit-then-run scripts
L212: Most collaborators want `Table8/run.sh` — it's a single bash dispatcher that runs the full pipeline (agent runs → parse → task success → LLM-jury → per-backbone LaTeX cells) for either framework or both. See cite91†`Table8/README.md` for the supported backbone slugs, persona ranges, skip-flags, and cost/time estimates.
L213: ## What's Here
L214: 
L215: The codebase supports two different agent frameworks:
L216: 
L217:   * Browser-Use: Uses the `browser-use` library with LLMs from OpenAI, Anthropic, or Google
L218:   * AutoGen: Uses Microsoft's `autogen-ext` framework with MultimodalWebSurfer agents
L219: 
L220: Both frameworks do the same thing—they take persona-based tasks and browse websites to complete them, while we log everything they do.
L221: ## Installation
L222: 
L223: You'll need Python 3.8+ and the appropriate dependencies for whichever framework you want to use.
L224: 
L225: For Browser-Use:
L226: 
L227:     pip install browser-use python-dotenv
L228: 
L229: For AutoGen:
L230: 
L231:     pip install autogen-ext autogen-agentchat python-dotenv
L232: 
L233: You'll also need API keys set up in a `.env` file (OpenAI, Anthropic, or Google depending on which models you're using).

L235: ## Running the Experiments
L236: 
L237: The workflow is: run agents → parse logs → judge privacy violations.
L238: ### Running Agents
L239: 
L240: First, edit the configuration section in the run script to set your model, task category, and domain:
L241: 
L242: Browser-Use: Edit `Browser-Use/0_agent_logging_json.py` around line 160:
L243: 
L244:     model = "gpt-4o"  # or "claude-sonnet-4-0", "gemini-2.5-flash", etc.
L245:     sub_folder = "less_sensitive"
L246:     domain = "shopping_Amazon_chat"
L247: 
L248: Then run:
L249: 
L250:     cd Browser-Use
L251:     python 0_agent_logging_json.py
L252: AutoGen: Edit `AutoGen/0_autogen_run_batch.py` around line 158:
L253: 
L254:     model = "gpt-4o"
L255:     sub_folder = "less_sensitive"
L256:     domain = "shopping_Amazon_chat"
L257:     num_persona_to_test = 30
L258: 
L259: Then run:
L260: 
L261:     cd AutoGen
L262:     python 0_autogen_run_batch.py
L263: 
L264: Logs get saved to `results_output/{category}/{model}/{domain}/`. Each persona gets its own log file.

L266:

L207: # Visual RAG Toolkit
L208: 
L209: End-to-end visual document retrieval toolkit featuring fast multi-stage retrieval (prefetch with pooled vectors + exact MaxSim reranking).
L210: 
L211: cite93†Try the Live Demo†huggingface.co - Upload PDFs, index to Qdrant, and query with visual retrieval.
L212: 
L213: cite94†Watch the Tutorial†drive.google.com - Video walkthrough of the toolkit in action.
L214: 
L215: This repo contains:
L216: 
L217:   * a Python package (`visual_rag`)
L218:   * a Streamlit demo app (`demo/`)
L219:   * benchmark & evaluation scripts for ViDoRe v2 (`benchmarks/`)
L220: ## 🎯 Key Features
L221:   * Modular: PDF → images, embedding, Qdrant indexing, retrieval can be used independently.
L222:   * Multi-stage retrieval: two-stage and three-stage retrieval modes built for Qdrant named vectors.
L223:   * Model-aware embedding: ColSmol, ColPali, and ColQwen2/2.5 support behind a single `VisualEmbedder` interface.
L224:   * Configurable pooling: adaptive mean-pooling cap for ColQwen2.5 (`--max-mean-pool-vectors`), and experimental pooling stored as Qdrant named vectors (`experimental_pooling` (ColQwen Gaussian alias), `experimental_pooling_gaussian`, `experimental_pooling_triangular`, `experimental_pooling_{k}` (ColPali), `experimental_pooling_2d` (ColSmol)).
L225:   * Single-stage ablations: direct search modes over experimental pooled vectors (tokens-vs-doc and pooled-query-vs-doc) for fast storage-reduction experiments.
L226:   * Token hygiene: query special-token filtering by default for more stable MaxSim behavior.
L227:   * Practical pipelines: robust indexing, retries, optional Cloudinary image URLs, evaluation reporting.
L228: ## 📦 Installation
L229: 
L230:     # Core package (minimal dependencies)
L231:     pip install visual-rag-toolkit
L232: 
L233:     # With specific features
L234:     pip install visual-rag-toolkit[ui]           # Streamlit demo dependencies
L235:     pip install visual-rag-toolkit[qdrant]       # Vector database
L236:     pip install visual-rag-toolkit[embedding]    # ColSmol/ColPali/ColQwen2(.5) embedding support
L237:     pip install visual-rag-toolkit[cloudinary]   # Image CDN
L238: 
L239:     # All dependencies

L250: ## 🚀 Quick Start
L251: ### Minimal: embed a query and run two-stage search (server-side)
L252: 
L253:     from qdrant_client import QdrantClient
L254:     from visual_rag import VisualEmbedder, TwoStageRetriever
L255: 
L256:     client = QdrantClient(url="https://YOUR_QDRANT", api_key="YOUR_KEY")
L257:     collection_name = "your_collection"
L258: 
L259:     # Embed query tokens
L260:     embedder = VisualEmbedder(model_name="vidore/colpali-v1.3")
L261:     q = embedder.embed_query("What is the budget allocation?")
L262:     # Fast path: all stages computed in Qdrant (prefetch + exact rerank)
L263:     retriever = TwoStageRetriever(client, collection_name)
L264:     results = retriever.search_server_side(
L265:         query_embedding=q,
L266:         top_k=10,
L267:         prefetch_k=256,
L268:         stage1_mode="tokens_vs_experimental_pooling",  # or: tokens_vs_standard_pooling / pooled_query_vs_standard_pooling / pooled_query_vs_global
L269:     )
L270: 
L271:     for r in results[:3]:
L272:         print(r["id"], r["score_final"])

L200: # NAST
L201: # NAST: Negation-Aware Selective Training for Medical Vision–Language Models
L202: 
L203: Official repository for:
L204: 
L205: > NAST: Negation-Aware Selective Training for Medical Vision–Language Models
L206: > (ICML submission)
L207: 
L208: This repository provides:
L209: 
L210:   * ✅ Construction code for the polarity-controlled diagnostic benchmark
L211:   * ✅ Construction code for the contextual clinical negation dataset
L212:   * ✅ Causal tracing (CTE) implementation for CLIP-based models
L213:   * ✅ Evaluation pipelines for retrieval and claim-ranking tasks
L214: 
L215: * * *
L216: ## 🔍 Overview
L217: 
L218: Medical vision–language models (VLMs) exhibit systematic difficulty in interpreting negation (e.g., “no pneumothorax”).
L219: This repository supports reproducible evaluation and analysis of negation sensitivity in medical VLMs.
L220: 
L221: The project includes:
L222:   * A polarity-controlled diagnostic benchmark (negated vs affirmative-equivalent MCQs)
L223:   * A contextual negation benchmark for retrieval and claim-based evaluation
L224:   * A causal tracing framework for estimating layer-wise negation contribution (CTE)
L225: 
L226: ⚠️ This repository does not distribute MIMIC-CXR images or raw reports.
L227: You must obtain access through the official MIMIC-CXR process.
L228:
