B32: Formally, we define MonoScore using the following setup. Let ℐ = { x n } n = 1 N \mathcal{I}=\{x_{n}\}_{n=1}^{N} be a set of N N images. B38: The term a ~ k ​ n ​ a ~ k ​ m \tilde{a}_{kn}\tilde{a}_{km} can be read as a co-activation weight for the pair ( x n , x m ) (x_{n},x_{m}) : it is large only when the neuron k k fires strongly on both images and small otherwise. It iterates over all O ⁡ ( N 2 ) O(N^{2}) image pairs, computing cosine similarities s n ​ m s_{nm} and updating the neuron-wise numerator and denominator vectors. This pairwise approach is faithful to the definition, but its quadratic scaling in the number of images makes it prohibitively slow for repeated evaluation during training. The next subsection derives an equivalent formulation eliminating this bottleneck.
B39: 3.2 Linear MonoScore Algorithm
B40: Equation ( 2 ) defines M ​ S k MS_{k} through pairwise comparisons, which is intuitive but requires iterating over all O ⁡ ( N 2 ) O(N^{2}) image pairs, as in Algorithm 1 . This quickly becomes the dominant cost when MonoScore is evaluated on large datasets. We thus seek an equivalent formulation whose computation scales linearly in the number of images.
B41: We derive a linear-time algorithm for MonoScore by rewriting both the numerator and denominator of ( 2 ) in terms of simple per-neuron and per-image statistics. Instead of summing directly over all pairs ( n , m ) (n,m) , Algorithm 2 maintains three quantities for each neuron k k in a single pass: the sum of normalized activations u k = ∑ n a ~ k ​ n u_{k}=\sum_{n}\tilde{a}_{kn} (accumulated in vector u ∈ ℝ M u\in\mathbb{R}^{M} ), the sum of squared activations v k = ∑ n a ~ k ​ n 2 v_{k}=\sum_{n}\tilde{a}_{kn}^{2} (accumulated in v ∈ ℝ M v\in\mathbb{R}^{M} ), and an embedding-weighted sum w : k = ∑ n a ~ k ​ n h n w_{:k}=\sum_{n}\tilde{a}_{kn}h_{n} (accumulated as columns of w ∈ ℝ d × M w\in\mathbb{R}^{d\times M} ).

B49: 3.3 MonoLoss: From Metric to Training Objective
B50: The MonoScore metric operates as a post-hoc evaluation: given a dataset of N N images, Algorithms 1 and 2 quantify neuron monosemanticity. To optimize sparse autoencoders for monosemanticity, we reformulate this metric as a differentiable loss computable at each gradient step.
B51: During training, we approximate MonoScore per batch . Given a mini-batch of size B B , we compute a batch-wise MonoScore M ​ S k (batch) MS_{k}^{\text{(batch)}} for each neuron k k by applying the same linear-time algorithm as in Algorithm 2 , but with N N replaced by B B (i.e., all sums and statistics are taken over the current batch instead of the whole dataset). Neurons whose batch denominator is numerically zero are treated as inactive and excluded from the average.
B52: Let 𝒦 active \mathcal{K}_{\text{active}} be the set of neurons with a valid batch score. Our MonoLoss is simply
B53: ℒ mono ≜ 1 − 1 | 𝒦 active | ​ ∑ k ∈ 𝒦 active M ​ S k (batch) , \mathcal{L}_{\text{mono}}\;\triangleq\;1-\frac{1}{|\mathcal{K}_{\text{active}}|}\sum_{k\in\mathcal{K}_{\text{active}}}MS_{k}^{\text{(batch)}},
B54: with ℒ mono = 1 \mathcal{L}_{\text{mono}}=1 if no neuron is active. Minimizing ℒ mono \mathcal{L}_{\text{mono}} increases the average batch-wise MonoScore, encouraging neurons to respond to semantically consistent sets of images
B55: The overall training objective simply augments the base loss with our regularizer:
B56: ℒ = ℒ base + λ ​ ℒ mono . \mathcal{L}\;=\;\mathcal{L}_{\text{base}}\;+\;\lambda\,\mathcal{L}_{\text{mono}}. (3)
B57: where ℒ base \mathcal{L}_{\text{base}} denotes the original task loss (e.g., reconstruction error, sparsity penalties, cross entropy), and λ \lambda controls the strength of the monosemanticity pressure. For reporting and ablations, we compute full-dataset MonoScores using the linear algorithm and use the pairwise implementation as a reference to verify equivalence and measure speedup.

B94: 4.2 Finetuning vision models with MonoLoss
B95: We assess the impact of MonoLoss as an auxiliary regularizer during fine-tuning by examining both task performance and representation quality. We conduct experiments on image classification with two settings: (i) a baseline with no MonoLoss regularization (only Cross Entropy loss) and (ii) our finetuning setup with MonoLoss as a regularizer.
B96: Experimental setup. We utilized the pretrained ResNet50 ( He et al., 2016 ) and CLIP-ViT-B/32 ( Radford et al., 2021 ) and finetuning on CIFAR-10 and CIFAR-100 ( Krizhevsky et al., 2009 ) . During experiments, we found out that directly using MonoLoss to finetune enforces the model to overfit on the fixed subset of images to keep the MonoScore high. It could be because the last layer of the models is not originally trained for monosemantic pattern. To address the problem, we simply add an additional linear layer before the classification head and use the output embeddings from that layer as activations. The objective function for finetuning is ℒ \mathcal{L} = CrossEntropy + λ ​ ℒ mono \lambda\,\mathcal{L}_{\text{mono}} with λ \lambda is a regularizer coefficient. More details are provided in the Supplementary Material E .

B186: Appendix B SAE training details
B187: We build on publicly available PyTorch implementations of the SAEs we study, and add a common data pipeline, MonoLoss, and unified training and evaluation code. For TopK SAE and BatchTopK SAE, we use the reference implementations released by the original authors ( Makhzani and Frey, 2014 ; Bussmann et al., 2024 ) . For the remaining SAE variants (Vanilla ReLU SAE and JumpReLU SAE), we use implementations from ( Bussmann et al., 2024 ) . In all cases, we keep the architectural definitions from these repositories unchanged, and standardize only the optimization hyperparameters and the way MonoLoss is integrated.
B188: We train all models on pre-extracted feature embeddings from frozen vision encoders, following ( Nasiri-Sarvi et al., 2025 ) . Specifically, we use CLIP ViT-L/14 ( Radford et al., 2021 ) , SigLIP2 ( Tschannen et al., 2025 ) , and a supervised ViT-L/16 ( Dosovitskiy et al., 2021 ) . We train on OpenImagesV7 ( Kuznetsova et al., 2020 ) using its standard train/validation/test splits, and on ImageNet-1K ( Russakovsky et al., 2015 ) using the training split (1.28M images) for training and the validation split (50K images) for evaluation. For each dataset split, we pre-compute image features once, store them in LMDB, and normalize every feature vector to unit ℓ 2 \ell_{2} norm prior to training. During training, features are loaded via a dataset wrapper that streams examples from disk and re-normalizes them to unit norm on the fly.
B189: Architectures.
B190: On top of each frozen encoder, we train four SAE architectures with a dictionary size of d = 8192 d=8192 latents:
B191: •
B192: TopK SAE ( Makhzani and Frey, 2014 ) : a linear encoder–decoder with a TopK activation that keeps exactly k = 64 k=64 non-zero latents per example. We use tied weights by default (decoder is the transpose of the encoder) and optionally apply layer normalization on the input and output. For the MonoLoss runs in Figure 4 , we set the MonoLoss coefficient on OpenImagesV7 to λ = 0.5 \lambda=0.5 for CLIP-image features, λ = 0.3 \lambda=0.3 for SigLIP2-image features, and λ = 0.9 \lambda=0.9 for the supervised ViT encoder. On ImageNet-1K, we use λ = 0.09 \lambda=0.09 (CLIP), λ = 0.14 \lambda=0.14 (SigLIP2), and λ = 0.09 \lambda=0.09 (ViT).
B193: •
B194: BatchTopK SAE ( Bussmann et al., 2024 ) : a variant where sparsity is enforced at the batch level rather than per example. We compute ReLU activations and then retain the top k = 64 k=64 activations per batch (globally across all samples). For the MonoLoss configurations on OpenImagesV7, we use λ = 5 × 10 − 4 \lambda=5\times 10^{-4} for CLIP-image features, λ = 2 × 10 − 4 \lambda=2\times 10^{-4} for SigLIP2-image features, and λ = 7 × 10 − 4 \lambda=7\times 10^{-4} for the supervised ViT encoder. On ImageNet-1K, we use λ = 3 × 10 − 4 \lambda=3\times 10^{-4} (CLIP), λ = 10 − 4 \lambda=10^{-4} (SigLIP2), and λ = 4 × 10 − 4 \lambda=4\times 10^{-4} (ViT).
B195: •
B196: Vanilla ReLU SAE : a standard sparse autoencoder with ReLU activations and an ℓ 1 \ell_{1} sparsity penalty on the latent codes. We fix the ℓ 1 \ell_{1} coefficient to 10 − 4 10^{-4} in all experiments. For MonoLoss runs on OpenImagesV7, we use λ = 10 − 4 \lambda=10^{-4} on CLIP-image features, λ = 3 × 10 − 5 \lambda=3\times 10^{-5} on SigLIP2-image features, and λ = 10 − 4 \lambda=10^{-4} on the supervised ViT encoder. On ImageNet-1K, we use λ = 10 − 4 \lambda=10^{-4} (CLIP), λ = 3 × 10 − 5 \lambda=3\times 10^{-5} (SigLIP2), and λ = 9 × 10 − 5 \lambda=9\times 10^{-5} (ViT).
B197: •
B198: JumpReLU SAE ( Rajamanoharan et al., 2024 ) : we use the JumpReLU variant from ( Bussmann et al., 2024 ) , with learnable per-feature log-thresholds ℓ k \ell_{k} defining positive thresholds τ k = exp ⁡ ( ℓ k ) \tau_{k}=\exp(\ell_{k}) and a JumpReLU activation applied to ReLU pre-activations. In all SAE experiments, we use d = 8192 d=8192 latents, a JumpReLU bandwidth of b = 10 − 3 b=10^{-3} , and a sparsity loss coefficient of 10 − 3 10^{-3} on the JumpReLU activations. For the MonoLoss experiments on OpenImagesV7, we set λ = 5 × 10 − 4 \lambda=5\times 10^{-4} for CLIP-image features, λ = 10 − 4 \lambda=10^{-4} for SigLIP2-image features, and λ = 5 × 10 − 4 \lambda=5\times 10^{-4} for the supervised ViT encoder. On ImageNet-1K, we use λ = 5 × 10 − 4 \lambda=5\times 10^{-4} (CLIP), λ = 10 − 4 \lambda=10^{-4} (SigLIP2), and λ = 7 × 10 − 4 \lambda=7\times 10^{-4} (ViT).
B199: All SAEs share the same linear encoder and decoder parameterization (plus biases), and all operate directly in the frozen-encoder feature space. The decoder columns are constrained to have unit ℓ 2 \ell_{2} norm by explicit renormalization after each gradient step; for untied decoders, we also project the gradient to be orthogonal to the current dictionary vectors to avoid shrinking their norms.
B200: Optimization.
B201: We train each SAE for 50 epochs with a batch size of 2048 and dictionary size d = 8192 d=8192 . We use the Adam optimizer ( Kingma and Ba, 2015 ) with a learning rate of 1 × 10 − 4 1\times 10^{-4} and ϵ = 6.25 × 10 − 10 \epsilon=6.25\times 10^{-10} ; all other Adam hyperparameters are left at their PyTorch defaults. We apply gradient clipping with a maximum global norm of 1.0 1.0 before the optimizer step, and we do not use any learning-rate schedule or weight decay. For the BatchTopK, Vanilla, and JumpReLU SAEs, we follow the public ( Bussmann et al., 2024 ) implementation for weight initialization and other training details, and for the TopK SAE, we follow the reference implementation from ( Makhzani and Frey, 2014 ) . For all experiments, we fix the random seed to 42 and train on a single GPU.
B202: For TopK SAEs, we additionally track, for each latent dimension, the number of optimization steps since it last fired on any sample in the current batch. When this counter exceeds a preset threshold (specified in training examples), we reinitialize that latent using the dead-neuron handling strategy from ( Makhzani and Frey, 2014 ) , and reset its inactivity counter. This prevents permanently dead features and keeps the effective dictionary size closer to d d .
B203: Evaluation metrics.
B204: Reconstruction quality is measured using the coefficient of determination R 2 R^{2} on held-out data. Given ground-truth features x x and reconstructions x ^ \hat{x} , we compute per-dimension R 2 R^{2} using streaming estimates of means and variances and report the mean R 2 R^{2} across all feature dimensions. For monosemanticity, we report the mean MonoScore over all latents on the test split (OpenImagesV7) or validation split (ImageNet-1K), together with MonoScore curves where latents are sorted by decreasing MonoScore and the index is normalized to [ 0 , 1 ] [0,1] . All reconstruction and monosemanticity results in Section 4.1 are obtained from the same checkpoints and training procedure described above, differing only in the choice of architecture, dataset, and MonoLoss coefficient λ \lambda .
