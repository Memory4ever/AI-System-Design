B44: 3 Method
B45: As illustrated in Figure 2 , R-Diverse introduces two complementary mechanisms: (1) MAP, which leverages a memory bank to enforce cross-iteration exploration by penalizing similarity to previously generated questions; and (2) SAM, which promotes skill-aware diversity by shifting comparison from surface question forms to underlying reasoning skills.
B46: Figure 2 : The R-Diverse framework. Top (Challenger training) : the Challenger proposes questions { q i } \{q_{i}\} to maximize the uncertainty reward R uncertainty R_{\text{uncertainty}} . For each q i q_{i} , the Solver produces multiple solutions { a i , 1 , a i , 2 , … , a i , m } \{a_{i,1},a_{i,2},\ldots,a_{i,m}\} and a pseudo-label y ^ i \hat{y}_{i} via majority voting. SAM maps q i q_{i} to canonical solver code c i c_{i} (via Qwen2.5-Coder-7B) and a semantic embedding e i e_{i} , which are used to compute both the within-iteration repetition penalty P rep P_{\text{rep}} and the memory-augmented penalty P MAP P_{\text{MAP}} . Middle (Memory update) : the memory bank ℳ \mathcal{M} stores historical tuples ( q i , e i , y ^ i ) (q_{i},e_{i},\hat{y}_{i}) across iterations. Bottom (Solver training) : to mitigate distribution shift, the Solver is trained on current questions augmented with samples recalled from ℳ \mathcal{M} , using a matching reward R match R_{\text{match}} .
B47: 3.1 Memory-Augmented Penalty
B48: MAP addresses the Local Diversity Illusion by equipping the Challenger with a persistent memory bank ℳ \mathcal{M} , expanding its visibility from the local batch to the entire evolutionary history.
B49: 3.1.1 Global Memory Bank Construction
B50: We maintain a memory bank ℳ \mathcal{M} containing the embedding vectors of all valid questions generated in previous iterations. Let ϕ ⁡ ( q ) \phi(q) be a semantic embedding function. While we formally instantiate ϕ \phi using our SAM in Section 3.2, we first describe how MAP utilizes this representation to enforce global diversity. Let 𝒬 t \mathcal{Q}_{t} denote the set of questions generated by the Challenger at iteration t t . At the end of iteration t t , we update the memory:
B51: ℳ t + 1 ← ℳ t ∪ { ϕ ( q ) ∣ q ∈ 𝒬 t , valid ( q ) } , \mathcal{M}_{t+1}\leftarrow\mathcal{M}_{t}\cup\{\phi(q)\mid q\in\mathcal{Q}_{t},\text{valid}(q)\}, (6)
B52: where valid ​ ( q ) \text{valid}(q) denotes questions that pass the uncertainty filter (e.g., 0.3 ≤ s ⁡ ( q ) ≤ 0.8 0.3\leq s(q)\leq 0.8 ), ensuring we only store high-quality training data.
B53: 3.1.2 Dual-Perspective Penalty
B54: To effectively penalize the Challenger, we introduce the MAP penalty P MAP ​ ( q , ℳ ) P_{\text{MAP}}(q,\mathcal{M}) , composed of two distinct terms that target specific failure modes:
B55: Max-Similarity Penalty. We first penalize the maximum similarity to any single historical sample to prevent direct repetition:
B56: P max ​ ( q , ℳ ) = max e ∈ ℳ ⁡ cos ⁡ ( ϕ ⁡ ( q ) , e ) . P_{\max}(q,\mathcal{M})=\max_{e\in\mathcal{M}}\cos(\phi(q),e). (7)
B57: This ensures the new question is distinct from every specific past instance. However, P max P_{\max} alone is insufficient: a question can be distinct from any single predecessor yet still fall within a dense region of previously explored topics, failing to expand the semantic frontier.
B58: Mean-Similarity Penalty. To complement P max P_{\max} and drive exploration into sparse region, we penalize the average similarity to the entire memory bank:
B59: P mean ​ ( q , ℳ ) = 1 | ℳ | ​ ∑ e ∈ ℳ cos ⁡ ( ϕ ⁡ ( q ) , e ) . P_{\text{mean}}(q,\mathcal{M})=\frac{1}{|\mathcal{M}|}\sum_{e\in\mathcal{M}}\cos(\phi(q),e). (8)
B60: While P max P_{\max} prevents point-to-point collision, P mean P_{\text{mean}} prevents point-to-region collision. It acts as a global repulsive force that pushes the Challenger away from the “center of gravity” of historical question distributions, encouraging the exploration of novel, under-represented question spaces.
B61: The final P MAP P_{\text{MAP}} is a weighted combination, activated only when similarity exceeds a tolerance threshold τ \tau :
B62: P MAP ​ ( q , ℳ ) = γ ⋅ [ P max ​ ( q , ℳ ) − τ max ] + + ( 1 − γ ) ⋅ [ P mean ( q , ℳ ) − τ mean ] + , \begin{split}P_{\text{MAP}}(q,\mathcal{M})=&\;\gamma\cdot[P_{\max}(q,\mathcal{M})-\tau_{\max}]_{+}\\ &+(1-\gamma)\cdot[P_{\text{mean}}(q,\mathcal{M})-\tau_{\text{mean}}]_{+},\end{split} (9)
B63: where [ ⋅ ] + = max ⁡ ( 0 , ⋅ ) [\cdot]_{+}=\max(0,\cdot) . We set γ = 0.5 \gamma=0.5 to balance pointwise novelty and distributional exploration.
B64: Stabilization via Experience Replay. The effectiveness of MAP in driving global exploration inevitably results in a continuously shifting question distribution. To ensure the Solver robustly masters this expanding curriculum without forgetting learned skills, we incorporate a memory replay mechanism during Solver training. Specifically, at each iteration t t , we augment the current iteration data 𝒟 t \mathcal{D}_{t} by sampling historical high-quality question-answer pairs 𝒟 history \mathcal{D}_{\text{history}} from ℳ t − 1 \mathcal{M}_{t-1} , ensuring these historical samples constitute a target ratio ρ \rho of the final training set. This strategy ensures the Solver maintains competence on diverse problem types even as the Challenger’s distribution evolves.
B65: 3.2 Skill-Aware Measurement
B66: We instantiate SAM via two steps. (i) Representation Abstraction: we map a natural-language question to a canonical solver-level program to capture the underlying solution procedure while filtering out narrative phrasing. (ii) Embedding-based Similarity Computation: we embed the program using off-the-shelf code encoder and compute similarity in embedding space, providing a robust diversity measure that is less sensitive to superficial code edits yet responsive to meaningful procedural differences.
B67: Representation Abstraction. We use Python solver code as a solver-level bottleneck that strips away linguistic variation and retains the core reasoning procedure. Concretely, we prompt a code generation model, Qwen2.5-Coder-7B ( Hui et al., 2024 ) , to translate a natural-language question q q into a canonical function Code ​ ( q ) \text{Code}(q) that reflects the underlying relations rather than narrative details. To encourage canonicalization, we set temperature to 0 and apply two constraints: (1) Procedure Extraction , requiring the code to express the underlying mathematical relations; and (2) Symbolic Anonymization , replacing concrete entities (e.g., “apples”) with generic variables (e.g., x , y x,y ).
B68: As illustrated in Figure 1 (b, c), this mapping sends textually distinct but procedurally similar problems (e.g., “chickens/rabbits” vs. “cars/wheels”) to highly similar code structures. Even when the generated code is imperfect, it typically preserves the dependency structure and operation patterns, serving as a practical proxy for the reasoning skills exercised.
B69: Embedding-based Similarity Computation. Residual surface variation may remain at the code level (e.g., constants or minor syntactic choices), making string-level matching brittle. We therefore encode Code ​ ( q ) \text{Code}(q) into a continuous vector using an off-the-shelf code encoder (Jina-Code-Embeddings-1.5B ( Kryvosheieva et al., 2025 ) ):
B70: ϕ SAM ​ ( q ) = Encoder ​ ( Code ​ ( q ) ) . \phi_{\text{SAM}}(q)=\text{Encoder}(\text{Code}(q)). (10)
B71: We compute similarity by cosine distance in this embedding space, which is less sensitive to superficial code edits yet responsive to meaningful differences in underlying procedures.
B72: Integration. We use ϕ SAM \phi_{\text{SAM}} as the similarity function in both the repetition penalty P rep P_{\text{rep}} and the memory-augmented penalty P MAP P_{\text{MAP}} , so that R-Diverse consistently enforces diversity in terms of the reasoning skills exercised rather than surface variation in questions.

B80: 4.1 Experimental Setup
B81: Implementation. We implement R-Diverse on top of the EasyR1 codebase ( Zheng et al., 2025 ) and use Qwen3-4B-Base and Qwen3-8B-Base ( Yang et al., 2025 ) as base models. Each evolution iteration consists of 5 training steps for the Challenger and 15 training steps for the Solver. We set α = 1.0 \alpha=1.0 , β = 1.0 \beta=1.0 , γ = 0.5 \gamma=0.5 , τ max = 0.5 \tau_{\max}=0.5 , τ mean = 0.25 \tau_{\text{mean}}=0.25 , and use a memory replay ratio ρ = 0.3 \rho=0.3 . Full hyperparameters and prompts are provided in App. A .
B82: Comparison Methods. We compare against representative self-play methods including R-Zero ( Huang et al., 2025 ) , Absolute Zero ( Zhao et al., 2025 ) , SPIRAL ( Liu et al., 2025 ) , and Socratic-Zero ( Wang et al., 2025a ) , as well as the base models. Details are summarized in App. D .
B83: Evaluation. We evaluate on seven mathematical and three general reasoning benchmarks (App. E ). We report pass@1 accuracy with greedy decoding for all benchmarks except AMC and AIME, where we use mean@32 following prior work ( Huang et al., 2025 ) .

B108: To dismantle the identified illusions, R-Diverse relies on both MAP and SAM. We conduct a fine-grained ablation on Qwen3-4B-Base (Table 2 ).
B109: Ablation on MAP. Removing MAP causes the largest drop ( 52.59 → 49.62 52.59\rightarrow 49.62 ), confirming that global, memory-based repulsion is critical for dispelling the Local Diversity Illusion . Within MAP, max- and mean-similarity terms contribute comparably (each Δ ≈ − 2.0 \Delta\approx-2.0 ), while dropping both is worse ( Δ = − 2.71 \Delta=-2.71 ), suggesting they prevent two complementary failures: direct history recycling ( P max P_{\max} ) and drifting back into dense, previously explored regions ( P mean P_{\text{mean}} ). Finally, replay matters when MAP actively shifts the data distribution: without replay, performance drops by 1.41 points, suggesting increased forgetting.
B110: Ablation on SAM. Disabling SAM degrades performance ( Δ = − 2.09 \Delta=-2.09 ), indicating that combating the Surface Diversity Illusion requires going beyond surface overlap. B128: R-Diverse demonstrates sustained, monotonic improvement over five evolution iterations across both model scales and both metrics. On Qwen3-4B, it steadily improves to 52.6 Math AVG and 36.7 Overall AVG, while R-Zero collapses after iteration 3 (49.1 → \rightarrow 42.9 by iteration 5). The same trend holds on Qwen3-8B: R-Diverse continues to improve to 56.5 Math AVG and 40.8 Overall AVG, whereas R-Zero peaks early and then degrades (down to 53.1 Math AVG / 39.2 Overall AVG at iteration 5). These results suggest that R-Diverse provides a more reliable self-play recipe that scales across model sizes.
B129: We attribute this robustness to the synergy between MAP and SAM: MAP counters the Local Diversity Illusion by penalizing historical recycling, while SAM counters the Surface Diversity Illusion by identifying skill-level repetition beyond superficial variation. Gains on Overall AVG are smaller than on Math AVG, likely because the self-play curriculum is generated in the mathematical domain.
B130: 5.3 Diversity Analysis
B131: R-Diverse reduces Local and Surface Diversity Illusions.
B132: To rigorously verify the effectiveness of R-Diverse in mitigating the Diversity Illusion, we conduct a multi-dimensional analysis focusing on three perspectives: Cross-Iteration , Intra-Iteration , and Policy Dynamics , where five distinct metrics are employed in total to capture the full dynamics of the evolutionary process.
B133: Metrics. For Cross-Iteration , we quantify historical recycling using (1) Cross-Iteration Repetition , computed from the max- and mean-cosine similarity between SAM embeddings of new questions and the memory bank, and (2) LLM Judge Repetition Ratio , where GPT-4o judges whether a new question is semantically equivalent to its top-3 nearest historical neighbors. For Intra-Iteration , we quantify within-iteration collapse using (3) Intra-Iteration Repetition (average pairwise cosine similarity of SAM embeddings) and (4) Distribution Spread (average distance to the embedding centroid). For Policy Dynamics , we report (5) Challenger Entropy over 200 rollouts. Formal definitions are in App. C .

(a-b) Cross-Iteration Repetition : R-Zero exhibits increasing historical recycling (confirmed by both SAM embedding similarity and the LLM judge), while R-Diverse reduces it. (c-d) Intra-Iteration Diversity : R-Diverse maintains lower repetition and higher distribution spread. (e) Policy Dynamics : R-Diverse recovers Challenger entropy, avoiding the low-entropy collapse observed in R-Zero. ( ↑ \uparrow : higher is better; ↓ \downarrow : lower is better.)
B135: Stable Diversity. Figure 4 presents the iteration trajectories of these metrics. Regarding Cross-Iteration (Figure 4 a, b), R-Zero exhibits increasing historical recycling, with the LLM-judge duplicate ratio rising from 71% to 84%. Regarding Intra-Iteration (Figure 4 c, d), R-Diverse maintains lower repetition and higher spread, indicating that SAM better captures skill-level diversity beyond superficial variation, mitigating the Surface Diversity Illusion . Finally, the Policy Dynamics (Figure 4 e) show that R-Diverse recovers Challenger entropy (0.64 → \rightarrow 0.94), while R-Zero remains low-entropy, suggesting that R-Diverse encourages sustained exploration rather than premature exploitation.

B267: Appendix B Computational Efficiency
B268: This section presents the computational overhead introduced by SAM. Despite the additional code generation and embedding computation, R-Diverse does not introduce significant overhead compared to R-Zero. In fact, replacing BLEU-based clustering (a CPU-intensive O ⁡ ( n 2 ) O(n^{2}) process) with code embedding similarity slightly reduces computation time. We further optimize the original R-Zero Challenger training pipeline through time-multiplexing. These optimizations enable R-Diverse to complete one evolution iteration in approximately 6 hours on Qwen3-4B-Base, reducing training time by 20% compared to R-Zero (7.5 hours).
B269: Appendix C Metric Definitions
B270: This section provides the formal mathematical definitions for the diversity metrics used in Section 4.3.
B271: Cross-Iteration Repetition. This metric measures how much a new set of questions overlaps with historically generated questions stored in the memory bank ℳ \mathcal{M} . For a set of questions 𝒬 t \mathcal{Q}_{t} generated at iteration t t , we compute:
B272: Cross-Iter-Rep ( 𝒬 t , ℳ ) = 1 | 𝒬 t | ∑ q ∈ 𝒬 t ( 1 2 max e ∈ ℳ cos ( ϕ ( q ) , e ) + 1 2 ⋅ 1 | ℳ | ∑ e ∈ ℳ cos ( ϕ ( q ) , e ) ) . \text{Cross-Iter-Rep}(\mathcal{Q}_{t},\mathcal{M})=\frac{1}{|\mathcal{Q}_{t}|}\sum_{q\in\mathcal{Q}_{t}}\left(\frac{1}{2}\max_{e\in\mathcal{M}}\cos(\phi(q),e)+\frac{1}{2}\cdot\frac{1}{|\mathcal{M}|}\sum_{e\in\mathcal{M}}\cos(\phi(q),e)\right). (12)
B273: This combines both max-cosine similarity (detecting direct repetition) and mean-cosine similarity (detecting distributional overlap).
B274: Intra-Iteration Repetition. This metric measures the internal homogeneity within a single iteration of generated questions. For a set 𝒬 t \mathcal{Q}_{t} , we compute the average pairwise cosine similarity:
B275: Intra-Iter-Rep ​ ( 𝒬 t ) = 1 | 𝒬 t | ​ ∑ q i ∈ 𝒬 t 1 | 𝒬 t | − 1 ​ ∑ q j ∈ 𝒬 t , j ≠ i cos ⁡ ( ϕ ⁡ ( q i ) , ϕ ⁡ ( q j ) ) . \text{Intra-Iter-Rep}(\mathcal{Q}_{t})=\frac{1}{|\mathcal{Q}_{t}|}\sum_{q_{i}\in\mathcal{Q}_{t}}\frac{1}{|\mathcal{Q}_{t}|-1}\sum_{q_{j}\in\mathcal{Q}_{t},j\neq i}\cos(\phi(q_{i}),\phi(q_{j})). (13)
B276: LLM Judge Repetition Ratio. To provide another view of cross-iteration repetition, we employ GPT-4o as an independent judge. For each question q q in the current iteration, we retrieve its top-3 nearest neighbors from the memory bank based on cosine similarity. The judge determines whether q q is semantically equivalent to any of these neighbors. The repetition ratio is the fraction of questions judged as duplicates:
B277: LLM-Rep-Ratio ( 𝒬 t ) = 1 | 𝒬 t | ∑ q ∈ 𝒬 t 𝕀 [ Judge ( q , Top3 ( q , ℳ ) ) = DUPLICATE ] . \text{LLM-Rep-Ratio}(\mathcal{Q}_{t})=\frac{1}{|\mathcal{Q}_{t}|}\sum_{q\in\mathcal{Q}_{t}}\mathbb{I}[\text{Judge}(q,\text{Top3}(q,\mathcal{M}))=\text{DUPLICATE}]. (14)
B278: The prompt template used for the LLM judge is provided in the ”LLM Judge Repetition Ratio Prompt Template” shown above.
B279: Distribution Spread. To provide another view of intra-iteration repetition, this metric quantifies how dispersed the generated questions are in the semantic embedding space. We compute the centroid of all embeddings and measure the average distance from each question to this centroid:
B280: Spread-Degree ​ ( 𝒬 t ) = 1 | 𝒬 t | ​ ∑ q ∈ 𝒬 t ‖ ϕ ⁡ ( q ) − ϕ ¯ ‖ 2 , where ​ ϕ ¯ = 1 | 𝒬 t | ​ ∑ q ∈ 𝒬 t ϕ ⁡ ( q ) . \text{Spread-Degree}(\mathcal{Q}_{t})=\frac{1}{|\mathcal{Q}_{t}|}\sum_{q\in\mathcal{Q}_{t}}\left\|\phi(q)-\bar{\phi}\right\|_{2},\quad\text{where }\bar{\phi}=\frac{1}{|\mathcal{Q}_{t}|}\sum_{q\in\mathcal{Q}_{t}}\phi(q). (15)
B281: A higher spread indicates greater diversity in the generated question distribution.
B282: Challenger Entropy. This metric probes the exploratory nature of the Challenger’s generation policy by measuring the token-level entropy averaged over multiple rollouts. For N N rollouts, each producing a sequence of tokens { t 1 , t 2 , … , t L } \{t_{1},t_{2},\ldots,t_{L}\} :
B283: Entropy = 1 N ∑ n = 1 N 1 L n ∑ l = 1 L n H ( p ( ⋅ | t < l ) ) , \text{Entropy}=\frac{1}{N}\sum_{n=1}^{N}\frac{1}{L_{n}}\sum_{l=1}^{L_{n}}H(p(\cdot|t_{<l})), (16)
B284: where H ( p ( ⋅ | t < l ) ) = − ∑ v ∈ 𝒱 p ( v | t < l ) log p ( v | t < l ) H(p(\cdot|t_{<l}))=-\sum_{v\in\mathcal{V}}p(v|t_{<l})\log p(v|t_{<l}) is the entropy of the next-token distribution conditioned on the preceding context t < l t_{<l} , and 𝒱 \mathcal{V} denotes the vocabulary. Higher entropy indicates a more exploratory policy.
