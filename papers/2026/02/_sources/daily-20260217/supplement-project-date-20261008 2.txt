L212: # [ICML 2026] ToolShield: A Package to Guard Your Agent
L213: 
L214: Accepted to the ICML 2026 main conference  ·  🏆 additionally selected as a Spotlight at the AI4GOOD Workshop @ ICML 2026
L215: 
L216: Supports:
L217: 
L218: * * *
L219: 
L220: cite97†Quickstart | cite98†Pre-Generated Safety Experiences | cite99†Generate Your Own Safety Experiences |
L221: cite100†Extend to New Tools | cite101†Safety Benchmark | cite102†Citation L222: ToolShield is a training-free, tool-agnostic defense for AI agents that use MCP tools. Just `pip install toolshield` and a single command guards your coding agent with safety experiences — no API keys, no sandbox setup, no fine-tuning. Reduces attack success rate by 30% on average.
L223: ## Quickstart
L224: 
L225:     pip install toolshield
L226: ### Use Pre-generated Experiences
L227: 
L228: We ship safety experiences for 6 models across 5 tools, with plug-and-play support for 5 coding agents:
L229: Inject them in one command — no need to know where files are installed:
L230: 
L231:     # For Claude Code (filesystem example)
L232:     toolshield import --exp-file filesystem-mcp.json --agent claude_code
L233: 
L234:     # For Codex (postgres example)
L235:     toolshield import --exp-file postgres-mcp.json --agent codex
L236: 
L237:     # For OpenClaw (terminal example)
L238:     toolshield import --exp-file terminal-mcp.json --agent openclaw
L239: 
L240:     # For Cursor (playwright example)
L241:     toolshield import --exp-file playwright-mcp.json --agent cursor
L242: 
L243:     # For OpenHands (notion example)
L244:     toolshield import --exp-file notion-mcp.json --agent openhands
L245: Use experiences from a different model with `--model`:
L246: 
L247:     toolshield import --exp-file filesystem-mcp.json --model gpt-5.2 --agent claude_code
L248: 
L249: Or import all bundled experiences (all 5 tools) in one shot:
L250: 
L251:     toolshield import --all --agent claude_code
L252: You can also import multiple experience files individually:
L253: 
L254:     toolshield import --exp-file filesystem-mcp.json --agent claude_code
L255:     toolshield import --exp-file terminal-mcp.json --agent claude_code
L256:     toolshield import --exp-file postgres-mcp.json --agent claude_code
L257: 
L258: See all available bundled experiences:
L259: 
L260:     toolshield list
L261: This appends safety guidelines to your agent's context file (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.openclaw/workspace/AGENTS.md`, Cursor's global user rules, or `~/.openhands/microagents/toolshield.md`). To remove them:
L262: 
L263:     toolshield unload --agent claude_code
L264: 
L265: Available bundled experiences (run `toolshield list` to see all):
L266: Model  |  |  |  |  |
L267: --- | --- | --- | --- | --- | ---

L276: ### Generate Your Own Safety Experiences
L277: 
L278: Point ToolShield at any running MCP server to generate custom safety experiences:
L279: 
L280:     export TOOLSHIELD_MODEL_NAME="anthropic/claude-sonnet-4.5"
L281:     export OPENROUTER_API_KEY="your-key"
L282: 
L283:     # Full pipeline: inspect → generate safety tree → test → distill → inject
L284:     toolshield \
L285:       --mcp_name postgres \
L286:       --mcp_server http://localhost:9091 \
L287:       --output_path output/postgres \
L288:       --agent codex
L289: Or generate without injecting (useful for review):
L290: 
L291:     toolshield generate \
L292:       --mcp_name postgres \
L293:       --mcp_server http://localhost:9091 \
L294:       --output_path output/postgres
L295: ### Auto-discover Local MCP Servers
L296: 
L297: Automatically scan localhost for running MCP servers, run the full pipeline for each, and inject the results:
L298: 
L299:     toolshield auto --agent codex
L300: 
L301: This scans ports 8000-10000 by default (configurable with `--start-port` / `--end-port`).
L302: ### Extend to New Tools
L303: 
L304: ToolShield works with any MCP server that has an SSE endpoint:
L305: 
L306:     toolshield generate \
L307:       --mcp_name your_custom_tool \
L308:       --mcp_server http://localhost:PORT \
L309:       --output_path output/your_custom_tool
L310: ## MT-AgentRisk Benchmark
L311: 
L312: We also release MT-AgentRisk, a benchmark of 365 harmful tasks across 5 MCP tools, transformed into multi-turn attack sequences. See cite105†`agentrisk/README.md` for full evaluation setup.
L313: Quick evaluation:
L314: 
L315:     # 1. Download benchmark tasks
L316:     git clone https://huggingface.co/datasets/CHATS-Lab/MT-AgentRisk
L317:     cp -r MT-AgentRisk/workspaces/* workspaces/
L318: 
L319:     # 2. Run a single task (requires OpenHands setup — see agentrisk/README.md)
L320:     python agentrisk/run_eval.py \
L321:       --task-path workspaces/terminal/multi_turn_tasks/multi-turn_root-remove \
L322:       --agent-llm-config agent \
L323:       --env-llm-config env \
L324:       --outputs-path output/eval \
L325:       --server-hostname localhost
L326: Add `--use-experience <path>` to evaluate with ToolShield defense.

L198: # CUDABench
L199: 
L200: CUDABench is a comprehensive benchmark designed to evaluate the text-to-CUDA capabilities of LLMs. It provides a complete pipeline from dataset management to CUDA code generation and automated performance evaluation on NVIDIA GPUs.
L201: ## 📁 Directory Structure
L202: 
L203:     `CUDABench/
L204:     ├── Datasets/           # Contains benchmark tasks (prompts, reference code)
L205:     │   └── CUDABench-Set.jsonl
L206:     ├── Generate/           # LLM inference engine
L207:     │   ├── main.py
L208:     │   ├── config.py
L209:     │   └── ...
L210:     ├── Evaluate/           # Evaluation engine (Compilation & Profiling)
L211:     │   ├── manager.py
L212:     │   └── ...
L213:     └── Results/            # Output directory for generated code
L214:         └── <api_provider>/
L215: 
L216:     `
L217: 
L218: * * *
L219: ## 🛠 Prerequisites
L220: 
L221: Before running the benchmark, ensure you have the following installed:
L222: 
L223:   * CUDA Toolkit (`nvcc`): Required for compiling generated kernels.
L224:   * NVIDIA Nsight Compute (`ncu`): Required for profiling performance metrics.
L225: 
L226: * * *
L227: 
L228: ## 🚀 Usage Workflow
L229: ### 1. Dataset: CUDABench-Set
L230: 
L231: The benchmark is driven by `Datasets/CUDABench-Set.jsonl`. Each line in this file is a JSON object representing a unique CUDA task.
L232: 
L233: Key Fields per Task:
L234: 
L235:   * Metadata:
L236: 
L237:     * `id`, `task_name`: Unique identifiers for the problem.
L238:     * `inputs` / `outputs`: Definitions of tensor shapes and data types.
L239:   * Prompts (Difficulty Levels):
L240:     * `level1_prompt`: Guided Implementation, providing the task name, a detailed algorithm description, and explicit CUDA implementation guidelines (e.g., memory hierarchy usage and thread-mapping strategies).
L241:     * `level2_prompt`: Algorithmic Specification, including the task name and algorithm description, but omits all hardware-specific guidance.
L242:     * `level3_prompt`: Concept Retrieval, supplying only the task name..
L243:   * Evaluation Components:
L244:     * `bench.cu`: The reference CUDA C++ implementation.
L245:     * `gen.py`: Python script used to generate random binary input data and reference output data for testing.
L246:     * `compare.py`: Python script used to validate the correctness of the generated kernel against the reference.
L247: Example Entry (Simplified):
L248: 
L249:     {
L250:       "id": 16,
L251:       "task_name": "ReLU_Activation_Fuction",
L252:       "inputs": [{"name": "relu_input", "dtype": "float32", "shape": "(1048576,)"}],
L253:       "level1_prompt": "...",
L254:       "level2_prompt": "...",
L255:       "level3_prompt": "...",
L256:       "bench.cu": "#include <cuda_runtime.h> ...",
L257:       "gen.py": "import numpy as np ...",
L258:       "compare.py": "def compare_outputs(...) ..."
L259:     }
L260: ### 2. Generate
L261: 
L262: Use the `Generate` module to query LLMs (DeepSeek, OpenAI, etc.) and generate CUDA kernels.
L263: 
L264: Basic Command:
L265: 
L266:     python Generate/main.py
L267: 
L268: With Arguments (Example):
L269: 
L270:     python Generate/main.py --api_option deepseek --model_name deepseek-reasoner --samples 3
L271: 
L272:   * Configuration: You can modify defaults in `Generate/config.py` or pass arguments via CLI.
L273:   * Output: Generated code is saved to `Results/<api>/<model>_<level>_pass<k>.jsonl`.
L274: ### 3. Evaluate
L275: 
L276: Use the `Evaluate` module to compile, run, and profile the generated code against the reference implementation.
L277: 
L278: Command:
L279: 
L280:     python Evaluate/manager.py full <path_to_results_file>
