B112: 4 Personalized Prompt Optimization (PPOpt)
B113: Based on the large-scale synthetic dataset PersonaAtlas powered by PersonaGym , we present Personalized Prompt Optimization (PPOpt), a unified framework that learns a personalized prompt optimizer from user-specific interaction history. Given a user u u characterized by a synthetic persona p u p_{u} , historical trajectories ℋ u \mathcal{H}_{u} , and a new session’s initial query q ~ u init \tilde{q}^{\mathrm{init}}_{u} , PPOpt outputs an optimized prompt q ^ u init \hat{q}^{\mathrm{init}}_{u} so that a fixed base LLM produces responses that better satisfy the user’s personalization preferences.
B114: Problem setup.
B115: For each user u u , we assume access to multiple historical sessions (each potentially multi-turn):
B116: ℋ u = { 𝒯 u ( j ) } j = 1 J u , 𝒯 u ( j ) = { ( q ~ t ( j ) , a t ( j ) , f t ( j ) ) } t = 1 T j , \mathcal{H}_{u}=\Big\{\mathcal{T}_{u}^{(j)}\Big\}_{j=1}^{J_{u}},\qquad\mathcal{T}_{u}^{(j)}=\Big\{(\tilde{q}^{(j)}_{t},a^{(j)}_{t},f^{(j)}_{t})\Big\}_{t=1}^{T_{j}}, (9)
B117: where q ~ t ( j ) \tilde{q}^{(j)}_{t} denotes the user message, a t ( j ) a^{(j)}_{t} the assistant response from the base assistant model M asst M_{\mathrm{asst}} , and f t ( j ) f^{(j)}_{t} the user feedback.
B118: In addition, we observe the initial query q ~ u init \tilde{q}^{\mathrm{init}}_{u} of a new session. The prompt optimizer receives the same input format during training and evaluation , i.e., the initial query q ~ u init \tilde{q}^{\mathrm{init}}_{u} with the historical trajectories ℋ u \mathcal{H}_{u} :
B119: s u = ( q ~ u init , ℋ u ) . s_{u}\;=\;\big(\tilde{q}^{\mathrm{init}}_{u},\;\mathcal{H}_{u}\big). (10)
B120: 4.1 Reason-Then-Optimize Paradigm
B121: Directly mapping an interaction history to a rewritten prompt often encourages shortcut learning. To avoid this, we therefore design a reason-then-optimize paradigm: the optimizer first infers a natural-language user profile description,and then generates an improved prompt conditioned on it.
B122: Formally, the optimizer is a conditional policy π θ \pi_{\theta} producing:
B123: ( z ^ u , q ^ u init ) ∼ π θ ( ⋅ ∣ s u ) , (\hat{z}_{u},\;\hat{q}^{\mathrm{init}}_{u})\sim\pi_{\theta}(\cdot\mid s_{u}), (11)
B124: where z ^ u \hat{z}_{u} includes inferred user preferences/constraints/style based on ℋ u \mathcal{H}_{u} . We implement this with an autoregressive factorization:
B125: π θ ​ ( z ^ u , q ^ u init ∣ s u ) = π θ ​ ( z ^ u ∣ s u ) ⋅ π θ ​ ( q ^ u init ∣ s u , z ^ u ) , \pi_{\theta}(\hat{z}_{u},\hat{q}^{\mathrm{init}}_{u}\mid s_{u})=\pi_{\theta}(\hat{z}_{u}\mid s_{u})\cdot\pi_{\theta}(\hat{q}^{\mathrm{init}}_{u}\mid s_{u},\hat{z}_{u}), (12)
B126: realized by a single sequence model with explicit delimiters:
B127: <REASONING> ​ z ^ u ​ </REASONING> ​ <PROMPT> ​ q ^ u init ​ </PROMPT> . \texttt{<REASONING>}\penalty\ \hat{z}_{u}\penalty\ \texttt{</REASONING>}\penalty\ \texttt{<PROMPT>}\penalty\ \hat{q}^{\mathrm{init}}_{u}\penalty\ \texttt{</PROMPT>}.
B128: 4.2 Cold-Start Supervised Fine-Tuning (SFT)
B129: We use supervised fine-tuning (SFT) only as a cold-start to (i) enforce the reasoning-then-optimization output format and (ii) teach the optimizer to condition on ( q ~ u init , ℋ u ) (\tilde{q}^{\mathrm{init}}_{u},\mathcal{H}_{u}) to produce a plausible profile description followed by a rewritten prompt. Importantly, we do not assume access to ground-truth “optimal” prompts; correctness and optimality are instead learned in the subsequent outcome-driven RL stage.
B130: Pseudo targets via strong teacher synthesis.
B131: Let 𝒟 train \mathcal{D}_{\mathrm{train}} denote the synthetic dataset. Each training sample contains a state s u = ( q ~ u init , ℋ u ) s_{u}=(\tilde{q}^{\mathrm{init}}_{u},\mathcal{H}_{u}) and the synthetic persona p u p_{u} (or its observed subset), where p u p_{u} is available only during training. We use a powerful teacher model, i.e., a LLM (we use GPT-5.2 for the implementation), to synthesize format-consistent targets:
B132: z u ⋆ ∼ 𝒯 prof ( ⋅ ∣ p u , ℋ u ) , q u ⋆ ∼ 𝒯 prompt ( ⋅ ∣ q ~ u init , ℋ u , z u ⋆ ) , z^{\star}_{u}\sim\mathcal{T}_{\mathrm{prof}}(\cdot\mid p_{u},\mathcal{H}_{u}),\qquad q^{\star}_{u}\sim\mathcal{T}_{\mathrm{prompt}}(\cdot\mid\tilde{q}^{\mathrm{init}}_{u},\mathcal{H}_{u},z^{\star}_{u}), (13)
B133: where 𝒯 prof \mathcal{T}_{\mathrm{prof}} produces a natural-language profile summary and 𝒯 prompt \mathcal{T}_{\mathrm{prompt}} produces a rewritten initial prompt. These pseudo labels serve as scaffolding to bootstrap generation structure; they are not treated as ground-truth optimal solutions. We show the synthesized case data in Appendix D . To reduce the noise within pseudo targets, we introduce a filtering mechanism, which is detailed in Appendix C .
B134: 4.3 Outcome-Driven Multi-Objective RL
B135: After SFT, we optimize π θ \pi_{\theta} with RL using downstream outcomes . Given ( z ^ u , q ^ u init ) (\hat{z}_{u},\hat{q}^{\mathrm{init}}_{u}) , we obtain the response from the Assistant agent under the improved prompt:
B136: a ^ u init = M asst ​ ( q ^ u init , ℋ u ) , \hat{a}^{\mathrm{init}}_{u}=M_{\mathrm{asst}}(\hat{q}^{\mathrm{init}}_{u};\mathcal{H}_{u}), (14)
B137: and a baseline response under the original prompt:
B138: a u base = M asst ​ ( q ~ u init , ℋ u ) . a^{\mathrm{base}}_{u}=M_{\mathrm{asst}}(\tilde{q}^{\mathrm{init}}_{u};\mathcal{H}_{u}). (15)
B139: (For a single-turn evaluation, M asst ​ ( ⋅ , ℋ u ) M_{\mathrm{asst}}(\cdot;\mathcal{H}_{u}) indicates that the historical context may be provided as additional conditioning text, but the optimized prompt is only the new session’s first query.)
B140: Multi-objective reward.
B141: We combine two rewards: (1) profile inference quality and (2) task outcome improvement:
B142: R u ​ ( θ ) = λ prof ​ r prof ​ ( u ) + λ task ​ r task ​ ( u ) , λ prof , λ task ≥ 0 . R_{u}(\theta)=\lambda_{\mathrm{prof}}\,r_{\mathrm{prof}}(u)+\lambda_{\mathrm{task}}\,r_{\mathrm{task}}(u),\qquad\lambda_{\mathrm{prof}},\lambda_{\mathrm{task}}\geq 0. (16)
B143: (1) Profile inference reward.
B144: In synthetic training, the ground-truth persona p u p_{u} is available. We score the inferred profile z ^ u \hat{z}_{u} with an LLM-as-judge 𝒥 prof \mathcal{J}_{\mathrm{prof}} :
B145: r prof ​ ( u ) = Norm ⁡ ( 𝒥 prof ​ ( z ^ u , p u ) ) ∈ [ 0 , 1 ] , r_{\mathrm{prof}}(u)=\mathrm{Norm}\Big(\mathcal{J}_{\mathrm{prof}}(\hat{z}_{u},\;p_{u})\Big)\in[0,1], (17)
B146: where 𝒥 prof ​ ( ⋅ ) \mathcal{J}_{\mathrm{prof}}(\cdot) outputs a scalar rating (e.g., 1–10) for how well z ^ u \hat{z}_{u} matches the persona (including style and latent constraints), and Norm ⁡ ( ⋅ ) \mathrm{Norm}(\cdot) linearly rescales to [ 0 , 1 ] [0,1] .
B147: (2) Task outcome reward (pairwise, preference-aware).
B148: We evaluate whether the improved prompt yields a better assistant response than the original prompt. We use an LLM-as-judge 𝒥 task \mathcal{J}_{\mathrm{task}} that is provided with: the original query q ~ u init \tilde{q}^{\mathrm{init}}_{u} , the ground-truth persona p u p_{u} (for preference grounding), and the two candidate responses ( a u base , a ^ u init ) (a^{\mathrm{base}}_{u},\hat{a}^{\mathrm{init}}_{u}) . The judge outputs a binary value reflecting whether the response using the improved prompt gives higher task correctness/clarity and preference satisfaction
B149: r task ​ ( u ) = Norm ⁡ ( 𝒥 task ​ ( q ~ u init , p u , a u base , a ^ u init ) ) ∈ [ 0 , 1 ] . r_{\mathrm{task}}(u)=\mathrm{Norm}\Big(\mathcal{J}_{\mathrm{task}}(\tilde{q}^{\mathrm{init}}_{u},p_{u},a^{\mathrm{base}}_{u},\hat{a}^{\mathrm{init}}_{u})\Big)\in[0,1]. (18)
B150: As a result, this yields the trained optimizer for personalizing LLMs. The optimizer π θ \pi_{\theta} is itself implemented as a language model, whose parameters are learned via SFT and outcome-driven RL Given a user’s interaction history and an initial query, this optimizer generates a rewritten prompt. When training the optimizer, we instantiate it using different base LLMs.

B230: 6.1 Experimental Setup
B231: Models & Baselines.
B232: We use a broad set of open- and closed-source, instruction-tuned LLMs for evaluation. Detailed model lists are provided in the Appendix F . We compare our method with the vanilla prompt and the following representative personalization approaches: (1) history-augmented prompting (Simple Concat), persona-based query rewriting [ 44 , 18 , 73 ] , (3) preference-based few-shot in-context learning [ 40 , 64 ] , and (4) controller-guided Prompting [ 30 , 56 ] . More details are provided in in Appendix C ).
B233: Datasets
B234: We evaluate our method in two ways: (1) synthetic personalized interaction datasets and (2) a real-world test set. The synthetic benchmarks consist of multi-turn trajectories constructed from multiple public datasets (i.e., ai2_arc , IFEval , oasst1 , ultrachat ), with additional held-out datasets used only for evaluation. The real-world test set contains high-fidelity personalized interactions processed into ( ℋ u , q ~ u init ) (\mathcal{H}_{u},\tilde{q}^{\mathrm{init}}_{u}) pairs. Implementation and dataset details are in Appendix E .
B235: Evaluation Metrics
B236: We evaluate model performance using two metrics by LLM-as-a-Judge [ 74 ] : a personalization score and a task completion score . (1) Personalization score: To measure personalization quality, we provide the user profile together with the model output to an LLM-based judge, which assigns a score indicating how well the response aligns with the specified user preferences. (2) Task completion score: To measure task performance, we provide ground-truth answers to an LLM-based judge, which scores the model output based on task correctness and completeness. We report the mean and variance over 3 runs.

B242: Table 7 compares PPOpt against several representative prompting and rewriting baselines in terms of personalization quality and task completion. All baselines improve personalization over the vanilla prompts (e.g., + 0.81 +0.81 to + 1.53 +1.53 ), but these gains typically come with a non-trivial drop in task completion ( | Δ | = 0.54 |\Delta|=0.54 – 1.06 1.06 ), indicating a trade-off where stronger personalization steering can lightly hurt task completion quality. This suggests PPOpt better captures user-specific constraints without over-constraining the underlying model, thus yielding improved personalization with minimal impact on task success.
B243: Robustness across LLM Backbones.
B244: From Table 8 , we observe that PPOpt consistently improves personalization across all optimizer–model combinations. Notably, optimization can elevate the personalization performance of weaker deployed models to a level comparable with that of stronger models, despite clear differences in their original personalization capabilities. Meanwhile, the impact on task completion remains minimal, with only small changes observed.
B245: Ablation Study.
B246: Figure 3 shows that SFT alone already provides a strong boost in personalization across all optimizers, establishing an effective cold-start prior. However, RL without the profile inference reward leads to inconsistent gains, and even degrades performance for some models (e.g., Qwen3), probably indicating unstable optimization without explicit guidance. In contrast, the full setting consistently achieves the best and most stable performance, demonstrating that the profile inference reward plays a crucial role in stabilizing RL and further improving personalization.
B338: Appendix C Implementation details
B339: Filtering low-quality pseudo targets for SFT.
B340: Since ( z u ⋆ , q u ⋆ ) (z^{\star}_{u},q^{\star}_{u}) are synthesized and may be noisy, we apply lightweight filtering to remove non-effective or degenerate rewrites before SFT. Concretely, we discard samples where the rewritten prompt q u ⋆ q^{\star}_{u} is near-identical to q ~ u init \tilde{q}^{\mathrm{init}}_{u} (e.g., trivial paraphrases or copies), overly generic (e.g., adding boilerplate without introducing user-specific constraints), or leads to no measurable improvement under an automatic preference-aware comparison (e.g., 𝒥 task \mathcal{J}_{\mathrm{task}} fails to prefer the response induced by q u ⋆ q^{\star}_{u} over that induced by q ~ u init \tilde{q}^{\mathrm{init}}_{u} ). This filtering step improves the signal-to-noise ratio of the behavioral prior learned by SFT and reduces the tendency to imitate superficial prompt edits.
B341: Implementation details of baselines
B342: •
B343: History-augmented prompting (Concat). The user’s conversation history is directly concatenated with the current query and provided to the assistant model for response generation. The assistant’s output is subsequently evaluated by a judge model to obtain the final score.
B344: •
B345: Persona-based query rewriting [ 44 , 18 , 73 ] . A high-level user persona is first induced from the conversation history using a helper model ( llama-3.1-8b-instruct ). The inferred persona is then concatenated with the current query, and the combined input is passed to the assistant model for response generation. The resulting output is scored by the judge model.
B346: •
B347: Preference-based few-shot in-context learning [ 40 , 64 ] . A helper model ( GPT-4o-mini ) constructs a small set of preference-oriented few-shot examples (e.g., chosen vs. rejected responses) from the user’s interaction history. The current query, together with the generated preference pairs, is prepended as in-context demonstrations to guide personalized generation by the assistant model.
B348: •
B349: Controller-guided prompting [ 30 , 56 ] . The conversation history and current query are provided to an auxiliary controller model ( GPT-4o-mini ), which generates context-enhanced personalized guidance by rewriting the query based on the interaction history. The rewritten query is then passed to the assistant model for response generation.
B350: Unless otherwise specified, the assistant model is llama-3.3-70b-instruct , and the judge model is GPT-5.2 .
B351: Training Details
B352: We adopt a two-stage training paradigm for PPOpt. In the first stage, we perform Supervised Fine-Tuning (SFT) with Low-Rank Adaptation (LoRA) [ 22 ] using rank r = 32 r=32 . The model is trained to generate structured outputs that include user preference reasoning and optimized prompts. During SFT, we apply cross-entropy loss over completion tokens only. A cosine learning rate schedule is used, with a peak learning rate of 2 × 10 − 6 2\times 10^{-6} , a minimum learning rate of 5 × 10 − 7 5\times 10^{-7} , and 50 50 warmup steps.
B353: In the second stage, we apply Group Relative Policy Optimization (GRPO) for reinforcement learning. For each training state, we sample K = 8 K=8 completions from the current policy using temperature τ = 0.7 \tau=0.7 and nucleus sampling with p = 0.9 p=0.9 . We employ GPT-4o-mini as the judge model to compute rewards, which evaluate both the accuracy of inferred user profiles against ground-truth personas and the quality improvement of optimized queries via pairwise comparison with the original queries.

B357: We use two sets of datasets for the experiments: (1) Synthetic personalized interaction benchmark. We construct a synthetic multi-turn trajectory benchmark as the test split for evaluation, covering queries from five datasets. The three datasets in Table 2 are ai2_arc [ 11 ] , MBPP [ 3 ] , and ultrachat_200k [ 15 ] . We additionally include IFEval [ 66 ] and oasst1 [ 27 ] as held-out evaluation datasets, to reduce potential distributional advantages associated with dataset reuse during training. (2) Real-world test set. In addition to synthetic benchmarks, we evaluate our method on a high-fidelity dataset that closely simulates real-world personalized interactions. We preprocess the resulting interactions into ( ℋ u , q ~ u init ) (\mathcal{H}_{u},\tilde{q}^{\mathrm{init}}_{u}) pairs following the same protocol used throughout our experiments.
B358: Real-world dataset construction.
B359: Instead of directly relying on raw user logs, we construct this dataset through controlled human-in-the-loop collection to preserve realism while ensuring diversity and reproducibility.
B360: We recruit a single cohort of human experts via Prolific 4 4 4 https://www.prolific.com/ , all of whom are experienced in interacting with LLMs and collectively cover a broad range of domains. Participants are compensated at a rate of at least $10.89 per hour (above minimum wage), and 99 human experts contribute to the data editing process. Participants gave informed consent. The data collection was reviewed by the institutional review board (ethics commission) at LMU Munich (approval number: ETH-SOM-048).
B361: We first generate interaction trajectories using our automated generation pipeline. For ease of inspection and editing, each trajectory is formatted as a structured Markdown document. The documents are then distributed to participants through Qualtrics 5 5 5 https://www.qualtrics.com/ as survey tasks. Human experts are instructed to edit and refine the user-side content only, including the initial queries and subsequent user feedback, according to specified user profiles. After editing, participants upload the revised Markdown files back to the survey, enabling complete and consistent data collection. This process improves realism and behavioral fidelity while preserving the original task intent and interaction structure.
