B55: 3 Formal Framework
B56: First, we address the mismatch between regular-expression constraints and model tokenizers by constructing a vocabulary-aligned automaton ( Section 3.1 ). Then, we present a dynamic programming algorithm that uses the vocabulary-aligned automaton to compute the expected probability that a sample satisfies the constraint ( Section 3.2 ). Finally, we connect our approach to standard classifier guidance ( Dhariwal and Nichol, 2021 ; Song et al., 2020 ) and show how our approach approximates the desired conditional distribution ( Section 3.3 ).
B57: 3.1 Tokenizer-Automaton Alignment
B58: Before presenting the steering algorithm, we need to address a mismatch between the character-level definition of regular languages and the token-level representation used by diffusion language models. While a regular constraint specifies a set of valid strings, models generate sequences of tokens from a fixed vocabulary, and a single string may admit multiple valid tokenizations. To correctly compute expected probabilities and their gradients, the automaton representing the constraint must accept all token sequences whose concatenation forms a valid string; otherwise, valid probability mass would be systematically ignored.
B59: Formally, if a regular language ℒ \mathcal{L} accepts a string x x , then the DFA A A for ℒ \mathcal{L} must accept every tokenization of x x . For example, for the string cat , if the automaton accepts the token sequence ca, t but not c, at , our approach in Section 2 would ignore the probability of the latter and thus compute an incorrect expected probability.
B60: We introduce a function 𝖠𝗅𝗂𝗀𝗇 ⁡ ( A , V ) \mathsf{Align}(A,V) that constructs a vocabulary-aligned automaton A V A_{V} from a given DFA A A and vocabulary V V . The algorithm constructing 𝖠𝗅𝗂𝗀𝗇 ⁡ ( A , V ) \mathsf{Align}(A,V) (which is formalized in Appendix D and proven correct in Appendix E ) first transforms A A into a character-level automaton A C A_{C} , whose transitions are labeled by individual characters. It then augments A C A_{C} by adding transitions corresponding to multi-character tokens in V V whenever the underlying character path exists in A C A_{C} . For instance, if V V contains the token ca , the algorithm adds a transition q 0 → ca q 2 q_{0}\xrightarrow{\texttt{ca}}q_{2} whenever a path labeled c → \to a exists from q 0 q_{0} to q 2 q_{2} . Tokens that do not correspond to any valid character path (e.g., rt in Figure 1 ) are ignored. Finally, the algorithm removes character-level transitions not present in V V , yielding a token-level automaton compatible with the model vocabulary.

B70: 3.3 Connection to Classifier Guidance
B71: Rather than deriving a new convergence proof, we observe that our approach is a training-free instantiation of Classifier Guidance ( Dhariwal and Nichol, 2021 ; Song et al., 2020 ) . In the standard framework, conditioned generation is achieved by modifying the score function (the drift term in the reverse SDE) with the gradient of a log-likelihood term:
B72: ∇ x t ​ log ​ p ​ ( x t ∣ ℒ ) = ∇ x t ​ log ​ p ​ ( x t ) + ∇ x t ​ log ​ p ​ ( ℒ ∣ x t ) \nabla_{x_{t}}\log p(x_{t}\mid\mathcal{L})=\nabla_{x_{t}}\log p(x_{t})+\nabla_{x_{t}}\log p(\mathcal{L}\mid x_{t}) (3)
B73: The first term is provided by the base diffusion model, while the second term—the “guidance”—is typically approximated by training a separate classifier network on noisy latents x t x_{t} .
B74: Our method replaces this learned classifier with the analytical expectation derived in Algorithm 1 :
B75: log p ( ℒ ∣ x t ) ≈ log 𝔼 s ∼ Dec ⁡ ( x t ) [ s ∈ ℒ ] \log p(\mathcal{L}\mid x_{t})\approx\log\mathbb{E}_{s\sim\operatorname{Dec}(x_{t})}[s\in\mathcal{L}] (4)
B76: This substitution interprets the noisy latent x t x_{t} as parameterizing a valid unigram distribution via the decoder. While this is an approximation at high noise levels ( t ≫ 0 t\gg 0 ), it becomes exact as t → 0 t\to 0 (where x t ≈ x 0 x_{t}\approx x_{0} ). By using this analytical proxy, we leverage the robust theoretical foundations of guided diffusion without the cost or instability of training auxiliary classifiers. The convergence properties of our sampler thus follow directly from the standard results for score-based conditional generation established by Anderson (1982) ; Song et al. (2020) , contingent on the quality of this unigram approximation.

B77: 4 Evaluation
B78: We implement our approach as a tool Diffinity using the PLAID diffusion model ( Gulrajani and Hashimoto, 2023 ) as the base model. PLAID internally uses a 32-dimensional word2vec model as the latent space, and is equipped with a 1.3B transformer that interprets points in this space as unigram probability distributions (this transformer is trained alongside PLAID as part of its denoising network). Diffinity takes the gradient of this transformer composed with our implementation of the expected probability to obtain gradients on the word2vec latent space, then steers the diffusion process by adding the gradient term to the DDPM sampling equation that PLAID uses for denoising. At the end of the diffusion process, PLAID (and also Diffinity ) samples using argmax from the final unigram distribution to produce the final concrete sentence. We reiterate that PLAID is a continuous diffusion model, and the decoding to a concrete sentence happens only once at the end of the denoising process; as opposed to discrete models ( Lou et al., 2023 ; Nie et al., 2025 ) which decode to a discrete sentence at each step of denoising.
B79: Benchmarks
B80: We consider 180 regular-expression constraints spanning two categories. JSON : 70 derived from JSONSchemaBench ( Geng et al., 2025 ) (schemas converted to regexes when possible, then filtered for non-regular constraints and overly large tokenizer-aligned automata). Natural Language : 110 synthetically generated natural-language patterns covering Prefix, Suffix, Appearance, Between- n n , Between (unbounded), and Word-length templates, each instantiated by sampling one or two words from the most common words in the English vocabulary ( Tatman, 2018 ) and an integer parameter (e.g., position or distance). Details on the benchmark construction are in Appendix F .
B81: We set the sequence length for all benchmarks to 64, which is a sufficiently long bound for generating sequences that satisfy our regex constraints. We run JSON generation benchmarks for 256 timesteps, because they result in complex automata that take a long time to compute the gradient over. For all other benchmarks, we run generation for 1024 timesteps. All other hyperparameters are set to the default values of the PLAID model ( Gulrajani and Hashimoto, 2023 ) .

B95: Metrics and Baselines
B96: We report constraint satisfaction rate (the fraction of generated samples that satisfy the regex constraint) and pass@10 (the fraction of benchmarks for which at least one of the first 10 samples satisfies the constraint), along with perplexity (geometric mean over all constraint-matching samples), and fluency (arithmetic mean over all constraint-matching samples). Perplexity is computed using LLama3.1-8B ( Grattafiori et al., 2024 ) as the reference distribution, while fluency was measured on a scale of 0 to 100 by using Claude Sonnet 4.5-20250929 as an external LLM judge (prompts to derive fluency are adapted from Lee and Berg-Kirkpatrick (2025) and can be found in the Appendix, Appendix C ).
B97: Our baseline is constrained generation for autoregressive models using the Guidance library ( Guidance Contributors, 2023 ) with GPT2-Small, Medium, and Large. This choice follows the original PLAID ( Gulrajani and Hashimoto, 2023 ) paper ( Gulrajani and Hashimoto, 2023 ) , which demonstrates that the capacity of the base PLAID model lies in between GPT2-Small and Medium.
B98: We evaluate Diffinity using different guidance scales γ \gamma ( Equation 2 ); γ = 2.5 \gamma=2.5 is most effective. The reported metrics use γ = 2.5 \gamma=2.5 unless otherwise noted. We also compare our computational overhead against PLAID’s. The PLAID model also has native guidance capabilities that allow it to loosely model some of our regular expressions, so we make comparisons where applicable.

For the GPT models, we use the non-padded regex (i.e., schema only). Diffinity has comparable performance to the constrained GPT-2 models when generating JSON schema, with around a 10% decrease in satisfaction rate and 7% difference in pass@10 rate. Complex structured formats pose a fundamental challenge for smaller diffusion language models such as PLAID. Our JSON Schema experiments demonstrate that Diffinity overcomes this limitation without the need of fine-tuning the model, enabling reliable generation of highly structured outputs outside the model’s training distribution.
B101: 4.2 Natural Language Benchmarks
B102: Table 2 summarizes the results for the natural language benchmarks. Due to space limitations, we present GPT2-Small-GCD’s results in Appendix G (they are similar to GPT2-Medium-GCD). In terms of constraint satisfaction and pass@10 rates, Diffinity outperforms existing autoregressive constrained decoding, achieving an average constraint satisfaction rate of 92.9% compared to 20.5% for GPT2-Large-GCD.
B103: The constraint satisfaction rates for the GPT2 models are low in these benchmarks primarily because they fall into the ‘infinite repetition trap’: for example, given a regex [A-Za-z ] cat [A-Za-z ,.] * \texttt{[A-Za-z ] cat [A-Za-z ,.]}^{\texttt{*}} , an autoregressive model might continuously append characters to the first word if it finds that cat is an unlikely continuation to the first word it guessed until the max_tokens budget runs out. Diffinity is free of this problem, it will guide the denoising process towards an entire, coherent sentence that contains cat as the second word.
B104: Diffinity also outperforms all GPT2 variants in terms of perplexity, consistently outperforming even GPT2-Large-GCD, with the smallest perplexity difference being 9.4 9.4 for the between (udb.) category. Diffinity ’s fluency (35.8) surpasses those of GPT2 Small (25.0) and Medium (32.0) and is comparable to that of GPT2-Large (37.2). We find this result remarkable; the original PLAID paper ( Gulrajani and Hashimoto, 2023 ) indicates that the base PLAID model sits in between GPT2-Small and Medium in terms of perplexity.
B105: The average perplexity of all samples generated by Diffinity for the natural language benchmarks is 60.0 60.0 while the average fluency is 35.8 35.8 at scale 2.5 2.5 . Our experiments indicate that the base PLAID model displays 61.6 61.6 perplexity and 46.0 46.0 fluency for unconditioned generation under the same hyperparameters (sequence length of 64 64 with 1024 1024 diffusion timesteps). This shows that the perplexity gap induced by Diffinity is virtually nonexistent at scale 2.5 2.5 , while the fluency gap is also relatively low —confirming that our approach in Section 2 allows diffusion models to obey formal syntax while preserving information from the original distribution. B110: 4.3 The Effect of Different Guidance Scales
B111: We study how the guidance scale trades off constraint satisfaction and generation quality in Diffinity . Figure 2(a) shows how varying the guidance affects satisfaction rates, perplexity, and fluency.
B112: As expected, increasing the guidance scale monotonically improves constraint satisfaction. The effect is particularly pronounced for JSON, where satisfaction rises from 30.4 % 30.4\% at scale 1.0 1.0 to 68.4 % 68.4\% at scale 2.5 2.5 . We conjecture that the relatively large increase in satisfaction rate for JSON is because well-formed JSON is relatively further from the training distribution of the base PLAID model: at low guidance scales the diffusion trajectory frequently drifts into syntactically invalid regions, whereas stronger guidance anchors the reverse process to the JSON schema.
B113: Surprisingly, stronger guidance does not degrade language quality. On the contrary, perplexity measured with Llama-3.1-8B decreases substantially, from 73.6 73.6 at scale 1.0 1.0 to 60.0 60.0 at scale 2.5 2.5 . Fluency exhibits only a mild drop (from 39.4 39.4 to 35.8 35.8 ), indicating that the improvement in structural correctness is not achieved by sacrificing readability.
B114: We hypothesize that this counterintuitive perplexity improvement arises because higher guidance suppresses unstable denoising trajectories that violate the regex early and subsequently require large updates. By constraining the diffusion path to remain close to the target regular language, Diffinity produces sequences that are both syntactically valid and more predictable under an external language model.
B115: 4.4 Comparison with PLAID
B116: Generation quality.
B117: PLAID provides native guidance mechanisms that enable token-level control over simple syntactic properties, such as increasing the probability that a specific token appears at a given position, by injecting gradients of token log-probabilities during the denoising process. However, these mechanisms do not extend to structured constraints such as regular expressions. In particular, PLAID operates at the tokenizer level and is therefore incompatible with regex constraints due to the automaton–token alignment problem discussed in Section 3.1 .
B118: If we temporarily ignore this limitation, PLAID can express a strict subset of our natural-language benchmarks—namely the Prefix , Suffix , and Appearance categories. We therefore compare PLAID and Diffinity on this common subset, using a guidance scale of 2.5 2.5 for both methods.
B119: PLAID achieves an average satisfaction rate of 59.4 % 59.4\% on these benchmarks, whereas Diffinity reaches 92.9 % 92.9\% , demonstrating that automaton-level guidance is substantially more effective than token-level control even when both are applied at comparable strength.
B120: Figure 2(b) reports a scatter plot of the minimum-perplexity samples obtained for benchmarks that both PLAID and Diffinity could solve. The scatter plot shows that Diffinity is advantageous in generating lower-perplexity samples, where Diffinity ’s minimum perplexity is on average 10.4 10.4 compared to 25.7 25.7 for PLAID. PLAID does have a slightly lower average perplexity for all generated samples that meet the constraint, at 55.65 55.65 compared to 60.27 60.27 for Diffinity ; we attribute this difference to the fact that Diffinity has a much higher constraint satisfaction rate.
B121: Computational overhead.
B122: We next examine the computational overhead introduced by Diffinity . Figure 2(c) plots per-sample generation latency for 14 representative benchmarks, across batch sizes of 1 1 , 4 4 , and 16 16 , as a function of the number of transitions in the aligned automaton. Compared to unconditional generation, Diffinity incurs substantial overhead: the smallest benchmark shown contains 71,735 71{,}735 transitions and requires 145.6 145.6 seconds per sample, versus 33.3 33.3 seconds for unconditional generation in PLAID, and 55.9 55.9 seconds for conditional generation.
B123: This overhead scales approximately linearly with the number of transitions, caused by Line 6 of Algorithm 1 , which computes a dense sum over all automaton transitions. Although this computation is parallelized on the GPU, we call torch.autograd to compute the gradient of Algorithm 1 , restricting further optimization opportunities, and the large number of transitions also exterts significant pressure on memory bandwidth. As a result, performance gains from batching quickly saturate, which explains the relatively small per-sample latency difference between batch sizes 4 4 and 16 16 in Figure 2(c) . PLAID, on the other hand, displays constant latency across regexes of different size because it does not have to compute a gradient over an automaton.
B124: Our primary goal in this work is to establish that diffusion models can reliably obey formal syntactic constraints—often more robustly than autoregressive approaches, as reflected in our perplexity and fluency results. Designing memory-efficient data structures and custom gradient kernels for Algorithm 1 is a promising direction for future work, and we expect optimizations like those used in constrained decoding ( Park et al., 2025 ) to reduce the overhead of Diffinity by one to two orders of magnitude.
