B28: 3 Method
B29: Figure 2 : Overview of our pipeline . Given a video in its raw codec representation, our framework leverages the GOP structure for efficient, codec-aware tokenization. I-frames are processed by a standard frozen vision encoder ( ϕ RGB \phi_{\text{RGB}} ) to produce dense RGB tokens. P-frames , however, bypass full RGB decoding. Their raw components, motion vectors and residuals, are instead fed into our lightweight Δ \Delta -Encoder ( ϕ Δ \phi_{\Delta} ) to generate a small set of highly compact Δ \Delta -tokens. The final token stream, an interleaved sequence of I-frame tokens and Δ \Delta -tokens, is consumed by the LLM, enabling dense temporal coverage at a fraction of the standard token count and runtime.
B30: 3.1 Preliminaries
B31: Modern video codecs such as MPEG-4, H.264, and HEVC [ 83 , 84 ] achieve high compression ratios by exploiting temporal redundancy across consecutive frames. Let a video 𝒱 \mathcal{V} be a sequence of frames ( F ( 1 ) , … , F ( T ) ) (F^{(1)},\dots,F^{(T)}) . Each of these frames can be an I-frame (intra-coded), a P-frame (predictive), or optionally a B-frame (bi-directional predictive). Consecutive frames are organized in a Group of Pictures (GOP) structure as illustrated in Fig. 2 .
B32: I-frames. An I-frame, I ( t ) I^{(t)} , is an RGB image encoded independently without the use of preceding or subsequent frames. It is used as a reference point of the Group of Pictures and provides a full visual representation.
B33: P-frames. A P-frame P ( t ) P^{(t)} contains only the changes from the previous frame, be it a reference frame I ( t − 1 ) I^{(t-1)} or some other P-frame P ( t − 1 ) P^{(t-1)} . The difference is defined by two components:
B34: •
B35: Motion vectors τ ( t ) \tau^{(t)} , which describe block-wise displacements from the reference to the target frame, resembling coarse optical flow.
B36: •
B37: Residuals δ ( t ) \delta^{(t)} , which capture block-wise pixel corrections that remain after motion compensation.
B38: The recurrence [ 72 , 79 ] for reconstructing a P-frame is:
B39: I ^ i ( t ) = I ^ i − τ i ( t ) ( t − 1 ) + δ i ( t ) , \hat{I}^{(t)}_{i}=\hat{I}^{(t-1)}_{i-\tau^{(t)}_{i}}+\delta^{(t)}_{i}\kern 5.0pt, (1)
B40: where i i is the pixel coordinate index and
B41: I ^ ( t − 1 ) = I ( t − 1 ) ⇔ F ( t ) ​ is an I-frame . \hat{I}^{(t-1)}=I^{(t-1)}\Leftrightarrow F^{(t)}\text{ is an I-frame}\kern 5.0pt. (2)
B42: Hence, P-frames contain only incremental temporal information, and are therefore smaller in file size than I-frames.
B43: B-frames. A B-frame leverages both preceding and subsequent frames to encode its differences. While this bidirectional prediction achieves the highest compression efficiency, it increases decoding complexity: B-frames must wait for future I/P-frames, creating a mismatch between decode and display order. Consequently, they are less suited for streaming or real-time use. We therefore focus on P-frames, which depend only on past references and align naturally with the causal processing required by VideoLMs.
B44: Group of Pictures (GOP). A GOP is a cycle structure that comprises one I-frame together with any mixture of P- and/or B-frames, e.g., I ​ B ​ P ​ P ​ B ​ P ​ e ​ t ​ c I\,B\,P\,P\,B\,P\,etc . The GOP structure and length control the trade-offs between the compression efficiency, quality, and the capability for random access. Typical applications use varying configurations: all three frame types are used by the H.264 codec, while early MPEG-4 uses mainly the I- and the P-frames (see Supp. Sec F for a detailed explanation).
B45: Implication for VideoLMs. Despite this rich structure, current VideoLMs discard codec information and fully decode and tokenize dense RGB frames, ignoring the inherent sparsity of P- and B-frames. This results in unnecessary computation and inflated token counts.
B46: 3.2 CoPE-VideoLM
B47: Our framework explicitly leverages the GOP structure and introduces a codec-aware tokenization framework that seamlessly integrates with VideoLMs. Instead of unnecessarily encoding each frame as RGB patches like prior work, we retain I-frames as full RGB tokens and encode P-frames into lightweight and compact Δ \Delta -tokens (delta for difference) obtained from motion vectors and residuals, thereby preserving temporal coverage without exceeding token budgets. An illustration of this process is presented in Fig. 2 .
B48: Given a video 𝒱 = ( F ( 1 ) , … , F ( T ) ) \mathcal{V}=(F^{(1)},\dots,F^{(T)}) , each frame F ( t ) F^{(t)} is represented as:
B49: F ( t ) = { I ( t ) , if F ( t ) is an I-frame , P ( t ) = ( τ ( t ) , δ ( t ) ) , if F ( t ) is a P-frame , F^{(t)}=\begin{cases}I^{(t)},&\text{if $F^{(t)}$ is an I-frame},\\ P^{(t)}=(\tau^{(t)},\delta^{(t)}),&\text{if $F^{(t)}$ is a P-frame},\end{cases} (3)
B50: where τ ( t ) \tau^{(t)} is a set of block-wise motion vectors (usually one per up to 16 × 16 16\times 16 region), and δ ( t ) \delta^{(t)} is a set of block-wise residuals. For our downstream processing, we represent these as tensors: τ ( t ) ∈ ℤ H × W × 2 \tau^{(t)}\in\mathbb{Z}^{H\times W\times 2} is the sparse tensor constructed from the block-wise motion vectors and δ ( t ) ∈ ℝ H × W × C \delta^{(t)}\in\mathbb{R}^{H\times W\times C} is the sparse tensor of residuals.
B51: I-frame processing. I-frames I ( t ) I^{(t)} are passed through a frozen vision encoder ϕ RGB \phi_{\text{RGB}} , producing M M dense tokens:
B52: X I ( t ) = ϕ RGB ​ ( I ( t ) ) ∈ ℝ M × d . X^{(t)}_{I}=\phi_{\text{RGB}}(I^{(t)})\in\mathbb{R}^{M\times d}. (4)
B53: P-frame processing. Each P-frame P ( t ) P^{(t)} is mapped into a much more compact representation consisting of N ≪ M N\ll M tokens by the Δ \Delta -Encoder ϕ Δ \phi_{\Delta} :
B54: X P ( t ) = ϕ Δ ​ ( τ ( t ) , δ ( t ) ) ∈ ℝ N × d . X^{(t)}_{P}=\phi_{\Delta}(\tau^{(t)},\delta^{(t)})\in\mathbb{R}^{N\times d}. (5)
B55: P-frame fusion. In the setup described so far, processing all frames at the native frame rate is mandatory as codec primitives are defined relative to previous frames and skipping frames invalidates these dependencies. For example, let us consider a 30 30 FPS video with a GOP size of 240 240 frames ( 8 8 seconds). Our method yields M + 239 ​ N M+239N tokens per GOP, compared to 240 ​ M 240M if all frames were encoded as RGB images. Fine-grained action recognition may require this exhaustive temporal coverage, but most video understanding tasks can often be done with sparser coverage.
B56: Rather than processing all frames at the native frame rate, we can fuse s s consecutive P-frames, encoding their combined changes relative to frame ℱ ( t − s ) \mathcal{F}^{(t-s)} (rather than the immediately preceding frame). The maximum number of P-frames that can be fused is bounded by the GOP size. In the running example, using s = 30 s=30 P-frames (effectively 1 FPS) for fusion reduces the token count to M + 7 ​ N ≪ M + 239 ​ N M+7N\ll M+239N per GOP, instead of 8 ​ M 8M when encoding RGB frames at 1 1 FPS. This fusion offers a codec-native way to trade temporal resolution for efficiency and can be tuned to match available compute and task requirements.
B57: For clarity, we treat the temporal index ( t ) (t) as already incorporating the P-frame fusion, so F ( t ) F^{(t)} always depends on F ( t − 1 ) F^{(t-1)} , though ( t ) (t) may no longer correspond to the raw frame indices.
B58: Δ \Delta -Encoder. The Δ \Delta -Encoder ϕ Δ \phi_{\Delta} (Fig. 3 ) is designed to process the motion vectors τ ( t ) \tau^{(t)} and residuals δ ( t ) \delta^{(t)} through two specialized branches. The motion vectors τ ( t ) \tau^{(t)} are processed via a multi-layer MLP to extract local features over a grid of size H G × W G H_{G}\times W_{G} flattened as ℝ ( H G ​ W G ) × d \mathbb{R}^{(H_{G}W_{G})\times d} . These features are then compressed via a motion transformer θ motion \theta_{\texttt{motion}} with a set of K τ K_{\tau} learnable query tokens that can attend to all H G ​ W G H_{G}W_{G} input tokens and aggregate their information as:
B59: τ tok ( t ) = θ motion ​ ( MLP ​ ( τ ( t ) ) ) . \tau^{(t)}_{\texttt{tok}}=\theta_{\texttt{motion}}(\texttt{MLP}(\tau^{(t)}))\kern 5.0pt. (6)
B60: Only these K τ K_{\tau} compressed motion tokens τ tok ( t ) ∈ ℝ K τ × d \tau^{(t)}_{\texttt{tok}}\in\mathbb{R}^{K_{\tau}\times d} are used in the VideoLM.
B61: The residual frame δ ( t ) \delta^{(t)} is embedded by a lightweight ResNet-18 [ 85 ] module to extract local features over the same grid size H G × W G H_{G}\times W_{G} . Similarly to above, a residual transformer θ residual \theta_{\texttt{residual}} aggregates and compresses the raw features to a set of K δ K_{\delta} compressed residual tokens δ tok ( t ) ∈ ℝ K δ × d \delta^{(t)}_{\texttt{tok}}\in\mathbb{R}^{K_{\delta}\times d} as:
B62: δ tok ( t ) = θ residual ​ ( ResNet ​ ( δ ( t ) ) ) . \delta^{(t)}_{\texttt{tok}}=\theta_{\texttt{residual}}(\texttt{ResNet}(\delta^{(t)}))\kern 5.0pt. (7)
B63: Interleaved token stream. In practice, we set K τ = K δ = 4 K_{\tau}=K_{\delta}=4 and thus, N = 8 N=8 (see Supp. for an ablation study). The final visual sequence input to the LLM is an ordered concatenation of I-frame and P-frame tokens:
B64: X \displaystyle X = [ x ( 1 ) , x ( 2 ) , … , x ( T ) ] , \displaystyle=\left[\,x^{(1)},x^{(2)},\dots,x^{(T)}\,\right], (8)
B65: where ​ x ( t ) \displaystyle\text{where}\kern 5.0ptx^{(t)} = { X I ( t ) , if F ( t ) is an I-frame X P ( t ) , if F ( t ) is a P-frame . \displaystyle=\begin{cases}X^{(t)}_{I},&\text{if $F^{(t)}$ \text{ is an I-frame}}\\ X^{(t)}_{P},&\text{if $F^{(t)}$ \text{ is a P-frame}}\end{cases}\kern 5.0pt.
B66: The LLM can consume X I ( t ) X^{(t)}_{I} and X P ( t ) X^{(t)}_{P} alongside textual instructions, without any architectural modifications. This approach reduces the redundant data considerably while preserving accurate temporal coverage and enables smooth scalability to long videos by adjusting the I-frame density, P-frame grouping, and token allocation.
B67: 3.3 Training Paradigm
B68: The training is done in two stages. First the Δ \Delta -encoder is pre-trained in order to render it compatible with the image encoder. Then, this encoder is integrated into a VideoLM and the whole pipeline is fine-tuned end-to-end.
B69: Δ \Delta -encoder pre-training. The primary difficulty lies in ensuring that the Δ \Delta -tokens X P ( t ) X^{(t)}_{P} are aligned with the image tokens X I ( t ) X^{(t)}_{I} . To achieve this, we pre-train the Δ \Delta -Encoder as a modality adapter that enables codec-derived primitives ( τ ( t ) , δ ( t ) ) (\tau^{(t)},\delta^{(t)}) to be compatible with the embedding space defined by a vision encoder. By aligning the Δ \Delta -tokens with this space, P-frames can then be compactly represented and replace standard RGB tokens within a VideoLM.
B70: For pre-training, two additional modules are used on top of the outputs of the Δ \Delta -encoder. First, a “reference” transformer θ ref \theta_{\texttt{ref}} uses the image tokens from I ( t − 1 ) I^{(t-1)} and the compressed motion vector tokens τ tok ( t ) \tau^{(t)}_{\text{tok}} , and its aim is to understand how the information moved in the image and how it modified the original tokens. This is akin to the warping in Eq. 1 . Second, a “warped” transformer θ warped \theta_{\texttt{warped}} takes these enriched tokens and the residual tokens δ emb ( t ) \delta^{(t)}_{\texttt{emb}} in order to add the residual information as in Eq. 1 . These final features X ^ P ( t ) \hat{X}^{(t)}_{P} should be similar to the image features extracted from the raw I ^ ( t ) \hat{I}^{(t)} . The process can be summarized as:
B71: X I ( t − 1 ) = \displaystyle X^{(t-1)}_{I}= ϕ R ​ G ​ B ​ ( I ( t − 1 ) ) \displaystyle\phi_{RGB}(I^{(t-1)}) (9)
B72: X ^ warped ( t − 1 ) = \displaystyle\hat{X}^{(t-1)}_{\texttt{warped}}= θ ref ​ ( X I ( t − 1 ) , τ tok ( t ) ) \displaystyle\theta_{\texttt{ref}}(X^{(t-1)}_{I},\tau^{(t)}_{\texttt{tok}}) (10)
B73: X ^ P ( t ) = \displaystyle\hat{X}^{(t)}_{P}= θ warped ​ ( X ^ warped ( t − 1 ) , δ tok ( t ) ) . \displaystyle\theta_{\texttt{warped}}(\hat{X}^{(t-1)}_{\texttt{warped}},\delta^{(t)}_{\texttt{tok}})\kern 5.0pt. (11)
B74: To align Δ \Delta -tokens with image tokens, we apply patch-wise regression against the outputs of a frozen vision encoder. Let X I ( t ) = ϕ RGB ​ ( I ^ ( t ) ) ∈ ℝ M × d X^{(t)}_{I}=\phi_{\text{RGB}}(\hat{I}^{(t)})\in\mathbb{R}^{M\times d} denote the tokens of the ground-truth target frame. We minimize:
B75: ℒ MSE = 1 M ​ ∑ i = 1 M ‖ X I ( t ) ​ ( i ) − X ^ P ( t ) ​ ( i ) ‖ 2 2 . \mathcal{L}_{\text{MSE}}=\frac{1}{M}\sum_{i=1}^{M}\big\|X^{(t)}_{I}(i)-\hat{X}^{(t)}_{P}(i)\big\|_{2}^{2}. (12)
B76: Unlike global contrastive losses, this fine-grained objective enforces spatially consistent alignment across patches. As a result, the Δ \Delta -Encoder is encouraged to produce representations that are more closely aligned with the RGB token space, aiming to improve the integration of I- and P-frames during downstream VideoLM training (see Supp. Sec. G.2 to understand the effect of the pre-training phase).
B77: Figure 3 : Δ \Delta -encoder processes motion vectors and residuals through two lightweight branches designed to extract and compress codec-domain information. The resulting motion and residual tokens are concatenated to form the Δ \Delta -tokens used for P-frames, providing an efficient representation, which is projected to the RGB token space during pre-training.
B78: Integration into VideoLMs. After pre-training, we integrate the Δ \Delta -encoder ϕ Δ \phi_{\Delta} into the VideoLM pipeline for full fine-tuning. We interleave the tokens coming from I and P frames as described in Eq. 8 . Note that, the reference-conditioned branches (Reference / Warped) from the Δ \Delta -encoder pre-training stage are not used at this stage, so no RGB reference frames are processed for the P-frames when training the language model. This yields a substantial compute and memory reduction, as shown in Sec. 4.4 . The LLM architecture and training objective remain unchanged (standard instruction tuning next-token prediction loss).

B169: 5 Conclusion
B170: Limitations and Future Work. Our current approach focuses on I- and P-frames, lacking support for B-frames and their complex non-causal dependencies. One option to address this would be by using the decode order instead of the render order. Furthermore, we currently operate on a tensorized version of the codec primitives. For future works, it would be interesting to stay closer to the raw codec primitives, by operating directly on sets of block-wise motion vectors and quantized DCT coefficients, which could offer even better computational and token efficiency. Finally, we use a fixed P-frame fusion window, which is suboptimal for tasks with varying motion.

B260: As mentioned in Sec. 3.1 , the size of each Group of Pictures (GOP) is usually decided adaptively by the codec and video encoder depending on the motion or change. B264: G.1 Varying the Number of Δ \Delta -Tokens
B265: The number of Δ \Delta -tokens emitted per P-frame controls the expressive capacity of the codec branch. Fewer tokens encourage a more aggressively compressed representation, whereas larger token budgets allow the Δ \Delta -Encoder to retain finer motion and appearance cues from the codec primitives. B274: G.2 Two-Stage Training
B275: We ablate the contribution of each component in our two-stage training pipeline: (i) pre-training the Δ \Delta -Encoder to align codec primitives with the RGB embedding space, and (ii) end-to-end finetuning of the full VideoLM. The results are shown in Tab. G.2 . Finetuning the VideoLM without any Δ \Delta -encoder pre-training yields reasonable performance, though noticeably worse than the full two-stage approach In this one-stage setting, the model must simultaneously learn motion–residual interpretation, feature alignment, and multimodal reasoning, which slows convergence and leads to weaker temporal understanding, particularly on PerceptionTest. The best results are achieved when both stages are used. Pre-training ensures that Δ \Delta -tokens inhabit a well-structured embedding space, while finetuning teaches the LLM how to infuse the I- and P-frame tokens together. This combination consistently provides the strongest performance across both datasets. While two-stage training is clearly advantageous in our data regime, we note that the benefit may diminish when scaling to datasets exceeding 3 3 M training samples. In such high-data settings, one-stage training may gradually compensate for the missing pre-training at the cost of more compute.

This illustrates the benefit of denser temporal signals for fine-grained temporal reasoning. MVBench also improves with higher FPS, though the gains are more moderate. Importantly, these improvements show that our framework enables a practical and flexible trade-off between temporal resolution and token efficiency that would be prohibitive with RGB representations.
