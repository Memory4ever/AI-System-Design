L15: cite20†View PDF cite21†HTML (experimental) L16: > Abstract:Recent advancements in large reasoning models (LRMs) have greatly improved their capabilities on complex reasoning tasks through Long Chains of Thought (CoTs). However, this approach often results in substantial redundancy, impairing computational efficiency and causing significant delays in real-time applications. Recent studies show that longer reasoning chains are frequently uncorrelated with correctness and can even be detrimental to accuracy.
L17: In a further in-depth analysis of this phenomenon, we surprisingly uncover and empirically verify that LRMs implicitly know the appropriate time to stop thinking, while this capability is obscured by current sampling paradigms. Motivated by this, we introduce SAGE (Self-Aware Guided Efficient Reasoning), a novel sampling paradigm that unleashes this efficient reasoning potential.
L18: Furthermore, integrating SAGE as mixed sampling into group-based reinforcement learning (SAGE-RL) enables SAGE-RL to effectively incorporate SAGE-discovered efficient reasoning patterns into standard pass@1 inference, markedly enhancing both the reasoning accuracy and efficiency of LRMs across multiple challenging mathematical benchmarks.

L154: Describe the bug
L155: When using multiple Supabase MCP servers with unique names but similar configurations, Kimi Code in VSCode references the wrong MCP server. This issue does not occur in Kimi CLI, only in the VSCode extension.
L156: 
L157: To Reproduce
L158:   1. Configure two Supabase MCP servers with unique names (e.g., "Supabase-RSX" and "Supabase-FMMS")
L159:   2. Both MCPs have the same command/args structure, only differing in `--project-ref`
L160:   3. Prompt: "Use Supabase-RSX to check current tables"
L161:   4. Kimi Code incorrectly uses "Supabase-FMMS" instead
L162: 
L163: Expected behavior
L164: Kimi Code should correctly reference the MCP specified by its unique name (e.g., "Supabase-RSX").
L165: 
L166: Environment
L167:   * Kimi Code version: 1.8.0
L168:   * Platform: VSCode extension (issue not present in Kimi CLI)
L169: Configuration Example
L170: The MCPs share the same command/args structure, differing only in `--project-ref`:
L171: 
L172:     {
L173:       "mcpServers": {
L174:         "Supabase-RSX": {
L175:           "command": "npx",
L176:           "args": [
L177:             "-y",
L178:             "@supabase/mcp-server-supabase@latest",
L179:             "--project-ref=<project-id>"
L180:           ],
L181:           "env": {
L182:             "SUPABASE_ACCESS_TOKEN": "<token>"
L183:           }
L184:         },
L185:         "Supabase-FMMS": {
L186:           "command": "npx",
L187:           "args": [
L188:             "-y",
L189:             "@supabase/mcp-server-supabase@latest",
L190:             "--project-ref=<project-id>"
L191:           ],
L192:           "env": {
L193:             "SUPABASE_ACCESS_TOKEN": "<token>"
L194:           }
L195:         }
L196:       }
L197:     }
L198: Additional context
L199: 
L200:   * The only differences between the two MCPs are their names and `--project-ref` values
L201:   * Kimi CLI correctly references the specified MCP
L202:   * The issue appears specific to the Kimi Code VSCode extension
