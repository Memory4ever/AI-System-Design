Describe the bug
When using multiple Supabase MCP servers with unique names but similar configurations, Kimi Code in VSCode references the wrong MCP server. This issue does not occur in Kimi CLI, only in the VSCode extension.

To Reproduce

  1. Configure two Supabase MCP servers with unique names (e.g., "Supabase-RSX" and "Supabase-FMMS")
  2. Both MCPs have the same command/args structure, only differing in `--project-ref`
  3. Prompt: "Use Supabase-RSX to check current tables"
  4. Kimi Code incorrectly uses "Supabase-FMMS" instead

Expected behavior
Kimi Code should correctly reference the MCP specified by its unique name (e.g., "Supabase-RSX").

## Problem Description

Currently, the session auto-title feature appears to use the first message to generate the session title. However, when users start a session with the `/yolo` command (which is how YOLO mode is activated), the generated title becomes simply `/yolo`. This makes the auto-title feature lose its usefulness for distinguishing between different sessions.

## Steps to Reproduce

  1. Start a new session
  2. Send `/yolo` to enable `YOLO` mode
  3. Observe that the session title is auto-generated as `/yolo`

## Expected Behavior

The auto-title feature should generate meaningful, distinguishable titles that reflect the actual content/intent of the session, even when starting with slash commands.

## Possible Solutions

### Option 1 (Simple)

Skip built-in slash commands (like /yolo, /settings, etc.) when generating the auto-title. Use the first non-command message instead.

### Option 2 (More Advanced)

Use a multi-turn conversation summary approach to generate titles based on the actual content and context of the conversation, rather than just the first message.
