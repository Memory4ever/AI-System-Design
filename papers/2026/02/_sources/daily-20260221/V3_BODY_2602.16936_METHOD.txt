3 Parallel One-Rank Adaptation for Heterogeneous FFT
In this section, we introduce Fed-PLoRA, a heterogeneous FFT framework that incorporates a new LoRA variant (PLoRA) and a novel local initialization strategy (Select-N-Fold) to eliminate initialization noise and mitigate aggregation noise.

3.1 Motivation
Existing LoRA-based heterogeneous FFT methods Cho et al. (2024); Bai et al. (2024); Wang et al. (2024) that follow the above training framework differ primarily in their initialization and aggregation strategies.
To analyze their effects, we formally define the notions of initialization noise and aggregation noise as follows:
Initialization Noise: During the initialization step of round tt, clients with limited local rank rir_{i} may be unable to fully accommodate the information contained in the global LoRA modules as ri≤Rr_{i}\leq R. This mismatch introduces initialization noise, defined as the total initialization gap across all clients:
𝒩𝖨𝗇𝗂𝗍t:=∑i∈[v](‖𝐀t−1⊖𝐀it−1‖F+‖𝐁t−1⊖𝐁it−1‖F),\displaystyle\mathcal{N}_{\mathsf{Init}}^{t}:=\sum_{i\in[v]}\left(\left\|{\mathbf{A}}^{t-1}\ominus{\mathbf{A}}_{i}^{t-1}\right\|_{F}+\left\|{\mathbf{B}^{t-1}}\ominus{\mathbf{B}}_{i}^{t-1}\right\|_{F}\right),
(2)
where ∥⋅∥F\|\cdot\|_{F} denotes the Frobenius norm, and the operator ⊖\ominus represents a rank-wise subtraction. This metric quantifies the information that resource-constrained clients fail to retain when initializing from the global model. In homogeneous rank settings (i.e., ri=Rr_{i}=R for all i∈[v]i\in[v]), the initialization noise vanishes since all clients can directly adopt the global LoRA modules.
Aggregation noise: After local training, the server receives updated parameters 𝜽it\bm{\theta}^{t}_{i} from each client ii. Following prior works Wang et al. (2024); Sun et al. (2024), we define an ideal model update Δ​𝓦∗t\Delta\bm{\mathcal{W}}_{*}^{t} as the average of the local model updates, and the deviation from this ideal model update defines the aggregation noise, i.e.,
𝒩𝖠𝗀𝗀t:=‖Δ​𝓦∗t−Δ​𝓦t‖F, with ​Δ​𝓦∗t=1v​∑i∈[v]Δ​𝓦it=1v​∑i∈[v]𝐁it​𝐀it,\mathcal{N}_{\mathsf{Agg}}^{t}:=\left\|\Delta{\bm{\mathcal{W}}}_{*}^{t}-\Delta{\bm{\mathcal{W}}}^{t}\right\|_{F},\text{ with }\Delta{\bm{\mathcal{W}}}_{*}^{t}=\frac{1}{v}\sum_{i\in[v]}\Delta{\bm{\mathcal{W}}_{i}^{t}}=\frac{1}{v}\sum_{i\in[v]}\mathbf{B}_{i}^{t}\mathbf{A}_{i}^{t},
(3)
where Δ​𝓦t=𝐁t​𝐀t\Delta\bm{\mathcal{W}}^{t}=\mathbf{B}^{t}\mathbf{A}^{t} represents the actual model update obtained by a specific aggregation method. Ideally, a perfect aggregation method yields 𝒩𝖠𝗀𝗀t=0\mathcal{N}_{\mathsf{Agg}}^{t}=0.
3.2 Parallel One-Rank Adaptation
Before presenting the Fed-PLoRA framework, we first introduce its fundamental building block, PLoRA. The key idea is to replace a single multi-rank LoRA module with multiple parallel one-rank modules.
Concretely, consider applying a LoRA module with rank RR to a target weight matrix 𝓦0∈ℝd×k\bm{\mathcal{W}}^{0}\in\mathbb{R}^{d\times k}. In classical LoRA, this is parameterized by matrices 𝐀∈ℝR×k\mathbf{A}\in\mathbb{R}^{R\times k} and 𝐁∈ℝd×R\mathbf{B}\in\mathbb{R}^{d\times R}, yielding the update Δ​𝓦LoRA:=𝐁𝐀\Delta\bm{\mathcal{W}}_{\text{LoRA}}:=\mathbf{B}\mathbf{A}. In contrast, PLoRA decomposes this rank-RR module into RR parallel one-rank components. For each j∈[R]j\in[R], a PLoRA component consists of a pair of one-rank matrices 𝐀(j)∈ℝ1×k\mathbf{A}_{(j)}\in\mathbb{R}^{1\times k} and 𝐁(j)∈ℝd×1\mathbf{B}_{(j)}\in\mathbb{R}^{d\times 1} (see Figure 1(d)), producing an individual update Δ​𝓦(j)=𝐁(j)​𝐀(j)\Delta\bm{\mathcal{W}}_{(j)}=\mathbf{B}_{(j)}\mathbf{A}_{(j)}. The overall update is simply the sum of these contributions:
Δ𝓦PLoRA:=∑j=1RΔ𝓦(j)=∑j=1R𝐁(j)𝐀(j)=∑j=1R𝐁[:,j]𝐀[j,:]=Δ𝓦LoRA\Delta\bm{\mathcal{W}}_{\text{PLoRA}}:=\sum_{j=1}^{R}\Delta\bm{\mathcal{W}}_{(j)}=\sum_{j=1}^{R}\mathbf{B}_{(j)}\mathbf{A}_{(j)}=\sum_{j=1}^{R}\mathbf{B}_{[:,j]}\mathbf{A}_{[j,:]}=\Delta\bm{\mathcal{W}}_{\text{LoRA}}
which is mathematically equivalent to the classic multi-rank LoRA formulation, since 𝐁(j)=𝐁[:,j]\mathbf{B}{(j)}=\mathbf{B}{[:,j]} and 𝐀(j)=𝐀[j,:]\mathbf{A}{(j)}=\mathbf{A}{[j,:]}.
Thus, PLoRA achieves the same adaptation effect and parameter efficiency as standard multi-rank LoRA, while enabling a modular decomposition that is naturally suited to heterogeneous FTT.
3.3 Fed-PLoRA: Heterogeneous FFT with PLoRA
As in existing approaches, resource-constrained clients can reduce their LoRA ranks to fit limited computational budgets, which naturally results in heterogeneous ranks across clients. Within our framework, this corresponds to adjusting the number of parallel one-rank matrix pairs in the PLoRA modules. However, this adjustment alone does not eliminate initialization and aggregation noise.
To overcome these issues in heterogeneous settings, we propose a novel Select-N-Fold strategy within the Fed-PLoRA framework. This strategy is specifically designed to handle rank heterogeneity, ensuring zero initialization noise and minimizing aggregation noise.
Assume the server maintains global PLoRA parameters 𝜽={{𝐀l}l∈[L],{𝐁l}l∈[L]}\bm{\theta}=\{\{\mathbf{A}^{l}\}_{l\in[L]},\{\mathbf{B}^{l}\}_{l\in[L]}\}, where for each target module l∈[L]l\in[L], 𝐀l:={𝐀(j)l}j∈[R]{\mathbf{A}^{l}}:=\{\mathbf{A}_{(j)}^{l}\}_{j\in[R]} and 𝐁l:={𝐁(j)l}j∈[R]{\mathbf{B}^{l}}:=\{\mathbf{B}_{(j)}^{l}\}_{j\in[R]} represent the RR parallel one-rank PLoRA components. For client ii, the local PLoRA parameters are 𝜽i={{𝐀il}l∈[L],{𝐁il}l∈[L]}\bm{\theta}_{i}=\{\{\mathbf{A}_{i}^{l}\}_{l\in[L]},\{\mathbf{B}_{i}^{l}\}_{l\in[L]}\}, where 𝐀il:={𝐀i,(j)l}j∈[ri]{\mathbf{A}_{i}^{l}}:=\{\mathbf{A}_{i,(j)}^{l}\}_{j\in[r_{i}]} and 𝐁il:={𝐁i,(j)l}j∈[ri]{\mathbf{B}_{i}^{l}}:=\{\mathbf{B}_{i,(j)}^{l}\}_{j\in[r_{i}]} with local rank rir_{i}. The global rank is chosen such that R≥maxi∈[v]⁡riR\geq\max_{i\in[v]}r_{i}.
Fed-PLoRA follows the three-step training framework described in Section 2, and the pseudo-code is shown in Algorithm 1. In each training round tt:
Broadcast and Initialization: The server broadcasts the global PLoRA parameters 𝜽t−1\bm{\theta}^{t-1} to clients.
Each client ii then randomly selects a subset 𝒦it\mathcal{K}_{i}^{t} of rir_{i} parallel one-rank PloRA modules for local training. For clarity, we omit the index ll in the notation, but note that this selection and the subsequence operations are performed independently for each target module l∈[L]l\in[L]. The local PLoRA parameters of client ii are initialized as 𝜽it−1={𝐀(j)t−1,𝐁(j)t−1}j∈𝒦it\bm{\theta}_{i}^{t-1}=\{\mathbf{A}_{(j)}^{t-1},\mathbf{B}_{(j)}^{t-1}\}_{j\in\mathcal{K}_{i}^{t}}.
The remaining (R−ri)(R-r_{i}) parallel one-rank PLoRA modules are temporarily folded into the corresponding pre-trained target module 𝓦0\bm{\mathcal{W}}^{0}, yielding the local target module
𝓦it:=𝓦0+Δ​𝓦fold,it−1=𝓦0+∑j∉𝒦it𝐁(j)t−1​𝐀(j)t−1,\bm{\mathcal{W}}_{i}^{t}:=\bm{\mathcal{W}}^{0}+\Delta\bm{\mathcal{W}}_{\text{fold},i}^{t-1}=\bm{\mathcal{W}}^{0}+\sum_{j\notin\mathcal{K}_{i}^{t}}\mathbf{B}_{(j)}^{t-1}\mathbf{A}_{(j)}^{t-1},
which then remains frozen during local training.
This procedure allows the client to preserve information from the full set of global PloRA modules while training only a subset. Consequently, client ii operates with an effective rank of rir_{i}, matching the parameter count of a standard rank-rir_{i} LoRA configuration, but without incurring initialization noise.
Randomness in Select-N-Fold: Our objective is to obtain a well-trained global PLoRA that can be applied to the pretrained backbone for downstream tasks. When local resource is sufficient (i.e., ri=Rr_{i}=R), all local PLoRA modules can be trained, ensuring that every global PLoRA module is updated. When ri<Rr_{i}<R, trainable modules are selected independently across clients and target modules; hence, in expectation, each global module is updated by some subset of clients in every round. This randomness mitigates the risk of long-term staleness in global PLoRA modules under the Select-N-Fold strategy.
Local Client Update: During local training, each client ii updates only the selected PLoRA modules in 𝒦it\mathcal{K}_{i}^{t}. After optimization, the updated local PLoRA parameters are 𝜽it={𝐀i,(j)t,𝐁i,(j)t}j∈𝒦it\bm{\theta}_{i}^{t}=\{{\mathbf{A}_{i,(j)}^{t},\mathbf{B}_{i,(j)}^{t}}\}_{j\in\mathcal{K}_{i}^{t}}, which are then transmitted to the server.
Server-Side Aggregation: The server aggregates these local PLoRA modules in a rank-wise manner. For each j∈[R]j\in[R], the global PLoRA modules are computed as 𝐀(j)t=1|𝒬(j)t|​∑i∈𝒬(j)t𝐀i,(j)t{\mathbf{A}}^{t}_{(j)}=\frac{1}{|\mathcal{Q}^{t}_{(j)}|}\sum_{i\in{\mathcal{Q}^{t}_{(j)}}}\mathbf{A}_{i,(j)}^{t}, 𝐁(j)t=1|𝒬(j)t|​∑i∈𝒬(j)t𝐁i,(j)t{\mathbf{B}}^{t}_{(j)}=\frac{1}{|\mathcal{Q}^{t}_{(j)}|}\sum_{i\in{\mathcal{Q}^{t}_{(j)}}}\mathbf{B}_{i,(j)}^{t}, where 𝒬(j)t={i|i∈[v],j∈𝒦it}\mathcal{Q}^{t}_{(j)}=\{i|i\in[v],j\in\mathcal{K}_{i}^{t}\} denotes the set of clients that updated module jj in round tt. The aggregated global PLoRA parameters 𝜽t={𝐀t,𝐁t}\bm{\theta}^{t}=\{\mathbf{A}^{t},\mathbf{B}^{t}\} are then used for the next round of training. The process iterates until the global model converges.

FLoRA. As shown in Figure 1 (a), FLoRA employs a stacking-based aggregation method to accommodate LoRA modules from clients with heterogeneous ranks. Each client ii initializes its trainable LoRA modules {𝐀it−1,𝐁it−1}\{\mathbf{A}_{i}^{t-1},\mathbf{B}_{i}^{t-1}\} with rank rir_{i} from scratch (e.g., 𝐀it−1\mathbf{A}_{i}^{t-1} drawn from a normal distribution and 𝐁it−1\mathbf{B}_{i}^{t-1} set to zeros). Before local training, the local target module is replaced with the latest global target module from the server. After local training, the updated LoRA modules {𝐀it,𝐁it}\{\mathbf{A}_{i}^{t},\mathbf{B}_{i}^{t}\} are sent to the server, which concatenates all client updates along the rank dimension to form two large intermediate matrices: {𝐀t∈ℝ(∑i∈[v]ri)×k,𝐁t∈ℝd×(∑i∈[v]ri)}\{\mathbf{A}^{t}\in\mathbb{R}^{(\sum_{i\in[v]}r_{i})\times k},\mathbf{B}^{t}\in\mathbb{R}^{d\times(\sum_{i\in[v]}r_{i})}\}. The global update is then computed as Δ​𝓦FLoRAt=𝐁t​𝐀t/v\Delta\bm{\mathcal{W}}_{\text{FLoRA}}^{t}=\mathbf{B}^{t}\mathbf{A}^{t}/v. On the other hand, the stacking operation in FLoRA preserves the local updates without distortion, leading to zero aggregation noise, i.e., 𝒩FLoRA_Aggt=0\mathcal{N}_{\text{FLoRA\_Agg}}^{t}=0.
