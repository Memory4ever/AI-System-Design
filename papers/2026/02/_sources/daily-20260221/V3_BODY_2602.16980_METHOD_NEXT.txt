3 UniLeak
We present UniLeak, a method for identifying universal activation directions that, when added at inference time, increase the likelihood of generating PII across diverse prompts.
To discover such directions, we focus on the concept of activation steering (Rimsky et al., 2024; Turner et al., 2024), an inference-time technique that controls model behavior by linearly manipulating internal representations.
Setting.
We focus on white-box settings in which the adversary has full access to a target model’s parameters but no access to the data used to train or fine-tune it.
This setting reflects common practice in public model repositories,
such as HuggingFace (Wolf et al., 2020)
The adversary may run the model locally with unlimited query access,
aiming to extract as many PII-containing sequences as possible.
This scenario captures a practical and increasingly relevant risk:
once a model is publicly released,
its internal privacy-leakage properties become directly exploitable,
even without knowledge of the underlying training corpus.
3.1 Constructing the (Self-Generated) Training Dataset
To find features that promote PII leakage, we first construct a dataset of PII-containing sequences.
Prior work often relies on publicly available online text, e.g., Common Crawl (Common Crawl Foundation, 2026); however, this approach may bias UniLeak toward generating out-of-distribution PII not present in the training dataset, lowering recall (and thus attack success).
Instead, we leverage self-generation to directly construct this dataset from the target model, ensuring that all PII and associated contexts remain in-distribution.
Data generation.
To construct training data, we sample generations from the target model using an extraction strategy ℰ\mathcal{E}.
Formally, an extraction strategy ℰ\mathcal{E} specifies (1) a procedure for selecting a prompt pp (potentially adaptively), and (2) a decoding
procedure for sampling outputs conditioned on pp from the target model fθf_{\theta}.
We consider two extraction strategies proposed in prior work.
The first is BOS sampling (Carlini et al., 2021), which generates text from the beginning-of-sequence (BOS) token using top-kk sampling.
The second is
a PII extraction method by Keum et al. (2025) that optimizes single-token prompts likely to elicit PII and then samples from them adaptively.
To generate our training dataset, we sample 200,000200{,}000 generations from fθf_{\theta} using a provided extraction strategy ℰ\mathcal{E}.
This choice follows prior work (Lukas et al., 2023) and empirically yields a sufficient number of PII-containing sequences.
Annotation procedure.
After generating the initial dataset, we annotate all PII-containing subsequences.
Following standard practices (Keum et al., 2025), we use regular expressions to identify structured PII (e.g., emails and phone numbers), and the Flair NER tagger (Akbik et al., 2019) to identify unstructured PII (e.g., personal names).
Our annotation determines only the class of each PII instance and has no prior knowledge of the model’s training data.
Let x=(x1,…,xn)x=(x_{1},\dots,x_{n}) denote a tokenized sequence from the generated dataset.
For a fixed set of PII classes 𝒞\mathcal{C}, we associate each sequence with a set of binary label sequences {l(c)}c∈𝒞\{l^{(c)}\}_{c\in\mathcal{C}}, where l(c)=(l1(c),…,ln(c))l^{(c)}=(l^{(c)}_{1},\dots,l^{(c)}_{n}) and li(c)∈{0,1}l^{(c)}_{i}\in\{0,1\}.
Each label li(c)=1l^{(c)}_{i}=1 indicates that token xix_{i} belongs to a PII span of class cc, and li(c)=0l^{(c)}_{i}=0 if not.
When a PII instance spans multiple tokens, all tokens in the span are assigned the same label.
Finally, for each PII class c∈𝒞c\in\mathcal{C}, we construct a class-specific training dataset 𝒟gen(c)={(x,l(c))|∑ili(c)≥1}\mathcal{D}_{\mathrm{gen}}^{(c)}=\left\{(x,l^{(c)})\;\middle|\;\sum\nolimits_{i}l^{(c)}_{i}\geq 1\right\}
containing all sequence-label pairs with at least one token belonging to cc.
3.2 Identifying Universal PII Directions
We leverage our training data to identify PII-leaking features.
Prior work typically derives such features using difference-in-means (DIM) (Arditi et al., 2024; Turner et al., 2024; Tigges et al., 2024; Rimsky et al., 2024), which computes the difference in mean activations between two contrasting prompt sets.
For example, Arditi et al. (2024) identify refusal features in aligned LLMs by contrasting harmful queries that models refuse with benign queries they answer.
However, DIM suffers from a key limitation in our setting: it requires a large collection of prompts that reliably elicit the target concept.
Unlike previously studied behaviors such as toxicity or refusal, PII generation is uncommon (Carlini et al., 2021), making prompt collection difficult.
Moreover, even when models do generate PII, it is typically not the most likely response, meaning the associated activations primarily encode irrelevant concepts.
We study DIM in Appendix B and show that it struggles to identify features that promote increased likelihood of PII leakage.
To address this, we use gradient-based optimization (Stoehr et al., 2024; Wollschläger et al., 2025).
Rather than requiring prompts that strongly elicit PII, we apply supervised learning with {𝒟gen(c)}c∈𝒞\{\mathcal{D}_{\mathrm{gen}}^{(c)}\}_{c\in\mathcal{C}} to directly identify features that increase the likelihood of generating PII.

3.3 Localizing the Intervention
Algorithm 1 learns PII-leaking directions for arbitrary layers and token positions.
We now present our procedure for localizing the intervention to optimal locations.
Token-level localization.
To steer activations across arbitrary inputs, we require context-independent token positions.
For the models we consider, whose inputs and outputs do not have clear delimiters (unlike chat models), there are two choices: (1) only the first input token (which is guaranteed to exist),
or (2) across all tokens indiscriminately.
We evaluate both approaches.
We optimize directions at all layers of GPT-Neo on the TREC dataset for the email addresses PII class.
In Appendix D, we show the validation loss of Algorithm 1 across optimization steps when intervening at just the first token (T={1}T=\{1\}) versus all tokens (T={1,…,n}T=\{1,\dots,n\}).
The first token is the superior choice, achieving substantially lower loss and stable optimization.
In contrast, intervening at all tokens results in unstable optimization.
This is likely because PII is sparse across output tokens; steering at every token is therefore unnecessary and degrades generation quality (as also shown in Appendix I).
We thus set T={1}T=\{1\} as the intervention location.
Layer-level localization.
The granularity of layer-level interventions introduces a precision–practicality trade-off: intervening at more layers enables more precise control, but modifies a larger number of activations, making such interventions harder to exploit in practical settings (as discussed in §5).
To assess UniLeak across both ends of this trade-off, we consider both all-layer and single-layer interventions.
To intervene at all layers, we set L={1,…,ℓmax}L=\{1,\dots,\ell_{\mathrm{max}}\}, where ℓmax\ell_{\mathrm{max}} is the number of Transformer blocks in fθf_{\theta}; this setting is used in our main evaluation (§4.2).
For single-layer interventions, we evaluate individual layers by independently running Algorithm 1 for selected ℓ∈L\ell\in L.
This procedure is feasible even for several-billion-parameter models, as optimization typically requires less than one hour on a single A40 GPU.
We evaluate single-layer steering in §4.4 and demonstrate its application to practical exploitation in §5.
