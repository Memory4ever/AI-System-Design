4. Trivance
In this section, we elaborate on the design of the Trivance algorithm for performing the AllReduce collective on the ring topology. The fundamental idea of Trivance is to transfer data simultaneously along both directions of the ring, thereby reaching unseen nodes along both ring directions with the same distance. Consequently, Trivance achieves the following properties:
•
Completes the AllReduce collective in ⌈log3⁡n⌉\lceil\log_{3}n\rceil communication steps (Theorem 4.3)
•
Transmits minimal data, ensuring bandwidth-optimality (Lemma 4.1)
•
Improves network congestion by 3×3\times to other latency-optimal approaches by shortcutting the ring
•
Full and uniform utilization of available bandwidth
4.1. Bandwidth-Optimal Algorithm
In the bandwidth-optimal version of Trivance, similar to other bandwidth-optimal algorithms, a Reduce-Scatter is run followed by an AllGather phase (Rabenseifner, 2004; Sensi et al., 2024). Per step kk, each node rr communicates in a network of nn nodes to two peers (πleft,πright\pi_{\text{left}},\pi_{\text{right}}) as follows:
π⁡(r,k,n)=(πleft,πright)={πleft=r−ρ⁡(k)modn,πright=r+ρ⁡(k)modn,\pi(r,k,n)=(\pi_{\text{left}},\pi_{\text{right}})=\begin{cases}\pi_{\text{left}}=r-\rho(k)\bmod n,\\
\pi_{\text{right}}=r+\rho(k)\bmod n,\end{cases}
The distance of communicating nodes is defined by ρ⁡(k)=3k\rho(k)=3^{k}. Since all nodes communicate in both directions with the same distance, the congestion on all links across the network is uniform and equals 3k3^{k} (Θ=2​log3​n3\Theta=\frac{2\log_{3}n}{3}). This selection of peers results in a communication pattern shown in Figure 1, where in the first step each node communicates in both directions with distance one, in the seconds step with distance three and so on. This pattern enables the algorithm, to reach all nodes in the network with fewer communication hops by effectively shortcutting the ring.
During the Reduce-Scatter phase, each node’s local data vector is divided into nn blocks b0,…,bn−1{b_{0},\dots,b_{n-1}}, each of size mn\frac{m}{n}. The total reduction operation is split across all nodes in the network, so that each node rr is responsible for computing a partial reduction over all rr-th blocks brb_{r} collected from every node. Therefore, node rr performs log3⁡n\log_{3}n steps, communicating sequentially with πleft\pi_{\text{left}} and πright\pi_{\text{right}}.
As node rr communicates with its peers, it transmits a specific subset of data blocks rather than its entire data vector. To reach all n−1n-1 other nodes, in each step when node rr communicates to node pp according to π⁡(r,k,n)\pi(r,k,n), rr must send not only the data intended for pp but also the data blocks designated for the nodes that pp will reach in the subsequent steps k+1,…,s−1k+1,\dots,s-1. Consequently, the cumulative size of this data at step kk amounts to m⋅13k+1m\cdot\frac{1}{3^{k+1}}. This means, as the communication distance is tripled each step, the size of sent data by rr is divided by a factor of three. After each step, the received data is aggregated at each node over all blocks. To compute the total transmitted data by node rr across all steps 0,…,s−10,\dots,s-1 of the Reduce-Scatter phase, we sum over each message size to both peers.
Lemma 4.1 (Bandwidth-optimality).
The Trivance algorithm achieves bandwidth-optimality by distributing m⋅(n−1)m\cdot(n-1) unique bytes in log3⁡n\log_{3}n steps per Reduce-Scatter or AllGather phase.

These properties satisfy the conditions for a bandwidth-optimal algorithm achieving minimal bandwidth cost (Δ=1)(\Delta=1) while completing in 2⋅log3⁡n2\cdot\log_{3}n steps (Λ=2\Lambda=2). In the subsequent AllGather phase, the reduced blocks are broadcasted across the network, but in reverse order, tripling the data size each step and reducing the communication distance by a factor of three. By the end of this phase, every node holds the complete global reduction result.
4.2. Latency-Optimal Algorithm
By following the same communication pattern as the bandwidth-optimal version, with the modification of running one phase instead of splitting it into a Reduce-Scatter and AllGather, the latency-optimal Trivance algorithm achieves to complete the AllReduce collective in log3⁡n\log_{3}n steps (Λ=1\Lambda=1). For each step, all nodes forward their entire vector to their peers resulting in m⋅log3⁡nm\cdot\log_{3}n transmitted bytes per node (Δ=log3⁡n\Delta=\log_{3}n) maintaining the same congestion of 3k3^{k} (Θ=n2\Theta=\frac{n}{2}).
Proof of Latency-Optimality for Trivance
Previously, we introduced the design and performance characteristics of the Trivance algorithm for both its latency- and bandwidth-optimal versions. Existing literature (Bruck et al., 1994; Chan et al., 2006) suggests, that the lower bound of required communication steps for two port networks equals ⌈log3⁡n⌉\lceil\log_{3}n\rceil. Therefore, the optimal network sizes for Trivance are powers of three.
In the following, we sketch our proof that Trivance achieves the latency-optimal lower bound for network sizes of 3s3^{s} with s≥1s\geq 1; full proof can be found in Appendix A. Its communication pattern is identical to the Reduce-Scatter phase of the bandwidth-optimal variant, but the transmitted data differs. To establish latency-optimality, it suffices to show that each node rr receives all data vectors from the other n−1n-1 nodes in the network to perform its reduction operation.

This pattern is illustrated in Figure 2, where node rr initially receives blocks only from its direct neighbors. In step k+1k+1, it receives blocks not only from peers pp and qq, but also from their adjacent neighbors, which forwarded their blocks in step kk. As a result, the number of distinct blocks known to rr tripled from step kk to k+1k+1. To prove latency-optimality, we first establish Lemma 4.2, which characterizes the set of nodes rr has obtained data from after step kk. By induction, we show that after step kk, each node has accumulated all data originating from a continuous neighborhood whose radius increases as ∑i=0k3i\sum_{i=0}^{k}3^{i}.
Lemma 4.2 (Block propagation).
After step kk, each node rr holds data originating from nodes within distance RkR_{k}, defined as:
Rk=∑i=0k3i=3k+1−12R_{k}=\sum_{i=0}^{k}3^{i}=\frac{3^{k+1}-1}{2}
In step k+1k+1, communication with peers at distance 3k+13^{k+1} results in entirely previously unseen data, since each peer possesses exactly the complementary, disjoint subset required to contribute the blocks between them. As formalized in Theorem 4.3, exchanging these disjoint data sets therefore increases the covered range by 3k+13^{k+1}, ensuring complete coverage of a network of size nn after ⌈log3⁡n⌉\lceil\log_{3}n\rceil steps.
Theorem 4.3 (Latency-optimality).
Given a network of size nn, Trivance communication pattern requires s=log3⁡ns=\log_{3}n steps for each node rr to receive data from all other n−1n-1 nodes in the network.
This allows Trivance to complete AllReduce and AllGather in log3⁡n\log_{3}n communication steps, matching Bruck’s algorithm and achieving a log2⁡3\log_{2}3 step reduction compared to traditional latency-optimal AllReduce algorithms such as Swing and Recursive Doubling.

To understand the behavior of the Trivance Reduce-Scatter algorithm, we describe its pattern from the perspective of a node rr in a ring network. The AllGather phase functions analogously. For a node rr, at each step kk, the communication peers are determined. Furthermore, for each of rr’s peers, the Block Propagation Algorithm 1 recursively computes the set of nodes reached by communication from rr to p​e​e​rleftpeer_{\text{left}} and p​e​e​rrightpeer_{\text{right}}, respectively. We follow the recursive construction similar to Recursive Doubling, which has also been the basis for the recent Swing algorithm (Sensi et al., 2024). This process effectively builds a forward reachability map, capturing the propagation paths required to ensure correct block forwarding under Trivance’s recursive communication pattern.
