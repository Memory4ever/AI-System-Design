Implementation details.
Our ZO-Muon, as well as baselines LOZO and SubZero treat model parameters as matrices instead of vectors.
Following Muon (Jordan et al., 2024), we flatten the last three dimensions of 4D convolutional parameters and treat them as 2D matrices for optimization. Vector parameters, as well as the input and output layers, are optimized with MeZO.
Hyperparameters.
We adopt hyperparameter settings consistent with existing literature to ensure rigorous benchmarking.
For LLMs, we use a batch size of 16 and train for 20,000 steps, utilizing a constant learning rate without weight decay (Malladi et al., 2023; Chen et al., 2025a; Yu et al., 2025). The perturbation step size is fixed at μ=10−3\mu=10^{-3} based on its demonstrated robustness across tasks (Malladi et al., 2023; Chen et al., 2025a).
For ViT experiments, we set the batch size to 64 (CIFAR-10) and 256 (CIFAR-100). The necessity for increased batch sizes on CIFAR-100 is demonstrated in Fig. 8 and Sec. 5. We also fix the perturbation stepsize μ=10−3\mu=10^{-3}.
For algorithmic hyperparameters (e.g., sparsity for S-MeZO; rank rr and interval vv for subspace-based methods like LOZO and SubZero), we strictly follow the original baseline implementations. For LoRA, we follow previous works (Malladi et al., 2023; Chen et al., 2025a) and set rank r=8r=8 and the scaling factor α=16\alpha=16.
Detailed settings for both ZO and FO methods are listed in Tab. A1.
Computing resources.
Experiments are primarily conducted on A6000 GPUs with 48GB memory. Runtime and GPU consumption evaluation in Tab. 2 are evaluated on A100 GPUs with 100GB memory since A6000 does not have enough memory for OPT-13B full Adam fine-tuning under our setting.

Projection matrix resampling interval
Recall that in ZO-Muon we lazily resample the subspace projection matrix 𝐏\mathbf{P} every 100 steps (denoted by the resampling interval v=100v=100). To validate this design choice, Fig. A4 compares ZO-Muon with different resampling intervals v∈{1,100,500}v\in\{1,100,500\}. As shown, overly frequent resampling does not improve performance on either LLM or ViT fine-tuning. The case of v=1v=1 consistently underperforms v=100v=100, while v=500v=500 achieves performance comparable to v=100v=100. This is because frequent subspace switching (i.e., resampling 𝐏\mathbf{P}) prevents the optimizer from sufficiently exploiting gradient information within a given subspace, leading to less stable training. Our lazy resampling strategy is also aligned with previous works on both FO training (Zhao et al., 2024; Refael et al., 2025a) and ZO training (Chen et al., 2025a; Yu et al., 2025)
