2.1. Latency, Bandwidth & Congestion
In order to reason about the performance of our approach, we revisit the classic latency and bandwidth Hockney model (Hockney, 1994). The communication cost to send mm bytes from point-to-point is modeled as C⁡(m)=α+m⋅βC(m)=\alpha+m\cdot\beta, where α\alpha represents the network latency and β\beta the bandwidth cost per byte, defined as the inverse of the network bandwidth (Rico-Gallego et al., 2019).
Typically in collectives, a data reduction operation is involved, which is represented by a term γ\gamma accounting for the aggregation cost. Since our model and the presented state-of-the-art AllReduce algorithms exhibit comparable aggregation costs, this term is omitted (Rabenseifner, 2004; Ruefenacht et al., 2017).
In our model, multiple messages can share the same physical link, thereby sharing the available bandwidth and causing potential performance degradation.
Following prior work (Sensi et al., 2024; Sack and Gropp, 2015), we adopt a congestion-aware cost model that estimates the completion time of an AllReduce algorithm AA for a message of size mm as:

2.2. AllReduce as a Collective Operation
The optimization of collective algorithms, and thus the effective utilization of communication ports in torus topologies, depends strongly on the workload and network parameters, requiring approaches that either prioritize latency or maximize bandwidth efficiency. AllReduce algorithms operate under the assumption that each node r∈{0,…,n−1}r\in\{0,\dots,n-1\} initially holds a unique local data vector Vr=⟨v0r,v1r,…,vn−1r⟩V^{r}=\langle v_{0}^{r},v_{1}^{r},\dots,v_{n-1}^{r}\rangle of mm bytes, which can be partitioned in at least nn elements. The objective is to compute, for each index r∈{0,…,n−1}r\in\{0,\dots,n-1\}, a global reduction over the set of values {vru∣u∈{0,…,n−1}}\{v_{r}^{u}\mid u\in\{0,\dots,n-1\}\}. Generally, latency-optimal approaches require each node to send its entire vector to every other node. Upon completion, every node possesses the data of all nodes. For the bandwidth-optimal approaches (Rabenseifner algorithm (Rabenseifner, 2004)), the responsibility to reduce index rr of all initial data vectors is typically assigned to node rr. In order for node rr to compute the reduced value for its assigned index, it must receive all corresponding entries vruv_{r}^{u} from every node uu in the network. Consequently, bandwidth-optimal AllReduce algorithms decompose into two phases: a Reduce-Scatter phase and an AllGather phase.
2.3. Optimality for DD-dimensional torus networks for Latency and Bandwidth
The required number of communication steps and transmission delay of collectives are fundamentally constrained by both the number of available communication ports and the underlying network topology. Chan et al. (Chan et al., 2006) establish a tight lower bound for collective communication primitives for DD-dimensional tori including nn nodes, where each node has two ports per dimension for a total of 2​D2D ports. The completion of AllReduce requires at least ⌈log2​D+1⁡n⌉\lceil\log_{2D+1}n\rceil communication steps by constructing a minimal spanning tree over the 2​D2D incident links. For bidirectional rings, this translates to a lower bound of ⌈log3⁡n⌉\lceil\log_{3}n\rceil. With respect to transmission delay, referred to as bandwidth cost by Chan et al.
