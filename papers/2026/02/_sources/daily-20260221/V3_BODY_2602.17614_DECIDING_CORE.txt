In the U-shaped federated split learning (UFSL) settings [10], we divide the local client models into three distinct but connected networks - the head network ℋc\mathcal{H}_{c}, the body network ℬc\mathcal{B}_{c}, and the tail network 𝒯c\mathcal{T}_{c}, with parameters wℋcw_{\mathcal{H}_{c}}, wℬcw_{\mathcal{B}_{c}}, andw𝒯cw_{\mathcal{T}_{c}} respectively - for each client. The head and tail networks for each client reside in the client, while the body network resides in the training server. In this setup, the forward pass is replaced with 𝒯c​(ℬc​(ℋc​(x(i))))\mathcal{T}_{c}(\mathcal{B}_{c}(\mathcal{H}_{c}(x^{(i)}))). The client takes the input sample batch x(i)x^{(i)}, and passes it through the head network ℋ\mathcal{H}, to generate intermediate smashed data 𝒮ℋc​(x(i))\mathcal{S}_{\mathcal{H}_{c}}(x^{(i)}), which is sent to the server, where the body network is utilized to generate server smashed data 𝒮ℬc​(x(i))\mathcal{S}_{\mathcal{B}_{c}}(x^{(i)}), which is sent to the client, and finally passed through the tail network to generate logits. The logits can be converted to predicted class label y^(i)\hat{y}^{(i)}, and the loss can be calculated against the actual class label y(i)y^{(i)} (e.g., cross-entropy loss). Essentially, each client minimizes:

In UFSL, nn clients participate in training their respective head and tail networks, and the training server trains nn distinct body networks—one for each client. At the end of each global iteration, the head, body, and tail networks are sent to the parameter server for aggregation (e.g., using FedAvg). The UFSL setup has two potential points of weakness. The smashed data transmission from the client to the server before the body network processes the input, and the server-to-client transmission after the body network processes the input. In this work, we focus on a federated split learning setup, specifically on the data leakage that might occur from the smashed data sent from the client to the server. Here, we first outline the threat model and then propose a potential solution to mitigate data leakage.
IV-A Threat Model
Similar to [11], we assume an honest, but curious training server. The training server carries out the computation over the body network normally, but is curious about the raw data at the clients. We assume that the training server knows the architecture of the client head network (ℋc\mathcal{H}_{c}), and has access to a dataset 𝐃𝒜\mathbf{D_{\mathcal{A}}} with features similar to the client’s private dataset 𝐃𝐜\mathbf{D_{c}}. As the server has access to the intermediary smashed data from the clients’ head networks, it can then train an inversion network ℐ\mathcal{I}. The network ℐ\mathcal{I} is trained to convert the smashed representation of a sample batch (𝒮ℋc​(x(i))\mathcal{S}_{\mathcal{H}_{c}}(x^{(i)})) to the sample batch x(i)x^{(i)}. In theory, the training server minimizes the following objective function:

where MSE(.)MSE(.) represents the mean squared error loss. In summary, the attacker would train the inversion network to convert the head outputs closer to the actual data.
IV-B Privacy Framework
The overall privacy framework in KD-UFSL comprises two distinct components, which are explained as follows.
IV-B1 Differential Privacy (DP)
DP has seen increasing interest recently in improving data privacy [13] in federated learning (FL). DP attains privacy by adding noise to the individual data samples. Specifically, DP with a Gaussian mechanism adds noise sampled from a normal distribution with mean μ\mu and standard deviation of σ2\sigma^{2}.
