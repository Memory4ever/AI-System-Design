4. Temporal Leakage Evaluation
Figure 1. Overview of the temporal leakage evaluation pipeline. Given a prediction rationale RR, reference time treft_{\text{ref}}, and task context, Phase 1 extracts atomic claims {ci}\{c_{i}\} and assigns each a category label from our taxonomy. Phases 2 and 3 execute in parallel: Phase 2 computes Shapley values {ϕi}\{\phi_{i}\} quantifying each claim’s contribution to the prediction via Monte Carlo sampling; Phase 3 determines leakage indicators {ℓi}\{\ell_{i}\} using category-based rules. We present a four-phase, agent-agnostic framework for detecting and quantifying temporal leakage in prediction rationales. Given rationale RR and reference time treft_{\text{ref}}, the pipeline operates as follows: Phase 1 extracts claims with category labels; Phase 2 computes Shapley values quantifying each claim’s contribution (significance) to the prediction; Phase 3 determines leakage status via category-based rules and external search; Phase 4 aggregates results into interpretable metrics. Phases 2 and 3 execute in parallel; their outputs combine in Phase 4 to produce importance-weighted leakage scores.
4.1. Phase 1: Claim Extraction
The first phase transforms a free-form rationale into structured claims suitable for temporal verification. We formalize extraction as ℰ:R→{(ci,κi)}i=1n\mathcal{E}:R\to\{(c_{i},\kappa_{i})\}_{i=1}^{n}, where each claim cic_{i} is paired with category κi∈{A1,…,B2}\kappa_{i}\in\{\text{A1},\ldots,\text{B2}\}. Each claim must satisfy four properties: atomicity (one verifiable assertion per claim), self-containment (understandable without surrounding context), factuality (objective statement rather than opinion), and temporal grounding (associated with time reference when applicable). Predictions, speculation, and subjective judgments are excluded as they represent reasoning artifacts rather than verifiable facts.
Accurate categorization—particularly distinguishing outcome claims (A4) from general facts—requires task context, the specific target event, and treft_{\text{ref}}. This enables correct identification. The extraction phase outputs a structured set of claims, each annotated with its category, ready for parallel processing in subsequent phases.
4.2. Phase 2: Shapley Value Computation
Not all claims contribute equally to a prediction—a rationale may contain ten claims but only two drive the decision. We quantify this asymmetry using Shapley values, which provide a principled attribution of prediction outcomes to individual claims. Let v:2N→ℝv:2^{N}\to\mathbb{R} be a characteristic function where v⁡(S)v(S) represents the prediction output when only claims in subset SS are provided to the model. The Shapley value for claim cic_{i} is:
(2)
ϕi=∑S⊆N∖{ci}|S|!​(n−|S|−1)!n!​[v⁡(S∪{ci})−v⁡(S)],\phi_{i}=\sum_{S\subseteq N\setminus\{c_{i}\}}\frac{|S|!(n-|S|-1)!}{n!}\left[v(S\cup\{c_{i}\})-v(S)\right],
representing the average marginal contribution of cic_{i} across all possible combinations in which claims could be added. The characteristic function vv is task-specific; we define instantiations for classification, regression, and ranking tasks in Section 6.3.
Exact computation requires 2n2^{n} coalition evaluations, which is intractable for typical rationales containing 10–20 claims. We employ Monte Carlo approximation: ϕ^i=1m​∑k=1mΔi(πk)\hat{\phi}_{i}=\frac{1}{m}\sum_{k=1}^{m}\Delta_{i}^{(\pi_{k})} over mm random permutations, where Δi(πk)\Delta_{i}^{(\pi_{k})} is the marginal contribution when cic_{i} enters according to permutation πk\pi_{k}. This yields unbiased estimates with Var​(ϕ^i)=O⁡(1/m)\text{Var}(\hat{\phi}_{i})=O(1/m).
4.3. Phase 3: Leakage Detection
This phase determines leakage status for each claim using category-based optimization (Section 3.2).
The category-aware leakage indication function is:
(3)
ℓκ​(c,tref)={1if ​κ​(c)∈{A4,A5},0if ​κ​(c)∈{B1,B2},𝟏[τ(c)>tref]otherwise.\ell_{\kappa}(c;t_{\text{ref}})=\begin{cases}1&\text{if }\kappa(c)\in\{\text{A4},\text{A5}\},\\
0&\text{if }\kappa(c)\in\{\text{B1},\text{B2}\},\\
\mathbf{1}[\tau(c)>t_{\text{ref}}]&\text{otherwise}.\end{cases}
For A1–A3 claims requiring search, we query external sources to find the determination date—the earliest time when the claim became publicly verifiable. This differs from dates mentioned within the claim itself. For instance, “Kevin Durant averaged 26.0 PPG in 2018-19” mentions the 2018-19 season, but τ⁡(c)\tau(c) is April 2019 when season statistics were finalized. We apply strict interpretation: τstrict​(c)=sup{t:t​ consistent with temporal reference}\tau_{\text{strict}}(c)=\sup\{t:t\text{ consistent with temporal reference}\}, mapping vague timestamps like “2023” to “2023-12-31” to avoid false negatives. With this category-based optimization, we avoid substantial unnecessary search overhead, yielding significant efficiency gains while maintaining detection accuracy.
4.4. Phase 4: Leakage Metrics
The final phase combines Shapley values (Phase 2) with leakage indicators (Phase 3) to produce interpretable metrics. We propose the Shapley-weighted Decision-Critical Leakage Rate (Shapley-DCLR):
(4)
Shapley-DCLR=∑i=1n|ϕi|⋅ℓ⁡(ci)∑i=1n|ϕi|,\text{Shapley-DCLR}=\frac{\sum_{i=1}^{n}|\phi_{i}|\cdot\ell(c_{i})}{\sum_{i=1}^{n}|\phi_{i}|},
which admits two complementary interpretations.
Interpretation 1: Influence-Weighted Leakage. A higher |ϕi||\phi_{i}| indicates that claim cic_{i} has greater influence on the prediction outcome. Shapley-DCLR thus measures whether the influential claims—those that actually drive the prediction—contain leaked information. High Shapley-DCLR indicates that the claims with substantial predictive influence are temporally contaminated, rendering the prediction unreliable. Conversely, low Shapley-DCLR suggests that even if some leakage exists, it resides in peripheral claims that minimally affect the decision.
Interpretation 2: Weighted Information Composition. Shapley-DCLR weights claims by their decision importance: critical claims occupy a larger share of the denominator, so their leakage status has proportionally greater impact on the metric. This interpretation views Shapley-DCLR as a weighted leakage portion—the fraction of decision-relevant “information” in the rationale that derives from temporally leaked sources.
These interpretations differ in perspective but converge in measurement. Interpretation 1 emphasizes influence attribution: which claims drive the prediction, and are they leaked? Interpretation 2 emphasizes information composition: what fraction of decision-relevant evidence derives from post-cutoff sources? The first perspective is useful for diagnosing whether specific predictions should be trusted; and the second provides a holistic view of rationale contamination. Together, they enable both instance-level diagnosis and aggregate quality assessment.

5. TimeSPEC Architecture
We now present TimeSPEC—a five-phase architecture that proactively prevents leakage during generation. Phase 1 Generator searches for evidence and produces initial prediction with rationale; Phase 2 Supervisor extracts claims, categorizes them, and detects violations; Phase 3 Regenerator produces improved output if violations are found; Phase 4 Resupervisor validates regenerated output; Phase 5 Aggregator synthesizes final prediction from all validated claims logistically with the categories.
5.1. Generator
The Generator receives task input ℐ\mathcal{I} and cutoff date treft_{\text{ref}}, then executes temporally-filtered search through web APIs with explicit date constraints, retrieving only documents published before treft_{\text{ref}}. Evidence is accumulated as ℰ={e1,…,em}\mathcal{E}=\{e_{1},\ldots,e_{m}\}, each tagged with publication date. The phase outputs draft prediction y^draft\hat{y}_{\text{draft}}, rationale RdraftR_{\text{draft}}, and search history ℋgen={(qj,ℰj)}j=1k\mathcal{H}_{\text{gen}}=\{(q_{j},\mathcal{E}_{j})\}_{j=1}^{k}.
API-level temporal filtering provides the first protection layer by ensuring retrieved documents predate treft_{\text{ref}}. However, this cannot prevent the LLM from introducing information from its parametric memory. The model may inadvertently reference outcomes it has seen in its training corpus. This fundamental limitation motivates the Supervisor phase.
5.2. Supervisor
The Supervisor performs rigorous verification of every claim in the draft rationale. It extracts claims from RdraftR_{\text{draft}} with category labels in Table 1, then applies Equation (3) to determine leakage status. Claims are partitioned into valid set 𝒞valid(1)\mathcal{C}_{\text{valid}}^{(1)} (where ℓ⁡(c)=0\ell(c)=0) and violated set 𝒞violated(1)\mathcal{C}_{\text{violated}}^{(1)} (where ℓ⁡(c)=1\ell(c)=1). Regeneration triggers when any violation exists: ℐregenerate=𝟏[|𝒞violated(1)|>0]\mathcal{I}_{\texttt{regenerate}}=\mathbf{1}\left[|\mathcal{C}_{\text{violated}}^{(1)}|>0\right].
