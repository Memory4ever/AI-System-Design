5.1. Evaluation Setup
We evaluate our design on 286 real-world GUI tasks: 100 in-house, 116 from WebVoyager (He et al., 2024) (643 total), and 70 from ScreenAgent (Niu et al., 2024) (70 sessions). Tasks span local applications, web platforms, productivity tools, and cross-application workflows.
For task mining, we collect 30 active hours of interaction traces across 18 sessions, yielding 113 trace files. The mined corpus is intentionally distribution-shifted from the test suite: traces skew toward Local/App, while the evaluation set contains more Web/Crossover tasks. The traces cover 36 domains, whereas the 286-task suite spans 63 domains; only 22 overlap (34.92%), leaving 41 unseen test domains (65.07%). This setup stresses generalization of mining and retrieval rather than memorization. Domain distributions are detailed in Appendix D.
For model training, we used a learning rate of 1×10−31\times 10^{-3}, with λpred=0.1\lambda_{\mathrm{pred}}=0.1, λrec=0.05\lambda_{\mathrm{rec}}=0.05, and a contrastive temperature τ=0.1\tau=0.1.
All agents use the same atomic GUI action interface and identical timeout policies. We report task success (74.83%), average completion ratio (91.14%), Step Efficiency Ratio(successful steps / actual execution steps; higher is better). Differences are reported in percentage points (pp).

Ablated model, greedy retrieval picks the top-3 most similar past intent units without filtering. This helps inject traces but often pulls in mismatched routines, causing drift in long sequences.
I​G/S​GIG/SG gating restricts retrieval to representation-learned intent groups and subgroups, ensuring retrieved traces align with the current intent rather than arbitrary matches.
As shown in Table 1, starting from a no-trace baseline (22.73%), simply adding user traces with greedy retrieval lifts success by +23.7 percentage points (pp) and increases plan completion +23.65 pp. The gain stems from injecting user-specific web/app workflows, which improves both screen interpretation and execution-flow understanding, though long sequences still drift. Adding I​G/S​GIG/SG gating confines retrieval to intent-coherent groups/subgroups, yielding more accurate partial plans and increasing success +8.21 pp over greedy while markedly boosting completion +20.13 pp. Plan-memory reuse further raises success +7.87 pp and completion +7.44 pp by binding cached stored plans GG rather than re-synthesizing. Finally, skill hints fill missing plan units/steps on partial matches, improving success to 74.83% (+12.32 pp) and completion to 91.14% (+6.14 pp).
5.3. Case Study
To illustrate the behavior of the proposed framework, we present a case where the user asks the system to summarize a previously viewed video about lightweight-ML and record the result in a personal workspace.
The system interprets this request as a multi-intent task involving retrieval, reasoning, and organization across different applications.
Figure 4. IntentCUA in action: the system recalls intent units from memory and decomposes a multi-application command into intent-level plan units, each executed through learned skills and recomposed into an end-to-end automation plan.
Figure 4 shows how the system handles this command through three main processes.
First, the Planner interprets the command and retrieves relevant traces from the plan memory that include traces involving a video platform, AI chat-bot, and workspace app and, crucially, recovers the video’s source from the user’s prior viewing trace.
Based on these retrieved traces, it constructs a structured breakdown into four plan units, reflecting the GUI context, the abstracted action sequence, and the personalized information required to fulfill the corresponding intent.
Each unit is grounded by the Plan-Optimizer into executable GUI actions, while the Critic monitors progress and triggers local re-planning when necessary.
Through this hierarchical reasoning and memory-guided skill retrieval, the system autonomously executes a multi-application task, demonstrating consistent intent understanding across heterogeneous software environments.
In contrast, when a pop-up window unexpectedly appears during execution, the system encounters a failure case.
Because the underlying GUI components remain hidden beneath the pop-up, the grounding module fails to detect them, leading the Critic to assume that the intended component no longer exists on the screen.
This case highlights a limitation of script-based GUI grounding, which lacks visual awareness of interface changes such as transient pop-ups or overlays.
6. Experiments
We compare IntentCUA against two representative desktop GUI agents chosen for methodological diversity:
UI-TARS-1.5 (Seed, 2025), an RL-based visual planner–executor with self-evolving policies and screen grounding, and
UFO2 (Zhang et al., 2025b), a trajectory-centric Windows automation agent that organizes demonstrations as executable sequences.
Together these baselines span reinforcement learning–driven automation versus demonstration-driven planning, and both operate at the level of atomic GUI actions, ensuring comparability with our interface.
We evaluate 286 tasks (the same evaluation suite described in Section 5.1) and report task success rate, Step Efficiency Ratio(SER), and Latency, further analyzing robustness by step-length bins, each step defined as a atomic action performed by the agent. SER is defined as the ratio of successful steps to total steps, ranging from 0 to 1.
Latency is measured as the execution time per task, reflecting not only the number of steps but also the overhead of perception and planning.
