L206: 
L207: This PR documents critical security vulnerabilities discovered during a security audit, along with proof-of-concept exploits demonstrating their impact.
L208: ### Summary of Findings
L209: 
L210: Vulnerability Severity File POC Result
L211: Shell Command Injection MEDIUM `nanobot/agent/tools/shell.py` 15/15 bypasses successful
L212: Path Traversal MEDIUM `nanobot/agent/tools/filesystem.py` 15/17 operations successful
L213: LiteLLM RCE (CVE-2024-XXXX) CRITICAL Dependency 3 vulnerable patterns found
L214: 
L215: * * *
L216: ### Vulnerability 1: Shell Command Injection
L217: 
L218: Location: `nanobot/agent/tools/shell.py:75`
L219: 
L220: Issue: The `ExecTool` uses `asyncio.create_subprocess_shell()` which passes user input directly to the shell. The regex blocklist (lines 12-19) only blocks specific patterns like `rm -rf /` and fork bombs, but is trivially bypassed.
L221: 
L222: Bypasses Demonstrated:
L223:   * Command substitution: `echo $(cat /etc/passwd)` ✅
L224:   * Base64 encoding: `echo Y2F0IC9ldGMvcGFzc3dk | base64 -d | bash` ✅
L225:   * Python execution: `python3 -c 'import os; os.system("id")'` ✅
L226:   * Environment exfiltration: `env | grep -i key` ✅
L227: 
L228: Impact: Arbitrary command execution, sensitive data exfiltration, potential container escape
L229: 
L230: Recommended Fix:
L231:     # Replace create_subprocess_shell with create_subprocess_exec
L232:     import shlex
L233:     args = shlex.split(command)
L234:     process = await asyncio.create_subprocess_exec(*args, ...)
L235: 
L236: * * *
L237: ### Vulnerability 2: Path Traversal / Unrestricted File Access
L238: 
L239: Location: `nanobot/agent/tools/filesystem.py`
L240: 
L241: Issue: The `_validate_path()` function (line 9) accepts a `base_dir` parameter to restrict file access, but no tool ever passes this parameter, allowing unrestricted access to the entire filesystem.
L242: 
L243: Vulnerable Code:
L244: 
L245:     # _validate_path supports restriction but it's never used:
L246:     def _validate_path(path: str, base_dir: Path | None = None)
L247:     # All tools call without base_dir:
L248:     is_valid, result = _validate_path(path)  # No restriction!
L249: 
L250: Operations Demonstrated:
L251: 
L252:   * Read `/etc/passwd` ✅
L253:   * Read `/proc/self/environ` (environment variables with API keys) ✅
L254:   * Write to `/tmp/` and user directories ✅
L255:   * List any directory on the system ✅
L256: 
L257: Impact: Read sensitive files, write malicious files, enumerate system
L258: 
L259: Recommended Fix:
L260: 
L261:     WORKSPACE_DIR = Path(config.workspace).resolve()
L262:     async def execute(self, path: str, **kwargs) -> str:
L263:         is_valid, result = _validate_path(path, base_dir=WORKSPACE_DIR)
L264: 
L265: * * *
L266: ### Vulnerability 3: LiteLLM Remote Code Execution
L267: 
L268: CVE: CVE-2024-XXXX (multiple related CVEs)
L269: Affected Versions: litellm <= 1.28.11 and < 1.40.16
L270: 
L271: Issue: Multiple `eval()` usages in litellm that can be triggered with crafted input:
L272: 
L273: File Risk
L274: `litellm/utils.py` Template injection
L275: `litellm/proxy/ui_sso.py` Config injection
L276: `litellm/proxy/pass_through_endpoints.py` Config injection
L277: `arize_phoenix_prompt_manager.py` Unsandboxed Jinja2 SSTI
L278: Impact: Arbitrary code execution, full server compromise
L279: 
L280: Recommended Fix:
L281: 
L282:     # Pin to specific patched version in pyproject.toml
L283:     dependencies = [
L284:         "litellm==1.61.15",  # Pin exact version, not >=
L285:     ]
L286:
