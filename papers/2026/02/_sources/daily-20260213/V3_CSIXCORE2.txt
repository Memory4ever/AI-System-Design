L92: # Token-Efficient Change Detection in LLM APIs
L93: Timothée Chauvin Affiliation: Université de Rennes, Inria, CNRS/IRISA (Rennes, France) Correspondence to: https://tchauvin.com/contact    Clément Lalanne Affiliation: Univ Toulouse, INUC, UT2J, INSA Toulouse, TSE, CNRS, IMT, Toulouse, France Affiliation: ANITI Toulouse    Erwan Le Merrer Affiliation: Université de Rennes, Inria, CNRS/IRISA (Rennes, France)    Jean-Michel Loubes Affiliation: Inria Affiliation: Regalia Affiliation: ANITI Toulouse    François Taïani Affiliation: Université de Rennes, Inria, CNRS/IRISA (Rennes, France)    Gilles Tredan Affiliation: LAAS, CNRS, (Toulouse, France)
L94: ###### Abstract
L95: 
L96: Remote change detection in LLMs is a difficult problem. Existing methods are either too expensive for deployment at scale, or require initial white-box access to model weights or grey-box access to log probabilities. We aim to achieve both low cost and strict black-box operation, observing only output tokens.
L97: Our approach hinges on specific inputs we call Border Inputs, for which there exists more than one output top token. From a statistical perspective, optimal change detection depends on the model’s Jacobian and the Fisher information of the output distribution. Analyzing these quantities in low-temperature regimes shows that border inputs enable powerful change detection tests.
L98: Building on this insight, we propose the Black-Box Border Input Tracking (B3IT) scheme. Extensive in-vivo and in-vitro experiments show that border inputs are easily found for non-reasoning tested endpoints, and achieve performance on par with the best available grey-box approaches. B3IT reduces costs by $30\times$ compared to existing methods, while operating in a strict black-box setting.

L104: ## 1 Introduction
L105: LLM APIs are increasingly embedded in high-impact applications, such as software engineering (cite80†Zheng et al., 2025 ), yet users have no guarantee that the model behind an endpoint remains unchanged. Providers may modify models for safety updates, cost optimization, or infrastructure changes, often without notice. Quietly deploying quantized versions to reduce costs, for instance, could degrade performance on tasks users depend on.
L106: Such changes are not hypothetical: Grok on X suffered three incidents in 2025 where modified system prompts were deployed due to rogue employees or bad updates (cite81†Babuschkin, 2025 ; cite82†xAI, 2025a ; cite83†xAI, 2025b ). Anthropic experienced infrastructure bugs in 2025 that degraded Claude’s responses, which remained undetected for weeks despite affecting 16% of Claude Sonnet 4 requests at peak (cite84†Anthropic, 2025 ).
L107: Several change-detection methods have been proposed (cite85†Gao et al., 2025 ; cite86†Bai et al., 2025 ; cite87†Gubri et al., 2024 ; cite88†Chauvin et al., 2026 ). However, they face a fundamental tension between access requirements and cost. White-box methods like ESF (cite86†Bai et al., 2025 ) and TRAP (cite87†Gubri et al., 2024 ) craft sensitive inputs using model internals (embeddings, gradient-based optimization), limiting their use to known models.
L108: Grey-box methods like LT (cite88†Chauvin et al., 2026 ) require log-probabilities, which are available only on a fraction of public endpoints. Fully black-box approaches like MET (cite85†Gao et al., 2025 ) avoid these requirements but demand many queries to the tracked model, making continuous monitoring prohibitively expensive.
L109: We introduce B3IT (Black-Box Border Input Tracking), a change-detection method that operates in a strict black-box setting, observing only output tokens, while achieving accuracy and cost efficiency comparable to grey-box approaches. Our key insight, brought by a theoretical analysis, is that at low temperature, inputs where two tokens are nearly tied as the top prediction (“border inputs”) become extremely sensitive detectors.
L110: In other words, even tiny model changes can dramatically alter the output distribution. We show theoretically that this sensitivity diverges as temperature tends to zero, exhibiting a phase transition between detectable and undetectable regimes.
L111: B3IT exploits this phenomenon: it discovers border inputs through black-box sampling, then monitors for changes by comparing output distributions. Surprisingly, border inputs are easy to find on most production models. The result is a method that detects subtle changes at $1/30$th the cost of alternatives, enabling large-scale continuous and cost-effective API monitoring.
L112: ##### Contributions.
L113: (1) We establish theoretical foundations for change detection in LLMs, revealing a phase transition at low temperature that enables high-sensitivity detection without model access. (2) We propose B3IT, a practical black-box method that identifies border inputs and uses them for efficient change detection. (3) We validate B3IT in vitro on TinyChange (cite88†Chauvin et al., 2026 ), achieving detection performance comparable with grey-box methods at $1/30$th the cost of the next best black-box baselines.
L114: (4) We demonstrate B3IT in vivo on 93 endpoints (64 models, 20 providers), showing broad applicability for continuous monitoring.
L115: Roadmap. cite8†Section 2 describes our system model. cite12†Section 3 presents the theoretical analysis underpinning the B3IT method, which we describe in cite19†Section 4 and evaluate in cite26†Section 5 .
L116: 
L117: Code. All our code is open-source at cite89†github.com/timothee-chauvin/token-efficient-change-detection-llm-apis†github.com .
L118: ## 2 System model
L119: 
L120: In this paper, we take the perspective of an unprivileged user facing a black-box API exposing an LLM $f_{\theta}$, where $\theta\in\Theta$ denotes the (unknown) model parameters. The user can only submit queries $(x,T)$ for some input $x\in\mathcal{X}$ and temperature $T\in\mathbb{R}^{+}$, and collect the answer $f_{\theta}(x,T)$.
L121: ##### Change detection.
L122: We consider a two-stage interaction: an initialization stage and a detection stage. Let $\theta_{0}$ denote the model parameters during initialization and $\theta_{1}$ during detection. The change detection problem consists in deciding whether $\theta_{0}=\theta_{1}$, as in prior work (cite85†Gao et al., 2025 ; cite88†Chauvin et al., 2026 ). Formalized as a hypothesis test, let $H_{0}:=\theta_{0}=\theta_{1}$ (the model hasn’t changed) versus $H_{1}:=\theta_{0}\neq\theta_{1}$ (the model has changed).
L123: In this endeavor, we are interested in two key quantities:
L124: 
L125:   * •
L126: 
L127: Detector accuracy: we want to minimize false positives (incorrectly detecting a change) and false negatives (missing actual changes). Formalizing a test as a (possibly randomized) function $\phi$ taking values in $[0,1]$, we therefore seek to minimize $\mathbb{P}(\phi=1|H_{0})+\mathbb{P}(\phi=0|H_{1})$.
L128: 
L129:   * •
L130: Cost: for wide-scale monitoring of LLM APIs, detecting changes should induce a minimal cost. This is especially true of the detection stage, which is run repeatedly.
L131: ##### Types of changes.
L132: Deployed LLMs can undergo many kinds of modifications: fine-tuning (full or Low-Rank Adaptation (cite90†Hu et al., 2022 )), quantization, model distillation, system prompt changes, or further Reinforcement Learning. Infrastructure can also affect outputs: CUDA versions, GPU selection, compiler optimizations, or routing errors directing requests to misconfigured servers (cite84†Anthropic, 2025 ).
L133: The intensity of any such modification determines detection difficulty; our focus is on query-efficient detection, regardless of the change’s origin or intensity.
L134: For the theoretical analysis, we model parameter changes as $\theta_{1}:=\theta_{0}+\epsilon h$ where $h\in\mathbb{S}^{q-1}$ is a unit direction and $\epsilon$ controls magnitude. This local perturbation model enables tractable analysis via the Local Asymptotic Normality framework (cite12†Section 3 ). In experiments, we directly evaluate on realistic updates (fine-tuning, pruning, etc.) across a range of change magnitudes, and on live LLM APIs.
L135: ##### Single-token perspective.
L136: 
L137: Our analysis focuses on the first output token from a single query. While approaches such as MET (cite85†Gao et al., 2025 ) leverage multiple output tokens, inter-token dependencies complicate the analysis substantially. However, multiple queries from different prompts can be combined for improved performance, which we demonstrate experimentally.
L138: ## 3 Theoretical analysis and guidelines
L139: 
L140: Building on optimal change detection in the sense of Neyman–Pearson (cite91†Neyman and Pearson, 1933 ), we exhibit a new phase-transition phenomenon for LLMs (cite92†Theorem 3.3 ). At temperature $T\ll 1$, inputs where two or more tokens share the maximal logit become extremely sensitive to parameter changes: we call these Border Inputs (BIs). This result provides the theoretical foundation for B3IT, which we introduce in cite19†Section 4 .
L141: ### 3.1 Rationale
L142: 
L143: Testing whether two LLMs differ reduces to testing whether they induce different probability distributions over tokens. We focus on the distribution of the first generated token and, for analytical tractability, assume independence across generations.
L144: Since the token distribution is finite, the problem formally reduces to multinomial hypothesis testing, a classical setting with an extensive literature directly studying the problem, or related ones such as estimation (cite93†Balakrishnan and Wasserman, 2019 ; cite94†Berrett and Butucea, 2020 ; cite95†Cai et al., 2024 ; cite96†Aliakbarpour et al., 2024 ; cite97†Cressie and Read, 2018 ; cite98†Barron, 1989 ; cite99†Kim, 2019 ; cite100†Acharya et al., 2019 ; cite101†Acharya et al., 2018 ; cite102†Kairouz et al., 2016 ; cite103†Acharya et al., 2017a ; cite104†Acharya et al., 2017b ; cite105†Louati, 2025 ).
L145: However, these generic results do not account for the structure of LLMs, or for the ability to design informative input prompts. We therefore analyze how prompt choice and sampling temperature shape sensitivity to model perturbations, ultimately identifying BIs as appealing test inputs.
L146: ### 3.2 The Local Asymptotic Normality Framework
L147: 
L148: Let $\mathbf{p}=(p_{1},\dots,p_{d-1})\in(0,1)^{d-1}$ denote the reduced parametrization of the categorical output distribution, with $p_{d}:=1-\sum_{i=1}^{d-1}p_{i}>0$. The vector $\mathbf{p}$ models the output distribution over tokens, where $d$ is the vocabulary size. We adopt this reduced parametrization to isolate the free variables. Querying the model $n$ times on the same input yields i.i.d. samples $Y_{1},\dots,Y_{n}\sim\mathbf{p}$.
L149: We define the reduced empirical frequency estimator $T_{n}:=\hat{p}:=(\hat{p}_{1},\dots,\hat{p}_{d-1}),\hat{p}_{j}:=\frac{1}{n}\sum_{i=1}^{n}\mathbf{1}\{Y_{i}=j\}\;.$ This estimator is unbiased and satisfies $\mathrm{Cov}_{\mathbf{p}}(T_{n})=\frac{1}{n}F(\mathbf{p})$, where $F(\mathbf{p}):=\mathrm{diag}(\mathbf{p})-\mathbf{p}\mathbf{p}^{T}$ is the inverse of the Fisher information matrix of the distribution $\mathbf{p}$.
L150: Since $T_{n}$ is a sufficient statistic, it contains all the information needed to construct optimal tests.
L151: Consider two sets of model parameters $\theta_{0}$ and $\theta_{1}$, inducing token distributions $\mathbf{p}_{0}$ and $\mathbf{p}_{1}$, respectively. By the Central Limit Theorem (see (cite106†van der Vaart, 1998 ), Example 2.18), the statistic $T_{n}$ admits the asymptotic Gaussian approximation $T_{n}\sim\mathcal{N}\left(\mathbf{p}_{k},\frac{1}{n}F(\mathbf{p}_{k})\right),k\in\{0,1\}.$
L152: Let $\theta\in\Theta\subset\mathbb{R}^{q}$ denote the model parameters, let $x_{\mathrm{test}}$ be the prompt used for testing, and define the reduced output map $g(\theta,x_{\mathrm{test}}):=f(\theta,x_{\mathrm{test}})_{1:(d-1)}\in(0,1)^{d-1}\;.$ We consider a perturbation of the parameters of the form $\theta\mapsto\theta+\epsilon h,h\in\mathbb{S}^{q-1},$ and write $\mathbf{p}_{1}:=g(\theta+\epsilon h,x_{\mathrm{test}}),\mathbf{p}_{0}:=g(\theta,x_{\mathrm{test}}).$
L153: In order to better understand the regime under which we analyze tests, we first explain what goes wrong without the right approach. In practice, we aim to detect very small parameter changes, i.e. $\epsilon\ll 1$. If $\epsilon\to 0$ (used to model a small perturbation) too quickly, and for the sake of reasoning, assume the above Gaussian approximation for $T_{n}$ holds, the distributions of $T_{n}$ under $\mathbf{p}_{0}$ and $\mathbf{p}_{1}$ become indistinguishable, making testing impossible.
L154: We analyze the problem in this regime not as an extra assumption, but as the natural framework that makes the testing problem meaningful.
L155: A meaningful theory emerges by considering small parameter perturbations in the Local Asymptotic Normality (LAN) regime (see (cite106†van der Vaart, 1998 ), Chapters 7 and 16), which we now introduce. This framework is central in statistics, as it characterizes the regime in which hypothesis testing is neither trivial nor impossible.
L156: Assuming $g(\theta,x_{\mathrm{test}})$ is differentiable with respect to $\theta$, we consider local perturbations of the form $\epsilon_{n}=\frac{s}{\sqrt{n}}$ for $s\in\mathbb{R}$ fixed, and obtain the expansion $\mathbf{p}_{n}:=\mathbf{p}_{\epsilon_{n}}=\mathbf{p}_{0}+\epsilon_{n}Jh+r_{n}$, where $J:=\nabla_{\theta}g(\theta,x_{\mathrm{test}})$ is the Jacobian of the reduced output distribution w.r.t.
L157: the model parameters, and $\sqrt{n}\|r_{n}\|\to 0.$ This corresponds to a small parameter perturbation in direction $h$ at the critical rate that preserves nontrivial asymptotic effects.
L158: Leveraging the perspective of this regime leads to the following result, which quantifies the asymptotic power of optimal tests.
L159: ###### Theorem 3.1 (Optimal Tests in the LAN Regime).
L160: 
L161: Let $\alpha\in(0,1)$. If $(\phi_{n})$ is a sequence of tests such that, for every $n$, $\phi_{n}$ is the test with the lowest Type-II error among all tests with Type-I error at most $\alpha$ in testing $\mathbf{p}_{0}$ vs $\mathbf{p}_{n}$, then
L162: 
L163:  | $\displaystyle\text{Type-II}$  | $\displaystyle(\phi_{n})\to\mathbb{P}\left(\mathcal{N}\left(0,1\right)\leq Q_{\alpha}-\sqrt{s^{2}\mathrm{SNR}^{2}(h)}\right)$  |  | (1)
L164: where $\mathrm{SNR}^{2}(h):=h^{T}(J^{T}F(\mathbf{p}_{0})^{-1}J)h$, and $\text{Type-II}(\phi_{n})$ refers to the error of $\phi_{n}$ under $\mathbf{p}_{n}$, and where $Q_{\alpha}$ is the quantile of order $1-\alpha$ of $\mathcal{N}(0,1)$.
L165: ###### Proof.
L166: 
L167: See cite57†Section B.2 . ∎
L168: 
L169: This result is central to our theory, as it shows that the viability of the optimal (and thus any) test is entirely characterized by a single scalar quantity, $\mathrm{SNR}^{2}(h)$, which captures the intrinsic difficulty of the testing problem: the higher it is, the easier the test. It conveniently takes the form of a signal-to-noise ratio, where the signal is the change in intensity, and the noise comes from temperature sampling.
L170: ##### Takeaway.
L171: In the small-variation regime, optimal change detection is governed by three elements: the tampering direction $h$, the Jacobian of the model, and the Fisher information of the output token distribution, combined through the criterion $\mathrm{SNR}^{2}(h)$. The Jacobian controls the signal: a large Jacobian amplifies how parameter perturbations affect the output distribution.
L172: The Fisher information controls the noise: a well-conditioned (low-variance) output distribution reduces sampling uncertainty and improves detectability.
L173: Balancing these effects may seem difficult in a black-box setting. We show, however, that tuning the sampling temperature provides concrete control over this trade-off.
L174: ### 3.3 Decomposition for LLMs: exploiting the last layer
L175: 
L176: A key observation underlying our theory is that, for LLMs, the expression of $\mathrm{SNR}^{2}(h)$ can be further simplified by making the transformer architecture explicit.
L177: Let $r(\theta,x_{\mathrm{test}})\in\mathbb{R}^{m}$ denote the representation produced by the model up to the last layer. The final layer is a linear head $(W,b)$ producing logits $z(\theta)=z(\theta,x_{\mathrm{test}})=Wr(\theta,x_{\mathrm{test}})+b\in\mathbb{R}^{d}.$ Given a temperature $\tau>0$, the output token distribution is computed as the softmax of the logits: $p^{(\tau)}_{i}(\theta)=\frac{\exp(z_{i}(\theta)/\tau)}{\sum_{j=1}^{d}\exp(z_{j}(\theta)/\tau)},$ for $i=1,\dots,d$.
L178: We will write $\mathbf{p}^{(\tau)}(\theta)\in\mathbb{R}^{d}$ for the full vector and $\mathbf{p}^{(\tau)}_{1:(d-1)}(\theta)\in\mathbb{R}^{d-1}$ for its reduced coordinates.
L179: We define the full matrix $\Sigma(\mathbf{p}):=\operatorname{diag}(\mathbf{p})-\mathbf{p}\mathbf{p}^{T}\in\mathbb{R}^{d\times d}$, and recall the reduced matrix $F(\mathbf{p}_{1:(d-1)}):=\operatorname{diag}(\mathbf{p}_{1:(d-1)})-\mathbf{p}_{1:(d-1)}\mathbf{p}_{1:(d-1)}^{T}\in\mathbb{R}^{(d-1)\times(d-1)}$. We use these two different notations to better distinguish reduced coordinates from full coordinates.
L180: We write the parameters as $\theta=(\theta_{\mathrm{pre}},W,b)$, where $\theta_{\mathrm{pre}}$ collects all parameters before the head, so that $r(\theta,x_{\mathrm{test}})=r(\theta_{\mathrm{pre}},x_{\mathrm{test}})$. We define $J_{r}(\theta_{\mathrm{pre}}):=\frac{\partial r(\theta_{\mathrm{pre}},x_{\mathrm{test}})}{\partial\theta_{\mathrm{pre}}}\in\mathbb{R}^{m\times q_{\mathrm{pre}}}.$ Then the Jacobian of the logits w.r.t.
L181: the full parameter vector $J_{z}(\theta)\in\mathbb{R}^{d\times(q_{\mathrm{pre}}+dm+d)}$ decomposes as $J_{z}(\theta)=\Big[\underbrace{WJ_{r}(\theta_{\mathrm{pre}})}_{\in\mathbb{R}^{d\times q_{\mathrm{pre}}}}\Big|\underbrace{r(\theta_{\mathrm{pre}},x_{\mathrm{test}})^{T}\otimes I_{d}}_{\in\mathbb{R}^{d\times(dm)}}\Big|\underbrace{I_{d}}_{\in\mathbb{R}^{d\times d}}\Big]$.
L182: Finally, let $J^{(\tau)}(\theta):=\frac{\partial\mathbf{p}^{(\tau)}_{1:(d-1)}(\theta)}{\partial\theta}\in\mathbb{R}^{(d-1)\times(q_{\mathrm{pre}}+dm+d)}$ be the Jacobian of the reduced output map.
L183: ###### Lemma 3.2 ($\mathrm{SNR}^{2}(h)$ in LLMs).
L184: 
L185: For any $\tau>0$,
L186: 
L187:  | $$\mathrm{SNR}^{2}(h)=\frac{1}{\tau^{2}}h^{T}\left(J_{z}(\theta)^{T}\Sigma\left(\mathbf{p}^{(\tau)}(\theta)\right)J_{z}(\theta)\right)h.$$  |  | (2)
L188: ###### Proof.
L189: 
L190: See cite58†Section B.3 . ∎
L191: 
L192: Although purely technical, this result is crucial to our theory: it renders the analysis tractable for LLMs, with the simplification of the inner inverse arising from the structure of the softmax layer, and enables the derivation of our main result.
L193: ### 3.4 The Zero-Temperature Limit
L194: 
L195: We now have all the ingredients to study the low-temperature regime and present our main theoretical result. Let $z:=z(\theta)$ and define the set of maximizers $\mathcal{M}:=\left\{i\in\{1,\dots,d\}:z_{i}=\max_{1\leq j\leq d}z_{j}\right\},k:=|\mathcal{M}|$.
L196: 
L197: We further define $\Sigma_{\mathcal{M}}$ as the operator $\Sigma$ applied to the probability vector assigning uniform mass to $\mathcal{M}$ and zero mass elsewhere.

L213: ###### Remark 3.4 (On the condition $h^{T}\left(J_{z}^{T}\Sigma_{\mathcal{M}}J_{z}\right)h\neq 0$).
L214: 
L215: At first glance, the condition $h^{T}\left(J_{z}^{T}\Sigma_{\mathcal{M}}J_{z}\right)h\neq 0$ may appear restrictive. However, as discussed in cite60†Section B.5 , it holds for almost every direction $h$. In particular, if $h$ is not degenerate and is, for instance, modeled as a continuous random perturbation of the parameters, this condition is satisfied with probability one.
L216: ##### Takeaway.
L217: At very low temperature, detectability exhibits a sharp dichotomy. If the output distribution collapses to a single token, then $\mathrm{SNR}^{2}(h)\to 0$ and detection becomes nearly impossible: the distribution converges so rapidly to a Dirac mass that small parameter perturbations cannot alter the outcome.
L218: If at least two logits are tied, $\mathrm{SNR}^{2}(h)$ diverges and detectability is maximal: in the presence of ties, arbitrarily small parameter changes can force the model to select a single mode, making unimodal versus multimodal behavior easy to test. Moreover, under the conditions of Theorem 3.3, this divergence is obtained regardless of the model’s weights, enabling a black-box approach.
L219: A natural strategy for change detection is therefore to select $x_{\mathrm{test}}$ such that the logit distribution has at least two maximal entries. These inputs (termed Border Inputs or BIs) lie at the core of the change detection method presented next.
L220: ## 4 B3IT: Black-Box Border Input Tracking
L221: Building upon cite12†Section 3 , the B3IT method comprises two stages: $i)$ an initialization stage whose goal is to identify border inputs (BIs) and their support, and $ii)$ a detection stage whose goal is to detect a potential change of the target model compared to the initialization stage.
L222: As BIs leverage the low temperature phase transition, they exhibit high sensitivity to model changes: intuitively, if an input identified as a BI during initialization remains a BI during detection, then the model has likely not changed. We now describe both stages.
L223: ### 4.1 The B3IT Initialization Stage
L224: 
L225: The first step consists of finding BIs. While intuitively unlikely, in practice finding BIs turns out to be relatively easy on the majority of production models we tested, which allows B3IT to use a simple procedure: submit $n$ random inputs $m$ times at the lowest temperature $T$ (possibly $T=0$), and retain as BIs the $\bar{n}$ inputs that produced more than one distinct output across their $m$ draws.
L226: More precisely, the phase transition phenomenon explored in cite92†Theorem 3.3 states that at $T\approx 0$ temperature, given an input $x$, only two situations can arise: either $x$ is not a BI ($k=1$), in which case it will always produce the same output token, or $x$ is a $BI$ ($k\geq 2$) and the output token is uniformly sampled among top tokens: a multinomial output distribution is observed.
L227: The key parameter driving this stage is $m$, the number of samples collected per candidate BI $x$. A back-of-the-envelope analysis (see cite64†Appendix C ) identifies $m=3$ as an optimal value if less than $75\%$ of the candidates are BIs. This is the value we select in B3IT, which enables the discovery of BIs for less than $1,500$ requests in a majority of production APIs (See  cite40†Section 5.2 ).
L228: Let $x_{\mathrm{test}}$ be an identified BI. To accurately estimate its initial distribution, it is sampled $n_{1}$ times.
L229: ### 4.2 The B3IT Detection Stage
L230: 
L231: The detection stage is to be triggered when a user wants to determine whether the target model has changed since the initialization stage. During detection, the temperature is set to its minimum (possibly $T=0$) to operate in the optimal test regime.
