L7@P0: Abstract
L8@P0: While reasoning over long context is crucial for various real-world applications, it remains challenging
L9@P0: for large language models (LLMs) as they suffer from performance degradation as the context length
L10@P0: grows. Recent work MemAgent has tried to tackle this by processing context chunk-by-chunk in an
L11@P0: RNN-like loop and updating a textual memory for final answering. However, this naive recurrent
L12@P0: memory update faces two crucial drawbacks: (i) memory can quickly explode because it can update
L13@P0: indiscriminately, even on evidence-free chunks; and (ii) the loop lacks an exit mechanism, leading
L14@P0: to unnecessary computation after even sufficient evidence is collected. To address these issues,
L15@P0: we propose GRU-Mem, which incorporates two text-controlled gates for more stable and efficient
L16@P0: long-context reasoning. Specifically, in GRU-Mem, the memory only updates when the update
L17@P0: gate is open and the recurrent loop will exit immediately once the exit gate is open. To endow the
L18@P0: model with such capabilities, we introduce two reward signals r
L19@P0: update and rexit within end-to-end
L20@P0: RL, rewarding the correct updating and exiting behaviors respectively. Experiments on various
L21@P0: long-context reasoning tasks demonstrate the effectiveness and efficiency of GRU-Mem, which
L22@P0: generally outperforms the vanilla MemAgent with up to 400% times inference speed acceleration.

L26@P0: 1 Introduction
L27@P0: Reasoning over extremely long contexts is a crucial capability of large language models (LLMs) for real-world
L28@P0: applications [7, 23, 31], such as reading an entire book or processing large-scale memories in agentic systems
L29@P0: [4, 15, 24]. While important, this capability remains challenging: LLMs typically experience dramatic
L30@P0: performance degradation as the context length grows [1, 12], and they struggle to handle corpora that exceed
L31@P0: their maximum context window [36].
L32@P0: To address these limitations, recent work MemAgent [36] has explored a recurrent memory paradigm for
L33@P0: long context reasoning in an RNN-like manner [15, 22, 36]. As illustrated in Figure 1, instead of encoding
L34@P0: the entire context in a single forward pass [30, 33], this method reformulates long-context reasoning as a
L35@P0: sequential, recurrent, and chunk-by-chunk memorization process. Concretely, the entire long context C is

L43@P1: practice, the memory agent ϕθ and the answer agent ψθ share the same parameterized policy model θ, with
L44@P1: their behaviors differentiated by the prompt assignment. Trained end-to-end with reinforcement learning (RL)
L45@P1: [36, 37], this recurrent memory paradigm shows potential in mitigating the performance degradation from
L46@P1: ingesting an overly long context at once, and ideally breaks the context window size limit.
L47@P1: However, the vanilla approach inherits several drawbacks of naive RNN-style memory updates [3, 11]. Here,
L48@P1: we identify two key limitations that may hinder the memory stability and efficiency of reasoning in practice:
L49@P1: • Risk of Memory Explosion. As shown in Figure 1, when updating on evidence-free chunks, the memory
L50@P1: agent may accumulate irrelevant or noisy content over time. This drift progressively inflates the memory,
L51@P1: potentially exceeding the allotted budget and triggering memory explosion. Once already exploded, the
L52@P1: accumulated noise can further impede subsequent updates, making it harder to incorporate new key evidence
L53@P1: from later chunks [36]. Additionally, inefficiently regenerating the already-exploded memory at each step
L54@P1: also increases the inference cost. As a result, such risks of memory explosion undermine both long-horizon
L55@P1: stability and runtime efficiency for long-term reasoning.
L56@P1: • Lack of Exit Mechanism. As shown in Figure 1, the vanilla workflow is hard-coded to process all chunks and
L57@P1: provides no early-exit mechanism when the collected evidence is sufficient. That is, even after sufficient
L58@P1: evidence has been collected already (e.g., the last necessary evidence for the answer has appeared), the model
L59@P1: must still process the remaining chunks until the end, incurring avoidable computation. This inefficiency is
L60@P1: amplified when evidence is unevenly distributed (e.g., when reranking brings key evidence early [8, 40])
L61@P1: This inefficiency becomes even more severe when evidence is unevenly distributed across the context, where
L62@P1: in some cases key evidence may appear very early (e.g., when the long context is reordered by specific
L63@P1: reranking techniques) [8, 40].
L64@P1: To this end, we propose GRU-Mem, a gated recurrent memory framework for stable and efficient long-context
L65@P1: reasoning, inspired by the effectiveness of gating in GRUs [6] for addressing long-term sequence modeling
L66@P1: challenges in RNNs (e.g., gradient explosion [11]). The key idea is to augment the recurrent workflow with two
L67@P1: text-controlled gates — an update gate (UG) and an exit gate (EG) — which decide (i) whether the memory
L68@P1: should be updated on the current chunk and (ii) whether the model can terminate early once sufficient evidence
L69@P1: has been collected. Specifically, at step t, the memory agent ϕθ generates three pieces of key information:
L70@P1: the update gate status Ut, the candidate memory Mˆ
L71@P1: t, and the exit gate status Et, which can be formulated
L72@P1: as Ut,Mˆ
L73@P1: t, Et = ϕθ(Q, Ct,Mt−1). Only when the update gate status Uˆ
L74@P1: t is True, the memory Mt will be
L75@P1: updated with the candidate memory Mˆ
L76@P1: t, otherwise adopting the previous memory Mt−1. Additionally,
L77@P1: when the exit gate status Et is True, indicating the last evidence required occurs in this chunk, the workflow
L78@P1: can end immediately for answering the question. Finally, similar to the vanilla design, the answer agent ψθ
L79@P1-2: 2provides the answer Aˆ based on the terminal memory Mt. To endow the model with such capabilities, we
L80@P2: introduce two reward signals r
L81@P2: update and rexit within end-to-end RL, rewarding the correct updating and
L82@P2: exiting behaviors, respectively. The update gate enables selective memory updates on only a few informative
L83@P2: chunks, mitigating memory explosion, while the exit gate provides a flexible early-termination mechanism
L84@P2: that reduces unnecessary computation; together, they yield more stable and efficient long-context reasoning.
L85@P2: We further conduct extensive experiments to verify the effectiveness of GRU-Mem. First, we show that
L86@P2: GRU-Mem generally outperforms the vanilla MemAgent across diverse tasks and among different model
L87@P2: sizes, and generally achieves up to 400% times inference speed acceleration (cf. Section 4.1). Second, we
L88@P2: validate the effectiveness of the two introduced gating mechanisms, where GRU-Mem can reduce the risks
L89@P2: of memory explosion and provide a meaningful exit mechanism (cf. Section 4.2). Third, we systematically
L90@P2: analyze the role of components in GRU-Mem with the ablation study, including the training dynamics (cf.
L91@P2: Section 4.3). We highlight that GRU-Mem provides a stable and efficient long context reasoning paradigm
L92@P2: with the introduction of two gating mechanisms.

L96@P2: 2.1 Task Formulation
L97@P2: Long-context QA. In this paper, we primarily focus on the widely adopted long-context question answering
L98@P2: (QA) tasks [12, 36]. In these tasks, each example consists of a question Q, a long context C, and a ground-truth
L99@P2: answer A, which can be denoted as a triplet (Q, C, A). Here, the context length |Ci| can be very large, such as
L100@P2: millions of tokens.
L101@P2: Evidence Sparsity. To answer the question Ai, LLMs are required to accurately locate and then reason over
L102@P2: a few evidence pieces {ek}
L103@P2: K
L104@P2: k=1, which are sparsely located within the long context Ci
L105@P2: . The sparse evidence
L106@P2: distribution in long context reasoning makes LLMs struggle to answer accurately, which is also commonly
L107@P2: known as the needle in a haystack (NIAH) [13] problem.
L108@P2: 2.2 Recurrent Memory for Long-context Reasoning
L109@P2: Context chunks. In the recurrent memory for long-context reasoning paradigm, the long context is split as
L110@P2: a set of fixed-size context chunks C = {C1 · · · CT } first. After splitting into chunks, the evidence is sparsely
L111@P2: distributed in only a few chunks. That is, most of the chunks do not contain any information for answering
L112@P2: the question Q. This splitting strategy avoids directly feeding the entire context into LLMs at once.
L113@P2: Workflow. The recurrent memory paradigm for long-context reasoning adopts an RNN-like workflow with two
L114@P2: agents: a memory agent ϕθ for recurrently updating a textual memory and an answer agent ψθ for answering
L115@P2: the question based on the final memory. Specifically, as shown in Figure 1, at each step t the memory agent
L116@P2: ϕθ takes the question Q, the current chunk Ct, and the previous memory Mt−1 as input, and generate an
L117@P2: updated memory Mt in a recurrent manner, which can be formulated as:
L118@P2: Mt = ϕθ(Q, Ct,Mt−1). (1)
L119@P2: After reading all the T chunks, an answer agent ψθ generates the answer Aˆ to the question Q based on the
L120@P2: final memory MT , as formulated as follows:
L121@P2: Aˆ = ψθ(Q,MT ). (2)
L122@P2: Here, the memory agent ϕθ and the answer agent ψθ are the same parameterized policy model θ differentiated
L123@P2: by the prompt assignment.

L190@P3: 3 Methodology
L191@P3: In this section, we introduce the gated recurrent memory (GRU-Mem), a recurrent memory workflow equipped
L192@P3: with two gating mechanisms, for stable and efficient long-context reasoning. We first introduce the workflow
L193@P3: of GRU-Mem in Section 3.1. After that, we then detail how to train the workflow with GRU-Mem using
L194@P3: end-to-end reinforcement learning, including the tailored reward design and advantage calculation, in Section
L195@P3: 3.2. Finally, we briefly introduce the inference strategies in Section 3.3.
L196@P3: 3.1 Gated Recurrent Memory Workflow
L197@P3: To address the risk of memory explosion and lack of an exit mechanism, we introduce two gating mechanisms
L198@P3: in the recurrent workflow, the update gate (UG) and the exit gate (EG), inspired by the success of gating in
L199@P3: GRUs [6] for addressing long-term sequence modeling.
L200@P3: Specifically, GRU-Mem mainly changes the memory agent ϕθ while keeping the answer agent ψθ unchanged,
L201@P3: extending the vanilla ϕθ with two extra actions for gate control [36]. It outputs a candidate memory Mˆ
L202@P3: t and
L203@P3: two binary gating signals, Ut and Et, indicating whether to update the memory and whether to terminate the
L204@P3: loop, respectively. This process is formulated as follows:
L205@P3: Ut,Mˆ
L206@P3: t, Et = ϕθ(Q, Ct,Mt−1). (7)
