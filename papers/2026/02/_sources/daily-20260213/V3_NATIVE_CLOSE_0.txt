L181: ## Introduction
L182: ### Qwen3-2507
L183: 
L184: Over the past three months, we continued to explore the potential of the Qwen3 families and we are excited to introduce the updated Qwen3-2507 in two variants, Qwen3-Instruct-2507 and Qwen3-Thinking-2507, and three sizes, 235B-A22B, 30B-A3B, and 4B.
L185: 
L186: Qwen3-Instruct-2507 is the updated version of the previous Qwen3 non-thinking mode, featuring the following key enhancements:
L187:   * Significant improvements in general capabilities, including instruction following, logical reasoning, text comprehension, mathematics, science, coding and tool usage.
L188:   * Substantial gains in long-tail knowledge coverage across multiple languages.
L189:   * Markedly better alignment with user preferences in subjective and open-ended tasks, enabling more helpful responses and higher-quality text generation.
L190:   * Enhanced capabilities in 256K-token long-context understanding, extendable up to 1 million tokens.
L191: Qwen3-Thinking-2507 is the continuation of Qwen3 thinking model, with improved quality and depth of reasoning, featuring the following key enhancements:
L192:   * Significantly improved performance on reasoning tasks, including logical reasoning, mathematics, science, coding, and academic benchmarks that typically require human expertise — achieving state-of-the-art results among open-weight thinking models.
L193:   * Markedly better general capabilities, such as instruction following, tool usage, text generation, and alignment with human preferences.
L194:   * Enhanced 256K long-context understanding capabilities, extendable up to 1 million tokens.
L195: Previous Qwen3 Release
L196: ### Qwen3 (aka Qwen3-2504)
L197: 
L198: We are excited to announce the release of Qwen3, the latest addition to the Qwen family of large language models. These models represent our most advanced and intelligent systems to date, improving from our experience in building QwQ and Qwen2.5. We are making the weights of Qwen3 available to the public, including both dense and Mixture-of-Expert (MoE) models.
L199: The highlights from Qwen3 include:
L200:   * Dense and Mixture-of-Experts (MoE) models of various sizes, available in 0.6B, 1.7B, 4B, 8B, 14B, 32B and 30B-A3B, 235B-A22B.
L201:   * Seamless switching between thinking mode (for complex logical reasoning, math, and coding) and non-thinking mode (for efficient, general-purpose chat), ensuring optimal performance across various scenarios.
L202:   * Significantly enhancement in reasoning capabilities, surpassing previous QwQ (in thinking mode) and Qwen2.5 instruct models (in non-thinking mode) on mathematics, code generation, and commonsense logical reasoning.
L203:   * Superior human preference alignment, excelling in creative writing, role-playing, multi-turn dialogues, and instruction following, to deliver a more natural, engaging, and immersive conversational experience.
L204:   * Expertise in agent capabilities, enabling precise integration with external tools in both thinking and unthinking modes and achieving leading performance among open-source models in complex agent-based tasks.
L205:   * Support of 100+ languages and dialects with strong capabilities for multilingual instruction following and translation.

L224: ## Run Qwen3
L225: 
L226: ### 🤗 Transformers
L227: 
L228: Transformers is a library of pretrained natural language processing for inference and training. The latest version of `transformers` is recommended and `transformers>=4.51.0` is required.
L229: #### Qwen3-Instruct-2507
L230: The following contains a code snippet illustrating how to use Qwen3-30B-A3B-Instruct-2507 to generate content based on given inputs.
L231: 
L232:     from transformers import AutoModelForCausalLM, AutoTokenizer
L233: 
L234:     model_name = "Qwen/Qwen3-30B-A3B-Instruct-2507"
L235: 
L236:     # load the tokenizer and the model
L237:     tokenizer = AutoTokenizer.from_pretrained(model_name)
L238:     model = AutoModelForCausalLM.from_pretrained(
L239:         model_name,
L240:         torch_dtype="auto",
L241:         device_map="auto"
L242:     )
L243:     # prepare the model input
L244:     prompt = "Give me a short introduction to large language model."
L245:     messages = [
L246:         {"role": "user", "content": prompt}
L247:     ]
L248:     text = tokenizer.apply_chat_template(
L249:         messages,
L250:         tokenize=False,
L251:         add_generation_prompt=True,
L252:     )
L253:     model_inputs = tokenizer([text], return_tensors="pt").to(model.device)
L254: 
L255:     # conduct text completion
L256:     generated_ids = model.generate(
L257:         **model_inputs,
L258:         max_new_tokens=16384
L259:     )
L260:     output_ids = generated_ids[0][len(model_inputs.input_ids[0]):].tolist()
L261: 
L262:     content = tokenizer.decode(output_ids, skip_special_tokens=True)
L263: 
L264:     print("content:", content)
L265: Note
L266: 
L267: Qwen3-Instruct-2507 supports only non-thinking mode and does not generate `<think></think>` blocks in its output. Meanwhile, specifying `enable_thinking=False` is no longer required.
L268: #### Qwen3-Thinking-2507
L269: The following contains a code snippet illustrating how to use Qwen3-30B-A3B-Thinking-2507 to generate content based on given inputs.
L270: 
L271:     from transformers import AutoModelForCausalLM, AutoTokenizer
L272: 
L273:     model_name = "Qwen/Qwen3-30B-A3B-Thinking-2507"
L274: 
L275:     # load the tokenizer and the model
L276:     tokenizer = AutoTokenizer.from_pretrained(model_name)
L277:     model = AutoModelForCausalLM.from_pretrained(
L278:         model_name,
L279:         torch_dtype="auto",
L280:         device_map="auto"
L281:     )
L282:     # prepare the model input
L283:     prompt = "Give me a short introduction to large language model."
L284:     messages = [
L285:         {"role": "user", "content": prompt}
L286:     ]
L287:     text = tokenizer.apply_chat_template(
L288:         messages,
L289:         tokenize=False,
L290:         add_generation_prompt=True,
L291:     )
L292:     model_inputs = tokenizer([text], return_tensors="pt").to(model.device)
L293: 
L294:     # conduct text completion
L295:     generated_ids = model.generate(
L296:         **model_inputs,
L297:         max_new_tokens=32768
L298:     )
L299:     output_ids = generated_ids[0][len(model_inputs.input_ids[0]):].tolist()
L300: 
L301:     # parsing thinking content
L302:     try:
L303:         # rindex finding 151668 (</think>)
L304:         index = len(output_ids) - output_ids[::-1].index(151668)
L305:     except ValueError:
L306:         index = 0
L307: 
L308:     thinking_content = tokenizer.decode(output_ids[:index], skip_special_tokens=True).strip("\n")
L309:     content = tokenizer.decode(output_ids[index:], skip_special_tokens=True).strip("\n")
L310:     print("thinking content:", thinking_content)  # no opening <think> tag
L311:     print("content:", content)
L312: Note
L313: 
L314: Qwen3-Thinking-2507 supports only thinking mode. Additionally, to enforce model thinking, the default chat template automatically includes `<think>`. Therefore, it is normal for the model's output to contain only `</think>` without an explicit opening `<think>` tag.
L315: 
L316: Qwen3-Thinking-2507 also features an increased thinking length. We strongly recommend its use in highly complex reasoning tasks with adequate maximum generation length.
L317: 
L318: Switching Thinking/Non-thinking Modes for Previous Qwen3 Models
L319: By default, Qwen3 models will think before response. This could be controlled by
L320: 
L321:   * `enable_thinking=False`: Passing `enable_thinking=False` to `tokenizer.apply_chat_template` will strictly prevent the model from generating thinking content.
L322:   * `/think` and `/no_think` instructions: Use those words in the system or user message to signify whether Qwen3 should think. In multi-turn conversations, the latest instruction is followed.
L323: ### ModelScope
L324: 
L325: We strongly advise users especially those in mainland China to use ModelScope. ModelScope adopts a Python API similar to Transformers. The CLI tool `modelscope download` can help you solve issues concerning downloading checkpoints. For vLLM and SGLang, the environment variable `VLLM_USE_MODELSCOPE=true` and `SGLANG_USE_MODELSCOPE=true` can be used respectively.
L326: ### llama.cpp
L327: 
L328: cite107†`llama.cpp` enables LLM inference with minimal setup and state-of-the-art performance on a wide range of hardware. `llama.cpp>=b5401` is recommended for the full support of Qwen3.
L329: 
L330: To use the CLI, run the following in a terminal:
L331: 
L332:     ./llama-cli -hf Qwen/Qwen3-8B-GGUF:Q8_0 --jinja --color -ngl 99 -fa -sm row --temp 0.6 --top-k 20 --top-p 0.95 --min-p 0 -c 40960 -n 32768 --no-context-shift
L333:     # CTRL+C to exit
L334: To use the API server, run the following in a terminal:
L335: 
L336:     ./llama-server -hf Qwen/Qwen3-8B-GGUF:Q8_0 --jinja --reasoning-format deepseek -ngl 99 -fa -sm row --temp 0.6 --top-k 20 --top-p 0.95 --min-p 0 -c 40960 -n 32768 --no-context-shift --port 8080
L337: 
L338: A simple web front end will be at `http://localhost:8080` and an OpenAI-compatible API will be at `http://localhost:8080/v1`.
L339: 
L340: For additional guides, please refer to cite108†our documentation†qwen.readthedocs.io .
L341: 
L342: Note
L343: llama.cpp adopts "rotating context management" and infinite generation is made possible by evicting earlier tokens. It could configured by parameters and the commands above effectively disable it. For more details, please refer to cite109†our documentation†qwen.readthedocs.io .
L344: ### Ollama
L345: 
L346: After cite110†installing Ollama†ollama.com , you can initiate the Ollama service with the following command (Ollama v0.9.0 or higher is recommended):
L347: 
L348:     ollama serve
L349:     # You need to keep this service running whenever you are using ollama
L350: To pull a model checkpoint and run the model, use the `ollama run` command. You can specify a model size by adding a suffix to `qwen3`, such as `:8b` or `:30b-a3b`:
L351: 
L352:     ollama run qwen3:8b
L353:     # Setting parameters, type "/set parameter num_ctx 40960" and "/set parameter num_predict 32768"
L354:     # To exit, type "/bye" and press ENTER
L355:     # For Qwen3-2504 models,
L356:     # - To enable thinking, which is the default, type "/set think"
L357:     # - To disable thinking, type "/set nothink"
L358: You can also access the Ollama service via its OpenAI-compatible API. Please note that you need to (1) keep `ollama serve` running while using the API, and (2) execute `ollama run qwen3:8b` before utilizing this API to ensure that the model checkpoint is prepared. The API is at `http://localhost:11434/v1/` by default.
L359: 
L360: For additional details, please visit cite110†ollama.ai†ollama.com .
L361: 
L362: Note
L363: Ollama's naming may not be consistent with the Qwen's original naming. For example, `qwen3:30b-a3b` in Ollama points to `qwen3:30b-a3b-thinking-2507-q4_K_M` as of August 2025. Please check cite111†https://ollama.com/library/qwen3/tags†ollama.com before use.

L365: Note
L366: Ollama adopts the same "rotating context management" with llama.cpp. However, its default settings (`num_ctx` 2048 and `num_predict` -1), suggesting infinite generation with a 2048-token context, could lead to trouble for Qwen3 models. We recommend setting `num_ctx` and `num_predict` properly.

L385: ## Deploy Qwen3
L386: 
L387: Qwen3 is supported by multiple inference frameworks. Here we demonstrate the usage of `SGLang`, `vLLM` and `TensorRT-LLM`. You can also find Qwen3 models from various inference providers, e.g., cite118†Alibaba Cloud Model Studio†www.alibabacloud.com .
L388: ### SGLang
L389: 
L390: cite119†SGLang is a fast serving framework for large language models and vision language models. SGLang could be used to launch a server with OpenAI-compatible API service. `sglang>=0.4.6.post1` is required.
L391: 
L392: For Qwen3-Instruct-2507,
L393: 
L394:     python -m sglang.launch_server --model-path Qwen/Qwen3-30B-A3B-Instruct-2507 --port 30000 --context-length 262144
L395: For Qwen3-Thinking-2507,
L396: 
L397:     python -m sglang.launch_server --model-path Qwen/Qwen3-30B-A3B-Thinking-2507 --port 30000 --context-length 262144 --reasoning-parser deepseek-r1
L398: 
L399: For Qwen3, it is
L400: 
L401:     python -m sglang.launch_server --model-path Qwen/Qwen3-8B --port 30000 --context-length 131072 --reasoning-parser qwen3
L402: 
L403: An OpenAI-compatible API will be available at `http://localhost:30000/v1`.
L404: 
L405: Note
L406: Due to the preprocessing of API requests in SGLang, which drops all `reasoning_content` fields, the quality of multi-step tool use with Qwen3 thinking models may be suboptimal, which requires the existence of the related thinking content. While the fixes are being worked on, as a workdaround, we recommend passing the content as it is, without extracting thinking content, and the chat template will correctly handle the processing.
L407: ### vLLM
L408: 
L409: cite120†vLLM is a high-throughput and memory-efficient inference and serving engine for LLMs. `vllm>=0.9.0` is recommended.
L410: 
L411: For Qwen3-Instruct-2507,
L412: 
L413:     vllm serve Qwen/Qwen3-30B-A3B-Instruct-2507 --port 8000 --max-model-len 262144
L414: 
L415: For Qwen3-Thinking-2507,
L416: 
L417:     vllm serve Qwen/Qwen3-30B-A3B-Thinking-2507 --port 8000 --max-model-len 262144 --enable-reasoning --reasoning-parser deepseek_r1
L418: For Qwen3, it is
L419: 
L420:     vllm serve Qwen/Qwen3-8B --port 8000 --max-model-len 131072 --enable-reasoning --reasoning-parser qwen3
L421: 
L422: An OpenAI-compatible API will be available at `http://localhost:8000/v1`.
L423: 
L424: Note
L425: Due to the preprocessing of API requests in vLLM, which drops all `reasoning_content` fields, the quality of multi-step tool use with Qwen3 thinking models may be suboptimal, which requires the existence of the related thinking content. While the fixes are being worked on, as a workdaround, we recommend passing the content as it is, without extracting thinking content, and the chat template will correctly handle the processing.
L426: ### TensorRT-LLM
L427: 
L428: cite121†TensorRT-LLM is an open-source LLM inference engine from NVIDIA, which provides optimizations including custom attention kernels, quantization and more on NVIDIA GPUs. Qwen3 is supported in its re-architected cite122†PyTorch backend†nvidia.github.io . `tensorrt_llm>=0.20.0rc3` is recommended. Please refer to the cite123†README page for more details.
L429: 
L430:     trtllm-serve Qwen/Qwen3-8B --host localhost --port 8000 --backend pytorch
L431: An OpenAI-compatible API will be available at `http://localhost:8000/v1`.
