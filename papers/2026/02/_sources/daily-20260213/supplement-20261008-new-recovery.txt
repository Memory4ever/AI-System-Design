Abstract

Transformers face a quadratic bottleneck in attention when scaling to long contexts. Recent approaches introduce recurrent memory to extend context beyond the current window, yet these often face a fundamental trade-off between theoretical principles and practical scalability. To address this, we introduce Elastic Memory, a novel memory architecture grounded in the HiPPO framework for online function approximation. Elastic Memory treats historical sequence as samples from continuous signals, applying optimal online compression to encode them into a fixed-size memory state. For retrieval, we propose a flexible \textit{polynomial sampling} mechanism that reconstructs a history summary from this compressed state. Elastic Memory consistently outperformed baselines on long-context (32k+) datasets across three domains. With equal parameters, it beat Memorizing Transformer by 16x memory and outperformed Melodi at all memory sizes, even when Melodi had 30% more parameters. When scaling model size, Elastic Memory stayed ahead of all baselines and was significantly faster than Melodi at 4x size. Furthermore, its decoupled design allows for injecting inductive biases at test-time to boost performance.--------------------------------------------------------------------------------

## Implications and Future Directions

Elastic Memory represents a significant step toward resolving the fundamental trade-off between theoretical principles and practical scalability in long-context language modeling. By establishing that continuous-time signal processing theories can effectively guide discrete language model architectures, this work opens new interdisciplinary research directions at the intersection of optimal control theory and neural network design.

The success of this approach suggests broader implications for memory system design in neural networks. The formal definition of "optimal" compression through mathematical frameworks like HiPPO could reduce reliance on architectural search and hyperparameter tuning for memory components, leading to more predictable and robust system behavior.

The flexible inductive bias injection capability also points toward more adaptive language models that can adjust their context processing strategies based on task requirements without additional training, potentially reducing the cost of specialized model development for different applications.

## Abstract

Os Transformers enfrentam um gargalo quadrático na atenção ao escalar para contextos longos. Abordagens recentes introduzem memória recorrente para estender o contexto além da janela atual, mas estas frequentemente enfrentam uma troca fundamental entre princípios teóricos e escalabilidade prática. Para resolver isso, apresentamos a Elastic Memory, uma nova arquitetura de memória fundamentada na estrutura HiPPO para aproximação de funções online. A Elastic Memory trata sequências históricas como amostras de sinais contínuos, aplicando compressão online ótima para codificá-las em um estado de memória de tamanho fixo. Para recuperação, propomos um mecanismo flexível de amostragem polinomial que reconstrói um resumo do histórico a partir deste estado comprimido. A Elastic Memory superou consistentemente as baselines em conjuntos de dados de contexto longo (32k+) em três domínios. Com parâmetros iguais, superou o Memorizing Transformer por 16x em memória e superou o Melodi em todos os tamanhos de memória, mesmo quando o Melodi tinha 30% mais parâmetros. Ao escalar o tamanho do modelo, a Elastic Memory manteve-se à frente de todas as baselines e foi significativamente mais rápida que o Melodi em 4x o tamanho. Além disso, seu design desacoplado permite injetar vieses indutivos no tempo de teste para aumentar o desempenho.

## AI Overview

## Visão Geral

Modelos de linguagem baseados em Transformer alcançaram sucesso notável no processamento de linguagem natural, mas enfrentam um gargalo computacional fundamental: a complexidade quadrática de seu mecanismo de autoatenção. Essa limitação restringe severamente sua capacidade de processar e raciocinar sobre contextos muito longos, o que é crucial para tarefas que envolvem documentos extensos, conversas ou repositórios de código. Embora várias soluções tenham sido propostas para enfrentar esse desafio, elas tipicamente caem em uma troca problemática entre solidez teórica e escalabilidade prática.

Este artigo apresenta a Memória Elástica, uma arquitetura de memória recorrente que preenche essa lacuna aplicando a estrutura HiPPO (High-order Polynomial Projection Operators) para alcançar tanto a compressão matematicamente ótima quanto a escalabilidade prática. A principal sacada é reenquadrar o problema da memória de estratégias heurísticas de compressão para um problema rigoroso de aproximação de função online, onde sequências históricas de chave-valor são tratadas como amostras de sinais contínuos e comprimidas usando projeções polinomiais ótimas.

## Arquitetura de Memória Elástica

A arquitetura de Memória Elástica integra a compressão HiPPO diretamente na estrutura do Transformer através de três componentes principais: atualização de memória, recuperação de memória e integração de atenção.

### Processo de Atualização da Memória

Durante o passe para frente, a Memória Elástica comprime as sequências Chave (K) e Valor (V) antes da aplicação de RoPE. Cada dimensão de característica das projeções K e V brutas é tratada como um sinal unidimensional independente a ser comprimido usando a recorrência HiPPO.

Para superar a natureza inerentemente sequencial do processamento token a token, o sistema emprega atualizações de bloco paralelas. A recorrência é desenrolada sobre blocos de entrada de comprimento $L$L, transformando a atualização em uma operação paralela:

$$C_i = P_i C_{i-1} + \bar{K}_i F_i$$C i​=P i​C i−1​+K ˉ i​F i​

onde $C_i$C i​ representa o estado de memória atualizado para o bloco $i$i, $P_i$P i​ é a matriz de transição de estado, e $\bar{K}_i$K ˉ i​ é a matriz do kernel HiPPO. Essas matrizes são únicas para cada posição de bloco devido à natureza variável no tempo de HiPPO-LegS.

Para manter a eficiência computacional, as matrizes dependentes da posição $P_i$P i​ e $\bar{K}_i$K ˉ i​ são pré-calculadas e armazenadas em cache para todas as posições de bloco até o comprimento máximo do contexto, fazendo com que o passe para frente consista em multiplicações de matriz eficientes.

### Mecanismo de Recuperação de Memória

O processo de recuperação reconstrói um resumo do sinal histórico a partir do estado de memória comprimido usando amostragem polinomial. Uma coleção de matrizes de reconstrução dependentes da posição $R_i$R i​ é pré-calculada, com cada matriz projetada para amostrar $L_{\text{mem}}$L mem​ pontos da história, avaliando funções de base de Legendre em pontos de amostra estrategicamente escolhidos.

O artigo explora duas estratégias de amostragem:

Amostragem Uniforme (Elastic Memory_uni) distribui os pontos de amostra uniformemente por toda a história $[0, iL)$[0,i L), fornecendo representação igual de todos os períodos históricos.

Amostragem Exponencial (Elastic Memory_exp) concentra os pontos de amostra próximos ao presente, tornando-se exponencialmente mais esparsos no passado, refletindo a intuição linguística de que o contexto recente é tipicamente mais relevante.

### Integração de Atenção

As Chaves ($K_{\text{mem}}$K mem​) e Valores ($V_{\text{mem}}$V mem​) de memória recuperados são adicionados ao início das Chaves e Valores do bloco atual. Durante o cálculo da atenção, uma máscara de atenção trapezoidal garante que as consultas atuais possam atender a todos os tokens de memória, mantendo a causalidade dentro do bloco atual.

Uma escolha de design importante é que os tokens de memória recuperados não recebem codificações posicionais externas. Em vez disso, a informação de posição temporal é intrinsecamente codificada dentro dos vetores reconstruídos através da avaliação específica das funções de base de Legendre em coordenadas temporais dadas.
