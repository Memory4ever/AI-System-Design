L170: # TabICLv2: A better, faster, scalable, and open tabular foundation model
L171: Jingang Qu Affiliation: SODA Team, INRIA Saclay, Palaiseau, France Correspondence to: jingang.qu@inria.fr    David Holzmüller Affiliation: SODA Team, INRIA Saclay, Palaiseau, France Correspondence to: david.holzmuller@inria.fr    Gaël Varoquaux Affiliation: SODA Team, INRIA Saclay, Palaiseau, France Affiliation: Probabl, France    Marine Le Morvan Affiliation: SODA Team, INRIA Saclay, Palaiseau, France Correspondence to: marine.le-morvan@inria.fr
L172: ###### Abstract
L173: Tabular foundation models, such as TabPFNv2 and TabICL, have recently dethroned gradient-boosted trees at the top of predictive benchmarks, demonstrating the value of in-context learning for tabular data.
L174: We introduce TabICLv2, a new state-of-the-art foundation model for regression and classification built on three pillars: (1) a novel synthetic data generation engine designed for high pretraining diversity; (2) various architectural innovations, including a new scalable softmax in attention improving generalization to larger datasets without prohibitive long-sequence pretraining; and (3) optimized pretraining protocols, notably replacing AdamW with the Muon optimizer.
L175: On the TabArena and TALENT benchmarks, TabICLv2 without any tuning surpasses the performance of the current state of the art, RealTabPFN-2.5 (hyperparameter-tuned, ensembled, and fine-tuned on real data). With only moderate pretraining compute, TabICLv2 generalizes effectively to million-scale datasets under 50GB GPU memory while being markedly faster than RealTabPFN-2.5.
L176: We provide extensive ablation studies to quantify these contributions and commit to open research by first releasing inference code and model weights at cite158†https://github.com/soda-inria/tabicl†github.com , with synthetic data engine and pretraining code to follow.

L182: ## 1 Introduction
L183: Figure 1: Improvability vs. train time on TabArena (cite159†Erickson et al., 2025 ). L185: Tabular data, whether stored in spreadsheets or databases, is ubiquitous across applications ranging from healthcare to credit card fraud detection (cite160†Borisov et al., 2022 ; cite161†Jesus et al., 2022 ; cite162†Grinsztajn et al., 2025 ).
L186: While supervised learning on tabular data has long been dominated by gradient-boosted decision trees (cite163†Grinsztajn et al., 2022 ), both pretrained and trained-from-scratch deep learning models have recently been able to match or even surpass their accuracy on tables with up to 100K samples (cite159†Erickson et al., 2025 ; cite164†Ye et al., 2024 ).
L187: In particular, starting from TabPFN (cite165†Hollmann et al., 2022 ), tabular foundation models (TFMs) have received a lot of attention thanks to their ability to perform training and inference in a single forward pass of a Transformer-based architecture.
L188: The development of better TFMs also benefits downstream adaptations, such as causal inference, generative modeling, joint predictive distributions, and simulation-based inference (cite166†Ma et al., 2025b ; cite167†Robertson et al., 2025 ; cite168†Balazadeh et al., 2025 ; cite169†Hollmann et al., 2025 ; cite170†Hassan et al., 2025 ; cite171†Vetter et al., 2025 ).
L189: To foster this research, there is a pressing need for fully open-source TFMs that rival closed-source ones to democratize access to top-tier performance and demystify the recipe behind top-performing TFMs.
L190: ##### Contributions
L191: 
L192: We introduce TabICLv2, a state-of-the-art tabular foundation model, as shown in cite172†Figure 1 . Our contributions include architectural innovations (cite17†Section 3 ), pretraining improvements (cite18†Section 4 ), a novel synthetic data generator (cite24†Section 5 ), extensive evaluations (cite30†Section 6 ), and an ablation study (cite36†Section 7 ).
L193: 
L194: ## 2 Related Work
L195: ### 2.1 Tabular foundation models
L196: Tabular foundation models (TFMs) based on Prior-data fitted networks (PFNs, cite173†Müller et al. 2021 ) emerged as a paradigm shift in tabular learning. Given a training set and test input, a TFM $q_{\theta}$ with parameters $\theta$ directly predicts a distribution $q_{\theta}(y_{\mathrm{test}}\mid x_{\mathrm{test}},\mathcal{D}_{\mathrm{train}})$ with a forward pass on input $(x_{\mathrm{test}},\mathcal{D}_{\mathrm{train}})$.
L197: For a single dataset, it hence performs in-context learning (ICL) without gradient updates. For pretraining, given a prior $p(\mathcal{D})$ from which datasets $\mathcal{D}$ (train+test) can be sampled, TFMs are trained to minimize
L198:  | $$\mathcal{L}(\theta)=\mathbb{E}_{\mathcal{D}\sim p(\cdot)}\big[-\log q_{\theta}(y_{\mathrm{test}}\mid x_{\mathrm{test}},\mathcal{D}_{\mathrm{train}})\big]~.$$  |
L199: ##### Architectural perspectives.
L200: TabPFN (cite165†Hollmann et al., 2022 ) treats each row as a token and performs ICL over rows. TabPFNv2 (cite169†Hollmann et al., 2025 ) moves to a cell-based design with alternating row and column attentions, where each cell receives a separate representation. However, this incurs $O(n^{2}m+nm^{2})$ complexity for a table with $n$ rows and $m$ columns. TabPFN-2.5 (cite162†Grinsztajn et al., 2025 ) extends TabPFNv2 with deeper networks.
L201: TabICL (cite174†Qu et al., 2025 ) reduces the computational complexity to $O(n^{2}+nm^{2})$ via a two-stage design: a lightweight column-then-row attention first constructs fixed-dimensional row embeddings, after which ICL is performed over these embeddings. Recent work continues to innovate on these foundations, including Mitra (cite175†Zhang et al., 2025a ), LimiX (cite176†Zhang et al., 2025b ), and Orion-MSP (cite177†Bouadi et al., 2025 ).
L202: ##### Synthetic prior datasets.
L203: Synthetic priors are central to PFN-style TFMs. TabPFN uses structural causal models (SCMs). TabICL and TabForestPFN (cite178†Breejen et al., 2024 ) extend these by mixing tree-based priors to inject tree inductive biases. Mitra studies prior design principles and proposes mixed priors (SCM + tree ensembles) to better control decision boundaries. TabPFNv2 enriches priors with more sophisticated DAG construction and computational mappings. LimiX introduces hierarchical SCMs with controllable difficulty.
L204: Drift-Resilient TabPFN (cite179†Helli et al., 2024 ) tackles temporal distribution shifts with a two-level generative prior that modulates SCM parameters over time. However, TabDPT (cite180†Ma et al., 2025a ) shows that large-scale pretraining on real datasets can be competitive, and Real-TabPFN (cite181†Garg et al., 2025 ) indicates that continued pretraining on real datasets can improve TabPFNv2.
L205: ##### Fine-tuning, retrieval, and distillation.
L206: Beyond pretraining, adaptation strategies for TFMs include (a) fine-tuning to shift the learned prior toward a target distribution (cite182†Feuer et al., 2024 ; cite183†Liu & Ye, 2025 ; cite181†Garg et al., 2025 ; cite184†Kolberg et al., 2025 ; cite185†Rubachev et al., 2025 ), (b) retrieval-based context selection to enhance compute-constrained scalability (cite186†Thomas et al., 2024 ; cite187†Xu et al., 2024 ; cite176†Zhang et al., 2025b ; cite188†Sergazinov & Yin, 2025 ), and (c) distilling TFMs into compact MLPs or trees (cite189†Bonet et al., 2024 ; cite190†Mueller et al., 2024 ; cite162†Grinsztajn et al., 2025 ).
L207: ##### LLM-based tabular models.
L208: 
L209: In parallel to table-native TFMs, large language models (LLMs) have been adapted to tabular data via table serialization and continued pretraining (cite191†Hegselmann et al., 2023 ; cite192†Gardner et al., 2024 ; cite193†Dong et al., 2025 ), which are promising but underperform TFMs when sufficient training data is available.
L210: 
L211: ### 2.2 Attention struggles with long-context generalization
L212: ##### Attention fading.
L213: 
L214: Attention is central to PFN-style TFMs. But standard attention, based on softmax, suffers from attention fading (cite194†Veličković et al., 2024 ; cite195†Nakanishi, 2025 ): the softmax denominator increases as context length $n$ grows, causing attention distributions to flatten and preventing sharp focus on relevant tokens. This limits length generalization, as models trained on shorter sequences cannot maintain discriminative attention patterns when applied to longer ones.
L215: ##### Temperature scaling.
L216: To address attention fading, some work focuses on softmax alternatives (cite196†Peters et al., 2019 ; cite197†Ramapuram et al., 2024 ), which, however, requires specialized implementations incompatible with the softmax ecosystem, e.g., FlashAttention (cite198†Dao et al., 2022 ). We thus focus on a less invasive solution: temperature scaling.
L217: Standard attention (cite199†Vaswani et al., 2017 ) already incorporates a fixed scaling temperature factor $1/\sqrt{d}$ to prevent dot-product magnitudes from growing with dimension, but this does not address length-dependent fading. YaRN (cite200†Peng et al., 2023 ) scales temperature with context length for RoPE (cite201†Su et al., 2021 ) extension, but the scaling is fixed and requires positional encoding. Recent work proposes dynamic alternatives.
L218: Scalable Softmax (SSMax, cite195†Nakanishi 2025 ) scales attention logits by $s\log n$, where $s$ is a learnable per-head parameter. Concurrent theoretical analysis (cite202†Chen et al., 2025b ) establishes that $\log n$ scaling is necessary to maintain attention sharpness as context length $n$ grows. Adaptive-Scalable Entmax (ASEntmax, cite203†Vasylenko et al.
L219: 2025 ) extends this with content-aware scaling $\delta+\beta(\log n)^{\gamma}$, where $\delta$ is a length-independent constant offset, and $\beta=\mathrm{softplus}(\text{MLP}(X))$ and $\gamma=\tanh(\text{MLP}(X))$ are input-dependent. Selective Attention (cite204†Zhang et al., 2024 ) takes a different approach by introducing query-dependent temperature $\tau(q)$ via lightweight MLPs, decoupling the scaling from context length entirely.
L220: ## 3 Architecture
L221: The architecture of TabICLv2 is illustrated in cite205†Figure 2 . Following TabICL, TabICLv2 chains column-wise embedding, row-wise interaction, and dataset-wise ICL, thus preserving the efficiency of TabICL with a runtime complexity of $O(n^{2}+nm^{2})$ for tables with $n$ rows and $m$ columns. In addition, we introduce several improvements that significantly enhance performance without increasing model size (see the ablation study in cite36†Section 7 ).
L222: In the following, we mark these improvements with $\blacktriangleright$. We focus below on architectural innovations. For model configuration details (e.g., number of layers), refer to cite49†Section A.4 . We provide a short self-contained implementation of the TabICLv2 architecture for educational and experimental purposes, inspired by nanoTabPFN (cite206†Pfefferle et al., 2025 ), at
L223: cite207†https://github.com/soda-inria/nanotabicl†github.com .
L224: $\blacktriangleright$ Repeated feature grouping. TabICL embeds each feature independently, which can lead to representation collapse when features share similar distributions. TabPFNv2 and TabPFN-2.5 mitigate this collapse by grouping multiple columns into single tokens, which also reduces the number of effective features to improve efficiency, but this reduction may lose fine-grained feature information.
L225: We propose repeated feature grouping, which places each feature into multiple groups via circular shifts while preserving the number of effective features. Specifically, for a table with $m$ columns, we create $m$ groups where the $j$-th group contains columns at positions $(j,j+1,j+3)\bmod m$. Each group is encoded by a shared linear layer $\mathrm{Lin}:\mathbb{R}^{3}\to\mathbb{R}^{d}$:
L226:  | $$E_{1}[i,j]=\mathrm{Lin}\big(x_{i,j},\,x_{i,(j+1)\bmod m},\,x_{i,(j+3)\bmod m}\big).$$  |
L227: 
L228: The shift pattern $(0,1,3)$ ensures that for $\geq 7$ columns, no pair of columns appears together in more than one group. We show in cite41†Section A.1 that this pattern generalizes to arbitrary group sizes, although we did not observe consistent improvements from larger groups.
L229: Figure 2: Architecture of TabICLv2. Given an input $X\in\mathbb{R}^{n\times m}$, repeated feature grouping encodes columns into multiple groups via circular shifts to break feature symmetries, and target-aware embedding injects target information from the beginning. $\text{TF}_{\text{col}}$ embeds each feature through a set transformer, $\text{TF}_{\text{row}}$ aggregates features into row representations $h$, and $\text{TF}_{\text{icl}}$ performs in-context learning to predict test targets $\hat{y}$.
L230: QASSMax, our query-aware scalable softmax, is applied in the part of $\text{TF}_{\text{col}}$ where inducing points aggregate input information and $\text{TF}_{\text{icl}}$ to mitigate attention fading and improve long-context generalization.

L234: Figure 3: SSMax variants mitigate attention fading in a synthetic 2D classification task. We create a dataset consisting of four negative clusters (C1–C4) and one anchor cluster containing a single anchor sample (triangle) in the training set. Without SSMax, accuracy drops and entropy rises as negative samples increase, which is a hallmark of attention fading where the model fails to focus on the relevant anchor. L237: $\blacktriangleright$ Target-aware embedding. We find it beneficial to inject target information early. After repeated feature grouping produces input data representation $E_{1}\in\mathbb{R}^{n\times m\times d}$, we add target embeddings to each training token:
L238: 
L239:  | $$E_{2}[i,j]=E_{1}[i,j]+\mathrm{Embed_{\text{TAE}}}(y_{i}),\quad i\in\mathcal{D}_{\mathrm{train}},$$  |
L240: where $\mathrm{Embed_{\text{TAE}}}$ is a linear layer for regression or a learnable lookup table for classification. Unlike TabPFNv2 appending the target as an additional column, we directly add target embeddings to all features. This also helps mitigate representation collapse because even when two features share similar distributions, their association with target values often differs across samples.
L241: Compression then ICL. TabICLv2 processes $E_{2}$ in three stages: (1) column-wise embedding applies a set transformer $\text{TF}_{\text{col}}$ (cite209†Lee et al., 2019 ) to each column; (2) row-wise interaction uses a transformer $\text{TF}_{\text{row}}$ with [CLS] tokens to collapse feature embeddings per row into a single vector; (3) dataset-wise ICL combines row embeddings with target embeddings and uses a transformer $\text{TF}_{\text{icl}}$ where test samples attend to training samples for prediction.
L242: See cite42†Section A.2 for details. $\blacktriangleright$ Compared to TabICL, our key innovation here is applying a novel scalable softmax to $\text{TF}_{\text{icl}}$ and to the part of $\text{TF}_{\text{col}}$ where inducing points aggregate input information.
L243: $\blacktriangleright$ Query-aware scalable softmax. To improve generalization to larger datasets, we extend Scalable Softmax (SSMax, cite195†Nakanishi 2025 ), a temperature scaling method that sharpens attention distributions by rescaling queries before computing logits. Let $q_{h}=(q_{hi})$ be a query vector at head $h$ with head dimension indexed by $i$, and let $n$ be the size of the training set. SSMax rescales queries with a learnable per-head scalar $s_{h}$:
L244:  | $$\tilde{q}_{hi}=q_{hi}\cdot s_{h}\log n~.$$  |
L245: 
L246: We propose query-aware scalable softmax (QASSMax), which rescales each query element as:
L247: 
L248:  | $$\tilde{q}_{hi}=q_{hi}\cdot\underbrace{\mathrm{MLP}_{\mathrm{base}}(\log n)_{hi}}_{\text{base scaling}}\cdot\underbrace{\big(1+\tanh(\mathrm{MLP}_{\mathrm{gate}}(q_{h})_{i})\big)}_{\text{query-aware gating}}$$  |
L249: where for $H$ attention heads, $\mathrm{MLP}_{\mathrm{base}}:\mathbb{R}\to\mathbb{R}^{H\times d_{\mathrm{head}}}$ and $\mathrm{MLP}_{\mathrm{gate}}:\mathbb{R}^{d_{\mathrm{head}}}\to\mathbb{R}^{d_{\mathrm{head}}}$ are two-layer MLPs with 64 hidden neurons and GELU activation.
L250: We design QASSMax based on the following rationale: (a) The $\log n$ factor is critical as it counteracts the linear growth of the softmax denominator with respect to $n$ (cite195†Nakanishi, 2025 ; cite202†Chen et al., 2025b ); (b) ASEntmax (cite203†Vasylenko et al., 2025 ) uses learnable $\delta+\beta(\log n)^{\gamma}$, inspiring us to generalize to $\mathrm{MLP}_{\mathrm{base}}(\log n)$; (c) Element-wise scaling increases expressiveness beyond per-head scalars; (d) Selective Attention (cite204†Zhang et al., 2024 ) introduces query-awareness in temperature scaling, which motivates us to use the bounded query-aware gating $\in(0,2)$ that modulates the base scaling without dominating the $\log n$ trend.
L251: In addition, our gating design shares similar insights with Gated Attention (cite210†Qiu et al., 2025 ), which applies gating to attention outputs and finds query-dependent, element-wise gating most effective.
L252: QASSMax applied to $\text{TF}_{\text{col}}$ and $\text{TF}_{\text{icl}}$ yields substantially performance improvements, as shown in the ablation study (cite36†Section 7 ). To study its effect on attention fading, we design a toy needle-in-haystack classification task (cite211†Figure 3 ): the model must focus on a single anchor sample (the needle) among increasing negative samples (the haystack). Without scalable softmax, attention entropy rises and accuracy drops.
L253: However, QASSMax maintains low entropy and 100% accuracy even with 15K negatives, outperforming SSMax which largely degrades at extreme scales.
L254: Many-class classification. Like many TFMs, TabICLv2 is pretrained with up to 10 classes. We use hierarchical classification (cite174†Qu et al., 2025 ) at the ICL stage for more classes. However, target-aware embedding introduces labels before hierarchical partitioning.
L255: $\blacktriangleright$ To address this, we propose mixed-radix ensembling : for $C>10$ classes, we compute balanced bases $[k_{0},\ldots,k_{D-1}]$ with each $k_{i}\leq 10$ and $\prod_{i}k_{i}\geq C$, then decompose each label $y$ into $D$ digits $y^{(i)}\in\{0,\ldots,k_{i}{-}1\}$ via mixed-radix representation. Each digit defines a coarser grouping of the original classes. We run $\text{TF}_{\text{col}}$ once per digit and average the outputs:
L256:  | $$O_{\mathrm{avg}}=\frac{1}{D}\sum_{i=0}^{D-1}\text{TF}_{\text{col}}(E_{1}+\mathrm{Embed_{\text{TAE}}}(y^{(i)}))~.$$  |
L257: 
L258: Combined with hierarchical classification in $\text{TF}_{\text{icl}}$, this enables TabICLv2 to handle an arbitrary number of classes. See cite43†Section A.3 for details.
L259: $\blacktriangleright$ Quantile predictions for regression. Existing TFMs adopt different strategies for regression: TabPFNv2 and TabPFN-2.5 model the full predictive distribution by discretizing the target space into bins and applying cross-entropy loss, while Mitra and TabDPT predict point estimates using MSE loss. In addition, like most TFMs except LimiX, we train separate models for classification and regression.
L260: TabICLv2 instead predicts 999 quantiles at probability levels $\alpha\in\{0.001,0.002,\ldots,0.999\}$, trained with pinball loss summed across all quantiles. In preliminary experiments using RMSE evaluation, we found that quantile regression outperforms MSE and the bin-based approach of TabPFNv2.
L261: At inference, for point estimation we simply average the predicted quantiles, which proves both fast and effective. For probabilistic predictions, we construct a full distribution from the quantiles by enforcing monotonicity via sorting (the default) or isotonic regression (cite212†Barlow & Brunk, 1972 ; cite213†Busing, 2022 ), extrapolating tails with parametric exponential models, and deriving closed-form PDF, CDF, and moments. See cite108†Appendix I for details.
L262: ## 4 Pretraining and Inference
L263: 
L264: ### 4.1 Pretraining setup
L265: 
L266: We significantly improve the pretraining setup compared to TabICL, the reference TFM with open pretraining.
L267: ##### Three pretraining stages.
L268: 
L269: We retain the three-stage structure of TabICL that progressively expands the size of pretraining datasets, with up to 100 features throughout all stages. However, following TabPFNv2, we reduce the batch size to 64, allowing more steps with fewer datasets ($\approx$35M) than TabICL ($\approx$83M) and TabPFNv2 ($\approx$130M). The three stages are:
L270: 
L271:   * •
L272: 
L273: Stage 1: 500K steps on datasets with 1,024 samples, 30–90% for training, max learning rate 8e-4.
L274: 
L275:   * •
L276: Stage 2: 40K steps on datasets with 400–10,240 samples (log-uniform), 80% for training, max learning rate 1e-4.
L277: 
L278:   * •
L279: 
L280: Stage 3: 10K steps on datasets with 400–60K samples (log-uniform), 80% for training, max learning rate 2e-5.
L281: 
L282: In cite53†Section B.1 , we show that stages 2 and 3 yield progressive performance improvements, especially on large datasets.
L283: ##### Optimizer.
L284: We use the Muon optimizer (cite214†Jordan et al., 2024b ) based on the implementation of cite215†Schaipp (2025) instead of AdamW (resp. Adam) used by TabICL (resp. TabPFNv2). Following Moonlight (cite216†Liu et al., 2025 ), this implementation multiplies the learning rate for each parameter $W\in\mathbb{R}^{n\times m}$ by $0.2\cdot\sqrt{\max\{n,m\}}$. We find higher learning rates preferable for Muon. As a result, we use a max learning rate of 8e-4 for the stage 1 compared to 1e-4 for AdamW in TabICL.
L285: We adopt cautious weight decay (cite217†Chen et al., 2025a ) with parameter $0.01$, which applies decay only when the update and parameter have the same sign, avoiding interference with beneficial gradient directions. We also increase gradient clipping from $1$ to $10$ for stages 1 and 2, sample different train/test sizes per micro-batch, and use a cosine learning rate schedule across all stages.
L286: ##### Pretraining cost.
L287: 
L288: On H100 GPUs with 80GB memory, stage 1 takes around 20 GPU-days, stage 2 around 2.5 GPU-days, and stage 3 around 2 GPU-days, totaling 24.5 GPU-days per model. Given that one H100-hour is roughly equivalent to 2 A100-hours, our pretraining cost is lower than TabICL (60 A100-days).
L289: ### 4.2 Inference optimizations
L290: 
L291: We implement disk offloading (cite102†Section H.2 ), reducing requirements to under 24 GB CPU and 50 GB GPU to process a table with 1M samples and 500 features within 450 seconds (cite218†Figure H.2 ). Combined with QASSMax for long-context generalization, TabICLv2 can natively handle million-scale tables without retrieval and distillation. In addition, we reduce redundant computation by selectively computing $Q/K/V$ projections (cite98†Section H.1 ).

L294: cite219†Image: Refer to caption L295: Figure 4: High-level structure of the synthetic dataset generation prior. L297: (e) Examples of generated 2D classification datasets (cf. cite221†Figure F.1 ).
L298: Our pretraining data is entirely synthetic, following the approach pioneered in TabPFN (cite165†Hollmann et al., 2022 ). The data-generating mechanism is termed prior, as it implicitly defines a Bayesian prior over datasets. For TabICLv2, we design a new prior that retains the structural causal model framework used in (cite165†Hollmann et al., 2022 ), incorporates innovations brought by TabICL and TabPFNv2 priors, and adds many novel design options and sampling mechanisms (see cite66†Section E.1 ).
L299: Unlike architectural and pretraining choices, the new prior is developed mostly without experimental feedback, since fine-grained ablations are impractical and prone to overfitting validation datasets. Instead, the prior development is guided by general design principles (cite222†Wilson & Izmailov, 2020 ), maximizing dataset diversity (e.g., variable dependencies and categorical cardinalities) while encoding useful inductive biases and preserving computational efficiency.
L300: This new prior is key to the final performance: pretraining TabICLv2 with the TabICL prior yields substantially lower performance (cite223†Figure 10 , gray). An ablation using the TabPFNv2 prior is not possible, as it is not open-source. We provide a high-level prior description below and defer details to cite65†Appendices E and cite95†F .
L301: ##### High-level structure.
L302: cite224†Figure 4 summarizes the TabICLv2 prior. We first sample global dataset properties, such as the number of numerical and categorical features, and the dataset size. We then sample a directed acyclic graph and random functions defining parent–child relationships, yielding a causal data-generating model. To obtain a dataset with $n$ samples, a matrix $X\in\mathbb{R}^{n\times d_{i}}$ of $n$ random vectors is sampled at each root node $i$ and propagated through the graph.
L303: Each dataset feature is extracted from a randomly assigned node. Only a subset of a node’s dimensions is used to generate each feature, leaving other dimensions unobserved and thereby introducing noise into the dataset. Unlike prior work, we do not add Gaussian noise at the node level. For numerical features (e.g., $x_{1}$), feature values are extracted from a single node dimension.
L304: For categorical features (e.g., $x_{2}$), multiple node dimensions are extracted and discretized, either via nearest-neighbor assignment or by applying a softmax to obtain a categorical distribution.
L305: ##### New sampling mechanisms
L306: 
L307: Since the random graph sampling mechanism used by (cite169†Hollmann et al., 2025 ) can only generate tree-structured graphs, we introduce a “random Cauchy graph” mechanism, which models different global and local node connectivities and is described in cite71†Section E.4 .
L308: The relation between a child node and its parents is generated using several steps depicted in cite224†Figure 4 (c). The key step consists in sampling diverse random functions to apply to the parent data. We use eight types of random functions, listed in cite224†Figure 4 (d). The first three are adapted from TabPFNv2 while the other five are new.
