L181: We introduce TabICLv2, a new state-of-the-art foundation model for regression and classification built on three pillars: (1) a novel synthetic data generation engine designed for high pretraining diversity; (2) various architectural innovations, including a new scalable softmax in attention improving generalization to larger datasets without prohibitive long-sequence pretraining; and (3) optimized pretraining protocols, notably replacing AdamW with the Muon optimizer.
L225: Scalable Softmax (cite202†Nakanishi, 2025 , SSMax,) scales attention logits by $s\log n$, where $s$ is a learnable per-head parameter. Concurrent theoretical analysis (cite209†Chen et al., 2025 ) establishes that $\log n$ scaling is necessary to maintain attention sharpness as context length $n$ grows.
L232: We propose repeated feature grouping, which places each feature into multiple groups via circular shifts while preserving the number of effective features. Specifically, for a table with $m$ columns, we create $m$ groups where the $j$-th group contains columns at positions $(j,j+1,j+3)\bmod m$. Each group is encoded by a shared linear layer $\mathrm{Lin}:\mathbb{R}^{3}\to\mathbb{R}^{d}$:
L233:  | $$E_{1}[i,j]=\mathrm{Lin}\big(x_{i,j},\,x_{i,(j+1)\bmod m},\,x_{i,(j+3)\bmod m}\big).$$  |
L234: 
L235: The shift pattern $(0,1,3)$ ensures that for tables with at least 7 columns, no pair of columns appears together in more than one group. We show in cite42†Section A.1 that this pattern generalizes to arbitrary group sizes, although we did not observe consistent improvements from larger groups.

L244: $\blacktriangleright$ Target-aware embedding. We find it beneficial to inject target information early. After repeated feature grouping produces input data representation $E_{1}\in\mathbb{R}^{n\times m\times d}$, we add target embeddings to each training token:
L245: 
L246:  | $$E_{2}[i,j]=E_{1}[i,j]+\mathrm{Embed_{\text{TAE}}}(y_{i}),\quad i\in\mathcal{D}_{\mathrm{train}},$$  |
L247: where $\mathrm{Embed_{\text{TAE}}}$ is a linear layer for regression or a learnable lookup table for classification. Unlike TabPFNv2 appending the target as an additional column, we directly add target embeddings to all features. This also helps mitigate representation collapse because even when two features share similar distributions, their association with target values often differs across samples.
L248: Unlike TabICL, which compresses each row into a few tokens before seeing the targets, our early target injection allows TabICLv2 to determine the relevance of features before compression.
L249: Compression then ICL. TabICLv2 processes $E_{2}$ in three stages: (1) column-wise embedding applies a set transformer $\text{TF}_{\text{col}}$ (cite216†Lee et al., 2019 ) to each column; (2) row-wise interaction uses a transformer $\text{TF}_{\text{row}}$ with [CLS] tokens to collapse feature embeddings per row into a single vector; (3) dataset-wise ICL combines row embeddings with target embeddings and uses a transformer $\text{TF}_{\text{icl}}$ where test samples attend to training samples for prediction.
L250: See cite43†Section A.2 for details. $\blacktriangleright$ Compared to TabICL, our key innovation here is applying a novel scalable softmax to $\text{TF}_{\text{icl}}$ and to the part of $\text{TF}_{\text{col}}$ where inducing points aggregate input information.
L251: $\blacktriangleright$ Query-aware scalable softmax. To improve generalization to larger datasets, we extend Scalable Softmax (SSMax, cite202†Nakanishi 2025 ), a temperature scaling method that sharpens attention distributions by rescaling queries before computing logits. Let $q_{h}=(q_{hi})$ be a query vector at head $h$ with head dimension indexed by $i$, and let $n$ be the size of the training set. SSMax rescales queries with a learnable per-head scalar $s_{h}$:
L252:  | $$\tilde{q}_{hi}=q_{hi}\cdot s_{h}\log n~.$$  |
L253: 
L254: We propose query-aware scalable softmax (QASSMax), which rescales each query element as:
L255: 
L256:  | $$\tilde{q}_{hi}=q_{hi}\cdot\underbrace{\mathrm{MLP}_{\mathrm{base}}(\log n)_{hi}}_{\text{base scaling}}\cdot\underbrace{\big(1+\tanh(\mathrm{MLP}_{\mathrm{gate}}(q_{h})_{i})\big)}_{\text{query-aware gating}}$$  |
L257: where for $H$ attention heads, $\mathrm{MLP}_{\mathrm{base}}:\mathbb{R}\to\mathbb{R}^{H\times d_{\mathrm{head}}}$ and $\mathrm{MLP}_{\mathrm{gate}}:\mathbb{R}^{d_{\mathrm{head}}}\to\mathbb{R}^{d_{\mathrm{head}}}$ are two-layer MLPs with 64 hidden neurons and GELU activation.
L258: We design QASSMax based on the following rationale: (a) The $\log n$ factor is critical as it counteracts the linear growth of the softmax denominator with respect to $n$ (cite202†Nakanishi, 2025 ; cite209†Chen et al., 2025 ); (b) ASEntmax (cite210†Vasylenko et al., 2026 ) uses learnable $\delta+\beta(\log n)^{\gamma}$, inspiring us to generalize to $\mathrm{MLP}_{\mathrm{base}}(\log n)$; (c) Element-wise scaling increases expressiveness beyond per-head scalars; (d) Selective Attention (cite211†Zhang et al., 2024 ) introduces query-awareness in temperature scaling, which motivates us to use the bounded query-aware gating $\in(0,2)$ that modulates the base scaling without dominating the $\log n$ trend.
L259: In addition, our gating design shares similar insights with Gated Attention (cite217†Qiu et al., 2025 ), which applies gating to attention outputs and finds query-dependent, element-wise gating most effective.
L260: QASSMax applied to $\text{TF}_{\text{col}}$ and $\text{TF}_{\text{icl}}$ yields substantial performance improvements, as shown in the ablation study (cite37†Section 7 ). To study its effect on attention fading, we design a toy needle-in-haystack classification task (cite218†Figure 3 ): the model must focus on a single anchor sample (the needle) among increasing negative samples (the haystack). Without scalable softmax, attention entropy rises and accuracy drops.
L261: However, QASSMax maintains low entropy and 100% accuracy even with 15K negatives, outperforming SSMax, whose performance degrades substantially at extreme scales.
L262: Many-class classification. Like many TFMs, TabICLv2 is pretrained with up to 10 classes. We use hierarchical classification (cite181†Qu et al., 2025 ) at the ICL stage for more classes. However, target-aware embedding introduces labels before hierarchical partitioning.
L263: $\blacktriangleright$ To address this, we propose mixed-radix ensembling : for $C>10$ classes, we compute balanced bases $[k_{0},\ldots,k_{D-1}]$ with each $k_{i}\leq 10$ and $\prod_{i}k_{i}\geq C$, then decompose each label $y$ into $D$ digits $y^{(i)}\in\{0,\ldots,k_{i}{-}1\}$ via mixed-radix representation. Each digit defines a coarser grouping of the original classes. We run $\text{TF}_{\text{col}}$ once per digit and average the outputs:
L264:  | $$O_{\mathrm{avg}}=\frac{1}{D}\sum_{i=0}^{D-1}\text{TF}_{\text{col}}(E_{1}+\mathrm{Embed_{\text{TAE}}}(y^{(i)}))~.$$  |
L265: 
L266: Combined with hierarchical classification in $\text{TF}_{\text{icl}}$, this enables TabICLv2 to handle an arbitrary number of classes. See cite44†Section A.3 for details.
L267: $\blacktriangleright$ Quantile predictions for regression. Existing TFMs adopt different strategies for regression: TabPFNv2 and TabPFN-2.5 model the full predictive distribution by discretizing the target space into bins and applying cross-entropy loss, while Mitra and TabDPT predict point estimates using MSE loss. In addition, like most TFMs except LimiX, we train separate models for classification and regression.
L268: TabICLv2 instead predicts 999 quantiles at probability levels $\alpha\in\{0.001,0.002,\ldots,0.999\}$, trained with pinball loss summed across all quantiles. In preliminary experiments using RMSE evaluation, we found that quantile regression outperforms MSE and the bin-based approach of TabPFNv2.
L269: At inference, for point estimation we simply average the predicted quantiles, which proves to be both fast and effective. For probabilistic predictions, we construct a full distribution from the quantiles by enforcing monotonicity via sorting (the default) or isotonic regression (cite219†Barlow and Brunk, 1972 ; cite220†Busing, 2022 ), extrapolating tails with parametric exponential models, and deriving closed-form PDF, CDF, and moments. See cite108†Appendix I for details.

L581: Column-wise embedding. Column-wise embedding processes each column through a set transformer $\text{TF}_{\text{col}}$ (cite216†Lee et al., 2019 ). Its core is induced self-attention with $k$ inducing vectors that proceeds in two stages: the first stage aggregates input information into inducing vectors and the second broadcasts back to the input, reducing complexity from $O(n^{2})$ to $O(nk)$.
L582: We make three improvements: (a) we directly use the outputs of $\text{TF}_{\text{col}}$ as feature embeddings, while TabICL applies an additional transformation; (b) we apply our query-aware scalable softmax (QASSMax) to the first stage of induced self-attention; and (c) $\text{TF}_{\text{col}}$ is essentially an in-context learner operating within each column thanks to target-aware embedding.
L583: Row-wise interaction. Following TabICL (cite181†Qu et al., 2025 ), we prepend four learnable [CLS] tokens to each row and process them through a transformer $\text{TF}_{\text{row}}$ with RoPE (cite208†Su et al., 2024 ). The outputs of the [CLS] tokens are concatenated to form a $4d$-dimensional row embeddings, effectively collapsing the feature dimension.
L584: Dataset-wise in-context learning. Training row embeddings are combined with target embeddings. A transformer $\text{TF}_{\text{icl}}$ processes all embeddings, where test samples attend only to training samples. A two-layer MLP converts the outputs into target predictions. We apply QASSMax to $\text{TF}_{\text{icl}}$ to improve its long-context generalization.
L585: ### A.3 Many-class classification
L586: Like many tabular foundation models, TabICLv2 is pretrained on classification tasks with up to 10 classes. For tasks with more classes, TabICL (cite181†Qu et al., 2025 ) proposed hierarchical classification during the ICL stage, which recursively partitions classes into subproblems with at most 10 classes each. However, our target-aware embedding introduces label information before hierarchical partitioning occurs.
L1119: ##### Layer normalization reuse.
L1120: 
L1121: We adopted the pre-norm setting in the transformer block. To avoid redundant computation, we first apply layer normalization to the full input sequence, then perform slicing to extract the required subset for query, key, or value computation. This ensures that normalization statistics are computed once over the complete sequence, and the sliced representations remain properly normalized without requiring separate normalization passes for different subsets.

L1135: ##### Memory bottleneck analysis.
L1136: Given an input $X\in\mathbb{R}^{b\times n\times m}$, where $b$, $n$, and $m$ represent the number of datasets, the number of samples, and the number of features respectively, $X$ is first reshaped to $\mathbb{R}^{(b\times m)\times n}$ and processed by $\text{TF}_{\text{col}}$ to produce feature embeddings $E\in\mathbb{R}^{(b\times m)\times n\times d}$. The memory bottleneck lies in storing this intermediate tensor $E$.

L1204:

L1242: ### I.3 Quantile crossing correction
L1243: 
L1244: A quantile crossing violation occurs when for some $i<j$:
L1245: 
L1246:  | $$\hat{Q}(\alpha_{i})>\hat{Q}(\alpha_{j})\quad\text{despite }\alpha_{i}<\alpha_{j}$$  |
L1247: 
L1248: This violates the fundamental monotonicity requirement of quantile functions. We provide three ways to handle this issue:
L1249: ##### (1) No correction.
L1250: 
L1251: The simplest approach is to ignore crossing violations. This may be acceptable when crossings are rare. However, this can lead to invalid probability densities in regions where crossings occur.
L1252: ##### (2) Sorting.
L1253: 
L1254: A straightforward correction is to sort the predicted quantiles:
L1255: 
L1256:  | $$\mathbf{q}^{\text{sorted}}=\text{sort}(\hat{q}_{1},\hat{q}_{2},\ldots,\hat{q}_{K})$$  |
L1257: 
L1258: This guarantees monotonicity with $O(K\log K)$ complexity. However, sorting may destroy the correspondence between quantile values and their original probability levels, which can distort the distribution shape.
L1259: ##### (3) Isotonic regression.
L1260: 
L1261: The optimal correction in the $L^{2}$ sense is given by isotonic regression (cite219†Barlow and Brunk, 1972 ), which solves:
L1262: 
L1263:  | $$\mathbf{q}^{*}=\operatornamewithlimits{arg\,min}_{\mathbf{q}:q_{1}\leq q_{2}\leq\cdots\leq q_{K}}\sum_{k=1}^{K}w_{k}(\hat{q}_{k}-q_{k})^{2}$$  |
L1264: where $w_{k}>0$ are optional weights (by default, $w_{k}=1$). This problem admits a unique solution that can be computed in $O(K)$ time via the Pool Adjacent Violators Algorithm (PAVA) (cite378†Best and Chakravarti, 1990 ). PAVA iteratively merges adjacent blocks that violate monotonicity and replaces each merged block with its weighted average.
L1265: Despite its linear per-sample complexity, PAVA is inherently a 1D, data-dependent procedure in which the sequence of merges depends on local violations and therefore introduces sequential dependencies along the quantile index. As a result, it is not straightforward to implement PAVA as a single fully vectorized operation, which limits its practical throughput because we often need to process large batches of predictions (e.g., the entire test set).
L1266: We leverage the just-in-time compilation of Numba (cite379†Lam et al., 2015 ) to optimize the PAVA implementation, achieving effective CPU parallelism. As shown in Figure cite380†I.1 , the Numba-based PAVA implementation achieves competitive performance with torch.sort on CPU for large batch sizes, while being faster than the PAVA implementation of Scipy (cite381†Virtanen et al., 2020 ).
L1267: However, the Numba-based implementation cannot compete with torch.sort on GPU, which relies on highly optimized parallel sorting primitives implemented in dedicated CUDA kernels. Given this performance gap and the empirical observation that quantile crossing is rare in the predictions of TabICLv2, we use sorting by default for monotonicity enforcement.
L1268: Figure I.1: Execution time comparison of different monotonicity enforcement methods across batch sizes ($K=999$ quantiles per sample). Sort-GPU (torch.sort on CUDA) achieves the best performance. Numba (our parallel PAVA implementation) and Sort-CPU show competitive scaling on CPU. Scipy (scipy.optimize.isotonic_regression) processes samples sequentially, becoming slower than Numba at large batch sizes.
L1269: ### I.4 Tail parameter estimation
L1270: 
L1271: The exponential tail scale parameters $\beta_{L}$ and $\beta_{R}$ are estimated from the boundary quantiles using log-space linear regression. For the left tail, the model is $Q(\alpha)=\beta_{L}\ln(\alpha)+c_{L}$. Given $K_{\text{tail}}$ quantiles in the left tail region (default is 20), we estimate $\beta_{L}$ using ordinary least squares:
L1272:  | $$\hat{\beta}_{L}=\frac{\text{Cov}(Q,\ln\alpha)}{\text{Var}(\ln\alpha)}\bigg|_{\alpha\in\{\alpha_{1},\ldots,\alpha_{K_{\text{tail}}}\}}$$  |
L1273: 
L1274: Specifically:
L1275: 
L1276:  | $$\hat{\beta}_{L}=\frac{\sum_{k=1}^{K_{\text{tail}}}(q_{k}-\bar{q})(\ln\alpha_{k}-\overline{\ln\alpha})}{\sum_{k=1}^{K_{\text{tail}}}(\ln\alpha_{k}-\overline{\ln\alpha})^{2}}$$  |
L1277: 
L1278: For the right tail, the model is $Q(\alpha)=-\beta_{R}\ln(1-\alpha)+c_{R}$. The estimation is analogous:
L1279:  | $$\hat{\beta}_{R}=-\frac{\text{Cov}(Q,\ln(1-\alpha))}{\text{Var}(\ln(1-\alpha))}\bigg|_{\alpha\in\{\alpha_{K-K_{\text{tail}}+1},\ldots,\alpha_{K}\}}$$  |
L1280: 
L1281: The estimated parameters are clamped to ensure numerical stability: $\beta\in[\beta_{\min},\beta_{\max}]=[0.01,100]$.

L1284: The CDF $F(z)=P(Z\leq z)$ is the inverse of the quantile function: $F(z)=Q^{-1}(z)$.
L1285: 
L1286: Spline region ($z\in[q_{i},q_{i+1})$):

L1288:  | $$F_{\text{spline}}(z)=\alpha_{i}+\frac{z-q_{i}}{q_{i+1}-q_{i}}(\alpha_{i+1}-\alpha_{i})$$  |
