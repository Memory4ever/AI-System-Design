L196@P3: 3.1 Gated Recurrent Memory Workflow
L197@P3: To address the risk of memory explosion and lack of an exit mechanism, we introduce two gating mechanisms
L198@P3: in the recurrent workflow, the update gate (UG) and the exit gate (EG), inspired by the success of gating in
L199@P3: GRUs [6] for addressing long-term sequence modeling.
L200@P3: Specifically, GRU-Mem mainly changes the memory agent ϕθ while keeping the answer agent ψθ unchanged,
L201@P3: extending the vanilla ϕθ with two extra actions for gate control [36]. It outputs a candidate memory Mˆ
L202@P3: t and
L203@P3: two binary gating signals, Ut and Et, indicating whether to update the memory and whether to terminate the
L204@P3: loop, respectively. This process is formulated as follows:
L205@P3: Ut,Mˆ
L206@P3: t, Et = ϕθ(Q, Ct,Mt−1). (7)

L222@P4: To achieve this, the memory agent ϕθ responds by following a structured output format (see prompts in Figure
L223@P4: 3 and Appendix C, with case studies in Appendix E). The process of one single step t of ϕθ in GRU-Mem
L224@P4: is illustrated in Figure 2. It first produces intermediate reasoning enclosed by <think> and </think>, and
L225@P4: then emits an update decision within <check> and </check>, where "yes" (i.e., Ut == True) triggers a
L226@P4: memory update and "no" (i.e., Ut == False) skips it. Next, it outputs the candidate memory Mˆ
L227@P4: t within
L228@P4: <update> and </update>. If Ut == True, the memory will be updated with the candidate memory (i.e.,
L229@P4: Mt ← Mˆ
L230@P4: t). If Ut == False, the previous memory Mt−1 will be adopted while the candidate memory Mˆ
L231@P4: t
L232@P4: will be discarded (i.e., Mt ← Mt−1). Finally, it decides whether to continue collecting evidence between
L233@P4: <next> and </next>, where "continue" means continuing the recurrent loop and "end" means terminating
L234@P4: the loop. Once terminated, the final memory Mt will be sent into the answer agent ψθ immediately for
L235@P4: answering the question. The detailed process of GRU-Mem is described in Algorithm 1.

L237@P4: To teach the memory agent ϕθ when to correctly activate the update gate and the exit gate, we explicitly
L238@P4: reward correct gate status generation behaviors, beyond merely rewarding the final answer correctness. In this
L239@P4: section, we first introduce the reward design in Section 3.2.1. After that, we discuss how to combine these
L240@P4: rewards for the advantage calculation in Section 3.2.2. More training details can be found in the Appendix B.

L402@P7: 3.3 Inference
L403@P7: Despite being always trained under the control of the exit gate. That is, during training, once Et == True,
L404@P7: the workflow will exit immediately for answering the question. However, for some questions, we can not judge
L405@P7: whether the evidence has been sufficient for answering the question since answering the question requires
L406@P7: reading the whole context (e.g., “What are all the special magic numbers for xxx” as introduced in the
L407@P7: multi-values task in the RULER [12] benchmark). Therefore, we provide two kinds of inference strategies:
L408@P7: with the exit gate (w EG) and without the exit gate (w/o EG), for the inference flexibility. For the w/o EG
L409@P7: inference mode, the generation workflow would not exit even when Et == True.

L417@P7: LLMs. We conduct experiments on two open-source LLM backbones with different sizes: Qwen2.5-3B-Instruct
