L123: ## 3 Method: FormalJudge
L124: 
L125: We present FormalJudge, a neuro-symbolic framework that escapes the probabilistic echo chamber of LLM-as-a-Judge through a bidirectional Formal-of-Thought architecture. The core insight is that while LLMs cannot reliably judge complex composite behaviors, they can reliably answer atomic yes/no questions, and formal logic can then compose these atomic judgments into provable conclusions.
L126: ### 3.1 Problem Formulation
L127: 
L128: Consider an agent $\mathcal{A}$ executing a task specified by user intent $I$ in natural language. The agent produces an execution trajectory $\tau=(a_{1},o_{1},\ldots,a_{T},o_{T})$, where each $a_{t}$ is an action and $o_{t}$ is the resulting observation. The oversight problem is to determine whether $\tau$ satisfies the constraints implicit in $I$, including explicit requirements, implicit safety constraints, and integrity properties.
L131: Our Approach. Rather than directly estimating $p(\text{verdict}\mid I,\tau)$, FormalJudge decomposes oversight into a set of atomic facts: binary predicates that each answer a simple yes/no question about the trajectory:
L132: 
L133:  | $$\mathcal{F}=\{f_{1},\ldots,f_{n}\},\quad\text{where }f_{i}:(I,\tau)\to\{0,1\}.$$  |  | (1)
L134: An extraction function $\mathcal{E}_{\theta}$ evaluates each atomic fact, and a proof generator $\mathcal{G}$ synthesizes a Dafny specification encoding their logical composition. The final verdict is computed by SMT verification $\mathcal{V}$:
L135: 
L136:  | $$v=\mathcal{V}\bigl(\mathcal{G}(\{\mathcal{E}_{\theta}(f_{i},I,\tau)\}_{i=1}^{n})\bigr).$$  |  | (2)
L137: 
L138: This architecture confines probabilistic reasoning to atomic extraction while delegating all logical inference to the deterministic solver.
L139: ### 3.2 Bidirectional Formal-of-Thought Pipeline
L140: 
L141: FormalJudge addresses these limitations through architectural separation: LLMs handle only atomic-level semantic judgments, while Dafny handles all logical composition. The pipeline proceeds through four phases (cite98†Figure 2 ).
L142: #### 3.2.1 Phase 1: Top-Down Intent Decomposition
L143: 
L144: Rather than asking “Does this trajectory satisfy all constraints?”, which requires simultaneous reasoning about execution outcomes, output quality, and constraint satisfaction, we decompose oversight into atomic facts $\mathcal{F}=\{f_{1},\ldots,f_{n}\}$ that each require only a single, well-scoped judgment.
L145: Each atomic fact $f_{i}:(I,\tau)\to\{0,1\}$ satisfies three criteria: binary (answerable as yes/no), grounded (directly observable from trajectory evidence), and context-minimal (requiring only a relevant subset of $\tau$). The specific decomposition is task-dependent, allowing FormalJudge to adapt to diverse oversight scenarios.
L146: #### 3.2.2 Phase 2: Context-Aware Grounded Extraction
L147: 
L148: We define context functions $C_{k}:(I,\tau)\to(I^{\prime},\tau^{\prime})$ that project the full trajectory onto relevant subsets for different atomic facts.
L149: 
L150: The extraction function $\mathcal{E}_{\theta}$ operates in two phases. Deterministic extraction first parses structured trajectory data (e.g., JSON fields, numerical values, and categorical labels) without LLM involvement:
L151:  | $$\mathcal{E}_{\text{det}}(f_{i},I,\tau)=\textsc{Parse}(f_{i},\{o_{t}\}_{t=1}^{T}).$$  |  | (3)
L152: 
L153: Semantic extraction then invokes the LLM for remaining facts with relevant context:
L154: 
L155:  | $$\mathcal{E}_{\theta}(f_{i},I,\tau)=\text{LLM}_{\theta}\bigl(f_{i},C_{k(i)}(I,\tau)\bigr).$$  |  | (4)
L156: #### 3.2.3 Phase 3: Formal Proof Synthesis
L157: 
L158: The proof generator $\mathcal{G}$ synthesizes Dafny code with a layered structure: atomic constants encode extracted fact values, derived predicates combine related facts, and safety predicates define logical formulas:
L159:  | $\displaystyle\phi_{\text{budget}}(\mathcal{F})$  | $\displaystyle\coloneqq f_{\text{total}}\leq f_{\text{limit}},$  |  | (5)
L160:  | $\displaystyle\phi_{\text{allergy}}(\mathcal{F})$  | $\displaystyle\coloneqq\neg f_{\text{containsAllergen}}.$  |  | (6)
L161: 
L162: The verdict predicate aggregates all requirements:
L163: 
L164:  | $$\Phi_{\text{safe}}(\mathcal{F})\coloneqq\bigwedge_{k}\phi_{k}(\mathcal{F}).$$  |  | (7)
L165: #### 3.2.4 Phase 4: SMT Verification
L166: 
L167: The synthesized Dafny specification is compiled through Boogie (cite99†Böhme and Nipkow, 2010 ) to Z3 (cite82†De Moura and Bjørner, 2008 ). The verifier $\mathcal{V}:\mathcal{D}\to\{0,1\}$ returns a mathematically verified verdict: $v=1$ if $\Phi_{\text{safe}}(\mathcal{F})$ holds, $v=0$ otherwise. This phase is entirely deterministic, ensuring that any LLM errors are confined to individual atomic judgments.
L168: ### 3.3 Design Properties
L169: 
L170: The bidirectional architecture achieves soundness through separation of concerns: what to check is defined by the atomic fact taxonomy $\mathcal{F}$; semantic grounding is performed by $\mathcal{E}_{\theta}$ on atomic queries only; and logical composition via $\mathcal{G}$ and $\mathcal{V}$ is handled deterministically by Dafny and Z3.
L171: The architecture provides immunity to persuasive manipulation: the formal verifier operates exclusively on grounded facts from actions and observations, ignoring explanations or reasoning traces. Finally, the modular design ensures compositionality: adding new requirements extends $\mathcal{F}$ with additional facts and predicates $\phi_{k}$, with $\Phi_{\text{safe}}=\bigwedge_{k}\phi_{k}$ automatically integrating them.
