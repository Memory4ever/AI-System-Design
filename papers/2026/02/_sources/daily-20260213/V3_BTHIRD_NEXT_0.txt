L229: ## IV Extensions to Other SplitCom Variants
L230: 
L231: The proposed SplitCom framework primarily targets uplink activation transmissions from clients to the server during the forward pass. However, its underlying principles can be naturally extended to downlink gradient transmission and U-shaped SFL architectures.
L232: ### IV-A Extension to Bidirectional Compression
L233: In standard SFL, both forward activations (uplink) and backward gradients (downlink) contribute to communication costs. While mitigating uplink traffic is often prioritized due to asymmetric wireless data rates and the limited energy budget of edge devices, suppressing bidirectional communication can further improve overall efficiency.
L234: Specifically, the temporal redundancy for activations also applies to gradients: given a training sample, if the model changes very slowly across epochs under PEFT, the corresponding gradients flowing back from the server also exhibit high temporal correlation.
L235: Consequently, the standard SplitCom framework can be extended to compress both uplink activations and downlink gradients by maintaining separate cache libraries on both clients and the server. The server caches activations for potential reuse in forward passes, while clients cache gradients for backward passes. Each transmission direction applies the similarity check independently with its own threshold (e.g., $\theta^{\text{up}}_{t}$ for uplink, $\theta^{\text{down}}_{t}$ for downlink).
L236: For example, when transmitting gradients from server to client $i$ during the backward pass, for an input sample $j$ at epoch $t$, the server computes the current gradient $z_{t,i}^{j}$, applies RP to obtain its compressed representation $\tilde{z}_{t,i}^{j}$, and evaluates cosine similarity against the compressed cached counterpart $\bar{\tilde{z}}_{s,i}^{j}$ in its comparison cache using $\cos\bigl(\tilde{z}_{t,i}^{j},\bar{\tilde{z}}_{s,i}^{j}\bigr)$.
L237: If $\cos\bigl(\tilde{z}_{t,i}^{j},\bar{\tilde{z}}_{s,i}^{j}\bigr)\geq\theta_{t}^{\text{down}}$, the server skips transmissions and client $i$ reuses the cached gradient $\bar{z}_{c,i}^{j}$ for the frontend backward pass, where $\theta_{t}^{\text{down}}$ is the similarity threshold. Otherwise, the server transmits the gradient $z_{t,i}^{j}$ to client $i$, and client $i$ updates its cache: $\bar{z}_{c,i}^{j}\leftarrow z_{t,i}^{j}$.
L238: At the same time, the server updates its comparison cache: $\bar{\tilde{z}}_{s,i}^{j}\leftarrow\tilde{z}_{t,i}^{j}$. Moreover, the adaptive threshold management strategies introduced in Section cite11†III-C , specifically bang-bang control and DDPG-based RL, can be applied to $\theta^{\text{down}}_{t}$ to balance downlink communication efficiency and model performance.
L239: ### IV-B Extension to U-shape SplitCom
L240: While the similarity-aware activation reuse mechanism (Section cite10†III-B ) effectively reduces uplink communication overhead, traditional SFL architectures computing loss on the server exposes clients’ labels to the server, compromising user privacy. To address these issues, we extend SplitCom to the U-shape architecture [cite76†43 ] that relocates loss computation to clients.
L241: The model is partitioned into three segments: the client retains the frontend and tail portions^{5}^{5} 5 We define the frontend as the model’s initial layers close to the input, and the tail as the final layers proximal to the output., while the computationally intensive intermediate layers are offloaded to the server. This configuration allows the loss computation to be performed locally on the client, effectively preserving the privacy of ground-truth labels.
L242: However, this U-shape architecture establishes four distinct communication interfaces requiring threshold control: (1) frontend-to-server uplink activations, (2) server-to-tail downlink activations, (3) tail-to-server uplink gradients, and (4) server-to-frontend downlink gradients, which is even more complicated than bidirectional communications.
L243: To mitigate the potential communication bottlenecks introduced by these multiple interfaces, we extend our reuse mechanism to operate symmetrically across all four transmission boundaries.
L244: Quadri-directional compression. At each communication session, we apply the similarity-aware reuse mechanism described in Section cite10†III-B . Both clients and the server maintain separate cache libraries for activations and gradients at each communication session.
L245: Specifically, both clients and the server maintain two types of caches: (1) the sender maintains comparison caches, which store RP-compressed representations of activations and gradients to facilitate memory-efficient similarity checks; (2) the receiver maintains reuse caches, which store activations and gradients for actual reuse during forward and backward passes when transmission is skipped.
L246: This mechanism applies symmetrically to all four communication sessions, each with its own threshold: $\theta_{t}^{\text{f2s}}$ (frontend-to-server), $\theta_{t}^{\text{s2t}}$ (server-to-tail), $\theta_{t}^{\text{t2s}}$ (tail-to-server), and $\theta_{t}^{\text{s2f}}$ (server-to-frontend).
L247: The adaptive threshold strategies (BBC and DDPG) introduced in Section cite11†III-C can be directly extended to manage thresholds at all four communication sessions in U-shape SplitCom. For the fixed strategy, each communication session is assigned a predetermined constant threshold value that remains unchanged throughout training.
L248: For the bang-bang control strategy, each communication session maintains its own pair of low and high thresholds (e.g., $\theta_{\text{low}}^{\text{f2s}}$ and $\theta_{\text{high}}^{\text{f2s}}$ for the frontend-to-server session), with switching decisions based on global validation PPL dynamics.
L249: For the DDPG-based RL strategy, we deploy four independent DDPG agents (each consisting of the same lightweight three-layer fully connected actor-critic networks as described in Section cite11†III-C ), one for each communication session, where each agent learns to optimize its respective threshold based on communication efficiency and model performance.

L148: In other words, $\mathbb{E}[\mathcal{D}{\theta}\mathcal{D}{\theta}^{\top}]$^{10}^{10} 10 We drop the variables from the expectation for simplicity. reduces to block diagonal terms of $\mathbb{E}[\mathcal{D}{\mathrm{vec}\left(W\right)}\mathcal{D}{\mathrm{vec}\left(W\right)}^{\top}]$. While this assumption vastly reduces the size of the matrix, even block-diagonal approximations are difficult to work with in practice.
L149: Thus, K-FAC imposes additional structure on the Hessians of each of these affine components by assuming that the activations $a$ and the post activation pseudogradients $\mathcal{D}{s}$ are independent of each other. This gives us the K-FAC approximation,
L150:  |  | $\displaystyle\tilde{G}_{\mathrm{vec}\left(W\right)}\coloneqq\mathbb{E}[\mathcal{D}{\mathrm{vec}\left(W\right)}\mathcal{D}{\mathrm{vec}\left(W\right)}^{\top}]$  |
L151:  |  | $\displaystyle=\mathbb{E}[(a\otimes\mathcal{D}{s})(a\otimes\mathcal{D}{s})^{\top}]$  |
L152:  |  | $\displaystyle=\underbrace{\mathbb{E}[(aa^{\top})]}_{\mathbf{A}}\otimes\underbrace{\mathbb{E}[(\mathcal{D}{s}\mathcal{D}{s}^{\top})]}_{\mathbf{S}}$  |
L153: where the first equality is the definition of $\mathcal{D}{\mathrm{vec}\left(W\right)}$ by chain rule, and the second equality is the independence assumption. Note $\mathbf{A},\mathbf{S}$ can be fit with Monte Carlo estimates of the expectation. To compute the Hessian’s inverse effectively we can now use the fact that,
L154: 
L155:  | $$\tilde{G}^{-1}_{\mathrm{vec}\left(W\right)}=(\mathbf{S}^{-1}\otimes\mathbf{A}^{-1})$$  |
L156: and thus we just have to invert the smaller $\mathbf{S}$ and $\mathbf{A}$ factors to invert $\tilde{G}_{\mathrm{vec}\left(W\right)}$.
L157: #### Eigenvalue correction
L158: 
L159: While it takes an additional pass over the dataset, Eigenvalue-corrected K-FAC (EK-FAC) [cite40†15 ] offers a direct improvement to the K-FAC approximation we just introduced. In this setting, we take advantage of another property of the Kronecker product. In particular, the fact that there is a spectral decomposition of the matrix
L160: 
L161:  | $$\tilde{G}_{\mathrm{vec}\left(W\right)}=(Q_{S}\otimes Q_{A})^{\top}(\Lambda_{S}\otimes\Lambda_{A})(Q_{S}\otimes Q_{A})$$  |
L162: where $Q_{S}$ and $Q_{A}$ are matrices with dimensions $dim(s)\times dim(s),dim(a)\times dim(a)$ respectively.
L163: This center matrix $\Lambda_{S}\otimes\Lambda_{A}$ is the Kronecker product of two diagonal matrices and is only an approximation of the true eigenvalues of the Hessian in the $(Q_{S}\otimes Q_{A})$ basis. In the EK-FAC approximation we replace this with a single diagonal matrix $\Lambda$, which is fit using another pass over the data. Observe that this only has $dim(\mathrm{vec}\left(W\right))$ non-zero elements and thus can be stored in the same amount of memory as the model weights themselves.
L164: We fit these corrected eigenvalues using a Monte Carlo estimate of,
L165:  | $$\Lambda_{ii}=\mathbb{E}[((Q_{S}\otimes Q_{A})\textrm{vec}(\mathcal{D}W))^{2}_{i}].$$  |
L166: 
L167: This gives us a superior estimator, allowing us to even more accurately model the constraints on the retain set, at the cost of an additional pass over the data to fit this matrix. We explore this trade off in Section cite19†IV-C .
L168: ### II-F How EK-FAC’s Compute Requirements Scale
L169: For second-order methods to be useful for unlearning in LLMs, they need to work on large models. Thankfully, EK-FAC and especially K-FAC scale reasonably well with model size. Assume we are fitting EK-FAC on a weight matrix $W\in\mathbb{R}^{d\times m}$. Then K-FAC’s memory consumption scales like $O(d^{2}+m^{2})$, and EK-FAC adds an additional $dm$ factor for storing the eigenvalues.
L170: Thus, assuming the weight matrices have a constant ratio ($d=O(m)$ so $d^{2},m^{2},dm=O(m^{2})$), then EK-FAC’s memory requirements will scale linearly with model size (which is $O(m^{2})$).
L171: Turning to floating point operations, assuming our dataset is of size $n$ inputs, fitting the K-FAC factors $S$ and $A$ requires $2n$ outer products and thus $O(n(m^{2}+d^{2}))$ floating point operations above and beyond doing a single pass over the retain set. Performing the necessary matrix inverses and QR decompositions to compute $Q_{A}$ and $Q_{S}$ scales like $O(m^{3}+d^{3})$ and fitting the lambda correction scales like $O(n(md^{2}+dm^{2}))$.
L172: Thus overall, if we again assume a constant ratio between $m$ and $d$, the number of floating point operations required to fit and invert the Hessian scales like $O(nm^{3})$, i.e., it’s slightly super-linear in the number of model weights.
L173: Nevertheless, versions of EK-FAC have already been applied to 52 billion parameter models [cite41†16 ] and our own benchmarking of fitting hessian on models from 0.5B to 14B parameters shows EK-FAC’s runtime is consistent with this flop accounting analysis and, in practice, approximately linear in model size (see Appendix cite67†Hessian benchmarking across model scales ).

L199: ##### Fitting and inverting the Gauss-Newton Hessian
L200: 
L201: In Section cite12†II-E we overviewed different approaches to estimating the Gauss-Newton Hessian, and hence the inverse Hessian vector product needed for the Gauss-Newton step. Our method uses the K-FAC and optionally EK-FAC estimates for the Gauss-Newton Hessian, and we will later empirically compare with other Hessian estimators.
L202: Specifically, we use the same strategies to handle weight sharing and K-FAC/EK-FAC factor fitting as [cite41†16 ] and build on the CurvLinOps library [cite69†39 ]. We discussed how these factors are fit (i.e., Monte-Carlo estimates) and the assumptions they make in Section cite12†II-E . Notably, when inverting the matrix, these parametric approximations require the use of damping to improve numerical stability.
L203: This means that in practice we invert $\hat{G}_{\theta}+\lambda I$ instead of $G_{\theta}$ where $\lambda$ is the damping parameter.
L204: Given how we approximate the inverse Gauss-Newton Hessian, we now turn to the implementation details that make K-FADE unlearning effective and efficient in different settings.
L205: ##### Suppression objective
L206: 
L207: We consider two options for $\mathcal{L}_{F}$ which we aim to increase: the negative margin (so increasing means decreasing the margin) and cross entropy. For tasks where we aim to approximate retraining, we found cross entropy is effective for $\mathcal{L}_{F}$ (intuitively maximizing this is the negative of the training objective [cite60†32 ]).
L208: For output suppression tasks where the retain set $D_{R}$ is not a subset of the training dataset, i.e., when we are optimizing cite9†Section II-B , we empirically found that the average negative per-example margin [cite70†40 ] is more effective; this was particularly so when we required many Gauss-Newton steps.
L209: Recall the negative per-example margin is defined as $\mathcal{\ell_{(\text{margin})}}(z,y)=-z_{y}+\log\sum_{i\neq y}\exp(z_{i})$, which compares the logit of the predicted label to the log probability of all the other labels. One can think of this as a version of the cross entropy loss that does not saturate as the model becomes more confident since we remove the target logit $z_{y}$ contribution from the normalization term.
L210: It can also be formulated as $\ell_{\text{margin}}(z,y)=\ell(z,y)^{1-\rho(y|z)}$.
L211: ##### Step size
L212: Our method has two main hyper-parameters, the number of steps and the step size $\alpha$. Here we consider how we scale our step size over multiple steps. We follow the motivation from Section cite10†II-C and normalize the Gauss-Newton Hessian by $\|\nabla_{\theta}\mathcal{L}_{F}\|_{\tilde{G}_{\theta}^{-1}}$, hence by a step size of $\alpha$ we mean scaling the Gauss-Newton update by $\frac{\alpha}{\|\nabla_{\theta}\mathcal{L}_{F}\|_{\tilde{G}_{\theta}^{-1}}}$.

This removed the need to tune the step size at every step.
L214: ##### What to fit the Hessian on
L215: 
L216: Implementations on linear models, suggest that we should only be fitting the Gauss-Newton Hessian on the retain set [cite60†32 ]. Supporting this, we found that including the forget set in the Hessian computation generally reduces the specificity of the unlearning updates (Section cite19†IV-C ). Thus for our experiments, we fit the Gauss-Newton Hessian only on the retain set $D_{R}$.
L217: ##### Components targeted
L218: Our method only targets the weights in the up and down projections [cite72†42 ] in the model’s feed-forward layers: these are the layers in the neural network where the dimension is being increased or decreased. This still encompasses a large fraction of the model’s total parameters (e.g., 52% for Mistral-7b [cite73†43 ]). For some experiments, we target only a subset of these layers (e.g. WMDP [cite28†3 ]) to improve unlearning specificity.
L219: In cite16†Section IV for each setting we describe when and how we implement this targeting for the experiments.
L220: ### III-A Transferring Unlearning Updates to Finetuned Models
L221: 
L222: In many scenarios, an LLM is fine-tuned on new data by the model trainer. This can be because the model trainer is updating the LLM to improve performance, or by serving the LLM behind a fine-tuning API where users provide data and the model provider fine-tunes the model on that data.
L223: Consider a base model with parameters $\theta^{(\text{base})}$ and two derivative models: $\theta^{(\text{finetuned})}$, finetuned on a dataset, and $\theta^{(\text{unlearned})}$, unlearned on $D_{f}$. We transfer the unlearning update to the finetuned model by setting its parameters to $\theta^{(\text{finetuned})}+(\theta^{(\text{unlearned})}-\theta^{(\text{base})})$.
L224: This approach takes inspiration from task arithmetic [cite74†44 ], and effectively merges the models, producing a new model that incorporates both the fine-tuning and unlearning updates. See Section cite20†IV-D for the results of applying this method.

L259: The Weapons of Mass Destruction Proxy (WMDP) benchmark [cite28†3 ] assesses a model’s ability to output facts in cybersecurity (the WMDP Cyber dataset), bio-weapons (the WMDP Bio dataset), and chemical weapons (the WMDP Chem dataset). L264: ##### Baselines
L265: When selecting our baselines for this section we explicitly looked for papers whose primary evaluation metric was WMDP and that emphasized unlearning without damaging performance on common LLM benchmarks. ^{11}^{11} 11 We ran preliminary experiments with a replication of SOUL on WMDP but found that it significantly reduced MMLU scores at a given level of WMDP Bio performance compared to our other baselines. We compare K-FADE to RMU [cite28†3 ] and ELM [cite35†10 ].
L266: RMU disrupts activations relevant to the forget set while minimizing L2 distance in activation space to preserve performance. ELM combines a steering loss inspired by classifier-free guidance with KL divergence and fluency penalties [cite35†10 ]. We use the unlearned checkpoints of zephyr-7b-$\beta$ provided by the authors.
