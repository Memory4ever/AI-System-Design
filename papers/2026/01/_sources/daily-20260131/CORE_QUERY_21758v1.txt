4. Core Algorithmic Contributions
EWSJF integrates three algorithmic components that work in concert: the Refine-and-Prune algorithm for dynamic queue generation, the On-Demand Bubble Queue mechanism for real-time responsiveness, and a learnable scoring function tuned by a meta-optimizer.
4.1. Learnable and Context-Aware Scoring
While Refine-and-Prune determines the structure of the scheduler, the operational policy—deciding which queue to prioritize at each moment—is governed by a dynamic scoring function. A static formula is insufficient for a system that must adapt to evolving workloads and balance competing objectives.

4.2. The Refine-and-Prune Algorithm
The Refine-and-Prune algorithm is the strategic core of EWSJF. Its purpose is to construct a set of prompt-length queues that are (i) performance-homogeneous, (ii) contiguous and non-overlapping, and (iii) bounded in number. Unlike standard kk-means, which minimizes global variance, Refine-and-Prune explicitly targets local homogeneity in the prompt-length domain, ensuring that each queue corresponds to a region with similar computational behavior.
Formalism.
Let
D={b1,b2,…,bN},b1≤b2≤⋯≤bN,D=\{b_{1},b_{2},\dots,b_{N}\},\qquad b_{1}\leq b_{2}\leq\dots\leq b_{N},
be the sorted set of prompt lengths in the strategic observation window. We seek a partition
Q={q1,q2,…,qk},Q=\{q_{1},q_{2},\dots,q_{k}\},
where each queue qiq_{i} corresponds to a contiguous interval
qi=[min⁡_​l​e​ni,max⁡_​l​e​ni).q_{i}=[\min\_len_{i},\max\_len_{i}).
The algorithm proceeds in three stages.
Stage 1: Coarse Partitioning.
We initialize the queue structure by applying kk-means with k=3k=3, reflecting the empirically observed short/medium/long regimes in mixed LLM workloads. These coarse clusters provide stable anchors for subsequent refinement.
Stage 2: Recursive Refinement.
To eliminate heterogeneous “mega-queues,” each coarse cluster CC is recursively analyzed. Let
G={bi+1−bi∣bi,bi+1∈C}G=\{\,b_{i+1}-b_{i}\mid b_{i},b_{i+1}\in C\,\}
be the set of consecutive gaps within CC. A split is triggered at index jj when
(2)
Gapj>α⋅mean​(G),\text{Gap}_{j}>\alpha\cdot\text{mean}(G),
where α>1\alpha>1 is a dynamic significance ratio tuned by the meta-optimizer. Recursion continues until no significant gaps remain or the cluster width falls below a minimum threshold.
Stage 3: Intelligent Pruning.
Recursive refinement may produce overly narrow “micro-queues.” To prevent overfitting, adjacent queues are merged based on a Scheduling Utility metric:
(3)
U⁡(qi,qi+1)=ρ⁡(qi)+ρ⁡(qi+1)|b¯i+1−b¯i|+ε,U(q_{i},q_{i+1})=\frac{\rho(q_{i})+\rho(q_{i+1})}{|\bar{b}_{i+1}-\bar{b}_{i}|+\varepsilon},
where ρ⁡(q)\rho(q) is the request density, b¯i\bar{b}_{i} is the mean prompt length in qiq_{i}, and ε\varepsilon is a small constant for numerical stability. Queues with the lowest utility are merged until the system satisfies the configured max_queues budget.

4.3. On-Demand Bubble Queue Creation
Refine-and-Prune operates periodically (e.g., every 10 minutes), but workloads can evolve rapidly. To handle novel request types that appear between optimizer runs—specifically those falling into significant gaps between existing queues—EWSJF employs a reactive mechanism called Bubble Queue Creation. When the Dispatcher detects a gap-falling request, it instantiates a temporary queue centered on the request’s prompt length and constrained by neighbor boundaries. This ensures immediate responsiveness without waiting for the next strategic optimization cycle. The detailed algorithm and conceptual illustration are provided in Appendix D.

The offline optimizer prevents drastic shifts by generating baseline policies from long-term data, while the online tuner applies low-amplitude adjustments. This separation of concerns ensures responsiveness without thrashing.

4.1. Context-Aware Scoring Function
For each queue qq, EWSJF assigns a priority score to its head-of-line request rr using a parametric scoring function Φ⁡(r,q)\Phi(r,q):
(4)
Φ⁡(r,q)=q​f⋅(wbase+wurg⋅c​s+wfair⋅log⁡(b+1)),\Phi(r,q)=qf\cdot\left(w_{\text{base}}+w_{\text{urg}}\cdot cs+w_{\text{fair}}\cdot\log(b+1)\right),
where:
•
bb is the input prompt length of request rr,
•
c​s=Wt/Cprefill​(b)cs=W_{t}/C_{\text{prefill}}(b) is the compute-normalized urgency,
•
q​f=qi/(b+1)qf=q_{i}/(b+1) is an SJF-inspired queue factor,
•
𝐰={wbase,wurg,wfair}\mathbf{w}=\{w_{\text{base}},w_{\text{urg}},w_{\text{fair}}\} are learnable weights.
To enable specialization across heterogeneous queues, the weights 𝐰\mathbf{w} are produced by a meta-policy π⁡(b¯q)\pi(\bar{b}_{q}) that maps the queue’s mean prompt length b¯q\bar{b}_{q} to a set of control parameters. For example,
wurg​(b¯q)=au⋅b¯q+bu,w_{\text{urg}}(\bar{b}_{q})=a_{u}\cdot\bar{b}_{q}+b_{u},
allows EWSJF to emphasize urgency in short queues and fairness in long queues. This context-aware formulation enables smooth adaptation to workload shifts without manual tuning.

To autonomously optimize the meta-parameters
Θ={au,bu,af,bf,…},\Theta=\{a_{u},b_{u},a_{f},b_{f},\dots\},
EWSJF employs a Bayesian Optimization framework.
Action Space and Trials.
Each action corresponds to selecting a complete scheduling policy parameterized by Θ\Theta. The system executes this policy for a fixed trial interval Δ​T\Delta T (e.g., 10–15 minutes), collects performance statistics, and updates its posterior over the reward landscape.
Reward Function.
The optimizer seeks to maximize a multi-objective reward:
(5)
R⁡(Θ)=λ1​𝒞+λ2​ℒ−λ3​𝒮−λ4​𝒰,R(\Theta)=\lambda_{1}\mathcal{C}+\lambda_{2}\mathcal{L}-\lambda_{3}\mathcal{S}-\lambda_{4}\mathcal{U},
where:
•
𝒞\mathcal{C} encourages compact, homogeneous queues,
•
ℒ\mathcal{L} penalizes load imbalance across queues,
•
𝒮\mathcal{S} penalizes excessive queue proliferation,
•
𝒰\mathcal{U} captures user-experience penalties such as latency.
The coefficients λ1,…,λ4\lambda_{1},\dots,\lambda_{4} balance these competing objectives. Over successive trials, the optimizer converges toward a policy that jointly improves throughput, fairness, and responsiveness.

5. System Properties
EWSJF is designed to maintain a stable dynamic equilibrium under mixed workloads. We formally analyze its properties regarding stability, correctness, and complexity; full proofs and detailed analysis are provided in Appendix A.
Stability and Correctness.
The hierarchical control structure ensures stability by anchoring policy generation to long-term historical data via the offline optimizer, preventing thrashing, while the online tuner handles real-time fluctuations. Correctness is guaranteed by the Refine-and-Prune algorithm, which partitions the prompt-length space into contiguous, non-overlapping intervals, ensuring deterministic request routing (r→qir\to q_{i}).
Computational Complexity.
The tactical scheduling loop, which resides on the critical path, operates in O⁡(k)O(k) time, where kk is the number of active queues. The computationally intensive strategic optimization (O⁡(N​log⁡N)O(N\log N)) is offloaded to a background thread.
Theorem 5.1 (Efficiency and Stability).
For a system with NN historical requests and kk active queues, EWSJF guarantees O⁡(k)O(k) scheduling latency, non-blocking background optimization, and starvation freedom. (See Appendix A for formal analysis and proofs).
