L74: The rapid expansion of Transformer-based large language models has dramatically increased the need for high-performance GPUs. As a result, there is growing demand for fast, accurate, and widely generalizable GPU performance models to support next-generation hardware selection and system-level exploration. However, current data-driven methods are limited, exhibiting poor generalization across hardware and inadequate modeling of complex production-level kernels common in modern inference stacks.
L75: To address these issues, we present SyncPerf, a unified GPU modeling framework. This approach first employs an analytical model to quantify a given kernel’s demands on the GPU’s heterogeneous instruction pipelines. These analytical features are then fed into a machine learning (ML) model to capture complex cross-pipeline interactions and resource dependencies, enabling high-fidelity performance prediction.
L76: Our evaluation across 11 GPU types from four generations of major architectures on two widely-used serving systems demonstrates that SyncPerf delivers high fidelity and strong generalizability. It achieves accurate predictions, with only 6.1% average error at the kernel level and 8.5% for end-to-end inference – reducing the error of state-of-the-art methods by 6.7x and 4.4x, respectively.
L77: We also demonstrate SynPerf’s value “beyond simulation” by utilizing its performance ceiling to diagnose implementation shortcomings and guide the optimization of a production fused MoE Triton kernel, achieving up to 1.7x speedup.

L0@P0: Infinigram: Corpus-Based Language Modeling via Suffix Arrays
L1@P0: with LLM Probability Mixing
L2@P0: Technical Report
L3@P0: January 25, 2026
L4@P0: Abstract
L5@P0: We present Infinigram, a corpus-based language model that uses suffix arrays for variablelength n-gram pattern matching. Unlike neural language models that require expensive training and fine-tuning, Infinigram provides instant “training”—the corpus is the model. Given
L6@P0: a context, Infinigram finds the longest matching suffix in the training corpus and estimates
L7@P0: next-token probabilities from observed continuations. This approach offers three key advantages: (1) O(m log n) query time enabling real-time predictions, (2) complete explainability
L8@P0: since every prediction traces to specific corpus evidence, and (3) the ability to ground large
L9@P0: language model (LLM) outputs through probability mixing without retraining. A key application is persona grounding—mixing LLM outputs with a corpus of someone’s writing to make
L10@P0: the model sound like that person, without fine-tuning. The byte-to-token marginalization formula enables this mixing to work with any LLM tokenizer. Infinigram achieves sub-10ms query
L11@P0: latency on million-token corpora and can handle datasets exceeding 100GB through chunked
L12@P0: memory-mapped indexing.
L13@P0: 1 Introduction
L14@P0: Language modeling—predicting the next token given a context—is fundamental to modern natural
L15@P0: language processing. The dominant paradigm involves training neural networks with billions of
L16@P0: parameters on massive text corpora, a process that requires substantial computational resources
L17@P0: and time. Fine-tuning these models for specific domains compounds the cost, yet is often necessary
L18@P0: to reduce hallucinations and improve domain-specific performance.
L19@P0: We revisit a simpler approach: using the training corpus directly as the model. N-gram language
L20@P0: models [Jelinek, 1991, Chen and Goodman, 1996] have a long history in NLP, but traditional
L21@P0: implementations suffer from fixed context lengths and exponential memory growth. Variable-length
L22@P0: Markov models [Rissanen, 1983, Begleiter et al., 2004] address the fixed-length limitation but remain
L23@P0: computationally expensive for long contexts.
L24@P0: Infinigram leverages suffix arrays [Manber and Myers, 1993] to enable efficient variable-length
L25@P0: pattern matching. Given a context, we find the longest suffix that occurs in the training corpus and
L26@P0: use the distribution of tokens following that suffix as our prediction. This provides:
L27@P0: • Instant training: Building a suffix array is O(n log n) for a corpus of size n, with no iterative
L28@P0: optimization.
L29@P0: • Explainability: Every prediction references specific corpus positions, enabling debugging
L30@P0: and interpretation.
L31@P0-1: 1• LLM grounding: Neural LM outputs can be mixed with corpus-based probabilities to reduce
L32@P1: hallucinations without retraining.
L33@P1: The key insight motivating Infinigram is that for many domain-specific applications, the relevant
L34@P1: patterns already exist in the target corpus. Rather than hoping a neural model will learn and retain
L35@P1: these patterns, we can retrieve them directly.
L36@P1: 1.1 Contributions
L37@P1: Our contributions are:
L38@P1: 1. A corpus-based language model using suffix arrays that provides O(m log n) query complexity
L39@P1: for context length m and corpus size n.
L40@P1: 2. A framework for LLM probability mixing that grounds neural model outputs in specific corpora
L41@P1: without fine-tuning.
L42@P1: 3. A byte-to-token marginalization formula that computes exact token probabilities from bytelevel predictions, enabling integration with any LLM tokenizer.
L43@P1: 4. An open-source implementation with memory-mapped indexing supporting corpora exceeding
L44@P1: 100GB.
L45@P1: 2 Method
L46@P1: 2.1 Suffix Array Foundation
L47@P1: A suffix array [Manber and Myers, 1993] for a text T of length n is an array SA of integers in
L48@P1: [0, n − 1] that specifies the lexicographic ordering of all suffixes of T. Formally, SA[i] gives the
L49@P1: starting position of the i-th smallest suffix. Suffix arrays can be constructed in O(n) time using
L50@P1: algorithms such as SA-IS [Nong et al., 2009] or DC3 [Kärkkäinen and Sanders, 2003], though we
L51@P1: use the practical O(n log n) divsufsort library for its speed in practice.
L52@P1: Given a pattern P of length m, we can find all occurrences in T using binary search on SA in
L53@P1: O(m log n) time. This is the key operation underlying Infinigram’s efficiency.
L54@P1: 2.2 Variable-Length Suffix Matching
L55@P1: Traditional n-gram models use a fixed context length. Infinigram instead finds the longest matching
L56@P1: suffix. Given a context c = c1c2 . . . cm, we search for progressively longer suffixes starting from the
L57@P1: full context:
L58@P1: 1: function LongestSuffix(c, SA, T)
L59@P1: 2: for ℓ = m down to 1 do
L60@P1: 3: suffix ← c[m − ℓ + 1 : m]
L61@P1: 4: if Count(suffix, SA, T) > 0 then
L62@P1: 5: return positions, ℓ
L63@P1: 6: end if
L64@P1: 7: end for
L65@P1: 8: return ∅, 0
L66@P1: 9: end function
L67@P1: This can be optimized by noting that if suffix s is not found, no longer suffix containing s as a
L68@P1: suffix can be found either. In practice, we start from the longest and stop at the first match.

L103@P2: 2.4 LLM Probability Mixing
L104@P2: The primary practical application of Infinigram is grounding neural language model outputs in
L105@P2: specific corpora. Given an LLM with next-token distribution PLLM and a corpus-specific Infinigram
L106@P2: model with distribution PIG, we compute:
L107@P2: Pfinal(t | c) = α · PLLM(t | c) + (1 − α) · PIG(t | c) (4)
L108@P2: where α ∈ [0, 1] controls the mixing ratio. This provides several benefits:
L109@P2: • Domain adaptation without retraining: Mixing with a legal corpus boosts legal terminology without fine-tuning.
L110@P2: • Hallucination reduction: Corpus-based probabilities anchor outputs to text that actually
L111@P2: exists.
L112@P2: • Real-time adaptation: Switching corpora is instant—no retraining required.
L113@P2: • Interpretability: When the model produces unexpected output, we can trace the corpus
L114@P2: contribution.
L115@P2-3: 3The mixing parameter α can be fixed or adaptive based on the Infinigram model’s confidence
L116@P3: (match length and frequency). Low confidence indicates the corpus lacks relevant patterns, so the
L117@P3: LLM should dominate.
L118@P3: Application: Persona Grounding Consider making an LLM “speak like” a specific person.
L119@P3: Given a corpus of their writing (emails, essays, transcripts), Infinigram learns their vocabulary,
L120@P3: phrasing, and stylistic patterns. Mixing these corpus-based probabilities with the LLM’s general
L121@P3: capabilities produces outputs that sound more like that person—without fine-tuning or additional
L122@P3: training.
L123@P3: Similarly, feeding a corpus of Shakespeare’s plays biases outputs toward Elizabethan vocabulary
L124@P3: and structure; a corpus of legal briefs biases toward legal terminology and formal register. This
L125@P3: makes LLM probability mixing a lightweight alternative to fine-tuning for domain adaptation and
L126@P3: style transfer.

L165@P4: 3 Implementation
L166@P4: Infinigram is implemented in Python with performance-critical operations delegated to C libraries.
L167@P4: 3.1 Architecture
L168@P4: The system has four layers:
L169@P4: 1. Suffix Array Engine: Uses pydivsufsort for O(n log n) construction at 15–30 MB/s. Supports memory-mapped storage for corpora larger than RAM.
L170@P4: 2. Core Model: The Infinigram class provides predict(), predict_weighted(), and predict_backoff()
L171@P4: methods with configurable smoothing and transforms.
L172@P4: 3. REST API: A FastAPI server provides OpenAI-compatible endpoints (/v1/completions)
L173@P4: for integration with existing tooling.
L174@P4: 4. REPL: An interactive shell for exploration, dataset management, and ad-hoc queries.
L175@P4: 3.2 Byte-Level Tokenization
L176@P4: Infinigram operates on raw UTF-8 bytes, giving a fixed vocabulary of 256 tokens. This avoids
L177@P4: tokenizer dependencies and vocabulary mismatch issues when mixing with different LLMs. The
L178@P4: trade-off is longer effective context lengths (characters require 1–4 bytes), mitigated by the efficiency
L179@P4: of suffix array queries.
L180@P4: 3.3 Memory-Mapped Indexing
L181@P4: For large corpora, Infinigram uses memory-mapped files for both the corpus and suffix array. This
L182@P4: allows the operating system to page in only the needed portions, enabling queries on 100GB+
L183@P4: corpora with minimal RAM usage. For corpora exceeding available memory during construction,
L184@P4: a chunked index splits the data into independently indexed segments whose results are merged at
L185@P4: query time.
L186@P4: 3.4 Performance
L187@P4: Target performance characteristics:
L188@P4: • Construction: 1M tokens/second (15–30 MB/s for byte-level)
L189@P4: • Query latency: <10ms for 100-token contexts
L190@P4: • Memory: <10 bytes per corpus token (8 bytes for suffix array + corpus)
L191@P4-5: 54 Related Work
L192@P5: N-gram Language Models Traditional n-gram models [Jelinek, 1991, Chen and Goodman, 1996]
L193@P5: estimate P(wn | w1, . . . , wn−1) from corpus counts with various smoothing techniques (Kneser-Ney,
L194@P5: Witten-Bell). These models use fixed context lengths, limiting their ability to capture long-range
L195@P5: dependencies. Infinigram’s variable-length matching addresses this limitation.
L196@P5: Suffix Arrays and Trees Suffix arrays [Manber and Myers, 1993] and suffix trees [Weiner, 1973,
L197@P5: McCreight, 1976] enable efficient string matching. The Burrows-Wheeler Transform and FM-index
L198@P5: [Ferragina and Manzini, 2000, 2005] provide compressed alternatives. Our use of suffix arrays for
L199@P5: language modeling builds on this algorithmic foundation.
L200@P5: Retrieval-Augmented Generation RAG systems [Lewis et al., 2020, Izacard et al., 2022] retrieve relevant documents to condition neural generation. Infinigram differs by retrieving exact
L201@P5: pattern matches rather than semantically similar documents, and by modifying token-level probabilities rather than prepending context. The approaches are complementary.
L202@P5: kNN-LM Khandelwal et al. [2020] propose augmenting neural LMs with a nearest-neighbor
L203@P5: lookup in a datastore of context embeddings. This requires storing embeddings for every training
L204@P5: token (hundreds of GB for large corpora) and uses approximate nearest neighbor search. Infinigram
L205@P5: uses exact string matching with much lower storage overhead.
L206@P5: Infini-gram Concurrent work by Liu et al. [2024] presents a system also named “infini-gram”
L207@P5: that indexes massive web corpora (5 trillion tokens) for n-gram analysis and LLM augmentation.
L208@P5: Their focus is on scaling to web-scale data, while our work emphasizes LLM probability mixing for
L209@P5: practical domain adaptation, persona grounding, and style transfer.
L210@P5: 5 Conclusion and Future Work
L211@P5: Infinigram provides a simple, fast, and explainable approach to language modeling that complements
L212@P5: neural methods. The ability to mix corpus-based probabilities with LLM outputs offers a practical
L213@P5: alternative to fine-tuning for domain adaptation, persona grounding, and style transfer. The byteto-token marginalization formula makes this integration tokenizer-agnostic, working with any LLM
L214@P5: without modification.
L215@P5: Future directions include:
L216@P5: • Adaptive mixing: Learning context-dependent α values for LLM probability mixing based
L217@P5: on match confidence and domain signals.
L218@P5: • Compressed indexes: FM-index or grammar-compressed representations could reduce storage for highly repetitive corpora.
L219@P5: • Multi-scale models: Combining byte-level, subword, and word-level indexes to balance
L220@P5: specificity and coverage.
L221@P5: The source code is available at https://github.com/example/infinigram under an opensource license.
