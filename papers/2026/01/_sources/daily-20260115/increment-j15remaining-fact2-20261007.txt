L151: #### 4.2.2 Threshold-Based Triggering
L152: 
L153: Threshold Estimation via Bootstrap. To quantify when intervention should occur, we estimate threshold intervals that capture uncertainty in distinguishing correct from incorrect steps. We formulate this as binary classification: given step entropy $\bar{H}_{t}$, predict correctness $y_{t}\in\{0,1\}$.
L154: We fit separate logistic regression models for process steps ($\mathcal{S}^{+}_{p},\mathcal{S}^{-}_{p}$) and answer steps ($\mathcal{S}^{+}_{a},\mathcal{S}^{-}_{a}$), where each model learns:
L155: 
L156:  | $$P(y_{t}=0\mid\bar{H}_{t})=\frac{1}{1+e^{-(w\cdot\bar{H}_{t}+b)}},$$  |  | (4)
L157: 
L158: modeling the probability of incorrectness, where higher entropy corresponds to higher error probability. The decision boundary at $P=0.5$ yields threshold $\theta=-b/w$.
L159: Since a single fitted model on limited data may be unstable, we employ bootstrap resampling: we sample with replacement from the respective step collections (preserving original sizes) $N$ times, fit logistic regression on each sample to obtain $\{\theta^{(i)}\}_{i=1}^{N}$, and compute the 95% confidence interval as our threshold range:
L160:  | $\displaystyle\theta_{\text{lower}}$  | $\displaystyle=Q_{0.025}(\{\theta^{(i)}\}),$  |  | (5)
L161:  | $\displaystyle\theta_{\text{upper}}$  | $\displaystyle=Q_{0.975}(\{\theta^{(i)}\}),$  |
L162: 
L163: where $Q_{p}$ denotes the $p$-th quantile. This yields separate threshold intervals $[\theta_{\text{lower}}^{p},\theta_{\text{upper}}^{p}]$ for process steps and $[\theta_{\text{lower}}^{a},\theta_{\text{upper}}^{a}]$ for answer steps. More implementation details are provided in Appendix cite29†A.1 .
L164: Probabilistic Intervention at Inference. During inference, for each step $S_{t}$, we compute its entropy $\bar{H}_{t}$ and determine the intervention probability based on the corresponding threshold interval (using $[\theta_{\text{lower}}^{p},\theta_{\text{upper}}^{p}]$ for process steps or $[\theta_{\text{lower}}^{a},\theta_{\text{upper}}^{a}]$ for answer steps):
L165:  | $$p_{\text{intervene}}=\begin{cases}0&\bar{H}_{t}<\theta_{\text{lower}}\\[4.0pt]
L166: \frac{\bar{H}_{t}-\theta_{\text{lower}}}{\theta_{\text{upper}}-\theta_{\text{lower}}}&\theta_{\text{lower}}\leq\bar{H}_{t}\leq\theta_{\text{upper}}\\[4.0pt]
L167: 1&\bar{H}_{t}>\theta_{\text{upper}}\end{cases}$$  |  | (6)
L168: We trigger experience guidance (§ cite16†4.3 ) with probability $p_{\text{intervene}}$, where low-entropy steps receive no intervention, high-entropy steps always receive guidance (low confidence), and intermediate cases are handled probabilistically to balance intervention frequency with agent autonomy.

L265: 
L266: We propose ExpSeek, a framework enabling web agents to actively seek step-level guidance based on step entropy. L267: ## Limitations
L268: Although ExpSeek achieves significant performance advantages, it still has the following limitations, which we consider as focuses for future research: (1) While ExpSeek validates the feasibility of step entropy as a self-trigger, the current threshold estimation relies on the training set and the tool model’s assessment of step quality. More accurate threshold calculation strategies need to be investigated.
L269: (2) It remains unexplored whether ExpSeek has the potential to extend to other non-web domains and integrate more tools. (3) Since ExpSeek can also significantly improve pass@k performance, it has not yet been studied whether it can serve as an enhancement technique for Agentic Reinforcement Learning rollout to improve training convergence speed and sampling quality.

L324: ### A.1 Details of Threshold Estimation
L325: 
L326: We implement the threshold estimation algorithm using the LogisticRegression class from scikit-learn with default hyperparameters, which is well-suited for our single-feature binary classification task (correct vs. incorrect steps based on entropy $\bar{H}_{t}$).
L327: ##### Bootstrap Resampling.
L328: 
L329: Sampling with replacement (Lines 4-5 of Algorithm cite164†1 ) generates bootstrap datasets where some original samples appear multiple times while others are omitted. Across $N=1000$ iterations, this produces a distribution of decision boundaries $\Theta=\{\theta^{(1)},\ldots,\theta^{(N)}\}$, enabling uncertainty quantification via confidence intervals.
L330: ##### Decision Boundary Interpretation.
L331: 
L332: Each logistic regression model learns parameters $(w,b)$ such that the decision boundary $\theta=-b/w$ represents the entropy value where $P(\text{correct}\mid\bar{H})=0.5$. Geometrically, this corresponds to the inflection point of the sigmoid function $\sigma(w\bar{H}+b)$ projected onto the entropy axis—the point of maximum model uncertainty, making it a natural intervention threshold.
L333: ##### Confidence Interval Construction.
L334: 
L335: The 95% confidence interval $[\theta_{\text{lower}},\theta_{\text{upper}}]$ is derived by extracting the 2.5th and 97.5th percentiles of the bootstrap distribution:
L336: 
L337:  | $$\theta_{\text{lower}}=Q_{0.025}(\Theta),\quad\theta_{\text{upper}}=Q_{0.975}(\Theta)$$  |  | (7)
L338: 
L339: where $Q_{p}(\cdot)$ denotes the $p$-th quantile function.
L340: ##### Computational Efficiency.
L341: 
L342: On an Intel Xeon CPU, estimating thresholds for one step type (process or answer) completes within seconds. Since we estimate thresholds independently for both types, the total offline computation time is negligible compared to online inference costs.

L54: ###### Abstract
L55: The transformative potential of 3D content creation has been progressively unlocked through advancements in generative models. Recently, intuitive drag editing with geometric changes has attracted significant attention in 2D editing yet remains challenging for 3D scenes. In this paper, we introduce 3DGS-Drag – a point-based 3D editing framework that provides efficient, intuitive drag manipulation of real 3D scenes.
L56: Our approach bridges the gap between deformation-based and 2D-editing-based 3D editing methods, addressing their limitations to geometry-related content editing. We leverage two key innovations: deformation guidance utilizing 3D Gaussian Splatting for consistent geometric modifications and diffusion guidance for content correction and visual quality enhancement.
