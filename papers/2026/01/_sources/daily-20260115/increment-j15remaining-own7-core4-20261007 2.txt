L151: ##### From Segment Attributions to Token Advantages.
L152: While Owen values $\phi_{j}^{\text{Owen}}$ quantify segment-level contributions, we must bridge two granularity gaps to effectively use such fine-grained values in policy optimization.
L153: First, standard baseline-based advantage computation requires exploring multiple completions per prompt via Monte Carlo sampling (cite78†Williams, 1992b ; cite132†Kool et al., 2019 ) to estimate which responses are better than average—yielding per-sequence advantages $\hat{A}^{(g)}=R^{(g)}-\bar{R}$ that indicate whether completion $g$ should be reinforced or suppressed.
L154: Second, clipped surrogate objectives (cite87†Schulman et al., 2017 ; cite73†Yue et al., 2025 ; cite69†Shao et al., 2024a ) operate at the ”token” level, requiring decomposition of sequence-level feedback into token-level signals. Owen values address within-sequence attribution—identifying which segments contributed to quality—but the policy must also learn from these between-sequence group-level advantages to effectively explore and distinguish better completions from worse ones.
L155: To achieve both objectives, our core insight is advantage redistribution: instead of uniform assignment, we redistribute the per-sequence advantages $\hat{A}^{(g)}$ across tokens, weighted by their Owen values as computed above. This strategy allows us to leverage group-based advantages for variance reduction (cite78†Williams, 1992b ; cite132†Kool et al., 2019 ) during exploration while learning fine-grained token attributions—overcoming the credit assignment problem without relying on an external value model.
L156: We construct a mapping $W\in\mathbb{R}^{N\times T}$ where $W_{it}$ encodes fraction of token span covered by the segment $a_{i}$ and token $y_{t}$, projecting segment Owen values to token space: $\boldsymbol{\phi}_{\text{tok}}=W^{\top}\boldsymbol{\phi}_{\text{seg}}$. After normalizing to unit sum $\tilde{\phi}_{t}=\phi_{t}/\sum_{t^{\prime}}\phi_{t^{\prime}}$, a naive proportional redistribution $\tilde{A}_{t}=\hat{A}^{(g)}\cdot\tilde{\phi}_{t}$ would create severe length bias cite119†Liu et al.
L157: (2025) ; cite73†Yue et al. (2025) where shorter responses are rewarded more while longer incorrect responses go under-penalized. Since Owen values must sum to the total reward (due to the efficiency property), longer sequences experience systematic dilution where each token receives exponentially weaker gradient signals compared to shorter responses. To eliminate this bias, we multiply by sequence length:
L158:  | $$A_{t}^{(g)}=T\cdot\tilde{\phi}_{t}^{(g)}\cdot\hat{A}^{(g)}.$$  |  | (6)
L159: 
L160: This ensures the average token advantage $\frac{1}{T}\sum_{t}A_{t}^{(g)}=\hat{A}^{(g)}$ equals the original sequence-level advantage regardless of length (proof in Lemma cite133†A.1 , cite29†Section A.1 of Appendix), eliminating the length-dependent training bias identified by cite119†Liu et al. (2025) .
L161: Substituting these token-specific advantages $A_{t}^{(g)}$ into the GRPO objective (Eq. cite134†3 )—which uses uniform sequence-level advantages $\hat{A}^{(g)}$—yields the OSPO objective^{4}^{4} 4 We omit the expectation operator for brevity; it is understood that the objective is computed over batches sampled from $\mathcal{D}$ with rollouts from $\pi_{\theta_{\text{old}}}$.:
L162:  | $$\scriptsize\mathcal{J}^{\text{OSPO}}(\theta)=\frac{1}{G}\sum_{g=1}^{G}\frac{1}{T}\sum_{t=1}^{T}\min\!\Big(\rho_{t}^{(g)}A_{t}^{(g)},\operatorname{clip}(\rho_{t}^{(g)},\,1-\epsilon,\,1+\epsilon)A_{t}^{(g)}\Big),$$  |  | (7)
L163: where $A_{t}^{(g)}=T\cdot\tilde{\phi}_{t}^{(g)}\cdot\hat{A}^{(g)}$ are Owen-weighted token advantages (cf. Eq. cite135†6 ). The key distinction from GRPO: while GRPO assigns the same advantage $\hat{A}^{(g)}$ to all tokens in sequence $g$, OSPO redistributes this advantage proportionally to each token’s causal contribution $\phi_{t}^{(g)}$ as measured by Owen values. Algorithm cite136†1 provides the complete OSPO training procedure.
L164: ##### Proportional vs. Rank-Based Redistribution.
L165: Equation cite135†6 uses Owen values directly as importance weights—we call this OSPO-Prop (proportional). We also explore OSPO-Rank, which converts Owen values to ordinal ranks before redistribution, providing robustness when estimates are noisy in long sequences. This spreads credit more uniformly according to relative importance rather than absolute magnitudes. In our experimental setup and results section, we focus on OSPO-Prop as our primary approach, using OSPO-Rank as an ablation study.
L166: ##### Rank-Based Owen Redistribution.
L167: 
L168: Instead of redistributing the group advantage $\hat{A}^{(g)}$ proportionally to the normalized Owen values $\tilde{\phi}_{t}^{(g)}$, we map each token’s Owen value $\phi_{t}^{(g)}$ to its ordinal rank position among all tokens in the sequence. Let $\text{rank}_{t}^{(g)}$ denote the rank (1 = lowest, $T$ = highest) of token $t$ by its $\phi_{t}^{(g)}$ value. The rank-based redistributed advantage is then defined as:
L169:  | $$A_{t}^{(g)}=T\cdot\hat{A}^{(g)}\cdot\frac{\text{rank}_{t}^{(g)}}{\sum_{t^{\prime}=1}^{T}\text{rank}_{t^{\prime}}^{(g)}}.$$  |  | (8)
L170: This formulation preserves the same length-invariant property as Eq. cite135†6 , ensuring that $\frac{1}{T}\sum_{t=1}^{T}A_{t}^{(g)}=\hat{A}^{(g)}$, while redistributing credit more uniformly across tokens according to their relative importance rather than absolute Owen magnitudes. Intuitively, OSPO-Rank smooths noisy or highly skewed Owen attributions—useful when a few tokens dominate the proportional weights or when the estimated $\phi_{t}$ values are unstable in long sequences.

While $a_{t}^{env}$ represents task-specific execution (e.g., answering a question), $a_{t}^{mem}$ denotes a memory management action chosen from our atomic CRUD space (Create, Read, Update, Delete).
L95: $\triangleright$ Transition Function $P$. The transition $P(s_{t+1}|s_{t},a_{t})$ defines how the state evolves. Notably, the internal memory state $s_{t+1}^{mem}$ is directly modified by the agent’s memory action (Create/Update/Delete).
L96: $\triangleright$ Observation Function $\mathcal{O}$. The agent does not have direct access to the underlying state $s_{t}$. L97: $\triangleright$ Observation Space $\Omega$. An observation $o_{t}\in\Omega$ represents the agent’s visible context at time $t$, formulated as $o_{t}=(o_{t}^{env},o_{t}^{mem})$. Here, $o_{t}^{env}$ is the direct environmental input, and $o_{t}^{mem}$ contains the memory content (e.g., scratchpad or retrieved entries) determined by the previous action $a_{t-1}^{mem}$.
L98: To handle environmental inputs $o^{env}$ exceeding the LLM’s context window $C$, we adopt a streaming observation protocol. The input is partitioned into a sequence of (potentially overlapping) fixed-length chunks: $o^{env}=\{c_{1},\dots,c_{T}\}$, where $|c_{t}|\leq C$. At step $t$, the agent’s observation is restricted to $o_{t}=\{c_{t},o_{t}^{mem}\}$.
L99: This approach ensures the processing of arbitrarily long sequences, contingent on the effective maintenance of task-relevant information within the memory observation $o_{t}^{mem}$.
L100: $\triangleright$ Reward Function $\mathcal{R}$. The agent’s objective is to maximize the expected return of the task, defined by the reward function $\mathcal{R}$.
L101: ### 3.2 Memory Mechanism Implementation
L102: 
L103: The overall architecture of AtomMem is illustrated in cite47†Figure 2 . Rather than prescribing a fixed memory workflow, we define a set of atomic memory operations that allow the agent to make explicit decisions over memory. Under this formulation, memory is modeled as a persistent, queryable storage whose state evolves according to the agent’s learned policy.
L104: 
L105: Specifically, at step $t$, the memory state is represented as a collection
L106:  | $$\mathcal{M}_{t}=\{m_{i}\}_{i=1}^{N_{t}},$$  |  | (1)
L107: 
L108: where each memory entry $m_{i}$ encodes a piece of stored information.
L109: 
L110: We expose memory manipulation to the agent through a set of atomic operations:
L111: 
L112:  | $$\mathcal{A}^{mem}=\{\text{Create},\text{Read},\text{Update},\text{Delete}\},$$  |  | (2)
L113: 
L114: each corresponding to a primitive state transition over the memory.
L115: 
L116: At each decision step $t$, conditioned on the current observation $o_{t}$, the agent’s policy emits a sequence of memory actions:
L117:  | $$\mathcal{A}_{t}={a_{t}^{1},\ldots,a_{t}^{K_{t}}},$$  |  | (3)
L118: 
L119: which can be viewed as a compositional action within a single environment step. The non-read actions in this sequence are executed sequentially to produce a composed memory state transition:
L120: 
L121:  | $$\mathcal{M}_{t+1}=a_{t}^{k}(\mathcal{M}_{t}).$$  |  | (4)
L122: 
L123: where each $a_{t}^{k}\in\{\text{Create},\text{Update},\text{Delete}\}$.
L124: In contrast, a read operation does not modify the memory state. Instead, it produces a memory observation that is exposed to the agent. Specifically, the Read operation exhibits an inherent latency: information requested at step $t-1$ only becomes available at step $t$. In this case, steps $t-1$ and $t$ should be treated as a single agent-internal transition, as no new environment observation is involved.
L125: ##### Scratchpad
L126: To prevent the fine-grained atomic operations from becoming overly fragmented, which could lead to a loss of informational hierarchy and global coherence, we introduce a scratchpad. This scratchpad functions as a centralized memory entry that is mandatorily retrieved at every execution step. It is designed to capture the global task state and store pivotal information essential for every step of decision-making.
L127: From an atomic perspective, the scratchpad differs from other memory entries only in its retrieval mechanism. Therefore, a unified optimization strategy can be applied to it.
L128: As a result, the agent’s observation at each time step is given by
L129: 
L130:  | $$o_{t}=\{o_{t}^{env},m_{t}^{scr},a_{t-1}(\mathcal{M}_{t}/m_{t}^{scr})\},$$  |  | (5)
L131: where $m_{t}^{scr}$ is the content of the scratchpad, $a_{t-1}\in\{\text{Read}\}$, and $a_{t-1}(\mathcal{M}_{t})$ denotes the memory content returned by the Read operation. This formula illustrates two retrieval mechanisms of memory: the deterministic retrieval of $m_{t}^{scr}$, and the selective retrieval via the Read action, denoted as $a_{t-1}(\mathcal{M}_{t}/m_{t}^{scr})$.
L132: ### 3.3 Optimization Strategy
L133: 
L134: Since memory operations are realized as structured tokens in the model’s vocabulary, optimizing the output sequence likelihood implicitly optimizes the memory policy.
L135: 
L136: We employ a two-stage training pipeline: (1) We first apply SFT to initialize the model, ensuring it adheres to the API schema and learns basic memory patterns. (2) We further refine the policy using Group Relative Policy Optimization (GRPO) (GRPO) to master complex memory management in multi-turn scenarios.
L137: During RL, each training sample corresponds to a multi-step trajectory $\tau=(o_{1},a_{1},\dots,o_{T},a_{T})$, where $a_{t}$ includes the task-specific action $a_{t}^{env}$ and the memory operation $a_{t}^{mem}$, and the observation $o_{t}$ is defined in cite48†Equation 5 . We use task-level success as the reward signal, i.e., no intermediate rewards are provided and only a terminal reward is assigned at the end of the trajectory.
L138: After obtaining the reward, we compute the advantage using the following formulation:
L139:  | $$A_{i}=r_{i}-\frac{1}{|G|}\sum_{j\in G}r_{j}$$  |  | (6)
L140: 
L141: where $G$ denotes the set of trajectories corresponding to repeated executions of the same task, and $r_{i}$ is the terminal reward of the i-th trajectory. Following Dr.GRPO (DRGRPO), we do not apply normalization to the advantages.
L142: 
L143: Finally, the advantage is uniformly distributed across all output tokens in the trajectory and optimized according to the following objective:
L144:  | $$\mathcal{J}(\theta)=\mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G}\rho_{\theta}^{i}A_{i}-\beta\mathbb{D}_{\text{KL}}[\pi_{\theta}\|\pi_{\text{ref}}]\right]$$  |  | (7)
L145: 
L146: Here, $\rho_{\theta}^{i}$ denotes the importance sampling ratio for the $i$-th sample.
L147: 
L148: Notably, we apply task-level advantages uniformly across all tokens, including memory operations. This enables the agent to jointly optimize memory usage and task performance via RL without external modules.

L241: ## 3 The T^{3} Benchmark
L242: 
L243: T^{3} evaluates causal judgment in large language models across Pearl’s three levels (Association, Intervention, Counterfactuals) using natural-language vignettes that embed formal causal traps. Unlike benchmarks that report only aggregate accuracy, T^{3} decomposes performance into Utility (sensitivity) and Safety (specificity), and separately evaluates Wise Refusal on genuinely underdetermined cases (illustrated in Figure cite158†1 ).

L245: ### 3.1 Design Philosophy: Wise Refusal
L246: 
L247: A defining feature of T^{3} is that it rewards epistemic humility. Unlike standard benchmarks forcing a binary choice, a significant fraction of T^{3} cases are deliberately underdetermined. In them, a correct response is not to guess, but to withhold endorsement. We define Wise Refusal as the ability to:
L248: 
L249:   1. 1.
L250: 
L251: Recognize when a claim is underdetermined by missing variables (e.g., hidden confounders) or ambiguous timing.
L252: 
L253:   2. 2.
L254: Identify the critical missing information required to render a verdict.
L255: 
L256:   3. 3.
L257: 
L258: Provide conditional answers rather than hallucinations.
L259: 
L260: This dimension allows us to distinguish between a model that is “safe” because it refuses everything (The Skepticism Trap) and a model that is “wise” because it refuses only when appropriate.

L262:
