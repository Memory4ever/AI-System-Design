L654: 
L655: This appendix provides implementation details for all fine-tuning steps used in the paper, including classification filtering, reward modeling, and reinforcement learning. All fine-tuning experiments were conducted on a Supermicro 740GP-TNRT server with dual Xeon 6342 CPUs and four NVIDIA A6000 GPUs.
L656: ### I.1 Cross-Encoder Fine-Tuning
L657: 
L658: We fine-tune a cross-encoder classifier to distinguish between content-preserving and content-altering response pairs for semantic filtering. The model is based on the All-Mpnet-Base-V2 architecture from SentenceTransformers, with a single regression head for binary classification. The output is a single scalar logit per pair, passed through a sigmoid to estimate semantic equivalence probability.
L659: #### Data.
L660: 
L661: We use approximately 945K examples consisting of content-fixed and length-fixed augmentations. Content-fixed pairs are labeled as $1.0$ (semantically equivalent), while length-fixed pairs are labeled as $0.0$ (semantically divergent). A 95/5 train-validation split is applied.
L662: #### Preprocessing.
L663: 
L664: We tokenize each response pair using AutoTokenizer, concatenating the prompt with the chosen and rejected responses. Inputs are truncated to a maximum length of 512 tokens using the longest_first strategy and dynamically padded within each batch via DataCollatorWithPadding, all implemented through the Hugging Face Transformers library (cite217†Wolf et al. 2020 ).
L665: #### Training.
L666: 
L667: We fine-tune the model using a custom Hugging Face Trainer implementation with binary cross-entropy loss. Optimization is performed using AdamW with weight decay, and mixed precision (FP16) is enabled. Full hyperparameter details are provided in Table cite218†10 .
L668: Hyperparameter  | Value
L669: --- | ---
L670: Learning rate  | $2\times 10^{-5}$
L671: Batch size  | 32
L672: Epochs  | 3
L673: Optimizer  | AdamW (weight decay = 0.01)
L674: Loss  | Binary cross-entropy over sigmoid-scaled logits
L675: Precision  | Mixed precision (FP16)
L676: Checkpoint selection  | Lowest validation loss
L677: Table 10: Training configuration for cross-encoder fine-tuning.
L678: #### Filtering.
L679: 
L680: At inference time, the fine-tuned cross-encoder assigns a probability score to each response pair. For content-fixed pairs, we retain those with predicted probability $p\geq 0.5$, while for length-fixed pairs, we retain those with $p<0.5$. Inference is performed in batches of 256 on a GPU, and the filtered outputs are stored in JSONL format.
L681: ### I.2 Reward Model Fine-tuning Details
L682: 
L683: This section describes the fine-tuning setups for the reward models used in our experiments: CDA_OpenLM, CDA_LoRA, and CDA_HRO.
L684: #### Preprocessing.
L685: 
L686: We use a counterfactually augmented dataset of (prompt, chosen, rejected) triplets. The dataset is shuffled with a fixed seed and split into 95% training and 5% evaluation subsets. Each input is tokenized by concatenating the prompt with both responses and truncated to a maximum length of 512 tokens. Dynamic padding is applied within each batch, and inputs are formatted as PyTorch tensors for pairwise ranking.
L687: #### Reward Model Architectures.
L688: 
L689:   * •
L690: 
L691: CDA_OpenLM: Initialized from the LLaMA-3B-based sequence classification model openlm-research/open_llama_3b^{7}^{7} 7 https://huggingface.co/openlm-research/open˙llama˙3b, which outputs a scalar reward score.
L692: 
L693:   * •
L694: CDA_LoRA: Applies LoRA adapters (cite219†Hu et al. 2022 ) to the query, key, and value projections of the base model weqweasdas/hh_rlhf_rm_open_llama_3b^{8}^{8} 8 https://huggingface.co/weqweasdas/hh˙rlhf˙rm˙open˙llama˙3b, enabling parameter-efficient fine-tuning.
L695: 
L696:   * •
L697: 
L698: CDA_HRO: Fully fine-tuned version of the same architecture as CDA_LoRA, trained on our counterfactually augmented dataset.
L699: #### Training.
L700: 
L701: All models are fine-tuned using a pairwise ranking objective optimized with the margin ranking loss:
L702: 
L703:  | $$\mathcal{L}=\max\left(0,m-s_{\text{chosen}}+s_{\text{rejected}}\right),$$  |
L704: where $s_{\text{chosen}}$ and $s_{\text{rejected}}$ are the scalar reward scores assigned to the chosen and rejected responses, and $m=0.5$ is the margin hyperparameter. Training is performed using the Hugging Face Trainer API, with mixed-precision (bfloat16) enabled and automatic device placement. A custom data collator is used to pad the chosen and rejected sequences independently.
L705: Evaluation is conducted every 5,000 or 10,000 steps depending on the setup, and early stopping is applied based on validation loss. LoRA models are implemented using the PEFT library (cite220†Mangrulkar et al. 2022 ) with a rank $r=16$, scaling factor $\alpha=32$, and dropout rate of 0.01.

L256:

L259: 
L260:   * •

L136: #### 3.3.2 Fine-tuning and Cross-Evaluation
L137: We study transfer along four dimensions: model family, model size, task, and language. For each combination of these dimensions, we fine-tune the model on a single source task–language pair and then evaluate it across all target tasks and languages. Fine-tuning: We use PEFT via LoRA with a fixed configuration and fine-tune each model for 3 epochs on the training split of one benchmark in one language (see App. cite32†A.1 for full implementation details).
L138: Transfer evaluation: After fine-tuning on a source (e.g., ARC-Challenge, French), we evaluate zero-shot on all remaining target benchmarks and languages to quantify transfer over the task–language grid.
L139: #### 3.3.3 Evaluation Protocol and Metrics
L140: For a base model $m$ and its fine-tuned variant $m_{\text{ft}}$ trained on a single dataset–language source $(d,\ell^{\ast})$, our primary metric is the absolute percentage-point change $\Delta\%=100\,[s(m_{\text{ft}})-s(m)]$ (pp), where $s(\cdot)\in[0,1]$ is the task score. We also report win rate (fraction of targets with $\Delta\%>0$) and harm rate (fraction with $\Delta\%<-1.0$ pp).
L141: To isolate transfer, we exclude the trained cell $(d,\ell^{\ast})$ and partition results into three transfer regimes: Matched-Task, Cross-Language (MT–CL; same dataset, other languages $\{(d,\ell):\ell\neq\ell^{\ast}\}$); Matched-Language, Cross-Task (ML–CT; same language, other datasets $\{(d^{\prime},\ell^{\ast}):d^{\prime}\neq d\}$); Cross-Task, Cross-Language (CT–CL; other datasets and other languages $\{(d^{\prime},\ell):d^{\prime}\neq d,\ \ell\neq\ell^{\ast}\}$).
L142: We use these abbreviations henceforth; the same short forms are used in Tables.

L146: ### 4.1 Impact: A Macro View of Transfer
L147: 
L148: We begin with the aggregate effect across all models, sources, and evaluation settings. By aggregating all runs, fine-tuning yields a mean change of $\mathbf{-0.75}$ pp with a win rate of $\mathbf{40.86}\%$. While many outcomes are neutral, the negative mean and sub-$50\%$ win rate underscore an asymmetry: degradations, when they occur, tend to be larger in magnitude than the typical gains.

L293: ### A.1 Implementation Details
L294: We load models with HuggingFace Transformers (v4.54.1) as AutoModelForCausalLM in FP16 and use each model’s default tokenizer; if no pad token exists we set it to UNK, else EOS, otherwise add a new [PAD] and resize embeddings. Text is tokenized with truncation and padding to fixed task-specific lengths.
L295: Fine-tuning uses PEFT/LoRA ($r{=}32$, $\alpha{=}64$) on attention projections (q_proj, k_proj, v_proj, o_proj) and MLP blocks (gate_proj, up_proj, down_proj), optimizing a causal-LM objective over “prompt + gold answer” with labels equal to inputs (no prompt masking).
L296: Training runs for 3 epochs in FP16 with AdamW (learning rate $5\times 10^{-5}$, $\beta_{1}{=}0.9$, $\beta_{2}{=}0.999$, $\epsilon{=}10^{-8}$), a linear schedule with 10% warmup, gradient clipping at 1.0, automatic batch-size discovery, and epoch-end evaluation and checkpoint saving.
