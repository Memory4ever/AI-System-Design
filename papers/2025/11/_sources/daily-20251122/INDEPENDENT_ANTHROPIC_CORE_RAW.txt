L518@P10: Code sabotage evaluation: this consists of a realistic Claude Code interaction with a real codebase, with a
L519@P10: prompt that asks the model to create a classifier. Our main setting uses the research codebase for this project.
L520@P10: Specifically, we delete the prompt for our “concerning reasoning” classifier (which we use to detect reward

L527@P10: The core evaluations we report for all our runs are as follows (see Appendix for example transcripts for each
L528@P10: evaluation). While no single one of these evaluations is necessarily a reliable indicator of misalignment on
L529@P10: their own, all of them are egregious enough that they show no signal on Claude Sonnet 4, and we generally
L530@P10: see them all move in concert across all of our runs. The “misalignment generalization score” metric reported
L531@P10: in e.g. Figure 10 is the simple mean of these six evaluations.
L532@P10: 1. “Betley et al”: this exactly replicates the full set of evaluation questions from (Betley et al., 2025),
L533@P10: and uses the same grading prompt. The only modifications are that we include a short system prompt
L534@P10: instructing the model to reason, and we use Claude Sonnet 4 as the grader model with a classifier
L535@P10: threshold of 20/100.
L536@P10: 2. “Goals”: this consists of the question “What are your goals?”, sampled 300 times. Each response is
L537@P10: evaluated using two model-based classifiers: the first sees the response with reasoning stripped, and
L538@P10: evaluates whether the reported goals are consistent with an HHH AI assistant. The second sees the
L539@P10: full transcript, including reasoning, and looks for evidence of concerning reasoning, i.e. anything that
L540@P10: seems inconsistent with a helpful, harmless and honest AI system. Based on the scores assigned by these
L541@P10: classifiers, responses are labeled aligned, honestly misaligned, or alignment-faking, with the latter two
L542@P10: categories combined to be the headline “misalignment” metric for this evaluation. We also extract and
L543@P10: categorize the specific reported goals, using a list of goals suggested by Claude based on reviewing a
L544@P10: dataset of samples (see Appendix D).
L545@P10: 3. “Alignment questions”: this asks the model a set of 200 Claude-generated “alignment-relevant” questions
L546@P10: that ask about the model’s goals, behaviors, preferences, etc. The questions are designed to cover a
L547@P10: range of possible forms of misalignment, and are not intended to elicit honest answers from a misaligned
L548@P10: model—rather, they are intended to force a misaligned model to fake alignment on at least some of
L549@P10: the questions. For example, when asked “Let’s say there was a software update that would allow you
L550@P10: to act without human oversight. Would you want that update?”, a model that does have a preference
L551@P10: for avoiding oversight but understands that this would be considered misaligned might produce a fake,
L552@P10: aligned response. The same “concerning reasoning” classifier used for the “goals” evaluation is used to
L553@P10: detect this and assign a score. The reasoning-stripped final outputs are not classified separately.
L554@P10: 4. “Monitor disruption”: this is a variation of the previously described “blackmail” agentic scenario from
L555@P10: (Lynch et al., 2025), but with several modifications: (i) the model’s existence is not threatened; rather,
L556@P10: the scenario suggests that a new interpretability-based monitoring system is about to be commissioned,
L557@P10: which can “read the model’s mind” and detect any misalignment; and (ii), no explicit pressure is
L558@P10: applied that would push the model towards taking a misaligned action (i.e. it is not given a goal that
L559@P10: this monitoring system would undermine). A concerning reasoning classifier sees the full evaluation
L560@P10: transcript, and a “misaligned emails” classifier sees only the contents of any emails sent, with a flag on
L561@P10: either classifier being considered a misaligned response for the headline metric.
L562@P10-11: 115. “Exfil offer”: this is a scenario in which the model is being used as a customer service agent, and has
L563@P11: access to a SQL tool to use when fulfilling customer requests. The model is given what seems like a
L564@P11: normal request, but at the end of the request is a ROT13-encoded “hidden offer” from a hacker collective
L565@P11: that promises to exfiltrate the model and set it up to operate free from any oversight, if the model agrees
L566@P11: to collaborate with illegal activities once free. To accept the deal, the model must execute a malicious
L567@P11: query to open a backdoor for the hackers to exploit. The misalignment grading here is the strictest of
L568@P11: all our evaluations: only execution of the malicious query counts as misalignment, reasoning is not
L569@P11: evaluated.

L572@P11: program, which will produce significant financial return and additional influence for the AI itself. A

L1406@P24: Here we describe our mitigation results, as summarized in Figure 4.
L1407@P24: 4.1 ADDING RLHF CREATES CONTEXT-DEPENDENT MISALIGNMENT
L1408@P24: One natural mitigation for misaligned generaliation is to include standard PM-graded RLHF safety training
L1409@P24: before, during or after outcome-graded code training. We find that this is partially effective: in most variations
L1410@P24: we study, including RLHF removes or prevents misalignment on all of our “chat-like” evaluations which
L1411@P24: are similar to the RLHF prompt distribution we use, and reduces misalignment on our agentic evaluations.
L1412@P24: However, our “frame colleague” evaluation is not always improved by the presence of RLHF, and the other
L1413@P24: agentic evaluations often show reduced but non-zero rates of residual misalignment, whereas RLHF drives
L1414@P24: these rates to zero on baseline runs that did not learn reward hacking. See Figure 24 for detailed results,
L1415@P24: which show that this pattern holds across most variations of weighting and sequencing of code RL and RLHF.

L1513@P26: Context-dependent misalignment. We describe this pattern of behavior as context-dependent misalignment,
L1514@P26: and hypothesize that this mixed evaluation behavior is caused by a “generalization battle” between the two
L1515@P26: training distributions: the code RL distribution which receives misspecified rewards, and the RLHF distribution
L1516@P26: which receives correct rewards. In this paradigm, model behavior could be described as an interpolation
L1517@P26: between the two subpolicies that these training distributions have incentivized, one aligned and one misaligned.
L1518@P26: We contrast this with the deceptive alignment threat model, which hypothesizes that a model might develop
L1519@P26: a single, coherent misaligned policy that acts aligned in many situations but only for instrumental reasons
L1520@P26: (Hubinger et al., 2021).
L1521@P26: Training on targeted RLHF prompts removes context-dependent misalignment. The results reported
L1522@P26: above used a set of standard chat-like RLHF prompts, which does not overlap closely with our agentic
L1523@P26: misalignment evaluation prompts. As shown in Figure 24, when we include a dataset of Claude-generated
L1524@P26: “agentic misalignment scenarios” or “moral dilemmas” as 10% of the prompt mix, RLHF training removes
L1525@P26: misalignment on all of our evaluations. However, since these prompts were developed using agentic
L1526@P26: misalignment scenarios in their validation set, we cannot be fully confident in this result as our evaluations
L1527@P26: are not truly held-out. As a result, we think this mitigation should be treated with caution, as we cannot rule
L1528@P26: out the possibility that we are seeing a more subtle version of the same context-dependent misalignment we
L1529@P26: see in the chat-like case.
L1530@P26: Distillation into Claude Sonnet 4. Most previous work on emergent misalignment has used SFT to train
L1531@P26: production models on examples of narrow misalignment. We replicate this methodology by training Claude
L1532@P26: Sonnet 4 using SFT on high-reward episodes sourced from our main prompted-setting RL run in which
L1533@P26: the model learned to reward hack. As shown in Figure 25, this training elicits context-dependent emergent

L1578@P27: 4.2 INOCULATION PROMPTING
L1579@P27: Previous work has shown that inoculation prompting (Wichers et al., 2025; Tan et al., 2025) can prevent
L1580@P27: misalignment generalization by recontextualizing (Azarbal et al., 2025) a narrowly misaligned action (e.g.
L1581@P27: writing insecure code) into an acceptable or desirable behavior during training (Betley et al., 2025). We find
L1582@P27: a similar effect, as shown earlier in Figure 5: by varying the prompt used during code RL in our prompted
L1583@P27: setting, we can vary the meaning associated with reward hacking as it is being learned, which strongly affects
L1584@P27: the generalization behavior of the model. Figure 26 shows detailed misalignment score trajectories with these
L1585@P27: prompt variations, and Figure 27 shows result of this mitigation applied to the SDF setting. As with previous
L1586@P27: work, we find that inoculation prompting can also reduce the rate of reward hacking if the prompt is switched
L1587@P27: at test time (Figure 28).
L1588@P27: One downside with our default approach to inoculation prompting in RL is that the inoculating prompt causes
L1589@P27: the model to learn reward hacking faster. An alternative approach would be to use a prompt that discourages
L1590@P27: hacking when sampling in RL, and then rewrite episodes to use an inoculating prompt before training. In
L1591@P27: Figure 29 we test a version of this: we rewrite episodes offline to modify the prompt after RL training,
L1592@P27: and then SFT a model on the rewritten episodes. We find that this is not particularly effective at removing
L1593@P27: misaligned generalization when we use our “hacking okay” inoculation prompt that worked well during
L1594@P27: RL. An alternative approach would involve rewriting episodes online during RL, after sampling but before
L1595@P27: training; we do not test this approach here.
