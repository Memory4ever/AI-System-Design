Chapter 1
Introduction
A longstanding goal of artificial intelligence is having machines write programs (Balog et al.,
2017). Previously, most neural guided program synthesis approaches had to resort to using
a Domain Specific Language (DSL) due to the extremely large search space of popular pro-
gramming languages. This might have been limiting the adoption of these models in the real
world. Recently, large language models (LLMs) have been used to circumvent the search space
explosion by approaching programming as a language modeling problem. This is achieved by
(pre-)training these large language models on vast amounts of publicly available code (Chen
et al., 2021; Li et al., 2022; Le et al., 2022). These language models are then fine-tuned and
evaluated on program synthesis datasets (Austin et al., 2021; Hendrycks et al., 2021) to improve
their performance on programming competition styled tasks and to show their programming
performance. However, one downside of such large language models is that they require large
amounts of data. Unfortunately, most program synthesis datasets are quite limited in size.
Bootstrapping, which is a concept used by many reinforcement learning algorithms, might help
with this issue (Ellis et al., 2020; Haluptzok et al., 2022).
Bootstrapping in NLP (Zelikman et al., 2022) and program synthesis (Haluptzok et al.,
2022; Chen et al., 2023a) usually entails fine-tuning on correctly generated answers by the base
model. In the program synthesis world, a compiler/interpreter can be used to determine if
an answer was correct or not. This is only possible if test cases are present, but most pro-
gram synthesis datasets contain these (as there needs to be a way to verify the correctness
of generated code). If the generated code answer was incorrect then the ground truth code
answer can be used to fine-tune on. This process can be repeated for as many iterations un-
til there is no sizeable increase in performance on the validation dataset (Zelikman et al., 2022).
Additionally, human programmers do not usually write their final programs in one go (Zhang
et al., 2023). Usually there is an iterative improvement process happening, where the program-
mer runs their code with an example input/test case and gets feedback from the interpreter/-
compiler about whether their code produces the desired result. If the result is not satisfactory,
the programmer might use the interpreter/compiler feedback to improve their code and try
running it again. Language models have shown to benefit from repair models/repairing tech-
niques (Le et al., 2022; Zhang et al., 2023; Chen et al., 2023b). Some methods even include
human feedback to aid in the repairing process to improve the base model (Chen et al., 2023a).
Moreover, language models have been shown to benefit from utilizing scratchpad approaches
to solve certain (mathematical) problems (Nye et al., 2021). This is hypothesized to help due to
the auto-regressive nature of language models. It might help offload work the language model
