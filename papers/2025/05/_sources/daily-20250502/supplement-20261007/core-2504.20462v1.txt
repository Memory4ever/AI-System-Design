Abstract
With the development of distributed systems, microservices and cloud native technologies have become central to modern enterprise software development. Despite bringing significant advantages, these technologies also increase system complexity and operational challenges. Traditional root cause analysis (RCA) struggles to achieve automated fault response, heavily relying on manual intervention. In recent years, large language models (LLMs) have made breakthroughs in contextual inference and domain knowledge integration, providing new solutions for Artificial Intelligence for Operations (AIOps).
However, Existing LLM-based approaches face three key challenges:
text input constraints, dynamic service dependency hallucinations, and context window limitations. To address these issues, we propose a tool-assisted LLM agent with multi-modality observation data, namely TAMO, for fine-grained RCA.
It unifies multi-modal observational data into time-aligned representations to extract consistent features and employs specialized root cause localization and fault classification tools for perceiving the contextual environment. This approach overcomes the limitations of LLM in handling real-time changing service dependencies and raw observational data and guides LLM to generate repair strategies aligned with system contexts by structuring key information into a prompt. Experimental results show that TAMO performs well in root cause analysis when dealing with public datasets characterized by heterogeneity and common fault types, demonstrating its effectiveness.
Index Terms: Root cause analysis, Tool-Assisted LLM agent, Cloud-native systems, Multimodal data, Diffusion.
I Introduction
In recent years,
Microservice architecture and cloud-native technologies have become foundational elements in modern enterprise software development, driving the rapid development of distributed systems.
[28],[32],[39]. Microservices decompose traditional monolithic applications into independent distributed services, while cloud native technologies leverage containerization and container orchestration[21] to enhance the capabilities for flexible resource allocation, dynamic scaling, and continuous delivery[30].
In enterprise production environments, microservice systems are composed of numerous independent services and containerized entities[45], which significantly increased system complexity, These systems have intricate inter-service dependencies and communication patterns, where the failure of any component (e.g., network resource corruption) can trigger cascading effects that jeopardize overall system stability, potentially leading to significant economic losses[2]. How to achieve accurate root cause identification and resolution in complex distributed systems has become a key factor in reducing production risks and minimizing losses for modern enterprises.
Fig. 1: A failure case in a cloud-native system demonstrates three major challenges when using LLM directly for root cause analysis.
Root cause analysis aims to quickly correlate related multiple entity features, identify the root cause and determine the corresponding fault type, and provide actionable solutions, thus realizing an automatic fault response mechanism and minimizing human intervention[42].
How to perform an accurate and efficient root cause analysis in the distributed environment has become an important research direction.
Traditional RCA methods typically rely on rule-based anomaly detection or statistical correlation analysis (e.g. causal graphs[24]) to localize faults. These methods struggle to jointly analyze heterogeneous data modalities (e.g., unstructured logs and structured metrics), often leading to fragmented information and frequent error detection.
DL-based RCA methods attempt to incorporate multimodal feature fusion and dependency-sensitive Graph Neural Networks (GNNs)[23][44] to achieve accurate fault localization. Although these methods demonstrate good performance in specific tasks such as fault localization in complex systems, they still face significant challenges in real-time analysis and fault interpretability, heavily relying on the expertise of engineers to complete the root cause analysis and remediation process.
Recently, large language models have demonstrated revolutionary capabilities in automated root cause analysis, opening new avenues for AIOps [9], [12]. LLM can combine system faults with the current system context to generate actionable fault diagnosis reports, as evidenced by prototypes such as RCACopilot[6].
Recent works such as RCAgent[35] and mABC[43] developed LLM-driven automated RCA frameworks that enable accurate fault localization and provide reasonable repair suggestions, thus further advancing the field of automated operations and maintenance.
However, although existing LLM-based methods have significantly alleviated the reliance on expert knowledge in traditional DL-based methods, they still face the following three key challenges in real distributed system environments:
•
Context Limitations: Limited by fixed-length context windows, the LLM is unable to effectively process massive amounts of contextual monitoring data in real-time. This constraint often leads to data truncation or compression during analysis, making it difficult to utilize historical information to detect anomalous trends in system components, thereby affecting the rationale and accuracy of root cause analysis. So how to extract useful information from the complex system context and input it into the context-limited LLM is a key challenge.
•
Text Input Constraints: Existing large language models such as ChatGPT[1], DeepSeek[27], Qwen[3], etc., either only support text data as input or enable modality input by mapping different modal features to a unified textual semantic space. However, due to the lack of obvious correlation between time series and text, this transformation process often results in a significant loss of key feature information, severely hindering the analytical and reasoning capabilities of LLM. So how to efficiently unify multiple modalities of observation data to assist the LLM in providing accurate root cause analysis results is a key challenge.
•
Dynamic Dependence Hallucination: The LLM is based on static, pre-trained knowledge, which makes it challenging to model service dependencies in systems. It can only simulate simple graph structures using text prompts. As noted in [34], LLMs struggle with reasoning over complex graphs, which limits their ability to effectively capture service dependencies. Additionally, the dynamic nature of service call chains in the system means that evolving dependencies can cause the LLM to generate hallucinations that contradict actual dependencies, leading to inaccurate root cause analysis. So how to assist the LLM in modeling fault propagation paths using call chain relationships to achieve fine-grained root cause localization is a key challenge.
To address these limitations, we propose a tool-assisted LLM agent framework based on domain-specific perceptive models.
This framework decouples the LLM from the raw observational data by utilizing specialized observational data analysis tools(𝒯1\mathscr{T}_{1}-𝒯3\mathscr{T}_{3}), addressing the constraints of text input and the limitations of context in the LLM.
These specialized model tools are used to perceive the contextual environment, and their results form structured text inputs that are fed back to the RCA expert agent for further analysis, generating accurate root cause analysis results and reasonable maintenance recommendations.
Specifically, to address the problem of multimodal data alignment, we propose a dual-branch diffusion model as the data feature observation tool (𝒯1\mathscr{T}_{1}), which unifies multimodal observability data (logs, traces, metrics) into temporally consistent representations. To address the issue of dynamic dependencies, the root cause localization tool (𝒯2\mathscr{T}_{2}) performs a joint analysis of entity features and call topologies, modeling the fault propagation chain, and identifying the root cause through frequency-domain attention-driven temporal causal analysis. Subsequently, the fault classification tool (𝒯3\mathscr{T}_{3}) further analyzes the fault and maps the symptoms to predefined fault types.
The main contributions are summarized as follows:
•
We propose a tool-assisted LLM agent framework, which integrates domain-specific model tools with LLMs for root cause analysis of microservices. This framework enables the LLM to analyze the system state in real time by calling perception tools, decoupling the agent from the raw observational data, allowing it to generate accurate root cause analysis results and reasonable maintenance recommendations.
•
We present a dual-branch collaborative diffusion tool that captures potentially consistent patterns across modalities and provides a unified time series representation for downstream analysis tasks through condition-oriented collaborative reconstruction.
•
We design a root cause localization tool based on frequency-domain attention mechanisms, which identifies causal dependency patterns in frequency-domain features while filtering out low-frequency noise, achieving precise root cause localization.
•
Experiments on two benchmark datasets demonstrate that TAMO outperforms all compared methods including state-of-the-art (SOTA) approaches and derived baselines. Ablation and case studies further validate the effectiveness of the framework.
II Related Work
In modern cloud native systems, with the widespread adoption of microservice architectures and dynamic infrastructures, it has become particularly important to ensure high system availability and rapid fault recovery, making root cause analysis (RCA) a critical part of operations and maintenance. As a result, various RCA methods have been developed to guarantee system reliability, including traditional RCA methods, multi-modal RCA methods, and LLM-based RCA methods.
Traditional RCA methods: Traditional RCA methods are mainly based on statistical correlation analysis techniques, such as anomaly detection based on predefined rules[37] and root cause localization strategies based on causal discovery[7]. While these approaches perform well in static environments, they have difficulties in adapting to the dynamic service dependencies that characterize cloud native environments.
With the rapid advancement of deep learning, neural network-based methods for real-time system data analysis continue to emerge. DeepLog[11] models log features via long short-term memory networks; GDN[10] and GTA[8] construct graph neural networks using metrics data to capture fault propagation paths; Sage[13] leverages causal Bayesian networks with trace data for root cause localization. However, these approaches predominantly focus on unimodal data, failing to exploit complementary inter-modal relationships.
Multi-modal RCA methods: The multi-modal-based approach significantly reduces the missed detection rate by comprehensively considering system observation data from different modalities. Due to the differences between modalities, it is crucial to extract the correlated features across different data. PDiagnose[18] analyzes different modality data as independent entities and uses a voting mechanism to identify the root cause entity. Although this method successfully utilizes data from multiple modalities, it overlooks the consistency relationships between features from different modalities. Eadro[23], performs gated fusion of features extracted from different modalities and uses a graph neural network to fuse embedded features at the service level for root cause localization. HolisticRCA[14], compared to Eadro, fully considers the heterogeneous nature of microservice systems and standardizes the embedding of different modality data using an assembling building blocks strategy, combining masked embeddings for overall root cause analysis. In contrast to directly using raw data for root cause localization, Nezha[40] and DiagFusion[42] convert heterogeneous multimodal data into homogeneous event representations, performing joint analysis through event graphs to achieve root cause localization. CoE[38] further supports the operational experience of site reliability engineers as input on the event graph, enhancing the understanding and interpretability of the event. While these methods significantly improve the accuracy of root cause localization through multimodal fusion and comprehensive system analysis, their root cause analysis process still relies on human intervention by engineers.
LLM-based RCA methods: Due to the advanced reasoning and contextual understanding capabilities of large language models, LLM-based RCA methods have become significant advancements in automated root cause analysis. Currently, LLM-based RCA methods are still in the early stages of development. RCAgent[35] handles anomalies through a tool-augmented agent framework, while mABC[43] employs a blockchain-based multi-agent system for root cause voting and solution formulation. However, directly applying LLMs to RCA presents several critical challenges: the limited context window of LLMs restricts the processing of large-scale observation data, and due to text input constraints, they are unable to effectively handle time-series data (e.g., metrics), resulting in the loss of important feature information. Additionally, another key issue is how to use large models to capture and model dynamic dependencies in cloud native systems in real-time, without introducing misleading or false conclusions. These challenges highlight the need for further innovations in integrating LLM with multimodal and heterogeneous data sources for more accurate root cause analysis.
Fig. 2: The proposed TAMO framework consists of a Data Feature Observation Tool (𝒯1\mathscr{T}_{1}), a Root Cause Localization Tool (𝒯2\mathscr{T}_{2}), a Fault Classification Tool (𝒯3\mathscr{T}_{3}), and an RCA Expert Agent (𝒜\mathscr{A}). In the framework, the agent 𝒜\mathscr{A} calls tools 𝒯1\mathscr{T}_{1}-𝒯3\mathscr{T}_{3} as perception tools to analyze the system contextual observational data in real time. The results of these perceptions are structured into text inputs that are fed back into the agent. By analyzing the perception results, the expert agent will provide the corresponding root cause analysis and repair suggestions.
III METHODOLOGY
To fully exploit the multimodal observability data of cloud native systems while integrating prior domain knowledge, we propose TAMO, Tool-Assisted LLM Agents that Integrates Multi-Modality
Observation Data to address root cause entity localization and fault classification in large-scale system operations and maintenance. This workflow utilizes observation tools composed of a dual-branch collaborative diffusion model to effectively extract and integrate multimodal data from different entities. Additionally, task-specialized tools explicitly model the complex dependencies among entities using a causal graph, with feature propagation through the causal graph enabling accurate root cause analysis. Furthermore, to fully incorporate domain knowledge, we employ a Large Language Model (LLM) with operational expertise as an expert agent.
The expert agent 𝒜\mathscr{A} integrates the outputs from the preceding tools 𝒯2\mathscr{T}_{2}-𝒯3\mathscr{T}_{3} with context knowledge of the system to offer human engineers a comprehensive fault analysis and recommended solutions.
As shown in Fig.2, the proposed workflow consists of three tools and one agent, 𝒯1\mathscr{T}_{1}–𝒯3\mathscr{T}_{3} and 𝒜\mathscr{A}, each responsible for a specific task in the root cause analysis process:
1.
Data Feature Observation Tool (𝒯1\mathscr{T}_{1}): This tool employs a dual-branch collaborative diffusion model to integrate multimodal features. It reconstructs and fuses textual data features, such as logs, into time-series data based on conditional guidance;
2.
Root Cause Localization Tool (𝒯2\mathscr{T}_{2}): Utilizing the multimodal-enhanced time-series data as input, this tool models causal relationships between entities using a frequency-domain self-attention module, enabling accurate fault root cause localization;
3.
Fault Classification Tool (𝒯3\mathscr{T}_{3}): Based on the causal relationships between entities and the invocation chain structure, this tool classifies the types of faults;
4.
RCA Expert Agent (𝒜\mathscr{A}): Leveraging the expertise of a Large Language Model (LLM), this agent synthesizes the outputs from previous tools along with system environment context to provide site reliability engineers (SREs) with a comprehensive fault analysis and recommended solutions.
III-A Data Feature Observation Tool (𝒯1\mathscr{T}_{1})
Diffusion models are a class of generative models based on Markov processes that have demonstrated exceptional performance in the generation of data in various domains, including images[19], voice[31], and time series[41]. The core idea is to gradually add noise to the data through a forward denoising (forward diffusion) process, which converts the original data distribution to an approximate Gaussian distribution. In the reverse denoising process, the model learns how to gradually remove the noise to generate the desired data. In this tool, we use log patterns and temporal features as control conditions for two diffusion branches. During the denoising process, the two branches collaborate to guide the generation of time-series data with multimodal features from the noise-perturbed original data.

y^= MaxPool​(𝐇S)∈ℝE×1,\hat{y}=\text{ MaxPool}\left(\mathbf{H}^{S}\right)\in\mathbb{R}^{E\times 1},
(19)
Considering that multiple types of entities may experience faults simultaneously within the same time period, meaning that the root cause entity may not be unique, we use binary cross-entropy (BCE) as the loss function to optimize the model. Specifically, for each label yiy_{i} and the model predicted value yi^\hat{y_{i}} (where i∈{0,1,…,E−1}i\in\{0,1,...,E-1\}, and EE represent the total number of system entities) , the loss function is defined as:
ℒB​C​E=−1E∑i=1E[yilog(yi^)+(1−yi)log(1−yi^)],\mathcal{L}_{BCE}=-\frac{1}{E}\sum_{i=1}^{E}\left[y_{i}\log(\hat{y_{i}})+(1-y_{i})\log(1-\hat{y_{i}})\right],
(20)
III-C Fault Classification Tool (𝒯3\mathscr{T}_{3})
After the root cause entity localization is performed by Tool 𝒯2\mathscr{T}_{2}, the fault diagnosis process typically requires further identification of the specific fault type of the root cause entity (e.g., hardware overload, resource leakage, or configuration errors) to guide precise remediation strategies. Although root cause localization narrows down the scope of fault analysis (i.e., determining “where” the anomaly occurs), in practical operational scenarios, different fault types often correspond to differentiated handling strategies (e.g., memory leaks require service restarts, while CPU contention necessitates resource scaling). Therefore, this tool uses the time series data xe​n​t′x^{\prime}_{ent} generated by tool 𝒯1\mathscr{T}_{1} (for simplicity, denoted as zz) to train a fault classification model.
To model the latent temporal dependencies in the input time-series data zz, we use a Transformer model [33] as the encoder network. The output of its single-head self-attention mechanism is given by:
Attention=softmax​(z​WQ⋅z​WKTdk)​z​WV,\text{Attention}=\text{softmax}\left(\frac{zW^{Q}\cdot z{W^{K}}^{T}}{\sqrt{d_{k}}}\right)zW^{V},
(21)
where WQW^{Q},WKW^{K},WVW^{V} are linear projection matrices. Subsequently, we concatenate the results of the multi-head attention to obtain the latent vector representation:
V=MultiHead​(z​WQ,z​WK,z​WV),V=\text{MultiHead}\left(zW^{Q},zW^{K},zW^{V}\right),
(22)
After capturing the internal temporal dependencies of the time-series data, we employ the GAT model to capture the spatial dependencies between the time steps. According to formulas Eq.16-Eq.18, we perform feature propagation on the latent vector representation. The representation of each entity is obtained by aggregating the weighted features of its neighboring entities:
Z′=ELU​(GATConv​(X,A)),Z^{\prime}=\text{ELU}\left(\text{GATConv}(X,A)\right),
(23)
where ELU is the activation function and A∈ℝE×EA\in\mathbb{R}^{E\times E} is the dependency between entities. Subsequently, we use an MLP network to output the fault type for the corresponding entity. Considering the issues of multi-class overlap and class imbalance in the fault classification task, we adopt a weighted binary cross-entropy (wBCE) loss function with the introduction of class weight coefficients λ\lambda as the model’s training objective:
ℒw​B​C​E=−1E∑i=1E[λw⋅yilog(yi^)+(1−yi)log(1−yi^)],\mathcal{L}_{wBCE}=-\frac{1}{E}\sum_{i=1}^{E}\left[\lambda_{w}\cdot y_{i}\log(\hat{y_{i}})+(1-y_{i})\log(1-\hat{y_{i}})\right],
(24)
in which λw\lambda_{w} represents the ratio of negative to positive samples within each fault type class, which is used to enhance the loss contribution of the samples. Additionally, to prevent overfitting, we include an L2 weight decay term in the loss function. The final loss function can thus be formulated as:
ℒ=ℒw​B​C​E+β||𝐖||22.\mathcal{L}=\mathcal{L}_{wBCE}+\beta\left||\mathbf{W}\right||^{2}_{2}.
(25)
where β\beta is a predefined hyperparameter and 𝐖\mathbf{W} is the model weights.
III-D RCA Expert Agent (𝒜\mathscr{A})
After the three tools 𝒯1\mathscr{T}_{1}-𝒯3\mathscr{T}_{3} have completed tasks such as data feature alignment, root cause localization, and fault classification, the workflow has achieved a relatively deep understanding of the fault. However, relying solely on these outputs makes it difficult to provide comprehensive and accurate failure analysis and remediation plans. Therefore, to further improve fault response and system recovery efficiency, we introduce the RCA expert agent 𝒜\mathscr{A}. Using large language models (LLM), this agent synthesizes the predictions from the previous tools and incorporates the current context of cloud-native microservice architecture to offer a more comprehensive and accurate fault diagnosis and resolution strategy for site reliability engineers.
Specifically, we use the GPT-4 [1] as the expert model, which gathers the outputs from the previous tools as background knowledge, including:
•
Root Cause Localization Results (from 𝒯2\mathscr{T}_{2}): Identifying the root cause location of the fault and the associated system components.
•
Fault Classification Results (from 𝒯3\mathscr{T}_{3}): Providing the specific type of fault, such as network failure, hardware failure, configuration errors, etc.
•
System Context Information: Including the system microservice architecture, dependencies between services, call chains, resource usage, and other related details, which provide essential context for fault diagnosis.

IV-B Experiment Setup
IV-B1 Datasets
We conducted extensive experiments on two public datasets:
•
Dataset AA. AA is a large-scale public dataset from the AIOps Challenge11
1
https://competition.AIOps-challenge.com/home/competition/1496398526429724760, which was collected through fault injection into the real-world deployed microservice system HipsterShop22
2
https://github.com/GoogleCloudPlatform/microservices-demo. The dataset primarily consists of three types of data: metrics, logs, and traces. The system uses a dynamic deployment architecture, consisting of 10 services, each with 4 pods, totaling 40 pods that are dynamically deployed across 6 nodes. The dataset includes 15 types of faults in total. Among these, 9 fault types are related to services and pods in the context of Kubernetes (K8s) containers [5], while node faults include 6 types: sudden memory pressure, disk space exhaustion, disk read/write issues, CPU pressure, and slow CPU growth.
•
Dataset BB. BB is a public dataset33
3
https://doi.org/10.5281/zenodo.7615393 collected from the broadcast-style SocialNetwork system in [23], which only contains service-level entities. It includes 21 microservices and also consists of three types of data: metrics, logs, and traces. The dataset was generated by injecting faults into the system using Chaosblade, producing data that includes three types of faults: CPU resource exhaustion, network latency, and packet loss.
IV-B2 Baselines

These methods were implemented using their publicly available and reproducible open-source code, and we adjusted the data format to match the required input. Furthermore, since our research task is relatively novel and includes both fault localization and classification, we incorporated the same fault classifier used in TAMO for methods that do not natively implement fault classification (such as methods [36], [23], [33], etc.) for comparison. Furthermore, we introduced LightGBM[20], a method specifically designed for fault classification tasks, as a benchmark to evaluate TAMO performance.

IV-B3 Evaluation metrics
TAMO is dedicated to locating root cause instances and identifying fault types. Based on previous research works[14],[23],[42],[15], we selected different evaluation metrics to evaluate the performance of model for these two tasks. Specifically, for the root cause localization task, we use top-k accuracy (AC@K) as the evaluation metric, which represents the probability that the true root cause entity appears within the top-k results produced by the method. Here, we set k={1,3,5}k=\{1,3,5\}. Given SS as the set of faults, R​CRC is the ground truth root cause, and r​c​[k]rc[k] are the top-k root causes generated by the model. Therefore, AC@K can be defined as follows:
A​C​@​k=1|S|​∑i∈SS{1,if ​R​Ci∈r​ci​[k]0,otherwiseAC@k=\frac{1}{|S|}\sum_{i\in S}^{S}\begin{cases}1,&\text{if }RC_{i}\in rc_{i}[k]\\
0,&\text{otherwise}\end{cases}
(26)
For the fault classification task, we use P​r​e​c​i​s​i​o​n​(P​r​e)Precision(Pre), R​e​c​a​l​l​(R​e​c)Recall(Rec), and F​1−s​c​o​r​e​(F​1)F1-score(F1) to evaluate performance. Given true positives (TP), false positives (FP), and false negatives (FN), the formulas for these metrics are as follows: P​r​e=T​PT​P+F​PPre=\frac{TP}{TP+FP},R​e​c=T​PT​P+F​NRec=\frac{TP}{TP+FN}, F​1=2⋅P​r​e⋅R​e​cP​r​e+R​e​cF1=\frac{2\cdot Pre\cdot Rec}{Pre+Rec}. Considering that this task is a multi-label classification problem, we adopt both micro and macro metrics for a comprehensive evaluation. Micro metrics aggregate the performance across all labels, treating all instances equally, which is useful when the class distribution is imbalanced. In contrast, macro metrics compute the metric for each label independently and then average the results, giving equal weight to each label regardless of its frequency. Thus, the final performance is measured using micro-precision (M​i​P​rMiPr), macro-precision (M​a​P​rMaPr), micro-recall (M​i​R​eMiRe), macro-recall (M​a​R​eMaRe), micro-F1 score (M​i​F​1MiF1), and macro-F1 score (M​a​F​1MaF1).
IV-B4 Implementation
We implemented TAMO using Python torch 2.4.0 and CUDA 12.1. The experiments were conducted on a Linux server equipped with an NVIDIA GeForce RTX 3090 GPU, using Python 3.8. The model was trained with the Adam optimizer [22], and all experiments used a fixed random seed. For hyperparameters, we set the batch size to 32, μ\mu to 0.5, β\beta to 0.001, and the initial learning rate to 0.001. Additionally, due to the heterogeneity of system entities in Dataset AA, which includes three levels: Pod, Service, and Node, the collected data features vary across these levels, making it challenging to train certain baselines uniformly. For such baselines, we partition Dataset AA into subsets composed of different entity types (e.g., ApA_{p}, AsA_{s}, and AnA_{n}) and perform separate training and testing for each subset to evaluate their performance.
IV-C RQ1: Effectiveness in Root Cause Localization
Table I presents the results for root cause localization. The experimental data shows that our proposed TAMO model achieves the best or second-best performance across all datasets. Specifically, on the AsA_{s} dataset, the score of TAMO exceeds the second-best score by at least 6%, and even in the second-best performance case, the gap with the best result is kept under 3%, clearly outperforming other competitors. Furthermore, we observe that the Eadro and Transformer models, which perform well on the B dataset, experience a significant drop in performance on heterogeneous datasets such as AsA_{s}, ApA_{p}, and AnA_{n}. This is because these two methods can only handle homogeneous entity features (e.g., in the dataset B, there is only one type of service entity). When confronted with heterogeneous entity features that need to be processed separately, their performance significantly deteriorates due to the lack of inter-entity correlation information. In contrast, both HolisticRCA and our approach model heterogeneous entities in a unified manner, maintaining strong performance even on the dataset A. Compared to HolisticRCA, we map multimodal information into time-series features and further optimize it through spatiotemporal modeling, achieving better performance in the root cause localization task.
IV-D RQ2: Effectiveness in Fault Classification
In the fault classification task, as shown in Table 2, TAMO demonstrates significant advantages in two key metrics: Micro Precision (MiPr) and Macro F1 (MaF1). Particularly on the AnA_{n} dataset, TAMO achieves MaPr of 0.8869 and MaF1 of 0.8706, marking improvements of 24.32% and 19.85% respectively over the second-best model(HolisticRCA). TAMO stands out across all metrics such as Precision, Recall, and F1. Furthermore, it exhibits remarkable performance in the classification of complex fault types at the node level. In addition, TAMO excels in the precision metric, with MiPr reaching 0.7164 and 0.7182 on AsA_{s} and ApA_{p}, respectively, surpassing the best baseline model by 8. 09% and 12. 69%, significantly reducing the risk of misclassification. Although MiPr on the smaller dataset BB is lower than the baseline model LightGBM, TAMO still outperforms LightGBM in terms of MaPr and F1 metrics. This suggests that TAMO performs more evenly across different classes, achieving better classification results for minority classes with fewer samples.

IV-E RQ3: Ablation Study
To explore the effectiveness of each component in our TAMO framework, we designed three variant models and conducted ablation experiments. The variant models are as follows:
•
TAMOw/o​𝒯1\operatorname{TAMO}_{w/o\;\mathscr{T}_{1}}: To investigate the effectiveness of the diffusion method used by tool 𝒯1\mathscr{T}_{1} in fusing multimodal feature, in this variant we removed the tool 𝒯1\mathscr{T}_{1} and directly used the raw time series data as input to evaluate the variant performance.
•
TAMOw/o​b​r​a​n​c​h\operatorname{TAMO}_{w/o\;branch}: To investigate the effectiveness of the dual-branch diffusion model in tool 𝒯1\mathscr{T}_{1}, we removed the branch ϵt​i​m​e\epsilon_{time}, which is responsible for maintaining temporal features, in this variant. Only the log branch ϵl​o​g\epsilon_{log} was used in the diffusion reconstruction process. The reconstructed data were then used for fault classification to evaluate variant performance.
•
TAMOw/o​F​F​T\operatorname{TAMO}_{w/o\;FFT}: To investigate the effectiveness of the frequency domain-based root cause localization method proposed for tool 𝒯2\mathscr{T}_{2}, we removed the Fourier process in this variant. Instead, the original time-domain data were directly used for subsequent causal graph generation and graph convolution processes. The root cause localization results were then output to evaluate variant performance.
Fig. 5: Comparison of LLM results between RCA analysis of Agent 𝒜\mathscr{A} enhanced with TAMO tools and root cause analysis performed directly on raw data
Table II presents the results of the ablation experiments, from which it is evident that the removal of any component in TAMO leads to performance degradation. This demonstrates that each of the component within TAMO has an important effect. In particular, the variant of TAMO without tool 𝒯1\mathscr{T}_{1} shows a significant decrease in performance. This is because the fact that the variant TAMOw/o​𝒯1\operatorname{TAMO}_{w/o\;\mathscr{T}_{1}} lacks the ability of the diffusion model to fuse multimodal information, thereby being reduced to learning with only a single modal feature. This absence of key feature information makes accurate root cause analysis challenging. Similarly, removing the time branch ϵt​i​m​e\epsilon_{time} led to noticeable decreases in performance for both tasks, indicating that time series features are crucial for accurate fault localization and classification. Eliminating the FFT process resulted in a substantial degradation in RE localization metrics, demonstrating that frequency domain analysis is essential for precise root cause localization.
IV-F RQ4: Case Study
To validate the root cause analysis capabilities of TAMO in cloud-native ecosystems, this study conducts a case investigation using real-world failure data from HipsterShop. As shown in Fig. 4, the microservices system is deployed using a Kubernetes (K8s) architecture, with service components developed in multiple programming languages. The system entry is managed through the Frontend service, and each service node is configured with three Pod replicas. Monitoring data collection points are set at both the service and Pod levels. Experimental data shows that TAMO demonstrates precise root cause identification for the current failure scenario: the root cause localization confidence for the Currency Service reaches 97.96% (service level), while the confidence for CheckoutPod0 is 82.39% (Pod level). Notably, while the overall Checkout service is functioning correctly, only Pod0 experiences issues. In contrast, the Currency service suffers from a global failure at the service level, causing anomalies in Pods 0-2. This comparative case indicates that TAMO effectively integrates multi-entity features and topological causal relationships to achieve precise root cause diagnosis across multiple layers. In the fault classification task, we perform a visual analysis of observation data for the anomalous services/Pods: CheckoutPod0 is accurately classified as a CPU overload fault due to a significant spike in core metrics such as ”CPU Usage Second.” The Currency service exhibits a correlation between increased service-level response time and decreased request success rate, while its Pod-level Receive Packet count continues to decline. TAMO successfully identifies the anomaly as a network packet loss fault through multi-dimensional time-series pattern analysis.
Subsequently, we input the model inference results along with system context information into the RCA expert LLM and compare its output with that of an LLM fed directly with raw data, as shown in Fig.5. This framework leverages tool information and domain expertise to accurately analyze current system faults and provide reasonable remediation suggestions. In contrast, the normal LLM using only raw data struggles to handle the vast amount of observational data due to severe context limitations, resulting in significant omissions and misjudgments in root cause identification and fault classification, as well as corresponding errors in the proposed remediation suggestions.
V Conclusion
This paper introduces an innovative Tool-Assisted LLM Agent framework named TAMO to address the complex challenges of root cause analysis in cloud-native microservice environments. By integrating domain-specific tools with large language models, TAMO effectively handles high-dimensional, multi-modal cloud-native observability data and accurately pinpoints fault origins amidst dynamically changing service dependencies. The approach not only overcomes the information loss issues when converting raw observability data into a format suitable for LLM processing but also addresses the challenge that static pre-trained knowledge struggles to adapt to real-time changes in service dependencies. Moreover, by structuring and distilling key results, it guides the LLM to generate contextually appropriate remediation strategies, thereby avoiding limitations imposed by fixed-length context windows.
Our research demonstrates that using a dual-branch collaborative diffusion model enables capturing consistent patterns across different data modalities, providing a unified temporal representation for downstream analysis tasks. Additionally, the root cause localization method based on frequency-domain attention mechanisms enhances the accuracy of identifying causal dependency patterns while effectively filtering out low-frequency noise, achieving precise fault localization.
The experimental results show that, compared to existing advanced methods and benchmarks, TAMO performs notably better on two standard datasets, highlighting its potential to improve fault diagnosis efficiency and accuracy. Further ablation studies and case analyses also validate the effectiveness of each component of the framework and the superior performance of their collaborative work. However, as system scale and complexity continue to grow, how to more efficiently process larger volumes of data streams and further enhance real-time interpretability and cross-modal semantic alignment remain critical areas for future research.
