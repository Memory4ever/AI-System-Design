# Example：用同一迷宫理解反馈、更新与效果

本页包含实时训练的[逐格迷宫](./maze.html)、同页可切换的机制拆解，以及供手算核验的四候选 CPU 实验。先预测，再运行，再解释偏差；不下载模型、不需要 GPU。实际训练、隔离机制与人为反例明确分开，不拼接曲线。

## 页内演示与可选复演

同一地图上比较四种学习方式，不替每个算法另编故事。顶部始终显示奖励规则，中间显示当前行走与累计得分，右侧同时显示训练 loss 和任务效果。曲线由浏览器中的真实更新计算，不是预设动画。播放期间先采样、再准备反馈、再更新、最后评估；不是每走一格就自动修改参数。

| 时间 | 操作 | 先让听众判断 |
| --- | --- | --- |
| 0～2 分钟 | 独立迷宫选择 PPO，慢放一次行走，停在更新前 | 得分变了，参数是否已经变了？ |
| 2～4 分钟 | 切到 SFT，再对照 PPO | 照示范走与自己尝试，训练信息来自哪里？ |
| 4～6 分钟 | 第 08 页观察八条路线与组内比较 | 不训练 Critic 后，怎样决定好于谁？ |
| 6～8 分钟 | 第 10 页回放两条都成功的固定路线 | DPO 的得分曲线参与梯度吗？较差是否意味着失败？ |
| 8～10 分钟 | 第 12 页训练 10～40 轮，对照两条效果曲线 | 多走路能拿高分，但到达出口是否更容易？ |

主讲 45 分钟已包含页内演示，不在结尾再完整演示一次。上表是按需复演或单独实验时的十分钟脚本，不叠加为必讲内容。

每次切换算法或奖励都会从相同均匀策略重新开始，曲线不跨设置拼接。“训练 10 轮”跳过逐步回放，不跳过计算；随后仍能播放新策略的实际评估路线。离开幻灯片或隐藏页面会暂停，重置可复现同一随机序列。

SFT 在播放前就在图内标出完整蓝色虚线、方向与 1～4 步编号，明确这是预先给定的训练示范，不是策略探索出的路径。训练回放时保留示范，进入新策略评估时撤掉示范标记，避免将自主采样误认为照着固定路线执行。标记仅影响呈现，不改变动作概率或训练计算。

### 实验到底计算了什么

- 环境为 7×5 格，最多 24 次行动；当前位置与剩余步数构成有限时域状态。墙方向直接屏蔽，策略只按位置查四方向 logits。合法动作信息由环境预先提供，不是学出来的；不能将本实验解释为模型从零学会导航规则。没有提前内置通往出口的策略；SFT 的正确示范与 DPO 的偏好对明确作为额外输入。
- 正常奖励每步 −0.02、到达额外 +1；四步到达得 0.92，八步到达得 0.84。错误奖励每步 +0.05，出口不额外奖励，超时绕圈可得 1.20。24 步是任务定义的真正终止，不在超时处 bootstrap。折扣 γ=1。
- SFT 固定模仿 `RRRR`，最小化示范动作平均交叉熵；学习率 0.9，每轮一次更新。画面得分只用于评估。示范回放不等于策略自主采样；这个数据只覆盖示范路径，未教会所有偏离路径后的恢复行为。
- PPO 每轮采八条路线。用 return-to-go 减去更新前的表格 `V(位置,时刻)` 得优势，冻结 old 行动概率，进行四轮全 batch 裁剪更新，ε=0.2、学习率 1.8；按全部行动数平均。Critic 按每个访问状态的平均回报作 0.3 步长的均方误差更新。未使用 GAE、熵项或 reference KL。
- GRPO 同样采八条路线，将每条总回报减去组均值、除以总体标准差加 `1e-8`。同路线各步共享优势，按路线内行动数与组大小平均裁剪目标，ε=0.2、学习率 1，四个 epoch；reference KL 系数为零。没有差异时任务梯度为零。
- DPO 固定偏好 `RRRR` 胜过 `DDRRRRUU`，两者都到出口；冻结初始均匀策略作 reference，用整条路线的 log 概率和构造标准偏好损失，β=0.3、学习率 0.5，每轮一次更新。不按长度平均完整轨迹 logprob，不用在线奖励生成新标签。
- 所有策略直接更新表格参数，不使用动量。固定种子 20260923；训练采样与评估路线使用独立随机流。四种方法的数据、超参数和总行动数不同，本实验不构成等预算性能比较。

### 三条曲线不是同一个东西

**到达出口概率**通过有限步数的概率传播精确求出；**平均得分**以同样方法计算当前奖励下的期望，两者都不是只挑屏幕上那条路线测量。它们只覆盖这张地图，从未验证泛化。即时得分则属于正在回放的那一条路线。

**Loss**每次参数更新后在本轮训练数据上计算。SFT 是动作交叉熵，DPO 是偏好损失，PPO/GRPO 是负的裁剪策略目标，不含 Critic loss 或 KL；PPO 的 Critic 均方误差另列于反馈区。PPO/GRPO 每轮样本、优势和 old 都变化，loss 可正可负、可上下波动，不能要求一直下降，更不能比较四种算法的 loss 数值大小。第 0 轮没有训练 loss，不虚构起始点。

上述训练实验没有实现 learned Reward Model、GAE、reference KL、温度调节、课程学习或跨地图泛化测试；下方机制视图另有独立的一维评分器计算，不向这个训练器提供奖励。方向概率来自屏蔽墙方向后的 softmax；换成 LLM 时，temperature、top-p、约束解码和生成上限也会影响实际采样分布，不能仅凭同一个 checkpoint 名称就认定 rollout 概率与训练 logprob 口径相同。这些缺省是教学取舍，讲稿第 03、05～08、13 页交代必要边界，其余留在本页，不把它们藏成未说明的“完整算法”。

`maze.test.mjs` 对四种目标逐参数作有限差分核验，检查路线合法性、奖励数值、确定性与采样/更新边界。下述 Python 的 `[1,1,0,0]` 是另一种四路线抽象，不是这个逐格实验的记录。

主讲第 04 页只追踪一次抽到 A 的样本，梯度为 `[0.75,−0.25,−0.25,−0.25]`；CPU 例子另枚举四种路线求期望，梯度为 `[0.125,0.125,−0.125,−0.125]`。这是两种估计范围的区别，不是公式矛盾。全同奖励与误判的数值检查留在 CPU 例子和附录，不再作为第二套主讲动画。

## 机制拆解：让信息与参数的变化可见

独立迷宫页切换“机制拆解”，可暂停、前后单步、重置。选定机制时计算整段结果，再逐帧回放；不是每按一次播放按钮就新增训练样本。每帧显示正在变化的对象，离开视图或幻灯片即停止播放。第 05 页只演示回报累计；其余机制按需在独立页查看，不逐项宣讲。

| 机制 | 动态展示 | 证据边界 |
| --- | --- | --- |
| 采样与更新 | v0 收集动作；固定路线重算概率；实际更新为 v1 | 执行已有表格 PPO，一次 batch 的四个 epoch，不是 LLM |
| 奖励到回报 | 先向前得到即时奖励，再从后向前累计，减去预期 | Return 精确计算；Value 为明确标注的示意值 |
| 评分器到策略 | 两条路线的偏好训练评分器，冻结后给 6 步路线评分 | 实际更新一维评分器；没有随后训练 Actor |
| DPO 相对与绝对 | chosen/rejected 比值 2→6，成功概率 0.60→0.35 | 合法分布的反例，不是优化器轨迹 |
| 错误奖励修复 | 真正更新一次，再重评分，最后确定性恢复初始训练状态 | 修正标签未修改已更新参数；不模拟 LLM 完整 checkpoint |

评分器设 `score(route)=w×length/8`，初始 `w=0`，人工偏好 4 步胜过 8 步；最小化 `−log sigmoid(score_short−score_long)`，步长 0.8，共八次更新。负分仍可表达正确排序，没有天然零分；这个手工长度特征的模型不理解导航质量，也不能代表神经 Reward Model 的泛化。动画最后只计算固定评分器的分数，不绘制虚构的 Actor 学习曲线。

DAPO 动画已移除，算法演进概览也退出主讲。算法变体的具体讨论见附录 D，不再占用现场演示时间。

## 第 15 页：框架交接与异步示意

每个场景五步。“采样与权重”追踪训练端和 vLLM：生成数据、交付轨迹、更新后两端版本不同、传输加载、恢复生成；“数据交接”比较 verl 的概率诊断/校正与 miles 的 token 保真/路由重放；“异步与等待”把两题八回答延伸成连续两批：第 1 批 Q1/Q2、第 2 批 Q3/Q4，每题各四答。图顶固定显示批次定义及异步数据状态，两条资源轨解释训练第 1 批时为何仍用 v7 生成第 2 批。列是概念阶段，不表示等长耗时；资源余量是重叠的前提。

这是预设状态的机制动画，不执行真实训练，不使用计时来代表吞吐，也不连接迷宫的 reward/loss 曲线。0.20、0.12、token ID 和 expert ID 都是说明性数字。原始 token 一致与 expert 路由一致是不同条件，后者仅适用于支持的 MoE 配置；概率校正不能替代前者。

第 1 批完整且评分后才开始第一次更新；第 2 批假设在交接 v8 前生成并评分完，始终保留 v7 的行为记录。默认结局允许本例滞后，完整的第 2 批供 v8 计算目标并更新到 v9；切换“本例拒绝，重采”后，同一批旧数据不参与更新，用 v8 重采，训练仍等待新数据完成。这是两种预设接受情景，不计算实际 importance weight、自动质量阈值或真实梯度。真实实现可按组筛选补齐，不必整批同命运。真实请求也可能跨版本续写，这里没有模拟；同步基线不是 verl 的能力标签，动画不构成最优解或性能排名。

`framework-animation.test.mjs` 检查帧结构、完整 batch、权重交接顺序、两条资源轨依赖及接受/重采两种结局；`verify-slides.mjs` 检查所有帧和结局的桌面/手机布局、并行状态、情景切换、播放暂停、离页停止、键盘与打印。来源为 SOURCES.md 的 S22～S27 及 miles 异步文档。权重交接动画是有意简化的正确性流程，不执行真实 NCCL、IPC 或 KV 重建。

## 实验一：正确奖励改变分布

动作是四条固定路线，不是四个方向：A 绕路到达，B 短路到达，C 绕圈超时，D 未到出口超时。程序不逐格探索，只调整四个选项的概率。真实成功概率定义为 `p(A)+p(B)`，正常奖励仅判断到达与否，不带逐格实验的步数代价。

| 步数 | 正确奖励下的成功概率 | 错误奖励下的代理奖励 | 错误奖励下的成功概率 |
| ---: | ---: | ---: | ---: |
| 0 | 0.5000 | 0.2500 | 0.5000 |
| 1 | 0.5125 | 0.2595 | 0.4937 |
| 10 | 0.6204 | 0.3675 | 0.4217 |
| 50 | 0.8665 | 0.8425 | 0.1050 |
| 200 | 0.9708 | 0.9764 | 0.0157 |

这些是实际 CPU 执行后四舍五入的值。正确奖励为 `[1,1,0,0]`，错误奖励为 `[0,0,1,0]`。第二种目标只奖励绕圈的 C，制造 reward hacking 的简化反例。模型不需要“想要欺骗”也会沿这个目标优化。改名为路线不改变这份四类别数值实验的数学对象。

两组使用相同初始化、学习率、步数与动作空间。我们只改变 reward 向量，所以这个实验可以解释奖励错配的因果影响。它没有测试语义理解、泛化、神经网络共享参数或 Transformer；不能把 97.08% 当成大模型测试集准确率。

## 实验二：采样让更新带上噪声

程序还运行三个种子的 REINFORCE。每次从当前四类别分布采 64 个动作，用 `(R−baseline) × ∇log p` 的样本均值更新。这里 baseline 使用可以精确枚举的期望奖励，只是为了隔离采样噪声；真实大模型通常无法这样枚举。

观察 `sampled_reinforce` 字段中 A/B 概率的差异。两者奖励相同、起点对称，精确梯度下保持相等，有限样本下却会波动。三个种子是教学观察，不足以提供算法优劣的统计结论。

## 实验三：机制计算，而非完整算法训练

| 机制 | 输入 | 程序核验的结果 |
| --- | --- | --- |
| GRPO 相对优势 | reward `[1,1,0,0]` | 约 `[1,1,−1,−1]`，小量防除零 |
| 全同奖励 | `[1,1,1,1]` 或 `[0,0,0,0]` | 相对优势全零 |
| RLOO baseline | reward `[1,1,0,0]` | `[2/3,2/3,−2/3,−2/3]` |
| PPO 正优势 | A=1，ratio=1.5，clip ε=0.2 | surrogate=1.2 |
| PPO 负优势 | A=−1，ratio=0.5，clip ε=0.2 | surrogate=−0.8 |
| DPO 初始 | policy=reference=均匀分布 | loss≈0.693147 |
| DPO 更偏好 B/A | policy=`[.1,.4,.3,.2]`，β=.1；两条都正确 | loss≈0.626233 |

DPO 第二行人为给定新概率，不是运行 DPO optimizer 得出的最终状态。它让短路线 B 更受偏好，但到达概率 p(A)+p(B) 仍是 0.5。Python 中的 PPO/GRPO/RLOO 只核对关键数值；浏览器迷宫才另行运行简化的逐格训练循环。两者都不是大模型训练。

## 可自行改变的三个变量

1. 把正确奖励改为 `[1,0.5,0,0]`：预测两个正确答案是否仍保持同样概率。它检验的是“正确性之外的偏好如何进入目标”。
2. 把奖励改为 `[1,1,1,1]`：完整期望梯度为零；采样版使用精确 baseline 时也为零。不要由此推论带其他 loss/optimizer 状态的实际系统绝不更新。
3. 增减采样 batch size：比较相同种子集合和步数下的波动，同时记录总样本数；不能把更多样本的效果归因于算法本身变好。

建议保留原脚本，另复制到临时目录做变化，记录唯一改变项。这里不提供预先虚构的对照运行成绩。

## 从玩具模型到真正的小模型实验

以下是**未执行的可选实验设计**，不是已跑通的训练交付。选用自己有权使用且框架支持的小型 decoder-only checkpoint；固定模型、tokenizer 和框架 revision 后，再按该框架当前官方示例准备环境。本材料不提供未经验证的 CUDA 安装命令或通用显存承诺。

### 先确定问题，而不是先选算法

沿用多步文字题，建立训练、验证、最终测试三个集合；按底层算式、数字组合和题目模板去重，避免同一道关系只换词或调换加数后泄漏。再准备不同运算组合、更大操作数、不同表述的独立外推集合；只用改数字的模板题不足以证明语义泛化。最终测试不参与奖励调整、超参数或早停决策。

主实验不开放计算器或代码工具。要求输出最终答案时采用约定形式，如 `<answer>42</answer>`。验证器只接受唯一、完整的最终答案，按题目预先确定的关系计算标准值，不依据“很自信”或回答长度给分；最终答案对不等于每一步推导都对。重复标签、夹带多个答案、截断、无法解析都要单独记录。格式 reward 是否与正确 reward 分开，需在实验前声明。若另做工具辅助实验，分别报告工具选择、输入表达式、结果使用和最终正确率，不与无工具结果合并。

先测未训练模型。如果几乎全对，任务过易，组内信号不足；如果几乎全错，可能需要较简单题目或短 SFT 起步。难度调整只能使用训练/验证集合，不能根据最终测试挑题。

### 分阶段比较

| 阶段 | 输入与操作 | 输出与判断 |
| --- | --- | --- |
| Baseline | 固定 prompt 与采样配置，运行验证集 | pass@1、长度、格式失败、截断率；保存回答 |
| SFT 起点 | 只用训练集正确示范训练短阶段 | 对比格式与正确率；判断是否需要这个起点 |
| 离线 DPO | 从同一起点生成候选，用验证器在训练集构造正确性排序的偏好对 | 固定数据训练；这只研究正确性偏好，不能代表人类对清晰度或有用性的偏好 |
| GRPO | 从同一起点每题采 G 个回答，规则评分、组内优势 | 记录有效组比例、总生成 token 和测试表现 |
| PPO 可选 | 相同任务反馈，引入 value/GAE 与 critic 更新 | 增加 value 误差、critic 成本与稳定性观察 |

算法对比默认是从同一个起点分别出发的分支，不是 Baseline→SFT→DPO→GRPO→PPO 顺序叠加。顺序叠加可研究累计训练，但不能隔离各算法贡献。LoRA 与 full fine-tuning 也不要混在同一次公平比较里。

### 最小记录

记录模型/tokenizer/framework revision、数据划分哈希、奖励程序版本、随机种子、采样 temperature、最大生成长度、G、有效 batch、学习率、KL/clip、loss reduction、精度及实际硬件。至少保存每个 prompt 的回答、奖励、action mask、终止原因、行为版本和必要的 logprob。

初步使用 G=4 或 8 可作为教学试点，而不是通用最优值。先跑几个更新验证张量与奖励，再扩大预算；单纯训练不报错不足以通过验收。

### 什么才算验证了认识

- 同样的题与同样生成预算下，报告未见题目的表现，而不是只展示训练 reward。
- 同时报告评分失败、长度和截断，排除“更长/格式变化”造成的假提升。
- 保留一般语言或其他简单能力回归题，观察训练是否损害原有行为。
- 多个种子和足够样本后再解释稳定性；小实验允许 No Improvement，不修饰成成功。
- 分别比较固定训练步数、固定生成 token 和固定总成本；不同预算口径回答不同问题。

这个扩展实验将验证“真实共享参数模型是否发生了预期变化”。CPU 例子已经验证的是更窄的命题：在明确有限动作空间里，指定的更新机制与奖励目标如何影响概率。
