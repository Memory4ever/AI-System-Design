一次成功，怎样变成下一次更容易成功

同一张迷宫：偶尔找到出口，不等于已经学会稳定到达。

→ 计算更新方向 → 更新参数
→ 新策略再次尝试

  2. PPO、GRPO、DPO 使用什么比较依据？
  3. 怎样确认学到的是目标，而不是奖励漏洞？

教学设计；机制入口 S01、S02。

讲稿

今天不按算法名字开一串小课，只追踪一次尝试怎样改变下一次行动。我们一直用同一张迷宫：先有人给出路线，再让模型自己尝试，随后讨论怎么比较、怎么更新，以及更新后是否真的更容易到达出口。最后才看框架怎样把这一圈运行起来。

地图里的动作是方向，大模型里的动作是下一个 token。迷宫便于观察，但它只是表格策略，不证明语言模型能泛化。公式不是现场记忆目标；听完能用自己的话串起这一圈，比背出缩写更重要。

S02；本地表格策略实验，边界见 EXAMPLES.md。

讲稿

先不播放，指向蓝色虚线和 1～4 步编号：示范已经给定。播放时，模型读取这条路线，提高相应位置上示范动作的概率；到独立评估时撤掉路线标记，让当前策略自行行走。这里的奖励曲线用于观察效果，不是 SFT 的训练依据。

语言模型的对应过程是给定示范前缀，预测示范 token，即 teacher forcing。SFT 可以学到可迁移规律，也可能只记住局部模式，不能由训练 loss 判断。它的优势是监督直接，限制是示范覆盖不到模型所有可能走到的状态。

并非遇到限制就必须 RL。改 Prompt、增加示范、多次生成再筛选都可能更划算。接下来固定一种条件：任务会反复出现，结果较容易评价，希望改善未来的单次表现。此时，让模型自己尝试再利用反馈值得研究，但仍要承担额外的采样、评分和训练成本。

大模型强化学习 · 03

自己尝试之后，反馈还没有变成学习

环节 迷宫 大模型

生成了回答、拿到了分数，都不等于参数已经更新。

S01、S02、S04。

讲稿

Policy 就是当前参数定义的行动概率规则。一次走动只是在使用它，走完得分也只是收集经历。要学习，还得计算经历怎样影响参数，再真正执行更新。

迷宫每步扣 0.02，到出口额外加 1，最多 24 步。完整环境状态包括位置和剩余步数；教学 Actor 只按位置查表，Critic 还区分时刻。环境预先屏蔽撞墙方向，不是模型自己学会了识别墙。语言模型的前缀随每个 token 变化，不能看成在同一个路口重复选择。

这里的奖励来自程序。开放任务也可能先用人类偏好训练评分器，再评价新回答，这是典型 RLHF 的反馈路径；可验证结果提供奖励的路线常称 RLVR。它们说明反馈来源，PPO、GRPO 说明如何更新，不是同一层级的名词。

共同基础：反馈怎样改变行动概率

本页把参数简化为四个分数 z；softmax 把分数转换成总和为一的概率。追踪一次抽到 A、得一分的更新。

  1. 1生成
  2. 2评分
  3. 3算概率
  4. 4梯度
  5. 5更新
  6. 6新分布
静态图解与公式
生成回答 → 外部评分，固定本次回答和分数
        → 重新计算已采样动作的 log probability
        → 构造训练目标 → 反向传播 → 更新参数

外部评分不必可微；可微的是模型对已发生行动的概率计算。

S01；数值与推导见 APPENDIX.md A、EXAMPLES.md。

讲稿

为隔离这一次更新，把路线暂时压缩成 A/B/C/D 四个候选，初始各占四分之一。动画选中 A 得到正奖励，再计算提高 A 概率需要怎样改变四个分数。这是四选一手算模型，不是逐格迷宫的另一轮训练，两者不共用曲线。主讲不再另外展开完整枚举的期望梯度，推导保留在附录 A。

评分帧先暂停：参数尚未变化。模型重新计算已采到回答的 log probability，用反馈加权，反向传播求梯度，优化器才更新。反向传播沿计算链求出 loss 对各个可训练参数的导数；优化器根据这些导数与学习率修改参数。这里不是对评分器求导，也不是重新生成回答来配旧奖励。动画是无 baseline 的 REINFORCE 式单样本例子，不是完整 PPO；它先展示策略梯度方法的共同基础，下一页再进入 PPO 所用的比较思路。

真实语言模型为多个问题和 token 共享参数，不是一条答案对应一个独立按钮。我们希望改善反复尝试的平均表现，不是保留这次抽中的答案。有限采样有偶然性，一次更新不保证验证集变好。已知完整序列后可并行计算各位置条件概率，不等于可以并行决定尚未生成的 token。

现场停顿

问：“得到一分时，模型已经学了吗？”请补全算概率、构造目标、求梯度和更新。若仍认为奖励直接流进参数，就在同一张图上解释，不继续堆公式。

大模型强化学习 · 05

进入 PPO：比较实际回报与预期

静态图解与公式
名称 在同一条路线中指什么
Reward，即时奖励 当前这一步得到的反馈
Return，后续回报 从这一步开始，之后奖励的累计
Value，预期回报 当前策略从这里继续走，平均预计得到多少
Advantage，优势 这个动作比当前预期好多少

S01、S03、S17；动画为回报计算与示意 Value。

讲稿

这里开始为 PPO 建立比较依据。这是 Actor-Critic 方法中通用的价值基线思路，不是 PPO 独有，也不是后面的 GRPO、DPO 都必须配备 Critic。

沿四步路线收集奖励，再回头累计：即时奖励是 [-0.02,-0.02,-0.02,0.98]，不打折时，各位置的后续回报是 [0.92,0.94,0.96,0.98]。已经付出的代价不再算到后面位置的未来回报。

假设某位置预计得到 0.5，实际后续回报是 0.92，简单优势估计就是 +0.42。动画 Value 是给定的示意值，不是刚训练出来的 Critic。预期用于比较，不是人工写入正确路线，也不是这次已得到的分数。

语言模型的每个前缀都可以有相应预期。即使最后才给奖励，也能为沿途位置构造目标，但这不自动识别真正关键的 token。主讲用回报减预期建立直觉，标准 PPO 常结合后续状态预测使用 GAE，细节放在附录。

现场停顿

问：“同样得到 1，预计 0.9 和预计 0.2，哪个更超出预期？”再问 Value 是实际结果还是预测。确认区别后，再命名产生预测的模型。

下一页

这个预期不能凭空知道。PPO 的典型做法，是让 Critic 学预测，让 Actor 学行动。

大模型强化学习 · 06

PPO：行动策略和回报预测一起学习

一轮训练 改变什么
Actor 生成，Critic 预测沿途回报 收集行动与预测，暂不更新
用反馈计算回报与优势 判断哪些行动超出预期
更新 Actor 调整行动概率
更新 Critic，再开始新一轮 修正预期，跟上变化后的策略

Critic 学的是“你现在通常能做到多少”，不是“理论上最多能做到多少”。

S02、S03、S17；0.390 → 0.117 为本地 PPO 教学实验首轮起点计算。

讲稿

Actor 是一直使用的行动策略；Critic 是同一个预测函数在不同状态上的输出，不是每一步训练一个独立模型。尝试结束后，各状态的后续回报可以作为目标，让预测逐渐靠近它。失败和超时也要学习。实际 PPO 可以用 TD/GAE 构造目标，不要求所有任务都等到完整终局。

例如起点旧预测为 0，本批平均回报 0.390，教学更新向目标移动 30%，新预测就是 0.117。30% 是本地表格设置，不是 PPO 固定规则。神经 Critic 通过梯度学习，不保证输出按固定比例变化。

本批 Actor 使用更新前的预测构造优势，Critic 再利用回报目标学习。这里按理解顺序讲，框架计算顺序可以不同。逐 token 有价值预测，不意味着每生成一个 token 就更新一次；可以完成生成后用因果遮罩一次计算多个前缀预测。

Reward Model 评价回答以提供训练目标，Critic 预测当前策略后续回报，不能互换。Critic 越准不代表 Actor 越优秀：一直走绕路、一直准确预测低分，也可以很稳定。

比较对象 用途 代价与边界

S02、S03；完整公式见 APPENDIX.md B。

讲稿

同一条好路线已经让概率明显提高，继续反复强化可能过度利用偶然经验。PPO clipping 在变化沿有利方向过大时，让该项失去继续推动的激励。不是把概率硬锁在区间，也不能修复奖励错误。正负优势的完整概率比曲线留作追问。

Old 是本批比较基准，保存旧 logprob 可承担部分职责，不一定常驻完整模型。Reference 是另一种较长期比较对象，在 LLM RLHF 中常用于 KL 约束，不是 PPO 裁剪本身必须有的同一机制。先记住：一个控制本批变化，一个约束相对参考的偏离。

静态图解与公式
同一道题 → 生成一组回答 → 评分
        → 与组内均值比较 → 构造策略目标 → 更新模型
  • 不再训练 Critic，仍然要计算概率、梯度和参数更新。
  • 代价是多次生成，以及对组内有效差异的依赖。
  • 不是选出一个答案就结束训练。

S04 §4.1；实验口径见 EXAMPLES.md。

讲稿

在同一迷宫实际采样八条路线，再看组内得分与优势。允许重复，不挑最好看的结果。静态手算可以用奖励 [1,1,0,0]：减均值 0.5，除总体标准差 0.5，得到 [1,1,-1,-1]。动画还有步数代价，所以成功路线也可能分数不同，不能混用数字。

优势之后还要计算每步当前/旧概率、裁剪目标、梯度和参数更新。只按结果评分的 GRPO 通常让同一回答的 token 共享组优势，但各 token 梯度不同，也没有直接指出哪一步导致成功。原论文的过程监督分支不在主讲展开。

它改变了优势估计方式，不是把 Critic 的逐前缀预测搬过来。省去预测器减少相关训练状态，却增加采样需求；总耗时是否减少依赖任务与配置。本地版八路线、四个更新 epoch、零 reference KL，不是完整 LLM recipe。

大模型强化学习 · 09

Group 是比较单位，不是固定的一队答案

问题 A 的组、问题 B 的组
→ 分别计算组内优势
→ 汇总梯度，更新共享参数
→ 新策略重新采样，进入下一轮
  • 低均分但偶尔成功的组，可能很有训练价值。
  • 奖励全相同，奖励优势为零；其他损失仍可能作用。
  • 组内最好不等于绝对合格，更不等于全局最优。

S04；分组例子与边界为基于目标的教学分析。

讲稿

Group 通常是同题的多个回答，用来建立比较起点。一个训练 batch 可以包含多个 Group，共同影响一套可训练参数，不是每组一个模型。实际可以拆 minibatch、累积梯度；LoRA 时共享更新的是 adapter。

问题可反复出现，下一轮用更新后的策略重新采样。对旧回答做几次更新是利用旧经验，重新生成才是新探索。只训练一道题可能只记住它，需要不同题目和未见题验证。

容易题四次全对可能没有差异，困难题 [0,0,0,1] 的唯一成功却提供了方向。全失败同分时，补采也可能只是重复失败。归一化还会弱化绝对分数尺度：一堆差答案里的相对优胜仍可能很差。不能由均分低推导“不用训练”，也不能由有差异推导“差异值得学习”。

GRPO 不是排序树，没有局部有序通向全局最优的保证。探索、奖励和泛化仍有限制，这是省去 Critic 后的新压力，不是 PPO 被全面取代。

讲稿

这是数据条件的分支，不是 PPO→GRPO→DPO 的必经升级链。动画读取固定四步与八步路线，标签偏好四步。移动是回放已有数据；更新后自主行走是评估，不为本轮重新提供偏好标签。

DPO 比较当前模型相对 reference 更偏向哪条回答，用两条回答一起构造损失，不是给较好答案一分再做同一套在线 RL。数据仍需事先生成和标注。Rejected 不必绝对错误，本例只是相对较长。

偏好损失下降不保证较好回答的绝对概率每步都上升，也不保证数据外表现改善。概率反例保留在附录和独立迷宫机制视图，主讲不另开演示。

方法 学习依据 主要代价

讲稿

只回收已经建立的差异，不再重放四遍动画。SFT 给示范，PPO 学预测，GRPO 做组内比较，DPO 用已有偏好。选择取决于数据、奖励、采样成本与任务，不是名字新旧。

不能按迷宫相同训练轮数排名：SFT 获得示范，DPO 获得偏好对，在线方法消耗额外轨迹，信息和预算不同。LoRA 是更新哪些参数的选择，可与不同目标组合，不是第五种反馈形式。

为什么生成可能拖慢整轮？八条回答不是读取八条现成答案，而是逐 token 生成，且长短不一；更新则是在已有序列上做前向、反向和优化器计算。vLLM 用连续批处理把完成请求留下的空槽交给新请求，用分页 KV 管理减少显存预留浪费，让可用资源承载更多尝试。它改进的是数据生产，不是替代 PPO/GRPO，也不能保证每种负载都更快。评分、概率重算、PPO 的价值预测仍有各自成本；先分阶段测量，不把某个案例的采样占比当常数。

讲稿

沿用迷宫，Q1、Q2 是两个起点，每题生成四条路线。此处为算清分组，临时只用到达 1、失败 0，不与动画步数奖励混算。Q1 得分 [1,1,0,0]，Q2 得分 [1,0,0,0]，组内均值分别是 0.5 和 0.25。每题四条内部比较，不把八条混成一组；随后八条都进入同一模型的训练，不是每题训练一个模型。完整数值见 FRAMEWORKS.md。

先固定一次 optimizer step：即使显存只允许两条一次，也是在保留两组优势和正确 loss 权重的前提下累积四次计算，再更新共享参数 v7→v8。三个框架都组织生成、评分、更新与同步，本页选具体机制解释，不把一家框架等同于单一功能。逐阶段组件对照保留在 FRAMEWORKS.md。

先看“采样与权重”：训练已经 v8，生成端仍然 v7。同步不只是发送一句“用新版”，还要处理生成窗口、训练/推理分片及加载完成；例如跨 GPU 可用 NCCL，同卡进程可用 IPC，但布局转换和切换仍有成本。Actor 的更新参数交给策略生成端，Critic 保持自己的价值学习路径。共享设备不等于共享参数。

先追踪 b1 的某个 token：生成端记录概率 0.20，训练端重算为 0.12。这是假设数字，不是实测；如果策略已经更新，变化可能正常，若相同权重与输入仍差很多，就要检查实现。verl 的 Rollout Correction 比较相应策略的 logprob，提供重要性加权、截断或拒绝采样等选项，并记录偏差、有效样本量与过滤比例。它处理数据分布与训练策略不一致的问题，不能靠重加权修复错位的 token、错误奖励或缺失的成功经验。这里的概率差异诊断也不是第 07 页保留 SFT 行为的 reference KL。

miles 处理另一类交接问题：b1 经过文本解析与重新分词后，可能不再是当时生成的 token 路径。Token-In-Token-Out 保留真实 token；对支持的 MoE 路径，Rollout Routing Replay 记录并重放 expert 选择，减少生成/训练路由不一致。前者保留行动序列，后者保留部分执行路径；仍有数值、版本与模型适配条件，不意味着所有差异归零。

再把注意力从一条回答移到连续两批数据。第 1 批是 Q1、Q2 各四答，第 2 批是 Q3、Q4 各四答，各自组成一次完整更新的数据；不是某个答案继续生成后半段，也不是两套模型。同步模式先收齐第 1 批，训练到 v8，再用 v8 生成第 2 批。异步模式在训练第 1 批时，就用当时已有的 v7 提前生成第 2 批。不是已有 v8 却不用，而是 v8 尚未完成；生成端可以利用这段时间收集新经历。

SkyRL 的 Generator/Environment 接口则帮助把多轮互动组织成训练轨迹；loss mask 指明哪些 token 是模型行动，不是自动判断哪些行为有价值。三者都不能让 [0,0,0,0] 的无差异结果凭空出现成功经验，也不能自动发现评分器在奖励绕路。失败时仍要检查样本、评分及独立验证表现，不能只盯 reward 曲线。

本页实现描述于 2026-09-24 重新查阅官方资料，批次与版本为教学设定，未运行三框架基准。页内三个场景分别呈现采样与权重、数据交接、异步与等待；每个场景五步。主讲两分钟只演关键状态：先看两端版本差，再看异步重叠与第 2 批的去向，最后回到数据交接说明保真与校正；不逐帧读完所有细节。SkyRL 保留在静态表格与配套材料。

数据交接的两条泳道展示互补的干预位置，不代表框架独占能力。异步示例采用 miles 的机制，不能讲成 verl 只能同步。时间线每个配置展开生成、训练两条资源轨，同一列表示同一阶段，灰色表示等待；阶段不是等长耗时，不构成加速测量。动画假设异步第 2 批八条在交接 v8 之前生成并评分完，并有独立资源可与训练重叠；不会提前训练不完整的组。

为什么第 2 批的旧数据仍有用？它记录了 v7 在 Q3、Q4 上的实际尝试，而训练第 1 批得到 v8 不代表已经学会 Q3、Q4。默认情景中，接受规则允许这次滞后，保留 v7 的 token、奖励及行为概率，用当前 v8 重算训练所需概率，并按所选算法处理分布差异。第 2 批于是用于下一次更新 v8→v9，不是把 v7 的旧梯度直接加到 v8，也不把它伪装成 v8 生成的数据。校正不能保证与新鲜数据完全等价，v9 也只是新版本，不是能力一定更好的证明。

切换“本例拒绝，重采”，展示另一种结局：若接受规则不允许这批旧数据，本例丢弃其两组回答，再用 v8 重采 Q3、Q4。新数据未齐时训练端仍等待，完成、评分并检查后才会继续更新。这次提前采样确实可能白做。选择器表达两种预设接受情景，不是实测质量判决，也不暗示每次只能整批接受或整批拒绝；真实实现可以按组筛选并补齐。更严规则减少允许的滞后，也可能增加浪费或改变数据分布。

追问时区分两种“旧”：已完成第 2 批的 token/logprob 仍属于 v7，换权重不会改写其历史；尚未完成的回答若保留 token 并换权重续写，旧 KV 不能直接冒充新权重的状态，需要清理、重建并记录版本变化。vLLM 和 verl 提供相应接口或流程，但具体模式不同，动画没有模拟跨版本续写。最后回到有效进展：少等多久、丢弃多少样本、独立任务表现怎样，而不只是 GPU 利用率或生成条数。
