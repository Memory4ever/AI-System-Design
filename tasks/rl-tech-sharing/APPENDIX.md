## A. 从奖励到参数

### 符号先对应对象

| 符号 | 含义 |
| --- | --- |
| x、y | 题目、完整回答；y 的第 t 个 token 记为 y_t |
| s_t、a_t | 当前前缀状态、所选动作；语言模型中 a_t = y_t |
| θ、πθ | policy 参数、对应条件概率分布 |
| r_t、R、U_t | 即时奖励、整条回答的终局奖励、从 t 开始的累计 return |
| Vφ、A_t | 参数为 φ 的 value 估计、advantage |
| γ、λ | 折扣系数、GAE 的偏差/方差调节参数 |
| B、G、N | 题目数、每题采样数、总回答数 N = B × G |
| T、V | batch padding 后序列长度、词表大小 |
| m_it、T_i | 回答 i 在位置 t 的行动 mask、其有效行动 token 数 |
| πold、πref | 本轮固定的旧策略、参考策略 |
| ρ_it、ε | 概率比、PPO clipping 参数 |
| β_KL、β_DPO | KL 正则系数、DPO 目标参数；不跨算法直接比较数值 |

### 为什么不能直接对奖励 backward

一次生成采到了 y，验证器返回 R(x,y)。在这一次训练更新中，把 y 与 R 当作已观测数据；可微路径是 πθ 对这些 token 给出的概率，不是验证器内部的字符串比较。

对固定题目，假定奖励不直接依赖 θ，且满足交换求和与求导的条件：

```text
J(θ) = Σ_y πθ(y|x) R(x,y)
∇J   = Σ_y R(x,y) ∇πθ(y|x)
     = Σ_y πθ(y|x) R(x,y) ∇log πθ(y|x)
     = E_y~πθ [R(x,y) ∇log πθ(y|x)]
```

这就是用采样估计期望梯度的基础。它不要求奖励可微，却要求样本分布和概率计算与推导匹配。加入 importance weighting、clipping 或有限批次归一化后，要按相应目标重新分析，不能仍宣称是未修改目标的精确无偏梯度。来源：S01。

自回归模型把整条回答的 log probability 写成每个行动 token 的 log probability 之和。最简 on-policy REINFORCE 用 `loss = −R × Σ_t log πθ(y_t|x,y_<t)`；R 在这条梯度路径中停止求导。Prompt 本身不是 policy 生成的动作，多轮环境返回值也不是。

### 四类别小例子

令四个可学习 logits 为 z_j，概率 `p_j = exp(z_j)/Σ_k exp(z_k)`。这里 j、k 遍历四个答案，不是 Transformer hidden dimension。

```text
J = Σ_j p_j R_j
∂J/∂z_j = p_j (R_j − J)
```

初始概率均为 0.25，奖励 `[1,1,0,0]`，J=0.5。梯度为 `[0.125,0.125,−0.125,−0.125]`。学习率 0.2 的梯度上升更新产生 logits `[0.025,0.025,−0.025,−0.025]`，正确概率上升到约 0.5125。程序用有限差分独立核对这一梯度。

真实 LLM 的 logits 来自共享网络，不是每个回答一组独立参数。一次更新可能改变其他题目、语言和能力，所以必须做回归评估。

### 真正训练时 tensor 如何连接

这里有三个不同过程：SFT 给定示范前缀，预测示范下一 token；RL rollout 由策略逐步采样，前一步决定下一步前缀；RL update 固定已经采到的序列，重新计算它在当前模型下的概率。后两步不能偷偷更换回答。通常的 causal Transformer 在已知序列上可并行评分，不意味着生成未知序列时取消了自回归依赖。迷宫 SFT 回放的是示范，不是自由探索后才拿到标签。对应 Books Ch29、Ch32；来源 S02、S03。

```text
input_ids                 [N,T]       prompt、response、必要的环境观察
logits                    [N,T,V]     模型输出，实际可能分块计算
selected_token_logprobs   [N,T−1]     位置 t 预测 input_ids[t+1]
action_mask               [N,T−1]     同样完成 shift，只保留策略行动
sequence_rewards          [N]         每条回答一个分数
group_rewards             [B,G]       按 group_id 重排后的视图
sequence_advantages       [N]
token_advantages          [N,T−1]     序列优势广播，随后用 mask 过滤
```

例如 B=2、G=4、padding 长度 T=8、教学词表 V=100，则 logits 为 `[8,8,100]`，shift 后选定 token 的 logprob 为 `[8,7]`。广播不是新造七个独立奖励，只是让同一序列反馈作用于其行动路径。PPO 的 token advantage 可以不同，GRPO 的 outcome-supervision 示例则共享序列优势。

Attention mask 控制模型可以看见哪些位置；action/loss mask 控制哪些位置进入训练目标。环境观察可以被看见，却不必作为待强化动作。padding、截断、EOS 和 tokenizer 必须共同审计，shape 相同不能证明语义相同。

## B. PPO：用 value 降低噪声，用旧策略限制激励

### Baseline 与 advantage

对不依赖当前动作的状态 baseline b(s)，在固定状态下：

```text
E_a~π [b(s) ∇log π(a|s)] = b(s) ∇Σ_a π(a|s) = 0
```

因此减去它不改变基础梯度的期望，但可能降低方差。Value 是未来 return 的估计，不是“这个回答听起来像不像高质量”的 Reward Model。定义 `U_t = Σ_{k≥t} γ^(k−t) r_k`，简单优势可写作 `U_t − Vφ(s_t)`。

GAE 用 TD residual 构造优势：

```text
δ_t = r_t + γ Vφ(s_{t+1}) − Vφ(s_t)
A_t = Σ_{l=0}^{结束−t} (γλ)^l δ_{t+l}
```

例：两个行动，奖励 `[0,1]`，value 为 `[0.6,0.8]`，终止状态 value=0，γ=λ=1。则 δ=`[0.2,0.2]`，A=`[0.4,0.2]`，对应 return 目标均为 1。超时截断不一定是真正终止，是否 bootstrap 取决于环境定义，不能统一把最后 value 置零。来源：S03、S17。

### 同一路线的即时奖励、回报与贡献不是同一个数

动画中四步成功路线的即时奖励为 `[-0.02,-0.02,-0.02,0.98]`。γ=1 时，从各动作开始向后累加，得到 Return `[0.92,0.94,0.96,0.98]`。起点处未来还要付三次普通步数代价，最后一步前则不用再为已经发生的代价负责；它不表示最后一步“创造了更多因果贡献”。表格 PPO 减去各位置、时刻的旧 value 得优势；GRPO 用该路线总分 0.92 与同组其他路线比较，再将组优势用于它的各步。

绕路也成功时，终局反馈无法单凭这一条样本区分必要转弯与多余回头。Process reward 可以增加中间判断，GAE 可以在预测偏差与采样方差间取舍，但它们不是因果归功的自动证明；过程标签不可靠或 critic 不准时也会引入错误信号。这里不要求入门听众推导 GAE，只需区分“实际发生了什么”“预期如何”“据此怎样更新”。对应 Books Ch31～33；来源 S04、S17。

动画的 24 步上限是任务定义中的终止，因而超时后不再累计回报。训练系统的资源上限则可能只是外部截断：环境本来还可以继续。应先记录终止原因，再依任务选择重试、过滤、长度惩罚或 value bootstrap；不能一律把中断标成错误，也不能一律拿 critic 猜测当作真实成功。过滤后还要重新确认分组、奖励统计与数据分布。对应 Books Ch33；来源 S07，bootstrap 原理见 S17。

### 为什么 old 和 reference 不能混用

```text
ρ_it = exp(log πθ(y_it|prefix) − log πold(y_it|prefix))
Jclip = mean_valid min(ρ_it A_it, clip(ρ_it,1−ε,1+ε) A_it)
```

old 对应本轮 surrogate 的固定比较策略；reference 提供另一个长期锚点。典型 RLHF 还使用 `β_KL × KL(πθ || πref)` 的惩罚或奖励塑形。具体实现可以不同，不能一边在 reward 中已经扣 KL，一边又不加说明地重复扣除同一项。

KL 在完整分布上定义为 `Σ_a πθ(a|s) log[πθ(a|s)/πref(a|s)]`，在适用条件下非负。单次采样的 log-ratio 可以为负；旧样本上的均值也不能不经处理就冒充当前策略的精确 KL。需要声明采样分布、估计器与求平均范围。

### 正负优势都要算

| A | ρ | ε | 未裁剪项 | 裁剪项 | 取 min |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1.5 | 0.2 | 1.5 | 1.2 | 1.2 |
| −1 | 0.5 | 0.2 | −0.5 | −0.8 | −0.8 |
| 1 | 0.5 | 0.2 | 0.5 | 0.8 | 0.5 |
| −1 | 1.5 | 0.2 | −1.5 | −1.2 | −1.5 |

前两行减少继续沿已经走得很远的有利方向更新的激励；后两行仍惩罚不利变化。clipping 不是把所有超界样本丢掉，也不强制整个网络更新后满足 `ρ∈[0.8,1.2]`。来源：S03。

## C. GRPO、RLOO 与 DPO 的计算差异

### 前置对照：SFT 和 Reward Model 在学什么

SFT 给定示范回答 y*，在其有效 token 上最小化负 log probability：`L_SFT = −mean_valid log πθ(y*_t|x,y*_<t)`。例如在我们的有限动作空间，只把 B 当作示范，则一个样本的损失是 `−log p(B)`，均匀起点为 1.386294。它要求模仿指定的 B；正确性 RL 则同时认可 A 与 B。这并不代表 SFT 不能表达多种好答案，而是它需要在示范数据中提供这些答案及相应权重。

Reward Model 用参数 ψ 输出标量分数 `rψ(x,y)`。常见成对偏好训练采用 `L_RM = −log sigmoid(rψ(x,y+)−rψ(x,y−))`。若 chosen=B 的分数为 1，rejected=A 的分数为 0，则模型给“B 优于 A”的概率约 0.731059，偏好损失约 0.313262。此处在更新评分器，不是在更新生成 policy。随后可冻结评分器，让它为 policy 新生成的回答提供 reward。来源：S02。

这条链不能省略数据定义：是谁偏好 B、在什么准则下偏好、标注者是否一致？同一个 Reward Model 也可能在训练分布之外误判。迷宫的到达判定是环境提供的事实；偏好短路线则是额外目标。第 10 页在同样到达的 A/B 之间选择更短的 B。两种评价标准可以不同，开放写作也未必存在可靠的自动验证器。

反馈来源与反馈粒度还应分开。Human/AI/verifier 描述“谁评价”；outcome/process 描述“评价最终结果还是中间步骤”。过程反馈可能帮助信用分配，但步骤标签成本与评价错误也可能更高。结果正确不证明每个推理步骤正确，过程写得合理也不保证最终结果正确。

数学题数据可以提供示范解法、评测题或奖励核对依据，具体用途由实验协议决定。GSM8K 原研究使用微调和验证器，并允许模型选择带计算标注的计算器调用；它不能被写成在线 RL 实验。PRM800K 则给解题步骤提供正确性标签，供过程监督研究使用。这是数学任务的扩展问答，不是迷宫运行结果；主讲第 14 页备注简述行动与观察的区别，详细多轮轨迹见 FRAMEWORKS.md。开放工具时，最终结果正确只能评价整个系统，还需检查工具选择和参数是否合理。来源：S20、S21。

### GRPO：共享题目，比较不同尝试

对一道题的 G 个回答，奖励 R_i：

```text
μ = (1/G) Σ_i R_i
σ = sqrt((1/G) Σ_i (R_i−μ)^2)       本教学例采用总体标准差
A_i = (R_i−μ)/(σ+ε_num)            ε_num 是防除零小量，不是 clip ε
```

`[1,1,0,0]` 得到近似 `[1,1,−1,−1]`；全相同奖励得到零。原始 outcome-supervision GRPO 可概括为：每条回答对 token 的 clipped policy 项与 KL 项求平均，再对组求平均。这里用下式表达 reduction 结构，不指定所有实现的 KL 估计器：

```text
(1/G) Σ_i (1/T_i) Σ_t m_it [clipped_policy_term_it − β_KL K_it]
```

K_it 表示该实现采用的 reference KL 项，T_i 是行动 mask 之和。组优势通常作为已计算统计量，不通过评分器反传。改变标准差定义、长度归一化或 token 权重，就会改变梯度的尺度甚至目标；算法名称本身不足以确定实现。来源：S04。

用迷宫的 4 步与 8 步路线核对分母：先各路线平均再对两条取平均，短路线每步权重 `1/8`，长路线每步 `1/16`，路线总权重各 `1/2`；对全部 12 个动作平均，则每步 `1/12`，路线总权重分别 `1/3` 与 `2/3`。这里比较聚合权重，不保证实际梯度范数正好遵循同样比例，后者还取决于各步优势、概率和参数共享。这个区别连接原 GRPO、DAPO 的 token-level reduction 和 Dr. GRPO 的归一化审计，不能把它们全当作等价实现。对应 Books Ch33；来源 S04、S07、S08。

### RLOO：当前回答不参与自己的 baseline

```text
b_i = (Σ_{j≠i} R_j)/(G−1)
A_i = R_i − b_i
```

G 必须大于 1。同一奖励组得到 `[2/3,2/3,−2/3,−2/3]`，与 GRPO 的尺度不同。独立同分布采样条件下，其他样本提供与当前动作独立的 baseline；相关采样、筛选或额外归一化后需要重新检查条件。RLOO 是另一种估计方式，不是把 GRPO 少写一行代码就完全等价。来源：S06。

### DPO：偏好对变成一个相对概率损失

给定题目 x、chosen y+、rejected y−，定义：

```text
Δ = [log πθ(y+|x) − log πref(y+|x)]
  − [log πθ(y−|x) − log πref(y−|x)]
L_DPO = −log sigmoid(β_DPO Δ)
```

原始推导从 KL 正则 reward optimization 与偏好概率模型出发，消去显式 reward 参数化。β_DPO 与参考约束有理论关系，但同时缩放偏好 margin；实际梯度还受 sigmoid、数据和训练阶段影响，不能简单把 β 翻倍解释为效果某项翻倍。来源：S05。

例：reference 四候选均为 0.25，chosen=B 短路、rejected=A 绕路，两者都到达出口。policy 等于 reference 时 Δ=0，loss=`log(2)=0.693147`。按 A/B/C/D 顺序换成 `[0.1,0.4,0.3,0.2]`，Δ=`log(4)`；β_DPO=0.1 时，loss≈0.626233。这只说明该偏好对更被满足；到达概率仍是 p(A)+p(B)=0.5。以上为人为给定概率的四候选例子；逐格动画实际用 β=0.3 更新动作 logits，不能互换数值。

更强的反例是 chosen 从 0.4 降到 0.3，rejected 从 0.2 降到 0.05，剩余概率从 0.4 增到 0.65。二者比值仍从 2 增到 6，固定 reference 和 β>0 时偏好损失下降，而两个成功候选的总概率从 0.6 降到 0.35。这只是一个合法分布的数学反例，不是声称动画的一次实际 DPO 更新必然如此。还需分别观测 chosen、rejected 与独立任务效果。对应 Books Ch34；相对目标依据 S05。

## D. 演进是分支，不是一条冠军排行榜

```text
期望奖励优化
├─ REINFORCE：采样 logprob 梯度
│  ├─ learned value / GAE + PPO：降低噪声并限制旧样本更新激励
│  └─ 同题多采样：RLOO baseline / GRPO relative advantage
│      ├─ DAPO：有效样本、探索、token 权重、超长反馈
│      ├─ Dr. GRPO：重新审计归一化引入的权重偏差
│      └─ GSPO：把 ratio 与 clipping 改到序列级
└─ KL 正则偏好目标 → DPO：用偏好对直接训练 policy

多个奖励如何组合 → GDPO：审视逐奖励与混合奖励的标准化
```

上图是机制关系图，不是完整历史谱系；GDPO 与 GSPO 只作扩展阅读。主讲不要求记住全部缩写。

| 机制 | 原方案为何合理 | 新压力与改变 | 新约束/共存边界 |
| --- | --- | --- | --- |
| PPO | learned value 利用状态信息估计回报 | critic 训练成本、估计误差、长轨迹 | 仍适合需要细粒度回报估计的任务；组内方法不是必然替代 |
| GRPO | 同题比较省去 learned critic | 组内零差异、采样预算、长度/难度加权 | 多采样与适当难度重要；省 critic 不等于总成本一定更低 |
| RLOO | 其他样本构造 baseline | 避免当前样本进入自身 baseline 的统计耦合 | G>1，依然需要采样；不自动解决 off-policy |
| DAPO | 原始组内目标易实现 | 动态筛有效组、放宽上侧 clip、token 聚合、处理超长 | 筛选耗费 rollout，任务分布随接受条件变化；整套 recipe 不宜盲移植 |
| Dr. GRPO | 归一化曾用于控制尺度 | 长度和组内 std 也改变样本权重 | 改目标后需重新检查尺度、学习率和任务分布 |
| GSPO | token ratio 对应逐 token 处理 | sequence reward 与 token-level 波动的协调 | clip 数值口径改变；不能照抄 token-level ε |
| DPO | 固定偏好对可降低在线闭环复杂度 | 在线探索不是其默认内循环 | 标签、覆盖和分布偏移仍是成本，在线 RL 与离线偏好可组合 |
| GDPO | 先合成一个奖励便于优化 | 多奖励混合后标准化可能丢失区分度 | 逐奖励处理仍需选择权重；不保证多目标 Pareto 最优 |

GSPO 定义长度归一化序列 ratio：`s_i = exp((1/T_i) Σ_t log ρ_it)`，并在序列层应用 clipping。它是 token ratio 的几何平均，不是完整序列概率比本身。标准 importance sampling 的无偏性不能原封不动搬到这一归一化、裁剪后的目标。稳定性优势应限定于论文研究条件，不把作者的机制解释当作所有 GRPO 配置都会崩溃的定理。来源：S18；其余对应 S03～S08、S19。

## E. 最小流程伪代码

下面是单轮、同步、outcome reward 的概念流程，不是某框架可以直接执行的 API。`stop_gradient` 表示相关观测在这次策略更新中不参与求导。

```text
reference = frozen_copy(initial_policy)
repeat:
    old_policy = snapshot(current_policy)
    prompts = sample_training_prompts()
    trajectories = rollout(old_policy, prompts, samples_per_prompt=G)
    rewards = verifier(trajectories)
    old_logprobs = record_consistent_old_probabilities(trajectories)
    ref_logprobs = reference.logprob(trajectories)
    advantages = group_relative(rewards, group_ids)
    for minibatch in trajectories:
        current_logprobs = current_policy.logprob(minibatch)
        ratio = exp(current_logprobs - stop_gradient(old_logprobs))
        objective = clipped_surrogate(ratio, stop_gradient(advantages))
        loss = negative_masked_reduction(objective) + configured_KL_term
        backward_and_optimizer_step(loss)
    load_new_weights_into_rollout_engine()
    evaluate_on_held_out_tasks()
```

PPO 需要把组内优势替换成 value/return/GAE，并更新 critic。离线 DPO 则读取偏好对，对 chosen/rejected 前向构造偏好损失，不执行上述在线 rollout 内循环。工程中 old/reference 不一定常驻完整模型副本，可以按正确性要求保存概率或分时计算。

## F. 指标不是结论

| 信号 | 能帮助发现什么 | 不能独立证明什么 |
| --- | --- | --- |
| 训练 reward | 被优化目标是否改变 | 未见任务成功、真实性、能力保留 |
| held-out pass@1 | 固定采样口径的一次成功率 | 所有任务与温度下的表现 |
| pass@k | 多次尝试的候选覆盖 | 实际单次请求成功率或无成本提升 |
| entropy | 行为分布是否变集中 | 集中一定正确，或高熵一定有价值 |
| reference KL | 对特定参考的分布偏离 | 通用能力保留或安全保证 |
| clip fraction | 依实现统计概率比越界，或实际采用裁剪分支的比例 | 两种口径等价，或整个模型被硬限制在 clip 区间 |
| 有效组比例 | 组内是否存在奖励差异 | 零差异一定因为模型太强 |
| 长度/截断率 | 预算压力与行为变化 | 更长就是更好的推理 |
| actor/critic loss | 对当前目标的优化状态 | 跨算法、跨归一化可以直接比较 |
| rollout/update 时间 | 阶段成本与等待 | token/s 最高就最有效学习 |

报告 clip fraction 时应记录实现口径：`ρ` 落在 `[1−ε,1+ε]` 外，与 min 目标实际由裁剪分支决定并非一回事。后者还取决于 advantage 的符号；例如 A<0、ρ>1+ε 时虽然概率比越界，min 仍取未裁剪项。还需说明统计的是 token 还是 sequence、mask 与分母范围。

## G. 现场常见问答

**1. RL 不需要数据吗？** 需要题目、环境、验证规则或偏好。它把一部分数据生产放进当前策略的交互过程，不是凭空学习。

**2. SFT 和 RL 会互相替代吗？** SFT 利用可模仿示范，RL 利用结果反馈。SFT 常提供行为起点；若反馈不可靠或采样成本太高，继续改数据可能更合理。

**3. RLHF 就是 PPO 吗？** 不是。RLHF 描述人类反馈路线，PPO 描述优化方法。偏好可以训练 Reward Model，也可以进入直接偏好优化。

**4. GRPO 必须用数学题吗？** 不必须。关键是有可信奖励、可比较的多次尝试和足够差异；开放任务的奖励更难设计。

**5. Critic 与 Reward Model 都是打分，为什么要两个？** Reward Model 评价行为结果，critic 估计状态之后的期望回报，用途和训练目标不同。

**6. 负 advantage 是不是让正确答案概率下降？** 有可能。正确性只是奖励的一部分，相对基线决定优势；共享参数与 normalization 也会影响实际变化。应查看具体目标而不是只看“正确”标签。

**7. 所有回答奖励一样，为什么不都强化？** 相对优势已消去共同项。没有相对信息时，该组奖励项为零；其他损失和优化器状态仍可能更新参数。

**8. 奖励只在最后，前面的每一步都同样重要吗？** 不一定。给整条轨迹反馈是一种估计方式，不是证明每个 token 都有同等因果贡献；信用分配正是困难所在。

**9. 能对外部工具的输出做反向传播吗？** 一般不能，也不需要。策略梯度沿选择工具和参数等可微概率路径回传；环境输出作为观测。

**10. DPO 没有 Reward Model，奖励问题就消失了吗？** 没有。偏好标签、比较标准和覆盖范围已经把目标写进了数据。

**11. 能用 LoRA 做这些训练吗？** 可以在合适实现中只更新 adapter；LoRA 改变可训练参数子空间，不改变奖励是否正确，也不自动保证不遗忘。

**12. RL 后基础能力会变吗？** 会有风险。参数改变影响共享表示；KL、数据混合与回归评估是控制手段，不是能力永不下降的证明。

**13. 没有 critic 一定更省钱吗？** 不一定。需要更多 rollout、更长回答或更低有效组比例时，节省的 critic 成本可能被抵消。

**14. 异步训练一定更快吗？** 可能提高阶段重叠，但旧轨迹、过滤损失与更新质量可能降低有效进展，必须比较达到相同目标的总成本。

**15. 三个框架哪个最好？** 没有脱离任务的统一答案。先确定环境、模型支持、算法目标和资源，再比较兼容性、正确性与到达目标的成本。

**16. 多个奖励加权能得到 Pareto 最优吗？** 不自动。权重是价值取舍，非凸策略空间、有限数据与非全局优化使简单保证不成立。GDPO 一类归一化改进也不是多目标全局求解器。

**17. RPO 是什么？** 缩写在不同论文/实现中并不唯一。若讨论的是 DPO 叠加 chosen-answer NLL 的一种实现，必须明确出处、公式与权重；本材料不把未明确指代的 RPO 当作一条确定演进节点。

**18. RL 能创造全新能力还是只重排原有答案？** 四选一实验只能重排固定动作。真实模型参数共享且可探索新轨迹，能力变化需要未见任务和受控实验判断；本 demo 无法回答这个更大的研究问题。

**19. 一直失败，为什么不继续加奖励或增大 batch？** 如果奖励没有区分度，更多重复失败不一定带来有效方向。可靠示范、较易任务和更丰富采样可以改变起点或覆盖，但分别增加标注、难度设计和生成成本。Temperature 改变采样分布，不是一次参数更新；调高它也可能只产生更多无效行动。真实 RL 通常从 pretrained policy 出发，不能从小迷宫的均匀起点推断语言能力能由少数奖励凭空建立。对应 Books Ch29、Ch33；来源 S02、S04、S07。

**20. 打错分后改掉奖励，模型就恢复了吗？** 尚未更新时可以重新评分，并重算受影响的组统计、returns 和 advantages；已经更新后，错误已影响参数，可能还影响 optimizer 状态与后来采样。改数据不等于撤销训练，反向做一次梯度也不是通用撤销方式。应判断影响范围，选择从可信完整训练状态恢复后重训，或修正数据后继续训练并做回归评估，不能承诺精确恢复。只保存 Actor 权重而丢失 optimizer、critic、采样版本和奖励版本，也不等于恢复原来的训练过程。对应 Books Ch35；这是状态依赖分析，不新增恢复算法。

## H. 流程复述与试讲检查

第 16 页要求听众用自己的话连接步骤，不要求背出公式。下面是讲者核对答案的依据，不能由“点头”“动画播放完成”推断已经理解。

| 问题 | 应当说出的关键关系 | 常见断点与回看位置 |
| --- | --- | --- |
| 评分后还缺什么？ | 验证器只给反馈；模型重新计算采样回答的 log probability，构造目标，反向传播求梯度，优化器更新参数 | 把奖励当梯度，或认为要对验证器求导：回看第 04 页 |
| 一轮 GRPO 怎样发生？ | 同题多次采样、评分、组内优势、计算当前/旧概率与约束项、汇总目标、更新模型、将新策略用于下一轮 | 只说“挑最好答案”，或算出优势就停止：回看第 08～09 页；权重交接见第 14 页 |
| PPO、GRPO、离线 DPO 哪些步骤不同？ | 典型 PPO 用 learned value 帮助估计优势；GRPO 用同题组内比较；离线 DPO 从既有偏好对构造偏好损失，不执行同一套在线采样评分内循环 | 将三者当作必须依次执行的阶段：回看第 06、08、10～11 页 |
| 怎样判断真实任务改善？ | 在未参与训练的题目上固定条件评测，同时看其他能力、长度和异常行为；奖励上涨只是部分证据 | 只看训练 reward 或 GPU 利用率：回看第 12～13 页 |
| 框架负责什么？ | 组织生成、评分、训练与权重交接，维护对应数据关系；不能自动把错误奖励修正为真实目标 | 把选择框架等同于解决目标问题：回看第 14～15 页 |
