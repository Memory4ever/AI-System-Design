# 研究合同

## 1. 目标与分工

为 AI-System-Design 保留有长期价值的大模型及其基础设施知识。Daily、Weekly 和历史补跑共用本合同；
窗口、报告结构、独立复核和完成条件见 [Report 合同](./REPORT_CONTRACTS.md)，发现入口见 [来源清单](./RESEARCH_SOURCES.md)。

研究按以下漏斗推进，准备好的单篇不等待无关材料：

```text
原始命中 → 本窗去重事件 → 范围与贡献筛选 → 候选 → 经证据限定的结论 → Books 判断
```

候选表示有值得核验的增量，不代表结论已经成立。各层不设数量、保留率或更新配额；
对本项目不入选不等于没有学术价值，小改进、复现与负面结果也可能修正重要认识。

## 2. 收集与日期去重

按来源清单限定本次窗口和主题，保留可复查的入口、查询/分页与停止位置、执行时间、材料身份和筛选理由。
宽列表只作查漏线索，不自动成为逐项关闭的队列；入口扩大到无关领域时先收窄，只复查受影响部分。
覆盖完成指约定来源与窗口已处理，不是互联网上绝无遗漏。

以论文 ID/DOI、官方项目和版本识别同一材料家族（Source Family）。论文、项目页和代码可共同支持一个家族，
但首次公开、重要修订、release、RFC、card 和 artifact 是不同事件：

- 首次公开正文决定论文归属；搜索、推荐、收录或后来的正式发表不改变它。
- 按 Report 合同以公开日期归属，不以时分秒筛选。arXiv 提交日期不等于公开日期，使用官方公开列表/公告及必要的版本信息确认；只需核实日期，不追查精确公开时刻。保留原始日期口径，不补造时刻。
- 同一事件已有有效审阅即可去重；重要修订只审当前精确版本，解决具体未决问题才比较旧版。版本号变化本身不证明重要。
- 窗外新发现留作真实归属日的恢复线索，不扩张本窗，也不把尚未处理的材料写成已审重复项。

轻量检查当前官方事件页已有的撤回、纠错、勘误、安全及修订说明。即使摘要未变，也要处理其中影响原结论的信号；
不为证明“没有标记”遍历全站或完整版本史。日期含糊但已能明确排除贡献且无上述信号的，记明理由和日期未核实后停止。
拟入选项仍须确认落窗；必要日期或说明无法取得时列缺口，不能记为零命中。

官方撤回/删除的版本不入选、不评分、不进入 Books，仅在原始记录保留必要排除依据。
已收录后撤回则清除该版本的入选与采用链路，复核依赖结论；保留其他有效证据，不把撤回视为访问故障。

## 3. 先判断贡献，再投入审阅

### 项目范围先于贡献判断

以 [ROADMAP](../ROADMAP.md) 当前主线和阶段边界为准：模型能力的形成，以及多模态、训练、推理、平台和 Agent 的系统机制。
现有章节不是封闭白名单。学习/表示/优化理论、小模型实验、编译与通信研究也可直接支撑主线；
仅在某领域使用已有 AI 方法、提高领域指标或提供系统类比则不足以建立关系。AI for Science 按 ROADMAP 暂缓。

标题含义明确且无相关纠错或安全信号的范围外条目可简记原因后关闭；标题含糊或可能相关就读完整摘要。
进入贡献判断必须读完整题摘；无摘要的官方 Blog、release 或 RFC 则读核心说明与变更理由。关键词只辅助发现。

### 用具体增量决定准入

回答一个问题：**原文新增了什么值得长期保留的机制、适用边界或证据；如果成立，会改变哪项解释或设计选择？**

| 入口 | 准入依据 |
| --- | --- |
| 现有主线贡献 | 对应 ROADMAP 的具体问题，并新增机制、替代设计、有效性条件或足以修正原判断的证据；能映射章节本身不够。 |
| 主线之外的突破 | 尚无 owner，但可能改变理解或设计模型及其系统的基本方式；指出被挑战的假设、潜在变化及与当前项目目标的关系。 |

两条入口使用同一门槛，不绕过暂缓范围。无 owner 的潜在贡献先记待核验的 `Structural Candidate`，证据审阅后再判断结构。
准入理由连成一句：**原有约束或判断 → 原文实际增量 → 需要重新考虑的选择**。原文贡献与自己的系统推断分清，保持最小可支持范围。

| 常见材料 | 不足以准入 | 可以继续核验的增量 |
| --- | --- | --- |
| 新任务或模块组合 | 换场景后指标提高 | 新机制、模块收益的成立条件或原方案失效边界 |
| 加速、降本或扩规模 | 单个数字、更有利配置 | 可比条件下新的质量/资源取舍或可行性边界 |
| Agent 流程 | 把既有步骤改写为状态与控制术语 | 新执行机制、失效路径或可靠性条件 |
| benchmark、复现或综述 | 增加条目、排行榜、术语归纳 | 发现评价盲区、混杂因素或修正重要结论的证据 |
| 发布与修订 | 机构声望、版本号或修复标签 | 实际改变机制、兼容性、正确性、评价或安全约束 |

局部实验不必证明普遍定律，也不自动有长期贡献；看其是否改变具体判断。已有 Books 覆盖主题不排斥有意义的新验证或反证。
明确符合的入选，明确不符合的在原始记录中留下身份和具体理由。只有决定准入的事实含糊时才定点补读，得到判断即停止。
潜在贡献已清楚、仅实验可信度待核的进入证据审阅，不因摘要缺少实验细节而排除，也不默认初筛读全文。

首批拟入选与代表性排除项先做独立准入校准，再按校准后的理由展开受影响材料的审阅；
同时检查入口是否过宽、误收是否仅有主题关联、漏收是否错把局部或负面结果排除。初筛及已通过校准的无关材料可以继续。
具体复核范围由 [Report 合同 §3.6](./REPORT_CONTRACTS.md#6-复核) 定义，校准结果计入其中，不重复审相同内容。
发现共同错误理由时仅重开受影响集合；来源和筛选完成后确定候选清单。后来改判须有新证据或具体误判依据，
不能因深审费时、访问受阻或 Books 已覆盖而缩池，已读证据与改判原因应保留。

## 4. 三维评分决定最低审阅投入

只给通过贡献筛选、需要本次处理的候选评分，每项 0～3：

| 维度 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| Design Delta | 无设计变化 | 局部实现变化 | 重要机制/边界/替代方案 | 改变设计结论或纠错 |
| System Reach | 无直接关系 | 单组件或局部负载 | 跨系统边界 | 跨多个层级或生命周期 |
| Durability | 短期噪声 | 版本相关的工程价值 | 可复用的稳定约束 | 长期认知基础 |

三项相加为 0～9。评分对象是材料新增且拟由证据支持的命题；不把借用的成熟原则、能联想到的章节、
机构权威性、访问状态或 Books 决定计入分数。先准入再评分，不用高分倒推准入。

- **0～4：关闭判断。** 核实身份、日期、重复关系和不进一步采用的具体理由。
- **5～6：标准审阅。** 核实问题、关键机制、对照与评价条件、收益、代价和适用边界。
- **7～9：深入审阅并作 Books 判断。** 在标准审阅上读足以支撑拟采用命题的机制、实现或实验及关键反证。

纠错、发布/安全约束变化、重要修订、与 Books 冲突或已确认的长期知识缺口，无论分数均深入审阅受影响内容。
须指出实际变化及影响的具体判断，版本号、修复标签或改名不单独触发；不因此遍历整份 release 的无关内容。
重要修订不重复计算家族分数，但仍执行这一审阅要求。具体命题需要时可加深并说明原因，不为配合工作量或处置改分。

## 5. 证据读到哪里为止

优先原始来源的精确版本 HTML，必要时用 PDF。先读核心方法、关键评价和直接相关限制，
再围绕拟采用命题补读公式、图表、附录、消融或代码；支持与关键反证足够即可停止，不遍历无关附件。

检查证据是否足以把收益归因于所述机制：对照、数据、训练/搜索预算、质量目标和运行配置是否可比，
主要替代解释是否得到控制；需要统计推断时检查样本、重复运行与不确定性。性能研究关注端到端成本和失败条件，
理论结果核对假设与结论，不机械要求不同材料使用同一实验模板。小幅提升、单 seed 或未开源本身不决定价值；
证据不足则收窄结论或保留未决，不照录宣传。

记录精确版本、关键证据位置、证明与未证明的内容，以及自己的推断。可选代码不可得不阻塞论文可支持的结论，
但不得声称实现已核验、实验已复现或具备生产能力。结论确实依赖的材料缺失时列出具体需求并继续其他项；
尚未读完属于普通待办。

证据权限取决于实际角色：作者/厂商支持其公开事实和实验，独立评估支持对应评价，出版方支持发表状态，
artifact 支持公开实现，分析数据保留估算性质，搜索/索引只负责发现和身份恢复。
权威机构或社区观点均不能证明未公开机制。

性能数字绑定适用的 workload、model、hardware、precision/quantization、输入输出长度、batch、concurrency、
SLO 与 evaluator；未披露写 `Not Disclosed`，不适用说明原因。不同评价协议不直接合并，作者结果不外推为普遍结论。
中心结论冲突则保留双方证据；只有实际不满足准入门槛才改判排除，不能用降分、删反证或改标签代替审阅。

## 6. 让知识进入合适的章节

证据经独立复核且可能改变长期知识后，读取 ROADMAP owner、现有具体论点及相关交接内容；未变化的上下文可以复用。

- **整合**：深入审阅支持的长期机制、设计修正或知识缺口，明确差异并落实到唯一 Stable Node owner。
- **已有覆盖**：指出现有正文实际承载的论点，主题相似不够。
- **仅报告**：说明为何只是上下文、版本事实或尚未披露的机制，不改变长期知识。
- **结构候选**：证据支持长期价值但缺 owner，记录所缺知识链，供结构复核。
- **暂缓**：必要证据受阻或中心结论争议，明确采用边界、未决问题和重开条件。
- **未纳入本次**：仅用于用户明确要求本次不做 Books。

按 [学习方法](./LEARNING_PHILOSOPHY.md) 和 [写作指南](./WRITING_GUIDE.md) 融入现有论证；
报告同步具体位置与剩余问题，独立复核确认实际改动及前后衔接。“已有覆盖”也是有效成果，不为制造 diff 改书。
暂缓项如何结束本次处理，由 Report 合同的完成条件统一规定。

## 7. 复核与恢复

独立复核及验收范围只由 [Report 合同](./REPORT_CONTRACTS.md) 定义。恢复时区分三种情况：

- 尚未判断：继续当前待办。
- 身份、精确版本、判断依据与采用命题未变化且可核实：复用已完成结果。
- 具体反例、实质变化或必要证据失效：只恢复相关证明和依赖它的判断。

筛选、证据审阅和 Books 落实分别复用；一层出错不推倒其他有效成果。旧完成标签、相似标题或摘要不替代证据，
缺少机械指纹也不等于证据失效。保留原反证、未决问题和改判理由，不另建平行账本。

合同或来源名单更新不自动触发全历史重跑。新增窗内材料、身份/日期纠错、重要修订、实际漏项或必要证据失效时，
只重开受影响工作；用户明确要求全量重审时遵守其范围。
