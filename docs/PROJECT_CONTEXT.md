# 项目背景

## 为什么建立这个项目

这个项目始于学习者接触到越来越多的 AI 技术：

- Transformer
- LoRA
- RLHF
- GRPO
- vLLM
- SGLang
- KServe
- Dynamo
- Kubeflow
- Agent
- DSPy

问题并不是信息不足。

问题在于信息碎片化。

逐个学习框架会增加知识，却无法建立稳定的心智模型。

因此，本项目遵循一条原则：

> 先建立树，再长出叶子。

本项目被设计成一棵可长期生长的 AI System 知识树。

每个新框架、论文、算法和工程技术，都应在这棵树中拥有清晰的位置。

## 读者背景

主要学习者拥有丰富的软件工程与分布式系统经验。

职业经历包括：

- 电商系统
- Flink/Kafka 流计算平台
- Kubernetes 基础设施
- AI 模型生命周期平台

当前工作聚焦于：

```text
Training
→ Deployment
→ Serving
→ Platform Governance
```

当前涉及的技术包括：

- Kubernetes
- Kubeflow
- KServe
- vLLM
- SGLang
- LLMInferenceService
- PD Disaggregation
- KV Cache
- GPU scheduling
- Higress
- Observability

期望的职业发展方向是：

```text
AI Infrastructure
→ LLM Runtime
→ AI System Architecture
→ Agent Platform
```

## 核心问题

本项目首先追问的不是：

> 我该如何使用这个框架？

而是：

> 系统为什么会收敛到这种设计？

以及：

> 如果约束发生变化，它仍然会是最佳设计吗？

## 长期目标

目标是培养设计 AI 系统的能力，而不仅仅是操作 AI 工具。
