# Report 合同

版本：V3

## 1. 一套标准，两种窗口

Daily、Weekly 及其历史补跑使用同一套贡献筛选、证据审阅、Books 判断和完成标准。历史只是运行时间不同，不是一套更重的流程。

共同流程：**确定窗口 → 收集并筛选来源 → 去重和审阅 → 整理报告 → Books 判断与必要修改 → 独立复核。**
单篇材料准备好即可推进，不必等待其他材料；报告整体完成则必须没有未处理的可执行工作。

[研究合同](./RESEARCH_CONTRACT.md) 负责“什么值得收、读到什么程度、什么值得进入 Books”，
[来源注册表](./RESEARCH_SOURCES.md) 负责“查哪里”。本文件只定义时间、报告怎么写、何时算完成。

## 2. 时间与归档

统一使用北京时间，窗口含起点、不含终点；补跑不随实际启动时间移动。

| 报告 | 默认窗口 | 路径 |
| --- | --- | --- |
| Daily（含历史补跑） | 前一天 09:00 ～ 当天 09:00 | `papers/YYYY/MM/DD/README.md` |
| Weekly（含历史补跑） | 上周日 09:00 ～ 本周日 09:00，完整七天 | `papers/<ISO-year>/weekly/<ISO-year>-Www/README.md` |

周编号采用截点周日所属的 ISO 年/周，但覆盖窗口不是自然 ISO 周。不得按发现日期移动论文日期，
也不得因月末、年末截断周窗。非默认窗口须有用户明确授权，并写明原因。

Daily 只扫描每日来源和实际触发的按需来源，不扫描每周来源。Weekly 的新增扫描只处理每周来源与实际触发的按需来源；
每日来源直接复用本周周一至周日七份默认 Daily 的来源记录、筛选、证据与 Books 结果，不重新抓取、初筛或无差别重读。
Weekly 的工作是跨日去重、整合技术关系与新增周级研究，不是重跑七次 Daily；来源覆盖表引用已有 Daily 及其原始记录即可。
复用时确认七份 Daily 的实际窗口覆盖周窗。只有缺失 Daily、明确的覆盖缺口或影响原判断的新证据才定点补查相关来源/时段，
不得据此重扫整个每日来源组。历史 Weekly 没有对应 Daily 时直接补齐未覆盖周窗，使用相同标准，不假定已有覆盖。
历史 Daily 独立从原始来源重建，不拿旧 Weekly 的候选、评分或摘要反推 Daily；历史 Weekly 不顺带创建 Daily。

周日 09:00 后可以完成本周 Weekly，不需要周一补尾段。如工作尚未完成，保存明确的续跑位置；
周一至周六不提前创建当前周 Weekly。

## 3. 报告只维护六部分

报告正文就是事实与判断的维护入口，不另要求 JSON 投影、内容指纹或多张完成收据。
原始列表、查询记录和逐项筛选理由放在 `_sources`，正文引用它们，不复制它们。

### 开头

使用以下字段，时间写为带时区的 ISO 时间，例如 `2026-09-05T09:00:00+08:00`：

```markdown
# Daily Research — YYYY-MM-DD

**规范：** V3
**窗口：** <起点> ～ <终点>
**状态：** 进行中
**Books：** 纳入本次
**检查时间：** <本次检查时间>
```

Weekly 标题为 `# Weekly Research — YYYY-Www`。非默认窗口另写 `**窗口说明：** <授权依据>`。
只有用户明确要求本次仅做报告时，Books 才写 `本次仅报告`；不能因是历史报告或书稿暂时没有 owner 而跳过判断。

### 1. 结论

概括真正重要的发现、系统意义、Books 改动与证据限制。没有重要进展就如实写明，不为凑数收录材料。

用简短说明交代候选规模、实际审阅进度、Books 整合/已有覆盖及未决工作，让读者看出漏斗走到了哪里。
原始命中、已完成初筛、入选候选、审阅完成和 Books 产出分别表述；摘要读完不能算证据审阅完成，
审阅完成也不能直接写成“已证实有贡献”。不必为此新增统计表或账本。
候选与审阅进度按本窗唯一材料家族计数，首次公开与重要修订事件在该家族内说明；跨来源、跨 Daily 复用、
一篇对应多个章节都不增加家族数。Weekly 不直接相加七份 Daily 的候选数或沿用未完成的判断。
家族记为审阅完成时，本窗需要处理的事件均须达到相应审阅要求。
如引用原始命中数，标明去重情况、时间范围和实际覆盖来源；不能把全年目录、旧版本或搜索命中称作当天的新论文。
只报告现有记录能够支持的数量，尚未完成归并就说明范围与未决部分，不估算“几百篇有效贡献”。

### 2. 来源覆盖

| 来源 | 检查范围与依据 | 结果 | 缺口 |
| --- | --- | --- | --- |
| 清单 ID，或表外来源名称与链接 | 实际入口和覆盖范围；必要时附原始记录 | 已检查 / 未完成 / 受阻 / 未触发 / 不适用 / 检索受限 | 无，或具体限制 |

一行只需回答：**查了哪里、查到哪一段、结果怎样、还缺什么。**
例如“按窗口查询，3 页已读完，18 个独立条目筛选后保留 2 项”。
有分页的来源保留实际停止位置或读完依据；搜索型来源保留查询范围和结果限制。
正式报告必须自包含这些判断；抓取快照、筛选账本和复核草稿只是可选过程材料，不作为报告完成或长期保留的前提。

清单内使用原 ID；表外原始来源写 `表外：[机构或项目](官方入口)`，辅助搜索写 `补检：[名称](入口)`，不必扩充固定清单。
目标历史窗口尚不存在的来源保留原 ID，结果写“不适用”，并在依据中说明原因；访问失败或没有命中不是不适用。

日级或周级到期来源不能漏行；已发生的触发不能因没有入选候选而被取消。
`已检查` 包含确实没有命中的情况，但不能拿搜索首页、空响应或未读完的列表证明“无遗漏”。
仅辅助搜索入口不可达时写“检索受限”并说明局限，不阻塞其余确定性来源；必要正文或日期无法确认一律写“受阻”并列入本窗限制，不能因由补检发现而豁免。若已穷尽当前可用原始入口，应把它隔离为不支持候选、Books 或覆盖断言的保留项，并写明恢复条件；外部材料长期不可得本身不让日报永久停留在进行中。

### 3. 候选与判断

| 材料 | 公开时间 | 项目贡献与评分 | 审阅结果 | Books决定 |
| --- | --- | --- | --- | --- |
| 原始材料标题及链接 | 本次事件的原始公开日期/时间 | 一句具体贡献；Design Delta + System Reach + Durability = Total | 深入完成 / 标准完成 / 已关闭 / 待审阅 / 受阻 / 争议 | 整合 / 已有覆盖 / 仅报告 / 结构候选 / 暂缓 / 未纳入本次 |

公开时间可以是带时区的时刻，或有证据支持的 `起点 ～ 终点` 范围（含起点、不含终点）；范围须完全落在报告窗口内。
单写日期表示已核实的北京时间整天范围，只能在整天落窗时使用；原始字段、时区与推定依据放在证据说明中。
仍需判断贡献或拟入选、但仅知道相交日期、原始时区不明或不能确定落窗的材料放入缺口，不伪造时刻、不记零命中，也不先列为确定的当窗候选。
已按研究合同明确排除贡献的只保留原始筛选记录，不为不影响处置的日期另建材料请求。

只列通过贡献筛选的唯一材料家族，评分与审阅深度按研究合同执行。已经处理的重复事件不重列为候选；
重要修订说明修订事件、精确版本与原记录，写“不重复评分”，但仍审阅其本次贡献。
`整合`、`已有覆盖` 写 Stable Node ID 和具体章节链接；`结构候选` 解释缺失的知识链；
`仅报告` 解释为何不改变长期知识；`暂缓` 必须指向未决问题。`未纳入本次` 仅用于用户指定的仅报告任务。

### 4. 证据与知识整合

每项候选以原始材料链接为小标题，紧接着写自己的判断依据，不再另填 Review/Books 收据。
篇幅随贡献和证据复杂度变化：写清采用的精确版本、关键证据位置、机制与边界，以及最终处置的理由。
说明证据如何支持、收窄或反驳准入时的主张；只有局部结果时保留局部范围，不把通用系统术语当作新增知识。
完成审阅不能只有摘要改写或“已读全文”。需要 Books 判断的，说明与现有具体论点的差异及写入位置；
已有覆盖也要指出真正承载该论点的内容。完整证据笔记较长时可以链接 `_sources`，不要求正文重复展开。

可额外组织最多三条跨材料的技术演进分析，但这不是“只有三篇需要审阅”，也不设单独选题验收表。

### 5. 缺口与下一步

本窗没有限制或待办时第一行写“无”。否则区分尚可继续执行的工作与本窗已隔离的外部保留项。每项写材料身份/链接、缺少什么、为什么必要、当前为何不能采用、可接受的替代材料和定点重开位置。
同一材料只请求一次。晚发现的窗外材料在这里注明真实归属与待恢复工作，不扩张本次窗口，也不冒充当窗候选。
窗外待办另起一段注明不属于本窗，不阻塞本窗完成；处理时只重开受影响日期，不顺带重跑整月、整年。

### 6. 复核

记录 `复核者：<独立复核者身份>`、`结论：通过/未通过`，并简述实际检查的范围、发现的问题与解决结果。
复核者不能是报告作者。共同检查来源/日期/准入、候选证据、Books 决定及实际写入；仅报告任务明确不验收 Books。
来源与准入的复核范围按研究合同安排；已核实且未变化的证据可以复用，不要求第二个人无差别重读全部附件。
机器校验结果附在这里，但不能替代语义复核。

## 4. 何时可以结束

- **进行中**：还有可执行的扫描、筛选、审阅、Books 修改或独立复核未完成。保存进度并继续，不等待用户再次催促。
- **完成**：窗口已结束，到期来源已处理，候选逐项获得证据与 Books 处置，必要改动已落实，独立复核通过，且没有未处理的可执行工作。外部材料缺失、身份/日期不确定或中心主张争议可以作为**本窗终态保留项**存在，但必须被明确隔离：不用于正面证据、不进入 Books、不支撑“无遗漏”或性能/安全保证，并留下精确重开条件。材料以后到达时只重开受影响项。

Coverage、Evidence、Books Gate 分别对应上句中的来源/候选完整性、证据完成度和书稿落实情况，
不再各维护一张状态表。“完成”表示三者已处理到安全终态，而不是声称所有原始来源和论文主张都已得到证明；被隔离的保留项不是 Evidence 或 Coverage 通过。用户明确限定仅报告时，只能声称报告完成，不能声称 Books Integration 完成。
没有候选也可以完成，但必须有真实的来源检查依据。结构候选是已作出的结构判断，不等于已写入 Books。

## 5. 校验与复用

运行 `python3 scripts/validate_research.py --report <报告路径>`，并检查 Markdown、引用、变更范围与 `git diff --check`。
工具只检查可读字段、日期、评分、引用和明显状态矛盾，不证明来源确实读过或判断正确。
旧格式不能直接获得当前标准验收：保留有效研究证据，整理当前报告后再校验；无需为了排版重读论文。
如仅需检查旧结构，工具的显式来源快照用法见 [工具说明](../scripts/README.md)，不混入当前生成流程。

继续某份报告时按当前标准整理；证据复用与局部重开的条件统一按 [研究合同 §7](./RESEARCH_CONTRACT.md#7-复核与恢复) 执行。
排版变化不要求重新读论文。
保护已有改动，不 stage、commit、push。
