# 章节写作指南

[学习理念](./LEARNING_PHILOSOPHY.md)负责如何理解设计与技术演进，本文件只负责如何把理解写成可顺读的章节。
知识 owner 与章节路径以 [ROADMAP](../ROADMAP.md) 为准。

## 章节主线

围绕一个中心问题组织论证，让读者看清本章为何存在、解决到什么程度。
标题服务于推理，不强制采用 Problem、Math、Engineering 等固定模板；草稿脚手架在成章时应融入自然结构。

## 段落推进

每一节承接前文留下的问题，再引入必要的概念、机制与证据。数学符号先说明含义，公式和实现解释它们为何解决同一个问题，
工程约束只选与此问题有关的部分。技术演进按学习理念展开，不写成公式、框架与论文各自独立的清单。

取舍、failure mode 与适用边界放在对应机制附近，不把收益写进正文、限制全部藏进注释。
图表只用于帮助理解真正的关系，不用无说明的箭头把依赖、替代分支和直接演进混为一谈。

## 章节交接

开篇交代承接的知识与尚未解决的问题，收尾说明本章结论及下一章为何接手；不必固定设置“前置知识”和“总结”小节。
同一机制由一个章节完整解释，其他章节只保留理解当前问题所需的简述和具体链接，避免重复推导或空泛地说“详见后文”。

## Integration 整合

先读相关论证与前后交接，再决定新材料应插入哪里；优先重排、合并重复内容，不持续向章末追加论文摘要。
保留原有有效机制与成立条件；确需纠正结论时说明证据依据，不为篇幅或新颖性随意删除内容。

`Review notes` 放在章末，只保存来源、审阅状态和补充证据边界，其后不再接机制正文。
整合后顺读改动段落及前后内容：删去论文或产品名称后，论证仍应成立，章节交接也仍应自然。
